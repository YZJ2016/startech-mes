# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 入库 Hub — 撤回已确认/已过账并回滚库存（IH-G12 / INV-A04 `withdraw`）
- Module: **`startech-mes-basic/backend/ktg-mes`**（各入库类型 **withdraw** 领域服务 + 库存逆事务）+ **`startech-mes-front/`**（Hub 抽屉「撤回」按钮，UI-A）。**禁止**改 Vue2。**本文件仅文档**；编码须点名 **127**。
- Priority: **P5 / 余型**（故意后开；库存回滚复杂度高；对齐出库 **OH-G7** 思路、**不实现出库撤回**）
- Related requirement/design documents:
  - 缺口 14：**IH-G12**、INV-A04；设计 14 §7.5；总控 104
  - 配对：缺口 15 **OH-G7**（出库撤回，另文件；本单元禁止顺手做）
  - 库存核心：现网 `IStorageCoreService` / `wm_transaction` 流水
  - 对照只读：快格 `derive_inbound_hub_capabilities` / `_WITHDRAWABLE_RECEIPT_TYPES`

### Business Goal

对 **已过账（FINISHED/已入库语义）** 的入库单据，仓管在权限允许时可 **撤回**：回滚库存至过账前，单据回到可编辑草稿态（或作废态，见 T0），并写审计日志。禁止无流水盲改库存。

**现网事实（2026-09-17）：**

| 项 | 现网 | 127 假设 |
| --- | --- | --- |
| 撤回 API | **无** Hub/单据级 withdraw；删除多限草稿 | **新建** `PUT …/withdraw`（分类型或统一 facade） |
| 库存流水 | `processItemRecpt` 等写事务；**未见** 通用 reverse API | 新增逆事务：按原单 TxBean **反向 flag** 或冲销流水（T0） |
| Hub capabilities | 无 withdraw 字段 | 列表/抽屉可计算 `withdrawAllowed`（服务端为准） |
| 状态 | `PREPARE`/`CONFIRMED`/`FINISHED` | 仅 **FINISHED（已过账）** 可撤；CONFIRMED 未过账 → **取消确认** 另议（默认纳入轻量「反确认」或 OUT） |

**对照只读（快格可撤类型）：**  
`purchase`、`finished_goods`、`semi_finished_goods`、`production_return`、`customer_material`、`sales_return`、`material_return`、`other_inbound`。  
**不可撤：** `outsource_material_return`、`outsource_product_return`（及未过账）。  
`outsource_receipt` 未进 withdrawable 集合 —— Startech **默认委外三类均不支持撤回**（123–125 后置且风险高）。

### Scope

In scope:

- **P5 核心类型撤回**（须已在 Hub 落地）：
  - `ITEM_RECPT`、`PRODUCT_RECPT`、`SEMI_PRODUCT_RECPT`
  - `RT_ISSUE`、`RT_SALSE`
  - `MATERIAL_RETURN`、`OTHER_INBOUND`
  - `CUSTOMER_MATERIAL`（若 122 已落；否则跳过并记 §4）
- 每类型：校验可撤 → 库存逆事务 → 状态回退 → `@Log` 审计
- Hub 抽屉按钮调对应 withdraw；权限字 `mes:wm:<doc>:edit` 或独立 `withdraw`（T0）
- 单测：过账后再撤库存回到前值；重复撤回拒绝；租户隔离

Out of scope:

- **出库 OH-G7** 全套
- **委外三类撤回**（默认 OUT）
- 跨单连锁撤回（已下游领用/已开票）——默认 **拒绝撤回** 并返回明确错误（不做级联）
- 打印/金额抛光；改 Vue2；yml 开关（可用 `sys_config` `mes.wm.inbound.withdraw.enabled` 默认 `on`，T0）

### Acceptance Criteria

1. 点名 **127**；至少物料入库 + 成品入库 + 其他入库（120）三路径单测绿。
2. 仅已过账可撤；草稿/已撤拒绝。
3. 撤回后库存数量与过账前一致（同租户同仓同批次维度）。
4. 下游已消耗导致无法逆事务时 → `AjaxResult.error`，库存不变。
5. 不改出库 Hub；§4 **已实跑（代码已落）**；部署手验仍开。

### Rules and Constraints

- 租户失败关闭；JWT；不进 PermitAll。
- 撤回必须与库存事务同 `@Transactional`；失败全滚。
- 日志不打印密钥/内部路径；错误不泄漏他厂单据存在性。

## 2. Plan

### Implementation Approach

1. T0：点名 127；读各 `process*` 与 transaction 表结构，定冲销 API。
2. 实现 ItemRecpt / ProductRecpt / OtherInbound 三条路径为样板。
3. 扩展 RT_* / 还料 / 客供。
4. Hub 抽屉按钮 + capabilities 只读提示。
5. 负向：委外类型无按钮；出库无入口。

### Affected Modules

- `ktg-mes` wm + storage；Vue3 Hub；可选 `sys_config` 总开关（master Flyway）。

### Public Contracts

- **加法** withdraw/unconfirm URL；旧 execute/confirm 语义不变。
- Hub list 可选回传 `withdrawAllowed`（非必须破坏契约；可仅前端按 status 猜 + 服务端拒绝兜底）。

### Persistence Changes

- **默认无新表**；依赖既有 `wm_transaction`（或等价流水）。
- 可选 master：`mes.wm.inbound.withdraw.enabled`=`on`。

### Transaction Boundaries

- withdraw：读单 → 校验 → 逆库存 → 更新状态；任一步失败回滚。

### Risks

| 风险 | 缓解 |
| --- | --- |
| 负库存 / 批次已耗尽 | 逆事务前校验可用量；失败明确文案 |
| 盲改库存无流水 | 禁止；必须冲销 |
| 与财务/发票已同步 | 无财务模块则忽略；有则拒绝（CAT-A01 后置） |
| 半成品/客供/委外状态不一致 | 矩阵分类型；委外 OUT |
| 误做出库撤回 | OH-G7 OUT；扫描 outboundhub |
| 并发双撤 | 状态机 + 行锁/版本 |

### Verification Strategy

- 单测：过账→撤→库存还原；并发/重复撤；跨租户 403/404。
- 手验：Hub 抽屉撤回成功与失败 toast。
