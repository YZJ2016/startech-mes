### Business Goal

同一套后端安全承载多家工厂：默认共享库行级隔离（`ROW`），创建租户时可选独立库（`DATABASE`）。登录先绑租户再路由数据源；SQL 失败关闭；菜单/字典共享、不按租户克隆。本文件只锁定原则、阶段门禁、决策表与单元顺序，不写 Java/SQL。

### Rules and Constraints

Tenant isolation:

- 默认 `ROW`（共享主库 + `tenant_id`）；创建时可选 `DATABASE`（独立 JDBC）
- 两档共用同一拦截器：无上下文访问租户表抛错；INSERT 填充/校验；SELECT/UPDATE/DELETE 加 `tenant_id = ?`（占位符绑定）
- `DATABASE` 行上仍写 `tenant_id`；专库不可用禁止回落主库
- 平台租户 `tenant_id=0` 强制 `ROW`，始终走主库
- SQL **永不跳过 `tenant_id`**（含 `user_id=1` 的现网 admin）
- 登录后租户只信 JWT/`LoginUser`，忽略客户端后续租户头
- 租户谓词先于 `@DataScope`；`isAdmin()` 不得关掉租户拦截器

Security and masking:

- 不引入第二套认证；继续 Spring Security + JWT + Redis `LoginUser`
- JDBC 口令 AES-256-GCM 加密落库；密钥仅环境变量 `TENANT_JDBC_CIPHER_KEY`；密钥轮换不进一期（S6）
- 列表默认打码 JDBC/口令；明文只经平台揭开接口且须审计（审计不记明文）；禁止 API 回传 cipher 当密码
- `ROW` 且 JDBC 任一字段非空 → HTTP 400，不落库
- 日志、异常、审计不得打印 token、口令、JDBC URL 中的密码、内部绝对路径
- 失败关闭：无开关可关掉拦截器；最多「拒绝所有登录」

Audit and lineage:

- 历史 SQL（`ry_*.sql` / `mes-*.sql` / `quartz.sql`）只追加增量，不原地改写
- 现网数据回填 `tenant_id=1`；种子平台 `platform`(0)、工厂 `default`(1)，均不绑 `server_name`（D10）
- 停用租户立即 SCAN 作废该租户全部 `login_tokens`（D6/R6）；`DATABASE` 卸载专池、不删库
- 平台 runAs 写审计；工厂管理员看不见代管（F9）

AI/rule-engine rules:

- 本批不涉及规则引擎或 AI

Database rules:

- 切线前历史增量仍在 `startech-mes-basic/backend/sql/`（`YYYYMMDD_NN_<topic>.sql`），**不原地改写**。切线后（基线 `20260822.20`）发布 DDL 只放 Flyway `db/migration`（见 `docs/03.design/05.mes-flyway-integration.md`），不再往 `sql/` 追加作为上线脚本
- 列约定：`tenant_id bigint not null`，加列时 `DEFAULT 1` 再回填
- 唯一键改为 `(tenant_id, 业务键)`；`DATABASE` 专库同一套 DDL，不改为仅业务键（S4）
- 加 UNIQUE 前跑 `GROUP BY tenant_id, 业务键 HAVING COUNT(*) > 1`；0 则直接加；非 0 才改键/软删，禁止未清时加索引，不自动合并工单/库存（S4 窄）
- `sys_config`：可空 `tenant_id` overlay；全局键 + 租户覆盖；`DATABASE` 读全局键走主库（D1/I8）
- 禁止一次 ALTER 全部 MES 表；按波次扩大拦截器 include 名单

## 2. Plan

### Implementation Approach

1. 先落地 P0 上下文与失败关闭拦截器，以及 `sys_tenant` 枚举/加密 JDBC（尚不切 DS）。
2. P1 把登录与身份表绑上 `tenantId`；Vue2 不改，交互登录失败为已接受后果。
3. P2 堵住 Redis/文件/异步/WebSocket 旁路；P3 共享菜单 + 许可裁剪路由。
4. P4 接管 md 表后才允许第二个 `ROW` 工厂。
5. P-D（41）在 P4 之后做懒加载专池与 I8 主库绑定；此前 DATABASE 保持拒登录。
6. P5–P8 按包扩大 include 名单与增量 SQL；P8 收口剩余 Mapper、按租户自动编码、Quartz、UReport Filter。
7. P9 只改 Vue3；P10 写明 v1 不做跨租户报表。

过渡期：P0–P3 拦截器只对**已加列**表生效；未加列的 MES 表仍是单租户数据（将回填为 1）。P4 之前不得写入第二套工厂业务数据。

### Affected Modules

- 文档：外层 `docs/02.requirements/02.mes-multi-tenant-gaps.md`、`docs/03.design/04.mes-shared-db-tenant-plan.md`、`docs/04.specs/35`–`47`
- 后端：`startech-mes-basic/backend` 的 `ktg-common`、`ktg-framework`、`ktg-system`、`ktg-mes`、`ktg-admin`、`ktg-quartz`

- 禁止：`startech-mes-basic/frontend/`；`docs/superpowers/`

### Public Contracts

- 保持：`POST /login`、`GET /getInfo`、`GET /getRouters`、`Authorization: Bearer`、响应 `code/msg/data`（登录成功仍 `token` 字段）
- 变更：`LoginBody.tenantCode` **必填**；匿名 Host 解析接口（路径由 37/46 定，须 permitAll）；工厂 `getInfo` 可含 `tenantId`/`tenantName`
- 不新增可伪造且登录后仍生效的租户 Header 作为权威来源
- 平台租户 CRUD / JDBC 揭明文 / runAs / 许可：仅平台账号；精确 path 在 36/46 定（建议 `/platform/tenant`）

### Persistence Changes

- 新建：`sys_tenant`、`sys_tenant_license`（36）
- 身份/系统表加 `tenant_id`（37）
- MES 表按 40/42/43/44/45 分波加列
- `sys_config` 可空 `tenant_id`（36 或 37，与 D1 一致；缓存键组装在 38）
- 不改 `QRTZ_*` 列；`sys_job` 加 `tenant_id`（45）

### Transaction Boundaries

- 创建租户：基本信息（及 DATABASE 的加密 JDBC）一次事务；建 schema/迁表为后续步骤，失败不回滚登记（I6）
- 登录：查 `sys_tenant`（主库）→ 路由确认 → 查用户；失败不发 token
- 业务写操作保持现有 service 事务；拦截器在 SQL 层，不扩大事务范围

### Risks

- 拦截器漏表导致跨租户读写（高于一切）
- P-D 前若允许 DATABASE 登录，数据会写入共享库却自称专库
- DataScope / `isAdmin` 被误当成跳过租户
- Redis 空前缀、异步池化串上下文、文件 URL 未校验租户
- 专池打满 `max_connections` 或失败开放回落主库
- Vue2 登录在 P1 后不可用（已接受，须在发布说明中写明）
