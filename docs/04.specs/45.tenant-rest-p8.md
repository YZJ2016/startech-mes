## 1. Spec

### Capability

- Name: P8 其余 MES 租户表 + 按租户自动编码 + Quartz 租户上下文 + UReport JWT Filter（I1）
- Module: `startech-mes-basic/backend` 的 `ktg-mes`（剩余包 `report` / `task` / `msg` / `autocode` 及转盘/库位遗留表）、`ktg-quartz`（`AbstractQuartzJob` 完整租户+DS）、`ktg-framework` 或 `ktg-admin`（UReport Filter）；增量 SQL 仅 `backend/sql/`
- Priority: P1
- Related requirement/design documents:
  - 设计：`docs/03.design/04.mes-shared-db-tenant-plan.md`（阶段 P8、I1、S2、S3、S5、D5）
  - 缺口清单：`docs/02.requirements/02.mes-multi-tenant-gaps.md`
  - 总控：`docs/04.specs/35.mes-multi-tenant-program.md`
  - 上一单元：`docs/04.specs/44.tenant-cal-dv-tm-p7.md`
  - 下一单元：`docs/04.specs/46.tenant-frontend-p9.md`

### Business Goal

把 ktg-mes 尚未进拦截器 include 的租户表全部接管；自动编码按厂流水互不抢号；定时任务仅平台可管且执行时带租户并打到正确数据源；公告/铃铛按租户隔离且不做全厂群发；MES 报表与 UReport 只查当前租户，并由 Filter 从 JWT 注入上下文。完成后 ktg-mes 无漏网 Mapper 表。

### Scope

In scope:

- 盘点并接管剩余租户表：`mapper/report`（`ureport_file_tbl`）、`mapper/msg`（`sys_attachment`、`sys_message`、`sys_notice_detail`）、`mapper/autocode`（`sys_auto_code_rule` / `sys_auto_code_part` / `sys_auto_code_result`）
- `com.ktg.mes.task`（`ItemPurchaseTask` / `PurchaseTask` / `RemindTask` 等）：无独立建表，执行必须继承 `SysJob.tenantId` 上下文，不得另开无租户线程
- `backend/sql/turnplate.sql` 遗留：`md_turnplate_records`（`md_turnplate`、`pro_task_turnplate` 已分别归 P4/P5；若 40/42 未纳入 records 则本单元补列并进 include）
- `backend/sql/area.sql`：仅 ALTER `wm_storage_location` / `tm_tool`。对照 42/44 已接管名单；未加 `tenant_id` 则本单元补，已加则只核对 include，禁止重复 ALTER、禁止改历史 `area.sql`
- `sys_job` / `sys_job_log` 加 `tenant_id`（S2）；`QRTZ_*` 仍在主库、不加租户列；`ScheduleUtils` JobKey 含租户
- `AbstractQuartzJob`：`before` 用 `SysJob.tenantId` 设 `TenantContext` 并按隔离级别路由 DS（依赖 41）；`after`/`finally` 清理；无 `tenantId` 的任务不得碰租户业务表
- 公告路径（S5）：若 37（P1）已给 `sys_notice` / `sys_notice_detail` / `sys_notice_read` 加列，本单元只收口「无平台群发」与 include；若未做则本单元补列。v1 不做平台对所有工厂群发
- UReport I1：Servlet Filter 覆盖 `/ureportM/**` 与 `/ureport/**`，从 JWT 设 `TenantContext`（及 DS）；内置数据源与业务同一套租户路由；空上下文不得跑报表 SQL；`DATABASE` 专库报表失败关闭、禁止回落主库
- 拦截器 include 扩大到本波全部表；对照 ktg-mes 全部 Mapper XML 做漏表扫描
- 增量 SQL 只追加 `backend/sql/YYYYMMDD_NN_*.sql`（接当时最大序号）

Out of scope:

- 改 Java/SQL 以外的 Vue2 `frontend/`；本单元不改 Vue3（属 46）
- 跨租户报表、跨专库 JOIN、平台跨厂汇总（D5；属 47，v1 不立项）
- 工厂自助调度；给工厂许可定时任务菜单
- 改 `QRTZ_*` 表结构；把 `QRTZ_*` 拷进专库
- 引入 Jugg / Sa-Token / MyBatis-Plus / fail-open / 菜单克隆；API 回传 JDBC 明文口令
- MQ / Feign / OpenAPI 验签 / BPM；`request.js` 加 `X-Tenant-Id`
- 原地改写 `ry_*.sql`、`quartz.sql`、`mes-*.sql`、`turnplate.sql`、`area.sql`
- 把 I1 在本文件第 4 节标成代码已完成（实现未跑通前保持开放）

### Acceptance Criteria

对齐设计 P8 退出标准，须全部满足：

- include 名单覆盖 **全部** ktg-mes 租户表；无漏网 Mapper 表（以 Mapper XML 中的表名为准做差集，差集必须为空）
- 自动编码流水按租户递增（S3）：两租户夹具互不抢号；唯一键 `(tenant_id, rule_code)` 及对应流水键
- 定时任务仅平台可管理（S2）；工厂用户不可见定时任务菜单、调用任务 CRUD 接口 403；公告/铃铛按租户、v1 无平台群发（S5）
- Quartz 任务执行带租户并走正确 DS；无租户任务不能碰业务表（无 `tenantId` → 失败关闭，不执行租户 SQL）
- MES `report` 与 UReport 查询仅当前租户（D5）；Filter 已设 JWT 上下文；空上下文不得跑报表 SQL；`DATABASE` 专库报表不得回落主库（I1）
- `mvn -pl ktg-mes,ktg-quartz,ktg-framework -am test`（或聚合编译 + 本单元新建夹具测试）实际跑过；未跑通不得写「测试通过」

### Rules and Constraints

Tenant isolation:

- 本波表全部为租户表（禁止靠 `sys_` 前缀当全局）。`ureport_file_tbl`、`sys_attachment`、`sys_message`、`sys_auto_code_*`、`sys_job` / `sys_job_log` 均加 `tenant_id`
- 无 `TenantContext` 访问 include 表 → 拦截器抛错，不执行 SQL
- `DATABASE` 专库同一套 DDL 与拦截器；专库不可用禁止回落主库
- 平台任务行 `tenant_id=0`；平台为某厂配置的任务行 `tenant_id` 为该厂，执行切该厂上下文（I3）
- `task` 包任务与 `pro`/`tm` 定时入口不得 `new Thread()` 跑租户 SQL
- 报表 SQL 仅当前租户；禁止为「方便」忽略 `tenant_id`

Security and masking:

- 仅平台 `is_platform` 可建/改/删 `sys_job`；工厂 403。菜单永不许可给工厂（F3 同类：平台模块不给工厂）
- UReport 入口必须已认证 JWT；匿名不得跑报表 SQL
- 不在报表、任务日志、异常栈中打印 token、JDBC 口令、内部绝对路径
- 不引入第二套认证；不把客户端租户头当权威
- Filter 只从服务端已解析的 JWT/`LoginUser` 取 `tenantId`，忽略 Query/Header 自称的租户

Audit and lineage:

- 增量脚本可审查、可回滚；加列 `DEFAULT 1` 再回填空值
- `sys_job_log` 写入当前任务的 `tenant_id`；无租户任务不得写业务库日志冒充工厂
- 公告操作只落当前租户；不提供「群发全部工厂」接口或开关

AI/rule-engine rules:

- 本单元不涉及规则引擎或 AI

Database rules:

- 脚本只放 `startech-mes-basic/backend/sql/`，命名 `YYYYMMDD_NN_<topic>.sql`，接目录现有最大序号追加，禁止改历史文件
- 列：`tenant_id bigint not null`，现网回填 `1`
- 加 UNIQUE 前跑 `GROUP BY tenant_id, 业务键 HAVING COUNT(*) > 1`；0 则直接加；非 0 禁止 `ADD UNIQUE`（S4 窄）。本波至少覆盖 `sys_auto_code_rule.rule_code`
- `sys_auto_code_part` / `sys_auto_code_result` 流水唯一键必须含 `tenant_id`（与 rule 对齐，两厂互不抢号）
- `QRTZ_*` 不加 `tenant_id`、不进专库（I8 忽略名单已含，本单元不改该名单语义）
- `DATABASE` 租户：本波增量由应用打到专库（I6）；未迁成功则该租户本波不可用，不回落主库

## 2. Plan

### Implementation Approach

1. **漏表盘点（先于 DDL）**：枚举 `ktg-mes/**/mapper/**/*.xml` 中的表名，减去 P4–P7（40/42/43/44）已进 include 的表，得到本波清单。`task` 无 XML 则记「无表、只跟 Quartz 上下文」。差集为空才允许宣称「无漏网」。
2. **增量 SQL**：对本波表 `ADD tenant_id` + 回填 1；自动编码复合唯一键；`sys_job` / `sys_job_log` 加列。公告三表若 P1 未做则一并补。不改 `quartz.sql`。
3. **S3 自动编码**：`AutoCodeUtil` / Result 查询与递增全部带当前 `tenantId`；规则码唯一改为 `(tenant_id, rule_code)`。夹具：两租户同一 `rule_code` 各自从 1 递增。
4. **S2 任务管理**：`SysJob` 增加 `tenantId`；Controller 拒绝非平台；`getRouters` 侧依赖 39 不给工厂许可，本单元再加接口层 403。`ScheduleUtils.getJobKey` / `getTriggerKey` 纳入租户（组名或 identity 后缀），避免两厂同名任务互相覆盖。
5. **I3 收口执行路径**：`AbstractQuartzJob.before` 设上下文并路由 DS；`after` 清理（与现有 startTime ThreadLocal 并列，不用 `InheritableThreadLocal`）。无 `tenantId`：只允许调用 `@TenantIgnore` 的平台维护逻辑，否则失败关闭。`DATABASE` 目标打专池，失败不回落主库。
6. **S5 公告**：列表/推送/铃铛只当前租户；删除或禁用任何「全租户广播」代码路径；不接若依 3.9 已读 HTTP。
7. **I1 UReport**：在 `ktg-framework` 或 `ktg-admin` 注册 Filter，urlPatterns 含 `/ureportM/*` 与 `/ureport/*`。从 JWT 设 `TenantContext`（Security 链若已设则校验非空，空则拒绝）。改造 `UReportConfig` 内置数据源：连接必须来自租户路由器，禁止固定注入主池后对 `DATABASE` 静默用主库；`getConnection` 失败抛错，**禁止返回 null**（现状失败时返回 null 视为开放，必须改掉）。
8. **include 扩大** + 领域/Mapper 夹具测试：两租户报表文件、消息、编码、任务元数据互不可见。

### Affected Modules

- `ktg-mes`：`com.ktg.mes.report`（`UReportConfig`、`UreportFileTbl*`、`MySQLProvider`）、`msg`、`autocode`、`task`；必要时 `md` 的 `md_turnplate_records`
- `ktg-quartz`：`SysJob` / `SysJobLog`、Mapper XML、`SysJobController`、`ScheduleUtils`、`AbstractQuartzJob`、`QuartzJobExecution` / `QuartzDisallowConcurrentExecution`
- `ktg-framework` 或 `ktg-admin`：UReport/JWT 租户 Filter 注册；`SecurityConfig` 不得把 `/ureport/**`、`/ureportM/**` 配成可匿名跑 SQL
- `ktg-system`：仅当本单元补做 `sys_notice` / `sys_notice_read` 时
- `ktg-mes` 拦截器 include 名单（P0 引入的租户拦截器配置）
- 增量 SQL：`startech-mes-basic/backend/sql/`
- 不改：`startech-mes-basic/frontend/`、`ktg-generator` 业务、UReport vendor 源码目录（`ureport2-*`）除非 Filter 无法在应用侧完成（默认不改 vendor）

### Public Contracts

- HTTP 路径、method、`code/msg/data` 不变。报表预览 URL 仍只来自环境变量，文档不写真实主机
- `sys_job` API 仅平台；工厂调用保持现有 URL 但必须 403，不改路径
- 不新增客户端租户 Header；UReport 请求仍带既有 `Authorization: Bearer`
- 不新增「跨租户报表」或「群发全部工厂」API
- `ureport_file_tbl` 列表/设计器读写仅当前租户文件名空间（同名文件跨租户允许，靠 `tenant_id` 区分，S4）

### Persistence Changes

- `ureport_file_tbl`：`ADD tenant_id`，回填 1；唯一性改为含租户（以现网 `SHOW CREATE TABLE` 为准，禁止跑空的 `05` 文件）
- `sys_attachment`、`sys_message`：`ADD tenant_id`，回填 1
- `sys_notice_detail`（及若缺则 `sys_notice` / `sys_notice_read`）：`ADD tenant_id`；`uk_notice_user` 类唯一键改为含 `tenant_id`
- `sys_auto_code_rule`：唯一键 `(tenant_id, rule_code)`；`part`/`result` 对应流水键含 `tenant_id`
- `sys_job` / `sys_job_log`：`ADD tenant_id`；现网回填：已有任务属平台则 `0`，或按产品确认回填 `1` 后仅平台可再改归属——**实现时：种子/现网任务回填 `tenant_id=0`（平台），禁止把调度元数据当成工厂 1 的自助任务**
- `md_turnplate_records`：若尚未加列则本单元加；已加则只进 include
- 不改 `QRTZ_*`

### Transaction Boundaries

- 自动编码取号：同一租户内短事务递增流水，事务边界保持现有 `AutoCodeUtil` 服务方法，不扩大到跨租户
- 任务 CRUD：写 `sys_job` 与注册 Quartz JobKey 同一服务事务；失败不留下「库有行、调度器无 Job」或反向（沿用现有补偿，只加租户维度）
- Quartz `execute`：`before` 设上下文 → `doExecute` → `unbind` → `after` 写 `sys_job_log`（主库，带 `tenant_id`）→ `finally` clear + unbind。写日志失败不得把上下文留给线程池
- UReport Filter：请求进入设上下文，`finally` 清理；不在 Filter 里开业务事务

### Risks

- Mapper 漏表导致报表/附件/编码跨租户读写（本单元最高风险）
- `UReportConfig` 固定主 `DataSource` 或 `getConnection` 返回 null → `DATABASE` 失败开放或空指针后静默
- Filter 未覆盖设计器 `/ureport/**`，仅盖了 `/ureportM/**`
- JobKey 不含租户，两厂同名任务互相覆盖或停错任务
- 无 `tenantId` 的历史任务仍跑 `RemindTask` 等业务 SQL
- 工厂仍能从直打 API 管理 `sys_job`（只藏菜单不够）
- 误把 `QRTZ_*` 加列或拷进专库，打乱 I8
- 把 I1 产品已拍板当成代码已完成

### Verification Strategy

- 静态：rg 全部 ktg-mes Mapper XML 表名 vs include 名单，输出差集（必须空）
- 单测/夹具：两 `ROW` 租户编码流水独立；租户 1 看不到租户 2 的 `ureport_file_tbl` / `sys_message` 行
- Quartz：带 `tenantId` 的 Job 执行后上下文正确且 `after` 清空；`DATABASE` 夹具（若 41 已完成）SQL 落专库；无 `tenantId` 的 Job 调用业务 Mapper 抛错
- UReport：无 JWT 或上下文空访问 `/ureport/*` 或 `/ureportM/**` 不得执行业务 SQL；专库不可用时内置数据源失败且主库无该租户报表查询
- 工厂账号调用 `SysJobController` 写接口 → 403
- 公告：租户 1 发的通知租户 2 铃铛不可见；不存在向全部 `tenant_id` 插入的代码路径
- 命令见第 4 节；未执行前保持「未执行」
