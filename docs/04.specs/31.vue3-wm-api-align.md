# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: Vue3 仓库域（wm）API 与 ktg-mes wm Controller HTTP 对齐
- Module: `startech-mes-basic/startech-mes-front/src/api/mes/wm`；只读对照 `startech-mes-basic/backend/ktg-mes` wm Controllers
- Priority: P0
- Related requirement/design documents:
  - 总控：`docs/04.specs/27.vue3-backend-api-align-program.md`
  - 缺口：`docs/02.requirements/01.vue3-backend-api-gaps.md`（**D-wm**）
  - 调研：`docs/03.design/03.vue3-backend-api-align-survey.md`

### Business Goal

让 Vue3 管理端仓库 API 的 URL+method 接到换壳后后端已经挂上的 wm HTTP，避免仓储页打到不存在的路径或用错动词。后端缺 mapping 的 Vue2 调用只记缺口，不补 Java。

### Scope

In scope:

- 静态对齐 `startech-mes-front/src/api/mes/wm/**` 与 `ktg-mes` 包 `com.ktg.mes.wm.controller` 的 HTTP mapping
- 归一：类 `@RequestMapping` + 方法 mapping；路径变量统一 `{id}`；忽略末尾 `/`
- Vue3 与后端不一致且后端已有对应 mapping 时，只改 Vue3 URL+method
- Vue2 已调用但后端无 mapping 的路径记入本文件第 4 节与清单 **D-wm**，不新增 Java
- 已匹配的 URL 不改

Out of scope:

- 改 Vue2 `frontend/`
- 改 Java、库表、MES 库存/单据状态机
- 改 lock / notice / login / upload / 其他 mes 域（md、pro、qc、cal、dv、tm、sale、report 等）
- 为平板/mobile 的 `/mobile/wm/**`、`listForPad`、`infoForPad` 等补管理端封装（本仓库无 pad 端）
- 把 `itempurchase.js` 挪到 tm，或把 `/md/salse` 从 `src/api/mes/sale` 挪进 wm
- 提交 lockfile；声称运行时通过（无本地后端）

### Acceptance Criteria

- Vue3 `src/api/mes/wm` 中打 ktg-mes 的 `request()` URL+method，在归一后与对应 Controller mapping 一致；本已一致的条目未被改写
- 后端不存在的 Vue2 路径只出现在缺口记录中，没有为此新增 Controller
- 第 4 节有完整静态清单与命令证据
- 无本地后端时运行时写「未验证」
- 文档与补丁无真实主机、口令、Token

### Rules and Constraints

Tenant isolation:

- 不改数据隔离方式

Security and masking:

- 不在文档中复述打印 agent 主机、Token、库口令
- Vue3 条码打印继续走 `VITE_APP_PRINT_AGENT_URL`，不写死地址

Audit and lineage:

- 对齐是接契约，不改仓储单据状态机
- 不把历史 `docs/superpowers/specs/` 当现行契约

AI/rule-engine rules:

- 不涉及

Database rules:

- 不改表、不执行 SQL

## 2. Plan

### Implementation Approach

1. 从 Vue3/Vue2 `src/api/mes/wm` 与 `ktg-mes` wm `*Controller` 抽出 URL+method，按调研归一规则对照
2. Vue3 与 wm Controller 不一致且后端已有 mapping → 只改 Vue3
3. Vue2 已封装但任何 Controller 都无 mapping → 记缺口，不补 Java，不改已匹配 URL
4. 物理放在 wm 目录、实际打 tm `/mes/purchase` 的封装：已匹配 tm 的保持；无 mapping 的列入 D-wm
5. 回填本文件第 4 节；用具体剩余项替换清单 **D-wm** 占位句

### Affected Modules

- 文档：`docs/04.specs/31.vue3-wm-api-align.md`；清单 **D-wm** 一条
- 代码：仅在发现可对齐的 Vue3 差集时改 `startech-mes-front/src/api/mes/wm/**`
- 只读：`backend/ktg-mes/.../wm/controller`、`TmPurchaseController`（`/mes/purchase`）、Vue2 `frontend/src/api/mes/wm`
- 禁止：Vue2 源码、Java、lock/notice/login/upload、其他 mes 域 API

### Public Contracts

- 仓库主路径：`/mes/wm/{warehouse|area|location|wmstock|barcode|barcodeconfig|issueheader|issueline|itemrecpt|itemrecptline|itemconsume|itemconsumeline|productrecpt|productrecptline|productproduce|productproduceline|productsalse|productsalseline|package|packageline|rtissue|rtissueline|rtvendor|rtvendorline|rtsalse|rtsalseline|transfer|transferline|sn}/**`
- 执行类：`PUT /mes/wm/{resource}/{id}`（领料/入库/出库/退料/退货/转移等 `execute`）；`PUT /mes/wm/itemrecpt/confirm`；`PUT /mes/wm/package/addsub`
- `itempurchase.js` 实际契约在 tm：`/mes/purchase`（`TmPurchaseController`），不是 wm Controller
- 仍为 Bearer JWT 与 `code/msg/data`；列表 `rows/total`

### Persistence Changes

- 无

### Transaction Boundaries

- 无

### Risks

- 把 `/mes/purchase` 误改成某个 `/mes/wm/**` 会打坏物料采购单
- 把 `productionConfirm`/`lackList` 改接到 `/mes/tm/purchase/**` 会串到工装采购
- 静态脚本把 `{warehouseId}` 与 `{id}`、或空 method mapping 报成缺失
- 无本地后端时无法做仓储页冒烟

### Verification Strategy

静态必做：归一后的 URL+method 对照 + Vue2/Vue3 文件差。运行时仅当本机后端可连；否则第 4 节写未验证。
