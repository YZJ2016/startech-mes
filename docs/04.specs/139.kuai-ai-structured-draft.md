# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: S6 — `structured_draft` 换 `with_structured_output`
- Module: **仅** `kuaigeyun-mes` 的 `core/ai/structured_draft.py`（白名单内）+ 经 S2 `runtime/model_factory` 解析模型。**禁止**改其它 `core/ai`；**禁止**绑 DeepSeek SDK。
- Priority: P2（KR-X6；依赖 S2 `model_factory`）
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/16.kuai-ai-rebuild-gaps.md`（KR-D13、KR-X6）
  - 设计：`docs/03.design/16.kuai-ai-rebuild-plan.md`（§6 路径 C、§15 S6）
  - 依赖：`135.kuai-ai-runtime-agent.md`

### Business Goal

结构化草稿主路径改为 `ChatOpenAI.with_structured_output(Pydantic)`（目录行优先），删除字符串抠 JSON 主路径；图片走多模态 content block（vision 目录行或同工厂兜底），不再绑 `deepseek_vision_client` / DeepSeek SDK。

### Scope

In scope:

- 改 `structured_draft.py`：`complete_json`（或等价入口）→ `build_chat_model` / vision 工厂 → `with_structured_output` → 校验过的 pydantic 对象
- 删/停用 `extract_json_object` 主路径依赖
- 图片：多模态 content block；vision 目录行优先，同工厂兜底（OpenAI 兼容，非 DeepSeek SDK）
- 保持现有对外调用方可用（签名尽量兼容；若必须微调仅限内部，产品信封不变）

Out of scope:

- 新前端页；确认闸；工作流；知识/MCP/会话新功能
- 恢复字符串抠 JSON 为主路径；按厂商分支 SDK
- 改 `chat_handler` 契约；改 `/ai/**` 或 `code/msg/data`
- HyDE、OCR 扫描件产品化、审计查询页

### Acceptance Criteria

1. 主路径使用 `with_structured_output`；不再依赖字符串抠 JSON 作为主路径。
2. 模型经 `model_factory`：目录行优先，兜底 OpenAI 兼容，无 DeepSeek SDK。
3. 图片走多模态 block + vision/工厂；无 `deepseek_vision_client` 绑定。
4. 失败有明确错误；日志无 Key；租户上下文失败关闭。
5. 不改产品 REST 表与权限码字符串。

### Rules and Constraints

Tenant isolation:

- 工厂解析带 `tenant_id`；空上下文不得出站。

Security and masking:

- 与 KR-I5 一致。

Audit and lineage:

- 沿用既有 core AI 审计中间件覆盖范围（若入口仍在 `/api/v1/core/ai`）。

AI/rule-engine rules:

- 仅结构化输出，不接 Tool 循环、不接确认闸。

Database rules:

- 无新表。
