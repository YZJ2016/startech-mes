### Business Goal

管理员用设计器选择数据源、列、筛选、格式和合计，新建 `category=custom` 的账表并写入 `report_config`，同时在已有版本表留下一份快照。保存后的账表能用 145 的 `executeReport` 预览。本段不是大屏设计器，也不提供版本回看或恢复。

### Scope

In scope:

- 新建账表由本切片写入 `category='custom'` 与 `report_config`。146 只种 KRP-D6 的 10 张系统报表，不向本切片提供自定义报表行。
- 设计器写入 `apps_kuaireport_reports.report_config`。可编辑内容：一个已登记数据源、列、筛选、格式、合计。保存结果必须能被现有 `UniReport` 的 `ReportConfigSchema` 读到，含已有的 `page_size`、`fields`、`filters`、`extra.uni_report.summaryFields`。一份账表只引用一个已登记数据源。绑定唯一键是 `report_config.extra.data_source_uuid`（本租户 `apps_kuaireport_data_sources.uuid`），不用顶层整数 `data_source_id`。
- 数据源只能选已登记的 `apps_kuaireport_data_sources` 行（`static` / `dataset` / `http`）。保存结果里仍然没有 SQL 正文。
- 每次成功保存插入 `apps_kuaireport_report_versions` 一行：`report_id`、`version_no`、`snapshot`（JSONB）、`tenant_id`。`snapshot` 就是当时的 `report_config` 裸对象，不包一层。唯一约束已是 `(tenant_id, report_id, version_no)`。
- 同步递增报表表上已有的 `current_version`（迁移 563，默认 `0`）。`version_no` 与 `current_version` 对齐，不另造版本号列。
- 保存后的预览仍走 `UniReport` config 模式与 `executeReport`。
- KRP-D6 的系统报表可以被打开查看；本切片不要求用设计器重画这 10 张，也不把它们改成非 `system`。

Out of scope:

- 编辑 `layout_config`、`widgets_config`、`theme_config`、`tv_config`（148）
- 版本列表、对比、恢复（149）。本切片只写入快照，不提供恢复操作。
- 分享、口令、授权、订阅
- 数采
- 新造版本表或改迁移 563 的文件名

### Acceptance Criteria

1. 设计器保存后，新建行的 `category` 为 `custom`。`report_config` 能被现有 `UniReport` 的 `ReportConfigSchema` 读到，含已有结构 `page_size`、`fields`、`filters`、`extra.uni_report.summaryFields`。一份账表只引用一个已登记数据源，绑定唯一键是 `report_config.extra.data_source_uuid`，不用顶层整数 `data_source_id`。配置不含 SQL 正文。
2. 同一次保存新增一条 `apps_kuaireport_report_versions`。`snapshot` 就是当时的 `report_config` 裸对象，不包一层，`version_no` 等于保存后的 `current_version`。
3. 再次保存使 `version_no` 增加，不覆盖上一条快照（唯一约束不允许同一租户、同一报表、同一版本号两行）。
4. 用保存后的 `reportId` 调用 `executeReport`，返回 `data` / `total` / `summary`。
5. 本切片没有大屏编辑页，也没有「恢复到某一版」的操作。

### Rules and Constraints

Tenant isolation:

- 版本行的 `tenant_id` 必须等于报表行的 `tenant_id`。不能把别的租户的数据源 uuid 写入 `report_config.extra.data_source_uuid`。

Security and masking:

- `snapshot` 不写入 SQL 正文、连接密文或口令。

Audit and lineage:

- 版本行使用已有 `created_by_user_id` 与 `note`。`note` 可空。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 只插入 `apps_kuaireport_report_versions`，不插入 `apps_kuaireport_dashboard_versions`。
- 不改已入库迁移。

### 依赖顺序

- 依赖 145 的数据源与执行。146 种入的系统报表可被打开查看；`category=custom` 的报表行由本切片新建。
- 不依赖 148、149。

## 2. Plan

### Implementation Approach

1. 设计器表单收集一个数据源、列、筛选、格式、合计，按现有 `ReportConfigSchema` 写回 `report_config`（含 `page_size`、`fields`、`filters`、`extra.uni_report.summaryFields`）。绑定唯一键是 `report_config.extra.data_source_uuid`，不用顶层整数 `data_source_id`。新建行 `category='custom'`。账表版本 `snapshot` 就是当时的 `report_config` 裸对象，不包一层。
2. 保存与插入版本行、更新 `current_version` 在同一事务。
3. 预览按钮把当前配置交给已有 `UniReport`，不另做表格。

### Affected Modules

- `riveredge-backend/src/apps/kuaireport`（报表保存与版本插入）。路由挂载保持只扫描 `api/slices/`。146、147、149 通过该目录转出 router。
- `riveredge-frontend/src/apps/kuaireport`（账表设计器页）。前端入口是 `apps/kuaireport/index.tsx`。
- 只读：`UniReport.tsx` 的 config 模式

### Public Contracts

- 执行契约仍是 145 的 `executeReport`。设计器不新增第二种预览返回形态。

### Persistence Changes

- 无新表。更新 `apps_kuaireport_reports.report_config` 与 `current_version`。插入 `apps_kuaireport_report_versions`。

### Transaction Boundaries

- `report_config` 更新、`current_version` 递增、版本行插入同一事务。任一步失败则配置与版本号都不前进。

### Risks

- 只更新 `report_config` 不写版本行，则 149 的账表回看没有快照。
- 在 `snapshot` 里复制数据集 SQL，违反 KRP-D3。

### Verification Strategy

- 见 §3。§4 实跑后填写。本文件写下时未跑命令。
