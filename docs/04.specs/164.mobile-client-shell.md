# 星制造移动端 — 壳

本文件可实施。只做工程、登录、工作台和注册机制。五个 scope 的业务页分别是 `165` 至 `169`。那些单元只往本壳的 registry 和 `pages.json` 追加自己的包，不改登录、请求头和工作台渲染。

### 已拍板

1. 适配目录是 `shared/channel/`，不用工程根上的 `platforms/`。官方编译器文档写明该目录只放各端页面。
2. scope 列表来自已安装 feature 包，壳不写死五个名字。某 scope 的 workbench 返回空列表时不显示该分区。某一个 scope 请求失败时，该分区显示错误，其它 scope 照常显示。
3. `pages.json` 管编译期页面，registry 管运行时有没有包。165 至 169 追加页面时两处一起改。
4. 登录只走现有 `POST /api/v1/auth/wecom/callback`。本单元只接通 H5 的 `GET /api/v1/auth/wecom/authorize-url`。小程序和 App 的取码函数返回未接通，不签发令牌。
5. 组织顺序：URL 查询参数 `tenant_id`，否则 `GET /api/v1/auth/wecom/bootstrap-tenant`，否则本机记住的组织。`bootstrap-tenant` 请求失败与返回 `tenant_id: null` 一样，回落本机组织；本机也没有才搜索。多组织用 `GET /api/v1/tenants/search`。多于一个启用企微组织时客户端不猜测。回调不把 `user.tenant_id` 或 `default_tenant_id` 写成组织。
6. 源码包在 `features/{scope}/{key}/`。`pages.json` 的 path 指向这个目录下的页面，只给编译器。工作台点击和 H5 打开后，地址栏是 `/mobile` 加上 manifest 的 `route`（含 `uuid`、`my=1` 这类查询）。壳把去掉 `/mobile` 前缀后的路径对照 registry 里的 route，打开对应页面，并把查询传给页面。route 上没有的查询不参与是否匹配；同时匹配时，声明了更多查询的 route 优先（`/mes?my=1` 优先于 `/mes`）。manifest route 不是接口路径。Caddy 已公开的设备地址也是这些 route。
7. 渠道函数按平台返回 `mobile_h5`、`miniprogram`、`android`、`ios`。不发 `h5`、`expo_android` 等别名。未接通的端没有令牌，发请求前不假装已登录。
8. 工作台格子读响应 `icon`。`icon_group` 有值才保留，现网没有该字段时不补造。没有对应字形时仍显示 `label`。`apps/` 只占位，不进五个 scope 的 registry。
9. 登录回调在令牌被保留时，把 `user` 的 `id`、`full_name`、`username` 写入本机 `user_info`。不从 `user.tenant_id` 或 `default_tenant_id` 写组织。清除令牌时同时清除 `user_info`。
10. `API_ORIGIN` 只来自已跟踪的 `shared/api/origin.uts`。空字符串表示请求走相对 `/api/v1`。本机换源只改这个文件，且不把地址提交。被忽略的 `origin.local.uts` 没有被导入，改它不改变请求源。

### Acceptance Criteria

1. 工程根是 `kuaigeyun-mes/kuaigeyun-client/riveredge-app-mobile`，`manifest.json` 仍是蒸汽模式。由 `kuaigeyun-mes` 跟踪，与工位壳相同。
2. 已登录 H5 请求带三个头，渠道为 `mobile_h5`。渠道函数还能返回 `miniprogram`、`android`、`ios`，与 `mobile_h5` 并列，不发 `h5`、`expo_android` 等别名。小程序和 App 取码未接通，不能进入工作台，发请求前不假装已登录。
3. 页面在三端的 registry 与 `pages.json` 都注册。业务操作的验收只在已登录 H5 上进行。小程序和 App 因取码未接通，不要求走通业务页。
4. 工作台每次请求都带 scope。scope 集合等于已安装包的声明。空列表不出现。分区 `title` 为空时不显示分区名。`solo_row` 为真时该格单独成行。格子读响应里的 `icon`。`icon_group` 有值时保留，现网没有该字段时不补造。没有对应字形时仍显示 `label`，不崩溃。
5. 声明了 `badge` 的 scope 显示 `pending_fault_count` 与 `overdue_maintenance_reminder_count`。这两个数来自包提供的读取函数，壳不算。`in_workbench` 为 `false` 的 route 能按 URL 打开，且不出现在宫格。
6. manifest 或发行说明记录：Android 蒸汽模式最低 Android 6.0+（HBuilderX 5.21+），iOS 最低 iOS 15+（HBuilderX 5.11+），微信基础库大于 3.7.1。业务页不按这些门槛分叉。
7. `apps/` 目录存在，并写明好力 GO 以后放这里、现在不做页面。五个 scope 的 registry 不包含它。
8. 响应里有入口、registry 没有该 key：显式空态，不崩溃，也不把该格藏掉。
9. `./fast-deploy/launch.dev.sh with-h5`、`me`、`h5` 都不再要求 `riveredge-app/mobile/package.json`，也不执行 uni-app x 编译，不启动 Expo。
10. 仓库和界面没有口令、令牌、密钥或生产地址。`API_ORIGIN` 的空字符串留在已跟踪的 `origin.uts`。
11. 令牌保留后，本机 `user_info` 只有回调 `user` 的 `id`、`full_name`、`username`。组织仍只按第 5 条写入。

### Rules and Constraints

Tenant isolation:

- 沿用 `X-Tenant-ID`。多组织不猜测。

Security and masking:

- 令牌只在本机存储。H5 接口基址用相对路径 `/api/v1`。本机调试若要别的源，用未提交的本地配置，仓库只留不含地址的示例。

Audit and lineage:

- 不新写审计。写请求带 `Idempotency-Key`，与 `riveredge-frontend/src/services/api.ts` 相同。

AI/rule-engine rules:

- 不涉及。

版本门槛:

- 数字以设计第 3 节为准：Android 蒸汽模式最低 Android 6.0+（HBuilderX 5.21+），iOS 最低 iOS 15+（HBuilderX 5.11+），微信基础库大于 3.7.1。记在 manifest 或发行说明。不在业务页分叉。

Database rules:

- 无新表，无新迁移。

## 2. Plan

### Implementation Approach

1. 上移蒸汽工程到设计目录，由 `kuaigeyun-mes` 跟踪。不 `git init`，不把该目录写入 `.gitignore`。
2. HBuilderX 插件市场安装 uni-ui x 1.0.5 到 `uni_modules`。
3. `shared/api` 发请求。体为 `{ success, data }` 时取出 `data`。工作台响应模型是分区列表。格子读 `icon`；响应带 `icon_group` 时保留，没有则不补造。包声明了 `badge` 时，壳调用该包的读取函数，只显示返回的两个数。
4. H5 完成授权跳转和回调换票。签名只调 `GET /api/v1/core/mobile-jsapi/signature`，`provider` 仅 `wecom`、`dingtalk`、`feishu`。渠道函数按平台返回四个正式码。只有 H5 走通取码。
5. feature 包按下面的包合同导出声明。壳只汇总已导入的包。`in_workbench` 为 `false` 的 route 只按 URL 打开。本单元可以没有任何业务包；此时有权限的入口全部空态，用来验收 **MOB-Q7**。
6. 留下 `apps/` 占位。manifest 或发行说明写入设计第 3 节的版本门槛。
7. 改 `launch.dev.sh` 的 `with-h5` 说明：H5 由本机 HBuilderX 发行。

### 给 165–169 的包合同

每个业务目录导出一份声明，壳不解析业务字段：

- `scope`：`workshop`、`warehouse`、`quality`、`equipment`、`mold` 之一
- `key`：manifest 入口 key。深链可以没有宫格 key，但必须有 `route`
- `route`：manifest 里的 route 字符串
- `platforms`：`h5`、`mp-weixin`、`app`，首批三个都写上
- `in_workbench`：`false` 表示深链，不进宫格，仍按 URL 打开。缺省视为进入宫格
- `badge`：可选。有该声明时，包提供读取函数，只返回 bootstrap 的 `pending_fault_count` 与 `overdue_maintenance_reminder_count`。壳只显示这两个数，不算

168 使用这里的 `badge` 与 `in_workbench`，不修改壳的渲染实现。
