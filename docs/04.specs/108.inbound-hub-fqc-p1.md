- 成品入库执行（及若产品要求则确认）卡 FQC；规则落领域 service，禁止只在前端判断

### Acceptance Criteria

- 无 `TenantContext` 不得访问 wm/qc；闸 SQL 带 `tenant_id`

- toast/API 不打印 JDBC、cipher、内部路径

Audit and lineage:

- 新 DDL 只进 Flyway `db/migration/{master,tenant}`；不改历史 `backend/sql/`
- 不占用入库 P0 已用版本号 `V20260915.01` / `V20260915.02`

AI/rule-engine rules:

- 不涉及

Database rules:

- 未拍板真源前 **零业务表**；拍板后仍不加金额列（IH-G5 / 110）
- 配置不进 yml

## 2. Plan

### Implementation Approach

- **现在：** 只维持本 spec。不改业务仓。
- **门禁后：** 对照 105 物料闸的「预览 GET + 执行前同一规则」，接到成品执行；禁止拷快格云 FQC ensure 源码。

### Affected Modules

- 门禁后：`ktg-mes` wm/qc；Flyway；Vue3 仅 `inboundhub` 抽屉
- 不改：`frontend/`、`kuaigeyun-mes/`、105 的 IQC 键与 itemrecpt 闸

### Public Contracts

- 保持：`/mes/wm/productrecpt/**` URL/method/信封；成品执行失败可多一种业务 error（与 105 物料闸同口径）
- 增量：闸预览 GET（路径实现时定，不替换旧 list）

### Persistence Changes

- 未拍板：无
- 拍板后：按真源加可空关联列或配置键；master 种子闸键

### Transaction Boundaries

- 闸失败则不调用成品过账

### Risks

- 未确认真源就建 `qc_fqc`（禁止）
- 把 OQC/出库打进本单元
- 改 `productrecpt/index.vue` 布局（违反 UI-A）

### Verification Strategy

- 门禁未开：第 4 节保持「未跑」
- 门禁后：单测闸；实跑 `mvn` / `npm run build:prod` 后写入第 4 节
