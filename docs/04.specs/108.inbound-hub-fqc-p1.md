### Business Goal

成品入库在 Hub 仍可见（105 已做）。本单元在产品确认 FQC 单据真源之后，让必检成品未合格不得过账。物料入库 IQC 闸保持 105 语义。旧产品入库 URL 保留。

**FQC 真源拍板：** 现网 `qc_ipqc` 且 `ipqc_type=FQC`（终检）。**不是**过程检验 FIRST/FINAL/SELF/PATROL/CHECK，**不**新建 `qc_fqc`。合格语义与 IQC 同：`ACCEPT` 且非 `PREPARE`。无 FQC 模板不挡。配置键独立：`mes.wm.inbound.fqc.gate.confirm` 默认 `off`，`mes.wm.inbound.fqc.gate.execute` 默认 `on`（缺失/非法同 IQC：确认当 off、执行当 on）。**禁止**复用 `mes.wm.inbound.iqc.gate.*`。半成品仍 IH-G10，本单元不做。

### Scope

In scope（**仅当编码门禁满足**）:

- 成品入库执行（及若产品要求则确认）卡 FQC；规则落领域 service，禁止只在前端判断
- Hub 抽屉成品行增加闸预览（UI-A：只动 Hub 抽屉，不重排 `productrecpt`/`iqc`）
- 配置走 `sys_config`，不写 yml；键名实现时按 105 双闸风格另定，**禁止**复用 `mes.wm.inbound.iqc.gate.*`
- 单测：无模板放行；闸 on 且未合格拒绝过账；闸 off 与今日成品过账一致

Out of scope:

- 改 105 已交付的 IQC 闸 / Hub list 契约
- 臆造 `qc_fqc` 表（真源已拍板：终检 `qc_ipqc.ipqc_type=FQC`）
- 出库 Hub / OQC（OH-G2）、8D/SPC、CAT-Q03
- 半成品类型及其 FQC 闸（故意后开、**无新 spec 号**：缺口 14 **IH-G10**；不扩大本单元成品范围）
- 入库金额（110）、Hub 打印（111）、历史回填（109）
- 其他入库 / 还料 / 客供 / 拉单 / 撤回 / 委外（IH-G7–G13，不进 104 TOC）
- 改 Vue2、改壳、改 `/index`、改行业包、扩 permitAll

### Acceptance Criteria

- **编码门禁（已满足）：** 开工会话点名 108；FQC 真源拍板为 `qc_ipqc.ipqc_type=FQC`（不是过程检验、不建 `qc_fqc`）。
- 有 FQC 模板绑定的成品行在执行闸 on 时未合格不得 `processProductRecpt`（`PUT /{recptId}` 与 `PUT /entry` 均卡）；无模板不挡；旧 `GET /mes/wm/productrecpt/list` 与执行 URL/method 不变
- 闸按 `(qc_ipqc.recpt_id, item_id, ipqc_type=FQC)` 匹配本张成品入库单；禁止只按 `itemId` 挂上其他入库单的终检
- **写路径 + 失败关闭：** Hub（或从 Hub 打开 IPQC 新增）创建/更新 `ipqc_type=FQC` 时，`POST/PUT /mes/qc/ipqc` 只持久化本租户已加载成品入库单的 `recpt_id`（`QcIpqcRecptBinder`，不信客户端裸 ID；缺失/错租户拒绝）。匹配与执行闸对 `recpt_id` NULL 仍失败关闭；该关闭发生在操作员已能建出挂单终检之后。
- 第 4 节未跑命令不得写绿

### Rules and Constraints

Tenant isolation:

- 无 `TenantContext` 不得访问 wm/qc；闸 SQL 带 `tenant_id`
- 只信 JWT；无客户端租户头

Security and masking:

- 新 GET 必 `@PreAuthorize`；不进 `MesPermitAllProvider`
- toast/API 不打印 JDBC、cipher、内部路径

Audit and lineage:

- 新 DDL 只进 Flyway `db/migration/{master,tenant}`；不改历史 `backend/sql/`
- 不占用入库 P0 已用版本号 `V20260915.01` / `V20260915.02`

AI/rule-engine rules:

- 不涉及

Database rules:

- 未拍板真源前 **零业务表**；拍板后仍不加金额列（IH-G5 / 110）
- 配置不进 yml

## 2. Plan

### Implementation Approach

- 对照 105 物料闸的「预览 GET + 执行前同一规则」，接到成品执行与 `PUT /entry`；禁止拷快格云 FQC ensure 源码。产品入库无确认步，`requireConfirm` 仅供预览/确认键 on 时语义与 IQC 同口径。

### Affected Modules

- 门禁后：`ktg-mes` wm/qc；Flyway；Vue3 仅 `inboundhub` 抽屉
- 不改：`frontend/`、`kuaigeyun-mes/`、105 的 IQC 键与 itemrecpt 闸

### Public Contracts

- 保持：`/mes/wm/productrecpt/**` URL/method/信封；成品执行失败可多一种业务 error（与 105 物料闸同口径）
- 增量：闸预览 GET（路径实现时定，不替换旧 list）

### Persistence Changes

- 未拍板：无
- 拍板后：`qc_ipqc.recpt_id` 可空关联成品入库单（tenant Flyway）；master 种子闸键。不建 `qc_fqc`

### Transaction Boundaries

- 闸失败则不调用成品过账

### Risks

- 未确认真源就建 `qc_fqc`（禁止）
- 把 OQC/出库打进本单元
- 改 `productrecpt/index.vue` 布局（违反 UI-A）

### Verification Strategy

- 门禁未开：第 4 节保持「未跑」
- 门禁后：单测闸；实跑 `mvn` / `npm run build:prod` 后写入第 4 节
