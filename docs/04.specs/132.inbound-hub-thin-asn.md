### Business Goal

仓管有一张 **仓储收货通知单**（ASN）：从现网可读采购订单生成，通知计划收货，**不写库存事务**。入库 Hub 可从该单拉出物料入库 `PREPARE` 草稿。IQC / 过账仍打在 `wm_item_recpt`。

**本单元名称必须带「薄 ASN」。** 文档、菜单中文、PR、§4 不得写成「已交付整套收货通知 / 采购协同」。整套 ASN（申请、询价、订单变更、到货预警、供应商协同闭环）是 **后续必做**，缺口 **IH-G15** / CAT-U01 余量，不在本文件编码。

### Scope

In scope（仅当点名 132）:

- 新表 **`wm_receipt_notice` + `wm_receipt_notice_line`**（Startech 命名；禁止快格表名）
- 头：采购订单 ID、供应商、计划仓/日期、状态（待收货 / 已通知 / 已关联入库 — 映射现网字典或本单元业务态，**不**引入第二套 `review_status` 审核引擎）
- 行：物料、通知数量、可选单价/行金额、采购订单行 ID
- REST `/mes/wm/receiptnotice`（+ line）；一步保存；**无** `process*` 库存
- Vue3 CRUD 页 + 菜单（空号段编码时核目录）；UI-A 不重排旧 `itemrecpt`
- 126 加法：源类型 `receipt_notice` → 目标 `ITEM_RECPT` 草稿；可拉量 ≤ 通知数量 − 已拉入库
- 126 已有「采购订单直拉入库」**保留**（薄 ASN 是可选中间单，不是唯一入口）

Out of scope（**整套 ASN / CAT-U01 余量，后续必做，禁止本单元偷渡**）:

- 采购申请、询价、订单变更、到货预警、供应商门户
- 用 `sys_notice` 当 ASN；用 113 `wm_delivery_notice` 当收货通知
- 收货通知过账加库存；在通知单上卡 IQC
- 打印设计器、审核流、Demand
- 改 Vue2、扩 PermitAll、拷快格打印/前端框架

## 2. Plan

### Implementation Approach

1. 点名 132 后：tenant/master Flyway → CRUD → 拉单臂 → Vue3。
2. 对照快格「采购创建、通知仓库、不直接动库存」；不拷模型源码。
3. 编码完成后回写缺口 14 IH-G14-code；**不**勾 IH-G15。

### Affected Modules

- `ktg-mes` wm；`ktg-system` Flyway；`startech-mes-front` 新页 + `inboundhub` 拉单菜单加法
- 126 facade 加法源类型；不重开 126 其它源

### Public Contracts

- 增量：`/mes/wm/receiptnotice/**`、`/mes/wm/receiptnoticeline/**`
- 126：`GET/POST /mes/wm/inboundpull/receipt_notice`
- 保持：`/system/notice/**`、`/mes/wm/deliverynotice/**`、`/mes/wm/itemrecpt/**` method/信封

### Persistence Changes

- tenant：两表 + 索引 `(tenant_id, notice_code)`、`(tenant_id, purchase_order_id)`
- master：菜单；无 `sys_role_menu` 自动授权

### Transaction Boundaries

- 保存通知单与拉单建入库草稿分事务；拉单失败不改通知已入库态
- 通知单关联入库后更新状态；撤回入库（127）时是否回退通知态 = 编码时读 127，默认：入库撤回则通知回到可拉（须单测）

### Risks

- 被写成「CAT-U01 已开」从而偷运申请/询价
- 与 113 送货单菜单/文案混淆
- 通知数量与 PO 可收量、已拉入库三重不一致

### Verification Strategy

- 单测：租户隔离、零库存、超量拉拒绝、PO 直拉仍绿
- `npm run build:prod`；未跑不得写绿
