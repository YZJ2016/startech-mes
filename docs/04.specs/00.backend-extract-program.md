# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 后端换壳前分叉抽出（总控）
- Module: `startech-mes-basic/backend` 平台模块 → `ktg-mes`
- Priority: P0
- Related requirement/design documents:
  - `docs/04.specs/01.extract-mes-constants.md` 至 `09.platform-purity-gate.md`
  - 调查结论：六个非业务模块并非纯平台；`ktg-quartz` / `ktg-generator` 可整模块替换，其余四个必须先抽 MES 分叉

### Business Goal

在不替换 RuoYi 平台模块、不升级 Spring Boot / JDK 的前提下，把误放在 `ktg-common`、`ktg-framework`、`ktg-system`、`ktg-admin` 中的 MES 能力迁回 `ktg-mes`（或明确废弃），使后续「用 `RuoYi-Vue` 对应模块换壳」时平台层可整包替换，且工单编号、上传、登录、报表等现网行为不丢。

本单元不写业务代码，只约束拆分顺序、完成定义与禁止事项。前端评估不在本批范围。

### Scope

In scope:

- 规定 `01`–`09` 的执行波次与依赖
- 规定换壳开工门槛（纯度门）
- 规定本批只动后端、不升级技术栈

Out of scope:

- 用 `RuoYi-Vue` 3.9.2 替换 `ktg-admin/common/framework/system`
- Java 8 → 17、Spring Boot 2.5 → 3/4、`javax` → `jakarta`
- 前端工程（另供 RuoYi 前端后再评估）
- 车间平板端（当前仓库无 `pad/`）

### Acceptance Criteria

- `01`–`09` 均有独立 spec，且本文件中的波次与各 spec 的「Next development unit」一致
- 纯度门（`09`）未通过前，不得开始替换 `ktg-common` / `ktg-framework` / `ktg-system` / `ktg-admin`
- `ktg-quartz` 与 `ktg-generator` 不在抽出范围内（与新若依文件集合一致，可随换壳整模块替换）
- 各单元验收以静态检索（import / 类名 / 路径）加受影响模块编译为准；未实际跑通的命令不得写「已通过」

### Rules and Constraints

Tenant isolation:

- 本批不引入租户字段，不改变现有数据隔离方式

Security and masking:

- 不在 spec、补丁、日志中复述 Token、Minio/OSS 密钥、数据库口令或内网地址
- 新增配置只用环境变量或占位符
- 不得扩大匿名访问面；现有 `permitAll` 只允许迁移或收紧，不允许新增长期匿名 MES 接口

Audit and lineage:

- 历史 SQL（`backend/sql/`、`backend/doc/` 下已有脚本）不原地改写；缺表或缺脚本时新增独立增量脚本
- 抽出是搬迁，不是借机改工单/库存状态机

AI/rule-engine rules:

- 本批不涉及规则引擎或 AI

Database rules:

- MES 业务表（wm/pro/qc 等）本批不改结构，除非某单元明确列出的平台侧 MES 表（自动编码、附件、消息、公告已读）
- 自动编码与消息表已有设计脚本，抽出时复用，不另起一套表名

## 2. Plan

### Implementation Approach

按三波在**当前** Java 8 / Spring Boot 2.5 工程上完成抽出，全部通过后再单独立项换壳。

| 波次 | 单元 | 依赖 |
| ---- | ---- | ---- |
| 一 | `01` MES 常量从 `UserConstants` 拆出 | 无 |
| 一 | `02` 自动编码整包迁入 `ktg-mes` | 建议在 `01` 之后，避免常量与编码规则交叉改动 |
| 一 | `03` `ItemType` 与条码/Excel/业务异常错层类型 | 可与 `02` 并行 |
| 二 | `04` Minio / `FileUploadUtils` 分叉隔离 | 无强依赖 |
| 二 | `05` 站内信 + WebSocket + 附件 + 公告已读 | 无强依赖 |
| 二 | `06` 移动端登录保留并迁入或删除 | 产品确认门 |
| 二 | `07` UReport 启动接线迁出 `ktg-admin` | 无强依赖 |
| 三 | `08` Security 放行清单迁到新归属 | 依赖 `05` `06` `07` 的路径仍可定位 |
| 三 | `09` 残留项与平台纯度门 | 依赖 `01`–`08` |

同一波次内除注明依赖外可并行。任一单元扩大范围到换壳或前端，视为范围失控。

### Affected Modules

- 实施阶段：`ktg-mes`（迁入）、`ktg-common` / `ktg-framework` / `ktg-system` / `ktg-admin`（迁出）
- 不改：`ktg-quartz`、`ktg-generator`、`frontend/`

### Public Contracts

- HTTP 路径、方法、`code/msg/data` 在抽出期间保持兼容（搬 Controller 不改 URL）
- 配置前缀仍为 `ktg-mes:`，直到未来换壳单元再映射到 `ruoyi:`

### Persistence Changes

- 见 `02` `05`；总控不新增表

### Transaction Boundaries

- 各单元自己的事务边界；总控不跨单元开事务

### Risks

- 把「抽出」做成「顺手重构」导致 MES 行为变化
- 未过纯度门就开始换壳，同名类静默丢失（尤其 `UserConstants`、`FileUploadUtils`）
- `06` 未确认客户端仍打 `/mobile/**` 就删除接口

### Verification Strategy

- 每单元用该 spec 第 3 节任务表的 Verification 列做门禁
- 波次结束时用 `09` 的检索清单做一次总检
- 编译范围至少覆盖被改模块；不声称测试通过除非命令已跑且成功
