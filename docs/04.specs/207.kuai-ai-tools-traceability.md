# KU-AI 场景 Tool：批次/序列追溯

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已完成；§1 决策已于 2026-10-23 选定。

## 1. Spec

### Capability

- Name: 新增只读 Tool `trace_lineage`（按序列号/批号/工单号正反向追溯）。
- Module: `riveredge-backend/src/apps/kuaiai/services`（tools 适配层）、manifest `ai_tools`；X2=b 时另改 `core/ai/runtime/tool_bridge.py`、`core/ai/tool_registry.py`。
- Priority: P2（S13 批次/序列追溯与召回范围）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D5、SC-D7；设计 26 §4、§5.2；前置 spec 189、190。

### Business Goal

质量工程师问“批次 B2410-07 用在了哪些成品、发给了哪些客户”“这个序列号的原材料来自哪个供应商批次”，助手基于追溯图给出正向/反向链路，辅助评估召回范围。

### Scope

In scope:

| Tool | 参数 | 底层 service（已读） | 权限 |
| --- | --- | --- | --- |
| `trace_lineage` | `code`（序列号/批号/工单号，必填）、`direction=forward\|backward\|both` | `TraceabilityService.build_profile(tenant_id, code, direction)` | 现路由 `GET /traceability/profile` 为 `require_permission_codes("kuaizhizao:quality-management-traceability:read", "kuaizhizao:material-lifecycle-trace:read")`，`require_all=False`（二者任一即可）；Tool 侧见 X2 |

- 输出：节点按层级列出（物料/批次/工单/单据编码与类型、数量），总节点数超上限时只列前 N 层并注明“已截断，完整追溯请到追溯页”。
- 数据范围：与追溯路由同口径（T1 核实 service 是否按用户范围过滤）。

Out of scope:

- 单据关联链（spec 208）。
- 召回动作或冻结批次（写操作）。

### 决策（2026-10-23 已选定）

选定：**X2=b** —— `tool_bridge` / manifest 支持 `permissions_any`（任一命中），与追溯页“任一权限即可”语义一致。

| 编号 | 场景 | 选项 | 推荐与理由 |
| --- | --- | --- | --- |
| X2 | 追溯页允许“质量追溯”或“物料生命周期追溯”任一权限访问；`tool_bridge` 当前每个 Tool 只能挂一个权限码。若 Tool 只挂质量追溯权限，仓库/计划人员只有物料生命周期追溯权限时，页面能查、AI 却说无权限，用户会认为 AI 故障 | a. Tool 只挂 `quality-management-traceability:read`，物料生命周期权限的用户需管理员另授；b. `tool_bridge` / manifest 支持“任一权限码”（新增 `permissions_any` 列表，与路由 `require_all=False` 同语义），Tool 与追溯页权限完全一致 | **b**：AI 权限与页面权限一致是长期原则；改动只在 `tool_bridge` 判权一处（仍集中校验，符合 SC-D7 的出发点），以后其他“任一权限”路由的 Tool 可复用。a 会制造“页面能看、AI 不能看”的不一致 |

### Acceptance Criteria

1. 同参数下 Tool 节点与追溯 profile 接口一致（截断前）。
2. `direction` 非闭集值返回固定错误文案；`code` 找不到时返回真实“未找到追溯记录”。
3. X2=b：持有任一权限码即可调用；两者都无 → 403 审计；单权限 Tool 行为不变（回归）。
4. 登记于 manifest（`label`、`kind=read`）。

### Rules and Constraints

Tenant isolation:

- 传 `ctx.tenant_id`。

Security and masking:

- 客户名称可出现（召回评估所需），联系人/电话/地址不出现。

Audit and lineage:

- 沿用 Tool 级审计；`route` 业务键记录追溯码。

AI/rule-engine rules:

- 追溯关系来自追溯图（SC-D5）；召回范围由用户判断，AI 只罗列。

Database rules:

- 无表结构变更。

### 场景模板（Y3=a）

本单元交付时同步登记场景模板 `trace-lineage`（批次追溯助手）：预置档案 `enabled_tools` 为本单元 Tool 集合，停用 + 空授权（Y4=a）；模板 key 即能力矩阵场景卡，默认绑定同 key 预置实例（spec 191，Y1/Y2=a）。system_prompt 只引用本单元 Tool，插画按 spec 201 T2 约定。

### Transaction Boundaries
