# KU-AI 页面上下文扩展

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施。

## 1. Spec

### Capability

- Name: 助手抽屉页上下文从“工单”扩展到 P1 场景相关单据页，并补齐 by-ID 摘要的行级数据范围。
- Module: `riveredge-backend/src/apps/kuaiai/services/page_context.py`、tools 适配层格式化函数；`riveredge-frontend/src/hooks/useRegisterAiContext.ts` 及各业务页。
- Priority: P1。
- Related requirement/design documents: 需求 25 §4.5；设计 26 §7；spec 135 AC7（页上下文原始契约）；前置 spec 190、195–197。

### Business Goal

用户在销售订单、采购订单、质量异常、库存预警等详情页打开助手时，助手自动知道“正在看哪张单”，不用用户复述单号。

### Scope

In scope:

- `_SCREEN_PAGE_NAMES` 新增页面（路径 T1 从前端路由与 manifest 取）：销售订单、采购订单、质量异常、库存预警、缺料异常。
- `_RESOURCE_READERS` 新增资源键：`kuaizhizao:sales_order`、`kuaizhizao:purchase_order`、`kuaizhizao:quality_exception`、`kuaizhizao:inventory_alert`、`kuaizhizao:material_shortage`；读权限码与对应 Tool 一致（spec 195–197）。
- 摘要函数复用对应 Tool 的单据格式化函数（同一字段口径），不另写。
- 现有 `_work_order_summary` 与所有新增 reader 在取数前做行级数据范围复核（复用 `_work_order_in_scope` / `_scoped_row_ids` 模式）：当前实现只校验功能权限、未校验 `record_id` 是否在当前用户数据范围内，客户端可传任意 id。
- 前端在上述页面的详情抽屉打开时调用 `useRegisterAiContext` 注册 `screen`、`resource_key`、`record_id`（参照工单页 `work-orders/index.tsx` 现有用法）。

Out of scope:

- 移动端、工位端页面上下文。
- 列表页多选上下文。

### Acceptance Criteria

1. 在新增页面打开助手：服务端摘要含单号与关键状态；客户端 `screen_label`/`record_label` 仍不进入提示词。
2. 范围外 `record_id`、无功能读权限、未知 screen/resource：摘要省略（返回 None），不报错、不泄露存在性。
3. 工单摘要补数据范围后，范围外工单不再产出摘要（新增测试）。
4. 摘要字段与对应 Tool 摘要同口径（共用函数，测试断言同一输出）。
5. 前端注册在抽屉关闭/路由离开时清理（沿用 hook 现有清理行为）。

### Rules and Constraints

Tenant isolation:

- reader 一律以服务端 tenant_id 查询。

Security and masking:

- 只信白名单 screen 与 resource_key；摘要不含客户/供应商联系方式与金额。

Audit and lineage:

- 不写审计（页上下文不是 Tool 调用）。

AI/rule-engine rules:

- 摘要以 SystemMessage 注入，位置与现有实现一致。

Database rules:

- 无表结构变更。

## 2. Plan

### Implementation Approach

- 把各 Tool 的单据行格式化函数提为模块级公共函数（若尚未独立），`page_context` 与 Tool 共同调用。
- 行级范围复核失败（含解析异常）按无摘要处理，与现有“异常返回 None”一致。

### Affected Modules

- Modify: `apps/kuaiai/services/page_context.py`、tools 适配模块（格式化函数导出）。
- Modify: 前端各目标页面（逐页手工修改，遵守 no-batch-codemod 规则）。
- Test: `tests/apps/kuaiai/test_spec204_page_context.py`；回归 spec 135 页上下文测试。

### Public Contracts

- chat 请求 context 字段不变；白名单值扩展。

### Persistence Changes

- 无。

### Transaction Boundaries

- 只读。

### Risks

- 前端涉及多页面：逐页修改并逐页 build/打开验证，不用脚本批量改。

### Verification Strategy

- 后端单测覆盖每个 reader 的权限、范围外、未知键；前端逐页浏览器打开详情→打开助手→提问“这张单现在什么状态”。
