# 触屏工位机 — 在线入口

本文件可实施。编码落在 `kuaigeyun-mes/riveredge-frontend`。本单元不改 `riveredge-backend` 契约，不改 `startech-mes-basic`。

## 1. Spec

### Capability

- Name: 触屏工位机在线入口
- Module: `kuaigeyun-mes/riveredge-frontend` 星制造应用。生产只有一份现有构建（`npm run build:16g`，静态根 `FRONTEND_ROOT`）。进入工位路由时请求头为 `station`，办公室页面为 `pc`。
- Priority: STN-D3、STN-Q1、STN-Q2、STN-Q3。158–161 依赖本入口；162 依赖本入口可被服务器访问。
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/20.station-terminal-gaps.md`（**STN-D3**、**STN-D6**、**STN-Q1**、**STN-Q2**、**STN-Q3**）
  - 设计：`docs/03.design/20.station-terminal-plan.md`（§2、§3）

### Business Goal

产线电脑打开的是服务器上的一个触屏工位入口。操作员在已有终端账号会话里绑定工位、点选当前操作员，并从该入口进入已经在线路由上的工单详情、报工、SOP、图纸、程序查看。

### Scope

In scope:

- 生产不另打工位构建，不新增 Caddy 站点，不替换办公室 `dist`。两个入口共用同一套前端工程、登录、权限与接口封装。渠道在发请求时按当前路由计算，见下方「公开契约」。
- 触屏布局沿用本仓 `TouchScreenTemplate`、`PremiumTerminalTemplate`（`src/components/layout-templates/`）。工位入口铺满触屏模板。
- 一个仍在线的工位入口：绑定工位、长期终端账号会话、点选切换当前操作员，并挂上已有 kiosk 子页。
- 绑定取值是星制造已有工位主数据。页面上的绑定与壳记住的本机工位指向同一工位（**STN-D6**）。初值来自壳打开入口时附上的 URL 查询参数 `workstationId`（URL query，不是 Electron 额外启动参数）。绑定成功后，页面通过壳暴露的窄接口 `stationShell.setWorkstationId` 回写壳的本机配置，参数只有工位 ID。下次开机壳仍打开这一工位，并再次带上同一查询参数。细则与 spec 162 的 **STN-S3** 一致。浏览器直接打开入口、没有该窄接口时，页面仍完成本地绑定。
- 工位子路径导航都带上当前 `workstationId`。进入执行、报工、安灯、刷脸，以及工位前缀下的 kiosk（含工单详情、SOP、图纸、程序查看）时，地址带这个查询参数。工位入口在挂载子页时按这个顺序恢复工位，再把工位传给只认 props 的叶子页：内存里的已绑定工位、URL query `workstationId`、本机记录（`StationBinder` 已有的 `getStationStorageKey()`）、壳配置（`stationShell.getWorkstationId()`，只读已保存的工位 ID）。刷新 `/apps/kuaizhizao/production-execution/station/execution?workstationId=` 后仍得到该工位。
- 工位入口提供可聚焦的扫码输入，接收键盘楔入的条码。页面解释业务条码。壳不解析（**STN-S2**，与 spec 162 一致）。
- 每台工位一个长期登录的终端账号，走现有登录。点选只改页面上的当前操作员，随后请求仍带这条登录会话（**STN-Q2**）。
- 工位入口打开下列已有 kiosk 页面时，地址留在工位入口前缀下，请求头保持 `station`。挂的是同一批现有组件，不复制页面：
  - 工单详情 `production-execution/station/work-orders/:id/kiosk`
  - 报工 `production-execution/station/reporting`（`StationReportingPage`，传入当前操作员与 `workstationId`）。入口「报工」按钮不指向 `station/reporting/kiosk`
  - SOP `production-execution/station/sop-viewer/kiosk`
  - 图纸 `production-execution/station/drawing-viewer/kiosk`
  - 程序查看 `production-execution/station/program-viewer/kiosk`
- 办公室直接打开的旧 kiosk 路径保持原样，渠道仍是 `pc`：
  - `production-execution/work-orders/:id/kiosk`
  - `production-execution/reporting/kiosk`
  - `production-execution/sop-viewer/kiosk`
  - `production-execution/drawing-viewer/kiosk`
  - `production-execution/program-viewer/kiosk`
- 入口路由已拍板为 `/apps/kuaizhizao/production-execution/station`（**STN-S1**），并写入本文件 §2 的「公开契约」。
- 当前操作员只来自入口上的点选或刷脸切换。登录会话只负责认证，入口不把登录用户写成当前操作员。本人报工用这名操作员，见 spec 159。

Out of scope:

- 标签装箱 `/apps/kuaizhizao/production-execution/label-station`
- 电视看板、小程序、企业微信
- 计划、主数据、审批、财务的工位页面
- 移动端再复制一份工位页面
- 新后端表、新后端接口、开工 API 内嵌 SOP 确认或上岗资质
- 把页面烤进 exe；改 `startech-mes-basic`；改 `fast-deploy`
- 安灯、刷脸、交接班、快捷报工三种方式、开工到结束与设备上下机（分别见 158–161）

需求 **STN-Q3** 只要求一个在线入口。2026-09-29 核对 `riveredge-frontend/src/apps/kuaizhizao/index.tsx` 与 `routePrefetch.ts` 后，入口路径已拍板。

- 入口路径是 `/apps/kuaizhizao/production-execution/station`。它与已在线的 kiosk 子页同在生产执行段。
- 不启用已注释下线的 `production-execution/terminal`。`index.tsx` 与 `routePrefetch.ts` 里这两处注释保持原样。对应页面文件 `work-orders/kiosk.tsx` 仍在。
- 不使用 `/apps/kuaizhizao/station`。
- `production-execution/label-station` 是标签工位，仍是另一条路由，与本入口分开。
- 五个旧 kiosk 路由仍在线。工位入口另在同一前缀下复用这五个组件，见公开契约。
- 核对时仓库内尚未挂上 `production-execution/station`。本单元按已拍板路径注册该路由。

壳加载的就是这一条地址。改按钮仍随前端发布，产线电脑上的 exe 沿用该地址。

### Acceptance Criteria

1. 同一份生产构建里，请求头按下面顺序取值：开发模式若设置了 `VITE_CLIENT_CHANNEL=station` 或 `pc`，只作本地整站调试，生产构建不读该变量。其后若页面里已有壳注入的 `window.stationShell`，请求头为 `X-Client-Channel: station`。没有这个对象时，当前地址在工位入口 `/apps/kuaizhizao/production-execution/station`（含其子路径）为 `station`，其余办公室页面为 `pc`。浏览器不伪造 `window.stationShell`。不另打一份会替换 `dist` 的 station 构建。
2. 已登录的终端账号打开工位入口后，看到触屏布局，可以绑定一个已有工位，并用点选更换当前操作员。更换操作员后登录会话仍是原来的终端账号。URL 带有查询参数 `workstationId` 时，绑定初值是该工位。绑定成功后，壳内页面调用 `stationShell.setWorkstationId` 回写本机配置。
3. 入口提供可聚焦的扫码输入，接收键盘楔入的条码。页面解释业务条码。
4. 入口打开工单详情、报工、SOP、图纸、程序查看时，地址在工位入口前缀下，请求头为 `station`。办公室直接打开的五个旧 kiosk 路径字面量不变，请求头仍为 `pc`。
5. `index.tsx` 与 `routePrefetch.ts` 里 `production-execution/terminal` 的注释仍在。标签工位路由仍在，工位入口不进入该页。
6. 入口路径是 `/apps/kuaizhizao/production-execution/station`。不注册 `/apps/kuaizhizao/station`，不恢复 `production-execution/terminal`。

### Rules and Constraints

Tenant isolation:

- 登录、工位主数据与后续业务请求沿用快格现有租户与组织隔离。终端账号的会话决定租户。

Security and masking:

- 页面、日志不输出入口令、令牌或密钥。
- 点选操作员不签发新的登录。

Audit and lineage:

- 本单元不新写审计表。当前操作员留在页面状态，供 158–161 调用现有接口时带上。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 无新表，无迁移。工位主数据用星制造已有工位。

## 2. Plan

### Implementation Approach

1. 不新增工位生产构建。沿用 `clientChannel.ts` 的 `resolveWebClientChannel`，在每次发请求时按当前路由计算渠道。
2. 新增工位入口页，套 `PremiumTerminalTemplate` 或 `TouchScreenTemplate`。绑定工位、展示当前操作员、提供点选切换，并提供可聚焦的扫码输入。
3. 在工位路由下复用五个已有 kiosk 组件。入口跳转到工位前缀下的子路径。旧 kiosk 路由保持原样。
4. 在 `kuaizhizao/index.tsx` 注册 `/apps/kuaizhizao/production-execution/station`。`production-execution/terminal` 的注释保持原样。`kiosk.tsx` 里已有的绑定与列表可以抽来复用，挂到该路径上。页面读取 URL 查询参数 `workstationId` 作为绑定初值。绑定成功后，若存在 `stationShell.setWorkstationId`，则调用它回写壳，只传入工位 ID。

### 依赖

- 158、159、160、161 依赖本入口已经可以打开，并依赖本入口上的「已绑定工位」和「当前操作员」。
- 162 依赖本入口部署后可被壳的窗口访问。158–161 彼此可先后实现。端到端冒烟放在 162。

- 已有子页：`work-orders/detail-kiosk.tsx`、`reporting/kiosk.tsx`、`sop-viewer/kiosk.tsx`、`drawing-viewer/kiosk.tsx`、`program-viewer/kiosk.tsx`

### Public Contracts

- 请求头沿用 `X-Client-Channel`。生产只有现有一份 `npm run build:16g` / `FRONTEND_ROOT` 构建，不新增 Caddy 站点，不另打会替换办公室 `dist` 的 station 构建。`resolveWebClientChannel()` 的判断顺序：开发模式若进程里已经设置 `VITE_CLIENT_CHANNEL=station` 或 `pc`，只作为本地整站调试覆盖，生产构建不读该变量；其后若存在壳注入的 `window.stationShell`，值为 `station`；再读当前 `window.location.pathname`，路径为 `/apps/kuaizhizao/production-execution/station` 或其子路径时值为 `station`，其余办公室页面为 `pc`。浏览器不伪造这个对象。`apiRequest`、`buildAuthTenantHeaders`、公开登录请求与 NDJSON 同步都在发请求时调用 `webClientChannelHeaders()`，不在模块加载时缓存。从工位打开 SOP、图纸、报工、工单详情、程序查看时地址留在工位前缀下并带 `workstationId`，请求头保持 `station`。办公室直接打开旧 kiosk 路径时仍是 `pc`。渠道不改成会话标记。
- 登录 URL、认证头、响应外层结构保持现有契约。登录会话不写入当前操作员。
- 入口「报工」打开 `station/reporting`（`StationReportingPage`），不指向 `station/reporting/kiosk`。工位前缀下仍复用的 kiosk 子路径为 `station/work-orders/:id/kiosk`、`station/sop-viewer/kiosk`、`station/drawing-viewer/kiosk`、`station/program-viewer/kiosk`（均相对 `production-execution/`）。旧路径字面量不改：`work-orders/:id/kiosk`、`reporting/kiosk`、`sop-viewer/kiosk`、`drawing-viewer/kiosk`、`program-viewer/kiosk`。
- 工位入口路径：`/apps/kuaizhizao/production-execution/station`（**STN-S1**）。不使用 `/apps/kuaizhizao/station`。不启用 `production-execution/terminal`。标签工位仍是 `production-execution/label-station`。
- 绑定初值：壳打开的 URL 查询参数 `workstationId`（URL query，不是 Electron 额外启动参数）。绑定成功后回写壳的窄接口 `stationShell.setWorkstationId`，只传工位 ID（**STN-S3**，与 162 一致）。
- 扫码：入口提供可聚焦输入，接收键盘楔入的条码。页面解释业务条码。壳不解析（**STN-S2**，与 162 一致）。

### Persistence Changes

- 无。当前操作员留在页面。绑定结果回写壳的本机配置，配置属于 spec 162。页面用查询参数 `workstationId` 作初值。

### Transaction Boundaries

- 本单元无新的写入事务。绑定选择的是已有工位主数据的 ID。

### Risks

- 若恢复 `production-execution/terminal`，会重新打开已经注释下线的主路由。本单元保持该注释。
- 若入口做成办公室侧栏里的普通菜单页，产线触屏会带上办公室导航。入口使用触屏模板。
- 页面绑定成功后若不调用 `stationShell.setWorkstationId`，下次开机壳仍打开旧工位。壳内绑定成功后回写本机配置。
