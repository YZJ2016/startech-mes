# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: Vue3 MES 排班（cal）+ 设备（dv）领域 API 对齐
- Module: `startech-mes-basic/startech-mes-front/src/api/mes/cal` 与 `src/api/mes/dv`（只读对照 `backend/ktg-mes` cal / dv Controller）
- Priority: P0
- Related requirement/design documents:
  - 总控：`docs/04.specs/27.vue3-backend-api-align-program.md`
  - 缺口：`docs/02.requirements/01.vue3-backend-api-gaps.md`（**D-cal**、**D-dv**）
  - 调研：`docs/03.design/03.vue3-backend-api-align-survey.md`

### Business Goal

让 Vue3 管理端排班与设备 API 的 URL+method 与换壳后 `ktg-mes` cal / dv Controller 一致，避免日历/班组/点检/维修页打到不存在的路径或用错动词。Vue2 有调用而后端无 mapping 的只记缺口，不补 Java。

### Scope

In scope:

- 对照 `startech-mes-front/src/api/mes/cal/**`、`src/api/mes/dv/**` 与 `com.ktg.mes.cal.controller`、`com.ktg.mes.dv.controller`
- 按调研归一规则比较（类 `@RequestMapping` + 方法 mapping；路径变量统一 `{id}`；忽略末尾 `/`）
- Vue3 与后端不一致时只改上述两个 Vue3 API 目录
- 清单 **D-cal**、**D-dv** 回填证据并按结果收口或保留
- 本文件第 4 节写入归一后的 URL 库存

Out of scope:

- 改 Vue2 `frontend/`
- 改 Java、Mapper、SQL、五项接线
- 改锁屏 / 公告 / 登录（`lock`/`notice`/`login`）
- 改其他 `src/api/mes/*` 目录（含 `md/workstation.js` 内的 `/mes/cal/workstation`）
- 把 `/mobile/dv/**` 接到管理端（本仓库无 pad）
- 提交；新增 lockfile；复述凭据或生产地址

### Acceptance Criteria

- 归一后，Vue3 `src/api/mes/cal` 与 `src/api/mes/dv` 中每一条打 ktg-mes 的 URL+method 都能落到对应 Controller mapping
- `cal/workStation.js` 的 `GET /mes/md/workstation/listAll` 能落到 md `MdWorkstationController`（文件在 cal 目录，路径属 md）
- Vue2 对应 API 有而后端无 mapping 的调用写入 Known gaps，且无新 Java
- 第 4 节含 Vue3 / 后端 / 差集库存
- 默认无 backend Java diff、无 Vue2 diff
- 无命令输出不得写构建或运行时通过

### Rules and Constraints

Tenant isolation:

- 不改数据隔离方式

Security and masking:

- 文档与日志不写 Token、口令、对象存储密钥、内网地址
- 不扩大匿名访问面

Audit and lineage:

- 对齐是接既有 HTTP 契约，不改排班/设备单据状态机
- 导出走页面 `download()` 的 POST，不把 blob 出口改成 JSON `request()`

AI/rule-engine rules:

- 不涉及

Database rules:

- 不改表、不执行 SQL

## 2. Plan

### Implementation Approach

1. 从 cal/dv Controller 与 Vue3/Vue2 `src/api/mes/cal`、`src/api/mes/dv` 抽出 URL+method 并归一
2. Vue3 多调或 method 不一致 → 改 Vue3 对齐后端
3. Vue2 有而后端无 → 记缺口，不补 Java
4. 后端多出的 export / mobile / 未封装 GET·PUT：export 由页面 `download()` POST 使用；mobile 管理端不接；未封装 CRUD 与 Vue2 相同则不补空封装
5. 回填本文件第 4 节与清单 **D-cal**、**D-dv**

### Affected Modules

- 文档：`docs/04.specs/33.vue3-cal-dv-api-align.md`、`docs/02.requirements/01.vue3-backend-api-gaps.md`（仅 **D-cal**、**D-dv**）
- 实现：仅在对照发现差集时改 `startech-mes-front/src/api/mes/cal` 与 `src/api/mes/dv`
- 只读：`backend/ktg-mes/.../cal/controller`、`.../dv/controller`；Vue2 `frontend/src/api/mes/cal` 与 `.../dv`（只作缺口探测）

### Public Contracts

- 排班 JSON：`/mes/cal/{calendar|calholiday|calplan|planteam|shift|team|teammember}` 的 list/详情/POST/PUT/DELETE（calendar 仅 list；planteam / teammember 无 PUT 封装，与 Vue2 相同）
- 排班额外：`GET /mes/cal/calplan/listAll`、`GET /mes/cal/team/listAll`
- 设备 JSON：`/mes/dv/{checkmachinery|checkplan|checksubject|dvsubject|machinery|machinerytype|repair|repairline}` 的 list/详情/POST/PUT/DELETE
- 导出：`POST .../export`（页面 `download()`，method 为 POST）
- 移动端（本单元不封装）：`GET /mobile/dv/checkplan/orderStatusCount`、`GET /mobile/dv/machinery/deviceStatusCount`、`GET /mobile/dv/machinery/operatingRate`

### Persistence Changes

- 无

### Transaction Boundaries

- 无

### Risks

- 把 `{planId}` 与 `{planIds}` 报成两套契约（归一后视为同一 `{id}`）
- 把未封装的 export 误报成 Vue3 缺接口（页面已用 `download()` POST）
- 把 `cal/workStation.js` 的 md 路径、或 `md/workstation.js` 的 `/mes/cal/workstation` 算进本单元改动
- 把 `/mobile/dv/**` 误接到管理端

### Verification Strategy

静态必做：归一差集。不跑 Maven/npm。无本地后端则不写 cal/dv 页面冒烟通过。
