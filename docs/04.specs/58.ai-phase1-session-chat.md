### Business Goal

已登录用户可建本租户会话、拉历史，并对本租户某个 **chat** 类模型发 OpenAI 兼容流式对话。上下文只来自该会话消息，不挂知识库。

### Scope

In scope:

- 表 `ai_session`、`ai_message` + include + 专库 catalog
- `/ai/session/**` 与 `GET /ai/session/{id}/messages`（**禁止**使用 `/system/message`）
- `POST /ai/chat/send`：`text/event-stream`，登录 + 租户隔离
- JDK `HttpClient` + Jackson 解析上游 SSE；事件至少 `content` 增量，结束带 `done`
- 持久化 user + assistant 消息；token 计数仅可选审计
- 对话页菜单/权限 SQL（若 57 未建聊天叶子）

Out of scope:

- 厂商/模型 CRUD 与 `options` 实现（57；本单元只 **读取** `ai_model`）
- Vue 页（59）
- RAG / Agent / MCP / workflow / 匿名 `/workflow/run` / 短剧 / Harness
- 游客；`permitAll`；知识库上传；OSS
- LangChain4j 全家桶；Sa-Token；MyBatis-Plus；第二套 `SecurityFilterChain`
- 实现 53–56

### Frozen HTTP contract (Phase 1 — do not drift)

Assume classic MES `code/msg/data` / `rows`+`total`. All authenticated.

- `GET/POST /ai/provider` list/create; `GET/PUT /ai/provider/{id}`; `DELETE /ai/provider/{ids}`
- `GET/POST /ai/model` list/create; `GET/PUT /ai/model/{id}`; `DELETE /ai/model/{ids}`
- `GET /ai/model/options` → `{id, modelName, providerCode, category}[]` no keys
- `GET/POST /ai/session` list/create; `GET/PUT/DELETE /ai/session/{id}`
- `GET /ai/session/{id}/messages`
- `POST /ai/chat/send` body `{sessionId?, modelId, content}` response `text/event-stream` data lines JSON `{content, done}`

Permissions (propose, keep consistent): `ai:provider:list|query|add|edit|remove`, `ai:model:*`, `ai:chat:list|send`.

本单元只实现 **session / messages / chat/send**。列表不要加 `/list` 后缀。会话写操作与列表用 `ai:chat:list`；发送用 `ai:chat:send`。

### Acceptance Criteria

- 无 JWT 调 `POST /ai/chat/send` → 401；无 `ai:chat:send` → 403
- `MesPermitAllProvider` 仍无 `/ai/chat`、`/ai/session`
- 他租户或他人 `sessionId` / 他租户 `modelId` → 失败且 **不调用上游**
- `category != chat` 的模型拒绝发送
- SSE：`Content-Type: text/event-stream`；`data:` 行 JSON 含 `content`，最后一条 `done: true`（或等价结束帧 + `done`）
- 流成功后 `ai_message` 有 user 与 assistant；上游失败有错误事件，不回滚已提交的 user 行，事件与日志无 Key
- 单测 Mock 上游（MockWebServer 或等价），不打真实公网模型
- 文档无真实主机与凭据

### Rules and Constraints

Tenant isolation:

- 会话属 `tenant_id` + `user_id`（当前 `LoginUser`）；列表只本用户本租户
- 模型必须属于当前租户（读 57 的 `ai_model`）
- SSE 工作线程必须带 `TenantContext`（P1-I3）
- `DATABASE`：本单元两表进 catalog，禁止回落主库

Security and masking:

- 解密 Key 或读取 `${AI_DEFAULT_API_KEY:}` 仅在出站调用处
- 响应、事件、日志无 apiKey / cipher / Authorization 上游头
- 不把聊天口放进 permitAll

Audit and lineage:

- 可选列 `prompt_tokens` / `completion_tokens`，不做扣费
- 增量新 SQL，不改历史脚本

AI/rule-engine rules:

- 只走 OpenAI 兼容 `chat/completions` stream
- 上游 URL = 模型 `apiHost`，空则厂商 `apiHost`；都空则失败，不写死公网地址
- 不兼容 ruoyi-ai MCP / `[NODE_CHUNK_*]` 工作流帧

Database rules:

- `ai_message.session_id` 指向本租户会话；无上下文失败关闭
- 不建知识库表

## 2. Plan

### Implementation Approach

- send：鉴权 → 校验模型归属与 `category=chat` → 无 `sessionId` 则建会话 → 提交 user 消息 → 带历史组请求 → 流式写出 → 提交 assistant
- 出站：`HttpClient` 发 `Authorization: Bearer <decrypted-or-env>`，body 为 OpenAI chat completions stream；Jackson 读 `choices[].delta.content`
- 与 57 并行：不要改 `ktg-ai/pom.xml` 的模块坐标（若模块尚不存在，只补与 57 T1 相同的空模块接入，然后停手 POM）；不要改 provider/model 包
- include / catalog：**只追加** `ai_session`、`ai_message` 与本单元 DDL 文件名

### Affected Modules

- 本单元可改：`backend/ktg-ai/src/**/session/**`、`chat/**`、`client/**`（名随风格）、对应 mapper XML、`backend/sql/20260823_22_*.sql`、`application.yml` include **追加两表**、`TenantDedicatedSchema` **追加**
- 若 57 尚未合并：允许创建空 `ktg-ai` 模块，但不得覆盖 57 随后提交的 provider/model 文件
- 本单元不可改：`startech-mes-front/**`、`frontend/**`、厂商/模型 Controller、UReport、generator

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- `POST /ai/session` body：至少 `title`（可空则用 content 截断）；自动填 `tenant_id`/`user_id`
- `PUT /ai/session/{id}`：改标题等，不可改归属
- `DELETE /ai/session/{id}`：删会话及消息（本租户本用户）
- `GET /ai/session/{id}/messages`：按时间升序
- `POST /ai/chat/send`：`sessionId` 可空；`modelId`、`content` 必填；响应不是 `AjaxResult` 信封，而是 SSE
- 非 SSE 接口仍用 `code/msg/data` 与 `rows`/`total`
- 权限见 Frozen 块

### Persistence Changes

Tables, indexes, migrations, mapper XML, and lifecycle rules:

- `20260823_22_ai_session_message.sql`（`NN` 按实现日顺延）→ **加入** `incrementalSqlFiles()`
- `20260823_22_ai_chat_menu.sql`：对话菜单 + `ai:chat:list` / `ai:chat:send` → **不要**进专库 catalog
- `ai_session`：`session_id` PK、`tenant_id NOT NULL`、`user_id NOT NULL`、`model_id`（可空，表示最后使用）、`title`、`status`、审计列
- `ai_message`：`message_id` PK、`tenant_id NOT NULL`、`session_id`、`role`（`user`/`assistant`/`system`）、`content`、可选 token 列、`create_time`；索引 `(tenant_id, session_id, message_id)`
- 不在本单元改 `ai_provider` / `ai_model` 列

### Transaction Boundaries

- user 消息先提交；assistant 另事务。流失败不删 user 行，可写一条失败标记或仅 SSE 错误事件（选一种并在第 4 节写明）
- 新建会话与首条 user 消息可同一事务

### Risks

- 流式线程丢租户上下文 → 写错库或失败开放
- 路径误用 `/system/message` 或 `/chat/send` 撞 MES / 对照项目
- 把 `/ai/chat/send` 放进 excludes / permitAll
- 与 57 同时改 yml / catalog 冲突
- SSE 把上游错误体（可能含 Key）原样转给浏览器

### Verification Strategy

- `mvn -pl ktg-ai,ktg-admin -am test`（或至少 compile + 本单元新测）
- Mock 上游：无 token 401；跨租户不发 HTTP；SSE 解析 `content`/`done`；落库两条消息
- 静态：无 `/system/message` 映射；无 permitAll
- 不跑 Vue 构建；不连真实模型
- 未真实跑通不得写「测试通过」
