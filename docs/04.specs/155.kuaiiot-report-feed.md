## 1. Spec

- Priority: KIO-W6。编码不得早于星报表 145–149 收口，也不得早于 150–154。这是数采与报表的唯一衔接（KIO-D4）。
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/19.kuaiiot-selfdev-gaps.md`（**KIO-W6**、**KIO-D4**、**KIO-D7**）
  - 设计：`docs/03.design/19.kuaiiot-selfdev-plan.md`（§3.6、§4）

### Business Goal

数采把设备运营馈送做成一个普通 HTTP 资源。星报表用已有的 HTTP 数据源类型登记它。登记这条 HTTP 源时种入一张已经绑好该源和指标路径的设备运营大屏，设计器仍可改布局。数据源类型仍是 HTTP。OEE 只在这一步、且只在条件齐备时出现在 `ops_metrics` 里。

### Scope

In scope:

- 馈送是本切片要补的接口。联动说明写的是 `GET /api/v1/apps/kuaiiot/analytics/equipment-ops-feed`，查询参数 `hours`（说明中的例子为 24）。仓内没有该路由。权限码沿用说明已写的 `kuaiiot:analytics:read`，走租户 RBAC，不用设备凭据。
- 响应字段沿用 `KUAIREPORT-LINK.md` 已列的五个：`equipment_list`、`ops_metrics`、`status_dist`、`workshop_stats`、`spot_check_recent`。设备来自本租户已绑定 `equipment_uuid` 的 IoT 设备，主数据只读 `apps_kuaizhizao_equipment`（含 `workshop_id`、`workshop_name`）。状态分段只读 150 写入的 `apps_kuaizhizao_equipment_status_monitors` 且 `data_source=sensor`。护栏行沿用上一条 status/is_online，因此不会把默认正常送进 OEE 分段。近期点检只读 `apps_kuaizhizao_equipment_spot_checks`（该表有 `equipment_uuid`）。
- 登记：在本租户 `apps_kuaireport_data_sources` 写入一行，`type` 为 `http`。该表在迁移 92 已存在。「地址必须等于登记行」是 spec 145 的规则。`apps/kuaireport` 槽位尚未收归，本切片不把星报表 HTTP 执行器写成已经在跑。编码不得早于 145–149 收口，不改 145，不增加数采专用报表接口，不新造大屏组件类型。大屏仍是普通组件。登记 HTTP 源时种入已绑定的大屏，组件指向该源以及 `ops_metrics` 下的 `oee_live` 等馈送路径；设计器仍可改布局。
- OEE 只在本步计算（KIO-D7），放进 `ops_metrics`（字段名 `oee_live`）。同时满足下面两条才给出数值：
  - 可用率只来自 `data_source=sensor` 的监控行按时间排成的状态分段。不用估算的计划工时。
  - 良品率只来自 `apps_kuaizhizao_reporting_records` 里 `status=approved` 的行：`qualified_quantity / reported_quantity`。报工表没有 `equipment_uuid` 列。现有 `EquipmentOEEService.calculate_equipment_oee` 用 `device_info` 里的 `equipment_id` 或 `id` 对设备 id，用 `equipment_code` 或 `code` 对设备编码。本切片沿用这组已有键把报工归到设备，不给报工表加列。
- 缺传感器状态分段，或没有已审核报工可算出的良品率时，`oee_live` 为空，不填 0 或其它默认值。`equipment_list`、`status_dist`、`workshop_stats`、`spot_check_recent` 以及 `ops_metrics` 里的其它字段照常给出。
- 不调用 `EquipmentOEEService.calculate_equipment_oee` 作为 `oee_live`。该方法用报工工时和「每天 8 小时」估算时间稼动率，不是传感器分段。

Out of scope:

- 150–154 的入站、护栏、边缘运行时、趋势、指令本身。状态分段只消费 150 已写回的监控行，不为 OEE 提前造指标
- 改 145–149 的任何文件；在星报表增加数采专用 URL、专用组件或专用数据源类型
- 把星制造 `equipment_board` 等固定看板页迁进设计器
- MQTT 订阅、ThingsBoard、JetLinks（KIO-D6，六步收口后另开，不在本文件）
- 内置 MQTT Broker；OPC UA / S7 可执行采集
- 用 `tag_history` 或未配置的 Influx 凑可用率
- 改 `startech-mes-basic`；改报工表结构

### Acceptance Criteria

1. 具备 `kuaiiot:analytics:read` 的本租户用户能 GET 馈送，响应含上述五个字段。无该权限或无租户上下文时不返回其它租户的设备。
2. 本租户 `apps_kuaireport_data_sources` 有一行 `type=http`，其地址就是这条馈送。「执行地址必须等于登记行」沿用 145 的规则。本切片不实现、也不宣称星报表 HTTP 执行器已在跑，没有新增报表路由，不改 145。编码不得早于 145–149 收口。
3. 某设备在查询窗口内既有 `data_source=sensor` 的状态分段，又有按 `device_info` 的 `equipment_id`、`id`、`equipment_code` 或 `code` 对上的已审核报工且 `reported_quantity` 大于 0 时，`ops_metrics` 中该设备的 `oee_live` 为计算出的数。
4. 缺分段或没有已审核良品率时，该设备的 `oee_live` 为空，不是 0。同一响应里其余字段仍在。
5. 馈送不读取 `apps_kuaiiot_tag_history`。不修改 `apps_kuaizhizao_equipment` 与报工表。

### Rules and Constraints

Tenant isolation:

- 馈送、监控分段、点检、报工、数据源登记都限当前租户。跨租户设备 uuid 不出现在响应里。

Security and masking:

- 馈送不接受设备凭据作为用户身份。登记行的地址不是密钥。日志不写口令或凭据。

Audit and lineage:

- OEE 的输入是已有监控行和已审核报工，不另建 OEE 结果表。空着就是没有值。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 报表侧写入本租户一条 HTTP 数据源，并在 `apps_kuaireport_dashboards` 种入一张已绑定该源的设备运营大屏（已有相同 code 则不覆盖）。不改报表迁移文件名，不改 145–149。
- 不新造数采表。

### 依赖顺序

- 依赖 150 的传感器监控行。点检与报工表是星制造已有数据，不依赖 151 的预填是否被页面使用。
- 依赖 145 已规定的 `type=http` 与「执行地址必须等于登记行」。编码时 145–149 应已收口。
- 不改 145–149 的文档与契约。KIO-D6 不在本文件开新 spec。

## 2. Plan

### Implementation Approach

1. 云侧按五个字段组装馈送。可用率只扫 `data_source=sensor` 的监控行。良品率只扫已审核报工，并用 `device_info` 里的 `equipment_id`、`id`、`equipment_code`、`code` 把报工归到设备。
2. 条件不齐时把 `oee_live` 留空。
3. 把馈送地址写入本租户一条 `type=http` 的报表数据源，并种入一张已绑定该源的设备运营大屏。设计器仍可改布局。

### Affected Modules

- `riveredge-backend/src/apps/kuaiiot/` 云侧馈送（本切片之前不存在；`tests/apps/kuaiiot/test_wave3_analytics.py` 引用的 `OeeLiveService` 不是实现）
- 只读：`EquipmentStatusMonitor`、`Equipment`、`EquipmentSpotCheck`、`ReportingRecord`
- 写入一行：`apps_kuaireport_data_sources`
- 不改 `riveredge-frontend/src/components/uni-report/`，不改 145 的 `executeReport` 契约

### Public Contracts

- 本切片要补：`GET /api/v1/apps/kuaiiot/analytics/equipment-ops-feed`。这是数采应用自己的 HTTP 资源，不是星报表的新接口。
- 「执行地址必须等于登记行」是 spec 145 的规则。`apps_kuaireport_data_sources` 在迁移 92 已存在。`apps/kuaireport` 槽位尚未收归，星报表 HTTP 执行器还没有在跑。本切片只登记一行，不改 145。

### Persistence Changes

- 无新表。报表侧多一行 `type=http` 的 `apps_kuaireport_data_sources`，并在已有大屏表种入一行已绑定该源的设备运营大屏。
- 不写监控、不写报工、不写 `tag_history`。

### Transaction Boundaries

- 馈送是只读计算。数据源登记单独写入，不放在同一次大屏渲染事务里改数采表。

### Risks

- 复用 `EquipmentOEEService.calculate_equipment_oee` 会把计划工时算进 `oee_live`，违反 KIO-D7。
- 缺数时填 0，会被大屏当成真实 OEE。
- 若在报表应用里加专用路由，就打破 KIO-D4。

### Verification Strategy

- 见 §3。§4 在命令实跑后填写。本文件写下时未跑测试。
