### Business Goal

把 `ktg-ai` 对话与 embedding 出站从 JDK `HttpClient`（`OpenAiCompatChatClient` / `OpenAiCompatEmbeddingClient`）改到 LangChain4j 官方 Chat/Embedding API，并按 61 为每个 `(tenantId, modelId)` 懒建缓存。同一波次按 62 挂上当期 Agent/AiService（一份定义 + A24 凭证），使每个租户出站仍用自己那一行的加密 Key。现网 `POST /ai/chat/send` 的 `{content, done}` 行为不得削弱。

### Scope

In scope:

- 父 BOM 已由 60 导入：`langchain4j-bom:1.19.0` 与 `langchain4j-community-bom:1.19.0-beta29`。`ktg-ai/pom.xml` **只加坐标、不写 version**
- 运行时依赖（无 version）：`dev.langchain4j:langchain4j-open-ai`（`OpenAiStreamingChatModel` / `OpenAiEmbeddingModel`，或 61 点名的等价类）。需要 AiServices 时加核心 `langchain4j`。Boot 4 starter `langchain4j-open-ai-spring-boot4-starter` **可以**加，但必须关掉 yml 全局 `ChatModel` / `chat-model.api-key` 自动装配。`langchain4j-agentic` **仅当** 62 的 `Function<AgenticScope, ChatModel>` 需要时才加，禁止借机上 A2A/MCP
- Chat/Embedding 工厂（落实 61）：配置只读 `ai_provider` / `ai_model`；按 `(tenantId, modelId)` 懒建 + 缓存；出站 Key 来自该行（解密或既有 `tenantId == 0` 的 `${AI_DEFAULT_API_KEY:}` 回退）；改 Key/host/模型名/删行后 evict；他租户 `modelId` 不 get、不调上游
- 替换 `OpenAiCompatChatClient.stream` / `OpenAiCompatEmbeddingClient.embed` 为上述 LangChain4j 模型；`AiChatServiceImpl.send` 与知识解析/RAG embedding 路径都走工厂
- 保持 `/ai/**` 登录 JWT、MyBatis、现有 `SecurityFilterChain`。SSE 工作线程与 Agent/Tool 并行线程拷贝 `TenantContext`（`TenantTaskDecorator` 或项目同等机制；禁止裸 `InheritableThreadLocal`）
- Agent（落实 62）：一份 Java 接口 / Agent 拓扑 / `@Tool` 单例；AiService 按 `(tenantId, modelId)` 缓存或唯一代理内部路由到 A24；Agent 执行时向工厂要 `ChatModel`，禁止只传 modelName 换 Key；`ChatMemoryProvider` 的 id 含 `tenantId + userId + sessionId`
- 第一批 Tool：仅只读「检索本租户知识库」，内部调用既有 `AiRetrievalService` / `VectorStoreService`，只信 `TenantContext` / `LoginUser`
- Agent HTTP（62 留给本代码单元冻结）：新增 `POST /ai/agent/send`（SSE）。**不**改 `POST /ai/chat/send` 体与 `{content, done}` 信封
- 单测：Mock 上游（MockWebServer 或 LangChain4j 可注入的假模型），**禁止**打真实公网模型

### Acceptance Criteria

- `ktg-ai/pom.xml` 含上述 LangChain4j 坐标且 **无** 手写 version；父 POM 仍只有 60 的双 BOM
- 无 `langchain4j.open-ai.chat-model.api-key`（或等价）全局 Bean；进程内不存在「一把 Key 打所有租户」的 `ChatModel`
- `POST /ai/chat/send`：路径、登录、`ai:chat:send`、请求体 `{sessionId?, modelId, content}`（既有 `knowledgeId` 可选 RAG 仍可用）、SSE `data:` JSON `{content, done}` **与 58 冻结一致**
- `POST /ai/agent/send`：须登录；不进 `MesPermitAllProvider`；SSE 同样 `{content, done}`（可选 `reasoning`）；无 MCP / `[NODE_CHUNK_*]` 帧；事件与日志无 Key
- 夹具两租户两模型：mock 上游 `Authorization` 各用各的 Key；跨租户 `modelId` / 知识 id **不调上游、不跑 Tool**
- 模型行改 Key 后再次出站不再使用旧实例
- SSE / Tool 线程有 `TenantContext`；空上下文不得检索向量
- 无 SQL Tool、无 community DashScope 依赖、无 `langchain4j-weaviate` 本单元引入
- 第 4 节未跑通前不得写「测试通过」；文档无真实主机/凭据

### Rules and Constraints

Tenant isolation:

- 只信 JWT / `TenantContext`；禁止请求体传 `tenantId` 或明文 `apiKey` 换钥匙
- `modelId` / `sessionId` / `knowledgeId` 必须属当前租户，否则 404/403，且不创建缓存项
- Tool 禁止接受客户端 `tenantId`；知识库 id 必须再查本租户
- `DATABASE` 专库：懒建读的是当前租户数据源上的 `ai_model`，禁止启动扫主库预热

Security and masking:

- `/ai/**` 必须登录；Agent 口不进 `MesPermitAllProvider`
- A3 / P1-D8：库内仍加密；A20 / options 仍不回明文 Key
- 日志、SSE、异常对前端不打印 apiKey / cipher / 上游 `Authorization` / 向量 token
- 不启用 LangChain4j starter 全局 `chat-model.api-key`
- 平台默认 Key 回退仍只允许既有规则（如仅 `tenantId == 0`）；缺 Key 不得 silently 用别人的 Key

Audit and lineage:

- 无新表；沿用 `ai_provider` / `ai_model` / `ai_session` / `ai_message`
- `@Log` 可记 Agent 发起，不记 Key；Tool 调用审计若做另开增量，不改历史 SQL

AI/rule-engine rules:

- Chat 与 embedding 共用键 `(tenantId, modelId)`：动态 `OpenAiStreamingChatModel.builder()` / `OpenAiEmbeddingModel.builder()`（或 61 等价），**不要** `@Autowired ChatModel`
- AiService **允许**，但必须显式按租户从工厂取模型；禁止「全局 `@AiService` + 唯一 `ChatModel` Bean」
- A7：禁止 SQL MCP 与任意 SQL Tool；第一批只读知识检索
- 不搬 ruoyi-ai 工作流帧；不引入过期 `langchain4j-spring-bom`
- DashScope ≠ DashVector

Database rules:

- 根键仍 `ruoyi:`；yml 仅平台占位（`${AI_MODEL_CIPHER_KEY:}`、`${AI_DEFAULT_API_KEY:}`、向量集群），不含租户模型清单
- 不改 include / 专库 catalog（无新表）

## 2. Plan

### Implementation Approach

61 与 62 的冲突按下列冻结处理（实现时不得重开）：

| 点 | 61 | 62 | 本单元 |
| --- | --- | --- | --- |
| 范围 | Chat/Embedding 工厂 | Agent/AiService | **同一波次都做** |
| `@AiService` | 禁止 `@Autowired` 唯一 `ChatModel` | 允许 AiService，键仍是 `(tenantId, modelId)` | AiService 可以；**禁止** starter 全局模型 Bean |
| HTTP | 不改 `/ai/**` | Agent path 由代码单元定，不得削弱 `send` | **冻结** `send`；**新增** `POST /ai/agent/send` |
| Weaviate | 未要求换官方 store | Retriever 检索时带 `tenant_id` | **不换** `WeaviateHttpVectorStore`；Tool 走既有 SPI |
| DashScope | OpenAI 兼容即可 | 未要求 | **不加** community DashScope |
| Vue | 不改 | 「后续 + 仅 Vue3」 | **本单元不改 Vue3** |

实现顺序：

1. `ktg-ai/pom.xml` 增加无 version 的 open-ai（及必要的 core / agentic）依赖；确认无全局 auto-config
2. 实现 `AiChatModelFactory`（名随风格）：`requireTenantModel(modelId)` → 解密 → 缓存 get-or-create `(tenantId, modelId)` → 返回 streaming chat 与 embedding 模型
3. `AiChatServiceImpl.send` / 知识 embedding 改为工厂；删除或停用 JDK `OpenAiCompat*` 出站路径
4. 模型/厂商写路径成功后 evict 对应键
5. Agent：单例拓扑 + 执行时 `chatModel(scope -> factory.get(...))`（或等价）；MemoryProvider；一个知识检索 `@Tool`
6. 薄 Controller：`POST /ai/agent/send`，权限复用 `ai:chat:send`（不新造权限字，避免重开 P1-D14）
7. SSE / Tool 线程装饰 `TenantContext`

### Affected Modules

- `startech-mes-basic/backend/ktg-ai/src/main/java/com/ktg/ai/client/**`（替换 `OpenAiCompatChatClient` / `OpenAiCompatEmbeddingClient`）
- `startech-mes-basic/backend/ktg-ai/src/main/java/com/ktg/ai/service/impl/AiChatServiceImpl.java` 及模型 CRUD evict

- 不改：父 `backend/pom.xml` BOM、`WeaviateHttpVectorStore`、`DashVectorHttpVectorStore`、`startech-mes-front/`、`frontend/`、UReport、generator

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- **冻结不变：** `POST /ai/chat/send` body `{sessionId?, modelId, content}`（既有可选 `knowledgeId` 保持）；响应 `text/event-stream`，`data:` 行 JSON `{content, done}`；`GET/POST /ai/provider|model|session` 及 58 其余 path
- **本单元新增：** `POST /ai/agent/send` body `{sessionId?, modelId, content}`；`text/event-stream`；`data:` JSON `{content, done}`（可选 `reasoning`）；权限 `ai:chat:send`；须 JWT；信封不是 `AjaxResult`
- 非 SSE 仍 `code/msg/data` 与 `rows`/`total`
- 禁止 `/system/message`、禁止 `/chat/send`（无 `/ai` 前缀）
- 内部契约：出站查找键 `(tenantId, modelId)`；Agent 不得只传 modelName

### Persistence Changes

Tables, indexes, migrations, mapper XML, and lifecycle rules:

- 无新表、无增量 SQL。配置继续在 `ai_provider` / `ai_model`。会话消息继续 `ai_session` / `ai_message`
- 若以后要 Agent 配置表，必须 `tenant_id` + include + 专库 catalog（不在本单元）

### Transaction Boundaries

- 读模型行与解密不扩大对话事务
- 与 58 相同：user 消息先提交；assistant 另事务；流失败不回滚 user 行
- 模型 CRUD 提交后 evict 缓存，不把 evict 放进长事务
- Tool 若读库用短事务，**不**包住整个 Agent 循环

### Risks

- Boot 4 open-ai starter 自动装配全局 `ChatModel`，所有工厂共用一把 Key
- 按 `tenantId` 只缓存一个模型，下拉第二个 `modelId` 仍打第一把 Key
- 改 Key 不 evict
- `@AiService` 在启动时 `build()` 钉死 ChatModel
- Tool 捕获构造期 `tenantId`，或 SSE 线程丢上下文后检索串租
- 把 Weaviate/DashVector/MCP/SQL 一并塞进本单元
- 改 `send` 信封导致 Vue3 对话页回归
- 单测打到真实公网模型

### Verification Strategy

- JDK 17 下：`cd startech-mes-basic/backend && mvn -pl ktg-ai -am test`
- 静态：`ktg-ai/pom.xml` 无 langchain4j version；无 `langchain4j-community-dashscope`；无 `langchain4j-weaviate`；yml 无租户模型目录 / 全局 `chat-model.api-key`
- 单测夹具：两租户两 Key；跨租户不调上游；evict 后新 Key；Agent Tool 空上下文失败；`send` 信封回归
- 本单元不跑 Vue `build:prod`、不连 live 模型 / Weaviate / DashVector、不跑现场 JWT
