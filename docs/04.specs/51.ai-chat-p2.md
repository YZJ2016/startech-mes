## 1. Spec

### Capability

- Name: P2 会话与已登录 SSE 对话
- Module: `ktg-ai` chat/session；`ktg-admin` 薄 Controller
- Priority: P2
- Related requirement/design documents:
  - 设计：`docs/03.design/06.mes-ai-platform-plan.md` §3、§5
  - 缺口：`docs/02.requirements/03.mes-ai-platform-gaps.md`（A2、A15、A17、A19、I-A4）
  - 总控：`docs/04.specs/48.mes-ai-platform-program.md`
  - 上一单元：`docs/04.specs/50.ai-model-p1.md`
  - 下一单元：`docs/04.specs/52.ai-frontend-p3.md`

### Business Goal

已登录且已许可用户可建会话、拉历史，并对本租户某个模型发流式对话。上下文来自本会话消息，不挂知识库（55）。

### Scope

In scope:

- 表 `ai_session`、`ai_message` + include + 专库 catalog
- CRUD：`/ai/session`、消息按 session 列表
- `POST /ai/chat/send` SSE：`text/event-stream`；事件含 `content`（可选 `reasoning`）
- OpenAI 兼容流式客户端（JDK HTTP 或最小依赖）
- 会话属 `tenant_id` + `user_id`；他人会话 404
- 异步/流式线程拷贝 `TenantContext`（I-A4）

Out of scope:

- RAG、MCP 帧、工作流 `[NODE_CHUNK_*]`
- Vue 页（52）
- 游客；permitAll
- Agent

### Acceptance Criteria

- 无 token 调 `/ai/chat/send` → 401
- 无 `ai` 许可 → 403
- 使用他租户 `modelId` / `sessionId` → 失败，不调上游
- SSE 结束落 assistant 消息；上游失败有错误事件且不把 key 写入事件
- 单测可用 Mock 上游，不打真实公网模型

### Rules and Constraints

Tenant isolation:

- 会话/消息 include 表
- 模型必须属于当前租户

Security and masking:

- 解密 key 仅在出站调用
- 事件与日志无密钥

Audit and lineage:

- 可选记录 token 用量，不做扣费

AI/rule-engine rules:

- 只 OpenAI 兼容 chat completions 流式
- A17：不兼容 ruoyi-ai MCP/工作流帧

Database rules:

- 消息表可空 `prompt_tokens` / `completion_tokens`

## 2. Plan

### Implementation Approach

- send：校验许可与所有权 → 落 user 消息 → 流式 → 落 assistant
- 上游 URL 来自本租户 `ai_model.base_url`，不是全局写死地址

### Affected Modules

- `ktg-ai`、`ktg-admin`、include yml、专库 catalog、SQL

### Public Contracts

- `POST /ai/chat/send` body：`sessionId`（可空则新建）、`modelId`、`content`
- `/ai/session` CRUD + 消息列表
- 保持信封用于非 SSE；SSE 单独 Content-Type

### Persistence Changes

- `ai_session`、`ai_message`

### Transaction Boundaries

- 用户消息先提交；assistant 另事务。不因流失败删 user 消息

### Risks

- 流式线程丢租户上下文
- 把 `/ai/chat/send` 放进 excludes
- 响应里带回 `apiKey`

### Verification Strategy

- 模块测试 + MockWebServer/等价 Mock
- 不强制连真实模型
