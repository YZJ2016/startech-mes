# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 自动编码整包迁入 `ktg-mes`
- Module: `ktg-common` / `ktg-system` / `ktg-admin` → `ktg-mes`
- Priority: P0
- Related requirement/design documents:
  - `docs/04.specs/00.backend-extract-program.md`
  - `backend/doc/设计文档/数据库设计/mes_sys.sql`（`sys_auto_code_rule` / `part` / `result`）
  - 调查：`ktg-mes` 14 处注入 `AutoCodeUtil`；新若依无此能力

### Business Goal

工单号、SN、领退料单号、检验单号等继续按现有规则生成，但实现不再依赖 `ktg-system.strategy`。换壳替换 `ktg-system` 后编号能力仍在。

### Scope

In scope:

- 迁移实体：`SysAutoCodeRule`、`SysAutoCodePart`、`SysAutoCodeResult` 及枚举 `PartTypeEnum`、`CycleMethodMnum`
- 迁移策略：`AutoCodeUtil`、`PartTypeHandler`、`PartTypeFixCharHandler`、`PartTypeInputCharHandler`、`PartTypeNowDateHandler`、`PartTypeSerialNoHandler`、`PartTypeTemplate`；`PhoneUtils` 仅当编码链路引用时一并迁移，否则在 `09` 处理
- 迁移 `ktg-system` 中 AutoCode 的 Mapper / Service / XML
- 迁移 `ktg-admin` 的 `SysAutoCodeController`、`SysAutoCodePartController`、`SysAutoCodeRuleController`
- 包名收到 `com.ktg.mes` 下（例如 `com.ktg.mes.autocode`），**HTTP 路径保持** `/system/autocode/**`
- `hutool-all` 依赖改由 `ktg-mes` 声明（若迁后 common 不再需要 hutool，从 common 移除，避免换壳后再丢）

Out of scope:

- 改编号算法、补齐规则、循环策略
- 新建另一套编码表
- Security `permitAll` 调整（`08`）
- Spring Boot / JDK 升级

### Acceptance Criteria

- `ktg-system` / `ktg-common` / `ktg-admin` 中不再存在 AutoCode 类名与 `SysAutoCode*Mapper.xml`
- `GET /system/autocode/get/{ruleCode}` 与 `GET /system/autocode/get/{ruleCode}/{inputCharacter}` 路径、方法、响应结构不变
- `/system/autocode/part`、`/system/autocode/rule` 的 list/get/post 行为不变
- `ktg-mes` 原 14 个调用点改为注入迁后的 `AutoCodeUtil`，`genSerialCode` 语义不变
- 表仍为 `sys_auto_code_rule`、`sys_auto_code_part`、`sys_auto_code_result`，无结构变更
- `mvn compile` 覆盖 `ktg-mes` 与 `ktg-admin`

### Rules and Constraints

Tenant isolation:

- 编码规则仍按现有 `rule_code` 全局配置，不按租户拆分

Security and masking:

- 本单元不改变 `/system/autocode/get/**` 的鉴权（现为 permitAll）。收紧放到 `08`
- Controller 仍走 service，不把生成逻辑写进 admin

Audit and lineage:

- 继续把生成结果写入 `sys_auto_code_result`（现有 `saveAutoCodeResult` 行为）
- 不改历史 `mes_sys.sql`，不需要新表则不新增脚本

AI/rule-engine rules:

- 分段策略保持现有 Handler 选择逻辑，不引入新规则引擎

Database rules:

- 禁止改列名/补齐算法相关字段语义
- 不在本单元做数据清洗

## 2. Plan

### Implementation Approach

1. 在 `ktg-mes` 建立 `autocode` 包，按 domain / mapper / service / strategy / controller 迁入
2. MyBatis XML 放到 `ktg-mes/src/main/resources/mapper/`，namespace 与新接口全名一致
3. `ktg-admin` 删除三个 AutoCode Controller，改由 `ktg-mes` 扫描到同等 `@RequestMapping`
4. 确认启动类对 `com.ktg.**` 的扫描已覆盖新包（若依默认扫 `com.ktg`，迁包后应仍能扫到）
5. 从 `ktg-system`、`ktg-common` 删除旧文件，`ktg-mes/pom.xml` 补 hutool（若需要）

### Affected Modules

- `ktg-mes`：迁入全部自动编码实现与 Controller
- `ktg-system`：删除 strategy 与 AutoCode service/mapper
- `ktg-common`：删除三个 SysAutoCode* 实体与两个枚举
- `ktg-admin`：删除三个 Controller；保留对 `ktg-mes` 的依赖

调用点（须改 import，不改业务）：

- `WmSnController`、`WmRtIssueController`、`WmIssueHeaderController`
- `QcIqcController`、`QcDefectController`
- `ProWorkorderServiceImpl`、`ProSalesOrderServiceImpl`、`ProWorkorderController`、`ProTransOrderMobController`、`ProTaskMobController`、`ProTaskController`
- `ItemTypeController`、`DvMachineryTypeController`
- `ItemPurchaseTask`

### Public Contracts

- `GET /system/autocode/get/{ruleCode}`
- `GET /system/autocode/get/{ruleCode}/{inputCharacter}`
- `/system/autocode/part`、`/system/autocode/rule` 现有 CRUD 路径
- Java：`genSerialCode(String ruleCode, String inputCharacter)` 签名保持

### Persistence Changes

- 无新表。Mapper XML 仅改 namespace/包名
- 生命周期：生成编码仍同步写 result 表（现类上有 `@Log` 与 `synchronized`，保持）

### Transaction Boundaries

- 保持 `genSerialCode` 现有同步与落库范围，不扩大到外层业务单据事务之外（调用方事务仍由原 Service/Controller 决定）

### Risks

- Mapper namespace 漏改导致运行期绑定失败
- `PhoneUtils` 误删或误迁（先确认是否仅被编码占用）
- hutool 仍留在 common 又被换壳丢掉

### Verification Strategy

- 文件检索：`AutoCodeUtil`、`SysAutoCodeRule` 仅出现在 `ktg-mes`
- 对照 14 个调用点全部改完
- Maven compile；有环境时用已有规则码打一次 GET 生成接口（本 spec 不强制无环境通过）
