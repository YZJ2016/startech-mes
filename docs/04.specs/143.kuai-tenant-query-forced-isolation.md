### Business Goal

一个机制强制组织条件，覆盖租户模型的读，以及 queryset 写（`.filter(...).update()` / `.delete()`）。收口范围是经 API handler 可达的这些读写。超级管理员跨组织必须显式、可审计。保留 `DataScopeService` 作为组织内行权限（全部/部门/本人/自定义），不要和组织间隔离混成一层。本期不上 RLS。约 12509 处 `tenant_id=` 含写入赋值与注释，不是本单元要改完的泄漏条数。

### Scope

In scope:

- 收口机制：一个机制强制组织条件，覆盖租户模型的读，以及 queryset 写 `.filter(...).update()` / `.delete()`（强化/推广 `TenantQuerySet` / `get_tenant_queryset` 等既有设施，或等价中间层——**一个机制**，不要按文件拆成多个 spec）。机制不能只收读
- 迁移范围：经 API handler 可达、作用于租户模型的读和写。以机制 + 抽样/门禁测试证明。约 12,509 处 `tenant_id=` 含写入赋值与注释，不是泄漏条数，本期不要求改完这些字面，也不上 RLS
- 超级管理员跨组织：显式 API/上下文开关 + 审计日志；默认仍本组织
- 与 140–142 协作：其新查询在合并前必须走本机制（或临时 `tenant_id` + 标注，合并时删临时）
- 保留 `DataScopeService` 语义，文档与代码注释区分「组织间」vs「组织内」

Out of scope:

- 按文件拆多个租户 isolation spec；本期上 PostgreSQL RLS
- 把 Startech `TenantLineInterceptor` / Java 过滤器抄进快格当步骤清单
- 第 6 项设备绩效 / OEE / 数采；上帝服务拆分；补 CI；APS；行业包空壳
- 改 `startech-mes-basic/`

### Acceptance Criteria

1. 经 API handler 可达的租户模型读和 queryset 写：无租户上下文不得查出或改到数据（失败关闭）；有上下文则结果不含他组织行，`filter().update()` / `delete()` 不得改到他组织行（抽样 + 机制级测试）。
2. 跨组织仅显式超级管理员路径可访问，且每次可审计（谁、何时、哪个组织、哪个资源）。
3. `DataScopeService` 行为保持；测试或文档证明其不替代组织间隔离。
4. 140–142 合并清单：新查询已走强制入口，无「永久手写 tenant_id 最终方案」。
5. 验收范围是 API handler 可达的租户模型读写，不是仓库里每一处 `tenant_id=`。约 12,509 含写入赋值与注释，不把它当作已修泄漏数，也不要求本期改完；验收以机制 + 关键路径证明为准。本期不上 RLS。
6. 本单元未改 Startech 代码。

## 2. Plan

### Implementation Approach

1. 选定单一强制入口，同时罩住读和 queryset 的 `update()` / `delete()`。
2. 门禁测试：无上下文、错租户 id、显式跨组织审计。
3. 为 140–142 提供「新代码必须用的」API 约定；临时手写路径列替换清单。
4. 文档区分 DataScope（组织内）与 Tenant（组织间）。
5. **不**按目录拆多个 isolation spec；**不**粘贴 Startech 拦截器移植步骤。

### Affected Modules

- 租户查询基础设施（`src/infra/domain/query_filter.py` 的 `TenantQuerySet` / `get_tenant_queryset`，及既有租户上下文 `src/infra/domain/tenant_context.py`）
- 超级管理员跨组织显式入口 + 审计
- 140–142 新增查询的落地约定（调用方）

### Public Contracts

- 对内：业务 service 读模型的推荐/强制 API。
- 对外 HTTP：默认仍本组织；跨组织若暴露管理端点须权限码 + 审计，路径实现时钉死。

### Persistence Changes

- 一般无表结构变更；审计若无表则复用既有审计中间件/表。

### Transaction Boundaries

- 只读查询无事务要求。queryset 写（`filter().update()` / `delete()`）与写前读都须已带组织条件；业务事务边界仍由各单据负责。

### Risks

- 以为改了 TenantQuerySet 就覆盖 12k 处 → 用机制默认管理器/lint/测试门禁，避免虚假安全感。
- 与 DataScope 叠加顺序错误 → 先组织间再组织内，单测锁。

### Verification Strategy

- 见 §3；§4 实跑后填。
