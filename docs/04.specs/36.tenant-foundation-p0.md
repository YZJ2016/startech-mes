### Business Goal

在共享主库上落下租户注册表与失败关闭的行级拦截器骨架：创建租户时可选择 `ROW`（默认）或 `DATABASE`；`DATABASE` 的 JDBC 口令以 AES-256-GCM 加密落库；本阶段仍全部打主库，已登记的 `DATABASE` 租户不得登录、不得把该厂数据写入共享库。为 P1 登录绑定与后续专库路由提供 `TenantContext`、拦截器与种子租户（平台 0 / 默认工厂 1）。

### Scope

In scope:

- 新增 `TenantContext`（ThreadLocal + `getRequired()` 空则异常）、MDC key `tenantId`、`@TenantIgnore`
- 新增 `TenantLineInterceptor`：对 **include 名单** 表失败关闭（无上下文抛错；SELECT/UPDATE/DELETE 用占位符加 `tenant_id = ?`；INSERT 填充/校验）；忽略表 SQL 不加 `tenant_id`
- P0 生产 include 名单 **为空或仅演示表**（不得把 `sys_user` 等现网身份表纳入，以免 P1 之前打挂登录）
- `MyBatisConfig` 显式 `setPlugins`：同时保留 `FieldMetaObjectHandler` 与租户拦截器
- 增量 SQL：`CREATE sys_tenant`、`sys_tenant_license`；种子租户 0=`platform`、1=`default`，均为 `ROW`，无 `server_name`、无 JDBC（D10）
- 为写入平台账号：`sys_user` / `sys_role` **本单元即加** `tenant_id`（DEFAULT 1 并回填）；插入 `user_name=platform`、`tenant_id=0`（**不是** `user_id=1`）；角色 `platform_admin`（`role_key=platform_admin`）只绑该用户，永不许可给工厂。口令 **不进 SQL**
- 首次启动用环境变量 `PLATFORM_ADMIN_PASSWORD` 对平台用户做 BCrypt 写入；生产 profile 缺变量 → 拒绝启动（D3）
- 创建租户 API 接受 `isolationLevel`；`DATABASE` 必填 JDBC URL/用户/口令并以 AES-256-GCM 加密为 `jdbc_password_cipher`；密钥仅 `TENANT_JDBC_CIPHER_KEY`
- `ROW` 且 JDBC 任一字段非空 → HTTP 400，不落库、不静默丢弃（S6）
- 列表 BO 只回打码 JDBC URL、用户名、打码口令；**无 password / cipher 字段**；揭明文接口本阶段不做
- `TenantLoginGuard`：`isolation_level=DATABASE` → 拒绝登录（失败关闭，D7）；本单元提供可测守卫，P1 接到全部登录入口
- 启动门禁：已有 `DATABASE` 租户但缺 `TENANT_JDBC_CIPHER_KEY` → 拒绝启动
- 更新租户若本单元提供：拒绝改 `isolation_level` 与 JDBC 目标 URL/库（D8）；口令覆盖可留待后续平台页
- 增量脚本命名：`startech-mes-basic/backend/sql/YYYYMMDD_NN_topic.sql`（接现有最大号 `20260820_08`，本单元用 `20260821_09`）

Out of scope:

- **按租户切 DataSource / 懒加载专池**（P-D，`41.tenant-dedicated-ds-pd.md`）。本阶段全部打主库
- I8：忽略名单 Mapper 整接口绑定主库（落 41，不是本单元）
- P1：`POST /login` 必填 `tenantCode`、JWT/`LoginUser.tenantId`、身份表其余列与唯一键
- P2：Redis `TenantCacheKeys`、上传前缀 `tenant/{id}/`、异步 TaskDecorator、WebSocket（I9）
- P3：许可裁剪 `getRouters`、菜单挂点；不克隆 `sys_menu`
- Vue3 租户管理页（P9，`startech-mes-front/`）；**不改** Vue2 `startech-mes-basic/frontend/`（F1）
- 揭明文 JDBC 接口（F4 后续）；runAs（F9）；停用即 SCAN token（D6，P1，依赖 `LoginUser.tenantId`）
- `sys_config` overlay（放入 P1）；MES 业务表加列；跨租户报表（D5）
- 引入 Jugg Maven、Sa-Token、MyBatis-Plus、JPA、第二套 JWT；fail-open 开关；每租户 Redis
- MQ / Feign / OpenAPI / BPM 租户传播（v1 非目标）
- 原地改写 `ry_*.sql` / `mes-*.sql` / `quartz.sql`
- 启用第二个工厂（ROW 门禁在 P4；DATABASE 门禁在 P-D）

### Acceptance Criteria

对齐设计第 9 节 P0 退出标准：

- 单测：无上下文访问 include 表 → 异常；忽略表 SQL 无 `tenant_id`；INSERT 填充 `tenant_id` 为当前上下文
- `MyBatisConfig` 同时保留 `FieldMetaObjectHandler` 与租户拦截器（`setPlugins` 可见两者）
- 创建 `ROW` 租户成功；创建 `DATABASE` 缺 JDBC 失败；`ROW` 且带 JDBC 字段 → HTTP 400，库中无该行
- 列表响应 JSON **无 password 字段**，无 cipher 明文；JDBC URL/口令仅打码
- 种子：租户 0 = `platform`、1 = `default`，均为 `ROW`，均无 `server_name`、无 JDBC（D10）。平台用户 `user_name=platform`、`tenant_id=0`
- 缺 `TENANT_JDBC_CIPHER_KEY` 且已有 DATABASE 租户 → 拒绝启动；缺 `PLATFORM_ADMIN_PASSWORD`（生产）→ 拒绝启动
- `TenantLoginGuard` 对 DATABASE 租户拒绝登录（单测即可；HTTP 登录入口由 P1 接线）
- 平台租户强制 `ROW`：创建/更新时 `is_platform=Y` 配 `DATABASE` 或 JDBC → 400
- `mvn -pl ktg-framework,ktg-common -am test` 实际跑过（见第 4 节；本 spec 撰写时 **未执行**）
- 文档与代码不含真实 JDBC URL、口令、生产主机

### Rules and Constraints

Tenant isolation:

- 默认 `ROW`（共享主库 + `tenant_id`）；创建时可选 `DATABASE`（独立 JDBC 元数据落主库，本阶段不切池）
- 两档共用同一拦截器；独立库将来仍过滤 `tenant_id`（纵深防御）
- 无上下文访问 include 表 → 抛错，不执行 SQL（失败关闭，禁止 fail-open 开关）
- 失败关闭只覆盖 **include 表**。表名不在 include、也不在 ignore → `skipTable` 跳过改写（静默放行）。这不是「关掉拦截器」的开关；新 Mapper 表必须进 `tenant.line.include-tables` 或明确进 ignore。类级 `@TenantIgnore` 的 Mapper 即使表在 include 也不改写 SQL（job 目录见 spec 45）
- 平台租户 `tenant_id=0` 强制 `ROW`，始终走主库，不允许配独立 JDBC
- SQL **永不跳过 `tenant_id`**（含现网 `user_id=1` 的 admin）。`user_id=1` 不是平台标志
- P0 include 为空或演示表；未加列的 MES 表不强制谓词。P4 之前不得写入第二套工厂业务数据
- 已登记 `DATABASE` 租户：拒绝登录，**永不**把该厂业务/身份数据写入共享主库（D7）
- 拦截器拼接必须占位符绑定 `tenantId`，禁止把 ID 拼进 SQL 字符串
- `@TenantIgnore` 仅用于平台 API / 全局表 Mapper（`sys_tenant`、许可等）；禁止用 `isAdmin()` 代替

Security and masking:

- 不引入第二套认证；本单元不改登录契约（P1 才强制 `tenantCode`）
- JDBC 口令算法 **AES-256-GCM**（JDK `AES/GCM/NoPadding`）；密钥只来自 `TENANT_JDBC_CIPHER_KEY`（32 字节，hex 或 base64）；IV/nonce 每次随机并与密文同存；密钥轮换不进一期（S6）
- 列表默认打码；禁止 API 回传 cipher 当密码；禁止在日志/异常/审计中打印口令、token、JDBC URL 中的密码、内部绝对路径
- `ROW` + JDBC 任一字段非空 → HTTP 400，不落库
- 平台用户口令不进 SQL、不进文档；只从 `PLATFORM_ADMIN_PASSWORD` BCrypt
- 创建 API 不接受、不返回明文 password 列名以外的「回填口令」
- 允许为 SQL 改写在 `ktg-framework` 增加 **JSqlParser**（固定版本、仅改写）；禁止 MyBatis-Plus、Sa-Token、Jugg

Audit and lineage:

- 历史 SQL 只追加增量，不原地改写
- 种子不绑生产域名（D10）；上线后由平台页配 Host（F10，非本单元）
- 揭明文与停用 SCAN token 不在本单元；本单元审计字段仍走现有 `create_by` / `create_time`（`FieldMetaObjectHandler`）
- 角色 `platform_admin` 永不许可给工厂；不把平台租户管理菜单克隆进工厂

AI/rule-engine rules:

- 本单元不涉及规则引擎或 AI

Database rules:

- 脚本只放 `startech-mes-basic/backend/sql/`，命名 `YYYYMMDD_NN_<topic>.sql`，本单元：`20260821_09_sys_tenant.sql`（若目录在实现当日已有更大 `NN` 则顺延，禁止改历史号、禁止插空）
- `sys_tenant` 建议列：`tenant_id` PK、`tenant_code` 全局唯一、`tenant_name`、`status`、`expire_time`、`is_platform`、`isolation_level` 默认 `ROW`、`server_name` 可空（非空则全局唯一）、`jdbc_url` / `jdbc_username` / `jdbc_password_cipher` 可空。无明文口令列
- `sys_tenant_license`：至少 `tenant_id`、`module_code`、许可过期；本单元只建表，不填业务许可（P3）
- `tenant_id bigint not null`；身份表加列时 `DEFAULT 1` 再 `UPDATE ... WHERE tenant_id IS NULL`（本单元仅 `sys_user`/`sys_role`）
- 禁止一次 ALTER 全部 MES 表；`sys_config` overlay 留 P1
- `DATABASE` 专库 DDL 将来与主库同一套（含 `tenant_id` 与复合唯一键）；本单元不建专库、不跑专库脚本

## 2. Plan

### Implementation Approach

1. **SQL 先于代码：** 追加 `20260821_09_sys_tenant.sql`：建 `sys_tenant` / `sys_tenant_license`；插入租户 0/1；`sys_user`/`sys_role` 加 `tenant_id` 并回填 1；插入平台用户（无口令）与 `platform_admin` 角色并绑定。不写真实口令。
2. **ktg-common：** `com.ktg.common.tenant` 包：`TenantContext`、`@TenantIgnore`、`IsolationLevel` 枚举（`ROW`/`DATABASE`）、`TenantJdbcCipher`、租户相关异常。`TenantContext.set/clear` 同步 MDC `tenantId`。
3. **拦截器：** `ktg-framework` `TenantLineInterceptor` 读可配置 include / ignore。忽略至少：`sys_tenant`、`sys_tenant_license`、`sys_menu`、`sys_dict_type`、`sys_dict_data`、`gen_table`、`gen_table_column`、`QRTZ_*`、`sys_config`。P0 include = 空或 `tenant_line_demo`（仅测试）。无上下文 + include 表 → 异常。
4. **注册插件：** `MyBatisConfig.sqlSessionFactory` 注入全部 `org.apache.ibatis.plugin.Interceptor` Bean 并 `setPlugins`（覆盖 `FieldMetaObjectHandler` 与新拦截器）。`ktg-framework` 不直接依赖 `ktg-mes` 类型。若当前自定义 Factory 导致审计拦截器未挂上，本单元一并挂上并回归 INSERT 审计字段。
5. **守卫与启动：** `TenantLoginGuard.assertLoginAllowed(SysTenant)`：停用/过期拒绝；`DATABASE` 拒绝（P-D 前）。`ApplicationRunner`/`EnvironmentValidator`（建议 `ktg-admin` 或 `ktg-framework`）：有 DATABASE 租户则必须能解密密钥；生产缺 `PLATFORM_ADMIN_PASSWORD` 拒启动；平台用户口令为空则 BCrypt 写入。
6. **平台 API：** 薄 Controller 在 `ktg-admin`，业务在 `ktg-system`。创建/列表；`ROW`+JDBC→400；`DATABASE` 缺三项→失败；列表打码。权限：`@PreAuthorize("@ss.hasRole('platform_admin')")`（P1 再加 `tenantId==0` 校验）。不实现揭明文、不切 DS、不克隆菜单。
7. **测试：** 拦截器纯单测（mock MappedStatement / 改写 SQL）；Cipher 加解密与篡改失败；Guard 对 DATABASE 拒绝；可选 MockMvc 创建契约。最后跑 `mvn -pl ktg-framework,ktg-common -am test`。

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- 保持既有：`POST /login`、`GET /getInfo`、`GET /getRouters`、Bearer、`code/msg/data`。**本单元不改登录 Body。**
- 新增（仅平台角色 `platform_admin`）：
  - `POST /platform/tenant`：Body 含 `tenantCode`、`tenantName`、`isolationLevel`（缺省 `ROW`）、可选 `serverName`、`jdbcUrl`/`jdbcUsername`/`jdbcPassword`（仅 DATABASE）。成功 `code/msg/data`，data 为打码后的租户，**无 password**
  - `GET /platform/tenant/list`（或项目既有分页风格 `/list` + `pageNum/pageSize`）：返回编码、可选域名、隔离级别、部分打码 JDBC、用户名、打码口令
  - 可选 `PUT /platform/tenant`：可改名称/状态/过期；**拒绝** `isolationLevel` 与 JDBC URL/库变化（HTTP 400，D8）
- 校验：
  - `ROW` + 任一 JDBC 字段非空 → 400，不落库
  - `DATABASE` 缺 URL/用户/口令 → 失败
  - 平台租户不可被建成 `DATABASE`
- 不新增登录后仍生效的客户端租户 Header
- 不把 JDBC 明文、cipher、`TENANT_JDBC_CIPHER_KEY`、`PLATFORM_ADMIN_PASSWORD` 放入任何响应
- `TenantLoginGuard` 不是 HTTP API；P1 登录必须调用
- 匿名 Host 解析接口属 P1，本单元不提供租户列表接口（F5：禁止登录前拉全量）

### Persistence Changes

Tables, indexes, migrations, mapper XML, and lifecycle rules:

- 新文件 `startech-mes-basic/backend/sql/20260821_09_sys_tenant.sql`（名称随目录最大 `NN` 顺延）：
  1. `CREATE TABLE sys_tenant`（列见 Database rules）；`uk_tenant_code (tenant_code)`；`server_name` 非空唯一（可用生成列或应用层保证空串当未绑定）
  2. `CREATE TABLE sys_tenant_license`

  4. `ALTER TABLE sys_user ADD tenant_id bigint NOT NULL DEFAULT 1` + 回填；`ALTER TABLE sys_role` 同样。**本单元不加 UNIQUE**（P1 做 `uk_tenant_user` 等，且须幂等跳过已存在列）
  5. `INSERT` 平台用户：`user_name='platform'`，`tenant_id=0`，`status` 正常，`password` 空或占位（**不是**可登录明文，也不是文档示例口令）；`user_id` 走自增，禁止写成 `1`
  6. `INSERT` 角色 `role_name` 平台运营、`role_key='platform_admin'`、`tenant_id=0`；`sys_user_role` 只绑平台用户。不要给 `user_id=1` 绑此角色

- 列表查询不得 `SELECT jdbc_password_cipher` 到前端 BO；Service 层打码
- 生命周期：`DATABASE` 创建只登记加密 JDBC，**不** `CREATE DATABASE`、不迁表（I7 在 41）。登记后 Guard 拒登录
- 回滚：同目录可另附注释块说明 DROP/DELETE 顺序；禁止改 `20260821_09` 已执行内容，修正用新 `NN`

### Transaction Boundaries

- 创建租户：基本信息 +（DATABASE 时）加密 JDBC **同一事务**写入 `sys_tenant`。加密在进事务前完成；密钥缺失则不进事务
- 建 schema / 迁表 **不是**本单元事务（I6/I7 在 P-D）；失败不得为对齐而把该厂写入共享业务表
- 平台口令 Bootstrap：单行更新 `sys_user.password`（仅 `user_name=platform` 且 `tenant_id=0`）；不扩大到其他用户
- 拦截器在 SQL 层，不新开业务事务、不扩大现有 `@Transactional`

### Risks

- include 名单过早纳入 `sys_user` → P1 之前登录无 `TenantContext` 直接 500。必须保持 P0 include 空/演示
- 自定义 `SqlSessionFactory` 未 `setPlugins` → 拦截器形同未装；或只装租户、丢掉审计填充
- 加密密钥进仓库 / 打码失败回传 cipher / 日志打印 JDBC 口令
- 平台用户被写成 `user_id=1` 或回填把 `tenant_id=0` 覆盖成 1
- P0 允许 DATABASE 登录或业务写入主库，造成「自称专库、数据在共享库」
- 生产缺 `PLATFORM_ADMIN_PASSWORD` 未拒启动，留下空口令账号
- 用 `isAdmin()` 跳过租户谓词（本单元即禁止该写法）
