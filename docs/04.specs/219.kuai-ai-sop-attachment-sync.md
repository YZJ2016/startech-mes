# KU-AI：SOP 附件同步进知识库

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已完成；§1 决策已于 2026-10-23 选定（X7=a）。

## 1. Spec

### Capability

- Name: 扩展 spec 200 的 SOP→知识库同步：把 SOP 附件（PDF/Word/图片等）一并解析入库或作为文档附件检索。
- Module: `riveredge-backend/src/apps/kuaiai`（同步任务）、master_data SOP 附件存储读取、kuaiai 文档解析管线。
- Priority: P3 跟进项（S11 的作业指导完整性；spec 200 S2=a 遗留缺口）。
- Related requirement/design documents: 需求 25 SC-D11；设计 26 §4；前置 spec 200。

### Business Goal

spec 200 只同步了 SOP 电子正文；实际工厂里大量 SOP 的关键参数在附件（带图工艺卡、扫描 PDF）。本单元把附件内容纳入知识库，让“焊接电流多少”这类问题能命中附件里的参数。

### Scope

In scope:

- 同步任务扩展：处理 `hybrid`/含附件 SOP 的 `attachments` 字段，逐个附件拉取文件 → 走 kuaiai 现有文档解析管线（pdf/docx/xlsx 等已支持类型）→ 抽取文本合并进该 SOP 对应的知识文档（同一 `source_ref` 文档，分段标注来源为附件名）。
- 附件新增/删除时的增量同步：复用 spec 200 的版本化任务，按附件列表差异更新文档内容。
- 不支持的附件类型（扫描件无文本层、视频等）：跳过该附件并在同步日志记录“附件 X 未解析（类型不支持/无文本层）”，正文不受影响。
- 附件大小/数量上限：沿用文档解析管线现有限制，超限附件跳过并记录。

Out of scope:

- OCR（扫描件图片转文字，KR-D18 明确不在范围）。
- 附件原文下载/预览入口。

### 决策（2026-10-23 已选定）

选定：**X7=a** —— 附件文本合并进同一知识文档，按“【附件：文件名】”分段标注。

| 编号 | 场景 | 选项 | 推荐与理由 |
| --- | --- | --- | --- |
| X7 | 附件文本和正文合成一个知识文档后，检索命中时用户问出处。一个文档内正文+多附件文本混在一起，溯源到具体附件会变难 | a. 附件文本合并进同一文档，按“【附件：文件名】”分段标注；b. 每个附件单独建一条知识文档，与主文档通过 metadata 关联 | **a**：实现简单、命中时模型转述会带出附件名；b 文档数膨胀，版本/作废联动要处理多文档，复杂度高。分段标注已能溯源 |

### Acceptance Criteria

1. 含附件 SOP 发布后，知识文档含正文 + 各可解析附件文本，分段标注附件名。
2. SOP 作废时下架整篇文档（含附件内容）；附件增删触发增量更新且幂等。
3. 不支持/超限附件跳过并记录日志，同步任务不失败。
4. spec 200 的正文同步行为不回归（正文-only SOP 结果不变）。

### Rules and Constraints

Tenant isolation:

- 任务携带 `tenant_id`；附件读取走文件存储现有租户路径。

Security and masking:

- 附件内容视同 SOP 正文，沿用知识库权限继承；不在日志记附件明文。

Audit and lineage:

- 同步日志记录每附件处理结果（解析成功/跳过原因）。

AI/rule-engine rules:

- 解析为确定性管线，LLM 只消费抽取文本。

Database rules:

- 无新表；若需记录附件级同步状态，优先用现有同步日志/文档 metadata 字段，T1 定。

### Public Contracts

- 无新增对外接口；知识文档内容结构按 X7 方案。

### Persistence Changes

- 无（除非 T1 发现需附件级状态字段）。

### Transaction Boundaries

- 附件解析失败不回滚正文同步；整篇文档更新为一次写入。

### Risks

- 大附件解析慢：任务设超时与单附件大小上限，超限跳过。
- 附件含敏感工艺参数：已属知识库权限范围，沿用文档权限。

### Verification Strategy

- 单测：多附件拼接、分段标注、不支持类型跳过、增量更新幂等、作废下架。

Result:

- T1 核对事实（源码为准）：
  - 附件字段：`SOP.attachments` 为 `JSONField`（`apps/master_data/models/process.py:494`）。前端 `normalizeDocumentAttachments` 落库形态为 `list[dict]`，项含 `uid=<core_files.uuid>`、`name=original_name`、`status`、`url`（`documentAttachments.ts:65-93`）；文控侧另容忍 `{"files": [{uuid, name/original_name}]}` 字典形态（`sop_control_service.py:56-65`、`sopAttachments.ts:18-27`）。上传字段 `DocumentAttachmentsField` 默认 `max=10`（`DocumentAttachmentsField.tsx:24`）。
  - 文件拉取：`FileService.get_file_by_uuid(tenant_id, uuid)`（`core/services/file/file_service.py:219`）租户过滤后返回 File 行（`file_size`/`original_name`/`file_extension`）；`FileService.get_file_content(tenant_id, uuid)`（同文件 :700）按存储后端读本地/对象存储 bytes，租户路径 `{tenant_id}/{yyyy}/{mm}/...`。
  - 解析管线：`extract_text(ext, data)`（`document_parsers.py:115`）支持 `pdf/docx/pptx/xlsx/xls/md/markdown/txt/text`；`doc/ppt` 旧二进制、未知扩展名、魔数不符、空文本一律 `ValidationError`（无文本层 = 「解析结果为空文本」）。大小上限沿用 `FileService.MAX_FILE_SIZE`（默认 100MB）；`raw_content` 上限 200000 字符（`_RAW_CONTENT_MAX` 截断）。
  - 版本化/幂等：`run_sop_knowledge_sync(tenant_id, sop_id)`（`core/tasks/ai_tasks.py:45`）不带版本参数、以 SOP 当前状态为准（乱序安全）；文档身份 = `(tenant_id, source_ref_type="sop", source_ref_id)` 部分唯一；作废/纸质/无正文 → `KnowledgeService.delete_document` 软删文档+chunks。附件增删无需 diff 检测——每次同步按当前 `attachments` 全量重建同一 `raw_content`，天然幂等。
- 实现：`sop_sync_service.py` 扩展——`_iter_sop_attachments`/`_attachment_ref`/`_attachment_ext`/`_attachment_sections` 归一化并逐附件拉取解析，成功项渲染 `【附件：{name}】\n\n{text}` 段拼接进同一 `raw_content`（正文后）；跳过原因（缺 file_uuid/类型不支持/文件不存在/超限/解析失败）逐条 warning 日志，不记附件明文；附件数 >10 截断处理；同一 file_uuid 去重；文档更新仍为单次写入后 `index_document`。
- 审计后修复：`_attachment_ext` 裸扩展名候选补 `isascii` 约束（`isalnum` 对「点检表」等 CJK 展示名也返 True，无扩展名展示名不再被误判为扩展名，`sop_sync_service.py:185`）；附件数 >10 被截断丢弃的项计入 `skipped`（统计口径=「未进入正文的附件数」）；附件拉取异常区分「文件不存在或已删除」（`NotFoundError`）与「读取失败（error_type）」（其余异常记类型不记明文）。

Behavior delivered:

- 生效且有电子正文的 SOP 同步时，`attachments` 中每个可解析附件（pdf/docx/pptx/xlsx/xls/md/txt 等）经 `FileService` 租户路径拉取、`extract_text` 解析，文本以「【附件：文件名】」分段拼接进该 SOP 同一 `("sop", sop.id)` 知识文档；附件增删由全量重建幂等覆盖，不产生第二条文档。
- 不支持类型、无文本层（扫描件）、超 100MB、文件缺失/无标识、附件数 >10 等逐条跳过并记同步日志（文件名+原因，无附件明文），任务不失败、正文不回滚；作废时下架整篇（含附件段）。
- 任务携 `tenant_id`；未引入 OCR；无新表/新接口；spec 200 正文-only 路径不回归。
