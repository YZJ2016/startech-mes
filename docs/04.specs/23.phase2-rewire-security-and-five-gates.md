## 1. Spec

### Capability

- Name: 阶段 2a 在 SecurityFilterChain 上重挂五项接线
- Module: `ktg-framework`（FilterChain）+ `ktg-admin`（notice / CommonController / yml）+ `ktg-system` / `ktg-common`（只勾选，原则上 `21` 已装回）
- Priority: P0
- Related requirement/design documents:
  - `docs/04.specs/19.backend-shell-swap-phase2-program.md` 五项检查单
  - 阶段 1：`16` / `17` / `18`（契约相同，**栈不同**）
  - 路径表：`08` + 现行 `MesPermitAllProviderImpl`

### Business Goal

在若依 springboot3 的 **Spring Security 6** `SecurityFilterChain`（`authorizeHttpRequests` + `requestMatchers`）上，确认阶段 1 的五项接线没有被 2a 覆盖冲掉。这是 **重做检查 / 重挂**，不是第一次从平台抽出 MES。前缀在阶段 1 结束后已应是 `ruoyi:`。

### Scope

In scope:

- 对照 `RuoYi-Vue-springboot3/ruoyi-framework/.../SecurityConfig.java` @ `9e3fb55f46d9998c6cecefd04fcf55c5d17158af`：
  - `@EnableMethodSecurity(prePostEnabled = true, securedEnabled = true)`
  - `@Bean SecurityFilterChain filterChain(HttpSecurity)`
  - `permitAllUrl.getUrls().forEach(url -> requests.requestMatchers(url).permitAll())`
  - 标准放行：`/login` `/register` `/captchaImage`、静态、`/swagger-ui.html` `/v3/api-docs/**` `/swagger-ui/**` `/druid/**`
  - **没有** `MesPermitAllProvider` —— 必须在 nested 再挂上
- 挂法（与阶段 1 同一职责，API 换成 requestMatchers）：
  - `@Autowired(required = false) MesPermitAllProvider mesPermitAllProvider;`
  - 在 `authorizeHttpRequests` 闭包内、`anyRequest().authenticated()` **之前**：若 provider 非 null，对其 `getPermitAllAntMatchers()` 逐条 `requests.requestMatchers(url).permitAll()`
  - 禁止把路径写成 framework 字面量
- 五项全表勾选（见下）；缺哪项回到 `21` 对应模块修，不要在 `23` 开新范围（例如不要改 mes 业务）
- 接口方法名可保持 `getPermitAllAntMatchers()`（避免无谓改 mes）；Javadoc 若仍写 `antMatchers` 可改成 `requestMatchers`，非必做
- yml：确认根键 `ruoyi:` 仍在；若 `21` 误覆盖了值，**把 nested 原值救回**，不要从对照仓抄密钥

Out of scope:

- 修改 `MesPermitAllProviderImpl` 路径集合（含「为 PathPattern 改写 `/**`」）——无 401 探测证据前不动
- 扩大匿名面；恢复 `/mobile/**` 整段放行
- 引入第二套 `SecurityFilterChain`、第二套 JWT、mes 内再写一套 `WebSecurityConfigurerAdapter`
- Boot 4.1 API（`24` 后再勾一次，见 `26`）
- 前端 Vue3
- 启动应用（无环境则五项里运行时项进 Known gaps）

### Acceptance Criteria

五项表全部 `[x]` 或书面豁免（豁免须写原因，不能是「大概还在」）：

1. **前缀**：`RuoYiConfig` `prefix = "ruoyi"`；admin 的 `application.yml` 根键为 `ruoyi:`（检索不要把值贴进文档）
2. **PermitAll**：common 有接口；mes 有 `MesPermitAllProviderImpl`；`SecurityConfig` 注入并 `requestMatchers` 放行；`rg "/mes/|ureport|autocode|loginOuth|/mobile/" backend/ktg-framework/src/main/java/com/ktg/framework/config/SecurityConfig.java` 无 MES 字面量
3. **notice list**：mes `SysNoticeListController` 仍 `GET /system/notice/list`；admin `SysNoticeController` 无 `@GetMapping("/list")`（`/listTop` 等若依已读 HTTP 阶段 1 已默认删，保持删）
4. **uploadMinio**：mes `MesMinioUploadController` 仍 `POST /common/uploadMinio`；admin `CommonController` 无该映射
5. **手机号登录**：`UserDetailsServiceImpl` 含阶段 1 同一套正则与 `selectUserByMobile`；system Mapper 方法仍在；无平行 `TokenService`

另外：

- 仍只有一套 JWT：`JwtAuthenticationTokenFilter` + `Authorization`
- 标准 `/login` `/logout` `/captchaImage` 仍 permitAll
- 未跑探测不得写「401 已验证」

## 2. Plan

### Implementation Approach

1. 读覆盖后的 `SecurityConfig`，对照 springboot3 文件确认 FilterChain lambda 还在
2. 补上 Provider 注入与循环 `requestMatchers`（若 `21` 已做，本步只 diff 确认）
3. 按五项表 `rg` 勾选；失败则回 `21` 的 common/framework/system/admin，不在 mes 改 URL
4. 若 `21` 把若依 `SysNoticeController` `/list` 又带回来：删除该方法（或整个 mapping），保留 mes 列表
5. 文档 UI 放行跟对照（`/v3/api-docs/**`），不要把已删除的 springfox `/webjars/**` 当必做

Security 6 注意：`requestMatchers(String)` 默认 PathPattern。`/mobile/login/**` 等 ant 写法 **先保持字符串不变**。行为差异只在有环境的 401 探测后另开缺口，不在本单元猜测修改。

### Affected Modules

- 可能改：`ktg-framework` `SecurityConfig`、`UserDetailsServiceImpl`；`ktg-admin` notice/common/yml
- 只读勾选：`ktg-common` 接口、`ktg-mes` 实现与两个 Controller、`ktg-system` mobile SQL

### Public Contracts

- 五项 URL 与认证头不变

### Persistence Changes

- 无

### Transaction Boundaries

- 无

### Risks

- 只编译通过就勾五项
- Provider 为 null 时静默丢掉全部 MES 匿名（`required = false` 是故意的：无 mes 依赖的测试模块不炸；**admin 运行时必须能扫到 mes 的 `@Component` 实现**）
- 双 FilterChain 或把 permitAll 加在 `anyRequest` 之后导致全部拦截
- yml 对照覆盖导致密钥丢失或端口变成 8080

### Verification Strategy

静态 `rg` +（有环境时）未登录探测。探测不写主机。命令见第 3 节。
