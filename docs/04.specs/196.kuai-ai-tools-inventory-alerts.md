# KU-AI 场景 Tool：库存预警、补货建议与呆滞料

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施。

## 1. Spec

### Capability

- Name: 新增只读 Tool `query_inventory_alerts`、`query_replenishment_suggestions`、`query_slow_moving_inventory`。
- Module: `riveredge-backend/src/apps/kuaiai/services`（tools 适配层）、manifest `ai_tools`。
- Priority: P1（场景 S21 库存/呆滞/补货建议；S02 缺料辅助）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D5、SC-D7、SC-D12、§4.2；设计 26 §4、§5；前置 spec 189、190。

### Business Goal

仓管与计划员能问“哪些物料触发库存预警”“系统给了哪些补货建议”“有哪些呆滞料、多久没出库”，回答来自现有预警、补货、呆滞分析的真实结果。

### Scope

In scope:

| Tool | 参数 | 底层 service（已读签名） | 权限码（各自独立，按 SC-D7 拆分） |
| --- | --- | --- | --- |
| `query_inventory_alerts` | `alert_type?`、`status?`、`alert_level?`、`material_id?`、`warehouse_id?`、`keyword?`、`limit≤20` | `InventoryAlertService.get_alerts(tenant_id, skip, limit, …)` | `kuaizhizao:warehouse-management-inventory-alert:read` |
| `query_replenishment_suggestions` | `status?`、`priority?`、`suggestion_type?`、`material_id?`、`warehouse_id?`、`keyword?`、`limit≤20` | `ReplenishmentSuggestionService.get_suggestions(tenant_id, skip, limit, …)` | `kuaizhizao:warehouse-management-replenishment-suggestions:read` |
| `query_slow_moving_inventory` | `warehouse_id?`、`limit≤20` | `ReportService.get_inventory_report(tenant_id, "slow_moving", …)`（内部 `build_slow_moving_inventory`） | `kuaizhizao:warehouse-management-reports-slow-moving-inventory:read` |

- 三个 service 均不接收 `current_user`：适配层按 `scene_tools._apply_scope` / `_scoped_row_ids` 补行级数据范围；资源键在 T1 从 kuaizhizao manifest `reference_resources` / data_scope_key 读取确定，读不到即本 Tool 不开工并回报。

Out of scope:

- 处理预警、采纳/下推补货建议（写操作，后续经 HITL 另立）。
- 库存金额、成本单价（呆滞报表若含金额字段，摘要中不输出）。

### Acceptance Criteria

1. 三个 Tool 结果都经数据范围收敛，越界仓/物料不出现、不计数；范围解析异常失败关闭。
2. 有界摘要：预警（物料、仓库、类型、级别、当前量/阈值、状态）；补货建议（物料、建议量、建议下单日期、优先级、状态）；呆滞（物料、仓库、结存、距最后出库天数）。
3. 闭集参数值在 T1 从对应 schema/模型读取后固化到 Tool 参数枚举；非法值返回固定错误文案。
4. 空结果、异常、limit 截断与既有 Tool 口径一致。
5. 三个 Tool 登记于 manifest（`label`、`kind=read`、权限码）。

### Rules and Constraints

Tenant isolation:

- 所有调用传 `ctx.tenant_id`。

Security and masking:

- 不输出金额/成本；权限码按 SC-D7 一 Tool 一码。

Audit and lineage:

- 沿用 Tool 级审计。

AI/rule-engine rules:

- 预警、建议量、呆滞天数取 service 结果，LLM 不计算。

Database rules:

- 无表结构变更。

## 2. Plan

### Implementation Approach

- `get_alerts` 返回 `(responses, total)` 且内部调用 `enrich_inventory_alert_list_capabilities`；适配层只取摘要字段。
- 数据范围：对返回行的 id 集合用 `_scoped_row_ids(Model, ctx, resource, ids)` 求交（与 `query_delivery_risk` 同模式）；呆滞报表行按 (material_id, warehouse_id) 与库存可见对求交（与 `query_inventory` 的 `_inventory_visible_pairs` 同模式）。

### Affected Modules

- Modify/Create: tools 适配模块、`constants.py`、`manifest.json`（两份）。
- Test: `tests/apps/kuaiai/test_spec196_inventory_tools.py`。

### Public Contracts

- Tool 闭集新增三名；无 REST 变更。

### Persistence Changes

- 无。

### Transaction Boundaries

- 只读。

### Risks

- 先取 service 结果再按范围过滤会让 total 偏大：摘要中的总数以过滤后数量为准，并注明“当前用户数据范围内”。
- 呆滞报表全量计算可能较慢：测试记录耗时，必要时只取前 N 条已排序结果。

### Verification Strategy

- 单测：数据范围收敛、非法枚举、空结果、异常、不含金额字段。
