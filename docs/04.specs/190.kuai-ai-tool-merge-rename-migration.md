# KU-AI 存量 Tool 合并改名与档案数据迁移

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：待实施。

## 1. Spec

### Capability

- Name: 11 个存量 Tool 按新目录合并/改名，并迁移 Agent 档案 `enabled_tools`。
- Module: `riveredge-backend/src/apps/kuaiai`（constants、manifest、chat_tools、scene_tools、agent_scene_service、migrations）。
- Priority: P0。
- Related requirement/design documents: 需求 25 SC-D1、SC-D2、SC-D7、SC-D13、§4.3；设计 26 §5.2、§10；前置 spec 189。

### Business Goal

消除按场景切分造成的重复 Tool，把存量 Tool 统一到“业务对象 + 视图”的新目录；已有档案、预置场景在迁移后行为不劣化。

### Scope

In scope（旧名 → 新名，权限码取自现 manifest，不变）：

| 旧名 | 新名 | 视图/参数 | 权限码 |
| --- | --- | --- | --- |
| `query_workorder` | `query_work_orders` | `view=summary`（原列表/详情参数照留） | `kuaizhizao:work-order:read` |
| `list_workorder_tasks` | `query_work_orders` | `view=operations`（需 `work_order_id`） | 同上 |
| `query_purchase_followup` | `query_purchase_orders` | 原参数全集 | `kuaizhizao:purchase-order:read` |
| `query_supplier_orders` | `query_purchase_orders` | `supplier_id` 过滤（同一参数集） | 同上 |
| `query_inventory_balance` | `query_inventory` | 原参数 | `kuaizhizao:inventory:read` |
| `query_delivery_risk` | `analyze_delivery_risk` | 原参数 | `kuaizhizao:work-order:read` |
| `query_published_schedule` | `query_schedule` | 原参数 | `kuaizhizao:plan-management-rolling-scheduling:read` |
| `query_quality_anomalies` | `analyze_quality` | 原参数 | `kuaizhizao:quality-analysis:read` |
| `search_knowledge`、`submit_production_feedback`、`update_workorder_status` | 不变 | — | 不变 |

- `query_quality_anomalies` 归入 `analyze_quality`（不归 `query_inspections`）：其权限码为 `quality-analysis:read`，与各检验单读权限不同，按 SC-D7 由代码唯一确定。
- 迁移后闭集 9 个：`search_knowledge`、`query_work_orders`、`query_purchase_orders`、`query_inventory`、`analyze_delivery_risk`、`query_schedule`、`analyze_quality`、`submit_production_feedback`、`update_workorder_status`。
- aerich 数据迁移改写 `apps_kuaiai_agent_profiles.enabled_tools`。
- 同步 `ENABLED_TOOL_NAMES`、`SCENE_READONLY_TOOL_NAMES`、`CHAT_TOOL_DEFINITIONS`、manifest `ai_tools`（前后端两份）、六个预置模板 `readonly_tools` 与 `system_prompt` 中的 Tool 名、hub `_has_registered_scene_readonly_tool` 依赖的常量、既有测试。

Out of scope:

- 新视图、新 Tool（spec 195 起）。
- 确认闸（spec 192–194）。

### Acceptance Criteria

1. 新 Tool 对相同入参返回的事实与旧 Tool 一致（字段不减少），以旧测试用例改名后全部通过为准。
2. `query_work_orders` 的 `view` 为闭集 `summary|operations`；`view=operations` 缺 `work_order_id` 返回固定错误文案。
3. 迁移按旧名→新名映射改写每条档案的 `enabled_tools`，去重保序（首次出现位置）；无旧名的行不改。
4. 迁移后保存含旧名的档案返回 400（闭集校验），代码中不存在旧名别名映射。
5. 六个预置模板与已存在租户的预置档案（由迁移改写）都只引用新名。
6. MCP 白名单 `allowed_tools` 字段是外部 MCP 工具名，不在本迁移范围；测试用例中出现的 `query_workorder` 样例保持原样。

### Rules and Constraints

Tenant isolation:

- 迁移跨租户逐行改写，只改 `enabled_tools` 列，不改 `tenant_id` 与其他列。

Security and masking:

- 权限码与数据范围适配（`_apply_scope` / `_scoped_row_ids`、by-ID `_work_order_in_scope`）原样保留。

Audit and lineage:

- 迁移不改 `updated_at` / `updated_by`，避免伪造用户操作痕迹（迁移文件头注明原因）。

AI/rule-engine rules:

- 预置模板 `system_prompt` 中引用的 Tool 名同步替换，避免模型调用不存在的 Tool。

Database rules:

- 迁移文件放 `riveredge-backend/migrations/models/`，文件名首段为 14 位时间戳，且大于目录现有最大时间戳（实施时核对；本文编写时最大为 `20261021235000`）。
- 迁移为纯数据迁移（JSONB 列内容改写），无 DDL；提供 downgrade：按反向映射还原（合并项还原为合并前的两名中第一个，见 Risks）。

## 2. Plan

### Implementation Approach

- 新 handler 放 `scene_tools.py` / `chat_tools.py` 原位置改名，`view` 分支内复用原函数体，不复制逻辑。
- 迁移 SQL：对 `enabled_tools` 做 JSONB 数组映射 + 去重保序；在 Python 迁移中分批读取 `id, enabled_tools` 逐行计算后回写，避免复杂 SQL。

### Affected Modules

- Modify: `apps/kuaiai/constants.py`、`manifest.json`（两份）、`services/chat_tools.py`、`services/scene_tools.py`、`services/agent_scene_service.py`、`models/agent.py`（注释）。
- Create: `migrations/models/<14位时间戳>_kuaiai_tool_catalog_rename.py`。
- Modify tests: `tests/apps/kuaiai/test_s2_tools.py`、`test_s5_agent_scenes.py` 及其他引用旧名的用例。

### Public Contracts

- Tool 名闭集变更（档案保存 API 的 `enabled_tools` 允许值变化）；REST URL、method、响应外层不变。
- 前端通过 spec 189 的目录接口自动获取新名，无前端代码改动。

### Persistence Changes

- `apps_kuaiai_agent_profiles.enabled_tools` 数据改写；无 DDL。

### Transaction Boundaries

- 迁移在 aerich 单次 upgrade 事务内完成。

### Risks

- downgrade 无法区分合并前的两个旧名：downgrade 还原为 `query_workorder`、`query_purchase_followup`（各组第一个），在迁移文件与本 spec 明示为有损回退。
- 运行中的会话历史里 `tool` 行保存的是旧名：历史回放只用于展示与上下文，不触发调用；须用测试确认旧名 tool 行回放不报错。

### Verification Strategy

- 迁移单测：多租户、含/不含旧名、合并后去重、仅新名、空数组。
- 改名后的 Tool 单测沿用旧用例（数据范围越界、空结果、失败关闭）。
- 本地 `uv run aerich upgrade` 实跑并抽查档案行。
