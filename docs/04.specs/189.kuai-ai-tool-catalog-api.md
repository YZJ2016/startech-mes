# KU-AI Tool 目录接口（前后端单一真源）

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施。

## 1. Spec

### Capability

- Name: 后端下发可选 Tool 目录，前端档案页与消息轨迹改读接口。
- Module: `riveredge-backend/src/apps/kuaiai`（manifest、api、services）、`riveredge-frontend/src/apps/kuaiai`（constants、pages/agents、pages/chat）。
- Priority: P0（存量合并迁移 spec 190 的前置）。
- Related requirement/design documents: 需求 25 SC-D9、§4.3；设计 26 §2、§10。

### Business Goal

管理员在 Agent 档案页能看到并勾选后端实际注册的全部 Tool（当前 11 个，前端只认 5 个），后续增删、改名 Tool 时前端不再改代码。

### Scope

In scope:

- manifest `ai_tools[]` 每项新增 `label`（中文显示名）与 `kind`（`read|write`）两个字段。
- 新增 `GET /api/v1/apps/kuaiai/tools`：返回已注册且在 `ENABLED_TOOL_NAMES` 内的 Tool 目录。
- 前端 `AgentEditModal` 的 Tool 勾选项与 `MessageList` 的工具显示名改读该接口；删除 `constants.ts` 的 `KUAI_AI_TOOL_NAMES`、`AgentEditModal.tsx` 的 `TOOL_LABELS`、`MessageList.tsx` 的 `TOOL_NAME_LABELS`（三处均只含早期 5 个 Tool）。
- 测试保证 manifest `ai_tools` 名称集合与 `ENABLED_TOOL_NAMES` 一致。

Out of scope:

- Tool 改名/合并（spec 190）。
- `kind=write` 的确认闸语义（spec 193 消费本字段）。
- MCP 工具（不在注册表，仍由 MCP 白名单管理）。

### Acceptance Criteria

1. 接口返回项字段：`name`、`label`、`description`、`kind`、`permission`；按 manifest 声明顺序稳定排序。
2. 只返回同时满足“已注册（含 handler）”且在 `ENABLED_TOOL_NAMES` 内的 Tool；未注册的不返回。
3. 档案页可勾选 11 个 Tool，保存后与后端闭集校验一致；未知名仍由后端 400。
4. 消息轨迹中工具显示名来自接口 `label`；目录接口失败时档案页 Tool 区显示错误与重试、禁止保存 Tool 勾选，不用本地映射表替代。
5. 前端源码中不再出现 Tool 名硬编码闭集。
6. 测试：manifest 名称集合 == `ENABLED_TOOL_NAMES`；缺 `label`/`kind` 或 `kind` 非法时测试失败。

### Rules and Constraints

Tenant isolation:

- 目录为进程级注册信息，不含租户数据；接口仍走 `get_current_tenant` 依赖保持既有鉴权链。

Security and masking:

- 权限：`require_permission_codes("kuaiai:agent:read")`（档案管理读权限，已在 kuaiai manifest `permissions` 中）。
- 不返回 handler 路径、参数 schema 以外的内部信息；`permission` 只返回权限码字符串。

Audit and lineage:

- 只读接口，不写审计。

AI/rule-engine rules:

- 不改变 Tool 装配与守卫逻辑；`agent_assembler` 仍按 `profile.enabled_tools ∩ ENABLED_TOOL_NAMES` 装配。

Database rules:

- 无表结构变更、无迁移。

## 2. Plan

### Implementation Approach

- manifest `ai_tools` 每项补 `label`、`kind`；`ToolRegistry.register_from_manifest` 现只取 `name/description/parameters/permission/handler`，目录接口直接读 manifest（与 `chat_tools._register_manifest_tools` 同一文件路径）并与 `ToolRegistry._tools`、`ENABLED_TOOL_NAMES` 求交。
- 新增 `services/tool_catalog_service.py` 负责读取与求交；路由只编排。
- 前端新增 `services/tools.ts` 请求函数与 React Query key（沿用 `KUAI_AI_OPTION_KEYS` 前缀 `['kuaiai','options',*]`，档案保存后的统一失效机制不变）。

### Affected Modules

- Modify: `apps/kuaiai/manifest.json`（前后端两份同步）、`apps/kuaiai/api/router.py`。
- Create: `apps/kuaiai/services/tool_catalog_service.py`、`apps/kuaiai/schemas/tool_catalog.py`。
- Modify: 前端 `constants.ts`、`pages/agents/AgentEditModal.tsx`、`pages/chat/MessageList.tsx`；Create `services/tools.ts`。
- Test: `tests/apps/kuaiai/test_spec189_tool_catalog.py`。

### Public Contracts

- 新增 `GET /api/v1/apps/kuaiai/tools` → `[{name,label,description,kind,permission}]`（走项目现有成功信封）。
- manifest `ai_tools[]` 新增字段 `label: str`、`kind: "read"|"write"`。

### Persistence Changes

- 无。

### Transaction Boundaries

- 只读，无事务。

### Risks

- manifest 前后端两份不同步：按 feature-delivery-checklist 同次修改两份。
- 现有 i18n key `toolSearchKnowledge` 等在删除 `TOOL_LABELS` 后成为孤儿：同次删除 zh-CN 中对应 key。

### Verification Strategy

- 后端单测覆盖：求交逻辑、未注册过滤、排序、权限 403、manifest 一致性。
- 前端 `npm run build`；档案页手工勾选保存。
