  - 上一单元：`docs/04.specs/90.ai-document-ingest.md`；管理页并行 `docs/04.specs/92.ai-knowledge-admin-ui.md`
  - Naive 基线（将被内部替换）：`docs/04.specs/55.ai-rag-p6.md`、`69.ai-rag-pipeline.md`
  - 对照：[LangChain4j RAG — Advanced RAG](https://docs.langchain4j.dev/tutorials/rag)

### Business Goal

对话挂知识库与 Agent `searchKnowledge` 走同一 `DefaultRetrievalAugmentor`：压缩多轮问句、默认可展开、按允许的 kid 扇出、RRF、chat Scoring 再排序、邻块扩窗后注入。不再以「embed 原句 → topK → system 前缀」为唯一生产路径。

### Scope

In scope:

- `DefaultRetrievalAugmentor`：`CompressingQueryTransformer`（必开）；`ExpandingQueryTransformer`（默认开，`sys_config` 可关）；`DefaultQueryRouter`；自写 ContentRetriever 调现网向量 + fragment 回表；`DefaultContentAggregator` RRF；`ReRankingContentAggregator` + A24 chat 实现的 `ScoringModel`（失败保留 RRF）
- 邻块 `chunk_index` ±1 回表（带 `tenant_id`）
- `DefaultContentInjector` 含 `file_name`、`source_ref`
- 自定义 Executor 拷贝 `TenantContext`
- chat `knowledgeId` 与 Tool/档案 `knowledgeIds` 只是 Retriever 集合不同
- `sys_config` 键（实现写死名，前缀 `ai.rag.`）：展开开关、展开条数、再排序开关。切块/检索回落五键由 **90** 种子（`chunk-size` / `chunk-overlap` / `chunk-separator` / `top-k` / `min-score`）；本单元**读取** topK / minScore：**知识库列 → `selectConfigByKey` → 与种子相同的硬编码**。禁止再读 `AiProperties.getRagTopK` / `getRagMinScore` / yml `AI_RAG_*`
- 单测：Mock 向量与 ChatModel；「Where did he live?」+ 记忆含 John Doe → 压缩后检索；跨租户 kid 不调向量；Scoring 抛错仍返回 RRF 命中；无 knowledgeId 行为与 55 一致；**禁止** `contentRetriever` 与 Augmentor 双注入

Out of scope:

- Easy RAG、HyDE、LanguageModelQueryRouter、Web/SQL/Neo4j Retriever
- Cohere 或其他新 SaaS Scoring
- 改 SSE 信封、改 Vue 对话发送 body
- OCR、live 集群 IT（可选、可跳过）
- 换官方 EmbeddingStore
- 把 topK / minScore 默认写回 yml / `@Value`

### Acceptance Criteria

- 生产路径无「仅 DefaultQueryTransformer + 单次 search」作为唯一实现（测试可 mock 组件，但组装必须是 Augmentor）
- 无命中仍纯聊；他租户 404 不调上游压缩
- Weaviate minScore 仍按相似度语义（不得把 distance 当相似度阈值用错）
- 空 `top_k` / `min_score` 走 `sys_config`，不走 yml
- 第 4 节未跑通不得写「测试通过」

### Rules and Constraints

Tenant isolation:

- Query metadata 禁客户端 `tenantId`
- 并行检索装饰 `TenantContext`
- 向量 search 走当前 `TenantContext` 解析的 store（DEDICATED 否则 yml）；空上下文不得检索

Security and masking:

- 注入与日志无 Key、无内部路径
- 压缩/打分 prompt 不含他厂片段

Audit and lineage:

- 旋钮不进 yml；`sys_config` 无密钥。不保留 yml 与参数表双源

AI/rule-engine rules:

- A24 工厂；无全局 ChatModel
- A7：Retriever 不准 JDBC

Database rules:

- 回表带 tenant_id；不删 fragment 权威存储

## 2. Plan

### Implementation Approach

1. 自写 `ContentRetriever` + `ScoringModel`（chat JSON/数字分）。
2. 按请求组装 `DefaultRetrievalAugmentor`（按 kid 列表缓存须含 tenant，避免串租）。
3. `retrieveContext` 改为 Augmentor 输出文本；chat 仍无 kid 则跳过。
4. Tool 走同一 facade；去掉重复 Naive 拼装。
5. 种子本单元自有 `ai.rag.*`（expand / expandN / rerank）默认：expand=true、expandN=3、rerank=true。topK/minScore 默认勿再写一套 yml。

### Affected Modules

- `ktg-ai` retrieval、chat attachRetrieval、knowledge Tool、本单元 expand/rerank 的 Flyway `sys_config`（五键回落已由 90 种子）

### Public Contracts

- **冻结：** `POST /ai/chat/send`、`POST /ai/agent/send`、Tool 名 `searchKnowledge`

### Persistence Changes

- `sys_config` 增量键（展开/再排序）；无新业务表。topK/minScore 列已有；回落键见 90

### Transaction Boundaries

- 检索只读；压缩/打分无业务写库

### Risks

- 时延与 token；须有超时与失败打开
- Augmentor 缓存 key 漏 tenantId

### Verification Strategy

- `mvn -pl ktg-ai -am test`
- 不连 live 模型/向量（MockWebServer 或假模型）
