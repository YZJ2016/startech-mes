## 1. Spec

### Capability

- Name: 生产与销售异常感知及可扩展 detector 框架。
- Module: `riveredge-backend/src/apps/kuaiai/services/pulse`、`riveredge-frontend/src/apps/kuaiai/pages/pulse`。
- Priority: P0。
- Related requirement/design documents: 需求 24 KO-04；设计 24 §6、§11.3；spec 181 的运营壳与权限矩阵；spec 185 的能力开关。

### Business Goal

让有业务权限的人员在一个页面看到当前租户真实的生产延期与销售交付风险，理解事实和建议并跳入原业务单据；单个领域不可用时仍能使用其他领域结果。

### Scope

In scope:

- detector registry、统一异常 DTO、超时/局部错误/去重/汇总。
- 首期 `ProductionDelayDetector`、`SalesDeliveryRiskDetector`。
- `GET /api/v1/apps/kuaiai/operations/pulse`。
- 五指标、按领域分节、三列卡片、筛选、业务跳转、长加载状态。
- hub 的 Pulse 指标改读真实聚合结果。

Out of scope:

- 库存、质量、设备 detector 的业务规则实现；只保留注册接口与“未接入”语义。
- LLM 判定异常、任意 SQL、自动改单、消息推送和定时后台扫描。
- 在本单元实现 HITL。

### Acceptance Criteria

1. 生产延期只由实际计划时间与实际未完成状态判断；销售风险只由真实交期、履约状态和运营阈值判断。
2. 响应含 summary、groups、errors、complete、generated_at；失败领域不计为 0。
3. 无对应业务读权限时该 detector 不泄露数量、ID、标题或路由。
4. 相同 domain/rule_code/resource_id 只出现一次，顺序为严重度、优先级、时间稳定排序。
5. 1280 桌面五指标一行、异常卡三列；1100 以下两列、768 以下单列。
6. 超过 400 ms 出骨架；15 s 显示仍在计算与取消/重试；旧请求不能覆盖新筛选。
7. 卡片跳转只使用服务端白名单 route，且目标业务页仍检查自身权限。

### Rules and Constraints

Tenant isolation:

- 每个 detector 接受显式 tenant_id 和当前用户权限上下文；每条领域查询含 tenant_id。

Security and masking:

- Pulse GET 按 181 矩阵同时要求 `kuaiai:entry:read` + `kuaiai:pulse:display`，各 detector 再校验领域读权限；`fact`、`suggestion` 不含客户敏感明细、内部 SQL、堆栈；跨权限领域不进入 errors 之外的任何计数。

Audit and lineage:

- item 包含 rule_code、resource 类型/ID、detected_at；页面读取不写业务审计。点击业务页使用目标模块既有审计。

AI/rule-engine rules:

- detector 为确定性规则。LLM 不参与计数、严重度、优先级、事实或 ID；后续解释能力只能消费已生成 fact。

Database rules:

- 不新增 Pulse 快照表。销售交期风险阈值固定存现有 `infra_tenant_configs`（`TenantConfig`），`config_key="kuaiai.pulse.sales_delivery_risk"`，`config_value={"warning_days":3}`；以 `TenantService.get_tenant_config(tenant_id,key)` 租户隔离读取。未配置时取 3 天；值仅接受非布尔整数 0..365，缺键、非整数、越界值统一回落 3 天并记脱敏配置告警，不把配置错误当作业务事实。未来 0..3 天（含今日）与已逾期的未履约订单进入风险候选，具体严重度按规则矩阵；不写 yml、密钥或新表。运营修改沿用现有 TenantConfig 写入授权路径，不新增匿名阈值接口。

## 2. Plan

### Implementation Approach

- 先从生产/销售模型与 service 读取真实状态闭集，形成 rule adapter；路由不直接拼 ORM。
- SalesDeliveryRiskDetector 经 TenantService 读取上述阈值；读取失败不伪装默认业务事实，标记该 detector 局部失败；缺键/值非法才按约定回落 3 天。registry 为每 detector 设置独立超时，`gather(return_exceptions=True)` 后转换成脱敏局部错误。
- 统一服务完成过滤、去重、稳定排序、分页和 summary；页面只渲染。
- URL search params 保存 domain/severity 筛选；AbortController 取消旧请求。

### Affected Modules

- Create: 后端 `schemas/pulse.py`、`services/pulse/{registry,base,production,sales}.py`。
- Modify: operations router/service、kuaiai backend manifest 权限。
- Create: 前端 `pages/pulse/index.tsx`、局部样式与 Pulse 类型/请求。
- Modify: 前端 manifest/index/locale；hub Pulse 数据接线。
- Test: `tests/apps/kuaiai/test_spec182_pulse.py`；按需补领域 service 测试。

### Public Contracts

- `GET /api/v1/apps/kuaiai/operations/pulse?domain=&severity=&page=1&page_size=60`。
- `domain` 在实现中固定为逗号分隔单参数，闭集 production/inventory/sales/quality/equipment；空表示全部。
- `severity` 单值闭集 info/warning/error/critical；page_size 1..100。
- item 精确字段采用设计 §6.2；新增字段必须回写设计和本 spec。

### Persistence Changes

- 无迁移、无快照表；复用 `TenantConfig` 已有 JSON 配置行，未配置不强行补种。

### Transaction Boundaries

- 全部只读；每个 detector 独立查询和超时，不持有跨 detector 事务。

### Risks

- 状态枚举或日期字段理解错误会制造假异常，必须以代码和测试数据为准。
- 大租户全量扫描可能慢；规则查询需在数据库聚合/过滤并有硬上限，禁 N+1。
- 服务器时间与业务时区边界可能造成提前/延后一天；统一 Asia/Shanghai 业务日期并测试临界点。

### Verification Strategy

- TDD 覆盖今天/昨天/未来交期、阈值未配置/非法/0/3/365/读取失败、完成/关闭、空日期、重复资源、跨租户、无权限、一个 detector 超时。
- 使用 query count 或 mock 断言避免逐卡查询。
- 浏览器检查五卡、分组、卡片、部分失败 Alert、筛选竞态和四视口。
