# KU-AI 作业指导场景：SOP 同步知识库与工艺路线 Tool

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施；S1–S3 已于 2026-10-23 选定（均为 a）。

## 1. Spec

### Capability

- Name: SOP 发布/作废经 Taskiq 异步幂等入库/下架到目标知识库；新增只读 Tool `query_process_routes`。
- Module: `riveredge-backend/src/apps/master_data/services/sop_control_service.py`、`apps/kuaiai/services/{knowledge_service,sop_sync_service}.py`、`core/tasks`、`apps/kuaiai/models/knowledge.py`、manifest `ai_tools`；前端 `/settings`（S1=a）。
- Priority: P1（S11 作业指导/SOP 问答）。
- Related requirement/design documents: 需求 25 SC-D11、SC-D12、§4.6；设计 26 §6；前置 spec 189、190。

### Business Goal

操作工问“这道工序怎么做、注意什么”，助手只引用当前生效的 SOP；SOP 作废后不再被 AI 引用，满足受控文件管理要求。

### Scope

In scope:

- `SopControlService.publish` / `obsolete` 成功后投递 Taskiq 任务（`core/tasks/taskiq_app.task` 装饰器，模式同 `core/tasks/ai_tasks.run_ai_job`，任务内 `with_tenant` 进入租户 scope）。
- 任务按 SOP 幂等：发布 → 为该 SOP 建或更新一条知识文档（`source_type=md`，正文取 SOP `content` 与标题/版本/工序信息），重置为 `pending` 并调用 `KnowledgeService.request_parse` / `index_document`；作废 → 软删该文档并清理切块。
- 只同步电子正文：`carrier=paper` 或 `content` 为空的 SOP 不入库，任务记录“无电子正文，未同步”。
- 任务失败不回滚 SOP 发布；失败在知识文档 `status=failed` + `error_message` 可见，并可在 `/knowledge` 或 `/corpus` 重试解析。
- 新增只读 Tool `query_process_routes`：`keyword?`、`material_id?`、`limit≤20`，底层 `ProcessService.list_process_routes` / `get_process_route_tree`（已读方法名，签名 T1 核实），权限码 `master-data:process:route:read`。

Out of scope:

- SOP 附件（S2=a，列 Known gap）。
- SOP 元数据查询 Tool（`master-data:process:sop:read`，P2 视需要另立）。

### 决策（2026-10-23 用户选定）

- **S1 = a**：配置存站点设置 `integrations.kuaiai.sop_sync = {enabled: bool, knowledge_id: int|null}`，在 `/settings` 配置，复用 spec 185 版本锁与深合并保存；保存时校验 `knowledge_id` 为本租户启用知识库。`enabled=false` 或未配置时任务跳过并记录。
- **S2 = a**：首期只同步电子正文；SOP 附件列为 Known gap，附件存储关联核实后另立。
- **S3 = a**：`apps_kuaiai_knowledge_documents` 新增可空列 `source_ref_type`、`source_ref_id`，`(tenant_id, source_ref_type, source_ref_id)` 在 `deleted_at IS NULL` 上部分唯一；SOP 同步写 `("sop", sop.id)`。

原选项存档：

| 编号 | 场景 | 选项 | 推荐与理由 |
| --- | --- | --- | --- |
| S1 | 同步开关与目标知识库配置位置 | a. 站点设置 `integrations.kuaiai.sop_sync = {enabled, knowledge_id}`，在 `/settings` 配置；b. `TenantConfig` 键 `kuaiai.sop_sync` | **a**：与 SC-D14 能力绑定同一配置槽与保存机制，管理员在同一页面完成 AI 相关配置；未配置或关闭则任务直接跳过并记录 |
| S2 | 混合载体 SOP 的附件是否同步 | a. 首期只同步电子正文；b. 附件经 `file_uuid` 路径（知识库支持 pdf/doc/docx 等）一并入库 | **a**：SOP 附件与文件存储的关联字段未核实，首期只做正文，附件列为 Known gap |
| S3 | SOP → 知识文档的对应关系存放（文档表现无外部来源列） | a. `apps_kuaiai_knowledge_documents` 新增可空列 `source_ref_type`、`source_ref_id`，`(tenant_id, source_ref_type, source_ref_id)` 部分唯一（未删除）；b. 新建映射表 | **a**：一列对一，以后设备手册等外部来源同步可复用同一机制；不引入第二张关系表 |

### Acceptance Criteria

1. SOP 发布后（S1 已启用并配置知识库），目标库出现该 SOP 文档并最终 `ready`；同一 SOP 再次发布新版本只更新同一文档，不新增第二条。
2. SOP 作废后该文档软删、切块不再参与检索；`search_knowledge` 检索不到作废内容。
3. 任务失败（embed 未配置、解析失败）时 SOP 发布结果不变，文档 `failed` 且有错误文案。
4. KU-AI 未安装或 S1 未启用：任务跳过并记录，不报错影响 SOP。
5. `query_process_routes` 返回路线编码、名称、版本、工序序列（工序编码/名称），有界摘要。
6. 迁移（S3-a）文件名首段 14 位时间戳且大于目录现有最大值。

### Rules and Constraints

Tenant isolation:

- 任务参数含 tenant_id，任务内 `with_tenant`；文档与 SOP 同租户。

Security and masking:

- 知识文档沿用知识库归属；只有档案选了该库才可被检索。日志不记 SOP 正文。

Audit and lineage:

- 文档创建/更新/删除审计字段写系统身份（`created_by=0`，`created_by_name="系统"`，同 spec 181 约定）。

AI/rule-engine rules:

- AI 只经 `search_knowledge` 引用；不根据 SOP 自动改工艺。

Database rules:

- S3-a 需 DDL 迁移；不新增 Tortoise app。

## 2. Plan

### Implementation Approach

- `sop_control_service` 在 `publish` / `obsolete` 保存成功后调用 kuaiai 侧投递函数（模块存在性探测，KU-AI 未组装则不投递），不在 SOP 事务内等待任务。
- `sop_sync_service` 负责：读 S1 配置 → 按 `(source_ref_type="sop", source_ref_id=sop.id)` 查找/建文档 → 触发解析；作废软删。

### Affected Modules

- Modify: `apps/master_data/services/sop_control_service.py`、`apps/kuaiai/models/knowledge.py`、`apps/kuaiai/services/knowledge_service.py`（按来源查找/更新）、`core/utils/integration_settings.py` + `settings_service.py`（S1-a）、前端设置页（S1-a）。
- Create: `apps/kuaiai/services/sop_sync_service.py`、Taskiq 任务函数、迁移文件。
- Test: `tests/apps/kuaiai/test_spec200_sop_sync.py`。

### Public Contracts

- 设置接口新增 `sop_sync`（S1-a）；Tool 闭集新增 `query_process_routes`。

### Persistence Changes

- S3-a：文档表两列 + 部分唯一索引。

### Transaction Boundaries

- SOP 发布事务与同步任务分离；任务内建/改文档单事务，解析/索引沿用 `KnowledgeService` 现有流程。

### Risks

- 版本快速连续发布可能出现任务乱序：任务执行时以 SOP 当前状态为准（读最新 `control_status` 与 `current_revision`），而非任务参数里的版本。

### Verification Strategy

- 单测：发布入库、再发布更新同一文档、作废下架、未配置跳过、纸质跳过、任务乱序以最新状态为准、失败不影响 SOP。
