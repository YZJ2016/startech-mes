# Mobile Durable Submission Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution, or superpowers:subagent-driven-development only if the user explicitly selects delegation. Track steps below with checkboxes.

**Goal:** 按用户选定 B2，提供跨重启、多进程的移动提交结果恢复及可恢复的后续动作。

**Architecture:** 移动端保留原提交快照及操作标识；后端将防重结果、业务主记录和后续任务意图纳入同一 PostgreSQL 事务。现有 Taskiq 负责已提交任务的执行与扫描恢复，不把 broker 投递成功等同于业务任务完成，也不在远端状态未知时盲目重发。

**Tech Stack:** uni-app x / UTS / uvue；Python 3.11 / FastAPI / Tortoise ORM / aerich / PostgreSQL / Taskiq。

**Spec:** 本文第 1 章；需求 `docs/02.requirements/21.mobile-client-gaps.md` 的 MOB-U4。

## 1. Spec

### Capability

- Name: 移动提交及后续动作恢复。
- Module: `kuaigeyun-mes/kuaigeyun-client/riveredge-app-mobile` 与 `kuaigeyun-mes/riveredge-backend`。
- Priority: P1；承接已修复的模具预览竞态、仓储分页游标问题之后。
- Related requirement/design documents: 需求 21 的 MOB-U4；用户先选择 B，再明确选择 B2。

### Business Goal

网络超时、客户端退出、API 或 worker 重启时，用户可恢复同一操作，不能因重试新增重复业务主记录，也不能丢失主记录对应的待执行后续动作。

### Scope

In scope:

- 逐条接入移动报工、仓储、质量、设备、模具的实际写入口；只有经过事务与副作用检查、测试的入口可标记已支持恢复。
- 提交快照保存、当前账号组织的恢复入口、同键结果重放、同键异参冲突、后端持久化任务及 Taskiq 恢复。
- 报工现有事务后的倒冲、模具用量、质检触发、自动入库、绩效刷新及金蝶推送的恢复边界；保持现有领域规则与审批规则。

Out of scope:

- 第二套队列、ORM、认证或框架；依赖升级；全站后台任务重写；未经授权应用迁移到现网。
- 远端接口没有去重或可核对能力时，承诺外部副作用恰好一次。
- 将本单元测试通过等同于 mobile 全部 UI/UX 缺口收口。

### Acceptance Criteria

- 两个 API 进程竞争同一操作，最多产生一份主记录；请求完成但响应丢失，重启后复用原键可获得已保存结果。
- 身份来自既有认证；组织、账号、方法、路径、查询和请求快照共同校验，同键异参返回既有错误外层结构的冲突结果，不执行新业务。
- 业务回滚时防重成功结果及任务意图一并回滚；不得保存虚假的成功响应。
- broker 投递前进程退出，已提交任务仍能被扫描执行；重复消息不得重复完成本地业务动作。
- worker 执行后、完成标记前退出，本地数据库动作依靠同事务完成标记安全恢复；远端动作进入核对状态，不盲重发。
- 本地快照保存失败时不得发送请求；超时保留快照；明确拒绝才解除待恢复状态；恢复复用原 body、时间字段、路径及键。
- 换账号、组织或服务地址不得读取或发送旧作用域快照；快照不含 token、认证头或凭据，日志及 toast 不暴露快照、内部异常路径。
- 响应结构保持原契约；返回“主记录已提交”不能误称异步倒冲、入库或外部推送已完成。PC 和未接入写入口保持既有行为。

### Rules and Constraints / Global Constraints

- 实现只落独立主仓 `kuaigeyun-mes/`；父仓文档仅在 `main` 修改，不提交子仓文件到父仓。
- 不改既有接口 URL、method、认证头、响应外层结构；复用已有 `Idempotency-Key`，不信任客户端租户头替代认证身份。
- 新模型沿用租户隔离 BaseModel；业务访问使用 `with_tenant`，无上下文失败关闭；调度跨组织扫描必须使用现有可审计非业务扫描模式，再逐条恢复组织上下文。
- 保留创建、更新审计字段及操作到主记录、后续任务的可追踪关系；没有 AI 接入变更。
- 新迁移仍放 `migrations/models/`；当前文件名中最大时间戳为 `20261003190000`，拟用 `20261006120000_mobile_submission_recovery.py`，落地前重检最大值。
- 不设置静默失效的短 TTL、不自动删除未知状态记录；清理策略另立明确生命周期规则，不能把清理变成再次创建许可。

### Review Focus

- 请求收到 2xx 但 body 丢失/损坏：保留原快照并重放，不重新生成键（T3）。
- 主事务嵌套领域事务：必须验证同连接提交/回滚，不依赖假定的 ORM 行为（T1）。
- broker 写池与 Tortoise 连接不同：只持久化 outbox 为提交保证，扫描兜底投递失败（T2）。
- 远端成功、本地回写失败：保留待核对状态，不能将过期租约等同于可重发（T2）。
- 登出或切组织时旧请求回调迟到：只更新请求捕获的原作用域，不污染当前会话（T3）。

## 2. Plan

### Implementation Approach / Affected Modules

- 后端新增 `src/core/models/mobile_submission.py`：租户业务防重记录与后续任务意图；在 `src/infra/infrastructure/database/database.py` 注册，核对动态配置模型扫描。
- 新增 `src/core/services/mobile_submission_service.py`：操作指纹、事务、并发互斥及结果重放；接入 `src/core/middleware/api_idempotency_middleware.py`，仅为已接入的移动恢复操作启用持久化分支。
- 新增 `src/core/services/mobile_submission_outbox_service.py`：任务领取、独立动作执行、回滚、恢复核对；`src/core/tasks/taskiq_app.py` 注册执行与扫描任务。
- `src/apps/kuaizhizao/services/reporting_service.py` 在恢复上下文中将后续动作改为同事务任务意图；非恢复上下文保留现有行为。其它领域入口逐个核对后接入，不给未验证入口套全局“已支持”标签。
- 移动新增 `shared/api/submission-recovery.uts` 处理作用域快照与恢复；`shared/api/http.uts`、`shared/api/index.uts` 传递原操作键；新增 `shared/ui/submission-recovery.uvue` 在支持的写页面显示结果未知、恢复与确认成功状态。

### Public Contracts

- 原 HTTP 合同不变；恢复为向同一接口重发同键同快照；已有 `X-Idempotency-Replay` 表示重放。
- 内部 `execute_durable_submission(request, call_next)` 产生原 Response；外层事务持有期间收集已接入业务的任务意图并保存响应。
- 内部 `enqueue_effect(effect_type, entity_id, acting_user_id, payload)` 仅在当前事务中落 outbox，不在未提交状态发送 broker 消息。
- 内部 `run_due_effects(limit: int)` 使用逐条租户上下文执行；不接受客户端提供任意函数名或任意 SQL。
- 移动 `prepareSubmission(action, method, path, query, body)` 返回固定键与序列化快照；`recoverSubmission(operationKey)` 只能读取当前服务地址、组织、账号作用域的原请求。

### Persistence Changes / Transaction Boundaries

- 防重表：租户、账号、操作键、请求指纹、方法/路径、已完成响应及主记录引用；唯一键包含租户、账号、操作键。
- 后续任务表：租户、防重记录引用、领域实体引用、动作类型、最小必要参数、状态、尝试次数及领取/核对信息；同操作同动作同实体唯一。
- 对本地业务写入，完成标记和效果写入同事务；严禁业务动作吞异常后将任务标记成功。
- 远端调用前落持久化执行意图；结果未知保持核对状态。沿用金蝶既有业务关联及推送通道，不新增第二套推送链路。

### Risks / Verification Strategy

- 报工审批自动通过路径与事务外动作交错，需要覆盖创建及递归审批路径，不将任务延后误改审核规则。
- 自动入库转为异步后，调用方不能依赖“返回即入库完成”；核对移动展示与 PC 调用方，明确显示主记录成功和后续状态的区别。
- PostgreSQL 锁、嵌套事务、多 worker 恢复必须用一次性测试库验证；mock 不能证明并发或原子性。
- 远端结果无法查证时报告人工核对，不以全自动重试掩盖不确定性。
