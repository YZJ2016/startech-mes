### Business Goal

给已登录且已许可 `ai` 的管理端用户提供多步编排：在 `/ai/**` 下定义步骤（调用 61 只读知识 Tool、62 受控写 Tools、以及若 63 已落地则白名单 MCP），按顺序执行并自定 SSE 推送进度。禁止匿名 runner，禁止兼容 ruoyi-ai 工作流帧。

Goal：登录用户可启动本租户工作流；匿名与无前缀 `/workflow/run` 不存在；SSE 不是 `[NODE_CHUNK_*]`。

### Scope

In scope:

- 精确 path **冻结为**（均须 JWT，均 `/ai` 前缀）：
  - 定义 CRUD：`/ai/workflow`（列表/详情/新增/修改/删除）
  - 运行：`POST /ai/workflow/run`（`text/event-stream`）
- SSE **自定**：`data:` JSON，字段允许 `content`、`done`，可选 `step` / `error`。**禁止** ruoyi `[NODE_CHUNK_*]` 帧，禁止 MCP 兼容帧冒充结束
- 步骤只允许调用**已注册白名单**（61 知识检索、62 两个写 Tool、63 已启用 MCP server）。禁止步骤里嵌任意 SQL / JDBC / 未登记 HTTP
- 表 `ai_workflow`、`ai_workflow_run`（名可微调）：均 `tenant_id bigint NOT NULL`；run 另含 `user_id`。唯一键 `(tenant_id, 业务键)`。include + 专库 catalog + 增量 SQL
- 运行时拷贝 `TenantContext` 到节点线程（I-A4）；空上下文失败关闭，不跑后续节点
- 权限：管理定义用独立权限字（如 `ai:workflow:*`）；运行须登录 + 许可；写节点仍走 62 的 MES 权限字，不因「工作流」绕过
- 不改 `POST /ai/chat/send`、`POST /ai/agent/send` 信封（工作流是第三条口，不是改聊天协议）

Out of scope:

- Vue3 工作流 runner 页（65）、Vue2、拷贝 ruoyi-web 工作流组件
- 匿名 `/workflow/run`、无前缀 `/workflow/run`、`/system/message`、游客
- 把 `/ai/**` 写入 `MesPermitAllProviderImpl`
- 短剧、Coding Harness、内置 SQL MCP（A22）
- Milvus / Qdrant、官方 EmbeddingStore、live 环境
- 独立 Agent 管理端页 / Agent 聊天页（设计 §7；已有 `POST /ai/agent/send`）
- 真实地址、凭据、Token

Non-goals:

- 不兼容 ruoyi-ai / ruoyi-web 工作流协议
- 不把 62/63 的实现范围并进本文件编码（可调用其已落地 API/Tool）
- 不做计费钱包

### Acceptance Criteria

- 无 JWT 调 `POST /ai/workflow/run` → 401；路径不在 `MesPermitAllProviderImpl`
- 不存在可匿名调用的 `/workflow/run`（无 `/ai` 前缀）
- SSE 无 `[NODE_CHUNK_*]`；事件与日志无 Key / MCP token / cipher
- 跨租户 workflow id → 404/403，不跑节点
- 步骤引用未白名单 Tool → 拒绝启动或该步失败关闭，不落任意 SQL
- chat/agent 信封保持 61/58 冻结
- 第 4 节未编码前不得写「测试通过」

### Rules and Constraints

Tenant isolation:

- 只信 JWT / `TenantContext`；禁止请求体传 `tenantId`
- workflow id / run id / 工单 id / MCP server id 必须再查本租户

Security and masking:

- `/ai/**` 必须登录；工作流口不进 `MesPermitAllProvider`
- 写节点不得绕过 62 权限字
- 日志、SSE 不打印 apiKey、MCP token、cipher、JDBC

Audit and lineage:

- run 行能追到用户、租户、工作流 id、步骤名；不记密钥
- 增量 SQL 新文件

AI/rule-engine rules:

- A17 / A28：SSE 自定，不兼容 ruoyi 工作流帧
- A22：禁止匿名 `/run`
- 节点短事务，不把整次 run 包成一个超大事务（对齐 §5.3）

Database rules:

- 新表必须 DDL + include + catalog + 单测
- yml 不写工作流密钥或真实 URL

## 2. Plan

### Implementation Approach

1. 增量两表 + include + catalog。
2. 定义 CRUD：JSON 步骤列表只允许枚举内 toolName。
3. `POST /ai/workflow/run`：鉴权 → 加载本租户定义 → 逐步调白名单 Tool → 自定 SSE。
4. 节点线程装饰 `TenantContext`。
5. 单测 Mock Tool；断言无 `[NODE_CHUNK_*]`；无 JWT 被安全链拒绝（或 Controller 测 401 夹具）。

### Affected Modules

- `ktg-ai`（workflow 域、Controller、运行器、测试）
- include、专库 catalog、增量 SQL
- 不改：`frontend/`、本单元默认不改 Vue3、chat/agent Controller 信封、`MesPermitAllProviderImpl`

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- ` /ai/workflow` CRUD：`code/msg/data`、`rows`/`total`
- `POST /ai/workflow/run` body：`{workflowId, input?}`（禁止 `tenantId`）；SSE `data:` JSON：`content`、`done`，可选 `step` / `error`
- 步骤 JSON：`[{name?, toolName, args?, serverId?, mcpTool?}]`。`toolName` 仅 `searchKnowledge` | `submitProductionFeedback` | `updateWorkorderStatus` | `mcp`（`mcp` 须 `serverId` + `mcpTool`）
- **冻结不变：** `POST /ai/chat/send`、`POST /ai/agent/send`
- 禁止无前缀 `/workflow/run`；禁止 `/system/message`

### Persistence Changes

Tables, indexes, migrations, mapper XML, and lifecycle rules:

- `ai_workflow`、`ai_workflow_run`（`tenant_id`；run 含 `user_id`、状态）
- 增量 `YYYYMMDD_NN_ai_workflow.sql`

### Transaction Boundaries

- 保存定义：一短事务
- 每步 Tool 用该 Tool 既有短事务；run 行状态更新另短事务
- 禁止单事务包住整个多步循环

### Risks

- 匿名 `/workflow/run` 或误进 permitAll
- 拷 ruoyi `[NODE_CHUNK_*]` 导致前端协议分裂
- 步骤允许任意 URL/SQL
- 抢在 62 之前编码，写节点无受控写白名单
- 做成独立 Agent 聊天协议，削弱 `agent/send`

### Verification Strategy

- `mvn -pl ktg-ai -am test`（实现后）
- 静态：全仓无匿名 `/workflow/run` 映射；permitAll 无 `/ai`；SSE 测试无 `[NODE_CHUNK_`
- 不跑 live 模型、不跑 Vue（65）、不连 live MCP
