# KU-AI 场景 Tool：生产日报与异常信号（开班/交班简报）

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施。

## 1. Spec

### Capability

- Name: 新增只读 Tool `query_production_daily`、`query_pulse_signals`。
- Module: `riveredge-backend/src/apps/kuaiai/services`（tools 适配层）、manifest `ai_tools`。
- Priority: P1（S07 开班/交班简报；`query_pulse_signals` 供各诊断场景复用）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D5、SC-D7、SC-D12、§4.2（`query_pulse_signals` 复用 `run_pulse`）；设计 26 §4、§5、§7；前置 spec 189、190。

### Business Goal

班组长开班时问一句“昨天我们班产量怎样、现在有哪些异常要处理”，助手基于生产日报与 Pulse 异常信号给出简报；异常判定与页面 `/pulse` 完全同口径。

### Scope

In scope:

| Tool | 视图/参数 | 底层 service（已读签名） | 权限码 |
| --- | --- | --- | --- |
| `query_production_daily` | `view=reports\|summary`；`team_name?`、`template_code?`、`date_start?`、`date_end?`、`limit≤20` | `ProductionDailyReportService.list_reports` / `summarize`（`production_daily_service.py`） | `kuaizhizao:production-daily:read` |
| `query_pulse_signals` | `domain?`（闭集 production/inventory/sales/quality/equipment，逗号分隔）、`severity?`、`limit≤20` | `apps.kuaiai.services.pulse.registry.run_pulse(tenant_id, user, domains, severity, page=1, page_size=limit)` | `kuaiai:pulse:display` |

- `query_pulse_signals` 不另写判定：各 detector 内部已按领域读权限与数据范围收敛；Tool 透传 `errors[]` 摘要（如“质量领域尚未接入检测器”“销售领域无权限”），不把失败领域说成“无异常”。
- `query_production_daily` 不调用 `ProductionDailyTemplateService.list_templates`（其 `ensure_seed=True` 默认会写入预置模板）。

Out of scope:

- 新建/提交日报（写操作）。
- Pulse 新领域 detector（spec 202、203；接入后本 Tool 自动覆盖）。

### Acceptance Criteria

1. `query_pulse_signals` 返回与 `GET /operations/pulse` 同参数下一致的条目（标题、事实、建议、严重度、领域），并列出 `complete=false` 时的失败/未接入领域。
2. `query_production_daily` 两视图返回日报编号、日期、班组、模板、汇总字段（`summarize` 展开的 field_values 只取前若干数值字段，T1 定），按日期倒序。
3. 数据范围：`query_production_daily` 与生产日报页面 API 同口径（T1 读路由确认是否补用户范围，路由补则 Tool 补）。
4. 空结果、异常、limit 与既有 Tool 口径一致。
5. 两个 Tool 登记于 manifest（`label`、`kind=read`、权限码）。

### Rules and Constraints

Tenant isolation:

- 所有调用传 `ctx.tenant_id`；`run_pulse` 以 `ctx.user` 生成 `PulseContext`。

Security and masking:

- `query_pulse_signals` 挂 `kuaiai:pulse:display`，领域数据另由 detector 权限把关；无领域权限时只回脱敏错误码文案。

Audit and lineage:

- 沿用 Tool 级审计。

AI/rule-engine rules:

- 异常是否成立、严重度、优先级全部来自 detector（SC-D5）。

Database rules:

- 无表结构变更。

## 2. Plan

### Implementation Approach

- `query_pulse_signals` 直接调用 `run_pulse`，把 `PulseOut` 转为有界文本：先汇总（总数/高优先级/严重），再逐条（最多 limit），最后一行列出 errors。
- `query_production_daily` 依 `view` 调用对应方法，日期解析复用既有助手。

### Affected Modules

- Modify/Create: tools 适配模块、`constants.py`、`manifest.json`（两份）。
- Test: `tests/apps/kuaiai/test_spec199_shift_brief_tools.py`。

### Public Contracts

- Tool 闭集新增两名；无 REST 变更。

### Persistence Changes

- 无。

### Transaction Boundaries

- 只读。

### Risks

- `run_pulse` 内部每个 detector 有独立超时，Tool 调用总耗时受最慢 detector 影响：沿用 detector 超时，不在 Tool 内另加超时。

### Verification Strategy

- 单测：与 Pulse REST 同参数结果一致、错误领域透传、日报两视图、无副作用（不写模板表）。
