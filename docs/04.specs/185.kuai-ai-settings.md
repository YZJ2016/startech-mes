从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施；浏览器保存链待补验。

## 1. Spec

### Capability

- Name: 对话/视觉连接选用、智能体开关与 KU-AI 能力配置。
- Module: `riveredge-backend/src/apps/kuaiai`、现有 application-connections service、`riveredge-frontend/src/apps/kuaiai/pages/settings`。
- Priority: P1；紧接 181 实施，作为六个出厂模板总开关与能力配置的真源；租户场景实例的单项开关由 181 映射表负责。
- Related requirement/design documents: 需求 24 KO-08；设计 24 §10、§11.6、§12.4；需求 16 的 2026-10-02 模型角色再决策。

### Business Goal

在不恢复旧 Models 目录、不复制密钥的前提下，为 AI 管理员提供示例系统式单页设置：选择 chat/vision 应用连接、启停六智能体并维护工具、RAG、流式和企业系统说明。

### Scope

In scope:

- `GET/PUT /api/v1/apps/kuaiai/operations/settings`。
- 对话模型、OCR 视觉、六个出厂模板总开关、KU-AI 能力配置四区块；不在设置页编辑场景实例和 Agent 档案。
- 复用应用连接列表与 IntegrationConfig 密钥脱敏/角色校验；角色选用与 KU-AI 能力项沿用 `SiteSetting.settings.integrations.kuaiai`，不迁移到连接 `config`。
- 乐观版本、单事务原子保存、Reset/Save/Refresh、dirty 确认。
- 打开现有系统设置→应用连接器。

Out of scope:

- 恢复 `/models` 菜单和模型目录运行时解析。
- 在 settings 页面新建/编辑 API Key；密钥维护继续在应用连接器。
- 新增厂商 SDK、第二套加密或 yml 配置。
- HITL、Pulse 规则阈值和 FAQ 配置。

### Acceptance Criteria

1. chat options 只含当前租户、启用、`model_role=chat` 连接；vision 同理。
2. GET 不返回明文 key/cipher；OCR 只显示 configured、脱敏地址和模型。
3. PUT 请求字段与设计 §11.6 完全一致，extra forbid；rag_top_k 1..20，rag_backend 只接受 native。
4. 六个预置模板总开关全部出现且使用稳定 template_key；`agent_switches` 字段/单键缺失默认 true 仅代表卡片可发现。181 在安装/升级时应已真实预置六份停用、空授权档案并绑定六实例；缺失是预置失败须报告/重试，不是常规“待管理员建档”。最终能否发问还需实例 enabled、管理员已在 `/agents` 配置使用权并启用对应档案、当前用户有使用权且 chat 就绪；复制项受来源模板相同总开关。保存后显式六键 map 覆盖默认并在库页即时生效，不改租户实例 enabled 或档案授权。
5. version 冲突返回 409，不覆盖他人更新；角色不符、停用、跨租户 UUID 返回 422/404 且不部分保存。
6. 重置只恢复本次加载快照；刷新在 dirty 时确认并重新加载；保存 pending 时按钮禁用。
7. 1280 下四区块尺寸和三列布局符合设计 §10；390 下单列，保存按钮始终可达。

### Rules and Constraints

Tenant isolation:

- UUID 必须由 IntegrationConfigService 按当前 tenant_id 查询；站点设置行也按 tenant_id 加锁并写入，客户端不得提交 tenant_id。

Security and masking:

- settings GET/PUT 按 181 矩阵要求 `kuaiai:entry:read` + `kuaiai:settings:display`，PUT 再要求 `kuaiai:settings:update`；settings body 无 api_key/ocr_api_key，任何未知字段 422。日志与 toast 不包含 config 原文。

Audit and lineage:

- 保存记录操作者、旧/新角色 UUID 和变更字段名，不记录密钥或 custom prompt 全文。

AI/rule-engine rules:

- 运行时仍由 AiRuntimeConfig 读取被选用 chat/vision 连接；embed/rerank 不在本页更改。RAG 关闭时检索不执行。

Database rules:

- 现有 `select_llm_connection_role` 把选中角色 UUID 写入 `SiteSetting.settings.integrations.kuaiai.active_{chat|vision}_connection_uuid`；运行时 `_merge_kuaiai_capabilities` 从同一 kuaiai 槽读取能力项。`agent_switches` 六模板总开关同样落此槽，保留 `settings` 与 `integrations` 的其他键；IntegrationConfig.config 只保留连接信息/密钥，不写第二份能力配置。本单元无新表/迁移；181 的租户场景实例单项 enabled 独立存表。

## 2. Plan

### Implementation Approach

- settings service 通过 IntegrationConfigService 校验候选连接并读取脱敏信息，通过 SiteSettingService/integration_settings helper 读取实际选中角色和能力项，禁止路由直接改 JSON。
- GET 的 opaque version 基于租户 SiteSetting 行 UUID/updated_at（含选用角色与配置）生成；PUT 在单个 `in_transaction()` 中对该租户 `SiteSetting` 行 `select_for_update()`，锁内重读和比较版本，不一致返回 409；全部 UUID/角色/启用状态及 payload 校验通过后，一次深合并写回该行 settings 的 `integrations.kuaiai`，只替换本页白名单字段。若站点行尚不存在，先通过既有 SiteSettingService 初始化，再在事务内锁定。禁止通过逐次调用会提前 `site.save()` 的 `select_llm_connection_role` 完成两步保存；仅复用其校验语义，提交成功后才失效模型缓存。事务失败回滚全部字段，不做补偿路径。
- 前端 Form 以 server snapshot 建初值，Reset 使用 snapshot，Refresh 重新请求；不把敏感配置放 localStorage/URL。

### Affected Modules

- Create: backend settings schema/service，挂入 operations router。
- Modify: `core/utils/integration_settings.py` 仅增加 agent_switches 白名单读写与验证；`core/services/system/site_setting_service.py` 或 settings facade 增量实现租户站点行锁读写；IntegrationConfigService 仅作连接校验，不改连接密钥持久化。
- Create: frontend `pages/settings/index.tsx`、`services/operations.ts`/types 增量。
- Modify: manifest/index/locale；spec 181 library/hub 读取新开关。
- Test: `tests/apps/kuaiai/test_spec185_settings.py`，application-connections/integration_settings 回归。

### Public Contracts

- GET/PUT 请求响应逐字采用设计 §11.6。
- 继续保留 `/core/application-connections/llm-roles` 与 `/{uuid}/select-role`；settings API 是服务端编排 facade，不改变原 API。
- `version` 为不透明字符串，客户端只能原样回传。

### Persistence Changes

- 无迁移；只更新 `core_site_settings.settings.integrations.kuaiai` 中的角色 UUID、六开关、能力配置，不修改 `core_integration_configs.config`。

### Transaction Boundaries

- 角色选用与能力配置是同一 `SiteSetting.settings` JSON 行的原子更新：先初始化（如缺失），事务内锁行、比较版本、校验候选连接，再一次 save；出错回滚并返回原错误/409，不改变选中角色或能力项；无需补偿。GET/PUT 均不得复制或写连接凭据。

### Risks

- 覆盖整个 SiteSetting JSON 会丢失无关设置；只在 `settings.integrations.kuaiai` 深合并白名单字段，不改连接 `config`。
- 切换 chat/vision 只改同一站点设置行中的角色 UUID；能力项不随连接切换而丢失。
- 并发更新若只靠前端时间戳会丢更新；version 必须锁内基于最新行重算。既有单独选用接口也更新该行的 updated_at，应导致旧 version 409。

### Verification Strategy

- TDD 覆盖跨租户、错误 role、停用连接、无 chat、并发 version 冲突、锁内回滚、site settings 深合并、六模板总开关缺省 true/显式 false 与实例 enabled 的交集、复制实例继承来源模板总开关、空 vision、未知字段、rag 边界和脱敏。
- 前端测试 Reset/Refresh/dirty、保存 busy、409 展示和连接器跳转。
- 回归 AiRuntimeConfig load、chat/vision 解析和 application connection CRUD/test/select-role。
