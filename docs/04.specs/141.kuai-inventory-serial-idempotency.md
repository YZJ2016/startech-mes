### Business Goal

序列号与批次在同一事务、同一把行锁下变更。幂等键在 `_increase_stock_no_atomic` 与 `_decrease_stock_no_atomic` 签名级强制，不传键即拒绝。公共包装 `increase_stock`/`decrease_stock` 在调用方未传键时按 `source_type` + `source_doc_id` + 动作合成确定性键（A 案），无法合成同样拒绝；其 20 个调用方不逐点补键。验收是下面 27 处调用点都传键，重试不加两次量、不减两次量。保留负库存默认关、批号管理出库必须带批号。不拆 `warehouse_service`。

## 2. Plan

### Implementation Approach

1. 序列号更新改为 `select_for_update`（或与批次同一事务内的等价行锁），与批次变更同提交。
2. 收紧 `idempotent_stock_change`：无键失败关闭；有键保持 advisory lock + 流水查重。
3. 按验收清单的 27 处调用传入稳定幂等键（单据类型 + 单号 + 动作，字面实现时钉死并测）。不传键在入口拒绝。包装层 `increase_stock`/`decrease_stock` 缺键时按 `source_type` + `source_doc_id` + 动作合成确定性键（A 案），其 20 个调用方不逐点补键。
4. 回归已传键的撤回/调拨/叫料路径。
5. 明确锁序与事务边界写进实现注释，**不**借机拆 warehouse 文件。

### Affected Modules

- `src/apps/kuaizhizao/services/inventory_service.py`（主落点，含 `increase_stock`/`decrease_stock` 包装层）
- 验收清单中的 27 处调用（`src/apps/kuaizhizao/services/warehouse_service.py` 等，只改调用，不拆文件）
- 已传键的撤回/调拨/叫料路径（回归）

### Public Contracts

- 库存增减服务签名：`idempotency_key` 变为必填（或空值显式拒绝）；对外 HTTP 尽量不变，由服务层生成键。
- 并发冲突：明确错误，不静默丢更新。

### Persistence Changes

- 优先复用既有库存流水/幂等表；若缺唯一约束导致双写，补最小唯一索引（aerich 十四位时间戳规则）。

### Transaction Boundaries

- 单次确认：门禁（140）→ 库存批次+序列号+幂等流水 **同一事务**；任一步失败全滚。
- 业财（142）另订同一成败；本单元先保证库存自身一致。

### Risks

- 锁序不当导致死锁 → 固定顺序 + 压测/并发单测。
- 历史无键调用方漏改 → 全仓检索 `_increase_stock` / `idempotent_stock_change` 调用点清单验收。

### Verification Strategy

- 见 §3；§4 实跑后填。
