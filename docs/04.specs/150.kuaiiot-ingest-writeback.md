### Business Goal

云侧槽位收归本仓后，能用设备鉴权凭据收下一条 HTTP 报文，按幂等留下最新点位值，并按 `equipment.uuid` 节流写回星制造设备状态监控。此时还没有告警、边缘配置下发、物模型趋势、指令和报表馈送。

- 写回只插入 `apps_kuaizhizao_equipment_status_monitors`（模型 `apps.kuaizhizao.models.equipment_status_monitor.EquipmentStatusMonitor`）。`data_source` 固定 `sensor`。绑定键是设备行上的 `equipment_uuid`，必须等于本租户 `apps_kuaizhizao_equipment.uuid`（`EquipmentService.get_equipment_by_uuid`）。`equipment_id`、`equipment_code`、`equipment_name` 从读到的设备行拷贝。点位 `map_target` 只映射监控行已有字段：`status`、`is_online`、`temperature`、`pressure`、`vibration`、`other_parameters`。
- 节流按星制造设备，不按单台 IoT 设备的 `last_mes_sync_at`。同一 `equipment.uuid` 至少隔 5 秒才再插入一条 `data_source=sensor` 的监控；间隔以上一条 sensor 监控行的插入时间（`created_at`）为准。`equipment_uuid` 在迁移 519 上是索引 `idx_apps_kuaiiot_devices_tenant_equip`，不是唯一索引。两台 IoT 设备绑同一台星制造设备时共用这 5 秒。未绑定 `equipment.uuid` 的入站可以留快照，但不写监控行。间隔内仍更新快照。

### Acceptance Criteria

1. 上述两个 `kuaiiot` 忽略行不再排除本仓新建文件；`PRO_APPS` 不再包含 `kuaiiot`。本切片只去掉 `kuaiiot` 的忽略，不把 `kuaireport` 加回忽略或 `PRO_APPS`。`edge-agent/` 仍在原路径。
2. 前后端 `manifest.json` 在本仓，且不来自私仓组装拷贝。云侧 `services` 在本切片之前不存在。
3. 凭据命中恰好一台未删除设备时，`POST /api/v1/apps/kuaiiot/ingest/{device_token}` 更新对应 `tag_snapshots`，并把该设备 `is_online` 写成真、更新 `last_seen_at`。未映射的 tag key 不产生快照行。
4. 同一 `idempotency_key` 再 POST 一次，快照与监控行不增加，响应与第一次相同。
5. 设备已绑定本租户 `equipment.uuid` 时，该 `equipment.uuid` 距离上一条 `data_source=sensor` 监控的插入时间不少于 5 秒才再插入一条。不足 5 秒不新增。两台 IoT 设备绑同一台星制造设备时共用这 5 秒，不按各自的 `last_mes_sync_at`。未绑定 `equipment.uuid` 的入站留下快照，不写监控行。`apps_kuaizhizao_equipment` 与 `apps_kuaizhizao_equipment_status_histories` 不被这次写回更新。
6. 凭据无效、命中多台、绑定的设备 uuid 不属于该租户、或没有设备行上的租户时，不写快照、不写监控。
7. `apps_kuaiiot_tag_history` 行数不因本切片入站增加。
8. 本租户能登记连接、IoT 设备、点位，并绑定星制造 `equipment.uuid`。登记 IoT 设备不填 `external_device_id` 则拒绝。无租户上下文拒绝。直接插入这些表的行不算控制面通过。
9. 登记完成后，本租户能读到该设备最新快照。直接查表不算通过。

- 鉴权凭据只在服务端校验，可轮换。日志、错误响应、文档不回显凭据。

Audit and lineage:

- 迁移 523 已给 519/520 这几张表补了 `created_by`、`created_by_name`、`updated_by`、`updated_by_name`、`deleted_by`、`deleted_by_name`。沿用这些列，不改 523 的文件名。

- 不改已经进过库的迁移文件名。不往 `tag_history` 写采样。

## 2. Plan

### Implementation Approach

1. 收归槽位：只动 `kuaiiot` 的忽略与 `PRO_APPS`。目录按 `apps/kuaiai` 的 manifest 骨架新建，保留已跟踪的 `edge-agent/`。
2. 控制面登记连接、IoT 设备、点位，并把 `equipment_uuid` 绑到本租户星制造设备。登记 IoT 设备必须带 `external_device_id`。登记完成后本租户能读到该设备最新快照。
3. 入站按凭据认设备，写幂等与快照，成功入站把 `is_online` 写成真并更新 `last_seen_at`，再按同一 `equipment.uuid` 的 5 秒节流只插入监控行。

### Affected Modules

- `kuaigeyun-mes/.gitignore`（只去掉两条 `kuaiiot` 路径）
- `kuaigeyun-mes/fast-deploy/tools/workspace/generate_workspace.py`（`PRO_APPS` 去掉 `kuaiiot`）
- 新建 `riveredge-backend/src/apps/kuaiiot/` 下的云侧包（本切片之前只有 `edge-agent/`）
- 新建 `riveredge-frontend/src/apps/kuaiiot/`（本切片之前不存在）
- 只读依赖：`apps.kuaizhizao.services.equipment_service.EquipmentService.get_equipment_by_uuid`、`EquipmentStatusMonitor` 模型。不调用会回写设备主数据状态的现有服务方法

### Public Contracts

- 本切片要补、仓内尚无实现：`POST /api/v1/apps/kuaiiot/ingest/{device_token}`。路径与路线图一致，不写成已经存在的路由。
- 已存在、本切片只读：`Equipment.uuid` 与监控表 `apps_kuaizhizao_equipment_status_monitors`。

### Persistence Changes

- 无新表。不改 519、520、523 的文件名。
- 写入：`tag_snapshots`、`ingest_dedup`、成功入站时的 `devices.is_online`（写成真）与 `devices.last_seen_at`、监控表新行。节流不读 `last_mes_sync_at`。
- 不写入：`tag_history`、设备主数据 `status`、设备状态历史。

### Transaction Boundaries

- 一次入站在同一租户内完成认设备、幂等判断、快照更新，并把 `is_online` 写成真、更新 `last_seen_at`。监控行只在同一 `equipment.uuid` 距上一条 sensor 监控超过 5 秒时插入。重复幂等键不开启第二次写回。

### Risks

- 若调用 `create_status_monitor`，只在状态变化时回写台账并写历史；若调用 `update_equipment_status`，状态没变也会写历史，且新监控行 `data_source` 固定为 `manual`。传感器写回不走这两处。
- 忽略规则未去掉时，新建云侧文件无法进入本仓。
- `device_token` 索引不唯一。多行命中必须拒绝，不能任取一行。

### Verification Strategy

- 见 §3。§4 在命令实跑后填写。本文件写下时未跑测试。
