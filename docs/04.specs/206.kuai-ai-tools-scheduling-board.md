# KU-AI 场景 Tool：排程看板解读

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：待实施；§1“待决”须用户选定后开工。

## 1. Spec

### Capability

- Name: 为 S04 排程解读与调整建议提供排程事实 Tool。
- Module: `riveredge-backend/src/apps/kuaiai/services`（tools 适配层）、manifest `ai_tools`；只读引用 `apps/kuaizhizao/services/{visual_scheduling_service,scheduling_ai_service}.py`。
- Priority: P2（S04）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D5、SC-D7；设计 26 §4、§5.2；前置 spec 189、190（`query_schedule` 已覆盖滚动排程已发布日计划）。

### Business Goal

计划员问“为什么这几张工单排不进来、冲突在哪、怎么调”，助手基于排产看板的真实冲突事实解释，并给出可执行的调整方向。

### Scope

In scope（按 X1 决策定稿）：

- 现状事实：可视排产已有 AI 助手 `SchedulingAiService.explain / suggest_priority / suggest_adjustments`（路由 `POST /scheduling/ai/*`，权限 `kuaizhizao:plan-management-scheduling:read`），这些方法内部自行调用大模型生成文字；滚动排程已发布计划由 spec 190 的 `query_schedule` 提供。

### 决策（2026-10-23 已选定）

选定：**X1=a** —— 新增 `query_scheduling_board` 纯事实 Tool；不包装 `SchedulingAiService`（避免“模型调 Tool 再调模型”的双层调用与审计绕行）。原选项存档：

| 编号 | 场景 | 选项 | 推荐与理由 |
| --- | --- | --- | --- |
| X1 | 计划员在对话里问“解释一下今天排程冲突”。若 Tool 内部再调 `SchedulingAiService.explain`，就是“模型调用 Tool、Tool 又调模型”：一次提问两次大模型调用，耗时与费用翻倍；内层模型产出的是文字判断而非事实，外层模型再转述，出错时无法区分是哪一层说错；内层调用不经 Agent 档案的模型选择与审计 | a. 新增 `query_scheduling_board`：只返回看板确定性事实（工单、工作中心、计划时段、冲突/诊断项），解释由 Agent 完成；b. Tool 包装 `SchedulingAiService.explain` / `suggest_adjustments`，直接返回其文字；c. 不新增 Tool，S04 只用 `query_schedule`（滚动排程已发布计划） | **a**：符合 SC-D5“Tool 给事实、模型做解释”，一次提问一次模型调用，审计与模型选择统一走档案；c 只覆盖滚动排程已发布日，看不到可视排产看板上的冲突 |

### Acceptance Criteria

1. `query_scheduling_board(plan_date?, work_center_id?, limit≤20)` 返回看板工单、计划时段与冲突/诊断事实，不含模型生成文字。
2. 权限码 `kuaizhizao:plan-management-scheduling:read`；数据范围与看板路由同口径（T1 核实）。
3. 不调用任何大模型；空结果、异常与既有 Tool 口径一致。
4. 登记于 manifest（`label`、`kind=read`）。

### Rules and Constraints

Tenant isolation:

- 传 `ctx.tenant_id`。

Security and masking:

- 一 Tool 一权限码。

Audit and lineage:

- 沿用 Tool 级审计。

AI/rule-engine rules:

- 冲突/诊断由排产引擎确定（SC-D5）；调整建议由 Agent 基于事实给出，不自动改排程。

Database rules:

- 无表结构变更。

### 场景模板（Y3=a）

本单元交付时同步登记场景模板 `scheduling-board`（排程解读助手）：预置档案 `enabled_tools` 为本单元 Tool 集合，停用 + 空授权（Y4=a）；模板 key 即能力矩阵场景卡，默认绑定同 key 预置实例（spec 191，Y1/Y2=a）。system_prompt 只引用本单元 Tool，插画按 spec 201 T2 约定。
