### Business Goal

配置 `VECTOR_STORE_TYPE=dashvector` 时，54 的同一套 `VectorStoreService` 走阿里云 DashVector。55 的对话检索无需改契约。集群属平台基础设施（A14：SHARED 默认或某厂 DEDICATED；工厂不可自改指向）。本单元落地时仍为进程级 yml type。

### Scope

In scope:

- `DashVectorVectorStoreStrategy`（名随风格）注册进 Factory
- 官方 `dashvector-java-sdk` 或 HTTP API 二选一（实现写死一种）
- Collection 维度与 embedding 一致；Field 或 Partition 带 `tenant_id`，推荐都做
- yml 占位：`${DASHVECTOR_ENDPOINT:}`、`${DASHVECTOR_API_KEY:}`（名称可微调，禁止真值）
- 缺凭证且 type=dashvector → 失败关闭（启动或首次调用）

Out of scope:

- 每工厂独立 Cluster
- 替换掉三种开源策略
- 百炼托管知识库当主存储
- Agent

### Acceptance Criteria

- Factory 在 type=dashvector 返回该策略
- 检索/写入带 tenant 过滤；错租户夹具不得命中
- 文档与 yml 无真实 endpoint/key
- 55 单测换 fake 仍通过；本策略至少 mock HTTP/SDK 单测

### Rules and Constraints

Tenant isolation:

- I-A3 同样适用
- Partition 名不得来自客户端

Security and masking:

- API Key 只环境变量 **或** 平台只写加密（**PR-D20** / 93：默认或该厂 DEDICATED）。本单元落地时仍为 yml 占位。工厂不可自改指向
- 日志不打印 token

Audit and lineage:

- 不把 Cluster 信息写入 `ai_*` 业务行

AI/rule-engine rules:

- embedding 仍 OpenAI 兼容，不强制改 DashScope
- community BOM（60）提供 DashScope，**不**提供 DashVector；本策略保持自定义 HTTP，不要改写成不存在的 community 构件

Database rules:

- 无新表
