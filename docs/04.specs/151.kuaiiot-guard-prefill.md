### Business Goal

入站写回时不再覆盖星制造里不可覆盖的设备状态。点位可以套用模板。阈值越过时留下告警。报工与点检能按设备读到采集预填值，单据本身仍由星制造保存。

### Scope

In scope:

- 状态护栏加在 150 的写回之前。语义沿用路线图 Wave 1.5，对照现有字段，不新造状态枚举：
  - `apps_kuaizhizao_equipment.status` 为停用、报废、校验中（字段说明里的枚举还包括正常、运行中、待机、故障、维修中）
  - 未闭环故障：`apps_kuaizhizao_equipment_faults.status` 为待处理或处理中。已修复、已关闭不拦截
  - 进行中维修：`apps_kuaizhizao_equipment_repairs.status` 为进行中。已完成、已取消不拦截
- 护栏命中时不要靠数据库默认值造出一条新的状态。监控行的 `status` 默认是「正常」、`is_online` 默认 false，且都是 NOT NULL（迁移 `34_20260116000007_create_equipment_status_monitor_models.py`，模型 `EquipmentStatusMonitor` 相同）。护栏要求不覆盖 `status` / `is_online`。若本条入站仍要插入监控行（其它点位如温度），这两列必须抄该设备上一条 `data_source=sensor` 监控行的同两列；没有上一条时，不要插入会落入默认「正常」的状态行。不调用会改星制造设备台账的入口（`EquipmentStatusMonitorService.create_status_monitor`、`update_equipment_status`）。有上一条时，`temperature`、`pressure`、`vibration`、`other_parameters` 仍按 150 的 5 秒节流写入。不修改 `apps_kuaizhizao_equipment.status`。
- 入站里的 status 只接受设备主数据字段说明中的枚举。未知值写成待机。报文没有 status 时，不把监控 `status` 默认成运行中。
- 点位模板是本切片要补的内容。路线图已写三套：通用产线、注塑机、CNC。创建设备时可选套用，落到已有 `apps_kuaiiot_tag_definitions`。仓内没有 `apps.kuaiiot.tag_templates`。`tests/apps/kuaiiot/test_wave15_tag_templates.py` 引用了该模块，测试不是实现。
- 阈值告警用已有表 `apps_kuaiiot_alert_rules` 与 `apps_kuaiiot_alerts`（迁移 `521_20260807140000_kuaiiot_wave2_tables.py`）。入站时按规则评估。`operator` 沿用路线图已写的 gt、lt、gte、lte、eq、ne。冷却用 `cooldown_seconds`。命中写入 `alerts`（`status` 默认 `open`）。`rule_type` 列在迁移 524，默认 `threshold`；本切片只用阈值，不写 `offline`。
- 预填读取是本切片要补的接口。点位列 `fill_target` 已在迁移 521。按 `equipment.uuid` 读最新 `tag_snapshots`，把 `fill_target` 以 `sop_parameters.` 开头的值交给报工参数，以 `spot_check.` 开头的值交给点检实测。报工参数列是 `apps_kuaizhizao_reporting_records.sop_parameters`。点检测量列是 `apps_kuaizhizao_equipment_spot_check_lines.measured_value`。本切片只返回预填值，不插入报工单或点检单。

### Acceptance Criteria

1. 设备 `status` 为停用、报废或校验中，或存在待处理/处理中故障，或存在进行中维修时，不覆盖 `status` 与 `is_online`，也不改设备主数据 `status`。本条仍插入监控行时，这两列抄该设备上一条 `data_source=sensor` 监控行；没有上一条则不插入，不能落入默认「正常」。有上一条时，温度等其余映射字段仍可在超过 5 秒后写入。不调用会改星制造设备台账的入口。
2. 入站 status 不在设备枚举内时，监控 `status` 为待机。报文无 status 时，不写成运行中。
3. 选用三套模板之一创建设备后，`tag_definitions` 出现该模板的点位。模板模块在本切片之前不存在。
4. 阈值命中且已过 `cooldown_seconds` 时新增一条 `alerts`。冷却期内不新增。未映射或未启用的规则不产生告警。
5. 预填接口按本租户 `equipment.uuid` 返回快照值。`sop_parameters.*` 与 `spot_check.*` 只出现在返回体里。`reporting_records` 与 `equipment_spot_checks` 的行数不因此增加。
6. 无租户上下文不读这些表。跨租户设备 uuid 不返回预填、不写告警。

### Rules and Constraints

Tenant isolation:

- 规则、告警、模板套用、预填都带当前租户。故障、维修、设备状态只读本租户行。

Security and masking:

- 预填接口走租户 RBAC，不使用设备凭据对外公开单据字段。
- 日志不写鉴权凭据。

Audit and lineage:

- 告警行保留 `rule_id`、`triggered_at`、`actual_value`。不新造告警表。

AI/rule-engine rules:

- 只做点位阈值比较。不做路线图所称的完整规则引擎。

Database rules:

- 告警与 `fill_target` 只用迁移 521 已有表和列。`rule_type` 保持默认 `threshold`，不改 521、524 的文件名。

### 依赖顺序

- 依赖 150 的入站与只插入监控行的写回。
- 152 的批量续传走本切片已收口的写回前护栏。
- 不依赖 152–155。
- 不改 145–149。

## 2. Plan

### Implementation Approach

1. 写回前读设备状态、未闭环故障、进行中维修。护栏命中时 `status` / `is_online` 抄该设备上一条 `data_source=sensor` 监控行；没有上一条则不插入监控行。
2. 模板常量套到 `tag_definitions`。阈值在入站路径上评估并写 `alerts`。
3. 预填只读快照与 `fill_target`，按设备 uuid 返回，不写星制造单据。

### Affected Modules

- `riveredge-backend/src/apps/kuaiiot/` 的云侧服务（150 建槽位；本切片之前这些服务不在）
- 只读：`apps_kuaizhizao_equipment`、`apps_kuaizhizao_equipment_faults`、`apps_kuaizhizao_equipment_repairs`、`reporting_records.sop_parameters`、`equipment_spot_check_lines.measured_value`
- 前端槽位内补告警与模板操作页。不改 `kuaizhizao` 页面

### Public Contracts

- 本切片要补：按 `equipment.uuid` 读取预填值的接口。路线图写过 `GET /fill-context`，仓内没有该路由。
- 已存在、本切片只读的单据字段见上文。不改其 URL。

### Persistence Changes

- 无新表。写入 `alert_rules`、`alerts`，以及模板产生的 `tag_definitions`。
- 护栏改变的是监控行哪些列被赋值：`status` / `is_online` 抄上一条 sensor 行，不靠默认「正常」。不新增监控列，不改设备台账。

### Transaction Boundaries

- 一次入站内完成护栏判断、快照、节流写回、阈值评估。预填读取不写单据。

### Risks

- 把「已修复」故障当成未闭环会多拦截写回。本切片只把待处理、处理中视为未闭环。
- 预填若直接插入报工或点检，会越过星制造原有保存路径。

### Verification Strategy

- 见 §3。§4 在命令实跑后填写。本文件写下时未跑测试。
