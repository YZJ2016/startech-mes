### Business Goal

仓库过账读不到批号/序列号管理开关时拒绝过账，不能当成开关关闭放行。工单没有 BOM 时，下达前的缺料检查拒绝下达，不能当成不缺料。

### Scope

In scope:

- 入库 `_increase_stock_no_atomic` 读 `_get_warehouse_management_flags` 失败时拒绝本笔过账。
- `check_material_shortage` 在没有 BOM 时带出 `bom_missing: true`。
- `release_work_order` 在缺料检查开启且拦截级别命中「下达」时，见到 `bom_missing` 则拒绝下达。

Out of scope:

- 不改变开关明确为关（读成功且两个标志为 False）时跳过强制批号/序列号校验。
- 不改变物料 `batch_managed` / `serial_managed` 与开关的组合。
- 不改变有 BOM 时的需求展开、`is_kitting_inventory_material` 跳过、缺料文案与拦截级别，以及有 BOM 且缺料时的下达拒绝。
- 不在出库 `_decrease_stock_no_atomic` 再包一层降级或第二套校验。出库读失败已经会冒泡。
- 不把无 BOM 的拒绝扩到开工、报工、生产管控、异常、缺料查询 API。
- 不新表。不改 URL、method、认证头、响应外层结构。

### Acceptance Criteria

1. 入库读 `parameters.warehouse.batch_management` / `serial_management` 抛错时，本笔库存过账被拒绝，批号/序列号强制校验不被跳过，标志不被降成 False。该过账若在单据确认事务内，整单回滚。
2. 读成功且两个开关为 False：入库仍跳过 744–754 行这一段强制批号/序列号校验。
3. 出库 1225 行仍直接调用 `_get_warehouse_management_flags`，读失败继续冒泡，过账不继续。
4. 没有 BOM（`calculate_material_requirements_from_bom` 抛 `NotFoundError`）时，`check_material_shortage` 的结果含 `bom_missing: true`。`release_work_order` 在 `check_shortage` 为真且缺料拦截级别命中「下达」时，对该结果抛 `BusinessLogicError`，工单状态不变。
5. 有 BOM 且确实缺料：下达仍按现网 `has_shortage` 路径拒绝，文案与拦截级别不改。
6. 开工（`work_order_service.py` 6598–6611 行）、报工（`reporting_service.py` 1211–1218 行只看 `has_shortage`）、`production_control_service.py`、`exception_service.py`、`api/productions/work_orders.py` 的缺料查询，不因 `bom_missing` 拒绝。无 BOM 时这些调用方仍看到 `has_shortage: false`。

### Rules and Constraints

- 沿用现有 `tenant_id` 与组织隔离，不新开查询口径。

Security and masking:

- 拒绝文案不包含凭据、连接串或内部路径。

Audit and lineage:

AI/rule-engine rules:

- 不涉及。

Database rules:

- 不新表，不写迁移。

## 2. Plan

### Implementation Approach

- 去掉入库读标志失败后的 warning 降级。失败改为抛业务错误。
- 无 BOM 的缺料结果增加 `bom_missing`。只有下达路径消费该标志。共享函数把无 BOM 的 `has_shortage` 留成 False，开工和报工行为不变。

### Affected Modules

- `src/apps/kuaizhizao/services/inventory_service.py`
- `src/apps/kuaizhizao/services/work_order_service.py`
- 对应单测

### Public Contracts

- 不改库存过账与工单下达的 URL、method、认证头、响应外层结构。
- `check_material_shortage` 的返回字典增加 `bom_missing`。无 BOM 时为 true；有 BOM 时为 false 或不依赖调用方去读它。既有 `has_shortage` / `shortage_items` / `total_shortage_count` 在有 BOM 时语义不变。

### Persistence Changes

- 无。

### Transaction Boundaries

- 入库读标志失败：拒绝该笔库存过账。过账已在单据确认事务内时，随该事务整单回滚。
- 无 BOM 下达：拒绝这一次下达，不改工单状态。

### Risks

- 把开关值为 False 误当成读失败。只有读函数抛错才拒绝。
- 把 `bom_missing` 接到开工或报工。那些调用方只读 `has_shortage`。

### Verification Strategy

- 在 `kuaigeyun-mes/riveredge-backend` 用 `uv run pytest` 跑覆盖上述坏路径与保持项的测试。未跑通不得声称通过。
