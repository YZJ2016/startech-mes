# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 用 springboot2 内容替换 `ktg-system`（保留手机号查询；已读不接回 `SysNotice`）
- Module: `ktg-system`
- Priority: P0
- Related requirement/design documents:
  - `docs/04.specs/11.backend-shell-swap-program.md`
  - `docs/04.specs/05.extract-message-attachment-notice.md`
  - `docs/04.specs/06.extract-or-drop-mobile-login.md`
  - `docs/04.specs/10.backend-extract-review.md` 第 7 节

### Business Goal

系统域（用户/角色/菜单/公告等）换成若依 3.9.2 springboot2 的 `ruoyi-system` 内容，仍为 `ktg-system` / `com.ktg.system`。手机号登录所依赖的 `selectUserByMobile` 必须留下。MES 公告已读继续走 mes 的 `SysNoticeDetail` / `SysNoticeListVo`，**禁止**把 `userId1`、`readStatus` 或若依的 `isRead` 当 MES 已读接回平台 `SysNotice`。

### Scope

In scope:

- 对照：`RuoYi-Vue-springboot2/ruoyi-system/`（commit `913524b1525a0e374774afbb54c452d8f68a5a8f`）
- 覆盖 nested `backend/ktg-system/` 的 Java 与 `src/main/resources/mapper/**`
- 机械替换包名与 pom GAV（规则同 `11`）
- **覆盖后并入**（从当前 nested、抽出后的实现拷回，不要发明新 SQL）：
  - `ISysUserService.selectUserByMobile` + `SysUserServiceImpl` + `SysUserMapper` + `SysUserMapper.xml`（`where u.phonenumber = #{phonenumber}`）
  - 公告列表给 mes 用的查询能力：`SysNotice.userId`、列表 SQL 按 `userId` 过滤、`userName`（`sys_notice` join `sys_user.user_name`）。这是列表展示/收件过滤，**不是**已读字段
- 对照含 `SysNoticeRead*`：允许作为 3.9.2 额外类型进入 system；**禁止**把 mes `GET /system/notice/list` 改去调这些类型；禁止与 `SysNoticeDetail` 做数据迁移合并（`05` 已 Out of scope）

Out of scope:

- 把已读字段接回 `SysNotice`（`userId1` / `readStatus` / 把 `isRead` 当 mes 已读 JSON）
- 改 `ktg-mes` 的 `SysNoticeListController` / `SysNoticeListVo` / `SysNoticeDetail*`
- 删除若依 admin `/list`（那是 `17`）
- Java 17 / Boot 3/4 / jakarta / 模块改名
- 新建第二套用户表

### Acceptance Criteria

- `selectUserByMobile` 在 Service/Mapper/XML 均存在，供 `16` 的 `UserDetailsServiceImpl` 调用
- 平台 `SysNotice` 与 `SysNoticeMapper.xml` **没有** `userId1`、`readStatus`
- 对照源里的 `SysNotice.isRead` **不要**接到 mes 已读链路；实体上若随 3.9.2 带了 `isRead`，不得让 `SysNoticeListVo` 改读该字段（本单元不改 mes；故不要在 Mapper resultMap 把已读写进 mes 仍在 copy 的字段语义里）
- `SysNotice.userId` + 列表 `userId` 条件保留，否则 mes `notice.setUserId(getUserId())` 失效
- `userName` 列表 join 保留（`09` 豁免/观察项，换壳后仍需要给 VO copy）
- `rg "com\\.ruoyi" backend/ktg-system` 为 0
- JDK 8 编译 `ktg-system,ktg-framework,ktg-mes,ktg-admin -am` 通过后再 `16`

### Rules and Constraints

Tenant isolation:

- 不改用户-部门数据权限模型

Security and masking:

- 不在日志打印口令；不扩大用户查询匿名面

Audit and lineage:

- `selectUserByMobile` SQL 与抽出后 nested 一致，不改列名

AI/rule-engine rules:

- 不涉及

Database rules:

- 不把 mes 已读迁到 `sys_notice_read`
- 不原地改 `mes_sys.sql`；`SysNoticeRead` 缺表不在本单元强行执行上游 sql/

## 2. Plan

### Implementation Approach

1. `14` 通过后再开始
2. 先拷出 nested 的 `selectUserByMobile` 四处文件片段，以及 `SysNotice.java` / `SysNoticeMapper.xml` 中与 `userId`/`userName`/list 过滤相关的段落
3. 整树覆盖 system；机械替换
4. 把 T2 片段并回：用户手机号查询 + 公告 list 过滤/join
5. 若覆盖带入 `SysNoticeRead*`：保留文件即可，不要改 mes 去调用
6. 对照 `SysNotice` 若仅有 `isRead`、没有 `userId`：以 mes 编译和列表过滤为准，**加回 userId/userName/SQL**，不要用 `isRead` 冒充已读

nested 现网关键路径（只读对照，实施时以当时文件为准）：

- `ktg-system/.../ISysUserService.java` `selectUserByMobile`
- `ktg-system/.../mapper/system/SysUserMapper.xml` id=`selectUserByMobile`
- `ktg-system/.../domain/SysNotice.java` 的 `userId`、`userName`
- `ktg-system/.../mapper/system/SysNoticeMapper.xml` 的 `selectNoticeList`（join `su.user_name`，`userId` 条件）

### Affected Modules

- `ktg-system`
- 编译会带到 framework / mes / admin，但不改 mes Java

### Public Contracts

- `ISysUserService.selectUserByMobile(String)` 保留
- `ISysNoticeService.selectNoticeList` 仍可被 mes 列表 Controller 调用；过滤语义（非管理员按 `userId`）保留
- 已读 JSON 字段名仍由 mes VO 提供（`17` 才处理 `/list` 冲突）

### Persistence Changes

- 无必做新脚本。`SysNoticeRead` 表若上游需要，记 Known gap

### Transaction Boundaries

- 沿用换入源码

### Risks

- 漏并 `selectUserByMobile`，`16` 编译失败或手机号登录静默消失
- 用若依 `isRead`/`SysNoticeRead` 替换 mes 已读，现场公告状态错乱
- 丢掉 `userId` 过滤，非管理员看到全部公告

### Verification Strategy

- `rg "selectUserByMobile" backend/ktg-system`
- `rg "userId1|readStatus" backend/ktg-system` 应为 0
- `rg "setUserId|userName" backend/ktg-system/src/main/java/com/ktg/system/domain/SysNotice.java`
- JDK 8 compile
