### Business Goal

平台开通租户时，在基本信息页用两个独立开关声明是否独立 DB、是否独立向量库；步骤条和表单**只出现已打开开关对应的后续步骤**。共享 DB 且共享向量的工厂：填完基本信息点完成即结束，不再看见 JDBC / 建 schema / 向量步骤。工厂不能在本页或知识库页改共享 yml 集群。

### Scope

In scope:

- 现网事实（2026-09-08 `index.vue`）：`el-steps` 固定三步「基本信息 / JDBC / 建 schema」。`isolationLevel === 'ROW'` 时「下一步」调用 `submitCreate()` 并关窗，但步骤条仍画出后两步。`DATABASE` 才进入 JDBC，提交后再到建 schema。
- **基本信息页两个独立开关（文案冻结）：**
  - 「独立 DB」：关 = `isolationLevel=ROW`；开 = `DATABASE`。创建后仍禁改档（D8）；编辑页隔离级别继续 disabled。
  - 「独立向量数据库」：关 = `SHARED`（不调向量 PUT，走 yml）；开 = `DEDICATED`。两开关互不绑架（可共享 DB + 专向量，或专 DB + 共享向量）。
- **步骤条只渲染将要走的步。** 冻结顺序：
  1. 基本信息（始终有）
  2. JDBC（仅独立 DB 开）
  3. 独立向量库（仅独立向量开；**必须已有 `tenantId`**，即登记成功之后）
  4. 建 schema（仅独立 DB 开）
- 两开关都关：基本信息校验通过 → `POST` 创建 → 关窗。主按钮文案「完成」，不出现「下一步」。
- 仅独立向量：基本信息 → 创建 → 向量步骤（`PUT /platform/tenant/{id}/vector-store`，`DEDICATED` + type/host/只写 Key）→ 完成。向量 PUT 失败：登记保留，可重试本步，不删租户（对齐 I6 精神）。
- 仅独立 DB：基本信息 → JDBC → 创建（带 JDBC）→ 建 schema。与现网 DATABASE 路径相同，只是步骤条不再对 ROW 厂展示 JDBC/schema。
- 两开：基本信息 → JDBC → 创建 → 向量 → 建 schema。
- 向量步骤字段：`type`（`weaviate` | `dashvector`）、对应 host/endpoint、只写 API Key。不回显 Key。不展示 SHARED 的 yml 地址。
- **编辑页：** 隔离级别仍 disabled。独立 DB 厂可覆盖 JDBC 口令（现网已有）。独立向量：开关 + 地址段；关开关并保存 = `PUT` `SHARED`（删专行）。未开则不渲染向量字段。
- 列表：不新增向量 Key 列；可不展示 host（避免工厂会话以外的平台列表把专库地址当普通列扩散——若展示须打码且仅平台）。本单元最低限度：列表不加 Key。
- 调用现网 `addTenant` / `updateTenant` / `createTenantSchema`；向量走 93 契约。不改这些 URL。
- `npm run build:prod`（有前端改动）

Out of scope:

### Acceptance Criteria

- 两开关都关：步骤条只有「基本信息」；点完成即创建结束，DOM 不出现 JDBC / 建 schema / 向量表单项
- 只开独立 DB：出现 JDBC 与建 schema，不出现向量步骤
- 只开独立向量：创建后出现向量步骤，不出现 JDBC / 建 schema
- 两开：四步按冻结顺序出现
- 独立向量步骤在登记成功前不可进入；缺 host 不能点完成
- 编辑页不能改 `isolationLevel`；可改向量档
- 工厂账号看不到本页（现网 `/platform/**` 门禁，不新开）
- 第 4 节未点选不得写 UI 已验
- 文档无真实 JDBC / 向量 host / Key

### Rules and Constraints

Tenant isolation:

- 只平台会话使用本页；不信客户端租户头
- 向量 PUT 只针对刚登记或正在编辑的该 `tenantId`

Security and masking:

- JDBC 口令与向量 Key 只写不回填；关窗清口令
- 不把 cipher、yml 共享地址渲染给本向导的 SHARED 厂

Audit and lineage:

- 揭明文仍走现网 JDBC reveal；本单元不新开向量 Key reveal
- 不改历史 `backend/sql/`

AI/rule-engine rules:

- 本单元不改 RAG 检索
- 不把集群字段放进 `/ai/knowledge`

Database rules:

- 本单元不改表。专绑定表由 93 建

## 2. Plan

### Implementation Approach

1. 将现网 `isolationLevel` 单选改为「独立 DB」开关（内部仍提交 `ROW`/`DATABASE`）。
2. 增加「独立向量数据库」开关；派生 `visibleSteps`，`el-steps` 只绑可见步。
3. `nextCreateStep`：独立 DB 关且独立向量关 → `submitCreate` 关窗；独立 DB 开 → JDBC；独立 DB 关且独立向量开 → `submitCreate` 后进向量步。
4. 向量步：`PUT /platform/tenant/{id}/vector-store`。失败保留登记。成功后若独立 DB 开则进 schema，否则关窗。
5. 编辑页按已有 `isolationLevel` 与 GET 向量绑定回填开关；保存时按开关 PUT `SHARED` 或 `DEDICATED`。
6. `src/api/platform/tenant.js` 增加向量 GET/PUT 封装（path 与 93 锁定一致）。

### Affected Modules

- `startech-mes-front/src/views/platform/tenant/index.vue`
- `startech-mes-front/src/api/platform/tenant.js`
- 不改 `frontend/`、不改 92、不改 Java（除非 93 尚未提供 API——则本单元向量步骤延期，第 4 节写明）

### Public Contracts

- **冻结：** `POST /platform/tenant`、`PUT /platform/tenant`、`POST /platform/tenant/{id}/schema`、`POST /platform/tenant/{id}/jdbc/reveal`
- **消费 93：** `GET`/`PUT /platform/tenant/{id}/vector-store`
- 创建 Body 仍：`tenantCode` / `tenantName` / `isolationLevel` / `serverName` /（DATABASE 时）JDBC 三字段。不把向量字段塞进创建 Body

### Persistence Changes

- 无。93 建表。

### Transaction Boundaries

- 每步独立 HTTP。创建成功、向量失败：租户行保留，向导停在向量步可重试。
- schema 失败：现网 I6（未就绪、可重试）

### Risks

- 步骤条仍写死三步，ROW 厂继续看到 JDBC（本单元要消灭的现状）
- 独立向量步在创建前就渲染，PUT 无 `tenantId`
- 把 yml 共享 host 回显到 SHARED 厂表单
- 创建 Body 夹带向量字段导致契约膨胀
- 93 未编码时把向量步骤写成已通

### Verification Strategy

- `cd startech-mes-front && npm run build:prod`
- 有已登录平台会话时：四种开关组合点选（两关 / 只 DB / 只向量 / 两开），写入第 4 节；无会话写「未点选」
- 只 DB 路径不依赖 93；只向量 / 两开路径须 93 HTTP 已存在
