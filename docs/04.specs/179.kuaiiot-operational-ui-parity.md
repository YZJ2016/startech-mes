## 1. Spec

### Capability

- Name: 星数采八页面运营 UI 闭环复刻。
- Module: `kuaigeyun-mes/riveredge-frontend/src/apps/kuaiiot`，以及其确有缺口的 `riveredge-backend/src/apps/kuaiiot` 标准端点。
- Priority: P1。
- Related requirement/design documents: `docs/02.requirements/19.kuaiiot-selfdev-gaps.md`（KIO-R12、KIO-R14）；`docs/03.design/19.kuaiiot-selfdev-plan.md`；`docs/04.specs/178.kuaiiot-core-integration-remediation.md`。

### Business Goal

把星数采从研发/实施人员使用的同页工程表单，升级为设备主管、自动化工程师和运维人员可持续使用的运营工作台。八个入口沿用示例系统的信息架构与交互模式，但所有可见操作必须连接当前自研后端真实能力；不得复制示例数据、凭据或无关模块。

### 2026-10-08 DOM 复核与用户决策

本轮通过 Computer Use 连接用户已登录的 Chrome，读取八个页面 DOM、表头和关键新建弹窗；未使用截图。页面内容证明上版仍有字段、卡片和流程偏差。用户选择 B：数采页提供应用连接的新建/选择入口；同一租户可创建多条同类型连接，以具体 UUID 绑定，不按租户或协议自动合并连接。

- 公共连接就是「系统配置 → 应用连接器 → 新建应用连接 → IoT物联网」维护的 `IntegrationConfig`。数采连接保存引用与载荷映射，地址和凭据通过既有 `/core/application-connections` 保存。
- 数采中心参考为四 KPI：在线设备（超时未上报附项）、今日点数、未确认告警、异常连接（启用连接附项），下方六个快捷入口、待办及六分区。
- 数采链路参考为五项统计与四列关系图；补上未确认告警统计，各源失败单独显示不可用。
- 设备列表参考包含产品与 MES 设备；本轮补齐已有响应字段的展示。单设备新建的产品/分组字段及外部设备发现候选并非当前创建契约能力，不能仅复制控件伪装实现。
- 点位/产品 Key 控件允许选择已有值和自定义输入；点位写回目标改为单字符串控件，填充目标候选来自已有合法值。参考的裸 `spot_check` 与本项目要求 `spot_check.*` 的校验不同，以后端代码为准。
- 告警规则先选择设备，再按该设备筛选点位候选；保留后端已有的可选设备/全局规则能力与手动输入。
- 边缘配置保留本仓已实现的结构化协议配置、发布与试读能力，不退回参考站的纯 JSON 表单。

### Scope

In scope:

- 八个用户指定路由的内容区、加载/空/错误/无权限状态和 390px 窄屏行为。
- `dashboard` 改为真正运营总览；`pipeline` 改为可选择节点并高亮关联的链路视图。
- 产品、设备、点位、连接、边缘、告警统一使用本仓现有列表页模式：模糊搜索、高级筛选、重置、帮助视图、客户端分页、列状态和真实行操作。
- 修复独立点位页无设备选择器的流程断点；新建/编辑使用实体选择器，避免要求用户记数字 ID 或 UUID。
- `edge-configs` 成为规范路由；保留现有 `/edge` 兼容跳转，不破坏旧书签和菜单契约。
- 后端已有能力直接复用；缺少详情、编辑、软删除时才增加同资源兼容端点。既有列表 URL、method、认证头和响应外层不变。
- 动作按钮按权限提前隐藏或禁用；后端 RBAC 继续作为最终安全边界。

Out of scope:

- 复制示例站数据、租户、凭据、主题壳、天气日历、全局工作台组件或其他应用页面。
- 新建第二套 ORM、认证、前端框架或通用列表框架；升级 React、Vite、Ant Design。
- 为视觉复刻虚构 OPC UA/S7 执行能力、内置 Broker、增加新表或修改已执行迁移。
- 把趋势、指令、分组、消息、模板从现有路由删除；它们保持可访问，但本单元不新增侧栏入口，除非示例取证或用户另行点名。
- 真实 PLC、Broker、Influx、ThingsBoard、JetLinks 和生产数据压力验收。

### Acceptance Criteria

- 八个路径均能从应用菜单直接进入，刷新后状态不依赖上一个页面的 React 内存。
- `/tags` 可选择已有设备后新增点位；不会再只能提示“请先登记 IoT 设备”。
- 六个资源页初次进入自动加载；具备搜索、重置、空状态、错误反馈、20 条默认分页和页码切换。
- 新建、详情、编辑、删除、批删、导出等可见按钮要么完成真实行为，要么因当前权限/能力明确隐藏或禁用；禁止假按钮和仅 toast 冒充完成。
- 设备、产品、连接、分组、MES 设备等关联字段使用可搜索选择器并显示编码+名称；JSON 仅在确属协议高级配置时放入高级区。
- 数采中心 KPI 与分区数据来自当前租户真实接口；未知或不可用显示 `—` 与原因，不补零冒充。
- 数采链路点击连接、设备或点位后，只高亮同一关联路径；键盘可聚焦并触发，颜色不是唯一状态信号。
- 状态、严重度、在线、健康、Agent 状态使用语义标签；时间按项目统一格式；表格在窄屏横向滚动且关键操作可达。
- 桌面参考示例站内容密度；390×844 下不出现整页横向溢出，固定操作不遮挡焦点，表单错误与提交 busy 可感知。
- 前后端权限、租户隔离、一次性设备凭据和现有入站/告警/OEE 契约不回归。

### Rules and Constraints

Tenant isolation:

- 所有新增读写继续依赖 `get_current_tenant`、现有 QuerySet 强制隔离和领域服务；禁止从前端传租户 ID 决定作用域。

Security and masking:

- 设备 token 仍只在创建/轮换当次显示；列表、详情、导出、错误和 toast 不回显凭据、公共连接密文或内部地址。
- 按 `useResourcePermissions`/现有权限工具控制动作可见性；不能依赖前端隐藏替代后端 `require_permission_codes`。

Audit and lineage:

- 新增、编辑、软删除沿用现有审计字段和用户信息；导出是只读客户端文件，不产生伪造业务审计。

AI/rule-engine rules:

- 不涉及 AI；告警规则沿用当前 operator、severity、cooldown 和通知语义，不新增平行规则引擎。

Database rules:

- 预期无迁移。若实施中发现字段确实缺失，必须先核对前端、模型和已有 aerich，再按 14 位时间戳规则另行请用户决策；不得为页面展示复制字段。

## 2. Plan

### Implementation Approach

- 采用用户确认的“分页面闭环复刻”：先建立 kuaiiot 内部共享列表页配置和状态呈现组件，不修改项目全局模板；再按接入配置→设备连接→点位映射→产品模型→边缘配置→数采中心→数采链路→告警中心顺序完成。
- 列表首轮复用现有数组响应，在前端完成搜索、筛选和分页，避免改变既有响应外层。数据规模或接口上限成为真实阻碍时，不在同一 URL 改响应形状，另行提出兼容分页端点选项。
- 详情/编辑/删除优先复用当前服务；确实缺失的标准动作以新增端点补齐。批删串行调用单条软删除，任一失败停止并保留成功/失败反馈。
- 共享视觉只抽取已出现三次以上且语义一致的局部组件；不为了八页复刻发明第二套 ProTable 或全局设计系统。

### Affected Modules

- 前端：`riveredge-frontend/src/apps/kuaiiot/index.tsx`、`manifest.json`、`services/kuaiiot.ts`、`pages/{registry,pipeline,alerts,products,edge}/`；按需新增应用内共享组件及 `dashboard/devices/tags/connections` 页面目录。
- 后端：`riveredge-backend/src/apps/kuaiiot/api/`、`schemas/`、`services/` 中当前动作确实缺失的资源；`manifest.json` 同步路由和权限。
- 测试：`riveredge-backend/tests/apps/kuaiiot/`；前端沿用仓库现有测试能力，没有可运行组件测试框架时以 TypeScript/build 与浏览器流程为证据，不伪造单测。

### Public Contracts

- 保持当前所有已存在 URL、method、认证头和响应外层结构。
- 新规范页面路由为用户给定的八个路径；`/apps/kuaiiot/edge` 兼容跳转到 `/apps/kuaiiot/edge-configs`。
- 新增后端动作只采用资源从属路径和现有 `apiRequest` 方式；不新增第二套 API client。

### Persistence Changes

- 无计划内表、索引或迁移变化。列表筛选与分页不复制业务数据。

### Transaction Boundaries

- 单条新建/编辑/软删除沿用领域服务事务；前端批删不是跨多行原子事务，逐条成功项不回滚，失败时报告明细并停止后续操作。

### Risks

- 示例站功能可能依赖当前开源/私有分支尚未提供的端点；不得用静态按钮掩盖。
- 八页同时修改易产生大文件和重复逻辑；按垂直页面逐段验证，公共组件保持局部。
- 示例站本轮取证以桌面内容为主；实施前还需采集关键弹窗/抽屉及 390px 状态，缺证据的视觉不猜。
- 当前业务仓与外层文档均有既存未提交改动；只修改本单元相关文件，不覆盖用户改动。

### Verification Strategy

- TDD：每个新增后端行为先写失败用例并确认红灯，再写最小实现；现有行为只补能暴露本轮缺口的回归。
- 相关后端：`PYTHONPATH=src:. uv run --no-sync pytest tests/apps/kuaiiot -q -p no:cacheprovider`。
- 前端：`npm run build`；记录既有警告，不把 exit 0 夸大为视觉验收。
- 浏览器：逐页核对桌面与 390×844 的加载、搜索、分页、新建、详情、编辑、删除/批删确认、权限、空/错状态；对照示例截图做设计 QA。
- 不启动后端即可完成的静态阶段不冒充端到端；真实写操作只在本地测试数据环境验证，不在示例系统提交。
