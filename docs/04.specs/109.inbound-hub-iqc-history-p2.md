### Business Goal

105 闸以 `recpt_id`+`item_id` 为准，历史空 `recpt_id` 走 IH-D7 回退（头 `iqc_id` 或 `purchase_code=poCode`）。本单元把能唯一解析的历史 IQC 写上 `recpt_id`。不改闸合格语义。无法唯一匹配的行保持 NULL。

### Scope

In scope（**仅当编码门禁满足**）:

- tenant Flyway（或等价一次性脚本进 `db/migration/tenant`）：按 IH-D7 回退规则回填可空 `recpt_id`
- JOIN 双方 `tenant_id`；外层 `UPDATE ... ON` 同时匹配 `iqc_id` 与 `tenant_id`（禁止只 ON `iqc_id`）
- 无法唯一匹配的行保持 NULL，**禁止**猜写跨单
- 回填前后计数校验（本租户、同 `tenant_id`）
- 文档回写缺口 13 IH-G3

Out of scope:

- 改 105 回退逻辑当「先回填才能开工 105」（105 已不依赖本单元）
- 全表盲填、跨租户 UPDATE、改历史 `backend/sql/`
- FQC（108）、金额（110）、打印（111）、出库
- 新建第三张入库头表
- 改 Vue / 新 HTTP

### Acceptance Criteria

- **编码门禁（已满足）：** 点名 109；用户明示执行历史回填。
- 能唯一解析的历史行由 tenant 脚本写 `recpt_id` 且 JOIN 同租户；无法唯一匹配者仍 NULL；闸行为不因误填串单而放行他单
- 第 4 节未跑命令不得写绿

### Rules and Constraints

Tenant isolation:

- UPDATE 必须带 `tenant_id`；禁止无上下文跑脚本
- `recpt_id` 指向的入库单必须同租户，否则不写

Security and masking:

- 脚本/日志不打印 JDBC 口令、内部路径

Audit and lineage:

- 只进 Flyway tenant；版本号按当时目录最大号顺延
- 不改 105 已发布的 `V20260915.02` 文件

AI/rule-engine rules:

- 不涉及

Database rules:

- 只写已有 `qc_iqc.recpt_id`；不加金额列

## 2. Plan

### Implementation Approach

- 幂等 tenant 回填：先头 `iqc_id`+`item_id`，再 `purchase_code=po_code`+`item_id`；`HAVING COUNT(DISTINCT recpt_id)=1`；禁止应用层扫全库再滤租户。

### Affected Modules

- `ktg-system` Flyway tenant；必要时只读校对 SQL（不进公开 API）
- 不改 Vue、不改 Hub 契约

### Public Contracts

- 无新 HTTP；IQC/入库旧 URL 不变

### Persistence Changes

- 仅回填 `qc_iqc.recpt_id`

### Transaction Boundaries

- 按租户批次回填；失败回滚该批，不半写他厂

### Risks

- 多入库单共享同一采购号导致误填（保持 NULL）
- 未证明回退不够就跑全表（违反 IH-G3）

### Verification Strategy

- 脚本静态单测（tenant_id / 唯一匹配）；真实库回填前后计数仍属部署手验
