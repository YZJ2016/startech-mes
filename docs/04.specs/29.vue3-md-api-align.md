# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: Vue3 管理端 MES 主数据（md）API 对齐
- Module: `startech-mes-basic/startech-mes-front/src/api/mes/md`（只读对照 `backend/ktg-mes` md Controller）；默认不改 Java
- Priority: P0
- Related requirement/design documents:
  - 总控：`docs/04.specs/27.vue3-backend-api-align-program.md`
  - 缺口：`docs/02.requirements/01.vue3-backend-api-gaps.md`（仅 D-md）
  - 调研：`docs/03.design/03.vue3-backend-api-align-survey.md`

### Business Goal

让 Vue3 主数据封装的 URL+method 对上换壳后 ktg-mes 已挂 HTTP 的 md Controller，避免图纸增删改打到不存在的 `/md/designpaper`、`/mes/md/designpaper`。不把无 mapping 的 Service 当成契约，不补 Java。

### Scope

In scope:

- 静态对照 `startech-mes-front/src/api/mes/md/**` 与 `ktg-mes` `com.ktg.mes.md.controller`
- 无 `/mes` 前缀、且确属主数据的封装：`packing`、`turnplate`、`designpaper`/`purchase`（`/md/manage`）、`taskTutnPlate`（若为 md）
- 仅当 md API 签名变化且页面硬编码同一路径时，最小改 views
- 归一：类 `@RequestMapping` + 方法 mapping；路径变量写成 `{id}`；忽略末尾 `/`
- 缺口写入本文件第 4 节（不改共享清单里非 D-md 行）

Out of scope:

- 改 Vue2 `frontend/`
- 改 Java、五项接线、工单/库存状态机
- `GET /system/notice/list` 归属、`uploadMinio`、`loginOuth`、锁屏（单元 28）
- `assessment` / `evaluation`：Controller 在 `pro` 包，封装在 `src/api/mes/edu/pj.js` → D-pro / D-rest
- `salse`：Controller 在 `wm` 包（`/md/salse`），封装在 `src/api/mes/sale/salse.js` → D-wm / D-rest
- `minutes` / `position` / `camera` 封装分别在 edu / tm / camera，本单元只静态记录，不改那些目录
- 为对齐去改已经打到后端真实 mapping 的 MES URL（例如 zip 走 `/mes/pro/workorder/*` 且后端有该方法）
- 提交 lockfile；运行时冒烟（无本单元对 live 后端的调用）
- 提交 git

### Acceptance Criteria

- Vue3 `src/api/mes/md` 每个非注释 `url`+`method` 能在 ktg-mes mapping 中找到，或在第 4 节列为开放缺口（Vue2 同样缺失且不补 Java）
- 不把 `GET /mes/md/bom` 与 `GET /mes/md/bom/{id}` 报成整模块缺失
- 图纸 add/update/delete 指向 `DrawingManageController` 的 `/md/manage`
- 无 Java diff；无 Vue2 diff；文档无真实地址/凭据
- 第 4 节有 grep/静态清单；未跑 live 则不写运行时通过

### Rules and Constraints

Tenant isolation:

- 不改数据隔离

Security and masking:

- 不在 spec、补丁、日志中复述 Token、对象存储密钥、数据库口令或内网地址
- 不扩大匿名访问面
- 图纸页已有的 OSS 签名 GET 保持为既有调用，不改成默认上传（清单 K2）

Audit and lineage:

- 对齐是接契约，不改 MES 状态机
- Vue2 仍保留的错误路径不在本单元修改

AI/rule-engine rules:

- 不涉及

Database rules:

- 不改表、不执行 SQL

## 2. Plan

### Implementation Approach

1. 抽出 md Controller mapping，与 Vue3 `src/api/mes/md`、Vue2 同目录对照（归一规则同上）
2. Vue3 打到后端没有的路径：若 Vue2 与后端已共同指向另一条现存 mapping，则改 Vue3；若 Vue2 也打缺失路径，则记缺口、不补 Java
3. 图纸 CRUD 生成器残留 `/md/designpaper`、`/mes/md/designpaper` 改接到已有 `/md/manage`（list/import/export 本就走该前缀）
4. `taskTutnPlate` 无 Controller（仅 Service，任务列表在 `/md/turnplate/tasklist`），不臆造 CRUD 映射
5. 把结果写入本文件第 4 节

### Affected Modules

- 文档：外层 `docs/04.specs/29.vue3-md-api-align.md`
- 实现：`startech-mes-basic/startech-mes-front/src/api/mes/md/designpaper.js`、`purchase.js`
- 只读：`startech-mes-basic/backend/ktg-mes/.../md/controller`、Vue2 `frontend/src/api/mes/md`
- 禁止：Vue2 `frontend/`、Java、`notice.js` / login / lock / 其他 mes 领域 api 目录

### Public Contracts

对齐后 Vue3 md 封装依赖的现存 HTTP（不新增）：

- `/mes/md/{bom,client,itemtype,mditem,capacity,sop,unitmeasure,vendor,workshop,workstation,workstationmachine,workstationtool,workstationworker}` 及既有子路径
- `/md/packing/**`、`/md/turnplate/**`、`/md/manage/**`
- 计划工作站：`POST|DELETE /mes/cal/workstation`（md 包 `CalPlanWorkstationController`）
- 图纸 zip：Vue3 继续用已存在的 `POST /mes/pro/workorder/upload-zip` 与（采购页）`POST /mes/pro/workorder/download-zip`；设计图纸下载走已存在的 `POST /md/manage/download-zip`

### Persistence Changes

- 无

### Transaction Boundaries

- 无

### Risks

- 图纸 add/update/delete 现行页面未引用这些函数；改封装只影响将来调用，当前导入/改报检时间已走 `/md/manage`
- `/md/taskTutnPlate/**` 无 HTTP，页面也未引用该封装；若有动态路由直调会 404
- 物料/图纸「下载模板」打的 `importTemplate` 后端无 mapping（Vue2 同样），本单元不补接口

### Verification Strategy

静态：grep Vue3 md `url`/`method`，对 Controller mapping；差集写入第 4 节。无 live 后端则不写运行时通过。

```text

  startech-mes-basic/backend/ktg-mes/src/main/java/com/ktg/mes/md/controller

rg -n "url:|method:" startech-mes-basic/startech-mes-front/src/api/mes/md

rg -n "md/designpaper|mes/md/designpaper|taskTutnPlate|url: 'md/manage'" ^
  startech-mes-basic/startech-mes-front/src/api/mes/md

rg -n "importTemplate|importData|importProcurementTemplate" ^
```

- 归一后 Vue3 `src/api/mes/md` 共 120 条 request 调用。标准 CRUD（bom/client/itemtype/mditem/packing/sop/unitmeasure/vendor/workshop/workstation* /turnplate）URL+method 与 md Controller 一致，包括无前缀的 `/md/packing`、`/md/turnplate`。
- 不把「有 list 无详情」或「有详情无 list」报成整模块缺失。例如 `GET /mes/md/bom/list` 与 `GET /mes/md/bom/{id}` 均存在。
- T2：`designpaper.js` / `purchase.js` 的 add → `POST /md/manage`，update → `PUT /md/manage`，delete → `DELETE /md/manage/{id}`；字段更新的 `md/manage` 补为 `/md/manage`。grep 已无 `/md/designpaper`、`/mes/md/designpaper`。
- zip：`POST /mes/pro/workorder/upload-zip` 与 `POST /mes/pro/workorder/download-zip` 在 `ProWorkorderController` 有 mapping，未改。
- `GET /get_post_signature_for_oss_upload` 后端有 mapping；按 K2 不改成默认上传。
- T3：`taskTutnPlate.js` 五条调用仍无 Controller；`ProTaskTurnplate` 仅 Service/Mapper，HTTP 在 `/md/turnplate/tasklist` 与 `POST /md/turnplate/endTask`。Vue2 同样打 `/md/taskTutnPlate/**`。页面未 import 该封装。
- T4：`/md/assessment`、`/md/evaluation` 属 pro Controller；`/md/salse` 属 wm `WmAfterSalseController`。封装不在 `api/mes/md`，本单元未改。
