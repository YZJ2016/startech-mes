### Business Goal

文档切块 → OpenAI 兼容 embedding → 写入当前配置的一种向量库，并能按租户+知识库检索。部署只开一种。DashVector 不在本单元。

### Scope

In scope:

- `VectorStoreService` + Factory：`weaviate` / `milvus` / `qdrant`
- 配置 `ruoyi.ai.vector-store.type` 及各库 host/port **占位符**
- `createSchema` / `storeEmbeddings` / `search` / `removeByDoc`
- 元数据强制 `tenant_id`、`kid`、`docId`、`fid`
- 解析任务：读 MinIO → 切块 → 写 `ai_knowledge_fragment` → 调 store（解析器可先纯文本/Tika 最小集）
- 未知 type 失败关闭
- 懒建**一种**客户端，不在启动时连三种

Out of scope:

- DashVector（56）
- 对话拼检索（55）
- 同时运行三种容器作为验收必项（单测可用 mock；一种 IT 可选）
- 复制 ruoyi-ai Plus Mapper

### Acceptance Criteria

- `search` 不传或错 `tenant_id` 不得返回数据（失败关闭或空且不查他租）
- 工厂 A 的 kid 不能读出工厂 B 的片段（夹具）
- type 非法 → 启动或首次调用失败，不落内存库
- yml 无真实 endpoint/key

### Rules and Constraints

Tenant isolation:

- I-A3：即使 collection 名含 kid，过滤仍要 `tenant_id`
- 空上下文不得调向量库

Security and masking:

- 集群凭证只环境变量
- 日志不打印 token

Audit and lineage:

- 无新密钥进仓

AI/rule-engine rules:

- Embedding 走本租户模型或单独 embedding 模型字段（50 已有 dimension）；凭证按 A24 从该 `modelId` 行取，不从 yml 模型目录取

Database rules:

- 写 fragment 行；向量不进 MySQL

## 2. Plan

### Implementation Approach

- 接口仿 ruoyi-ai `VectorStoreService`，实现自写
- 本单元运行时仍 JDK HTTP（默认 Weaviate）。父 POM 已导入双 LangChain4j BOM（60），`ktg-ai` **尚未**改写为 EmbeddingStore。后续若改写，只引对应 store，不引 Agent/MCP。community BOM 含 DashScope、**不含** DashVector。不要使用已过期的 `langchain4j-spring-bom`
- 默认本地 type 建议 `weaviate`

### Affected Modules

- `ktg-ai` vector 包、application.yml 占位、`ktg-admin` 解析 API（薄）

### Public Contracts

- `POST /ai/knowledge/attach/{id}/parse`（名称随风格）
- `POST /ai/fragment/retrieval` 可供 55 复用或本单元先内部 API

### Persistence Changes

- 写 `ai_knowledge_fragment`；附件状态字段

### Transaction Boundaries

- 切块落库与向量写入分步；向量失败标附件失败，可重试，不删知识库

### Risks

- 三种 SDK 启动全连
- 只按 kid 拼 class 名
- 把 ruoyi-ai 源码连同 Plus 依赖粘贴

### Verification Strategy

- 工厂单测：FakeVectorStore 或 mock client 验 tenant 过滤
- 每种策略至少一个单元测试（可用 mock HTTP/gRPC）
- 不要求本机起 Docker 才算单元完成；若做 IT 须可跳过
