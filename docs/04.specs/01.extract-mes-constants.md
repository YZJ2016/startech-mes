# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 从 `UserConstants` 拆出 MES 业务常量
- Module: `ktg-common` → `ktg-mes`
- Priority: P0
- Related requirement/design documents:
  - `docs/04.specs/00.backend-extract-program.md`
  - 调查：`UserConstants.java` MES 侧约 204 行，若依原版约 61 行；`ktg-mes` 约 130 个 Java 文件引用该类

### Business Goal

平台类 `com.ktg.common.constant.UserConstants` 只保留若依用户/角色/菜单/通用是否等常量。工单状态、仓储事务类型、质检类型、条码类型、班次、报表类型等 MES 常量迁到 `ktg-mes` 自有常量类，避免后续整模块替换 `ktg-common` 时业务常量静默消失、大面积编译失败。

### Scope

In scope:

- 新建 `ktg-mes` 常量类（建议名 `com.ktg.mes.common.MesConstants`，最终以代码落地名为准）
- 把 MES 专用常量从 `UserConstants` 移入新类
- 更新 `ktg-mes`（及仍引用这些常量的平台类，若有）的 import 与简单类名
- 保持常量**字符串值**不变

Out of scope:

- 改状态机取值、改字典、改前端枚举
- 替换 `ktg-common` 模块
- 自动编码、上传、登录等其它抽出

### Acceptance Criteria

- `UserConstants` 中不再包含 MES 业务常量（检索无 `ITEM_TYPE_CODE`、`TRANSACTION_TYPE_`、`QC_TYPE_`、`BARCODE_TYPE_`、`CAL_SHIFT_`、`ORDER_STATUS_`、`PURCHASE_STATUS_`、`REPORT_JASPER_PATH` 等）
- `ktg-mes` 中上述语义改引用新常量类；编译 `ktg-mes`（及被改到的模块）通过
- 常量字面量与迁出前逐项一致（可用 diff 旧 `UserConstants` 对照）
- `UserConstants` 仍保留若依通用项：`SYS_USER`、`NORMAL`、`YES`/`NO`、用户名密码长度、菜单类型等

### Rules and Constraints

Tenant isolation:

- 不新增租户维度

Security and masking:

- 不把常量类当成配置中心存放地址或密钥

Audit and lineage:

- 只搬迁符号，不改值；提交说明写明「抽常量、行为不变」

AI/rule-engine rules:

- 不涉及

Database rules:

- 不改表。库内若已按这些字符串落库，值必须保持原样

## 2. Plan

### Implementation Approach

1. 以当前 `ktg-common/.../UserConstants.java` 为清单，划出 MES 段与若依段
2. 在 `ktg-mes` 建 `MesConstants`，原样复制 MES 段
3. 在 `ktg-mes` 内把 `UserConstants.X` 换为 `MesConstants.X`（仅 MES 符号）
4. 从 `UserConstants` 删除已搬走的字段
5. 全仓检索确认无残留 MES 符号留在 `UserConstants`

`MessageProvider` 等仍在 `ktg-framework` 的类若使用 `MESSAGE_STATUS_*`，本单元一并改为引用 `MesConstants`，或暂时把消息状态常量留到 `05` 再搬。推荐本单元把 `MESSAGE_STATUS_*` 也迁入 `MesConstants`，避免 `05` 再拆一次。

### Affected Modules

- `ktg-mes`：新常量类 + 约 130 个引用文件
- `ktg-common`：缩小 `UserConstants`
- `ktg-framework`：若 `MessageProvider` 引用消息状态常量，改 import（仍不把类迁走，类搬迁属 `05`）

### Public Contracts

- 对外 HTTP 与库内状态字符串不变
- Java 调用方从 `UserConstants` 改为 `MesConstants`，属模块内 API，允许在本单元一次改完

### Persistence Changes

- 无

### Transaction Boundaries

- 无运行时事务变化

### Risks

- 漏改一处编译不过或运行期用错若依的 `YES`/`NO`（若依段必须留在 `UserConstants`）
- 把若依通用常量误迁走，导致 `ktg-system` 用户模块编译失败

### Verification Strategy

- `rg` 确认 MES 前缀符号只出现在 `MesConstants` 与业务引用，不再出现在 `UserConstants` 定义处
- 对 `ktg-common`、`ktg-framework`、`ktg-system`、`ktg-mes`、`ktg-admin` 执行 Maven compile（至少受影响模块）
