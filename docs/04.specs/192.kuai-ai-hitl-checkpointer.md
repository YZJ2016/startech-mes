# KU-AI HITL checkpointer（Tortoise 自实现）

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施（验收标准 5 中 aerich upgrade 未在本地 PG 实跑，见 §4 Known gaps）。

## 1. Spec

### Capability

- Name: 基于 Tortoise 的 LangGraph `BaseCheckpointSaver` 实现与表结构。
- Module: `riveredge-backend/src/apps/kuaiai/models`、`riveredge-backend/src/apps/kuaiai/services/checkpoint_saver.py`、`migrations/models/`。
- Priority: P0（确认闸 spec 193 的前置）。
- Related requirement/design documents: 需求 25 SC-D3、SC-D8、§4.4；需求 16 KR-D15、KR-G3（2026-10-23 改判）；设计 26 §9。

### Business Goal

为确认闸提供持久化的执行现场：中断等待确认期间服务重启或多实例部署，待确认动作不丢失，确认后能续跑同一次运行。

### Scope

In scope:

- 两张表：checkpoint 主表、pending writes 表；aerich 迁移。
- `TortoiseCheckpointSaver(BaseCheckpointSaver)` 实现异步接口：`aget_tuple`、`alist`、`aput`、`aput_writes`、`adelete_thread`；同步接口抛 `NotImplementedError`（本仓 agent 全异步运行）。
- 序列化沿用基类 `serde`（`dumps_typed` / `loads_typed`），值以 `(type, bytes)` 存储。
- 按租户隔离：`config["configurable"]` 必须含 `tenant_id` 与 `thread_id`，缺失即抛错；所有读写带 tenant_id。
- 过期清理方法 `purge_older_than(tenant_id | None, before)`，供 spec 193 的过期策略调用。
- 接口契约测试（升级 langgraph 时必跑）。

Out of scope:

- 接入 `build_agent`、中断/续跑流程（spec 193）。
- 前端（spec 194）。
- `aprune`、`acopy_thread`、`adelete_for_runs`、delta channel history 等本仓不用的扩展接口：不实现，调用时抛 `NotImplementedError` 并在类注释列明。

### Acceptance Criteria

1. 契约测试覆盖：put 后 get_tuple 取回同一 checkpoint/metadata/parent；list 按 checkpoint_id 倒序、支持 `before` 与 `limit`；put_writes 后 get_tuple 的 `pending_writes` 正确；同 task 重复写幂等；delete_thread 清两表。
2. 用 `langgraph` 真实小图（一个 interrupt 节点）跑通：中断 → 新建 saver 实例（模拟重启）→ `Command(resume)` 续跑完成。
3. 跨租户：A 租户 thread 在 B 租户 config 下不可见。
4. `configurable` 缺 `tenant_id` 或 `thread_id` 时抛明确异常，不写库。
5. 不新增 psycopg、`langgraph-checkpoint-postgres` 依赖（`pyproject.toml` 无新增）。

### Rules and Constraints

Tenant isolation:

- 主键/唯一键含 `tenant_id`；查询一律 `tenant_id=` 过滤。

Security and masking:

- checkpoint 内容可能含业务参数：表不进任何对外接口；日志只记 thread_id 与类型，不记值。

Audit and lineage:

- checkpoint 只存执行现场，不作为审计或历史真源（消息表仍是真源，KR-G3 方案 C）。

AI/rule-engine rules:

- 不改变 agent 行为；本单元只提供存储。

Database rules:

- 迁移文件名首段 14 位时间戳，大于目录现有最大值（实施时核对）。
- 建议表名：`apps_kuaiai_agent_checkpoints`（`tenant_id, thread_id, checkpoint_ns, checkpoint_id` 唯一；`parent_checkpoint_id`、`checkpoint_type`、`checkpoint_blob bytea`、`metadata_type`、`metadata_blob bytea`、`created_at`）与 `apps_kuaiai_agent_checkpoint_writes`（`tenant_id, thread_id, checkpoint_ns, checkpoint_id, task_id, idx` 唯一；`channel`、`value_type`、`value_blob bytea`、`task_path`、`created_at`）；索引 `(tenant_id, thread_id, checkpoint_ns, checkpoint_id DESC)`、`(created_at)`。
- 模型在 `apps/kuaiai/orm_models.py` 注册；不新建 Tortoise app。

## 2. Plan

### Implementation Approach

- 参照已安装 `langgraph/checkpoint/memory` 的 `InMemorySaver` 语义逐方法对齐（版本号生成用基类 `get_next_version`）。
- Tortoise 模型使用 `BinaryField` 存 blob；写入用 `update_or_create` 保证幂等。
- 契约测试以 `InMemorySaver` 作参照：同一组操作在两个 saver 上结果一致。

### Affected Modules

- Create: `apps/kuaiai/models/checkpoint.py`、`apps/kuaiai/services/checkpoint_saver.py`、迁移文件。
- Modify: `apps/kuaiai/orm_models.py`、`apps/kuaiai/models/__init__.py`。
- Test: `tests/apps/kuaiai/test_spec192_checkpoint_saver.py`。

### Public Contracts

- Python 类 `TortoiseCheckpointSaver`，构造无参；`configurable` 约定键 `tenant_id`、`thread_id`、`checkpoint_ns`（默认空串）、`checkpoint_id`。

### Persistence Changes

- 新增两表与索引（见 Database rules）。

### Transaction Boundaries

- `aput_writes` 一次调用内多条写在同一事务；`adelete_thread` 两表删除同一事务。

### Risks

- langgraph 小版本升级可能改 saver 接口或 checkpoint 结构：契约测试列为升级必跑项（写入 AGENTS 级说明由 spec 193 收尾时补）。
- blob 体积：只存执行现场，配合 spec 193 的完成即删与过期清理控制增长。

### Verification Strategy

- 契约测试 + 真实图中断续跑测试 + 跨租户测试；本地 `uv run aerich upgrade` 实跑。
