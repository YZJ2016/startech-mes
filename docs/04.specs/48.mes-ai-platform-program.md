### Rules and Constraints

Tenant isolation:

- AI 表 `tenant_id bigint NOT NULL`；加入 include 名单；无上下文失败关闭
- 登录后租户只信 JWT/`LoginUser`
- 未许可 `ai` 的工厂：`getRouters` 无 AI 菜单，`/ai/**` 403
- `DATABASE`：AI 表进专库 catalog；未就绪失败关闭，禁止回落主库
- 向量检索必须带 `tenant_id`（I-A3）

Security and masking:

- 不引入第二套认证；`/ai/**` 必须登录，不进 `MesPermitAllProvider`
- 模型 Key：AES-256-GCM，`AI_MODEL_CIPHER_KEY`；列表打码；VO 无明文/cipher（A20）
- 向量集群凭证只环境变量（A14）
- 日志不打印 Key / token / 内部路径（I-A5）
- 上传仍 `uploadMinio` + `tenant/{id}/`

Audit and lineage:

- 历史 SQL 不原地改写；AI 用新增量 `YYYYMMDD_NN_ai_*.sql`
- 许可变更走现有平台许可 API + `mes_module` 字典增量
- 操作日志可用现有 `@Log`

AI/rule-engine rules:

- 本期只做 OpenAI 兼容对话/embedding + 知识检索
- 禁止模型直连 MES 业务库
- 禁止搬 ruoyi-ai 匿名 `/workflow/run` 与内置 SQL MCP

Database rules:

- 列约定与租户总控相同：`tenant_id`、复合唯一键
- 新表必须同时：DDL、include 名单、专库 catalog、单测
- 根键 `ruoyi:`；AI 配置占位符

## 2. Plan

### Implementation Approach

1. P0 建 `ktg-ai` 空模块、许可字典、`/ai/**` 鉴权骨架。
2. P1 模型 CRUD + 加密密钥 + OpenAI 兼容探活（可不对流式）。
3. P2 会话表 + `POST /ai/chat/send` SSE。
4. P3 Vue3 模型页与全宽对话页。
5. P4 知识库元数据与 MinIO 附件（尚不检索）。
6. P5 三种开源向量策略（配置激活一种）。
7. P6 对话可选 `knowledgeId` 检索拼上下文。
8. P7 DashVector 第四策略。

与租户并行：不改租户已拍板 D/F/S/I/R；AI 只追加表与许可码。

### Affected Modules

- 文档：`docs/02.requirements/03.mes-ai-platform-gaps.md`、`docs/03.design/06.mes-ai-platform-plan.md`、`docs/04.specs/48`–`56`
- 后端：新建 `ktg-ai`；`ktg-admin` 依赖与薄 Controller；`ktg-system` 许可字典/映射；`ktg-framework` include 名单；专库 catalog（`ktg-system` 既有 provisioner）
- 前端：仅 `startech-mes-front`
- 禁止：`frontend/`；`docs/superpowers/`；`ktg-generator` / UReport 除非后续单独立项

### Public Contracts

- 保持：现有登录/getInfo/getRouters/uploadMinio/信封
- 新增：仅 `/ai/**`（精确 path 分单元定）
- 不新增可伪造且登录后仍生效的租户 Header

### Persistence Changes

- 新建 `ai_*` 表（50/51/53）
- `mes_module` 字典增加 `ai`（49）
- include 名单与专库 catalog 随表扩大
- 不改 `sys_tenant` 结构

### Transaction Boundaries

- 模型保存：校验 + 加密 + insert/update 同一事务
- 会话发消息：先落 user 消息，再流式；assistant 落库在流结束（失败标错，不回滚用户消息）
- 知识解析：附件行与向量写入分步；解析失败保留附件、可重试，不删知识库登记

### Risks

- 把 ruoyi-ai 路径/认证抄进来撞 `/system/message`
- 向量只按 kid 隔离导致跨租户检索
- 密钥进日志或模型 VO
- 聊天口误进 permitAll
- 三种向量 SDK 同时初始化拖垮启动
- 未列入专库 catalog 的 `DATABASE` 租户写进主库

### Verification Strategy

- 总控只验收文档完整性与 TOC 锁定
- 各实现单元第 4 节：未执行前填「未执行 / 待本单元实现后填写」
- 后端：`cd startech-mes-basic/backend` 后受影响模块 `mvn test` 或 `-am compiler:compile`；写明是否跳过 antrun
- Vue3：`cd startech-mes-basic/startech-mes-front && npm run build:prod`（有前端改动的单元）
- 未实际跑通不得写「测试通过」
