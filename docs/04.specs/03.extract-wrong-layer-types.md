# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 错层类型与小工具迁入 `ktg-mes`
- Module: `ktg-common` → `ktg-mes`
- Priority: P0
- Related requirement/design documents:
  - `docs/04.specs/00.backend-extract-program.md`
  - 调查：若依无 `ItemType`、`BarcodeUtil`、`ExcelUtils`、`BussinessException`

### Business Goal

物料分类实体、条码图生成、Excel 单元格读取、拼写为 `BussinessException` 的业务异常不再放在 `ktg-common`。换壳替换 common 后，主数据分类、仓库条码、工装导入仍可用。

### Scope

In scope:

- 将 `com.ktg.common.core.domain.entity.ItemType` 迁到 `ktg-mes` 主数据包（与现有 `ItemTypeService` / `ItemTypeMapper` 同层）
- 将 `BarcodeUtil` 迁到 `ktg-mes`（建议 `wm` 工具包，因唯一业务调用是 `WmBarcodeServiceImpl`）
- 将 `ExcelUtils` 迁到 `ktg-mes` 工具包；调用方：`TmToolController`、`TmToolMobileController`、`TmToolPurchaseController`、`DrawingManageController`
- 将 `BussinessException` 改为使用已有 `ServiceException`，或原样迁入 `ktg-mes` 并改两处抛出（优先前者，减少换壳后的自定义类型）
- `barcode4j-light`、`zxing` 依赖改由 `ktg-mes` 声明，并从 `ktg-common` 移除（若无其它引用）

Out of scope:

- 改条码码制、改导入列映射
- Minio / `FileUploadUtils`（`04`）
- 自动编码（`02`）

### Acceptance Criteria

- `ktg-common` 不再包含上述四个类型
- `ItemType` 与 `md` 的 Service/Mapper/Controller 编译期引用闭合
- `WmBarcodeServiceImpl` 仍能调用生成条码文件的方法，签名与格式参数不变
- 工装/图纸导入仍用同一套单元格读取逻辑
- 业务异常对调用方仍是运行时异常，错误消息不要求改文案
- 受影响模块 compile 通过

### Rules and Constraints

Tenant isolation:

- 不改 `ItemType` 树与工厂组织的关系

Security and masking:

- 条码内容不写入日志；本单元不新增接口

Audit and lineage:

- 只改包名与依赖，不改表 `md` 物料分类结构

AI/rule-engine rules:

- 不涉及

Database rules:

- `ItemType` 对应表已在 MES 主数据，不新建表、不改列

## 2. Plan

### Implementation Approach

1. 移动 `ItemType.java` 到 `com.ktg.mes.md.domain`（若该包已有同名冲突，保持单一实体，删除 common 副本）
2. 移动 `BarcodeUtil` 与条码依赖
3. 移动 `ExcelUtils`
4. 检索 `BussinessException` 两处业务抛出，改为 `ServiceException`（若依已有）；删除 common 中的错拼类
5. 全仓 `rg` 确认 common 无残留

### Affected Modules

- `ktg-common`：删除 4 个类及条码依赖（在无引用后）
- `ktg-mes`：接收类型；`md` / `wm` / `tm` 调用方改 import

### Public Contracts

- HTTP 不变（`ItemTypeController` 等路径不改）
- `BarcodeUtil.generateBarCode(...)` 对 `WmBarcodeServiceImpl` 的调用方式保持
- `ExcelUtils.getValue(cell)` 保持

### Persistence Changes

- 无

### Transaction Boundaries

- 无变化

### Risks

- `ItemType` 迁包导致 Mapper XML `resultType` 全名未改
- 删除 `BussinessException` 时漏改 catch 类型
- zxing/barcode4j 仍被其它模块引用却从 common 移除

### Verification Strategy

- `rg "class ItemType|class BarcodeUtil|class ExcelUtils|class BussinessException" backend`
- 检查 `ItemTypeMapper.xml` 的 `type` / `resultType`
- Maven compile `ktg-mes,ktg-admin`
