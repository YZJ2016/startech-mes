- Module: `startech-mes-basic/backend/ktg-mes`（wm 新资源）与 `startech-mes-front`（Vue3 送货单页）。**禁止**改 Vue2。业务仓分支 `feature/mes-kuaige-capability`。
- Priority: P2（出库切片后续；同一域 CAT-W03）
- Related requirement/design documents:

  - 设计：`docs/03.design/15.mes-outbound-hub-plan.md`（§7.2；菜单 9340–9346）
  - 切片总控：`docs/04.specs/106.mes-outbound-hub-program.md`
  - P0：`docs/04.specs/107.outbound-hub-p0.md`（送货单 **不是** `PRODUCT_SALSE`）
  - P1：`docs/04.specs/112.outbound-hub-other-borrow-p1.md`（本单元不依赖借料表）
  - 总览 CAT-W03；CAT-N2：不打包看板/功能/库存/报表/配料

### Business Goal

对照仓送货单是**独立资源**（`delivery-notices`），不是 Hub 里的销售出库。本单元在现网补送货单能力，并禁止把它当 `sales_delivery` / `wm_product_salse` 纳入。P0 销售出库仍走现网 `productsalse`。发送/签收**不扣库存**。

### Scope

In scope:

- 独立送货单资源：tenant 表 `wm_delivery_notice` / `wm_delivery_notice_line`；菜单 **9340–9346**（不占 9300–9319 / 9320–9334）；Vue3 页
- REST：`/mes/wm/deliverynotice` CRUD + `PUT /{noticeId}/send` + `PUT /{noticeId}/sign`；明细 `/mes/wm/deliverynoticeline`
- 与销售出库的关联：可选 `salseId`/`salseCode` 深链/引用，不合并成一种 Hub `outboundType`
- 旧 `GET /mes/wm/productsalse/list` 与执行 PUT 不变

Out of scope:

- 把送货单塞进 Hub UNION（默认不做）
- 其他出库/借料（112）、退料/退货（114）、委外、采购退货
- CAT-W01 / W04 / W05 / W06 / W07
- OQC 闸、出库金额、把送货单当销售出库改名
- 改 Vue2、改入库、扩 permitAll、把 `productsalse` execute 改成送货单

### Acceptance Criteria

- **编码门禁：**（1）点名 113；（2）107 完成 **或** 用户明示开工本单元；（3）送货单与销售出库的边界已书面确认（OUT-F08：独立资源）；（4）无待确认（冲突）。本会话已点名 113。
- 存在独立送货单入口或资源；Hub **不得**用送货单替换 `PRODUCT_SALSE`；送货单默认不进 `outboundhub/list`
- 发送/签收不调用 `StorageCore` / `processProductSalse`
- 新路径鉴权；不进 `MesPermitAllProvider`；新表 `tenant_id` + include
- 实跑后写第 4 节

### Rules and Constraints

Tenant isolation:

- 新表必 `tenant_id` + include；失败关闭
- 只信 JWT

Security and masking:

- 新路径鉴权；不进 `MesPermitAllProvider`

Audit and lineage:

- DDL 只进 Flyway；菜单 9340–9346，不占用 9300–9319 与 112 的 9320/9330 段
- 不改历史 `backend/sql/`

AI/rule-engine rules:

- 不涉及

Database rules:

- 不把送货单行写入 `wm_product_salse`
- 不加金额列（OH-G5）
- 生命周期 `PREPARE` → `SENT` → `SIGNED`，独立于销售出库过账（OUT-X02 不改）

## 2. Plan

### Implementation Approach

- 独立资源 + 菜单加法；Hub 默认 **不** 进 `outboundhub/list`（与 OUT-F08 一致）。
- 不改 107 的 ISSUE/PRODUCT_SALSE 合并语义；不把 `productsalse` execute 改成送货单。

### Affected Modules

- `ktg-mes`：`WmDeliveryNotice*` Controller / Service / Mapper
- Flyway master 菜单 9340–9346；tenant 建表
- Vue3：`views/mes/wm/deliverynotice/`、`api/mes/wm/deliverynotice.js`
- `TenantDedicatedSchema.WM_TABLES` 与 `application.yml` include

### Public Contracts

- 保持销售出库旧 URL / method / 执行语义
- 新增：
  - `GET/POST/PUT/DELETE /mes/wm/deliverynotice`
  - `PUT /mes/wm/deliverynotice/{noticeId}/send`
  - `PUT /mes/wm/deliverynotice/{noticeId}/sign`
  - 明细 `/mes/wm/deliverynoticeline`

### Persistence Changes

- tenant：`wm_delivery_notice`、`wm_delivery_notice_line`（`tenant_id`，无金额列）
- master：`sys_menu` **9340–9346**（页 + 查/增/改/删/发/签）。不占 Hub 9300–9319，不占 112 的 9320–9334。

### Transaction Boundaries

- 送货单生命周期独立于销售出库过账（OUT-X02 不改）
- 发送/签收只改状态与时间，不入库存事务

### Risks

- 把送货单当销售出库纳入 Hub（违反 OUT-F08）
- 未拍板拷快格云 `delivery-notices` 表（本单元用 MES 命名，不拷对照仓 DDL）

### Verification Strategy

- 单测：独立 REST、PreAuthorize、不进 Hub UNION、不调 StorageCore、productsalse execute 仍过账、租户失败关闭、菜单 9340 且不占 9300–9334
- Vue3 `npm run build:prod`
- 未对真实 MySQL 跑 Flyway、未登录手验
