# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: P-D 独立库数据源（`DATABASE` 工厂启用门禁）
- Module: `startech-mes-basic/backend/ktg-framework`（`TenantDataSourceRouter`、懒加载 Druid 专池、停用驱逐、I8 主库绑定）；`ktg-system`（建 schema + 租户表增量 + ping + `provision_status`）；登录链路 `SysLoginService` / `JwtAuthenticationTokenFilter` 接路由。禁止 MyBatis-Plus `@DS`
- Priority: P0（总控：任意 `DATABASE` 启用工厂的硬门禁；**必须在 40 完成之后开工**）
- Related requirement/design documents:
  - 设计：`docs/03.design/04.mes-shared-db-tenant-plan.md`（D7、I5/I6/I7/I8、F4、D8、§2.1.3–2.1.7、§5.5、P-D 阶段）
  - Flyway 后继：`docs/03.design/05.mes-flyway-integration.md`（产品决策：迁表器由 `incrementalSqlFiles` 换为 Flyway tenant location）。**本单元不落地 Flyway**；代码见 `docs/02.requirements/06.mes-flyway-follow-on-gaps.md`。本单元既有开通分步仍有效
  - 缺口清单：`docs/02.requirements/02.mes-multi-tenant-gaps.md`（I5/I6/I7/I8、F4、D8、S6、I10 租户轨已收口）
  - 总控：`docs/04.specs/35.mes-multi-tenant-program.md`
  - 上一单元：`docs/04.specs/40.tenant-md-p4.md`（P4 完成 = 本单元开工门禁；第二个 `ROW` 工厂不依赖本单元）
  - 下一单元：`docs/04.specs/42.tenant-pro-wm-p5.md`

### Business Goal

在 P4 已证明共享库 md 隔离之后，为创建时选择 `DATABASE` 的工厂提供失败关闭的专库路径：启动只建主池；应用建库并打与主库同一套租户表增量；迁表+ping 成功才可登录；首次业务访问才懒建专池；全局表经忽略名单 Mapper 整接口走主库；专库不可用禁止回落主库。本单元完成后才允许启用 `DATABASE` 工厂。P-D 完成前已登记的 `DATABASE` 租户继续拒登录，永不写入共享主库。

### Scope

In scope:

- **排期门禁：** 40 的 P4 退出标准达成后才改本单元代码
- 启动只初始化现有主池（`DruidConfig.masterDataSource`）；禁止启动扫描全部租户 eager 建专池（否决 Jugg 做法）
- `sys_tenant.provision_status`（若 36 未加则本单元增量补列）：至少 `NOT_READY` / `READY` / `FAILED`；建 schema/迁表失败保持未就绪或 `FAILED`，登记不删，可重试
- 开通 `DATABASE`：解密 JDBC（AES-256-GCM，密钥仅 `TENANT_JDBC_CIPHER_KEY`）→ 若 schema 缺失则 `CREATE DATABASE` → 跑**同一套租户表增量**（身份表 + 截至 P4 的 MES 租户表，空表）→ 复制角色 + 角色菜单授权模板 → ping → 成功才标 `READY` 并允许登录
- 失败：`provision_status` 保持未就绪/失败；不可登录；可改 JDBC **口令**后重试「创建 schema/表」；**禁止**删除登记；**禁止**把该厂数据写入共享主库
- 懒加载专池：`initialSize=0`、`minIdle=0`、`maxActive` 默认 8；迁表+ping 之后、**第一次业务访问**才建池（ping 用一次性连接，不因此常驻池）
- 停用/删除租户：卸载（`close`）专池并从路由表摘掉，**不删库**；同时沿用 D6 作废 token
- 拦截器不变；专库 SQL 仍带 `tenant_id`（与 ROW 同一套 DDL/UNIQUE）
- I8：忽略名单 Mapper **整接口**绑定主池；不按 SQL 表名回切；不引入 Plus `@DS`
- 平台 `runAs` 进入 `DATABASE` 租户时切到该专池（F9；仅平台账号；现网 `admin` 不能 runAs）
- 主库后续增量由应用打到每个已启用 `DATABASE` 租户（I6）；某库失败只阻断该租户
- I5 连接预算门禁：再开一个 `DATABASE` 会超则拒绝开通
- F4：列表/详情默认打码 JDBC 与口令；揭明文单独接口、须审计、仅平台
- D8：更新 API 拒绝改 `isolation_level` 与 JDBC 目标 URL/库；允许平台覆盖重写 JDBC 口令（S6）
- 登录链路：`DATABASE` 且未 `READY` 或 ping 失败 → 拒登录，文案仍「用户名或密码错误」（D9），不回落主库

Out of scope:

- 不在本单元扩大 md 以外的 MES 波次（P5+ 仍走 42–45）；但迁表清单必须包含 **40 已落地的 md 租户表 + P1 身份租户表**，否则专库无法登录
- ROW↔DATABASE 改档迁数（D8 禁用）
- 克隆 `sys_menu`、复制物料/主数据
- 把全局表拷进专库：`sys_tenant`、`sys_tenant_license`、`sys_menu`、`sys_dict_*`、`QRTZ_*`、`gen_*`、`sys_config`
- MyBatis-Plus、Sa-Token、Jugg eager 全池、失败开放回落主库
- 专库 SLAVE / 每租户 Redis 实例 / 密钥轮换（S6 一期不做）
- 改 Vue2；Vue3 揭明文按钮可在 46 再接，但本单元必须先有后端揭明文 API
- 不在日志、API、审计正文打印 JDBC 口令或完整明文 URL

### Acceptance Criteria

对齐设计「P-D 退出」并写死 I6 并行/权限验收：

- 夹具走应用建库+迁表入口（空表 + 角色/角色菜单模板，**不**复制物料、**不**克隆 `sys_menu`）；该租户登录只读写专库；主库即使误插同 `tenant_id` 的 md 夹具行，专库会话也不可见；专库无 `sys_menu` 表（或不含菜单行）
- 建库/迁表失败 → 登记保留为未就绪、不可登录、可重试；专库宕掉或错口令 → 登录/请求失败；主库无该租户业务写入
- `GET /getRouters` 与字典在专库无 `sys_menu` 时仍走主库成功（I8）
- 列表/详情默认无明文 password（打码 JDBC）；揭明文接口须审计且仅平台（F4）；工厂账号 403；审计不记明文
- 停用后池被关闭（测试间谍或连接计数证明不再泄漏）；不删库
- 不在启动日志里打印 JDBC 口令；`DynamicDataSourceContextHolder` 不得把 URL/口令当 lookup key 打到 `log.info("切换到{}数据源")`
- 启动只建主池：无 `DATABASE` 租户业务访问时，进程内专池数为 0
- 专池参数：`initialSize=0`、`minIdle=0`、默认 `maxActive=8`；首次业务访问后才 `getConnection`
- 专库不可用：**禁止**回落主库（业务 Mapper 失败关闭；忽略名单 Mapper 仍可读主库）
- I5 门禁：`主池 maxActive + N×专池 maxActive + 20 ≤ max_connections × 0.7`；再开一个会超 → 拒绝该 `DATABASE` 开通/建 schema；N = 已 `READY` 的 DATABASE 数（评估时含拟开通的这一个）
- **并行 N（I6，本单元写死）：** 应用侧「创建 schema/表」同时进行的租户数 **N ≤ 2**（含 2）。第三路并发必须排队或拒绝（明确 HTTP 429 或业务错误码，不得静默并行打满 `max_connections`）。验收：用测试夹具同时触发 3 次开通，最多 2 个真正执行 `CREATE DATABASE`/迁表
- **`CREATE DATABASE` 权限验收（I6）：** 使用**占位** JDBC（禁止真实生产主机/口令写入仓库）。账号无 `CREATE DATABASE` 时：迁表入口失败、`provision_status` 未就绪、不可登录、登记仍在、主库无该厂 md/身份业务行。账号有权限且 schema 缺失时：`CREATE DATABASE IF NOT EXISTS` 成功后再跑增量。有 schema 则跳过 CREATE 只跑增量
- 发布衔接：主库新增量文件加入「租户表」分类后，已 `READY` 的 DATABASE 租户由同一迁表器重放；失败只阻断该租户，不回落主库
- D8：PUT/更新拒绝改 `isolation_level`、拒绝改 JDBC URL/库名；口令 overlay 只写不回填
- 本单元完成后才允许**启用** `DATABASE` 工厂；第二个 `ROW` 工厂仍只依赖 40，不依赖本单元

### Rules and Constraints

Tenant isolation:

- `ROW` / 平台（`tenant_id=0`）始终主池；平台强制 `ROW`
- `DATABASE` 行上仍写 `tenant_id`；拦截器两档共用，永不跳过
- 登录先查主库 `sys_tenant` → 校验 `provision_status=READY` 且 ping 成功 → 再在**目标 DS** 按 `(tenantId, username)` 查用户
- 专库身份表在专库；未路由成功不得在主库查该厂用户（避免误命中或把登录写成共享库）
- runAs 目标为 DATABASE 时 DS 随目标厂；退出代管回到平台主池

Security and masking:

- JDBC 口令仅服务端解密用于建连；列表 BO 打码；禁止 API 回传 cipher 当密码
- 揭明文：仅 `is_platform` 账号；写操作日志（谁/何时/哪租户/哪字段）；**审计正文不写明文**
- `ROW` 且 JDBC 任一字段非空 → 仍 HTTP 400（36 已有则保持）
- 工厂不能改 JDBC；`tenantCode`/`server_name` 只许平台改（F10，本单元更新 API 一并拒绝工厂改连接信息）
- 无开关 fail-open；无「专库挂了读主库」
- 不引入第二套认证

Audit and lineage:

- 开通分步（F4）：① 基本信息；② DATABASE 必填 JDBC；③ 后续步骤「创建 schema/表」（谁点：仅平台运营接口，建议 `POST /platform/tenant/{id}/schema`，精确 path 与 36 对齐不得另造第三套前缀）
- 未就绪如何展示：平台详情返回 `provisionStatus`，不回 JDBC 明文；工厂不可见该字段
- 角色模板：从租户 1（或平台指定模板角色）复制 `sys_role` + `sys_role_menu` 到目标 `tenant_id`（DATABASE 时写入**专库**身份表）；模板范围由平台签发，禁止复制 `sys_menu` 行
- 停用卸载池写审计，不删库

AI/rule-engine rules:

- 本单元不涉及规则引擎或 AI

Database rules:

- 租户表增量 = 与主库同一套已发布的身份/`md` 增量（36/37/40 的租户表脚本），**不含**全局表 DDL
- 专库 UNIQUE 保持 `(tenant_id, 业务键)`，不改为仅业务键
- 本单元落地时增量仍在 `startech-mes-basic/backend/sql/YYYYMMDD_NN_*.sql`。Flyway 切线之后专库迁表改走 `docs/03.design/05.mes-flyway-integration.md`，不再追加 `sql/` 作为发布 DDL
- 禁止把现网 dump、真实 URL、口令写入仓库

## 2. Plan

### Implementation Approach

1. **确认 40 已完成**（md include + 隔离测试）。未完成则本单元不得合并启用 DATABASE。
2. 扩展 `DynamicDataSource`：支持运行时注册/移除 lookup key（如 `TENANT_{id}`），默认仍 MASTER；SLAVE 只作用于共享主库。禁止把 JDBC URL 当作 key。
3. 新增 `TenantDataSourceRouter`（`ktg-framework`）：
   - 启动不读租户建池
   - `ensurePool(tenantId)` 仅在 `READY` 且首次业务 SQL 需要专库时创建 Druid：拷贝主池超时等参数，覆盖 `initialSize=0`、`minIdle=0`、`maxActive=8`（可配置，默认 8）
   - ping：`DriverManager` 一次性连接 `SELECT 1`，失败不建池
   - `evict(tenantId)`：`close()` 并从 resolved map 删除
   - 专库失败抛错，**绝不**改 lookup 为主库
4. I5：开通 DATABASE 或点「创建 schema/表」前计算预算；超限拒绝。`max_connections` 来自该 JDBC 上 `SHOW VARIABLES LIKE 'max_connections'`（结果不当作密钥；日志只记数字）
5. I6/I7 `ktg-system` 迁表器：维护「主库专用脚本」vs「租户库脚本」清单。租户库：P1 身份表 + P4 md 表（及 P0 中非全局的租户列脚本）。执行顺序与主库发布顺序一致。失败标 `FAILED`/`NOT_READY`，不删 `sys_tenant` 行，不 INSERT 该厂 md 到主库
6. 并行 N≤2：进程内信号量（或等价）包住 CREATE DATABASE+迁表
7. I8：忽略名单 Mapper 整接口在调用期强制主池，且必须 **push/pop**，不得沿用现有 `DataSourceAspect` 的 `finally clear` 把后续业务 SQL 清回默认主库后误打主库。允许使用现有 `com.ktg.common.annotation.DataSource` **仅当**实现改为可恢复租户 lookup；否则单独 `MasterBindingInterceptor`（MyBatis plugin）按 Mapper 类型绑定。禁止 Plus `@DS`，禁止按表名解析 SQL
8. 登录：`SysLoginService` 在发 token 前：DATABASE → 未 READY/ping 失败 → 拒绝。`JwtAuthenticationTokenFilter` 在设 `TenantContext` 后绑定 DS lookup（业务默认专池；I8 Mapper 例外）
9. F4/D8/S6：列表打码；`POST .../jdbc/reveal` 平台+审计；更新拒绝 isolation/URL；口令 overlay 加密覆盖
10. 改 `DynamicDataSourceContextHolder.setDataSourceType`：lookup key 非敏感；禁止 `log.info` 打印含口令字符串

  - `com.ktg.framework.datasource.DynamicDataSource` / `DynamicDataSourceContextHolder`

  - `SysLoginService`、`JwtAuthenticationTokenFilter`、`TokenService`（不改登录 HTTP 契约）
- `ktg-system`
  - 租户 API（36 的 `/platform/tenant` 族）：补 schema 开通、揭明文、D8 拒绝字段、`provisionStatus`
  - 新建迁表/建库服务（如 `TenantSchemaProvisioner`）

### Public Contracts

保持：`POST /login`、`GET /getInfo`、`GET /getRouters`、Bearer JWT、`code/msg/data`。

本单元新增/收紧（仅平台，建议前缀与 36 相同，如 `/platform/tenant`）：

- `POST /platform/tenant/{id}/schema`：执行 CREATE DATABASE（若缺）+ 租户表 DDL + 角色模板 + ping；非平台 403
- `POST /platform/tenant/{id}/jdbc/reveal`：Body `{ field }`（如 `jdbcPassword`）；`data.value` 明文一次；写审计（无明文）；非平台 / `user_id=1` 403。**未实现 GET `/secret`。**
- `POST /platform/tenant/runAs/{id}`、`POST /platform/tenant/runAs/exit`：仅平台；`user_id=1` 不能 runAs；返回顶层 `token`；DATABASE 目标须 READY，DS 随目标厂
- 列表/详情：JDBC URL 部分打码、口令打码、无 cipher 字段；详情含 `provisionStatus`
- 更新：拒绝 `isolationLevel` 变更；拒绝 JDBC URL/用户名/库名变更；接受口令 overlay（只写）
- 工厂会话 `getInfo` 仍不回 `isolationLevel`、许可清单、JDBC（F2）
- 登录失败统一「用户名或密码错误」，含未就绪 DATABASE（D9）

### Persistence Changes

- `sys_tenant.provision_status`：`varchar` 非空默认 `READY` 对已有 `ROW` 种子（0/1）；新 `DATABASE` 插入为 `NOT_READY`，迁表成功改为 `READY`
- 不把 JDBC 明文列加回表；继续 `jdbc_password_cipher`
- 专库：应用执行与主库相同的租户表增量，得到空 md/身份表 + 模板角色，**无**物料复制、**无** `sys_menu` 表
- 主库误插入的该 `tenant_id` 业务行不得在专库会话中可见（验收夹具）

### Transaction Boundaries

- 保存租户基本信息 + 加密 JDBC：短事务（36）；**不**含 CREATE DATABASE
- 建 schema/迁表/模板角色/ping：独立步骤，失败不回滚登记（I6）
- 登录：无长事务；路由确认失败不发 token
- 业务 SQL 事务在已选定的 DS 上；I8 读菜单不把整请求事务绑死专库

### Risks

- 失败开放回落主库（高于一切，与漏表同级）
- `DataSourceAspect.finally clear` 导致 I8 读完菜单后业务打到主库或丢专池
- 启动 eager 建池打满 `max_connections`
- 并行开通无上限
- 迁表失败仍标 READY 或删除登记
- 克隆菜单 / 复制物料造成跨厂模板污染
- 日志打印解密口令或 Druid URL 中的 userinfo
- 揭明文无审计或工厂可调
- 未完成 40 就启用 DATABASE，专库缺 md 列

### Verification Strategy

- 单元：Router 启动后专池 map 为空；ensure 后参数为 0/0/8；evict 后 close 被调用
- 单元：I8 名单 Mapper 在模拟「当前 lookup=TENANT_x」时仍获取 MASTER；业务 Mapper 在专库关闭时抛错而非改 MASTER
- 集成夹具：占位库执行 provision → 登录该 `tenantCode` → 插物料只在专库；主库同 id 夹具不可见；`GET /getRouters` 200 且专库无 menu 表
- 失败夹具：错误口令/无 CREATE 权限 → NOT_READY、登录失败、主库无该厂 md
