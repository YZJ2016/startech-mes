# KU-AI 场景 Tool：一次合格率与缺陷帕累托

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施。

## 1. Spec

### Capability

- Name: 新增只读 Tool `analyze_first_pass_yield`、`analyze_defect_pareto`；与 spec 190 的 `analyze_quality`、spec 197 的 `query_quality_exceptions` 组成 S12 质量异常归因工具组。
- Module: `riveredge-backend/src/apps/kuaiai/services`（tools 适配层）、manifest `ai_tools`。
- Priority: P1（S12）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D5、SC-D7、SC-D12；设计 26 §4、§5；前置 spec 189、190。

### Business Goal

质量工程师能问“近 7 天一次合格率多少、哪道工序最差”“主要缺陷类型是什么”，配合质量异常与不合格检验记录做归因，所有数字来自现有统计口径。

### Scope

In scope:

| Tool | 视图/参数 | 底层 service（已读签名） | 权限码 |
| --- | --- | --- | --- |
| `analyze_first_pass_yield` | `view=summary\|operations\|trend`；`date_start?`、`date_end?`、`days?(1..31，trend 用)`、`limit≤20` | `FirstPassYieldService.get_summary` / `get_operation_breakdown` / `get_daily_trend` | `kuaizhizao:production-execution-reports-first-pass-yield:read` |
| `analyze_defect_pareto` | `material_id?`、`date_start?`、`date_end?` | `ReportService.get_quality_report(tenant_id, "defect-pareto-analysis", …)` | `kuaizhizao:quality-management-reports-defect-pareto-analysis:read` |

- 三个 FPY 视图同属一个权限码，按 SC-D7 可同 Tool 分视图；帕累托权限码不同，独立 Tool。
- 数据范围：与对应报表页 API 同口径。T1 读两个报表路由：路由对结果补了用户数据范围则 Tool 同样补；路由未补则 Tool 不额外收紧也不放宽，并在 §4 记录该事实。

Out of scope:

- 按检验类型查询检验单（S15，P2，按各检验单权限码另立）。
- SPC（P2）。

### Acceptance Criteria

1. `analyze_first_pass_yield` 三视图输出与报表页同参数下数值一致（以同一 service 调用为准）。
2. `analyze_defect_pareto` 输出缺陷类型、数量、占比、累计占比（若 service 只返回明细，则在适配层按缺陷类型聚合并在 §4 说明口径）。
3. 日期参数非法返回固定错误文案；`view` 非闭集值返回固定错误文案。
4. 空结果、异常与既有 Tool 口径一致。
5. 两个 Tool 登记于 manifest（`label`、`kind=read`、权限码）。

### Rules and Constraints

Tenant isolation:

- 所有调用传 `ctx.tenant_id`。

Security and masking:

- 一 Tool 一权限码；不输出员工个人绩效排名（`get_worker_breakdown` 不接入）。

Audit and lineage:

- 沿用 Tool 级审计。

AI/rule-engine rules:

- 合格率、占比由 service 或确定性聚合得出，LLM 只解读。

Database rules:

- 无表结构变更。

  - `FirstPassYieldService.get_summary(tenant_id, *, date_start, date_end, worker_id=None, approved_only=False)` → `{first_pass_qualified_quantity, first_pass_reported_quantity, first_pass_yield_rate, qualification_rate}`（`first_pass_yield_service.py:121-144`）。
  - `get_operation_breakdown(tenant_id, *, date_start, date_end, approved_only, limit=10)` → 行 `{operation_name, count, reported_quantity, qualified_quantity, unqualified_quantity, qualification_rate, first_pass_*}`，service 内按 count 降序（`:146-170`）。
  - `get_daily_trend(tenant_id, *, days=7, end_at=None, approved_only=False)` → 每日 `{date, qualification_rate, first_pass_yield_rate}`（`:227-283`）。
  - `get_worker_breakdown` 存在但按 spec §1 不接入（不输出员工绩效排名）。
  - 数据范围（T1 路由事实）：`/production` 报表路由 `get_production_report`（`reports.py:699-756`）与 `/quality` 路由 `get_quality_report`（`:517-564`）均**不传** `current_user`，service 签名亦无该参 → 报表页无用户数据范围，Tool 不额外收紧也不放宽。
  - 帕累托：`get_quality_report(tenant_id, "defect-pareto-analysis", date_start, date_end, material_id)` → `{data, success}`，`data` 为**明细**（`DefectRecord` 最近 100 条，`-created_at`；`report_service.py:4460-4475`），非聚合 → 适配层按 `defect_type` 聚合 `defect_quantity`、算占比/累计占比（AC2 允许确定性聚合），摘要注明样本量与 100 条上限。
  - 日期口径：既有 Tool 惯例（`scene_tools.py:410-417`）start→日初、end→日末含界；路由裸 `strptime("%Y-%m-%d")` 零点解析（不含当天），Tool 采用含界口径（spec §2 既定），故 Tool 的 date_end 语义比路由更宽（含当天全部记录）。
