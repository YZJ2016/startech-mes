### Business Goal

租户能维护产品物模型，并按产品批量建 IoT 设备、套上点位。设备超时离线时产生告警。数值点位的趋势只在租户自己配好 InfluxDB 时可用；没配则趋势不启用，150 的快照和设备状态写回照常。

### Scope

In scope:

- 产品物模型用已有表 `apps_kuaiiot_products`（迁移 `524_20260807170000_kuaiiot_wave5_lite_platform.py`）。点位模板在 `tags`（JSONB，默认 `[]`）。`(tenant_id, code)` 唯一。本切片只用 `tags`。`events`、`functions` 两列在迁移 525，留给 154。
- 按产品批量建设备是本切片要补的行为。设备行写已有 `apps_kuaiiot_devices`，并填迁移 524 已加的 `product_id`。点位从产品 `tags` 套到 `tag_definitions`。一批不超过路线图已写的 100 台。每台凭据可轮换，响应与日志不回显凭据。设备主数据仍只读 `apps_kuaizhizao_equipment`，批量创建的是 IoT 设备行，不是第二套星制造台账。
- 离线告警用 `apps_kuaiiot_alert_rules.rule_type`（迁移 524 已有该列，默认 `threshold`）。`rule_type=offline` 只写在规则表上，不要加到 `alerts`，也不新加列。只针对曾经在线、之后被 152 把 `is_online` 写成假的设备（`last_seen_at` 已有值，且超过 152 的 5 分钟无入站）。从未成功入站、`is_online` 仍为迁移 519 默认假、`last_seen_at` 为空的设备不产生离线告警。不把阈值规则改成离线规则。
- 插入时，无默认值的 NOT NULL 这样填。规则表 `tag_key`、`operator` 不能空：需求与设计没有单独的在线点位名，触发条件用绑定设备的 `is_online`，`tag_key` 填固定字面 `is_online`。`operator` 在迁移 521 是 `VARCHAR(10)` 自由字符串，不是枚举，填 `eq`，比较值 false，记在可空的 `threshold_text`（字面 `false`），不写入 `threshold_number`。告警表仍填 `device_id`（该 IoT 设备）、`tag_key`（同一字面 `is_online`）、`severity`（抄规则行，规则表该列默认 `warning`，告警表无默认值）、`message`（写明该设备已被 152 标成离线）、`triggered_at`（本次离线判定时间）。`rule_id` 指向这条 offline 规则。不要照搬 154 的空 `rule_id`：迁移 525 虽对 `alerts.rule_id` DROP NOT NULL，那是事件告警。
- 趋势只认租户自建 InfluxDB 2.x OSS（KIO-D8）。配置行用已有 `core_integration_configs`（模型 `core.models.integration_config.IntegrationConfig`）：`code` 为 `kuaiiot_tsdb`，`type` 为 `influxdb`，`is_active` 为真。地址、组织、bucket、鉴权凭据放在该行 `config` 里。日志、错误响应和文档不回显这些值。
- 未找到该集成行，或行未启用时，趋势不启用：接口明确不可用，不返回一条空序列来冒充历史。不查询 `apps_kuaiiot_tag_history`，不向该表插入采样，不用它做降采样。此时 150 的 `tag_snapshots` 与 `data_source=sensor` 写回仍然可用。
- 已配置时，趋势只画数值点位。写入与查询都走该租户自己的 InfluxDB。不把 Influx 做成平台内置库。

Out of scope:

- 产品上的 `events` / `functions`、指令、分组、消息追踪（154）
- `equipment-ops-feed` 与 OEE（155）
- MQTT 订阅、ThingsBoard、JetLinks；内置 MQTT Broker
- OPC UA / S7 可执行采集

- 合规说明里「未配置时历史接口返回空列表」。本切片按 KIO-D8 做成趋势不启用，不做成空历史

### Acceptance Criteria

1. 能写入本租户 `apps_kuaiiot_products`。按产品一批创建的 IoT 设备不超过 100，且 `product_id` 指向该产品，点位来自 `tags`。超过 100 拒绝整批。不新增 `apps_kuaizhizao_equipment` 行。
2. `rule_type=offline` 的规则只在设备曾经在线、之后被 152 标成离线时产生 `alerts`，且 `rule_id` 指向该规则。从未成功入站、默认仍为假的设备不产生。阈值规则行为仍按 151。
3. 本租户没有启用的 `code=kuaiiot_tsdb` 集成时，趋势不可用。`tag_snapshots` 仍可更新，监控写回仍按 150。`tag_history` 行数不增加。
4. 本租户启用了该集成时，数值点位能写入并查出一段趋势。凭据和地址不出现在日志与错误文案里。其它租户的集成行不能被用来查询。
5. 无租户上下文不读 `apps_kuaiiot_products`，不写 Influx。

### Rules and Constraints

Tenant isolation:

- 产品、批量设备、离线规则、集成配置都带 `tenant_id`。趋势读写只用本租户的 `kuaiiot_tsdb` 行。

Security and masking:

- Influx 鉴权凭据只放在 `core_integration_configs.config`。不写入仓库、不写进可被日志打出的错误信息。
- 批量创建返回的设备凭据只在创建当时交给操作者，随后接口不再回显。

Audit and lineage:

- 产品表在迁移 524 已含 `created_by` 等审计列。沿用，不改文件名。

AI/rule-engine rules:

- 离线告警只判断 152 把曾经在线的设备写成离线的结果。默认仍为假、从未成功入站的设备不算。不另做规则引擎。

Database rules:

- 不新造产品表。不改 519、524。不给 `alerts` 加 `rule_type`，离线告警的 `rule_id` 不留空。
- `tag_history` 保持不动，不作为趋势数据源。

### 依赖顺序

- 依赖 150 的快照与写回，以及 152 的离线判定（5 分钟无上报）。
- 不依赖 154、155。
- 不改 145–149。

## 2. Plan

### Implementation Approach

1. 产品 CRUD 落在 `apps_kuaiiot_products.tags`。批量建设备写 `devices.product_id` 并套点位。
2. 离线规则只读 152 已把曾经在线的设备写成 `is_online` 假的结果，按上面的 NOT NULL 填法写 `alerts`。
3. 趋势客户端只在本租户 Influx 集成启用时工作。未启用则拒绝趋势，快照路径不经过 Influx。

### Affected Modules

- `riveredge-backend/src/apps/kuaiiot/` 云侧（本切片之前没有产品服务与趋势客户端）
- 只读：`core.models.integration_config.IntegrationConfig`，表 `core_integration_configs`
- 前端槽位内补产品、批量建设备，以及「未配置则不提供趋势」的展示
- `tests/apps/kuaiiot/test_wave5_lite_platform.py` 引用的 `ProductService` 等不在槽位中，不是实现

### Public Contracts

- 本切片要补产品与批量创建设备、趋势查询。仓内没有这些路由。
- 已存在、本切片读取而不改表结构：`core_integration_configs`。

### Persistence Changes

- 无新表。写入 `products`、`devices.product_id`、`tag_definitions`、`alert_rules.rule_type`、`alerts`。
- 趋势数据在租户自建 InfluxDB，不在 PostgreSQL 追加采样。

### Transaction Boundaries

- 一批设备要么全部写入，要么整批拒绝。趋势查询不写快照，也不写 `tag_history`。

### Risks

- 用空列表表示「没有历史」会被当成趋势已经启用。未配置必须是不可用。
- 批量创建若写入星制造设备表，就变成第二套台账。

### Verification Strategy
