### Business Goal

管理端已登录用户在内嵌页配置模型并 SSE 对话。无第二套登录。交互对照 `ruoyi-web`，实现用现有 Element Plus。

### Scope

In scope:

- `src/api/ai/model.js`、`session.js`、`chat.js`
- `src/views/ai/model/index.vue`、`src/views/ai/chat/index.vue`
- 全宽对话路由（弱化 tagsView：可用 `meta` 隐藏侧栏或内容撑满，实现随现有 layout 习惯）
- SSE：`fetch` + Bearer（与 `request.js` 同一 token 读取方式），不引入 `hook-fetch`
- 菜单 SQL 叶子：模型管理、对话
- 模型表单：密钥只写不回填

Out of scope:

- 知识库页（53 可补）
- `vue-element-plus-x` / UnoCSS / TS 化
- 改 `frontend/` Vue2
- 登录弹窗、扫码、注册、应用市场
- 升级 Vue/Vite/Element Plus；提交 lockfile

### Acceptance Criteria

- `npm run build:prod` 成功（在 `startech-mes-front`，依赖已装的前提）
- 源码无 `hook-fetch`、`vue-element-plus-x`、硬编码生产地址
- 未许可用户 `getRouters` 无 `/ai/**`（依赖 49 许可裁剪）
- 对话页无「未登录可聊」分支

### Rules and Constraints

Tenant isolation:

- 不传租户头；依赖已有 JWT

Security and masking:

- 前端不存 apiKey；不把密钥写进 localStorage
- 不把向量库或模型密钥放进 `.env` 示例真值

Audit and lineage:

- 菜单增量 SQL，不改历史菜单脚本原地大改（可追加）

AI/rule-engine rules:

- 只消费 50/51 契约

Database rules:

- 无新业务表（仅菜单/权限）

## 2. Plan

### Implementation Approach

- API 封装对齐现有 `src/api` 风格（js + request）
- 对话页结构参考 ruoyi-web：左会话、中气泡、上模型下拉；组件自写

### Affected Modules

- `startech-mes-front/src/api/ai/**`、`src/views/ai/**`
- 后端菜单 SQL（`ktg-system` 数据，不是 Java 逻辑）

### Public Contracts

- 只消费 `/ai/model`、`/ai/session`、`/ai/chat/send`
- 上传仍走既有 MinIO 组件（本页可不上传）

### Persistence Changes

- `sys_menu` / 角色授权种子（追加）；`module_code=ai`

### Transaction Boundaries

- 无

### Risks

- 为 SSE 另写一套 axios 实例丢掉 401 处理
- 把 ruoyi-web 整页 TS/UnoCSS 贴进来
- 菜单挂到 `platform` 前缀导致工厂永远看不见，或挂错被 F3 剥掉

### Verification Strategy

- `npm run build:prod`
- 静态审查：无新 UI 套件、无游客分支
- 浏览器点选属实现阶段；本 spec 落盘不声称 UI 已验
