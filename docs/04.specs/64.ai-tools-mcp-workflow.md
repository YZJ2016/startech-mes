### Business Goal

当期平台轨道在 Agent（A25）之上再纳入三类能力：**受控写业务 Tools（方案 B）**、**白名单 MCP**、**已登录工作流**。写操作必须走现有 MES service + JWT 权限，不能让模型直连业务库或执行任意 SQL。MCP 与工作流必须登录、带租户；禁止匿名 `/workflow/run`，禁止搬 ruoyi-ai 的 SQL MCP 与 `[NODE_CHUNK_*]` 帧。

### Scope

In scope:

- 产品决策 **A26**：Tools 方案 **B**。白名单 Tool 可调本租户已有业务 service 做受控写（如报工、工单状态变更）。每条 Tool 仍须当前 JWT、`TenantContext`、原 `@PreAuthorize` 权限字。禁止客户端传 `tenantId`
- 产品决策 **A27**：白名单 MCP。可作为 Tool 后端；配置按租户加密落库（主密钥仍 `${AI_MODEL_CIPHER_KEY:}`，不复用 JDBC 密钥）。默认不开放任意远程 MCP。连接与调用须登录 + 本租户
- 产品决策 **A28**：已登录工作流。多步编排给已登录管理端用户；HTTP 前缀仍 `/ai/**`（精确 path 留给代码单元）。禁止匿名 `/run`。SSE 自定，不兼容 ruoyi-ai MCP / `[NODE_CHUNK_*]`（A17 仍有效）
- 修订 A7：红线改为「禁止直连库 / 禁止任意 SQL」，不再写「禁止任何 SQL Tool」。所谓 SQL 工具 = 白名单 service 调用，不是 JDBC/`execute_sql_query`
- 修订 A22：49–56 仍不回改；短剧 / Coding Harness / 匿名 `/run` / 内置 SQL MCP **仍不做**。工作流与 MCP **改由 A27/A28 进当期**，不塞进 49–56 或 63
- 文档同步：缺口 03、设计 06、总控 48、单元 61/62/63 的「永不做 MCP/工作流/SQL」措辞改为「不在该单元；见本文件」

### Rules and Constraints

Tenant isolation:

- Tool / MCP / 工作流节点只信 JWT / `TenantContext`；禁止请求体传 `tenantId`
- 业务 id（工单、报工、知识库、MCP server id）必须再查本租户，跨租户 404/403 且不调上游、不跑 Tool
- 并行 Tool、MCP 调用、工作流节点线程拷贝 `TenantContext`（I-A4）；空上下文失败关闭

Security and masking:

- `/ai/**` 必须登录；Agent / MCP / 工作流口不进 `MesPermitAllProvider`
- 写操作不得绕过原业务权限字；Agent 不能因为「是 Tool」就提权
- 日志、SSE、异常不打印 apiKey、MCP token、cipher、JDBC
- MCP 凭证加密落库；列表/options 不回明文（对齐 A20）

Audit and lineage:

- 本单元无表。后续代码单元若需 `ai_mcp_*` / `ai_workflow_*`，必须 `tenant_id` + include + 专库 catalog，新增量 SQL，不改历史脚本
- 受控写须能追到用户、租户、Tool 名、业务主键；审计不记密钥与大结果集明文口令

AI/rule-engine rules:

- A7：禁止 JDBC、禁止 `execute_sql_query` / `query_all_tables`、禁止 SQL MCP 跑任意语句
- A26：写 = 调用 `ktg-mes`（或既有）service，例如报工/工单状态；第一批白名单在代码单元列死，不开放「任意 Mapper」
- A27：MCP 白名单；`langchain4j-mcp` 可以，禁止借机上 A2A / agentic 全家桶与匿名端点
- A28：工作流必须登录；不搬 ruoyi-ai `/workflow/run` 与 `[NODE_CHUNK_*]`
- 凭证仍走 A24 `(tenantId, modelId)`；禁止 yml 全局 `ChatModel`

Database rules:

- 根键仍 `ruoyi:`；MCP/工作流凭证不进 yml 明文
- 无本单元 DDL
