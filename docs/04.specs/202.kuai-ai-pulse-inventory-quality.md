# KU-AI Pulse：库存与质量 detector

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施。

## 1. Spec

### Capability

- Name: 接入 `InventoryAlertDetector`、`QualityExceptionDetector`，替换 inventory、quality 两个领域的 `not_connected`。
- Module: `riveredge-backend/src/apps/kuaiai/services/pulse/{inventory,quality,registry}.py`、`riveredge-frontend/src/apps/kuaiai/pages/pulse`（跳转按钮文案）。
- Priority: P1。
- Related requirement/design documents: 需求 25 §4.5；设计 26 §7；设计 24 §6；spec 182（框架）、187（批次扫描规则）。

### Business Goal

`/pulse` 与 `query_pulse_signals` 能看到当前未处理的库存预警与质量异常，严重度来自业务单据本身的级别，可一键跳回业务页处理。

### Scope

In scope:

| detector | 事实来源（已读） | 领域读权限 | 候选条件 |
| --- | --- | --- | --- |
| `InventoryAlertDetector`（domain=inventory） | `InventoryAlert` 记录，经 `InventoryAlertService` 既有查询口径 | `kuaizhizao:warehouse-management-inventory-alert:read` | 未处理状态的预警（状态闭集 T1 从模型读取） |
| `QualityExceptionDetector`（domain=quality） | `QualityException` 记录，经 `ExceptionService.list_quality_exceptions` 口径 | `kuaizhizao:production-execution-quality-exceptions:read` | 未关闭状态的质量异常 |

- 严重度/优先级映射：由预警 `alert_level`、质量异常 `severity` 的实际枚举决定，T1 形成映射矩阵并写入本 spec；不臆造枚举值。
- `rule_code`：`inventory_alert`、`quality_exception`；`resource_type/resource_id` 指向预警/异常记录。
- `route` 只用服务端白名单：质量异常页 `/apps/kuaizhizao/production-execution/quality-exceptions`（已在 `SCENE_ROUTE_PERMISSIONS`）；库存预警页路径 T1 从 kuaizhizao manifest 取。
- 按 spec 187 规则以固定批次扫描完整候选集，summary 与领域 count 为真实总数。
- 数据范围：detector 内用 `pulse.base.apply_scope`；资源键 T1 从 manifest 确定。

Out of scope:

- 设备领域（spec 203）。
- 处理预警/关闭异常。

### Acceptance Criteria

1. 两领域不再返回 `not_connected`；无权限返回 `permission_denied` 且不泄露数量。
2. 已处理/已关闭记录不出现；同一记录不重复。
3. 严重度映射与 T1 矩阵一致，有逐值测试。
4. 超过一个批次的候选集，summary、领域 count、分页结果准确。
5. 单个 detector 超时或异常只影响本领域，`complete=false`。
6. 卡片跳转按钮文案（“查看库存预警”“查看质量异常”）仅加 zh-CN。

### Rules and Constraints

Tenant isolation:

- 所有查询带 `ctx.tenant_id`。

Security and masking:

- `fact` 只含物料/单号/数量/级别，不含处理人联系方式或内部路径。

Audit and lineage:

- 只读，不写审计。

AI/rule-engine rules:

- 判定确定性，LLM 不参与（SC-D5）。

Database rules:

- 无表结构变更；不新增快照表。

## 2. Plan

### Implementation Approach

- 参照 `pulse/production.py`、`pulse/sales.py` 的结构与批次扫描实现；在 `registry.DETECTORS` 注册两个新 detector。
- 前端 Pulse 页按 `resource_type` 显示跳转文案，路由仍用服务端 `route`。

### Affected Modules

- Create: `apps/kuaiai/services/pulse/inventory.py`、`pulse/quality.py`。
- Modify: `pulse/registry.py`、前端 `pages/pulse/index.tsx`、`locales/zh-CN.ts`。
- Test: `tests/apps/kuaiai/test_spec202_pulse_inventory_quality.py`；回归 `test_spec182_pulse.py`。

### Public Contracts

- Pulse 响应结构不变；inventory、quality 领域开始产出 items。

### Persistence Changes

- 无。

### Transaction Boundaries

- 只读；每 detector 独立超时。

### Risks

- 预警记录可能大量堆积未处理：批次扫描 + 硬上限，测试记录 1000+ 候选耗时。

### Verification Strategy

- 单测：状态过滤、严重度矩阵、去重、权限、数据范围、批次总数、超时局部失败。
