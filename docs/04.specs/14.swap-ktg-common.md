# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 用 springboot2 内容替换 `ktg-common`，留下 `MesPermitAllProvider`
- Module: `ktg-common`（接线例外可改 `ktg-mes/pom.xml`）
- Priority: P0
- Related requirement/design documents:
  - `docs/04.specs/11.backend-shell-swap-program.md`
  - `docs/04.specs/08.migrate-security-permit-all.md`
  - `docs/04.specs/09.platform-purity-gate.md` 豁免：接口在 common
  - `docs/04.specs/10.backend-extract-review.md` 第 7 节第 1 条

### Business Goal

平台工具层换成若依 3.9.2 springboot2 的 `ruoyi-common` 内容（含 `@Anonymous`、fastjson2、yauaa 等上游增量），但 **MES 匿名清单接口不丢**：覆盖后必须把 `MesPermitAllProvider` 放回 `com.ktg.common.security`。721 个 mes 业务文件不是换壳对象。

### Scope

In scope:

- 对照：`RuoYi-Vue-springboot2/ruoyi-common/`（commit `913524b1525a0e374774afbb54c452d8f68a5a8f`）
- 覆盖 nested `backend/ktg-common/` 的 src 与模块 pom
- 机械替换 `com.ruoyi` → `com.ktg`；`artifactId` 保持 `ktg-common`；parent 保持 `com.ktg:ktg`
- **覆盖后恢复** nested 现有文件：`backend/ktg-common/src/main/java/com/ktg/common/security/MesPermitAllProvider.java`（接口正文与抽出后一致，仅此 MES 豁免类型）
- 根 POM：允许对齐 springboot2 的 `spring-boot.version=2.5.15`、`fastjson2`、`yauaa` 等 **Java 8 / Boot 2.5** 属性；**dependencyManagement 须继续能解析 `com.alibaba:fastjson`（1.x）**，或给 `ktg-mes/pom.xml` 显式声明 fastjson1
- 检索 mes 是否仍 `import com.alibaba.fastjson`（抽出时至少 `MessageProvider`、`TokenController`、`WebSocketServer`、`OssController`、`QcIpqcLineController`）：有则 **只改 pom**，不改这 721 个 Java 的 import

Out of scope:

- 改 721 个 mes Java 去迁 fastjson2
- 删除或改名 `MesPermitAllProvider`；不要改成第二套 Security
- 把 `RuoYiConfig` 前缀改成 `ruoyi`（那是 `17`；本块若对照源已是 `prefix = "ruoyi"`，**允许随 common 换入**，但 admin yml 根键必须在 `17` 同步，本块不要去改 admin yml）
- Java 17 / Boot 3/4 / jakarta / 模块改名
- `SecurityConfig`、公告 list、uploadMinio、手机号登录（`15`–`17`）

### Acceptance Criteria

- `MesPermitAllProvider` 仍在 `com.ktg.common.security`，方法仍为 `String[] getPermitAllAntMatchers()`
- `ktg-common` 无 `com.ruoyi`；无 `import com.ktg.mes`
- `UserConstants` 仍无 MES 业务常量（`01`/`09` 不得回潮）
- `FileUploadUtils` 无 Minio（`04`/`09`）
- `ktg-mes` 与 `ktg-admin` 在 JDK 8 下能与新 common **编译**（mes 业务源码无本单元功能 diff，pom 例外允许）
- 未把密钥写入新文件

### Rules and Constraints

Tenant isolation:

- 不涉及

Security and masking:

- 不扩大匿名面；本块只保留接口，不改路径列表（列表在 mes 实现）

Audit and lineage:

- 覆盖前把 `MesPermitAllProvider.java` 拷到工作区外再拷回，避免丢失

AI/rule-engine rules:

- 不涉及

Database rules:

- 无

## 2. Plan

### Implementation Approach

1. `13` 编译通过后再开始
2. 单独保存 `MesPermitAllProvider.java`
3. 整树覆盖 common；机械替换；pom GAV 留 ktg
4. 放回 `MesPermitAllProvider`
5. 根 POM：按需 2.5.12→2.5.15；增加 fastjson2 / yauaa；**不要删掉 mes 仍需要的 fastjson1 解析能力**
6. 若 `ktg-mes` 编译缺 `com.alibaba.fastjson`，在 `ktg-mes/pom.xml` 增加 `com.alibaba:fastjson`（版本用现网已在用的管理版本或 1.2.x 线，不在文档写仓库外私服地址）
7. 不要把 hutool/minio/ureport/barcode 加回 common（这些已在 mes）

对照 common 已去掉 `commons-fileupload`、改用 yauaa。平台侧跟对照走。mes 若仍直接依赖 fileupload，同样只补 mes pom，不改 721 文件。

- `ktg-common`（主）
- `backend/pom.xml`（属性/dependencyManagement）
- `ktg-mes/pom.xml`（仅当传递依赖断裂）

### Public Contracts

- `MesPermitAllProvider` 作为 framework 编译期依赖，签名不变
- HTTP 不变

### Persistence Changes

- 无

### Transaction Boundaries

- 无
