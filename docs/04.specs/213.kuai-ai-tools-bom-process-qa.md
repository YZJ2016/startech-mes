从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已完成。

## 1. Spec

### Capability

- Name: 新增只读 Tool `query_engineering_bom`、`query_process_route`（后者为 spec 200 `query_process_routes` 的 P2 补充视图时按实际目录并轨，T1 核对是否已存在同名 Tool，避免重复登记）。
- Module: `riveredge-backend/src/apps/kuaiai/services`（tools 适配层）、manifest `ai_tools`。
- Priority: P2（S24 BOM/工艺问答）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D5、SC-D7；设计 26 §4、§5.2；前置 spec 189、190、200、212（where-used）。

### Business Goal

工艺/生产问“产品 P-3301 的 BOM 有哪些层级和替代料”“这道工序的工艺参数是什么”，助手基于工程 BOM 与工艺路线的真实结构回答。

### Scope

In scope:

| Tool | 参数 | 底层 service | 权限码 |
| --- | --- | --- | --- |
| `query_engineering_bom` | `material_id` 或 `bom_id`（二选一必填）、`view=tree\|flat\|substitutes`、`level≤5` | master_data 工程 BOM service（T1 核对签名） | `master-data:process:engineering-bom:read` |
| `query_process_route`（若 spec 200 已建则本单元只补视图） | `material_id` 或 `route_id`、`view=nodes\|parameters` | master_data 工艺路线 service（spec 200 已用） | `master-data:process:process-route:read`（T1 核对） |

- BOM 树形输出按层级缩进列出（物料编码、名称、用量、单位、损耗率）；节点超过上限时截断并注明总节点数。
- `view=substitutes` 输出替代料组明细；无替代关系时如实返回空。
- 数据范围：service 不接收 `current_user` 的，适配层补行级范围；物料主数据一般全厂可见，范围键 T1 定。

Out of scope:

- BOM/工艺的新建、变更、版本切换（写操作走 ECN 流程，见 spec 212）。
- 图纸文件正文。

### Acceptance Criteria

1. BOM 树输出与工程 BOM 页结构一致；层级/截断正确。
2. `query_process_route` 参数视图输出工序参数（如适用）；若 spec 200 已建同名 Tool，本单元只做增量，不重复登记 manifest 条目。
3. 非法 `view`/`level` 返回固定错误文案；物料不存在按“不存在”回复。
4. 新增 Tool 登记于 manifest（`label`、`kind=read`）。

### Rules and Constraints

Tenant isolation:

- 传 `ctx.tenant_id`。

Security and masking:

- 不输出供应商进价、客户专属信息。

Audit and lineage:

- 沿用 Tool 级审计。

AI/rule-engine rules:

- 结构、用量、参数来自业务记录（SC-D5）。

Database rules:

- 无表结构变更。

### 场景模板（Y3=a）

本单元交付时同步登记场景模板 `bom-process`（BOM 工艺助手）：预置档案 `enabled_tools` 为本单元 Tool 集合，停用 + 空授权（Y4=a）；模板 key 即能力矩阵场景卡，默认绑定同 key 预置实例（spec 191，Y1/Y2=a）。system_prompt 只引用本单元 Tool，插画按 spec 201 T2 约定。

## 4. Verification Record

T1 事实表（2026-10-23 核对，以代码为准）：

- **spec 200 `query_process_routes` 复用结论**：既有签名 `keyword?, material_id?, limit`——`material_id` 反查（物料级 `process_route_id`→分组兜底）与工序节点序列已覆盖本单元 `material_id` + `view=nodes` 需求，参数面重合。T3 **只补 `view` 参数与 `parameters` 视图**，不新建 `query_process_route`、不重复登记 manifest 条目。`route_id` 直查未补：按路线编码经 `keyword` 已可命中，记为偏差见下。
- 工艺路线权限码实测为 `master-data:process:route:read`（既有 manifest 登记），非 spec 表中 `process-route:read`，以代码为准。
- 工序参数数据源：`MaterialProductProcessService.get_for_material(tenant_id, material.uuid)`（`@staticmethod`）→ `MaterialProductProcessResponse.lines[]`（`ProductProcessLineSchema`），与产品工艺页同源的「路线模板行+物料产品工艺存储行」合并口径；字段含 `standard_time`/`standard_time_qty`（秒/件基准）、`setup_time`、`reporting_type`、`is_node_operation`、`is_outsourced`+`outsource_lead_time_days`+`outsource_supplier_name`、`over_report_mode/value`、`piece_rate`。`piece_rate` 属工资敏感不输出。
- `MaterialService.generate_bom_hierarchy(tenant_id, material_id, version=None)` → dict（`material_code/name`、`version`、嵌套 `items[]`，item 含 `component_id/component_code/component_name/quantity/unit/waste_rate/level(0起)/is_alternative/alternative_group_id/priority/is_configurable/children`），与工程 BOM 页/打印同源、过滤 `is_active & !is_obsolete`；`bom_id` 入参经 `BOM.filter` 行定位 `material_id`+`version` 后走同一路径。
- 范围键 T1 定：物料/子件行级套 `master-data:material`（material:bom reference_resources 无独立 data_scope_key，物料即范围键）；不可见节点连同子树只计数（与 spec 208 X3=a 同口径）。
- `MaterialService.list_bom_where_used(tenant_id, component_id, recursive, include_obsolete, top_level_only)` → `{items,total}`，父件行含 `material_id/material_code/material_name/bom_code/version/quantity/unit/approval_status/path`。

Behavior delivered:
