### Business Goal

当期平台轨道 **包含** LangChain4j Agent / AiService（白名单 Tools），与对话共用 A24 凭证工厂。每个租户出站仍用自己的 `ai_model` Key。**不**为每个租户启动时各造一个 Agent；**不**把「只传 modelName」当成换 Key。Agent **不能**直连 MES 业务库。

### Scope

In scope:

- 产品决策：Agent/AiService **进入当期平台轨道**（A25）。49–56 已落地代码不回改；新能力走后续改写单元
- 生命周期与 61 对齐：
  - **一份** Java 接口 / Agent 拓扑 / `@Tool` 类（Spring 单例）
  - **凭证**仍按 `(tenantId, modelId)` 从 A24 工厂取 `ChatModel`
  - AiService：缓存代理键同样是 `(tenantId, modelId)`，或唯一代理内部路由到该工厂
  - Agent：优先 `chatModel(Function<AgenticScope, ChatModel>)`（或等价）在执行时向 A24 get；禁止 yml 全局模型
  - Memory：`ChatMemoryProvider`；`@MemoryId` 必须能区分 `tenantId + userId + sessionId`，禁止全进程一份 `ChatMemory`
  - RAG/Retriever：检索时带当前 `tenant_id`，禁止构造期写死他租 kid
- Tools：63 第一批只读/白名单知识检索；方法内只信 `TenantContext` / `LoginUser`；线程必须带租户（I-A4）。受控写（B）不在本文件实现，见 64 / A26
- 文档同步：设计 06、缺口 03、总控 48、61

Out of scope:

- 本单元改 Java/SQL/Vue；不改 Phase 1 `POST /ai/chat/send` 冻结信封（57–59 仍无 Agent）
- 内置 `execute_sql_query` / `query_all_tables` / 模型直连 MES 库（A7 仍有效）
- 受控写 Tools / 白名单 MCP / 已登录工作流（见 64；**不**在本单元或 63 实现）
- 匿名 `/workflow/run`、短剧、Coding Harness、独立对话端、游客
- 启动时按租户扫描并注册 Agent Bean
- 为每个租户 new 一份 Tool 实例（除非 Tool 自身持有无法共享的连接；默认共享单例 + 运行时租户）

### Acceptance Criteria

- 缺口 03 有 A25；A7 改为「禁止直连库」且不再写「Agent 不进当期」；A22 不再把 Agent 与工作流捆在一起排除
- 设计 06 决策表与 §5.2 描述「一份定义 + A24 解析模型」
- 总控 48 TOC 含本文件；48 非目标不再列 Agent

- 文档无真实主机、凭据；第 4 节不把 Agent 标成已实现

### Rules and Constraints

Tenant isolation:

- Agent 调用前与对话相同：校验 `modelId` 属当前租户，否则不 get 模型、不跑 Tool
- Tool 禁止接受客户端 `tenantId`；知识库/工单等 id 必须再查本租户
- 并行 Tool / SSE 工作线程拷贝 `TenantContext`（I-A4）

Security and masking:

- `/ai/**` 必须登录；Agent 口不进 `MesPermitAllProvider`
- 日志不打印 apiKey / Tool 入参中的密钥
- A3/A20 不变

Audit and lineage:

- 本单元无表。后续若要记 Tool 调用，另开增量，不改历史 SQL
- `@Log` 可记 Agent 发起，不记 Key

AI/rule-engine rules:

- A7：禁止直连库与任意 SQL；受控写见 A26 / 64，不在本单元
- 第一批 Tool（63）仅「检索本租户知识库」等只读；MES 业务写操作不进 63
- 不搬 ruoyi-ai 工作流帧 / 匿名 `/run`；已登录工作流见 A28 / 64
- `langchain4j-agentic` 若引入，只为 Agent 执行时解析 ChatModel；MCP 模块留给 64，不借 63 上全家桶

Database rules:

- 无新表亦可先做（Tool 走现有 `ai_*`）。若以后要 Agent 配置表，必须 `tenant_id` + include + 专库 catalog
- 根键仍 `ruoyi:`；Agent 凭证不进 yml

## 2. Plan

### Implementation Approach

文档锁定后，后续代码应与 61 同一改写波次：

1. A24 工厂先可用
2. 再挂 AiService/Agent：build 时或执行时注入该工厂取出的 `ChatModel`
3. Tool 单例 + `TenantContext`
4. 不在 `ApplicationRunner` 里为每个租户 `AiServices.builder().build()`

精确 HTTP（新 path 或扩展 `send`）在代码单元定，不得削弱现网 `POST /ai/chat/send` 的 `{content, done}` 纯对话行为。

### Affected Modules

- 文档：本文件、设计 06、缺口 03、总控 48、`61.ai-chatmodel-factory.md`
- 代码：无（后续 `ktg-ai` + 仅 Vue3）

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- Phase 1 `/ai/provider|model|session|chat` **本单元不改**
- 后续 Agent HTTP 必须登录、SSE 或同步均不得含 Key；禁止 `/system/message`

### Persistence Changes

Tables, indexes, migrations, mapper XML, and lifecycle rules:

- 无

### Transaction Boundaries

- 无。后续：Tool 写库用各自短事务，不包住整个 Agent 循环

### Risks

- `@AiService` 自动装配全局 `ChatModel`，所有工厂共用一把 Key
- Agent 按租户启动全量注册，专库租户缺失或改 Key 不生效
- Tool 捕获构造期 `tenantId`
- 把工作流/MCP/受控写一起塞进 63（那些能力见 64）

### Verification Strategy

- 本单元：静态核对 A7/A22/A25 与 06/48/61 交叉引用
- 不跑 Maven / Vue
- 后续代码：两租户两模型，Agent/Tool 出站 Authorization 各用各的 Key；跨租户 id 不调上游、不跑 Tool
