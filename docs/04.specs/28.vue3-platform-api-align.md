# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: Vue3 平台壳 API 对齐（锁屏、getInfo 密码字段、MES 公告铃铛）
- Module: `startech-mes-basic/startech-mes-front`（只读对照 `backend`）
- Priority: P0
- Related requirement/design documents:
  - 总控：`docs/04.specs/27.vue3-backend-api-align-program.md`
  - 缺口：`docs/02.requirements/01.vue3-backend-api-gaps.md`（P1–P8、M1–M3、X1）
  - 调研：`docs/03.design/03.vue3-backend-api-align-survey.md`

### Business Goal

让 Vue3 管理端壳能打换壳后的后端：启用已存在的锁屏和密码策略字段；铃铛改走 MES 公告已读；保持 MinIO 与 SSO。完成后平台冒烟可做；MES 业务页不在本单元。

### Scope

In scope:

- 恢复锁屏：`POST /unlockscreen`、`/lock` 路由、Navbar 入口、`permission.js` 已锁拦截、`lock.js` / `lock.vue` 真正调用后端
- `getInfo` 写入 `isDefaultModifyPwd`、`isPasswordExpired`、`pwdChrtype`；session `pwrChrtype` 与 `passwordRule.js` 对齐；需改密时走 3.9 壳原个人中心流程
- `src/api/system/notice.js` 删除 `listTop`/`markRead`/`markReadAll`/`readUsers`
- `HeaderNotice` 改接 `GET /system/notice/detail/message` 与 `POST /system/notice/detail`；已读用 `readStatus`/`userId1`
- 静态核对 P5–P7（MinIO 默认、`loginOuth`、`deptTree`）；平台 `src/api` 对 Controller（P8），结果回填缺口清单
- 将 `D-*` 从目录占位补成「脚本列出的 URL 差集」（只记录，不修领域页）

Out of scope:

- 改 Vue2 `frontend/`
- 改 Java、五项接线、MES 业务 URL
- 给 `SysNoticeReadService` 挂 HTTP
- 启用 OSS 为默认上传
- 实现 md/pro/wm/qc 等业务页对齐
- 提交 lockfile；升级 Vue/Vite/Element Plus
- 无环境时声称冒烟通过

### Acceptance Criteria

- 清单 P1–P8、X1、M1–M3 均为 `[x]`，或 P8 中降级项已改分类并写明原因
- M4/M5 本单元只确认路径未被改掉，正式收口留在对应 `D-*` 单元
- Vue3 源码检索无 `listTop`、`markRead`、`markReadAll`、`readUsers` 调用
- 锁屏失败不清 token；成功才解锁
- 第 4 节有静态检索摘要；冒烟逐步勾选或「未验证 + 原因」
- 无命令输出不得写构建/登录成功
- 默认无 backend Java diff

### Rules and Constraints

Tenant isolation:

- 不改数据隔离

Security and masking:

- 不在文档或日志中写口令、Token、Minio 密钥、内网地址
- 代理与 `.env` 不新增真实主机；沿用占位或环境变量
- 不扩大匿名面；`/unlockscreen` 保持需登录

Audit and lineage:

- 锁屏实现对照 RuoYi Vue3 3.9.2 壳，不自造协议
- 公告已读继续 mes 字段，不改成若依已读表

AI/rule-engine rules:

- 不涉及

Database rules:

- 不改表、不执行 SQL

## 2. Plan

### Implementation Approach

1. 用脚本从 `startech-mes-front/src/api` 与 `backend/**/*Controller.java` 抽出 URL+method，按类前缀归一后回填清单 P8 与 D-*（脚本可丢弃，不提交为产品）
2. 恢复锁屏与 `unlockscreen` API（对照 3.9.2，改掉当前「本地直接解锁」）
3. 接 `getInfo` 密码字段与 `pwrChrtype` session
4. 删 3.9 公告封装，改 `HeaderNotice`
5. 静态 grep 核对 MinIO、`loginOuth`、`deptTree`、无 `listTop`
6. 有本地后端则按冒烟表勾选；否则写未验证

### Affected Modules

- `startech-mes-front/src/api/login.js`
- `startech-mes-front/src/api/system/notice.js`
- `startech-mes-front/src/store/modules/user.js`
- `startech-mes-front/src/store/modules/lock.js`
- `startech-mes-front/src/views/lock.vue`
- `startech-mes-front/src/router/index.js`
- `startech-mes-front/src/permission.js`
- `startech-mes-front/src/layout/components/Navbar.vue`
- `startech-mes-front/src/layout/components/HeaderNotice/index.vue`
- 只读：`FileUpload`/`ImageUpload` 默认 action、`loginOuth` 路由、`passwordRule.js`
- 缺口清单回填：外层 `docs/02.requirements/01.vue3-backend-api-gaps.md`

### Public Contracts

- `POST /unlockscreen` JSON `{ "password": "..." }`
- `GET /getInfo` 使用 `pwdChrtype`、`isDefaultModifyPwd`、`isPasswordExpired`（额外字段，不删 `user/roles/permissions`）
- 铃铛：`GET /system/notice/detail/message`、`POST /system/notice/detail`
- 上传默认：`POST /common/uploadMinio`
- SSO：`GET /loginOuth`
- 仍为 Bearer JWT 与 `code/msg/data`

### Persistence Changes

- 无库表变更。锁屏状态仅前端 localStorage（与 3.9.2 壳一致）。

### Transaction Boundaries

- 无

### Risks

- 打开改密策略后测试账号被强制改密
- MES 铃铛列表形态与 `listTop` 不同
- 静态脚本误报 MES CRUD
- 无 MinIO/SSO 环境时第 5、6 条冒烟无法做完

### Verification Strategy

静态必做。运行时按第 3 节冒烟表；缺环境则 Known gaps 写明。检索根目录：`startech-mes-basic/startech-mes-front` 与 `startech-mes-basic/backend`。

| Task | Description | Output | Verification |
| ---- | ----------- | ------ | ------------ |
| T1 | 静态抽出平台+MES URL 差集，回填 P8 与 D-* | 更新后的缺口清单 | 归一规则见调研；无主机/凭据 |

冒烟表（有本地后端才执行）：

1. 验证码 + 登录，获得 JWT
2. getInfo 含密码字段；若策略开启则进入改密流程
3. 锁定 → `/lock` → 正确密码解锁；错误密码仍锁定
4. 铃铛列表与已读；Network 无 `listTop`/`markRead`
5. 上传请求打到 `/common/uploadMinio`（对象存储成败单独记录）
6. `/loginOuth` 路由可开（无 code 则只做静态存在性）
