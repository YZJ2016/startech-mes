### Business Goal

库存过账与业财/成本副作用同一成败：禁止「库存已成功、财务异常只打日志当成功」。成品入库必须生成存货/生产成本事件（不能只记数量）。常数 30 只喂报工统计展示；缺 `estimated_wage_rate` 时该字段返回 null 并标「未配置」，其余数据照常返回。金蝶推送失败必须变成可见的未推送状态（`fail_on_error` 种子为 False 的前提下）。

### Scope

In scope:

- `finance_integration_hooks.py`（约 111–121 行）：`record_finance_accounting_event` **不得**捕获全部异常只打日志后吞掉；销售出库→应收、采购入库→应付、退货、其他入出库等同路径改为与库存事务同一成败（失败则库存回滚或等价补偿策略须可证明，禁止假装成功）
- `warehouse_service.py` 其他入库确认后 `InventoryCostService.on_other_inbound_confirmed`（约 15390–15394 行）失败不得只 `logger.warning`
- 成品入库：新增/接入存货·生产成本会计事件（今日事件集含 `SALES_DELIVERY_TO_RECEIVABLE`、`SALES_RETURN_TO_RECEIVABLE`、`PURCHASE_RECEIPT_TO_PAYABLE`、`PURCHASE_RETURN_TO_PAYABLE`、`WAREHOUSE_INBOUND`、`WAREHOUSE_OUTBOUND`，**成品入库不在其中**——本单元补上）
- 报工预估工资：`src/apps/kuaizhizao/services/reporting_service.py` 490 行 `_get_reporting_estimated_wage_rate` 与 `src/apps/kuaizhizao/api/productions/reporting.py` 122 行今日回退 `Decimal("30")`，分别喂 `get_reporting_statistics` 的 `estimated_wages` 与 `get_reporting_overview_statistics`。缺 `estimated_wage_rate` 时该字段返回 null 并带「未配置」，接口其余数据照常返回；禁止整端点报错；禁止回退 30。若同一数值被拿去当记账金额，缺配置则该笔记账失败，与库存同一成败
- 金蝶推送：`fail_on_error` 种子为 False → 失败必须落可见「未推送」态（本 spec 收口，不另开文件）
- 保留：`posting_service` 拒绝借贷不平；结账默认 `pre_close_checks`；`close_period` 的 `skip_checks` 能力保留且当前无 `skip_checks=True` 调用方——**不要**新增偷偷跳过检查的调用

### 产品规则（已确认）

1. 业财/成本失败与库存同一成败；禁止吞异常假装成功。
2. 成品入库要生成存货/生产成本事件，不能只记数量。
3. 统计字段 `estimated_wages` 缺 `estimated_wage_rate` 时返回 null 并带「未配置」，其余数据照常；禁止回退 30；禁止整端点报错。该数值若用于记账，缺配置则该笔记账失败。
4. 金蝶推送失败 → 可见未推送状态（本 spec）。
5. 借贷不平拒绝记账；结账默认预检；不新增 `skip_checks=True` 偷跑。

### Acceptance Criteria

1. 销售出库/采购入库/退货/其他入出库：财务事件写入失败时，整单确认失败或库存与账同回滚；日志可有，但**不得**仅日志后返回成功。
2. 其他入库：`on_other_inbound_confirmed` 失败与确认同一成败。
3. 成品入库成功路径必产生存货/生产成本相关会计事件（事件码实现时钉死并测）；禁止「只有库存数量」。
4. `get_reporting_statistics` 与 `get_reporting_overview_statistics`：缺 `estimated_wage_rate` 时 `estimated_wages` 为 null 并带「未配置」，响应其余字段仍返回；响应中不出现回退常数 30。若实现把该数值写入记账金额，缺配置时该笔记账失败且库存回滚。
5. 金蝶推送失败：单据/任务可见「未推送」（或等价状态），可重试；不假装已推送。
6. 借贷不平仍拒绝；`close_period` 默认预检；仓库内无新增 `skip_checks=True` 调用。
7. 依赖 140 状态与 141 幂等：业财重试不得依赖「无幂等的双过账」掩盖失败。

Security and masking:

- 财务日志禁止打印 JDBC 口令、金蝶密钥、cipher。

Audit and lineage:

- 失败须可追踪到单据 id 与事件类型；金蝶未推送态可审计。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 会计事件与库存流水同事务优先；若外部金蝶推送无法同事务，则**库存+本地会计事件**同事务，金蝶结果写本地可见状态（失败不改「业务已成功且已推送」语义）。

## 2. Plan

### Implementation Approach

1. 改 `record_finance_accounting_event`：异常向上抛（或返回失败并由调用方回滚），去掉「全捕获只打日志」。
2. 其他入库成本钩子改为失败即失败。
3. 成品入库确认接入存货/生产成本事件（对齐既有 `WAREHOUSE_*` 风格，事件名实现钉死）。
4. 两处预估工资读取缺配置时返回 null+「未配置」，去掉常数 30 回退；统计端点不因缺配置整体失败。
5. 金蝶：推送失败写未推送可见态；保持 `fail_on_error=False` 种子语义（不靠抛崩进程，靠状态可见）。
6. 回归：借贷不平拒绝、结账预检、无新 skip_checks 调用。

### Affected Modules

- `src/apps/kuaicaiwu/services/finance_integration_hooks.py`
- 其他入库确认成本调用（`src/apps/kuaizhizao/services/warehouse_service.py` 约 15390 一带；**不拆文件**）
- 成品入库确认路径（事件接入）
- `src/apps/kuaizhizao/services/reporting_service.py` 的 `_get_reporting_estimated_wage_rate` / `get_reporting_statistics`
- `src/apps/kuaizhizao/api/productions/reporting.py` 的 `_get_reporting_estimated_wage_rate` / `get_reporting_overview_statistics`
- 金蝶推送状态落点（既有集成模块内）

### Public Contracts

- 确认类 API：失败时业务错误明确（财务/成本/推送），成功意味着库存与本地会计事件一致。
- 金蝶：增加或钉死「未推送」可查询字段/状态，前端或运维可看见。

### Persistence Changes

- 若需未推送状态列/枚举，走 aerich 十四位时间戳规则；最小变更。

### Transaction Boundaries

- 理想：库存（141）+ 本地会计事件同一事务。
- 金蝶外呼：事务提交后推送；失败只更新推送态，不回写「财务事件未记」除非产品要求同单补偿——本单元最低线是**未推送可见**，且本地账与库存已同一成败。

### Risks

- 历史依赖「财务失败仍出库」的脏数据对账 → 上线说明与修复脚本不在本单元强制范围，但不得继续吞异常。
- 成品入库事件科目映射缺失 → 缺配置应失败关闭，禁止写假金额。
