## 1. Spec

### Capability

- Name: 星数采平台入站 — MQTT 订阅、ThingsBoard、JetLinks
- Module: **仅** `kuaigeyun-mes` 的应用槽位 `apps/kuaiiot`。云侧订阅客户自备 Broker，不内置 Broker。**禁止**改 `startech-mes-basic`，**禁止**把本能力写回 `docs/04.specs/150.kuaiiot-ingest-writeback.md` 至 `155.kuaiiot-report-feed.md`。
- Priority: KIO-D6。六步收口之后，不插入 KIO-W1–W6，不改 W6 的报表衔接。
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/19.kuaiiot-selfdev-gaps.md`（**KIO-D6**）
  - 设计：`docs/03.design/19.kuaiiot-selfdev-plan.md`（§3.7）

### Business Goal

云侧把客户自备 MQTT Broker 上的订阅，以及 ThingsBoard、JetLinks 上的遥测，收成与 HTTP 入站相同的一条入站。ThingsBoard 与 JetLinks 上的设备指令仍走现有创建与回执，由对应平台发出，不再经边缘心跳交给 Agent。

### Scope

In scope:

- 云侧订阅客户自备 Broker。星数采不内置 Broker。边缘 Agent 继续 HTTP 上报，不读 `publish.mode`。`publish.mode=mqtt` 只表示这条连接由云侧订阅。边缘配置里该字段的既有校验保持不变。
- MQTT、ThingsBoard、JetLinks 的遥测都收成现有 `IngestBody`（`tags`、`events`、`timestamp`、`idempotency_key`），调用现有 `IngestService.ingest`。未登记设备不入库。重复投递靠已有 `idempotency_key`。不另写快照、写回、阈值、告警；这些只发生在现有入站之内。
- 调度只用已经注册、且 workflow 文件尚不存在的两个任务，不新注册 cron：
  - `kuaiiot_mqtt_reload_tick`（`taskiq_app.py`，cron `*/2 * * * *`）每 2 分钟对齐订阅。import 目标是 `apps.kuaiiot.workflows.functions.mqtt_subscriber_workflow.run_kuaiiot_mqtt_reload`。Worker 启动时调用现有 reload 对齐一次。停止钩子保持现状：`stop_all` 是空操作，不断开 Broker。周期仍是已注册的 `kuaiiot_mqtt_reload_tick`。
  - `kuaiiot_telemetry_pull_tick`（同文件，cron `*/5 * * * *`）每 5 分钟按连接类型拉遥测。import 目标是 `apps.kuaiiot.workflows.functions.telemetry_sync_workflow.run_kuaiiot_telemetry_pull`。
- MQTT 的 topic 与 JSON 路径、ThingsBoard 与 JetLinks 的 JSON 路径都写在该连接上（`KuaiiotConnection`，表 `apps_kuaiiot_connections` 的 `config`）。字段名见下文「连接 config 字段」。不另建映射表。
- ThingsBoard / JetLinks 的指令仍由 `command_service.create_command` 只创建指令行，回执仍调用 `command_service.submit_command_result`。按连接源注册下发器。通道用已有字段 `dispatch_channel`，不新增列、不另建指令表。心跳里的 `claim_pending_commands` 只把 `edge_heartbeat` 交给 Agent。平台指令停在 `not_sent`（未发出），不得被领走。超时仍用现有 `timeout_sent_commands`（只处理已发出的 `sent`）。MQTT 连接不做指令下发。边缘 Agent 设备的领取和回执保持原样。
- 现有工程没有连接口令加密。连接口令按该连接已有的 `config` 明文保存，不新增密钥，不新增列。不进边缘配置：`EdgeConfigService` 已拒绝口令字段（`password`、`passwd`、`broker_password`、`mqtt_password`）。不进日志、URL、仓库。

Out of scope:

- 内置 Broker
- 连接健康检查（含已注册的 `kuaiiot_connection_health_tick`；本单元不实现它）
- 留存清理（含已注册的 `kuaiiot_retention_tick`；本单元不实现它）
- push-telemetry
- 启用连接时自动授予 `kuaiiot:fill:read` 或 `kuaiiot:analytics:read`。这两项保持角色管理里人工勾选
- 新注册 cron
- 新写快照、写回、阈值、告警
- 让边缘 Agent 读取 `publish.mode` 或改用 MQTT 上报
- 改 150–155，改 `startech-mes-basic`

### Acceptance Criteria

- 云侧只订阅客户自备 Broker。没有内置 Broker。边缘 Agent 仍走 HTTP 入站，不读取 `publish.mode`。`publish.mode=mqtt` 的连接由云侧订阅对齐，不改成让 Agent 自己发 MQTT。
- 三条遥测都由各自的归一化函数读该连接的 `config`，收成 `IngestBody`，然后只调用 `IngestService.ingest`。未登记设备没有新的点位行。同一 `idempotency_key` 的重复投递不重复入库。本单元没有单独的快照、写回、阈值或告警实现。
- 订阅对齐：Worker 启动时调用现有 reload 对齐一次。停止钩子保持现状：`stop_all` 是空操作，不断开 Broker。周期仍是已注册的 `kuaiiot_mqtt_reload_tick` → `run_kuaiiot_mqtt_reload`。遥测拉取只走已注册的 `kuaiiot_telemetry_pull_tick` → `run_kuaiiot_telemetry_pull`。没有新的 cron 名，不改 taskiq 表达式。`run_kuaiiot_mqtt_reload` 只按 `config.topic` 统计可对齐订阅，不连接 Broker，不读取口令。
- MQTT、ThingsBoard、JetLinks 的 config 字段名见「连接 config 字段」。ThingsBoard、JetLinks 的遥测地址见「平台地址未进入仓库」：地址未进入仓库与 spec，拉取因此为空。文档和代码都不写具体平台 URL。
- ThingsBoard / JetLinks 设备的指令由 `create_command` 创建。下发器已按连接源注册，但不得发出猜测的 HTTP 请求，指令标成平台通道并停在 `not_sent`。回执仍走 `submit_command_result`。心跳领取不把这类指令交给 Agent。超时仍由 `timeout_sent_commands` 处理已发出的指令。MQTT 连接没有指令下发。边缘 Agent 设备的 `claim_pending_commands` 与 `submit_command_result` 行为与现在相同。
- 现有工程没有连接口令加密。连接口令按该连接已有的 `config` 明文保存，不新增密钥，不新增列。边缘配置、日志、URL、仓库都没有口令。本轮不实现加密。
- 本单元不实现连接健康检查、留存清理、push-telemetry，也不在启用时写入 `kuaiiot:fill:read` 或 `kuaiiot:analytics:read`。

### Rules and Constraints

Tenant isolation:

- 订阅、拉取、入站和指令都限连接与设备所属租户。未登记设备不入库。

Security and masking:

- 口令不进边缘配置，不进日志、响应、URL、仓库。config 里若出现 `password`、`passwd`、`broker_password`、`mqtt_password`，这些键的值不读取。
- 现有工程没有连接口令加密。连接口令按该连接已有的 `config` 明文保存，不新增密钥，不新增列。
- 查找结果（2026-09-29，只看 `kuaigeyun-mes` 调用处）：`TENANT_JDBC_CIPHER_KEY`、`AI_MODEL_CIPHER_KEY` 在本仓没有调用处。`KuaiaiLlmProvider.decrypt_api_key` 与 `KuaiaiMcpServer.decrypt_token` 按列返回原值。许可证加密只服务许可证。因此连接口令不新造加密，沿用连接 `config` 的现有保存方式。

### 连接 config 字段

写在已有 `KuaiiotConnection.config`。每种连接源一个归一化函数，读这些字段，产出 `IngestBody`，然后只调用 `IngestService.ingest`。

| 字段 | 连接类型 | 含义 |
| --- | --- | --- |
| `topic` | `mqtt` | 订阅主题。`+` 匹配一层，`#` 只能放在末段并匹配剩余层 |
| `device_token_path` | `mqtt`、`thingsboard`、`jetlinks` | 载荷中设备凭据的点分路径 |
| `tags_path` | 同上 | 点位对象的点分路径 |
| `events_path` | 同上 | 事件数组的点分路径 |
| `timestamp_path` | 同上 | 时间字符串的点分路径 |
| `idempotency_key_path` | 同上 | 幂等键的点分路径 |

`http` 连接不使用上表。ThingsBoard、JetLinks 没有遥测地址字段。

### 平台地址未进入仓库

ThingsBoard、JetLinks 的遥测地址未进入仓库与 spec，拉取因此为空。调试时看这一节，不要到代码里猜地址。`load_platform_records` 返回空列表，不发请求。

RPC 同样没有官方地址。下发器可以按连接源注册（`thingsboard` → `dispatch_thingsboard`，`jetlinks` → `dispatch_jetlinks`），但不得发出猜测的 HTTP 请求。指令用已有 `dispatch_channel` 标成 `thingsboard` 或 `jetlinks`，状态停在 `not_sent`（未发出）。`claim_pending_commands` 只领取 `dispatch_channel` 为 `edge_heartbeat` 且状态为 `pending` 的指令。

Audit and lineage:

- 遥测的幂等沿用现有 `idempotency_key`。指令状态仍以现有指令行和回执为准。

AI/rule-engine rules:

- 不涉及。不新写阈值或告警。

Database rules:

- 不新造快照、写回、阈值、告警、映射或指令表。topic 与 JSON 路径写在已有连接的 `config` 上，字段名见「连接 config 字段」。
- 指令通道用已有列 `dispatch_channel`（`edge_heartbeat`、`thingsboard`、`jetlinks`）。未发出用已有列 `status` 的值 `not_sent`。不新增列。
- 现有工程没有连接口令加密。连接口令按该连接已有的 `config` 明文保存，不新增密钥，不新增列。
