### Business Goal

提升检索质量与一致性：附件解析采用重叠切块 + 可配分隔符；检索支持相似度阈值与可配置 topK；对话挂知识库与 Agent 只读检索走同一 `AiRetrievalService`，避免两套参数漂移。

Goal：overlap + 分隔符 + minScore + topK 生效；chat RAG 与 `searchKnowledge` 同 service；无 hybrid/rerank。

### Scope

In scope:

- **切块：** 知识附件解析（`POST /ai/knowledge/attach/{id}/parse` 路径不变）增加 **overlap**（须 > 0，占位如 `${AI_RAG_CHUNK_OVERLAP:200}`）+ **分隔符**（per-`ai_knowledge` 可配或租户/全局默认，如 `\n\n` / 自定义字符串；占位如 `${AI_RAG_CHUNK_SEPARATOR:\n\n}`）
- **检索：** 增强 `AiRetrievalService`（或等价）：参数 `topK`、`minScore`（相似度阈值）；向量查询仍带 `tenant_id`（I-A3）
- **配置：** topK / minScore / chunk 分隔符 可 per-`ai_knowledge` 字段或租户级默认（设计 07 §8 开放细节）；yml 仅占位
- **共用：** `POST /ai/chat/send` 的 `knowledgeId` RAG 与 `TenantKnowledgeSearchTool` 均调同一 service 方法
- 单测：Mock 向量；低于阈值不返回；topK 截断；overlap 解析产出相邻块重叠；分隔符优先于纯固定窗口

Out of scope:

- hybrid BM25、cross-encoder rerank、多向量融合
- 换向量 SDK（仍用 54/56 HTTP 适配）
- 改 chat/send HTTP 契约
- Vue3 知识库页改表单（可后续）
- 真实集群地址、凭据

Non-goals:

- 不引入第二套检索 service
- 不做 rerank 模型

### Acceptance Criteria

- 解析后 fragment 行存在 overlap 语义（测试可比对相邻块文本交集）
- 分隔符配置生效（per-knowledge 或默认）；块边界优先按分隔符切分再套 overlap
- 检索结果数 ≤ topK；得分 < minScore 的 hit 不进入上下文
- chat 与 searchKnowledge 调用同一 service 入口（静态或集成测试断言）
- 跨租户 knowledgeId 404/403，不调向量
- 第 4 节未编码前不得写「测试通过」

### Rules and Constraints

Tenant isolation:

- 检索必带当前 `tenant_id`；kid 须本租户

Security and masking:

- 检索日志不打印向量 token / 密钥

Audit and lineage:

- 若改 `ai_knowledge` 列则增量 SQL + include

AI/rule-engine rules:

- A32：无 hybrid/rerank
- 不削弱纯对话无 knowledgeId

Database rules:

- 可选 `ai_knowledge.top_k`、`min_score`、`chunk_separator` 列；或仅 yml 默认
