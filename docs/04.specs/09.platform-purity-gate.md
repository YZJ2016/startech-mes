# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 残留项清理与平台纯度门
- Module: `ktg-admin` / `ktg-framework` / `ktg-common` / `ktg-mes`
- Priority: P0
- Related requirement/design documents:
  - `docs/04.specs/00.backend-extract-program.md`
  - `docs/04.specs/01.extract-mes-constants.md` 至 `08.migrate-security-permit-all.md`

### Business Goal

`01`–`08` 完成后，确认六个平台模块相对 `RuoYi-Vue` 3.9.2 只剩可替换差异（版本与 jakarta 不在本单元修复）。残留 MES 项要么迁入 `ktg-mes`、要么有书面废弃。本单元通过后才允许单独立项做「ruoyi 模块换壳」。

### Scope

In scope:

- Godex：`ktg-admin` 下 `godex` 包与 `/godex`。现场仍用则迁入 `ktg-mes`；不用则删除。JNI/DLL 不在无现场时强行验证
- `FieldMetaObjectHandler`：评估与若依 `BaseEntity` 填充是否重复。重复则删除拦截器；仍需要则迁入 `ktg-mes` 并声明 MyBatis 插件。处理其对 hutool 的依赖（与 `02` 联动）
- 删除 `SwaggerController`（`/tool/swagger`）——换壳将用 SpringDoc，旧页不必迁
- 删除 `ktg-admin` 的 `TestController`（src/test 测试桩若仅调试用）
- 文档化配置前缀：当前 `RuoYiConfig` 为 `ktg-mes:`，若依为 `ruoyi:`。本单元不改前缀（避免现网配置失效），只在本 spec 写明换壳时必须做键映射
- 纯度检索：对照调查中「仅 MES 有的文件」清单，平台模块清零或列入书面豁免

Out of scope:

- 实际替换为 `ruoyi-admin/common/framework/system`
- JDK / Spring Boot 升级
- 前端

### Acceptance Criteria

- 调查列出的 only-in-MES 文件在 `ktg-common/framework/system/admin` 中为 0，或每条豁免写在第 4 节（豁免必须有理由，例如「换壳单元再映射 ktg-mes: 前缀，本单元故意保留 RuoYiConfig」）
- `UserConstants` 无 MES 业务常量（`01` 已完成）
- `FileUploadUtils` 无 Minio（`04` 已完成）
- `SecurityConfig` 无 MES 路径字面量（`08` 已完成）
- `RuoYiApplication` 无 UReport（`07` 已完成）
- Godex 与 FieldMeta 有 KEEP-迁入或 DROP 结论
- `ktg-quartz` / `ktg-generator` 仍无额外文件
- `mvn -pl ktg-admin -am compile` 通过（实际跑命令后才能勾选）

允许的豁免（预置，实施时确认）：

- `RuoYiConfig` 的 `prefix = "ktg-mes"` 保留到换壳单元
- `application.yml` / `application-back.yml` / `application-druid*.yml` 仍在 admin（换壳时对照 ruoyi 配置，不复制密钥）
- Java 8、javax.servlet、fastjson1、springfox 等版本差留到换壳，不在本单元「纯度」失败

### Rules and Constraints

Tenant isolation:

- 不涉及

Security and masking:

- Godex 若保留，不把打印机地址写进 spec
- 配置对照时不粘贴 secret/password 行

Audit and lineage:

- 删除代码须在 PR 说明现场确认人（Godex DROP 时）

AI/rule-engine rules:

- 不涉及

Database rules:

- 无新表。若 Godex 无独立表则不改库

## 2. Plan

- `ktg-admin`：godex、SwaggerController、启动残留
- `ktg-framework`：FieldMetaObjectHandler

- `ktg-mes`：接收仍保留的残留能力

- DROP Godex：`/godex` 消失，须通知现场
- KEEP Godex：路径保持 `/godex`
- 配置前缀 `ktg-mes:` 本单元不变

### Persistence Changes

- 无

### Transaction Boundaries

- 无

### Risks

- 未完成 `01`–`08` 就宣布纯度通过
- DROP Godex 导致车间打印中断
- 删除 FieldMeta 后部分未手写 `createBy` 的插入为空（若现网依赖该拦截器）

### Verification Strategy

对 `startech-mes-basic/backend` 执行（路径以仓库为准）：

- 检索只应出现在 `ktg-mes` 的类型：`AutoCodeUtil`、`MinioUtil`、`MobileLoginService`、`WebSocketServer`、`MessageProvider`、`SysAttachment`、`UReportConfig`、`ItemType`（实体）
- `ktg-framework` 的 `SecurityConfig` 不含 `/mes/`、`ureport`、`autocode`、`loginOuth`
- Maven compile `ktg-admin -am`

对照根目录 `RuoYi-Vue` 再做一次规范化文件差集（com.ktg 与 com.ruoyi 视为同层）。差集中平台侧只允许豁免清单。
