# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 移动端登录：保留迁入或删除
- Module: `ktg-framework` / `ktg-system` / `ktg-admin` → `ktg-mes` 或删除
- Priority: P1
- Related requirement/design documents:
  - `docs/04.specs/00.backend-extract-program.md`
  - 调查：`LoginController` 映射 `/mobile/login`；`TokenController` 映射 `GET /loginOuth`；Security 对 `/mobile/**` permitAll；当前仓库无 `pad/`

### Business Goal

明确还有没有客户端依赖 `/mobile/login/**`、`/mobile/user/**`、`/loginOuth`。有则整包迁入 `ktg-mes` 且 URL 不变；无则删除实现并在 `08` 去掉对应放行。避免换壳时平台模块里残留一套若依没有的登录。

### Scope

In scope:

- T1 书面决策：KEEP 或 DROP（记入本文件第 4 节 Result，未决策不得删代码）
- KEEP：迁移 `MobileLoginService`、`LoginParams`、`LoginController`、`UserController`（`/mobile/user`）、`TokenController`
- DROP：删除上述类型，并列出将在 `08` 删除的放行路径
- 不改 JWT 主登录 `/login`（若依标准登录）

Out of scope:

- 新建第二套认证体系
- 恢复 pad 工程
- 调整 Token 过期策略或密钥（禁止在文档中写出 secret 值）

### Acceptance Criteria

- 第 4 节 Result 中有且仅有 KEEP 或 DROP
- KEEP：类只在 `ktg-mes`；路径 `/mobile/login/loginByPassword`、`/mobile/login/sendCode`、`/mobile/login/logout`、`/mobile/user/registerUser`、`/mobile/user/getUserInfo`、`/mobile/user/saveUserInfo`、`GET /loginOuth` 不变
- DROP：全仓无 `MobileLoginService`、`LoginParams`（该登录用途）、`/mobile/login` 映射；标准 `/login` 仍可用
- 不引入平行 JWT 实现；继续用现有 `TokenService`（KEEP 时改为依赖平台 TokenService，类本身可留在 framework 直到换壳）
- compile 通过

### Rules and Constraints

Tenant isolation:

- 不改用户-部门数据权限模型

Security and masking:

- 禁止新增匿名登录入口
- KEEP 时本单元不扩大 permitAll；收口在 `08`（应变为需认证的接口应在 `08` 收紧）
- DROP 时不得留下死路径却仍 permitAll
- 口令与验证码不写日志

Audit and lineage:

- 登录日志仍走现有异步工厂（若 `MobileLoginService` 已调用），KEEP 时保持

AI/rule-engine rules:

- 不涉及

Database rules:

- 使用现有 `sys_user`，不新建用户表

## 2. Plan

### Implementation Approach

决策门：根据是否仍有 H5/App/旧 pad 打这些 URL。当前外层仓库无 pad，不能据此默认 DROP。

KEEP 路径：

1. 将 Controller 迁入 `ktg-mes`（例如 `com.ktg.mes.mobile`）
2. `MobileLoginService` 迁入 mes 或保留为 mes 服务类；继续注入现有 `TokenService`、`AuthenticationManager`
3. `LoginParams` 迁入 mes.domain
4. 删除 admin/framework/system 旧文件

DROP 路径：

1. 删除五个类型及相关映射
2. 在 `08` 的任务中删除 `/mobile/**`、`/loginOuth` 放行（本单元 PR 说明交叉引用）

### Affected Modules

- KEEP：`ktg-mes` 迁入；`ktg-admin` / `ktg-framework` / `ktg-system` 迁出
- DROP：三处平台模块删除；`ktg-mes` 无新增

### Public Contracts

KEEP 时冻结：

- `POST /mobile/login/loginByPassword`
- `POST /mobile/login/sendCode`
- `GET /mobile/login/logout`
- `POST /mobile/user/registerUser`
- `GET /mobile/user/getUserInfo`
- `POST /mobile/user/saveUserInfo`
- `GET /loginOuth`

DROP 时上述路径应 404，且不得再匿名放行。

标准合约 `/login`、`/logout`、`/captchaImage` 两方案都不得破坏。

### Persistence Changes

- 无新表

### Transaction Boundaries

- `MobileLoginService` 现有 `@Transactional` 仅用于其注册/写用户路径；KEEP 时不扩大

### Risks

- 未确认客户端就 DROP，现场登录全挂
- KEEP 却继续把 `/mobile/**` 全部匿名，安全面过大（交给 `08` 但本单元 PR 必须提示）
- 误改若依 `SysLoginController`

### Verification Strategy

- 决策写入第 4 节后再动代码
- `rg "/mobile/login|loginOuth|MobileLoginService" backend`
- Maven compile
- KEEP 时用测试账号走移动登录（不记录口令）

# 结果：BUILD SUCCESS（ktg-admin 编译 40 个源文件）

Result:

- 决策：**KEEP**（保留并迁入 `ktg-mes`，URL 不变）
- 代码：已实施。`MobileLoginService`、`LoginParams`、`LoginController`、`UserController`、`TokenController` 仅存在于 `ktg-mes` 的 `com.ktg.mes.mobile` 包；继续注入现有 `TokenService` / `AuthenticationManager` / `SysLoginService.loginOuth`，无第二套 JWT
- 标准 `/login`：`SysLoginController` 未改
- Security：本单元未改 `SecurityConfig` permitAll（交给 `08`）
- compile：JDK 8 下 `ktg-mes` 通过；`ktg-admin` 在跳过既有 antrun（缺 frontend dist）后通过。未做运行时移动登录验证。

交叉引用 `08`：

- KEEP 故 `08` **不得删除** `/mobile/login/**` 与 `/loginOuth` 的放行处理入口
- `08` 应将过宽的 `/mobile/**` 收紧到登录所需路径；`/mobile/user/**` 建议改为需认证
- DROP 相关删除项不适用

Known gaps:

> 状态：`[ ]` 开放 · `[x]` 已收口（收口详情见 `docs/02.requirements/99.升级交付剩余缺口与收口清单.md`）

- `[x]` 书面决策：KEEP（产品确认缺口仍在，但不阻塞迁入）
- `[ ]` 产品/现场未确认是否仍有客户端调用 `/mobile/**`（KEEP 后该缺口变为验收/下线依据，不再阻塞抽出）
- `[ ]` `/mobile/**` 整段 permitAll 过宽，KEEP 后由 `08` 收紧到登录相关路径
- `[ ]` `TokenController` 仍含既有第三方 OAuth 凭据硬编码（迁入未改写运行时配置）；`08` 或后续安全债应改为环境变量，且不得把 secret 写入文档
