# KU-AI 场景 Tool：检验单与供应商绩效

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：待实施。

## 1. Spec

### Capability

- Name: 按检验类型新增 4 个检验单查询 Tool，以及供应商评价查询 Tool。
- Module: `riveredge-backend/src/apps/kuaiai/services`（tools 适配层）、manifest `ai_tools`。
- Priority: P2（S15 来料质量与供应商绩效；也为 S12 提供明细）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D5、SC-D7；设计 26 §4、§5.2（P2 检验单按权限码拆分）；前置 spec 189、190。

### Business Goal

质量/采购问“供应商 A 近一个月来料检验合格率怎样、不合格的是哪些批次”“上季度供应商评价得分排名”，助手基于检验单与供应商评价的真实记录回答。

### Scope

In scope（一检验类型一 Tool，权限码各不相同，SC-D7）：

| Tool | 底层 service（已读） | 权限码 |
| --- | --- | --- |
| `query_incoming_inspections` | `IncomingInspectionService.list_incoming_inspections(tenant_id, skip, limit, **filters)` | `kuaizhizao:quality-management-incoming-inspection:read` |
| `query_process_inspections` | `ProcessInspectionService.list_process_inspections(…)` | `kuaizhizao:quality-management-process-inspection:read` |
| `query_finished_inspections` | `FinishedGoodsInspectionService.list_finished_goods_inspections(…)` | `kuaizhizao:quality-management-finished-goods-inspection:read` |
| `query_oqc_inspections` | `OQCInspectionService.list(…)`（`quality_improvement_service.py`） | `kuaizhizao:quality-management-oqc-inspection:read` |
| `query_supplier_evaluations` | `SupplierEvaluationService.list(…)`（`supplier_evaluation_service.py`） | `kuaizhizao:supplier-eval:read` |

- 通用参数：`keyword?`、`material_id?`、`supplier_id?`（来料/评价）、`work_order_id?`（过程/成品）、`result?`、`date_start?`、`date_end?`、`limit≤20`；实际可用过滤键 T1 从各 `**filters` 实现读取，只暴露 service 已支持的键。
- 数据范围：各 service 不接收 `current_user` 时，适配层用 `_scoped_row_ids` 补行级范围，资源键 T1 从 manifest 确定（`query_quality_anomalies` 已用 `kuaizhizao:quality-analysis` 资源键的先例仅作参考，不照搬）。
- 委外检验（`quality-management-outsource-inspection:read`）不在本单元，按需另立。

Out of scope:

- 新建/审核检验单（写操作）。
- 供应商评价打分计算（读结果，不重算）。

### Acceptance Criteria

1. 每个 Tool 输出检验单号、物料、供应商/工单、检验数、合格/不合格数、结论、检验时间；供应商评价输出供应商、周期、得分/等级。
2. 行级数据范围收敛；非法参数固定错误文案；空结果、异常口径一致。
3. 不输出检验员联系方式、供应商联系人与价格。
4. 五个 Tool 登记于 manifest（`label`、`kind=read`）。

### Rules and Constraints

Tenant isolation:

- 传 `ctx.tenant_id`。

Security and masking:

- 一 Tool 一权限码。

Audit and lineage:

- 沿用 Tool 级审计。

AI/rule-engine rules:

- 合格判定、评价得分来自业务记录（SC-D5）；合格率若需计算，在适配层做确定性计算并注明样本数。

Database rules:

- 无表结构变更。

### 场景模板（Y3=a）

本单元交付时同步登记场景模板 `inspection-supplier`（检验与供应商助手）：预置档案 `enabled_tools` 为本单元 Tool 集合，停用 + 空授权（Y4=a）；模板 key 即能力矩阵场景卡，默认绑定同 key 预置实例（spec 191，Y1/Y2=a）。system_prompt 只引用本单元 Tool，插画按 spec 201 T2 约定。

## 2. Plan

### Implementation Approach

- 四个检验 Tool 共用一个内部摘要函数（字段口径一致），各自只差 service 与权限码。

- Modify/Create: tools 适配模块、`constants.py`、`manifest.json`（两份）。
- Test: `tests/apps/kuaiai/test_spec209_inspection_supplier_tools.py`。

### Public Contracts

- Tool 闭集新增五名。

### Persistence Changes

- 无。

### Transaction Boundaries

- 只读。

### Risks

- `**filters` 各 service 支持的键不一致：每个 Tool 只声明其 service 实际支持的参数，不做统一假参数。

### Verification Strategy

- 单测：每个 Tool 的范围收敛、参数过滤、敏感字段不出现。
