# 报表中心系统数据集：用户级数据范围

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：待实施；§1 决策已于 2026-10-23 选定。

## 1. Spec

### Capability

- Name: 给报表中心（kuaireport）系统数据集补上用户级数据范围控制。
- Module: `riveredge-backend` kuaireport 数据集执行/查询路径（与 AI 无直接耦合，但为 AI 开放数据集的前置，SC-D10）。
- Priority: 后续缺口（独立立项；不阻塞 P1–P3 任何单元）。
- Related requirement/design documents: 需求 25 SC-D10；设计 26；前置：无（AI 侧不依赖本单元）。

### Business Goal

系统数据集的 SQL 目前只按租户过滤：有报表权限的用户在报表中心就能看到全租户数据。这既是 AI 接入的拦路问题，也可能是报表中心本身的越权缺口。本单元给数据集查询补上用户级数据范围（DataScope），让数据集结果与业务页面口径一致。

### Scope

In scope:

- 核实现状：系统数据集 SQL 的过滤方式、是否已有组织/角色维度条件、报表权限与数据范围的关系（T1 全量核实，本 spec 不预设结论——若现状即越权，问题面不止 AI）。
- 为数据集定义并落地用户级数据范围：数据集声明其数据域（如工单域、库存域），查询时按当前用户 DataScope 追加过滤。
- 与 AI 的关系：本单元落地后，才允许另立 spec 把受控数据集开放为 AI 只读 Tool（届时须重新走需求评审）。

Out of scope:

- 任何 AI Tool 登记（本单元不为 AI 开放数据集）。
- 自定义报表的编辑器改造。

### 决策（2026-10-23 已选定）

选定：**X9=a**（执行器统一注入范围条件，数据集声明数据域；未声明按失败关闭）、**X10=a**（若核实为越权，按安全缺口全量修复）。

| 编号 | 场景 | 选项 | 推荐与理由 |
| --- | --- | --- | --- |
| X9 | 数据范围过滤的实现位置：(a) 在数据集 SQL 外层包一层范围条件（执行器统一注入）；(b) 要求每个数据集 SQL 自带范围占位符；(c) 在结果集返回前按行过滤 | a. 执行器统一注入范围条件（数据集声明数据域 → 执行器查该域范围 → 追加 WHERE）；b. 数据集 SQL 自含占位符；c. 结果行级过滤 | **a**：b 要求所有存量 SQL 改造且靠作者自觉，漏写即越权；c 在大数据集上性能不可接受且与分页/聚合冲突。a 把范围收敛在执行器一处，与 tool_bridge 集中判权同思路 |
| X10 | 如果核实发现现状已是越权（业务用户在报表中心能看全租户），修复范围 | a. 本单元直接修复全量数据集；b. 先只修 AI 可能用到的数据集，其余另立 | **a**：若确认越权，这是安全缺口不是 AI 需求，应按数据范围缺口一次性修复；拆分只会拖延 |

### Acceptance Criteria

1. T1 核实结论明确记录：现状是否越权、涉及哪些数据集与权限。
2. 数据集查询按当前用户 DataScope 收敛；无范围权限的用户查询结果为空而非报错（与业务列表页同口径）。
3. 既有报表在正常权限下结果不变（回归基线）。
4. 数据集未声明数据域时，默认拒绝开放行级明细（失败关闭）或维持现状并记录例外清单（T1 定哪种，倾向失败关闭）。

### Rules and Constraints

Tenant isolation:

- 沿用租户过滤 + 新增用户级范围，不削弱租户隔离。

Security and masking:

- 本单元即安全修复单元。

Audit and lineage:

- 数据集查询审计补记数据域与范围命中情况（沿用现有审计通道）。

AI/rule-engine rules:

- 无 AI 逻辑。

Database rules:

- 若数据集元数据需新增“数据域”字段，走 aerich 迁移（14 位时间戳序号规则）。

## 2. Plan

### Implementation Approach

- 先核实（T1）：读 kuaireport 数据集定义、执行器、权限声明；抽样核对若干数据集的过滤 SQL。
- 按 X9 方案在执行器层落地数据域 → 范围注入；存量数据集逐个登记数据域。

### Affected Modules

- Modify: kuaireport 数据集执行器、数据集元数据模型（如需数据域字段）。
- Test: 数据集范围测试（含无权限、部分权限、全权限三层）。

### Public Contracts

- 数据集查询响应结构不变；元数据模型可能新增字段（迁移）。

### Persistence Changes

- 视 T1 结论：数据集元数据加 `data_domain` 列（如需）。

### Transaction Boundaries

- 只读为主；元数据迁移为 DDL。

### Risks

- 存量报表按新范围过滤后，原本习惯看全租户数据的用户（如总部管理员）结果变化：需确认管理角色是否默认全数据范围（与业务列表页行为对齐）。
- 这是可能已存在的越权问题：若 T1 确认，优先按安全缺口处理，不等 AI 需求。

### Verification Strategy

- 单测 + 抽样数据集端到端核对：同用户角色在报表中心与业务列表页看到的数据范围一致。
