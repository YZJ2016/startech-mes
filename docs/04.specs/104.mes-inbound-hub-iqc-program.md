- Hub/闸 SQL 永不跳过 `tenant_id`；`qc_iqc.recpt_id` 与入库单同租户

Security and masking:

- 新 GET 必 `@PreAuthorize`；不进 `MesPermitAllProvider`
- 日志不打印 token、JDBC、内部路径

Audit and lineage:

- 新 DDL 只进 Flyway `db/migration/{master,tenant}`
- 不改历史 `backend/sql/`
- 执行闸可用现有 `@Log`

AI/rule-engine rules:

- 本切片不涉及 AI

- 菜单 9300–9309；配置键 `mes.wm.inbound.iqc.gate.confirm` / `.execute` / `.autoDraft` 走 `sys_config`，不写 yml

## 2. Plan

### Implementation Approach

1. 105 一次交付：菜单/三键配置、Hub list（含仓库筛）、抽屉（合格量/序列号/只读检验项/深链）、`recpt_id`、闸预览、confirm/execute 闸；autoDraft 默认 off。**105 范围不变。**
2. 出库 Hub 不进本 TOC（106）。FQC / 历史回填 / 金额 / Hub 打印进 **108–111**，不进 105。**108–111 不是其他入库/还料/客供。** 余型 IH-G7–G13 无文件、不进本 TOC。
3. 旧页不重排；服务端闸对旧页同样生效。

### Affected Modules

- 文档：14、设计 14、本文件、105；总览 13 号仅指针
- 编码（105）：`ktg-mes` wm/qc；Flyway master+tenant；`startech-mes-front` Hub 页；iqc/purchase/workorder **仅** `route.query` 水合（不改布局）
- 禁止：`frontend/`、`kuaigeyun-mes/`、`ktg-generator`、UReport

### Public Contracts

- 保持：`/mes/wm/itemrecpt/**`、`/mes/wm/productrecpt/**`、`/mes/qc/iqc/**` 的 URL/method/信封
- 增量：`GET /mes/wm/inboundhub/list`；`GET /mes/wm/itemrecpt/{recptId}/iqc-gate`；`POST /mes/qc/iqc` 可带可选 `recptId`
- execute 失败多一种业务 `AjaxResult.error`；confirm 键 `on` 时确认也可多一种 error。不是新 URL

### Persistence Changes

- tenant：`qc_iqc.recpt_id` 可空；入库行三列可空（合格/不合格/序列号）
- master：菜单 9300 段；`sys_config` `mes.wm.inbound.iqc.gate.confirm`=`off`、`.execute`=`on`、`.autoDraft`=`off`
- 无新业务头表；无金额列

### Transaction Boundaries

- 确认闸失败则不把入库改为 `CONFIRMED`；执行闸失败则不调用 `processItemRecpt`

### Risks

- 默认 execute=`on` 挡现网未做 IQC 的过账（overlay `off` 回退）；confirm 默认 `off` 不改今日确认
- 头表单一 `iqc_id` 不够盖多行（以 `recpt_id`+`item_id` 为准）
- 把出库页一并改皮肤（违反 UI-A）

### Verification Strategy

- 见 105 第 2/3 节；本文件不跑命令
