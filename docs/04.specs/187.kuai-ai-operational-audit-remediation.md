- Module: `kuaigeyun-mes/riveredge-backend/src/apps/kuaiai`、`riveredge-frontend/src/apps/kuaiai`；外层需求/设计/spec 文档。

- Related requirement/design documents: 需求 24 KO-04、KO-09；设计 24 §4、§6、§11；审计报告 25 F-01～F-07；spec 181、182、184、185、186。

### Business Goal

修复审计确认的数量失真、运行时假就绪、能力入口偏差、设置并发窗口和同日延期事实夸大，使 181～185 的代码行为重新与需求/设计一致；同时把 186 的验收状态恢复为与证据相符的“待浏览器/真实链路复验”。本单元不在未启动前后端时伪造浏览器验收结果。

### Scope

In scope:

- Pulse production/sales detector 以固定批次分段读取候选，不再以单次 200 条上限作为业务全集；registry 在 timeout/cancellation 约束内基于完整成功 detector 结果完成筛选、去重、排序、summary 与分页，公开 `PulseOut` 字段不变。
- 同日已超过计划完成时刻的生产工单使用 `delay_days=0`，事实文案为“今日已逾时”；跨日按真实业务日期差显示 N 天，严重度仍为 warning，工单自身高/紧急优先级仍可升为 high。
- 智能体库 chat 就绪删除 `KuaiaiLlmModel` 目录兜底，只消费 `AiRuntimeConfig.public_status()` 的当前应用连接事实；读取失败或未配置均不返回 ready。
- Hub“智能问数”要求 chat 运行时已配置启用、`tools_enabled` 未关闭、注册表中至少一个 KU-AI 只读 Tool 实际可用；知识检索 route 改为 `/apps/kuaiai/corpus`。
- Settings PUT 在同一数据库事务内按稳定顺序锁定并重新校验 payload 引用的 IntegrationConfig，再锁 SiteSetting，锁内比较 version 并一次保存；事务提交后再失效模型缓存。
- 修正 181、184、186 中与当前资产不一致的测试文件名、用例数量和验收状态；186 保留浏览器、三角色、真实 RAG→审计→统计为开放项。
- 为上述行为先新增失败测试，确认红灯原因正确后再修改生产代码。

Out of scope:

- 库存、质量、设备 Pulse detector；新的 Pulse 响应字段、游标或快照表。
- 修改既有公开 URL、method、认证头、响应外层或前端页面布局。
- 重新引入模型目录作为运行时真源，或迁移/删除历史模型目录数据。
- 浏览器四视口、键盘、三角色及真实 FAQ/RAG 链验证；待用户启动前后端并提供可用测试环境后单独执行。
- 修复与 KU-AI 无关的前端 duplicate key、循环 chunk、大 chunk 或全仓弃用 warning。

### Acceptance Criteria

1. 单一成功 detector 产生 250 条异常时，Pulse `summary.total=250`、领域 `count=250`，第 3 页能返回第 201～250 条；Hub `pulse_count=250`。每次 ORM 读取批次不超过 200，timeout/cancel 后不继续调度下一批。
2. domain、severity 筛选后的 summary、领域 count、全局排序和分页仍精确；失败/越权 detector 不泄露计数，未接入 detector 维持 `not_connected` 语义。
3. 今日已超过计划完成时刻的生产工单事实包含“今日已逾时”，不包含“逾期 1 天”；`delay_days=0` 对应 warning，urgent/high 工单 priority 仍为 high。
4. 仅有启用 `KuaiaiLlmModel` 目录行、但当前 chat 应用连接未配置/未启用时，场景状态不得因目录行变为 ready；不查询目录表作为兜底。
5. Hub 智能问数仅在 chat ready + tools enabled + 至少一个已注册只读 Tool 同时满足时 ready；任一不满足均 `not_ready` 并返回对应用户可理解原因。
6. Hub 知识检索能力 route 固定为 `/apps/kuaiai/corpus`，前端权限白名单和跳转按 `kuaiai:corpus:display` 判断。
7. Settings PUT 在事务锁内复核连接的 tenant、未软删、启用、角色匹配；校验后被并发修改的场景由行锁串行化。任一连接失败时 SiteSetting 不变、缓存不失效；version 冲突仍返回 409。
8. operations 公开请求/响应结构、既有 agents/knowledge/chat/mcp/core stats/audit 契约不变；前后端 40 个权限码和 menu_config 继续一致。
9. 181/184/186 文档只记录本次真实命令和结果；186 不再宣称未执行的浏览器/真实链路已通过。

### Rules and Constraints

Tenant isolation:

- Pulse 每一批查询继续显式带 `tenant_id` 并经过当前用户 DataScope；Settings 锁定连接必须同时按 `tenant_id` 和 UUID 查询，跨租户统一按不可用处理。

Security and masking:

- detector 分批读取不得绕过权限检查；Settings 错误不回 connection cipher、API key 或内部字段；日志只记 tenant、operator、UUID 变化和 error type。

Audit and lineage:

- 不新增页面读取审计；真实 chat、core stats/audit 沿既有链。修复记录回链需求 24 KO-09、审计报告 25 和本 spec。

AI/rule-engine rules:

- chat 就绪只认应用连接 runtime；模型目录不是 fallback。智能问数的“只读 Tool 可用”由服务端注册表/manifest 闭集判定，禁止仅凭前端卡片或开关推断。
- Pulse 事实、计数、严重度和 ID 仍由确定性规则生成，LLM 不参与。

Database rules:

- 不新增表或迁移。Settings 使用现有 IntegrationConfig 与 SiteSetting；锁顺序固定为 payload 中连接 UUID 排序后逐行锁定，再锁 SiteSetting，降低死锁风险。

## 2. Plan

### Implementation Approach

- Pulse detector 保留公开 `detect(ctx)` 入口，但内部通过固定 `SCAN_BATCH_SIZE=200` 的 `offset/limit` 循环读取，每批立即映射统一 item；不足一批结束。registry 仍负责跨 detector 去重、稳定排序、severity 过滤、summary 和最终 page slice，因此公开契约不变。`asyncio.wait_for` 包住完整 detector 扫描；协程取消会阻止后续批次。
- Production 同日规则把 `delay_days=max(0, date_diff)`；事实格式按 0/N 分支，严重度函数接受 0 并归入 warning。
- `is_chat_ready()` 只返回 runtime public status 的 configured∧enabled；异常失败关闭。
- Hub 从 KU-AI Tool 注册事实中计算是否至少有一个只读 Tool。只读判定使用明确闭集/Tool metadata，不以名称字符串或“非写接口”猜测；状态失败关闭。知识检索 route/前端映射统一改 `/corpus`。
- Settings 将 `_load_connection_for_role` 拆成可接收事务连接/锁定查询的内部校验：收集非空 UUID、排序去重、事务内 `select_for_update()` 获取 IntegrationConfig，逐项校验 tenant/status/model_role；再锁 SiteSetting 并执行现有 version/merge/save。所有返回视图和 cache eviction 在提交后执行。
- 文档只更新验证事实和开放项，不提前填写浏览器通过记录。

### Affected Modules

- Modify: `riveredge-backend/src/apps/kuaiai/services/pulse/{base,production,sales,registry}.py`（按最终最小实现可能无需改 base/registry 类型）。
- Modify: `riveredge-backend/src/apps/kuaiai/services/agent_scene_service.py`、`operations_service.py`、`settings_service.py`。
- Modify: `riveredge-frontend/src/apps/kuaiai/pages/hub/index.tsx`（知识 route 权限映射）。
- Test first: `riveredge-backend/tests/apps/kuaiai/test_spec182_pulse.py`、`test_s5_agent_scenes.py`、`test_spec185_settings.py`；补齐/重命名 181 测试资产时不得重复测试同一行为。
- Docs: 需求 24、设计 24、spec 181/182/184/185/186、本 spec 验证记录。

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- `GET /api/v1/apps/kuaiai/operations/pulse` 的参数、`PulseOut` 字段和状态码不变；只纠正超过 200 条后的计数与分页。
- `GET /operations/hub` 字段不变；仅纠正 capability status、disabled_reason 和 knowledge route 值。
- `GET/PUT /operations/settings` body/response/version 字段不变；只加强事务内校验。
- Agent library API 字段不变；仅纠正 chat readiness 来源。

### Persistence Changes

- 无 DDL、无 aerich 迁移、无数据回填。

### Transaction Boundaries

- Pulse、Hub、Agent library 均只读，不开写事务。
- Settings：单事务内锁 payload 引用的 IntegrationConfig 行并校验，随后锁本租户 SiteSetting 行、校验 version、深合并和一次 save；异常整体回滚。缓存失效和响应重读在成功提交后。

### Risks

- Pulse 精确扫描在异常量极大时增加查询次数；以 200 条批次、现有 8 秒 detector timeout 和 cancellation 限制单请求成本，不改成一次全表加载。后续若规模证明仍不足，再单独设计数据库聚合/游标契约。
- 多连接行与 SiteSetting 的锁顺序不一致可能死锁；本单元固定 UUID 排序后锁连接、最后锁 SiteSetting，并通过并发测试固定顺序。
- Tool 注册表可能包含写 Tool；必须使用现有显式只读闭集/metadata，不得把所有注册 Tool 都算作“智能问数可用”。
- 删除模型目录兜底可能让历史租户从“假 ready”变为 not_ready，这是预期纠正；不自动为其选择连接。

### Verification Strategy

- TDD：每一项先运行新增测试并观察因当前缺陷失败，再最小实现至通过。
- 后端专项：Pulse 超 200/第三页/Hub count、同日逾时；runtime 未配置但目录行存在；Hub chat/tools/read Tool 组合；Settings 锁内校验、回滚、锁顺序、409。
- 回归：`uv run pytest tests/apps/kuaiai`，再运行后端全量 `uv run pytest`。
- 前端：KU-AI 纯函数测试、TypeScript/build；构建输出放临时目录以免覆盖用户已有 dist。
- 静态一致性：前后端 manifest 权限差集为空、menu_config 相等、`/corpus` route 映射一致。
- 浏览器验证延期：待用户启动前后端后执行 spec 186 的四视口、键盘、三角色与真实链路，不在本单元伪填通过。
