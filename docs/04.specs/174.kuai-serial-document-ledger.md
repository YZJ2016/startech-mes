## 1. Spec

### Capability

- Name: 序列号出入库留痕台账
- Module: `kuaigeyun-mes/riveredge-backend`：`InventoryService` 与新的出入库留痕；序列号追溯读沿用现有 trace
- Priority: P0（KR-PG5）
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/22.kuai-production-grade-closeout-gaps.md`（**KR-PG5**）
  - 设计：`docs/03.design/22.kuai-production-grade-closeout-plan.md` 第 5 节
  - 锁序与幂等键：`docs/04.specs/141.kuai-inventory-serial-idempotency.md`

### Business Goal

按序列号能查出这件货经过哪些出入库单据、当前落在哪一张。明细行上的序列号仍只是录入。`MaterialSerial` 仍是身份与当前在库状态。撤回追加反向留痕，不删历史。

### Scope

In scope:

- 新的出入库留痕台账：一件序列号在一次出入库动作上一行。
- `InventoryService` 入库/出库路径带了非空序列号时，每个序列号记一行，与 `MaterialSerial` 状态变更同一事务。
- 撤回追加相反方向的行。
- 现有序列号追溯读能带回台账，并算出当前单据。

Out of scope:

- 不造第二套序列号主数据。不把单据字段塞进 `MaterialSerial` 代替流水。
- 不往 `MaterialStockMovement` 上塞序列号列表。
- 不做多级投料族谱，不回答父子件、工序消耗。
- 不改 spec 141 的行字段 `serial_numbers` 与库存幂等键语义。过账仍从明细行读取序列号，不从台账反写行。
- 没传序列号的数量过账不记台账。
- 不改现有序列号 trace 的 URL、method、认证头、响应外层结构。

### Acceptance Criteria

1. 带非空 `serial_nos` 的入库或出库过账，每个序列号有一行台账，与 `MaterialSerial` 状态在同一事务。台账写入失败则该笔库存过账整笔回滚，不允许库存已变、台账没记。
2. 同一库存幂等键加同一序列号已有行：显式幂等成功，不插第二行。
3. 撤回（`source_type` 带撤回，或出库冲入库）不删除、不改原行。追加一行相反方向，反向指针指向原行。
4. 再确认入库走 848–861 行的再确认容忍时，台账只在没有对应正向行时追加；已有则幂等成功。
5. 当前单据：按序列号取时间序，跳过已被反向指针指到的正向行之后，最后一笔正向行的来源单据。历史行仍可查。
6. 明细行 `serial_numbers` 仍是录入。`MaterialSerial` 字段仍是物料、序列号、在库/已出库状态，没有单据。无序列号的数量过账不产生台账行。
7. 现有 `GET` 序列号 trace（`material.py` 1636 行 `/serials/{serial_uuid}/trace`）的 URL、method、认证头不变。返回中能看到经过的单据和当前归属，身份仍来自 `MaterialSerial`。

### Rules and Constraints

Tenant isolation:

- 台账行带组织。查询带组织。序列号字符串与 `MaterialSerial.serial_no` 相同，不另编主键身份。

Security and masking:

- 追溯返回不包含凭据或内部路径。

Audit and lineage:

- 台账是单据查询真相。撤回只追加，不删历史行。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 新增一张出入库留痕表，挂在现有 Tortoise app `models`。需要一条 aerich 迁移。文件放 `migrations/models/`。文件名第一段为 14 位时间戳，且大于该目录已有迁移文件名里出现过的最大时间戳。不要接开源仓序号（如 793）。本 spec 不指定文件名，也不指定迁移序号。
- 不改 `MaterialSerial`、不改 `MaterialStockMovement`、不改明细行 `serial_numbers`。

## 2. Plan

### Implementation Approach

- 在库存领域新增留痕模型。写入放在入库 832–875 行与出库 `_mark_serials_out_stock` 1105–1138 行已经持有序列号行锁的同一事务里，锁序不改：先批次行锁，再按序列号排序加锁，然后写台账。
- 查询规则放在库存领域服务。trace 读把台账附在现有返回上。

### Affected Modules

- `src/apps/kuaizhizao/services/inventory_service.py`
- 新的留痕模型与查询（`kuaizhizao`）
- `src/apps/master_data/services/material_serial_service.py` 的 `trace_serial`（384 行起）只增加台账结果，不改 `MaterialSerial` 写入
- 对应单测

### Public Contracts

- 序列号 trace 的 URL、method、认证头、响应外层结构不变。
- 在现有 trace 字典中增加台账行与当前单据。不改 `serial` 身份字段的含义。

### Persistence Changes

新实体职责：回答这件序列号经过哪些出入库单据、当前归属哪一张。不回答父子件、投料族谱、工序消耗。

关键字段意图：

- 组织、序列号、物料。序列号字符串与 `MaterialSerial.serial_no` 相同。
- 方向：入或出。
- 移动类型、来源单据类型、来源单据 id、来源单据编码。类型与库存过账已有的 `source_type` / `movement_type` 同一套词，不另起一套单据类型码。
- 库存幂等键，与序列号一起区分同一次过账重试。
- 发生时间、操作人。
- 反向指针：撤回行指向被冲销的那一行。空表示正向流水。

同一幂等键加同一序列号已有行时不插第二行。需要能按组织 + 序列号 + 时间序查出正向行，并判断该行是否被反向指针指到。

### Transaction Boundaries

- 台账与 `MaterialSerial` 状态变更、批次数量变更同一数据库事务。任一侧失败全滚。
- 幂等命中不再插行，也不把本笔过账打失败。

### Risks

- 重试插入第二行。同一库存幂等键加同一序列号必须命中已有行。
- 撤回改原行或删原行。只追加反向行。
- 把序列号列表写进 `MaterialStockMovement`。禁止。

### Verification Strategy

- 在 `kuaigeyun-mes/riveredge-backend` 用 `uv run pytest` 覆盖：过账与台账同成败、幂等不双行、撤回留反向行、再确认不双行、无序列号不过账台账。未跑通不得声称通过。
