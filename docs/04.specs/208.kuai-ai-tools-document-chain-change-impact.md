# KU-AI 场景 Tool：单据关联链与变更影响

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已完成；§1 决策已于 2026-10-23 选定。

## 1. Spec

### Capability

- Name: 新增只读 Tool `trace_document_chain` 与三个变更影响 Tool。
- Module: `riveredge-backend/src/apps/kuaiai/services`（tools 适配层）、manifest `ai_tools`。
- Priority: P2（S05 需求/订单变更影响面）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D5、SC-D7；设计 26 §4、§5.2；前置 spec 189、190。

### Business Goal

计划员/采购问“客户改了 SO-0912 的数量，会影响哪些工单和采购单”“这张采购单上下游关联了哪些单据”，助手基于单据关联与变更影响分析给出影响清单。

### Scope

In scope:

| Tool | 参数 | 底层 service（已读方法名） | 权限码 |
| --- | --- | --- | --- |
| `trace_document_chain` | `document_type`（闭集，T1 从 service 支持类型读取）、`document_id`、`direction=upstream\|downstream\|both`、`max_depth≤10` | `DocumentRelationNewService.trace_document_chain` | 见 X3 |
| `analyze_sales_order_change_impact` | `sales_order_id` | `DocumentRelationNewService.get_change_impact_sales_order` | `kuaizhizao:sales-order-change:read` |
| `analyze_purchase_order_change_impact` | `purchase_order_id` | `DocumentRelationNewService.get_change_impact_purchase_order` | `kuaizhizao:purchase-order-change:read` |
| `analyze_demand_change_impact` | `demand_id` | `DocumentRelationNewService.get_change_impact_demand` | `kuaizhizao:plan-management-demand-change:read` |

- 变更影响按来源单据类型拆为 3 个 Tool（SC-D7：三者对应的变更权限码不同）。
- 现状事实：`GET /document-relations/{type}/{id}/trace` 所在 router 未声明权限依赖（仅登录）；销售订单变更影响路由挂在带 `require_kuaizhizao_sales_order_access()` 的 router 下；需求变更影响路由的权限 T1 核实。
- 源单 by-ID 先做行级数据范围复核（销售/采购单用对应 service 的 current_user 范围，需求单 T1 定），范围外按不存在回复。

Out of scope:

- 发起变更单（写操作）。

### 决策（2026-10-23 已选定）

选定：**X3=a** —— 链上节点按其单据类型读权限过滤，无权节点只显示计数不显示编号。

| 编号 | 场景 | 选项 | 推荐与理由 |
| --- | --- | --- | --- |
| X3 | 关联链跨模块：一条销售订单的链可能包含工单、采购单、入库单、发货单、财务单据。采购员问“SO-0912 关联了哪些单”，如果原样返回，他会看到自己无权查看的应收/发票单号与金额相关单据；现有 trace 路由只要求登录，页面上也存在同样问题，但 AI 会主动汇总、更容易暴露 | a. Tool 挂源单类型对应的读权限（按 `document_type` 映射），并对链上每个节点按其单据类型的读权限过滤，无权节点只显示“N 个无权查看的关联单据”；b. Tool 挂单一权限（如 `kuaizhizao:work-order:read`）且不过滤节点；c. 暂不提供关联链 Tool，只做三个变更影响 Tool | **a**：AI 不应比用户本人看到更多；节点级过滤让用户知道“有关联但无权看”，不泄露内容。现有 trace 路由仅登录可访问的问题记入 Known gap，建议另立页面侧修复，本单元不改既有路由 |

### Acceptance Criteria

1. 三个变更影响 Tool 输出受影响单据（类型、编号、状态、影响说明），与对应接口同参数一致。
2. X3=a：源单无读权限 → 不返回；链上无权节点只计数不显示编号与内容。
3. 源单范围外按“不存在”回复；`direction`、`document_type` 非闭集值返回固定错误文案。
4. 四个 Tool 登记于 manifest（`label`、`kind=read`）。

### Rules and Constraints

Tenant isolation:

- 传 `ctx.tenant_id`。

Security and masking:

- 链路节点不输出金额；无权节点不输出编号。

Audit and lineage:

- 沿用 Tool 级审计。

AI/rule-engine rules:

- 影响判定来自关联与变更影响 service（SC-D5）。

Database rules:

- 无表结构变更。

### 场景模板（Y3=a）

本单元交付时同步登记场景模板 `change-impact`（变更影响助手）：预置档案 `enabled_tools` 为本单元 Tool 集合，停用 + 空授权（Y4=a）；模板 key 即能力矩阵场景卡，默认绑定同 key 预置实例（spec 191，Y1/Y2=a）。system_prompt 只引用本单元 Tool，插画按 spec 201 T2 约定。
