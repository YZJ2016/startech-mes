### Business Goal

让 Agent（`POST /ai/agent/send`）的多轮上下文读写统一落 `ai_message`，与 chat 会话数据同源、`memoryId` 含租户与用户，避免进程内易失记忆导致刷新丢上下文或串会话。

Goal：`memoryId = {tenantId}:{userId}:{sessionId}` 可读可写 `ai_message`；跨租户 session 拒绝。

### Scope

In scope:

- 实现 LangChain4j `ChatMemoryStore`（或项目等价接口）：`getMessages` / `updateMessages` / `deleteMessages` 映射 `ai_message` + `ai_session`
- `ChatMemoryProvider` 返回的 id **冻结为** `{tenantId}:{userId}:{sessionId}`（`:` 分隔，数字转字符串）
- 与 66 共享 runtime 协作：agent 流结束写 assistant 行；Tool 回合按 LangChain4j 语义落库
- 加载历史时按 session 过滤本租户；禁止客户端传 `memoryId`
- 单测：Mock Mapper；跨租户 sessionId 不读写；memoryId 格式断言

Out of scope:

- 新 UI、Vue3 Agent 页
- Supervisor / 多 memory 合并
- 改 `POST /ai/agent/send` path 或基础 SSE 信封
- 独立「记忆导出」API
- 真实地址、凭据

Non-goals:

- 不用全进程 `InMemoryChatMemory` 作为生产默认
- 不为 memory 新造第二套消息表（除非 DDL 评审后仍用 `ai_message`）

### Acceptance Criteria

- Agent 多轮对话重启进程后仍可从 `ai_message` 恢复（同 session）
- memoryId 含 tenant + user + session；他租户 session → 404/403
- 与 chat 共用 `ai_session` / `ai_message` 租户规则（I-A1）
- 第 4 节未编码前不得写「测试通过」

### Rules and Constraints

Tenant isolation:

- memoryId 解析后必须匹配当前 `TenantContext` 与 `LoginUser`
- 禁止请求体指定 memoryId 绕过 session 校验

Security and masking:

- 消息内容按现有 AI 表规则；日志不打印密钥

Audit and lineage:

- 可选沿用 `ai_message` 既有 token 列；无新表亦可

AI/rule-engine rules:

- 对齐 A25：Provider id 含租户+用户+会话
- 不削弱 `POST /ai/chat/send` 落库时序

Database rules:

- 优先复用 `ai_message`；若需索引再开增量 SQL + include + catalog

## 2. Plan

### Implementation Approach

1. 新增 `AiMessageChatMemoryStore`（名可微调）实现 LangChain4j 接口。
2. 改 Agent 装配：`ChatMemoryProvider` 用新 Store + 冻结 memoryId 格式。
3. 与 66 runtime 对齐流结束 persist 钩子。
4. 单测覆盖 CRUD 与跨租户拒绝。

### Affected Modules

- `ktg-ai`：memory store、Agent 配置、测试
- 可能：`AiMessageMapper` 查询方法（无破坏性改表优先）

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- **冻结：** `POST /ai/agent/send` body 仍 `{sessionId?, modelId, content, agentId?}`（agentId 见 68）；SSE `{content, done}`
- 内部：`memoryId` 格式 `{tenantId}:{userId}:{sessionId}`

### Persistence Changes

Tables, indexes, migrations, mapper XML, and lifecycle rules:

- 默认无 DDL；若加 `(tenant_id, session_id, create_time)` 索引则增量 SQL

### Transaction Boundaries

- 单次 updateMessages 短事务；不包住整个 SSE 流

### Risks

- 与 chat 并发写同一 session 行冲突
- memoryId 与旧 Agent 内存实现不兼容导致空上下文

### Verification Strategy

- `mvn -pl ktg-ai -am test`
- 单测 memoryId 解析与跨租户
- 不跑 live 模型
