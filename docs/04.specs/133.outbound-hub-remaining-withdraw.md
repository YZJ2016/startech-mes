### Business Goal

对 **任意已过账（`FINISHED`）** 的其他出库 / 借料 / 采购退货整单（含旧页手工建单，**不依赖** `outboundpull` / 130），仓管在权限允许时可 **撤回**：出库过账是库存 −1，撤回是加回库存；写新 `wm_transaction` **反向 flag**，单据回到 `PREPARE`，并写审计日志。禁止物理删除历史流水；失败全滚。Hub 抽屉出按钮，实际调用各单据 withdraw。

### Scope

In scope:

- **仅** 已过账 `OTHER_ISSUE`、`MATERIAL_BORROW`、`PURCHASE_RETURN` **整单**撤回
- 校验可撤 → 新流水反向 flag 冲销库存 → 采购退货可退占用随 FINISHED 消失而回冲 → 状态回 `PREPARE` → `@Log`
- Hub 抽屉按钮转发：
  - `PUT /mes/wm/otherissue/{otherId}/withdraw`
  - `PUT /mes/wm/materialborrow/{borrowId}/withdraw`
  - `PUT /mes/wm/purchasereturn/{returnId}/withdraw`
- 权限：独立 `withdraw`（`mes:wm:otherissue:withdraw` / `mes:wm:materialborrow:withdraw` / `mes:wm:purchasereturn:withdraw`）+ **复用** `mes.wm.outbound.withdraw.enabled`（缺失/非法当 on）
- 工序：先采购退货，再其他出库，最后借料（D1 已锁 A，借料臂可编码）
- 单测：租户隔离；过账后再撤库存回到前值；采购退货 FINISHED→PREPARE 后可退余量回升；借料已还仍可撤；重复撤回拒绝；开关 off 拒绝；Hub **无**发料撤回

Out of scope:

- 出入库混用万能 withdraw（禁止复用 127 `InboundWithdrawSupport`）
- 领料 / 销售出库撤回（131；本刀不重开其 AC）
- 委外发料 Hub 拉单与撤回（Hub **禁撤**；133 **继续 OUT**，不补 API、不补按钮）
- 送货单进 UNION / 扣库存 / 当拉单目标 / 撤回（113）
- 112/129 的 Hub 拉单（130 对这两臂仍 OUT）；选仓弹层；物料默认仓
- 生产退料 / 销售退货 / 还料进出库 Hub
- 行级撤回、部分撤回、unconfirm、级联删下游
- 快财务应付冲减 / 付款退款 / `ReturnOpenBalanceOffsetService`
- CAT-W01 / W04 / W05 / W06 / W07；价目、UReport、Vue2、前端假分页
- 对照仓 React / Python / kuaizhizao 权限字、`MaterialStockMovement`、审核流
- 改 `frontend/`；扩 PermitAll

### Acceptance Criteria

1. 点名 **133**。Git 根 `startech-mes-basic/`。功能不依赖 130 / `outboundpull` / 选仓。编码工序：先 `purchasereturn`，再 `otherissue`，最后 `materialborrow`。
2. 仅 `FINISHED` 的三余型可撤；草稿/已撤/他类型/发料拒绝。手工建单过账后也必须可撤。
3. 出库过账是库存 −1，撤回是加回库存。撤回后同租户同仓同批次库存与过账前一致；失败全滚；**不**物理删历史 `wm_transaction`。拒撤基线（已锁）：并发双撤、非 `FINISHED`、开关 off、仓/批次档不在。下游已耗用默认加回仍允许，编码不得发明拒撤。**已还料不是拒撤理由**（D1=A）：`FINISHED` 借料已挂 119 还料（`PREPARE` 或 `FINISHED`）仍须可撤；只回滚借料本单库存；借料回 `PREPARE`；119 还料单据保持原状（不查、不拒、不级联撤还料、不回冲还料）。

5. 其他出库撤回 **不**回冲会计/价目（112 无金额过账副作用；快格撤回也不回冲会计事件）。
6. Hub：`FINISHED` 的三余型有「撤回」；`OUTSOURCE_ISSUE` / 送货单 **无**撤回按钮；入库 Hub 无出库撤回入口。131 两臂行为不回退。

- Hub list 可不破坏契约（前端按 `FINISHED` + 类型 + `withdraw` 权限显示按钮；服务端拒绝兜底）

### Persistence Changes

- **默认无新表**；新冲销行写入既有 `wm_transaction`
- 不新增 `sys_config` 键；可选 master 菜单按钮号段按当时目录顺延

### Transaction Boundaries

- withdraw：读单 → 校验开关/状态/租户（借料 **不**查还料，D1=A）→ 冲销库存 → 更新 `PREPARE`；任一步失败回滚。禁止先改状态再丢流水。

### Risks

| 风险 | 缓解 |
| --- | --- |
| 与 127 共用万能服务 | 复用 131 出库 service/support；扫描禁止依赖 `InboundWithdrawSupport` |
| 物理删历史流水 | AC 禁止；只插反向 flag |
| 抄 127 负库存拒单 | 出库撤回是加回库存。失败表见 T0 |
| 借料已还仍撤导致库存虚增 | **接受**的对照仓语义（D1=A）；只回滚借料本单库存，119 还料保持原状。不另开产品会 |
| 搬快财务应付 | T0 OUT；129 无应付字段 |
| 做成 unconfirm 两步 | 不新增路径 |
| 委外 Hub 可撤 | 128/本刀均禁；无按钮无 API |
| 打进 130 拉单/选仓 | 功能不依赖；Hub 只加撤回按钮 |

### Verification Strategy

- 单测：过账→撤→库存还原；采购退货可退余量回升；借料已还仍可撤且 119 还料原状；重复撤；跨租户；开关 off；发料无 API。

- 手验后置：Hub 抽屉三余型撤回成功与失败 toast。
