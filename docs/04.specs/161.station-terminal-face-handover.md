# 触屏工位机 — 刷脸、交接班与工序文档

本文件可实施。刷脸只切换 157 入口上的当前操作员。交接班与文档角标调用现有工位接口，文档正文打开 157 已挂的 kiosk 子页。

## 1. Spec

### Capability

- Name: 刷脸切换操作员、交接班、工单文档角标
- Module: `kuaigeyun-mes/riveredge-frontend` 工位入口。接口为现有 `/api/v1/apps/kuaizhizao/station` 的人脸、交接班与文档路由。
- Priority: STN-D8、STN-Q1、STN-Q2。依赖 157。
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/20.station-terminal-gaps.md`（**STN-D8**、**STN-Q1**、**STN-Q2**，以及「后端已有」人脸、交接班、文档行）
  - 设计：`docs/03.design/20.station-terminal-plan.md`（§3）
  - 入口与文档子页：`docs/04.specs/157.station-terminal-entry.md`

### Business Goal

工位保持终端账号的长期登录。刷脸或已有的点选用来切换当前操作员。交班时按本工位汇总并确认。工单列表标出 ESOP 与图纸，工序文档打开 157 已挂上的 SOP、图纸子页。

### Scope

In scope:

- 刷脸比对调用 `POST /api/v1/apps/kuaizhizao/station/face-identify`。`matched` 为真时，把返回的 `user_id` 与姓名写成 157 的当前操作员。响应里没有新的登录令牌；页面不保存、不替换终端账号的登录会话（**STN-D8**、**STN-Q2**）。
- 人脸登记、查看自己的、删除沿用现有接口，供比对有模板可用：`POST /station/face-templates`、`GET /station/face-templates/me`、`DELETE /station/face-templates/{template_id}`。登记不签发登录。`user_id` 已拍板，见下文。
- 交接班汇总：`GET /station/shift-summary`，查询带 157 的 `workstation_id` 以及班次起止。页面展示现有字段：计划数量、完成数量、不合格数量、停机分钟、安灯次数、报工次数。
- 交接班确认：`POST /station/shift-handover`，请求体带 `workstation_id`、`workstation_name`、班次起止与备注。现有接口把确认人记为当前登录用户。页面沿用该结果，确认人是终端账号。
- 工单列表 ESOP / 图纸角标：`GET /station/work-orders/document-flags`，查询参数 `ids` 为工单 ID 列表。有标记的工单可以进入工序文档。
- 工序文档：`GET /station/work-orders/{work_order_id}/operations/{operation_id}/documents`。返回的 SOP、工程图纸、物料附件、工单附件在页面上列出，并打开 157 已挂的 `sop-viewer/kiosk`、`drawing-viewer/kiosk`。工序文档响应没有程序代码或 URL 时，不猜测程序查看参数，不新增程序按钮。

Out of scope:

- 刷脸签发登录、刷新令牌或切换终端账号
- 新的人脸算法、新的交接班表、新的文档存储
- 资质维护、SOP 硬卡控开关（158）、快捷报工（159）、安灯发起（160）
- 标签工位、电视看板、小程序、企业微信、移动端复制页面
- 改 `startech-mes-basic`；把页面烤进 exe

### Acceptance Criteria

1. 比对成功后，入口上的当前操作员变为识别出的人员，随后的业务请求仍使用原来的终端账号登录会话。
2. 可以登记、查看自己的模板、删除自己的模板，这三步都不出现新的登录响应。
3. 交接班页按当前绑定工位显示汇总，确认后生成一条现有交接班记录，确认人是登录中的终端账号。
4. 工单列表能显示 ESOP / 图纸角标。从工序文档可以打开 157 已挂的 SOP 与图纸 kiosk，URL 不变。
5. 本单元没有新的人脸、交接班或文档接口。

### 已拍板

1. 采集库已拍板为 `@vladmandic/human` 的 HSE FaceRes。描述子从该库 `faceres` 里 `shape[1] === 1024` 的张量读出，经 `face.embedding` 交给页面。页面不用 `match.similarity`。度量仍是后端 `FaceTemplateService` 的余弦相似度，阈值保持 0.48。模型由浏览器按已安装包 `3.3.6` 的 `models/` 从 jsDelivr 下载后本地推理，不打进 Electron。长度不是 1024 时不发请求。登记 `POST /face-templates` 的 `user_id` 用工位入口传入的当前操作员（props `operatorUserId`），没有该 id 时登记按钮不可用。`GET /face-templates/me` 只列出当前登录用户。操作员与终端登录用户不是同一人时，页面说明这份模板不会出现在「我的模板」里。比对 `POST /face-identify` 成功后写入入口当前操作员，不换令牌。写入 `{ id: user_id, name: full_name 或 username }`。失败是 HTTP 400，页面显示后端 `detail`。
2. 工位与工单由工位入口经 props 传入：`workstationId`、`workstationName`、`workOrderId`、`operationId`。入口记住执行页选中的工单和工序。页面不读 URL `workstationId`，工单与工序只信 props。

### Rules and Constraints

Tenant isolation:

- 人脸模板、交接班与文档查询沿用现有租户隔离。

Security and masking:

- 人脸描述数据只提交给现有登记与比对接口。页面日志不写描述数据、令牌或口令。
- 比对结果写入入口当前操作员，不换令牌。

Audit and lineage:

- 交接班记录沿用现有 `shift-handover`。汇总数字来自现有 `shift-summary`，其中报工按 `workstation_id` 归属（报工写入见 159）。

AI/rule-engine rules:

- 不涉及。比对使用现有人脸服务。

Database rules:

- 无新表，无迁移。

## 2. Plan

### Implementation Approach

1. 在 157 入口增加刷脸入口：采集后调用比对，成功则调用 157 已有的「设置当前操作员」。
2. 交接班页先拉汇总，确认时提交现有交接班接口。
3. 158 的工单列表增加角标；点进工序后拉文档，并跳到 157 的 SOP、图纸 kiosk。

### 依赖

- 依赖 157 的入口、当前操作员状态、已绑定工位，以及已挂上的 SOP / 图纸 / 程序 kiosk。
- 汇总里的报工次数依赖产线已经用 159 的方式写入 `workstation_id`。页面本身可先于 159 合入，冒烟时再一起看数。
- 与 158、159、160 可先后实现。端到端冒烟在 162。

### Affected Modules

- 157 工位入口（当前操作员、刷脸、交接班、列表角标）
- 只调用 `api/station/station.py` 已有人脸、交接班、文档路由
- 跳转目标保持 `sop-viewer/kiosk`、`drawing-viewer/kiosk`。工序文档响应没有程序代码或 URL 时不打开 `program-viewer/kiosk`

### Public Contracts

- `POST /api/v1/apps/kuaizhizao/station/face-identify`
- `POST /station/face-templates`、`GET /station/face-templates/me`、`DELETE /station/face-templates/{template_id}`
- `GET /station/shift-summary`、`POST /station/shift-handover`
- `GET /station/work-orders/document-flags`
- `GET /station/work-orders/{work_order_id}/operations/{operation_id}/documents`
- 这些路由的字段与权限保持现有契约。

### Persistence Changes

- 无。当前操作员仍是 157 的页面状态。

### Transaction Boundaries

- 比对不写登录会话。
- 交接班确认沿用 `confirm_shift_handover` 的现有事务。

### Risks

- 比对成功后若更换登录令牌，就离开 **STN-D8**。
- 交接班查询不带 `workstation_id` 时，汇总会混入其他工位。
- 另做一套文档预览页会和 157 已挂的 kiosk 分成两套入口。

### Verification Strategy

- 见 §3。§4 在命令实跑后填写。本文件写下时未跑测试或构建。
