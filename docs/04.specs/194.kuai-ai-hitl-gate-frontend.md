## 1. Spec

### Capability

- Name: 对话中出现待确认写操作时，展示确认卡并提交确认/拒绝，续跑结果接回同一条对话。
- Module: `riveredge-frontend/src/apps/kuaiai/{services/chatApi.ts,pages/chat}`、`riveredge-frontend/src/components/ai-assistant/index.tsx`、`riveredge-frontend/src/apps/kuaiai/pages/trust`。
- Priority: P0。
- Related requirement/design documents: 需求 25 SC-D3、§4.4；设计 26 §9；前置 spec 193。

### Business Goal

用户在全宽对话页和右侧助手抽屉中都能清楚看到 AI 准备执行的动作（做什么、对哪张单、什么数量），一键确认或拒绝；未确认前业务数据不变。

### Scope

In scope:

- 解析 SSE 扩展帧 `kuaiai_interrupt`，在对应 assistant 气泡下渲染确认卡：动作中文名（目录 `label`）、参数摘要、过期时间、确认/拒绝按钮。
- 调 `POST /api/v1/core/ai/chat/resume` 并以与发送相同的流式解析接回回答与工具轨迹。
- 全宽 `/chat`（`chatApi.ts sendChatMessage`）与抽屉（`components/ai-assistant`，基于 `@ant-design/x-sdk useXChat`）两处接入。
- H1=a：抽屉在选用含写 Tool 的档案时先经 `POST /api/v1/apps/kuaiai/sessions` 建会话并在后续请求携带 `session_id`。
- H2=a：存在挂起确认卡时用户直接发送新消息，卡片转为“已取消（未确认）”，不阻止发送。
- 过期、已处理、404 的明确提示；按钮防重复提交（`Idempotency-Key` 沿用全站写防护约定）。
- 信任中心 HITL 卡文案随后端状态切换（禁止在 `not_ready` 时出现“已接入”）。

Out of scope:

- 参数编辑（H4=a，不做）。
- 工位端、移动端（另立）。

### Acceptance Criteria

1. 收到中断帧后气泡停止“思考中”，确认卡出现；未操作前不显示任何“已执行”字样。
2. 点确认：卡片变为“已确认，执行中”，随后显示工具结果与最终回答；点拒绝：卡片变为“已拒绝”，显示模型回复。
3. 过期或 404：卡片显示“已过期/已处理”，按钮禁用，不自动重试。
4. 连点只发一次 resume；网络失败显示错误与重试，不改变卡片终态。
5. 切换会话后返回，已落库的确认结果按历史消息正确回显（依赖后端落库）。
6. 写请求带 `X-Client-Channel: pc` 与 `Idempotency-Key`（全站写防护要求）。

### Rules and Constraints

Tenant isolation:

- 前端只持有不透明 `thread_token`，不拼装 thread_id。

Security and masking:

- 参数摘要只渲染后端给出的 `args_summary`，不在前端拼接业务字段；不在控制台打印 token。

Audit and lineage:

- 审计在后端；前端不另写。

AI/rule-engine rules:

- 前端不判断哪些 Tool 需要确认，只响应中断帧。

Database rules:

- 无。

Fixed findings（按「`pendingConfirmation`/`message.interrupt` 出现即视为新挂起」重构，不依赖后端 token 唯一性）：

- F-C1 续跑中二次中断被误判终态：`chat/index.tsx handleConfirmDecide` 与 `ai-assistant/index.tsx handleConfirmDecision` 改为「流中/流末出现 `pendingConfirmation` 一律换新 interrupt 回 pending」；全宽页用 `cardToken` 跟踪卡当前 key（连续多个 interrupt 不失配），收尾只清同 token 的非 pending 卡。抽屉 `ConfirmEntry` 由 token 比对改为 interrupt 对象标识比对（同 token 新对象也算新挂起）；`ToolConfirmCard` `expiredNotifiedRef` 复位依赖同样改为 interrupt 对象。
- F-C2 token 去重吞卡：`handleSend` onDelta 改为同 token 命中即更新 interrupt 并回 pending；异 token 时优先覆盖驻留的 `expired` 终态卡，否则追加。
- F-M1 H2 取消范围过宽：`cancelPendingConfirmCards(sessionId)` 只取消目标会话的 pending 卡；`selectedSessionId==null`（新建会话）不取消任何卡。
- F-M2 抽屉同类：新增 `hitlActiveSessionRef`（conversationKey → 最近发送实际携带的 session id），取消逻辑移入 `sendToChat`，仅当本次发送落进同一 kuaiai 会话才收口；换档案/无会话发送保持 pending。
- F-M3 多动作中断恒 422：`resumeChat` 新增 `actionCount`，`decisions` 按 `interrupt.actions.length` 展开同类型决策数组；两处调用方传 `interrupt.actions.length`。
- Minor：`handleSend` 失败/中止时回滚本次收口的 cancelled→pending；resume 在飞期间停止按钮不动作（`resumingRef`，resume 未接 signal，`signal: undefined` 死代码删除）；抽屉 `handleSubmit` 判定统一 `resumingRef.current`；中断后有生效确认卡时不再渲染空 assistant 气泡；`ToolConfirmCard` 非法 `expiresAt` 判 `isValid()`；`sendChatMessage`/`resumeChat` 非 SSE JSON 回退分支同样解析 `kuaiai_tool`/`kuaiai_interrupt`。

Behavior delivered:

- 全宽 `/chat` 与右侧抽屉在收到 `kuaiai_interrupt` 帧时各自渲染同一张确认卡：动作中文 label、参数摘要、业务对象、过期倒计时，仅「确认/拒绝」两键。
- 确认/拒绝调 resume（`{thread_token, decisions:[{type}], stream:true}`，写防护头+幂等键），续跑 SSE 走与发送同一解析路径，工具轨迹与最终回答接回原气泡；续跑中再次中断换新 token 则卡片回到待确认。
- H1=a：抽屉发送前对含写 Tool 的档案先建 kuaiai 会话并携带 `session_id`；判定/建会话失败照常发送，由后端确认闸明确报错。
- H2=a：挂起确认卡时直接发新消息 → 卡片转「已取消（未确认）」，不阻止发送。
- 404/倒计时归零 → 「已过期或已处理」终态禁按钮；网络失败 → 待确认态+错误+重试；连点只发一次 resume。
- `kuaiai_interrupt` 帧在两条解析路径都不进回答正文；前端只持不透明 token，只渲染后端下发的 args_summary。
- 信任中心 HITL 卡随后端 status 切换文案。
