## 1. Spec

### Capability

- Name: 入库 Hub — 入库侧拉单（IH-G11 / INV-A03）
- Module: **`startech-mes-basic/backend/ktg-mes`**（各入库单据 **从源单生成草稿** 的应用服务 + 可选预览 API）+ **`startech-mes-front/`**（**仅** Hub / 相关入库页「拉单」入口与选单弹层，UI-A）。**禁止**改 Vue2。**禁止**新建 CAT-U01 收货通知主档（除非会话改拍）。**本文件仅文档**；编码须点名 **126**。
- Priority: **P5 / 余型**（故意后开、不挡 105；**不是** 108–111 抛光；**不是** 委外后置本身）
- Related requirement/design documents:
  - 缺口 14：**IH-G11**、INV-A03；总览 **CAT-U01**（收货通知默认后置）、**CAT-W02**
  - 设计 14 §7.5；总控 104
  - 配对出库指针：缺口 15 **OH-G6**（出库拉单，**不进本单元**）
  - 既有单据：105 物料/成品、118 退料退货、119 还料、120 其他入库、121 半成品、122 客供（若已落）
  - 对照只读：快格 `InboundHubQuickPullKey` / `INBOUND_PULL_ACTION_RECEIPT_TYPES`

### Business Goal

仓管在入库 Hub（或对应入库页）可 **从源单据拉单** 生成目标入库草稿行，减少手工录入；服务端生成，禁止前端假分页拼单。

**现网事实（2026-09-17）：**

| 项 | 现网 | 126 假设 |
| --- | --- | --- |
| 拉单 API | **无** 统一 pull；入库多手工建单 + 选供应商/工单 | **新建** 按源类型的 pull 预览 + 创建草稿接口（可挂在各 Controller 或薄 `InboundPull` facade） |
| 采购源 | 物料入库有 `poCode`；深度采购/收货通知主档 **弱**（CAT-U01 后置）；有 `ItemPurchaseTask` 等遗留，**非**完整收货通知 | **P5 必做臂**：从 **采购订单/可解析采购行**（现网能读的最小源）→ `ITEM_RECPT` 草稿 |
| 工单源 | `ProWorkorder` 已有 | 从工单 → `PRODUCT_RECPT` / `SEMI_PRODUCT_RECPT` 草稿 |
| 退料/退货源 | `wm_rt_issue` / `wm_rt_salse` 已有（118） | 拉单创建 **已有类型草稿** 的场景有限；快格是从工单/销售单拉 → 退料/退货单 |
| 收货通知 ASN | MES **无** 对等 `receipt_notice` 业务表（对照仓有）；有 **送货单** `wm_delivery_notice`（113，出库域） | **ASN 主档默认 OUT**（CAT-U01 后置）；若仅「入库侧」需要通知，**不得**把 113 送货单冒充收货通知 |
| 委外拉单 | 无 WO | **OUT** 直至 CAT-O01/123+ |

**对照只读（快格拉单键 → 目标类型）：**

| QuickPullKey / action | 目标 Hub 类型 | 126 P5 |
| --- | --- | --- |
| `purchase_order` / pull_from_purchase_order | `purchase` → ITEM_RECPT | **纳入**（源=现网可读采购） |
| `receipt_notice` | purchase | **默认 OUT**（ASN 后置；见 T0） |
| `work_order` | finished / semi | **纳入** |
| `production_return` | production_return | **纳入**（从工单拉生产退料草稿） |
| `sales_return` | sales_return | **纳入**（从销售订单拉销售退货草稿；源不够则降级 OUT） |
| `outsource` | 委外三类 | **OUT**（后置 123–125） |

### Scope

In scope:

- **入库侧** 拉单：预览可拉数量 + 创建 **PREPARE** 草稿头/行（写回目标既有表）
- Hub 工具栏「拉单」菜单（Element Plus；不拷 AntD）
- 权限：沿用目标单据 `add` 权限；可选 `mes:wm:inboundhub:pull`（T0）
- 单测：租户隔离、超量不可拉、创建后可在 Hub 见到草稿

Out of scope:

- **CAT-U01 收货通知主档**（ASN CRUD/菜单）——明确后置；本缺口只锁「入库侧拉单」可追
- 出库拉单 **OH-G6**；委外拉单；客供扫码拉单
- 前端多源假分页；改 Vue2；改若依壳；自动确认过账（拉单只建草稿，过账仍走各单据 execute）

### Acceptance Criteria

1. 点名 **126**；至少 **采购→物料入库** 与 **工单→成品/半成品** 两臂可测。
2. 拉单只建 `PREPARE`；不绕过 IQC/FQC 闸（后续确认/执行仍卡）。
3. 无 `TenantContext` / 跨租户源单 → 拒绝。
4. 不创建 ASN 表；文档与代码不把 `deliverynotice` 称为收货通知。
5. §4 **编码已开** 并实跑 `WmInboundPullServiceTest` + `npm run build:prod`。

### Rules and Constraints

- 租户失败关闭；JWT；不进 PermitAll。
- 拉单服务 **不得** 直连任意 SQL / AI。
- 不写 yml 业务开关；可拉数量规则写死在 service（或日后 `sys_config` 限流类键，非本单元必须）。

## 2. Plan

### Implementation Approach

1. T0：点名 126；盘点采购/工单/销售可读 API。
2. 实现 facade + 两核心臂（采购、工单）。
3. Hub 拉单 UI；单测租户与草稿状态。
4. 条件臂（退料/退货）按源可用性增量。

### Affected Modules

- `ktg-mes` wm（+ 只读 pro/md）；Vue3 `inboundhub`（及必要选单组件）；**不改** 113 deliverynotice 语义。

### Public Contracts

- **保持** 各入库 CRUD URL。
- **增量** pull 预览/创建；不替换 list。

### Persistence Changes

- **无** 新业务头表（除非 T0 改拍 ASN）；仅写入既有入库表草稿行。

### Transaction Boundaries

- 创建草稿：一头多行同事务；预览只读。

### Risks

| 风险 | 缓解 |
| --- | --- |
| 拖进 CAT-U01 ASN | scope/T0 明文 OUT |
| 采购源不足导致空头单 | AC 允许降级；禁止假数据 |
| 拉单直接过账绕闸 | 只建 PREPARE |
| 与 OH-G6 范围搅在一起 | 出库拉单另缺口 |
| 委外未就绪 | OUT |

### Verification Strategy

- 单测：采购臂/工单臂租户；创建后 Hub list 可见。
- 手验：Hub 拉单 → 抽屉仍须走确认/执行闸。
