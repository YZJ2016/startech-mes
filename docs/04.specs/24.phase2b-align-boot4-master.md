## 2. Plan

### Implementation Approach

1. 确认 2a：`java.version=17`、`spring-boot.version=3.5.16`、`22` 聚合编过、`23` 五项静态已勾
2. 确认对照 `git rev-parse origin/master` = `a6ea55ecf74ae6cdb063f2b413d66a33f29bf828`
3. **一次一块**，建议顺序与差集一致：根 POM → `ktg-common` → `ktg-framework` → `ktg-admin`（启动类）→ `ktg-quartz` pom → `ktg-generator` pom。`ktg-system` 若 name-only diff 为空则 **不要**为「仪式感」整模块覆盖（避免再次冲掉 `selectUserByMobile`）
4. 每块：`git diff origin/springboot3 origin/master -- ruoyi-<mod>` 为清单，只合并这些文件，再机械替换包名
5. framework 覆盖 `SecurityConfig` 时若文件无 diff（实测 SecurityConfig **不在** springboot3…master 文件列表），**不要重拷**，以免误删 Provider
6. admin 只改 `RuoYiApplication` 的 DataSource import 时，核对启动注解与 exclude 数组仍在
7. mes 编译失败：记录 GAV/API，最小改；未知则先编再记

Boot 4 已知 API 差（来自实测 diff，实施时仍以对照文件为准）：

| 点 | 2a (springboot3) | 2b (master) |
| -- | ---------------- | ----------- |
| Boot | 3.5.16 | 4.1.0 |
| DataSourceAutoConfiguration | `org.springframework.boot.autoconfigure.jdbc` | `org.springframework.boot.jdbc.autoconfigure` |
| Web starter | `spring-boot-starter-web` | `spring-boot-starter-webmvc` |
| AOP starter | `spring-boot-starter-aop` | `spring-boot-starter-aspectj` |
| Druid | `druid-spring-boot-3-starter` | `druid-spring-boot-4-starter` |
| Jackson | `com.fasterxml.jackson.core` | `tools.jackson.core`（`SensitiveJsonSerializer` 等） |
| SpringDoc | 2.9.0 | 3.1.0 |
| MyBatis starter | 3.0.5 | 4.1.0 |

`StringUtils` 在 master 有大段增量：以对照覆盖 common 后跑编译，不要手工挑着抄。

### Affected Modules

- 改：根 POM、common、framework、admin 启动类、quartz/generator pom（以 diff 为准）
- 可能改：`ktg-mes` 最小编译修复
- 不改：`frontend/`、`RuoYi-Vue3-front`

### Public Contracts

- HTTP 契约与五项不变

### Persistence Changes

- 无

### Transaction Boundaries

- 无新边界

### Risks

- 未做 2a 就拷 master，mes 与平台同时炸
- 整模块覆盖 system/framework 冲掉手机号与 Provider（而这两文件在 Boot3→4 **可能无 diff**）
- 启动类仍 exclude 旧包名，Boot 4 编译或启动失败
- Jackson2 API 残留与 `tools.jackson` 混用
- 把 Vue3 或改名塞进来
