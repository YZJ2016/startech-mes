## 1. Spec

### Capability

- Name: S3 — 知识库 + 解析 + 单一 retrieval facade + `search_knowledge`
- Module: **业务**落 `kuaigeyun-mes` 的 `apps/kuaiai`（知识表/解析/检索/Tool）+ 复用 S2 `model_factory.build_embeddings` / chat 模型。**禁止**改白名单外 `core/ai`、`startech-mes-basic/`；不放开 KR-G0 例外以外的快格仓目录。
- Priority: P1（KR-X3；依赖 S1 会话与 S2 runtime/工厂）
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/16.kuai-ai-rebuild-gaps.md`（KR-D12、KR-I6、KR-G6/G7、KR-X3）
  - 设计：`docs/03.design/16.kuai-ai-rebuild-plan.md`（§9、§6 路径 E、§15 S3）
  - 上一单元：`135`；后续 `137`–`139`

### Business Goal

补齐知识库父表与文档挂接、按类型解析与 768 维 embedding、唯一 retrieval facade（压缩→展开→分库检索→RRF→打分失败保留 RRF→±1 扩窗）；纯对话可选 `knowledge_id` 注入与档案路径 `search_knowledge` Tool 共用该 facade。

### Scope

In scope:

- 新建 `apps_kuaiai_knowledge_bases`；documents 增 `knowledge_id` FK；复用 chunks/`embedding_vector vector(768)`
- 文档上传经既有 `file_uuid` 对象存储读流；解析路由（**与代码对齐**）：`pdf`→pypdf；`docx`→python-docx；`pptx`→python-pptx；`xlsx`/`xls`→openpyxl（真实 OLE2 `.xls` 无轻量解析器，失败关闭）；`md`/`txt`→文本（utf-8，失败回落 gb18030）；`doc`/`ppt` 旧二进制**明确拒绝**（提示转 docx/pptx，不装重型依赖）；魔数/空文本 → `status=failed` + `error_message`，不落乱码 chunk
- 切块：`langchain-text-splitters==1.1.2`；库级参数可空回落租户可运营配置；`overlap > 0` 且 `< chunk_size`
- embedding：绑 `model_type=embed` 目录行；**未绑则用本租户第一条启用的 embed 模型**；仍然没有则解析失败，不得标成功；≠768 失败关闭
- 单一 `retrieval` facade（压缩→**有限展开默认开启、条数小、可配置关闭**→分库检索→RRF→打分失败保留 RRF→±1 扩窗）；删文档同事务软删 chunks；重解析；片段浏览只读
- `search_knowledge` Tool（档案 `knowledge_ids` 闭包，调用复核归属）；纯对话可带一个请求级 `knowledge_id`
- 知识 REST（契约表 knowledge-bases/documents/chunks/parse）
- 解析等异步任务（taskiq）：必须拷贝租户与用户上下文，空上下文失败关闭（KR-I6）

Out of scope:

- HyDE、OCR 扫描件、BM25/hybrid、单次多向量库融合、外部向量、换维迁列（KR-D18/KR-G7）
- FAQ 列产品化、`apps_kuaiai_training_samples` 产品接入
- MCP（S4）；前端页（S5）；`structured_draft`（S6）
- 确认闸、工作流、审计查询页
- 第二套 RAG（`rag_backend=llamaindex` 废弃，不并存）

### Acceptance Criteria

1. 库/文档/切块/parse REST 与权限同契约表；跨租户 404/403。
2. 解析失败不落乱码 chunk；未绑 embedding 用本租户第一条启用 embed；仍无则解析失败不得标成功；≠768 维失败关闭；禁止扫盘/未隔离临时语料库。
3. 检索唯一入口：压缩失败回退原句；有限展开默认开、条数小、可配置关闭；打分失败保留 RRF；±1 扩窗禁止整篇；无命中仍纯对话。
4. 选中档案不接受请求级 `knowledge_id`；只用档案库 id 经 `search_knowledge`。
5. 解析异步任务拷贝租户/用户上下文；空上下文失败关闭（KR-I6）。
6. 不引入 HyDE/OCR 扫描件/外部向量/第二 RAG 栈。

### Rules and Constraints

Tenant isolation:

- 检索 SQL 必 `tenant_id` + 已校验 `knowledge_id`；空上下文不得检索。
- 解析 taskiq job 必须拷贝租户与用户上下文（KR-I6）。

Security and masking:

- 注入片段 metadata 仅 `file_name`（文档 title，**与代码对齐**作 source_ref 等价）；不落 Key。

Audit and lineage:

- Tool 级审计经既有 `wrap_tool_call`（S2）。

AI/rule-engine rules:

- 档案 `knowledge_ids` = 库 id，非文档 id。
- 有限展开默认开启、条数小、可配置关闭（租户可运营配置，不新写 yml）。

Database rules:

- 新建 bases；documents 改表加 FK；chunks 复用；FAQ/training 不接产品。

### 依赖上一单元

依赖 **S1（134）** 会话/委托与 **S2（135）** 的 `model_factory`（chat+embed）、Tool 桥接与档案 `knowledge_ids` 字段。无 S2 工厂不得本单元硬编码厂商客户端。

## 2. Plan

### Implementation Approach

1. bases 表 + documents FK 迁移；知识 REST。
2. parsers + 切块 + embedding 写入（768 关闭）。
3. `retrieval.retrieve` 七步流水线。
4. 接通纯对话注入与 `search_knowledge` Tool。

### Affected Modules

- `apps/kuaiai`：knowledge models/api/services、`document_parsers`、`retrieval`、`chat_service` 注入点、Tool 实现

### Public Contracts

- 见 §1；本单元落地 knowledge-bases/documents/chunks/parse。

### Persistence Changes

- **与代码对齐：** `apps_kuaiai_knowledge_bases` 列实落 `name`/`description`/`embedding_model_id`/`chunk_size`/`chunk_overlap`/`expand_enabled`/`status`（相对 KR-D12 字段清单：`desc`→`description`；增 `expand_enabled`；**未落** `chunk_separator`/`top_k`/`min_score` 列——`top_k` 为 `retrieve(..., top_k=5)` 参数，`min_score` 本期未用，切块分隔符用 `RecursiveCharacterTextSplitter` 默认；需求表字段清单不在本单元改）
- `apps_kuaiai_knowledge_documents.knowledge_id`；chunks 复用（迁移 395/517 `embedding_vector vector(768)`+HNSW）

### Transaction Boundaries

- 删文档同事务软删 chunks；解析失败不标成功且不残留半截成功向量（失败关闭）。

### Risks

- 无 ORM 拦截器 → 检索 helper 强制 tenant 过滤 + 单测。
- 真实 embedding 维度漂移 → 严格 768 失败关闭。

### Verification Strategy

- 见 §4；mock embed/chat 测 RRF/打分回退/跨租户。
