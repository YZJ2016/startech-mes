# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 后端换壳阶段 1 总控（内容替换，不改模块名/包名）
- Module: `startech-mes-basic/backend` 的 `ktg-quartz` / `ktg-generator` / `ktg-common` / `ktg-system` / `ktg-framework` / `ktg-admin`
- Priority: P0
- Related requirement/design documents:
  - 抽出历史：`docs/04.specs/00.backend-extract-program.md` 至 `09.platform-purity-gate.md`
  - 合入审查与五项接线：`docs/04.specs/10.backend-extract-review.md` 第 7 节
  - 本批开发单元：`12`–`17`；全量门禁：`18`

### Business Goal

在 **Java 8 + Spring Boot 2.5.x** 上，用若依 `RuoYi-Vue` 的 **`origin/springboot2`（3.9.2）** 内容替换六个平台模块的源码，使平台层贴近上游，同时 **MES 721 个业务文件留在 `ktg-mes`**，现网五项接线不丢。不改 Maven 模块名 `ktg-*`，不改包名 `com.ktg`。本文件只约束阶段 1 的对照源、顺序、工作树、git 边界、完成定义；不写业务代码。

### Scope

In scope:

- 阶段 1：按模块把 `ruoyi-*` **内容** 换入对应 `ktg-*`（机械替换 `com.ruoyi` → `com.ktg` + 五项接线）
- 对照源锁定为下方实测 commit，**不是** 当前 `RuoYi-Vue` checkout 的 `master`（Java 17 / Boot 4.1 / jakarta）
- 改动只发生在 nested `startech-mes-basic`；外层 `RuoYi-Vue` / `RuoYi-Vue-springboot2` / `RuoYi-Vue3-front` 只读
- 允许根 POM `spring-boot` **2.5.12 → 2.5.15**，以及 springboot2 3.9.2 带来的同代依赖对齐（仍 Java 8 / javax / Security 5）
- 五项接线在换壳当时做完（清单见下，细节链到 `09`/`10`，不另发明）

Out of scope（阶段 2，另立项；**不得写入 `12`–`17` 的必做列表**）：

- Java 8 → 17
- Spring Boot 2.5 → 3.x / 4.x
- `javax` → `jakarta`
- 模块改名为 `ruoyi-*`
- 包名改 `com.ruoyi`
- 前端 Vue2 换 Vue3；不碰 `RuoYi-Vue3-front`；不改 `startech-mes-basic/frontend/`
- 改 `ktg-mes` 的 721 个业务 Java（除非某单元为编译闭合必须给 `ktg-mes/pom.xml` 补依赖，例如保留 fastjson1）
- 用 `master` 树做对照或复制

### Acceptance Criteria

- `12`–`17` 各有独立 spec，顺序与本文件模块表一致；`18` 为阶段 1 全量门禁
- 每个模块换完后 **JDK 8 编译通过** 才允许下一个；未跑通的命令不得写「已通过」
- 模块目录名、`<modules>`、`artifactId` 仍为 `ktg-*`；Java 包仍为 `com.ktg`
- `ktg-mes` 仍在聚合工程中；admin 仍依赖 `ktg-mes`
- 五项接线在 `17` 结束时全部满足，并在 `18` 再勾一次
- 文档、补丁、日志不出现真实密码、Token、生产地址、数据库连接串

### Rules and Constraints

Tenant isolation:

- 本批不引入租户字段，不改变现有数据隔离方式

Security and masking:

- 不在 spec、补丁、日志中复述 Token、Minio/OSS 密钥、数据库口令或内网地址
- yml **只对键、不对密钥**：对照 springboot2 的键名，值留在 nested 现有文件中，不把对照仓或现网的 secret 抄进文档
- 不得扩大匿名访问面；`MesPermitAllProvider` 的路径集合以抽出后 `08` 为准
- 不引入第二套认证；继续 JWT `Authorization`

Audit and lineage:

- 历史 SQL（`backend/sql/`、`backend/doc/`）不原地改写；若 3.9.2 新表（例如 `SysNoticeRead`）需要脚本，另开增量文件，不在本总控当必做
- 换壳是内容替换 + 接线，不是借机改工单/库存状态机

AI/rule-engine rules:

- 本批不涉及规则引擎或 AI

Database rules:

- MES 业务表本批不改结构
- 禁止把 mes 公告已读字段（`userId1` / `readStatus`）接回平台 `SysNotice`；已读仍走 mes `SysNoticeListVo` / `SysNoticeDetail`（见 `05`/`10`）

## 2. Plan

### Implementation Approach

#### 对照真源（实测，2026-08-20）

在外层 `RuoYi-Vue` 目录执行 `git fetch` 后：

| 项 | 值 |
| -- | -- |
| 远程分支 | `origin/springboot2` |
| **完整 commit** | `913524b1525a0e374774afbb54c452d8f68a5a8f` |
| 该 commit 说明 | `update README.md`（2026-08-17） |
| `java.version` | `1.8`（`git show origin/springboot2:pom.xml`） |
| `spring-boot.version` | `2.5.15` |
| `ruoyi.version` | `3.9.2` |
| **禁止当对照的 checkout** | 当前 `RuoYi-Vue` 的 `master`（`a6ea55ec…`，`java.version=17`，`spring-boot.version=4.1.0`，jakarta） |

阶段 1 复制源码前必须 `git rev-parse` 确认工作树 HEAD 等于上表完整 hash。hash 漂移则停止，先更新本文件再开工。

#### 工作树（外层，只读对照）

不要在 `RuoYi-Vue` 的 `master` 工作区改文件或提交。建议另建 worktree：

```text
# 外层仓库根目录
git -C RuoYi-Vue fetch origin refs/heads/springboot2:refs/remotes/origin/springboot2
git -C RuoYi-Vue rev-parse origin/springboot2
# 期望：913524b1525a0e374774afbb54c452d8f68a5a8f

git -C RuoYi-Vue worktree add ../RuoYi-Vue-springboot2 origin/springboot2
```

之后 `12`–`17` 的对照路径一律写：

- 对照根：`RuoYi-Vue-springboot2/`（或等价 worktree）
- 模块：`ruoyi-quartz` → `ktg-quartz`，其余同理

外层 `.gitignore` 已忽略 `/RuoYi-Vue/`、`/RuoYi-Vue-springboot2/`、`/RuoYi-Vue3-front/`。**不要** `git add` 若依源码到外层仓库。

#### git 边界

| 仓库 | 角色 | 本批 |
| ---- | ---- | ---- |
| 外层 `startech-mes` | 文档 / `.gitignore` | 只写 spec；**不 commit 除非用户另要求** |
| nested `startech-mes-basic` | 唯一改 Java 的地方 | 实施 `12`–`17` 时在此提交（本总控任务 **不改 Java、不 commit、不 push**） |
| `RuoYi-Vue` 及其 worktree | 对照 | 只读；禁止把业务改动提交进去 |
| `RuoYi-Vue3-front` | 无关 | 不碰 |

实施前：`git rev-parse --show-toplevel` 必须是 `…/startech-mes-basic`，分支建议继续 `upgrade/ruoyi-framework`（或用户指定的换壳分支）。不要把 nested 文件 `git add` 到外层。

#### 机械替换（每个模块相同）

1. 用对照树 `ruoyi-<mod>/` 覆盖 nested `backend/ktg-<mod>/` 的 **src**（及该模块 pom 中与上游对应的依赖声明）
2. 全模块将 `com.ruoyi` → `com.ktg`（Java、XML namespace、vm 模板、注释中的包名）
3. 该模块 `pom.xml`：`artifactId` `ruoyi-*` → `ktg-*`；parent 保持 `com.ktg:ktg` + nested 现有 parent 版本（当前 `3.8.2`，不必改成若依产品号 3.9.2）；`${ruoyi.version}` → `${ktg.version}`
4. **禁止** 改目录名、聚合 `<modules>` 里的 `ktg-*`、`groupId` `com.ktg`
5. 做该模块 spec 列出的接线，然后 JDK 8 编译

根 `backend/pom.xml`：保留 `<module>ktg-mes</module>` 与 `com.ktg` / `ktg`。允许按需把 `spring-boot` 升到 **2.5.15**，并纳入 springboot2 的同代属性（仍 Java 8）。禁止引入 Boot 3/4、Java 17、jakarta 坐标。

#### 模块顺序（一次一块）

| 顺序 | 单元 | 模块 | 本块必须留下/并入的接线 |
| ---- | ---- | ---- | ---------------------- |
| 1 | `12` | `ktg-quartz` | 无五项；编译过再往下 |
| 2 | `13` | `ktg-generator` | vm 模板里的 `com.ruoyi` 一并替换；不改 Vue2 工程 |
| 3 | `14` | `ktg-common` | **留下** `MesPermitAllProvider`；mes 若仍 import fastjson1 则给 `ktg-mes/pom.xml` 补 fastjson1，**不改 721 个业务文件** |
| 4 | `15` | `ktg-system` | 留下 `selectUserByMobile`；**不要**把已读字段接回 `SysNotice` |
| 5 | `16` | `ktg-framework` | `SecurityConfig` 继续读 `MesPermitAllProvider`；`UserDetailsServiceImpl` 并入手机号登录 |
| 6 | `17` | `ktg-admin` | 前缀 `ktg-mes:`→`ruoyi:`；删换入的若依 `GET /system/notice/list`；保留 mes `POST /common/uploadMinio`；启动类保留 `@EnableAsync` / `@EnableScheduling`；yml 只对键 |
| 7 | `18` | 全量 | 编译 + 纯度回归 + 五项勾选；运行时标未验证 |

对照源的 `SecurityConfig` 在 springboot2 上已是 **Spring Security 5.7 + `SecurityFilterChain`**（仍 Boot 2.5.15 / javax），不是 Boot 4 / Security 6。阶段 1 **允许**随 `16` 换入该形态；禁止借此跳到 Boot 3/4。

#### 五项检查单（与 `10` 第 7 节同一套，换壳当时做）

1. 配置前缀 `ktg-mes:` → `ruoyi:`（`RuoYiConfig` + admin yml 根键）
2. 带走 `com.ktg.common.security.MesPermitAllProvider` 接口；framework 继续 `@Autowired(required = false)` 注入；实现仍在 `ktg-mes`
3. mes 保留 `GET /system/notice/list`（`SysNoticeListController`）；**删除**换入的若依 `SysNoticeController` 上的 `/list`
4. mes 保留 `POST /common/uploadMinio`（`MesMinioUploadController`）；换入的 `CommonController` **不得**再声明同路径
5. `UserDetailsServiceImpl` 并入手机号判断：命中手机号则 `selectUserByMobile`，否则 `selectUserByUserName`；正则与抽出后 nested 实现一致；无第二套 JWT

`ktg-mes` 路径冻结（换壳不得改 URL）：

- `GET /system/notice/list`
- `POST /common/uploadMinio`
- `08` 的 permitAll 集合（`/mobile/login/**`、`/loginOuth`、`/ureport/**`、`/websocket/**`、`/system/autocode/get/**` 等）

### Affected Modules

- 改：`ktg-quartz`、`ktg-generator`、`ktg-common`、`ktg-system`、`ktg-framework`、`ktg-admin`，以及根 POM 属性（按需）
- 原则上不改：`ktg-mes` 业务源码；`frontend/`
- 例外：`ktg-mes/pom.xml` 可补 fastjson1 等传递依赖，避免 721 文件为换壳改 import

### Public Contracts

- HTTP 路径、方法、`code/msg/data`、`Authorization` 保持兼容
- 标准 `/login` `/logout` `/captchaImage` 不丢
- 配置根键从 `ktg-mes:` 改为 `ruoyi:`（部署侧同步键名，**不在文档写值**）

### Persistence Changes

- 总控不新增表。`SysNoticeRead` 若随 3.9.2 源码进入 `ktg-system`，阶段 1 不与 mes 已读合并、不把字段接回 `SysNotice`；缺表不在本批强行建，除非运行时另立项

### Transaction Boundaries

- 各模块单元自己的事务；总控不跨模块开事务

### Risks

- 误用 `RuoYi-Vue` `master`（Boot 4 / jakarta）当对照，一次跳栈
- 改模块名为 `ruoyi-*` 或包名为 `com.ruoyi`，Vue2 与 mes 全线编译失败
- 覆盖 `ktg-common` 时丢掉 `MesPermitAllProvider`，匿名面丢失或误放到 `SecurityConfig` 字面量
- 换入若依 `/list` 与 mes 列表双映射
- 换入 `CommonController` 覆盖或漏接 `/common/uploadMinio`
- 换入 `UserDetailsServiceImpl` 丢掉手机号登录
- 用若依 yml **整文件覆盖** nested，把密钥/库地址写丢或写错（只对键）
- 覆盖 admin 时删掉 `ktg-mes` 依赖或 antrun，或清空已打包的 `static/`
- 把 mes 的 `com.alibaba.fastjson` 调用改成改 721 文件，而不是补依赖
- `12`/`13` 换入后引用了尚未换入的 3.9.2 common 新类型：停止，先评估，不要偷偷把 common 拆进本块

### Verification Strategy

- 每模块用该 spec 第 3 节 Verification 列；统一 JDK 8 + `-Dmaven.antrun.skip=true`（PowerShell 必须给 `-D` 加引号）
- 波次结束用 `18` 做全量编译、纯度回归、五项勾选
- 不声称测试通过，除非该命令已跑且成功

本机若默认 `java` 为 JDK 21，必须设 `JAVA_HOME` 为 JDK 8（抽出确认曾用 `C:\Program Files\Java\jdk1.8.0_492`，以实施机为准）。
