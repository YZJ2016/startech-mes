### Business Goal

销售出库在 Hub 仍可见（107 已做）。本单元在产品拍板闸键、合格语义与必检判定之后，让必检出货未合格不得过账。旧销售出库 URL 保留。不把 OQC 打进 107。

**现网事实（禁止臆造）：** `QcOqcController` `/mes/qc/oqc` 已存在。`WmProductSalse` 已有 `oqcId`/`oqcCode`；旧页 `productsalse/index.vue` 可选手动关联。本单元前 `PUT /mes/wm/productsalse/{salseId}` **不读、不卡** OQC（有行即 `processProductSalse`）。销售出库无独立 confirm 步（OH-D6）。Hub 抽屉本单元前无 OQC 块。

**编码门禁（本会话已满足）：** 开工会话点名 115；§7.4 拍板项书面确认如下。禁止臆造第二套出货检表、禁止复用 `mes.wm.inbound.iqc.gate.*` / `mes.wm.inbound.fqc.gate.*`。

**拍板（本会话）：**

- 闸键：`mes.wm.outbound.oqc.gate.execute` 默认 `on`；缺失/非法当 `on`。无确认闸键（OH-D6）。
- 合格：OQC `checkResult == ACCEPT` 且状态非 `PREPARE`。
- 必检：物料绑定 OQC 模板（`qc_types` 含 `OQC`）。无模板 / 未要求不挡。禁止「仅当头已挂 oqcId 才卡」。
- Hub 预览 GET：`GET /mes/wm/productsalse/{salseId}/oqc-gate`；`@PreAuthorize` 现网 `mes:wm:productsalse:query` 或 `mes:wm:outboundhub:list`。不进 `MesPermitAllProvider`。
- UI-A：只动 Hub 抽屉。不重排 `productsalse/index.vue`；OQC 列表仅可选 `oqcCode` query hydrate。
- 真源：现网 `qc_oqc` + 头 `oqcId`/`oqcCode`。不加第二套表、不加 `salse_id` 列。
