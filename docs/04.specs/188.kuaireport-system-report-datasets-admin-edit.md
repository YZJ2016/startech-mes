# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 星报表 — 系统报表专属数据集与管理员可编辑
- Module: **仅** `kuaigeyun-mes` 的 `apps/kuaireport`（后端 slices 146/149/150，前端 reports/wizard、reports 列表）。不改 `startech-mes-basic`。
- Priority: KRP-D6 收口。在 146/150 之后。
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/18.kuaireport-selfdev-gaps.md`（KRP-D6）
  - 前段：`docs/04.specs/146.kuaireport-center-system-reports.md`、`docs/04.specs/150` 向导
  - 用户拍板（2026-10-14）：绑定走 `report_config.dataset_uuid` 直连；编辑入口走自制报表向导；数据集建绑并进种入；SQL 口径由实现先写一版、逐张验收

### Business Goal

10 张系统报表（KRP-D6）从「空壳 + 全站只读」变为「每张绑专属平台数据集、可打开出数，且系统管理员可在向导里改列/筛选/图表」。新租户安装/启用时同样开箱可用。

### Scope

In scope:

- `seed_system_reports` 扩展为幂等三步：确保 `system_default` 数据连接存在（`IntegrationConfigService.ensure_system_default`）→ 为每张系统报表建 `core_datasets` 行（`query_type='sql'`、`output_type='list'`、按报表 code 查重）→ 写入/补齐 `report_config` 为向导形状（`chart_type='table'`、`dataset_uuid`、`fields`、`parameters=[]`、`interaction`、page_size）。已有 `dataset_uuid` 的报表行不覆盖（管理员改过的配置不被种入回刷）。
- `s146_center._rebind_missing_sources`：跳过 `report_config` 顶层已带 `dataset_uuid` 的行——否则登记任一 dataset 数据源后回绑会盖掉直连绑定。
- `s150_wizard.save_wizard_report`：`existing.is_system` 且管理员（`is_admin`）放行更新；系统报表 `code` 创建后不可改（body.code 与存量不一致时报错），`category`/`is_system` 保持 `system`/`true` 不被改写。
- 前端 `reports/wizard.tsx`：`is_system` 的 readOnly 仅对非管理员生效；系统报表页签「编辑」改跳 `/apps/kuaireport/reports/{id}/edit`（向导），非管理员进入仍是只读。
- 10 张报表各配一条数据集 SQL（按现有业务表写一版可运行口径，交付附逐张字段清单）。

Out of scope:

- 设计器（s147）对系统报表放开编辑——保持只读预览。
- 登记数据源绑定路径（`extra.data_source_uuid`）继续存在但不再是系统报表的绑定方式。
- 大屏、分享、订阅、版本回看。
- 数据集 SQL 的业务精修（验收后按缺口单走）。

### Acceptance Criteria

1. 种入后每张系统报表 `report_config.dataset_uuid` 指向本租户一条专属 `core_datasets` 行（`tenant_id` 一致、`is_active=true`），打开 `/apps/kuaireport/reports/view/{id}` 返回 `data`/`total`/`summary` 不再报「报表未绑定数据源」。
2. 重复执行种入不产生重复数据集/报表行；管理员在向导里改过的报表不被种入回刷。
3. 管理员在向导里可编辑并保存系统报表（数据集、列、筛选、图表、发布状态）；非管理员打开仍是只读；`code` 不可改。
4. 登记过 dataset 数据源后，列表回绑不再覆盖已带 `dataset_uuid` 的报表。
5. 删除 `apps_kuaireport_data_sources` 行的保护（`_report_binds_source`）不受影响。

### Rules and Constraints

Tenant isolation:

- 数据集、报表、连接都带 `tenant_id`；无租户上下文不种入。

Security and masking:

- 数据集 `query_config.sql` 只查本租户业务表并带 `tenant_id` 条件；不写密文。

Audit and lineage:

- 数据集/报表创建沿用 `created_by`/`created_by_name` 已有列。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 不加列、不加表。只写 `core_datasets` 与 `apps_kuaireport_reports.report_config` 行数据。

### 依赖顺序

- 依赖 145 `execute_report` 的 `dataset_uuid` 直连分支与 150 的向导保存。
- 不依赖 147 设计器改造。

## 2. Plan

### Implementation Approach

1. 按域查表现状，写 10 条数据集 SQL（`sysrep_<code>` 编码），`display_config.columns` 同步给出列清单供向导字段检测。
2. `s146_center` 新增种入 helper：建/取数据集 → 组装向导形状 `report_config` → 只对缺 `dataset_uuid` 的系统报表回写。
3. `_rebind_missing_sources` 增加守卫：已带顶层 `dataset_uuid` 的行不回绑。
4. `s150_wizard`：`existing.is_system` 且 `is_admin` 放行；code 不一致报「系统报表编码不可修改」。
5. 前端 wizard：`readOnly = (is_system || category==='system') && !admin`；列表系统页签编辑跳 `/reports/{id}/edit`。
6. 本租户实跑一次种入，逐张验证 execute 返回数据。

### Affected Modules

- `riveredge-backend/src/apps/kuaireport/slices/s146_center.py`
- `riveredge-backend/src/apps/kuaireport/slices/s149_distribution.py`（回绑守卫，同文件内的 `_rebind_missing_sources` 在 146）
- `riveredge-backend/src/apps/kuaireport/slices/s150_wizard.py`
- `riveredge-frontend/src/apps/kuaireport/pages/reports/index.tsx`、`reports/wizard.tsx`
- 种入调用方不变（`application_service` 安装/启用入口）

### Public Contracts

- `report_config` 顶层 `dataset_uuid` 直连契约（与 150 向导产出一致）。
- 系统报表更新仍走 `PUT /apps/kuaireport/reports/{id}`（权限 `kuaireport:report:design` + 服务端 admin 校验）。

### Persistence Changes

- 无新表新列。新增 `core_datasets` 行（每租户至多 10 条，code `sysrep_*`）。

### Transaction Boundaries

- 每张报表的「建数据集 + 回写 report_config」在同一事务；10 张幂等可重入，中途失败已种入的 code 不重复建。

### Risks

- 10 条 SQL 口径是实现先行版，可能与预期业务口径有偏差——交付附逐张字段清单验收。
- 老租户已有空壳行：种入补齐只写缺 `dataset_uuid` 的行；若管理员已改过配置则不回刷。

### Verification Strategy

- 后端 `uv run pytest`；前端 `npm run build`。
- 实跑种入后逐张调 `execute_report` 验证返回。

Result:

- 种入幂等：二次执行 `inserted=[]`，不重复建行；缺 `dataset_uuid` 的老行被补写向导形状配置。
- 10 张系统报表全部可执行（不再报「报表未绑定数据源」）。
- 向导管理员编辑：后端放行 admin 更新 `is_system` 行，`code` 不一致报「系统报表编码不可修改」；`category`/`is_system` 服务端锁死。非 admin 更新系统报表仍 `AuthorizationError`。
- 前端：系统页签「编辑」对管理员跳 `/apps/kuaireport/reports/{id}/edit`；非管理员仍进设计器只读。向导内 `code` 与「报表归属」对已存在系统报表禁用。

Known gaps:

- 数据集 SQL 口径为先行版，逐张字段清单随交付给出，业务精修另立缺口。
- 租户业务数据稀疏，多数报表当前返回空集（执行链路与 SQL 本身已验证可用）。
- `biz_overview` 等指标口径仅汇总计数/金额，未做同比环比。

## 5. Final Summary

Files changed:

- `riveredge-backend/src/apps/kuaireport/services/system_report_dataset_service.py`（新）：10 条 `sysrep_*` 数据集定义（SQL + 列清单）、幂等创建、向导形状 `report_config` 组装。
- `riveredge-backend/src/apps/kuaireport/slices/s146_center.py`：种入改为「确保专属数据集 → 写 dataset_uuid 配置」，并对已存在但缺绑定的行补写；`_rebind_missing_sources` 优先补专属数据集，目录外系统行才回绑租户首条 dataset 源。
- `riveredge-backend/src/apps/kuaireport/slices/s150_wizard.py`：admin 可更新系统报表，code/category/is_system 锁死。

- `riveredge-frontend/src/apps/kuaireport/pages/reports/wizard.tsx`：系统报表 readOnly 仅非管理员；编辑态锁 code 与归属。
- `riveredge-backend/tests/apps/kuaireport/test_146_center.py`、`test_150_wizard.py`：同步新契约断言。

Behavior delivered:

- 每张系统报表绑定专属 `sysrep_<code>` 数据集（`system_default` 连接、SQL 自带 `tenant_id` 条件），预览/Excel 直接出数。

- 管理员可在向导改列/筛选/图表/发布状态；编码与归属不可改。
- 新租户安装/启用时种入自动建绑，开箱可用；系统数据集定义漂移时按代码口径刷新。
