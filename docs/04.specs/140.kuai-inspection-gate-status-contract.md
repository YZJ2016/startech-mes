### 产品规则（已确认，禁止再开放成待定）

1. 无策略（source `default_none`）时：成品入库、采购来料、客供料登记都默认必检，与 `require_fqc_before_finished_goods_receipt`、`require_incoming_inspection_for_receipt`、`require_incoming_inspection_for_customer_material` 的存值无关。这三个开关下线或只读，不参与 skip。不做把存量 False 翻成 True 的数据迁移。
2. 免检只认 source `material` 且 eff 为 `none`。eff 全集为 `none` / `simple` / `plan`。source 全集为 `default_none`、`material`、`material_legacy`、`material_group`、`stage_disabled`、`module_disabled`、`work_order_override`、`work_order_operation`、`operation`、`operation_legacy`。`material` 在 `inspection_stages` 非空且 iqc/fqc/oqc 至少一环节 mode 不是 `none` 时出现；当前环节 mode 为 `none` 时仍是显式免检。三环节都是 `none` 或未配置时 source 为 `default_none`。`stage_disabled` / `module_disabled` 保持环节或模块未启用，不改判成无策略必检，也不当作免检。`material_legacy` / `material_group` 只在 mode 不是 `none` 时返回。IPQC 的四个 source 不作为物料免检口。
3. 成品入库入参 `work_order_id` 为空不得绕开 FQC。
4. 检验单质量态 = 中文「合格/不合格/待判定」；批次账 = `qualified` / `pending_qc` / `quarantine` / `unqualified`。成品入库过批次写 `qualified`，查检验单用「合格」。
5. 工单模型状态保持英文枚举；半成品一键入库同时接受中文「进行中」「已完成」与英文 `in_progress` / `completed`。
6. 范围仅检验与入库确认相关状态。采购退料不纳入。委外收货不新造检验类型。
7. **建单出口（评审拍板①）**：`default_none` 必检物料不补建单通道——客供料登记/FQC 工单建单路径维持对 eff=`none` 拒绝/跳过。倒逼用户先配置检验策略或显式免检；门禁与建单拒绝文案必须引导「请在物料/工序档案配置检验策略或设置显式免检」。采购侧既有 `include_unset_iqc`+`inspection_plan_id` 逃生口保留。
8. **全环节 `none` 语义（评审拍板②）**：`inspection_stages` 三环节全部 `none` 视同未配置（source `default_none` → 必检），且主数据保存校验拒绝该配置（`assert_master_data_inspection_stages_allowed` 报错引导）。物料级显式免检的表达方式是：至少一个环节配置 `simple`/`plan`，目标环节设 `none`。
9. **预览判定同源（评审拍板③）**：入库预览/额度/建议数量等只读路径与门禁共用 `inbound_inspection_required` 判定（`warehouse_service` `_get_work_order_inbound_quota`/`_resolve_work_order_suggested_receipt_quantity`/`_resolve_work_order_inbound_preview_quantities`）；不得显示「无需检验」却确认被拒。检验单**建单侧**的拉料预览/下推候选属创建路径，按规则 7 维持 eff 判定不动。
10. **行级字段口径（评审拍板④）**：`iqc_required`/`fqc_required` 按 source 判定；必检但无策略（`default_none`）时 `iqc_mode`/`fqc_mode` 置 `null`（待配置），免检行仍显示 `none`。不允许出现 `required=True` + `mode="none"` 的矛盾组合。

### Acceptance Criteria

1. source 为 `default_none` 的物料：成品入库、采购来料、客供料登记都被拒绝。拒绝与 `require_fqc_before_finished_goods_receipt`、`require_incoming_inspection_for_receipt`、`require_incoming_inspection_for_customer_material` 的存值无关。这三个开关不参与 skip。
2. source 为 `material` 且 eff 为 `none`：成品入库、采购来料、客供料登记按免检放行。eff 为 `simple` 或 `plan` 时仍必检。
3. source 为 `stage_disabled` / `module_disabled` 且 eff 为 `none`：保持「环节/模块未启用」语义跳过该行门禁（不拒绝、也不当作免检配置的证据）。`resolve_inspection_policy` 的 `material_inspection_mode` legacy 回退分支（868–875 行间）随 source 透传一并改，不得再造第二处吞 source 的收口点。
4. 成品入库入参 `work_order_id` 为空时不得 `return` 绕开 FQC；该行无策略仍按 `default_none` 必检。
5. 采购退料确认不新增检验门禁。委外收货不新增检验类型、不新增 assert。
6. 成品入库成功后批次质量态为 `qualified`；门禁查检验单时匹配中文「合格」。
7. 半成品一键入库：工单为 `in_progress`/`completed` 或展示「进行中」/「已完成」均可进入合法路径；非法态拒绝。
8. 本单元新增/改动的查询：若 **143** 尚未落地，临时仍须带 `tenant_id`（失败关闭），并在代码/注释标成「将被 143 收口替换」；**不得**把「手写 tenant_id」当最终方案写死。
9. 未改 SPC/Cpk/8D；未开第 6 项设备绩效；未做把存量来料开关 False 翻成 True 的 aerich 数据迁移。
10. 门禁拒绝文案引导配置检验策略/显式免检；`inspection_stages` 全环节 `none` 保存被拒；入库预览额度对 `default_none` 物料按必检口径（FQC 余量封顶）；行级 mode 字段无 `required=True`+`"none"` 矛盾组合。
