### Business Goal

仓管在 **同一入库 Hub**（菜单 9300）中，除物料入库与成品入库外，还能按类型/仓库筛选看到 **生产退料** 与 **销售退货** 单，点单号打开抽屉查看现网头/行明细并 **一步执行过账**（与旧散页相同 PUT），无需在 Hub 与 `wm/rtissue`、`wm/rtsalse` 之间来回切换。旧生产退料/销售退货菜单、URL、权限字保留；**出库 Hub 永不出现这两类**（114 负向约束保持）。

### Scope

In scope:

- **`GET /mes/wm/inboundhub/list` 加法**：UNION 再并入 `wm_rt_issue`、`wm_rt_salse` 两臂；`receiptType` 查询参数可筛 **`RT_ISSUE` / `RT_SALSE`**；未传类型时默认 **四臂**（`ITEM_RECPT` + `PRODUCT_RECPT` + `RT_ISSUE` + `RT_SALSE`）。筛选省略未用臂（105/112 同模式：禁止 `AND 1=0` 式占位）。保留 **`warehouseId`** 及现网已有单号/状态/日期筛选项（与 105/107 对齐；投影列以实现时头表字段为准）。
- **Hub 抽屉只读 + 执行**：生产退料 / 销售退货打开抽屉时，调 **现网** 头 GET、行 `list`、执行 **现网** `PUT`；一步过账；无 confirm 按钮（除非代码核对发现存在 confirm——则文档跟现网，见 T0）。
- **Vue3 UI-A**：仅 `inboundhub/index.vue`（及同目录子组件）增加类型选项、抽屉分支、深链（工单/领料/销售出库/客户等 **有字段则跳**，无则纯展示）；**不改** `rtissue`/`rtsalse`/`itemrecpt`/`productrecpt` 布局。
- **权限**：Hub list 仍 `mes:wm:inboundhub:list`；执行按钮与旧页 `handleExecute` 同一权限字（实现时对齐 `rtissue`/`rtsalse` 的 `edit` 或等价字）。
- **单测**：`WmInboundHubMapperXmlTest` / `WmInboundHubTenantRewriteTest` 扩四臂；**保留** `WmOutboundHubReturnsGatedTest`（114）断言出库仍无退料/退货；可选 `InboundHubReturnsVueTest` 断言类型筛含两新值。
- **Flyway**：默认 **无新菜单**（9300 已存在）；**无新 business 表**；仅当实现发现缺按钮权限 seed 时走 master 增量（须占用 9301–9309 空位，**禁止**占 9310+ 出库段）。

### Acceptance Criteria

1. **编码门禁：** 用户在同一会话 **点名 118**；105 与 108–111 代码已存在且 **不重开** 其范围声明；114 **不纳入出库** 结论不变。
2. 角色具备 `mes:wm:inboundhub:list` 时，Hub list **可分页** 返回本租户四类型混合结果；`total` 为服务端 UNION 计数，非前端切片。
3. `receiptType=RT_ISSUE` 仅查 `wm_rt_issue` 臂；`receiptType=RT_SALSE` 仅查 `wm_rt_salse` 臂；省略未用臂；每臂 SQL 带 `tenant_id`。
4. `warehouseId`（及现网其它 list 筛选项）对退料/退货臂 **生效或安全忽略**（编码时若头表无仓库字段则忽略且单测/document 说明；**禁止**因缺列导致 UNION 500）。
5. 抽屉：生产退料/销售退货展示现网头字段 + 行表；执行成功/失败与旧页同一 PUT 语义；Hub 无权限时隐藏或禁用执行（与 105 成品/物料一致策略）。
6. **`GET/PUT /mes/wm/rtissue/**`、`**/mes/wm/rtsalse/**`** URL、method、`code/msg/data` **不变**；`GET /mes/wm/itemrecpt/**`、`/productrecpt/**`、iqc-gate、outboundhub **不变**。
7. 出库 Hub list / Vue 类型枚举 **仍不含** `RT_ISSUE` / `RT_SALSE`（114 测试仍绿）。
8. 无密钥进 yml/文档；无按租户 `INSERT sys_menu`；无客户端租户头。
9. 实跑 `mvn` / `npm run build:prod` 后结果写入第 4 节；**未跑不得写绿**。

### Rules and Constraints

Tenant isolation:

- 无 `TenantContext` 不得访问 `wm_rt_issue` / `wm_rt_salse` 及 Hub UNION。
- 四臂 UNION **每一臂** 独立带 `tenant_id`；禁止内存合并后再滤租户作为唯一隔离。
- Hub 行 `recptId` + `receiptType` 唯一定位单据；跨租户 id 403/空，不泄漏他厂。

Security and masking:

- 不新增匿名 GET；`/mes/wm/inboundhub/**`、`rtissue`、`rtsalse` 不进 `MesPermitAllProvider`。
- 403/404 不泄漏他厂是否存在该 `rtId`。
- toast/API 不打印 JDBC、cipher、内部路径。

Audit and lineage:

- 新 DDL（若仅 master 权限 seed）进 `ktg-system/.../db/migration/master/`；版本号按目录最大号顺延；不改 `backend/sql/`。
- 菜单仍 **9300–9309** 段；出库 **9310+**、112 的 9320/9330 不占用。

AI/rule-engine rules:

- 不涉及；`/ai/**` 无变更。

Database rules:

- **不新建**入库/退料混合头表；UNION **仅查询**。
- 不新增 IQC/FQC 业务列；不把退料/退货 secretly 写进出库 `wm_item_recpt` / `wm_product_recpt`。

## 2. Plan

### Implementation Approach

1. **编码前只读核对**（`startech-mes-basic`）：`WmInboundHubMapper.xml` 两臂结构；`WmRtIssue`/`WmRtSalse` 实体字段；Controller 的 `@PutMapping` 路径变量名、list 查询参数；Vue3 `rtissue/index.vue` execute 与权限指令。
2. **后端**：在 `WmInboundHubMapper.xml`（或等价）增加 `wm_rt_issue`、`wm_rt_salse` 的 `SELECT … UNION ALL …`，投影到 `WmInboundHubRow`；Service 层类型筛选逻辑与 105 一致（省略未用臂）。**不**改 `WmRtIssueController` 业务语义，除非缺 list 筛字段且必须加法 query（优先在 Hub Mapper 内用现有列）。
3. **前端**：`inboundhub/index.vue` 类型下拉增加两项；抽屉 `switch(receiptType)` 分支：退料/退货走 rtissue/rtsalse API；执行按钮调 `PUT`（一步）；**不**渲染 IQC/FQC 闸块；金额/打印块若 110/111 仅绑两入库类型则保持隐藏。
4. **测试**：扩 Hub XML/tenant rewrite；跑 114 出库负向测试；必要时加 Vue 字符串测试（类型 label / API 路径）。
5. **文档回写**：缺口 14 IH-G10（退货臂）、104 TOC、本文件 §4。

- **增量（仅 list 语义扩展）：** 同上 GET；`receiptType` 合法值增加 `RT_ISSUE`、`RT_SALSE`；默认 UNION 四臂；响应 `rows[].receiptType` 可出现两新值；`rows[].recptId` 对退料/退货为 rt 头表主键。
- **抽屉：** 无新 Hub 专用 GET；一律复用附录 B 现网路径。
- **执行流：** 生产退料 / 销售退货 **一步** `PUT /{rtId}`（与缺口 15、107 销售出库一致）；**不是** 物料入库 `confirm` + `execute` 两步（除非 T0 代码核对推翻）。

### Persistence Changes

- **无新业务表**；无 tenant 新列（除非发现 Hub 投影缺列且必须 ALTER——须单独立项，**默认无**）。
- UNION 只读；事务仍在各 `processRtIssue` / `processRtSalse` 内。

### Transaction Boundaries

- Hub list：只读；任一臂 SQL 异常则整请求失败（设计 14 §4）。
- 抽屉执行：与旧页相同 `@Transactional` 边界；Hub 不包一层新事务。

### Risks
