# 触屏工位机 — 静态页托管与 exe 分发

本文件已按拍板收口。不改 `kuaigeyun-mes/fast-deploy/` 的 Caddy 与发布命令。本单元不编译 `kuaigeyun-client/riveredge-app-station`（本仓跟踪，仓外打包）壳，不把工位页面烤进 exe，不改手机端 H5 的现有发布命令。

## 1. Spec

### Capability

- Name: 工位静态页托管与 exe 分发
- Module: 工位页面是主站 SPA 已有路由，由现有 `{{FRONTEND_ROOT}}` 托管。exe 在 `kuaigeyun-mes/kuaigeyun-client/riveredge-app-station` 按 spec 162 打好后，放到本仓已有的安装包静态目录。
- Priority: STN-D4、STN-D5、STN-D11。依赖 157 的工位路由与渠道请求头，以及 162 的可分发 exe。
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/20.station-terminal-gaps.md`（**STN-D4**、**STN-D5**、**STN-D11**）
  - 设计：`docs/03.design/20.station-terminal-plan.md`（§4、§5）
  - 入口：`docs/04.specs/157.station-terminal-entry.md`
  - 壳：`docs/04.specs/162.station-app-station-shell.md`

### 已拍板

- 不新增 Caddy 站点，不改 `{{FRONTEND_ROOT}}`，不替换办公室 `dist`。
- 工位页就是主站 SPA 里的路由 `/apps/kuaizhizao/production-execution/station`。现有兜底 `handle` 用 `try_files` 从 `{{FRONTEND_ROOT}}`（`riveredge-frontend/dist`）提供该路径。
- 进入该路由时请求头用 `station`。办公室构建保持 `pc`。渠道运行时由 spec 157 改 `riveredge-frontend`。本单元不改前端，也不新增会替换 `dist` 的 station 构建发布命令。`build.web.sh` 仍执行现有的 `npm run build:16g`。
- H5 仍走 `/mobile`（`{{MOBILE_WEB_ROOT}}`、`install-h5`、`build.mobile.web.sh`），与工位分开。不把工位页面塞进 `/mobile`。
- 本仓不编译 exe。产出在 `kuaigeyun-mes/kuaigeyun-client/riveredge-app-station`，按 spec 162。已打好的安装包放到下面「exe 分发」里的现有目录。

### Business Goal

产线电脑上的壳从服务器打开主站上的工位路由。改界面随主站 `dist` 发布，不用重装 exe。已经在 `kuaigeyun-client/riveredge-app-station`（本仓跟踪，仓外打包）打好的 exe 放到现有安装包静态目录，再装到车间电脑。

### Scope

In scope:

- 写明工位页由现有主站静态托管提供。入口路径是 `/apps/kuaizhizao/production-execution/station`。页面不烤进 exe。不新增 Caddy `handle`，不改 `FRONTEND_ROOT`。
- 与现有 `install-h5`、`build.mobile.web.sh` 分开。手机端 H5 继续走这两条现有命令和 `/mobile`。
- 写明已打好的 Electron exe 如何分发。脚本不在本仓编译 `kuaigeyun-mes/kuaigeyun-client/riveredge-app-station`。仓外打包仍在 162。exe 本体不在本仓产出。
- 分发流程：`kuaigeyun-client/riveredge-app-station`（本仓跟踪，仓外打包）按 162 打出安装包之后，把该文件放到本仓已有的安装包静态目录。车间电脑安装壳。壳的本机配置填写服务器上的工位入口，窗口加载 157 的路径，并带 URL 查询参数 `workstationId`。说明不写生产地址、口令或密钥。

Out of scope:

- 在本仓或 `fast-deploy` 编译 Electron、生成 exe
- 新增 Caddy 站点或 `handle`，修改 `{{FRONTEND_ROOT}}`，用 station 构建替换办公室 `dist`
- 修改 `install-h5` 或 `build.mobile.web.sh` 的现有手机端行为
- 把工位页面拷进 `/mobile`
- 工位业务页面与渠道运行时（157）以及壳主进程实现（162）
- 改 `riveredge-frontend`、`startech-mes-basic`
- 新后端表或新后端接口
- 新造第二套安装包发布流水线

### exe 分发

本仓不编译、不产出 exe。安装包由 `kuaigeyun-mes/kuaigeyun-client/riveredge-app-station` 按 `docs/04.specs/162.station-app-station-shell.md` 打好。

已打好的安装包放到现有目录，不新造发布命令：

- 磁盘根：`CLIENT_RELEASE_ROOT`。未设置时，`lib/common.sh` 的 `gen_caddyfile` 使用 `riveredge-backend/uploads/clients`。
- URL：`templates/Caddyfile.template` 已有 `handle_path /static/client-packages/*`，`root * {{CLIENT_RELEASE_ROOT}}`，`file_server`。同根还有 `handle_path /static/client-updates/*`（OTA，同一目录，不是另一套流水线）。
- `config/deploy.env.example` 将该根注为「客户端安装包/OTA 静态文件根目录（Caddy 直出；默认 riveredge-backend/uploads/clients）」。
- 模板注释写明剥离前缀后与后端 StaticFiles 布局 `clients/{key}/packages/...` 一致。本单元不新增 key；推荐安装包落位 `clients/touch-terminal-windows/packages/`（后端 `client_product_registry.py` 已注册 `touch-terminal-windows` 键），而非裸放根目录。

车间电脑从上述现有 URL 取得安装包并安装壳。壳的本机配置填写现场服务器上的工位入口 `/apps/kuaizhizao/production-execution/station`，并带查询参数 `workstationId`。服务器地址只留在现场壳配置里，不写入仓库。

### Acceptance Criteria

1. 工位页由现有主站 SPA 托管，能打开 `/apps/kuaizhizao/production-execution/station`。不新增 Caddy 站点，不改 `FRONTEND_ROOT`，不替换办公室 `dist`。安装包内没有这些页面。
2. 现有 `install-h5` 与 `build.mobile.web.sh` 仍只服务手机端 Web 的 `/mobile`。工位页面不出现在 `/mobile`。
3. 本仓脚本不编译 `kuaigeyun-mes/kuaigeyun-client/riveredge-app-station`，不产生 exe，不新增会替换 `dist` 的 station 构建发布命令。分发说明指向现有 `/static/client-packages` 与 `CLIENT_RELEASE_ROOT`。产出在 `kuaigeyun-client/riveredge-app-station`（本仓跟踪，仓外打包），按 162。
4. 文档与脚本不包含生产地址、口令或密钥。

Security and masking:

- 脚本、说明、日志不写入口令、令牌、密钥或生产地址。
- 服务器地址留在现场的壳本机配置里，不写入仓库。

Audit and lineage:

- 本单元不新写审计表。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 无新表，无迁移。静态文件与现场 exe 副本不进 Git。

## 2. Plan

### Implementation Approach

1. 工位页不另起静态根。它是主站 SPA 路由，随现有 `build.web.sh` 提交的 `riveredge-frontend/dist` 发布。办公室构建保持 `pc`。进入工位路由时的 `station` 请求头由 157 实现。本单元不注入 `VITE_CLIENT_CHANNEL=station` 去替换 `dist`。
2. 不新增 Caddy `handle`，不改 `{{FRONTEND_ROOT}}`。H5 继续 `/mobile`，不改 `install-h5` 与 `build.mobile.web.sh`。
3. exe 只接收 `kuaigeyun-client/riveredge-app-station`（本仓跟踪，仓外打包）已经打好的文件，放到现有 `CLIENT_RELEASE_ROOT`，由现有 `/static/client-packages/*` 直出。本仓不运行 `kuaigeyun-mes/kuaigeyun-client/riveredge-app-station` 的 Electron 打包。现场安装后，壳按 162 加载主站上的工位入口。

### 依赖

- 157 的工位路由 `/apps/kuaizhizao/production-execution/station`，以及进入该路由时的 `station` 请求头。办公室构建保持 `pc`。
- 162 的可分发 exe。exe 本体不在本仓产出。

### Affected Modules

- 不改 `kuaigeyun-mes/fast-deploy/`。
- 不改 `riveredge-frontend`。渠道运行时由 157 修改。
- 不改 `kuaigeyun-client/riveredge-app-station`（本仓跟踪，仓外打包）源码。不在本仓放置 exe。

### Public Contracts

- 工位页面入口仍是 157 的 `/apps/kuaizhizao/production-execution/station`。托管不另起一条业务 API，不另起 Caddy 站点。
- 进入该路由时请求头为 `station`；办公室构建的请求头保持 `pc`。该行为由 157 实现。
- 壳与页面的交接仍是 162：URL 查询参数 `workstationId`（URL query，不是 Electron 额外启动参数）；回写窄接口 `stationShell.setWorkstationId`。
- H5 继续由 `install-h5` 与 `build.mobile.web.sh` 发布到 `/mobile`。工位静态资源不进入 `/mobile`。
- 已打好的安装包使用现有 `/static/client-packages/*` → `CLIENT_RELEASE_ROOT`。

### Persistence Changes

- 无数据库变更。

### Transaction Boundaries

- 无业务事务。

### Risks

- 把工位页并进 `/mobile` 会和手机端 H5 混在同一发布物里。工位留在主站路由。
- 用 `VITE_CLIENT_CHANNEL=station` 另打一份 `dist` 并覆盖 `FRONTEND_ROOT`，办公室渠道会变成 `station`。本单元不新增该发布命令。
- 在 `fast-deploy` 里编译 `kuaigeyun-client/riveredge-app-station`（本仓跟踪，仓外打包）壳，会把 exe 打包拉进本仓。本单元只指向现有安装包目录。
- 把页面烤进 exe 后，改一个按钮就要重装产线电脑。页面留在主站 SPA。

### Verification Strategy

- 见 §4。核对以现有 Caddy 模板与 `gen_caddyfile` 为准。未改 Caddy，未跑 deploy。
