## 1. Spec

### Capability

- Name: P10 跨租户报表（v1 明确不立项）
- Module: 无实现模块。本文件只锁定 D5 非目标与后续约束。业务代码仍在 `startech-mes-basic`，本单元**不改** Java/SQL/Vue
- Priority: P2（文档门禁；v1 无开发优先级）
- Related requirement/design documents:
  - 设计：`docs/03.design/04.mes-shared-db-tenant-plan.md`（阶段 P10、D5、I1）
  - 缺口清单：`docs/02.requirements/02.mes-multi-tenant-gaps.md`
  - 总控：`docs/04.specs/35.mes-multi-tenant-program.md`
  - 上一单元：`docs/04.specs/46.tenant-frontend-p9.md`
  - 下一单元：无（v1 多租户轨道结束）

### Business Goal

把「跨租户报表不进 v1」写成可执行门禁：任何普通 MES 报表、UReport、平台运营端都只查当前租户。本文件的存在本身禁止把跨厂汇总当成本轮实现范围。

### Scope

In scope:

- 文档化 v1 非目标：跨租户聚合、跨厂仪表盘、跨厂 UReport、平台特权 SQL 汇总均不立项
- 记录后续若立项才适用的约束（权限、只读、审计、SQL 只能打共享库 `ROW` 租户；`DATABASE` 无法 JOIN）
- 确认 45 已要求当前租户报表 + I1 Filter；本单元不授权额外报表工作

Out of scope:

- **实现**任何跨租户报表、跨厂 UNION/JOIN、平台总览数字
- 改 UReport 模板、改 `report` Mapper、改 Vue 报表页
- 为平台单独开「可关隔离」的查询开关
- 改 Java/SQL/Vue；引入第二套报表库或联邦查询
- 把本文件第 4 节写成「已实现跨租户报表」

### Acceptance Criteria

- 本文件已按模板五章落在 `docs/04.specs/47.tenant-reports-p10.md`
- **本 spec 不授权 v1 任何跨租户报表开发。** 出现相关 PR/任务须先改 D5 并新开轨道，不得声称「47 已覆盖实现」
- 普通 MES 报表、UReport、平台运营查询在 v1 均仅当前租户（D5）
- 平台也不做跨租户报表（不只是不做特权仪表盘）
- 物理事实写明：`DATABASE` 专库与主库不在同一连接，**不能**用一条 SQL 跨库 JOIN
- 第 4 节保持未执行（无代码可跑）

### Rules and Constraints

Tenant isolation:

- v1 默认查询永远仅当前 `TenantContext.tenantId`
- 平台 `runAs` 进入某厂后，报表仍只是该厂，不是多厂合计
- 禁止「平台身份自动 SELECT 全库业务表」的报表通道

Security and masking:

- 将来若立项：仅平台租户 + 明确权限标识；普通角色 403；只读；全程审计；审计不写业务明文大结果集中的口令/JDBC
- v1 不预留未鉴权的跨厂查询接口

Audit and lineage:

- 本文件是 D5 的开发单元指针，不产生 schema 变更
- 后续立项须新 spec，不得追加实现进本文件而不改决策

AI/rule-engine rules:

- 本单元不涉及规则引擎或 AI

Database rules:

- v1 **零**跨租户报表 DDL/DML
- 将来 SQL JOIN/UNION **只**能覆盖共享主库上的 `ROW` 租户行
- `DATABASE` 租户数据物理上不在同一 MySQL 连接，跨专库 JOIN 做不到；不能靠「回落主库」拼出假跨厂结果（失败关闭）
