## 2. Plan

### Implementation Approach

1. 主写入入口已定为 `document_relation_new_service`，不在实现时再选。
2. 旧服务改为薄委托到新服务的三个写函数，或停止被新代码调用。
3. 拆分路径：关联写入纳入同一事务；去掉「只记日志 / 忽略已存在当成功」。
4. 契约：operation 拆分保持拒绝；OpenAPI/校验枚举若仍列出则改为不可选或文档 Deprecated-never。
5. **不**借机拆工单/仓储大文件。

### Affected Modules

- `src/apps/kuaizhizao/services/document_relation_service.py` / `src/apps/kuaizhizao/services/document_relation_new_service.py`
- `src/apps/kuaizhizao/services/work_order_service.py` 拆分关联段（约 5029–5056）
- 各写关系调用方（迁移）

### Public Contracts

- 写入口为 `DocumentRelationNewService.create_relation`、`batch_create_relations`、`delete_relation`。
- 拆分 API：不接受 operation 为可成功类型。

### Persistence Changes

- 一般无新表；若唯一约束与「忽略已存在」冲突，以事务失败为准或显式幂等，不静默。

### Transaction Boundaries

- 拆分创建子工单 + 写关系 = 同一事务；任一步失败全滚。

### Risks

- 双服务语义不完全一致 → 迁移前对照公开方法差异表，避免行为回退。
- 调用方多 → 分批迁移但合并门禁为「写路径零双入口」。

### Verification Strategy

- 见 §3；§4 实跑后填。
