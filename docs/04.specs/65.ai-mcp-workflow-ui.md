## 1. Spec

### Capability

- Name: MCP / 工作流 Vue3 管理端页（F-A3 页面单元）
- Module: **仅** `startech-mes-basic/startech-mes-front/`（`src/api/ai/`、`src/views/ai/`）。菜单种子可在后端增量 SQL（与 63/64 对齐）。**禁止**改遗留 Vue2 `frontend/`。
- Priority: P10（**63/64 后端契约冻结之后**；不要做成 Agent 聊天页）
- Related requirement/design documents:
  - 设计：`docs/03.design/06.mes-ai-platform-plan.md` §5.3、§7（MES 自有 MCP/工作流页另开；仍 Element Plus；无独立 Agent 页；已有 `POST /ai/agent/send`）
  - 缺口：`docs/02.requirements/03.mes-ai-platform-gaps.md`（F-A1–F-A4、A27、A28）
  - 总控：`docs/04.specs/48.mes-ai-platform-program.md`
  - 后端契约：`docs/04.specs/63.ai-mcp-whitelist.md`、`docs/04.specs/64.ai-logged-in-workflow.md`
  - 上一单元：`docs/04.specs/64.ai-logged-in-workflow.md`
  - 前端先例：`docs/04.specs/59.ai-phase1-vue3-ui.md`（`request.js`、Element Plus、不引入 x/hook-fetch）
  - 链：`61` → `62` → `63` → `64` → **`65`（本文件）**

### Business Goal

工厂管理员在内嵌管理端配置本租户 MCP 白名单、维护并运行已登录工作流。交互用现有 Element Plus 表格/表单/对话框，走现有 `src/utils/request.js` Bearer。不是独立对话端，也不是 Agent 聊天页。

Goal：Vue3 可完成 MCP 配置（密钥只写不回填）与工作流列表/运行（SSE 自定帧）；不引入新 UI 栈。

### Scope

In scope:

- API 模块（新建，风格对齐现网 `src/api/ai/model.js` 等）：
  - `src/api/ai/mcp.js` → `/ai/mcp/server` CRUD 与 options
  - `src/api/ai/workflow.js` → `/ai/workflow` CRUD；运行用 `fetch` 流（与 `src/api/ai/chat.js` 相同 Bearer 头），**不要** `hook-fetch`
- 页面（`path` 前缀 `ai`，`module_code=ai`）：
  - `/ai/mcp`：白名单 MCP server 表格/表单；凭证只写不回填；无明文回显
  - `/ai/workflow`：工作流定义表格/表单 + 本页触发 `POST /ai/workflow/run` 的进度展示（Element Plus；**不拷** ruoyi-web runner / MCP 卡片）
- 菜单进 `sys_menu`，权限字与 63/64 对齐（如 `ai:mcp:*`、`ai:workflow:*`）
- 仅 Element Plus + 现有 Vue3 栈；axios 走 `request.js`；代理与 env 只动既有 `vite.config.js` / `.env.*` 若缺 `/ai` 代理（现网对话已走 `/ai` 则不改）

Out of scope:

- **Agent 管理端页 / Agent 聊天页**（设计 §7：无独立 Agent 页；聊天仍 `/ai/chat`；Agent 仅 `POST /ai/agent/send`）
- 改 Vue2 `frontend/`
- 引入 `vue-element-plus-x`、UnoCSS、`hook-fetch`、Vben、TypeScript 工程形态
- 为聊天/本页升级 Vue / Vite / Element Plus；提交 lockfile
- 实现 62/63/64 的 Java（本单元只消费已冻结 HTTP）
- 改 `POST /ai/chat/send` / `POST /ai/agent/send` 信封
- Milvus / Qdrant、官方 EmbeddingStore、live 环境作为本单元 In scope
- 把 MCP/工作流口做成游客可进
- 真实地址、凭据、Token 写入前端 env

Non-goals:

- 不对照 ruoyi-web 搬登录弹窗、扫码、应用市场、MCP 市场卡片
- 不把 `/ai/chat` 改成工作流 runner
- 不为平台另做独立对话 SPA

### Acceptance Criteria

- 两页走 `/ai/mcp/server` 与 `/ai/workflow`；401/403 走现有 axios 拦截，不吞成「未登录可玩」
- 凭证输入框只写不回填；详情/options 无 token 字段展示
- SSE 只解析 64 自定 `{content, done}`（可选 `step`）；忽略且不依赖 `[NODE_CHUNK_*]`
- 无 `element-plus-x` / `hook-fetch` / Vben 依赖新增；`frontend/` git diff 为空
- 不新增 Agent 路由（无 `/ai/agent` 页）
- 有前端改动则实现后跑 `npm run build:prod`；第 4 节未跑前不得写通过

### Rules and Constraints

Tenant isolation:

- 不传客户端 `tenantId` 头或 body；租户只信登录 JWT
- 跨租户 id 展示为后端 404/403，前端不猜测切换租户

Security and masking:

- 不把模型 Key、MCP token、向量 token 放进 `.env.*`
- toast / 控制台不打印凭据、cipher、内部路径

Audit and lineage:

- 菜单 SQL 用新增量，不改历史菜单脚本（若 63/64 已种菜单则本单元只接线）

AI/rule-engine rules:

- F-A2 / F-A3：Element Plus 重做；不拷 ruoyi-web MCP/runner
- 工作流运行不是匿名 `/run`

Database rules:

- 本单元不改表结构（表在 63/64）
