# 星制造移动端 — 模具

本文件可实施。只增加 `mold` 包。依赖 `docs/04.specs/164.mobile-client-shell.md`。不把模具并进设备 scope。

## 1. Spec

### Capability

- Name: 移动端模具
- Module: `kuaigeyun-mes/kuaigeyun-client/riveredge-app-mobile/features/mold/`
- Priority: **MOB-Q6**
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/21.mobile-client-gaps.md`（**MOB-Q6**）
  - 设计：`docs/03.design/21.mobile-uni-app-x-plan.md` 第 5 节 `features/mold`
  - 壳：`docs/04.specs/164.mobile-client-shell.md`

### Business Goal

有模具权限的人在模具工作台查模具、领用、归还、保养和维修。模具状态和保养规则仍由现有后端执行。

### Scope

In scope:

- 下表 6 个页面。
- registry 导入与 `pages.json` 登记。三端都注册。

Out of scope:

- 把模具入口放进 `equipment`。
- 试模、报废、校准、导出。
- 在客户端另写模具状态机。

### 主操作

| key | 中文名 | route | 数据 | 主操作 |
| --- | --- | --- | --- | --- |
| `mold-scan` | 扫码查模具 | `/mold/scan` | `GET /api/v1/apps/kuaizhizao/molds` | 打开扫到的模具 |
| `mold-borrows` | 模具领用 | `/mold/borrows` | `GET /api/v1/apps/kuaizhizao/mold-borrows` | 创建一条领用 |
| `mold-returns` | 模具归还 | `/mold/returns` | `GET /api/v1/apps/kuaizhizao/mold-returns` | 创建一条归还 |
| `mold-maintenances` | 模具保养 | `/mold/maintenances` | `GET /api/v1/apps/kuaizhizao/mold-maintenances` | 创建一条保养 |
| `mold-repairs` | 模具维修 | `/mold/repairs` | `GET /api/v1/apps/kuaizhizao/mold-repairs` | 创建一条维修 |
| `mold-reminders` | 模具保养提醒 | `/mold/reminders` | `GET /api/v1/apps/kuaizhizao/molds/maintenance-reminders` | 只读 |

这些路径来自 PC `riveredge-frontend/src/apps/kuaizhizao/services/moldOps.ts` 与 `equipment.ts` 里已经出现的调用。

保养创建体与 `mold-maintenances/index.tsx` 的 `handleSubmit` 一致：先 `GET /api/v1/apps/kuaizhizao/mold-maintenances/preview-lines`，提交时 `lines` 每行带 `line_no`、`item_id`、`item_code`、`item_name`、`requirement`、`executed`、`remark`。`executed` 缺省为 false。维修创建体与 `mold-repairs/index.tsx` 的 `handleSubmit` 一致，并另带 `urgency`。不把 `executed` 改写成 `is_done`，也不为了让服务复制方案行而省略 `lines`。后端已接受 `executed`（兼容 `is_done` 入参，落库列 `is_done`，响应输出 `executed`）；`urgency` 已是真实字段 `MoldRepair.urgency`（VARCHAR(32)）。

### Acceptance Criteria

1. 模具工作台能打开上表每一格，创建类操作走表中的现有资源。
2. 设备工作台不出现模具入口。
3. 去掉本包导入后，这些入口回到空态。
4. 页面在三端的 registry 与 `pages.json` 都注册。业务操作的验收只在已登录 H5 上进行。小程序和 App 因取码未接通，不要求走通业务页。

### Rules and Constraints

Tenant isolation:

- 沿用壳的租户头。

Security and masking:

- 不写令牌或生产地址。

Audit and lineage:

- 不新写审计。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 无新表。`MoldRepair` 新增 `urgency` 列，迁移见 §2 Persistence Changes。

- 壳 registry 与 `pages.json` 的追加

### Persistence Changes

- 新增 `MoldRepair.urgency`（VARCHAR(32)），迁移 `riveredge-backend/migrations/models/20260930120000_add_urgency_to_mold_repairs.py`。

- 每次创建调用一次现有接口。

- 扫码查模具若被写成设备的 `resolve-scan`，会串到设备 scope。本单元只用模具档案接口。

### Verification Strategy

- 在已登录 H5 上打开模具工作台，完成一次领用和一次归还。确认设备宫格没有模具 key。小程序和 App 不要求走通这些页。§4 实跑后填写。
