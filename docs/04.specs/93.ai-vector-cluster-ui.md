### Business Goal

业务必须同时支持：① 无法自建向量库的工厂 → 用**平台 yml 里的共享**向量集群；② 能且必须用自建向量库的工厂 → 用**该厂自己的**集群。效果对齐本 MES 的 MySQL 隔离（`ROW` 共享库 vs `DATABASE` 专库）：**平台绑定连接**，工厂不能在 AI 菜单或「参数设置」自改集群 URL。共享集群与主库数据源一样走部署配置，不另挂运营页。API Key 不进仓库 yml 明文、不进参数表明文。

### Scope

In scope:

- **是**现网 `ruoyi.ai.vector-store.*`：`type`（`weaviate` | `dashvector`；未知失败关闭）、Weaviate `host`、DashVector `endpoint`。不是 MinIO，不是 chat 模型 host，不是 `ai.rag.*` 切块旋钮。
- **两档（冻结名 `SHARED` / `DEDICATED`，不复用 MySQL 的 `ROW`/`DATABASE`）：**
  - **SHARED（默认）：** 该租户无专集群绑定 → `VectorStoreFactory`（或其后继）用 **yml/env** 共享集群。共享集群上仍逻辑过滤 `tenant_id`（I-A3）。yml **是**产品面。
  - **DEDICATED：** 平台运营为本租户绑定其自建集群（type + host/endpoint + 只写 API Key）。运行时用**该租户客户端**，**禁止**回落 yml。专集群上仍写/滤 `tenant_id`。
- **谁写绑定：** 仅 `isPlatformOperator` 的 `GET`/`PUT /platform/tenant/{id}/vector-store`。工厂 `/ai/**` 与工厂 `sys_config` overlay **不得**改指向。工厂 403：写、以及读他厂绑定。专集群工厂用户也不得看见 API Key。
- **谁部署库：** 租户/其运维在其网络部署；MES 只存连接绑定，不替厂建向量进程。
- **无默认集群页。** 不作 `/platform/ai-vector`。SHARED 改地址 = 改部署 yml/env 并重启。
- HTTP：一律 `/platform/**`，JWT/`LoginUser` 只信。不进 `MesPermitAllProvider`。不走 `/ai/**`。信封 `code/msg/data`。
- **不落 overlay 型 `sys_config`。** 集群 URL 若进该表，工厂就能劫持指向。禁止。
- **持久化（一张 master 表，只存专绑定）：** Flyway **master** `ai_platform_vector_store`（名可微调）。
  - 专绑定：`tenant_id` = 工厂 id，每租户至多一行，**禁止 NULL 默认行**。
  - **无绑定行 = SHARED**（用 yml）。表在主库、拦截 **ignore**，**不**进 `tenant.line.include-tables`，**不**拷进专库 catalog。
  - 列：`store_type`、`weaviate_host`、`dashvector_endpoint`、两列 cipher（或等价）。无真实 host/key 种子。
- GET 专绑定：回 `type`、`weaviateHost`、`dashvectorEndpoint`、可用 `*ApiKeySet` 布尔 + `{ vectorIsolation: 'SHARED' | 'DEDICATED' }`。`SHARED` 时地址可空（表示走 yml，不回 yml Key 布尔冒充本厂）。**永不**回 apiKey / cipher。
- PUT 专绑定：`DEDICATED` 必须有平台录入的 type + 对应 host/endpoint；缺 host / 未知 type → 失败关闭，**禁止**回落 yml，**禁止**「工厂 env」。`SHARED`（或清空绑定）= 删该租户行。平台允许改向量档（与 MySQL D8「v1 禁改 JDBC 档」不同：向量无迁库工单）。api-key **只写不回填**（空 = 保留密文）。cipher 算法与 `ai_model` 相同（AES-256-GCM，`AI_MODEL_CIPHER_KEY`）。
- **运行时解析（当前 `TenantContext`）：** 有该 `tenant_id` 专行 → 用该客户端；否则 yml/env `VECTOR_STORE_TYPE` / `WEAVIATE_HOST` / `DASHVECTOR_ENDPOINT`（及对应 `*_API_KEY`）。yml `@Value` **保留且即为 SHARED 产品面**。空 yml + 空 env 行为与现网一致（Weaviate 懒连、缺 host 到调用再失败；DashVector 缺 endpoint/key 失败关闭）。
- **V4：** 一种 type 绑定**一个租户客户端**。A 厂 Weaviate、B 厂 DashVector 必须可同时存活。懒缓存键 `(tenantId)`（SHARED 共用 yml 客户端，键可用 `0` / 哨兵）。改该租户绑定后 **evict**。改 yml 须重启（进程级）。不是 per-knowledge。
- 引导（非硬禁）：不能出厂/须自建的租户**通常**绑自建 Weaviate；DashVector 留给能走云的租户。
- 单测：非平台 403（含工厂读他厂绑定）；工厂 overlay 写不进本表；GET 无密钥；未知 type / DEDICATED 缺 host 失败关闭；无专行则读 yml/env 夹具；DEDICATED 不读 yml；改 host 后不再打旧 host；两租户不同 type 各打各的客户端（mock）；无 `/platform/ai-vector` 映射。
- 本单元 **不改** 开通向导 Vue（94）。可先提供 HTTP 供 94 接线。

### Rules and Constraints

Tenant isolation:

- 写/读专绑定只信平台身份（`isPlatformOperator` / 平台 `tenant_id=0`），不信客户端租户头
- ingest / 检索解析 store 只信当前请求 `TenantContext`（90/91 同一 facade）
- 向量读写仍带 `TenantContext.tenantId`（I-A3），含 DEDICATED
- 表在主库 ignore；不是租户业务表

Security and masking:

- 专绑定 API Key 只写、加密、不回显、不打日志
- SHARED Key 只来自环境变量占位，禁止仓库 yml 真值
- 工厂 UI / 列表 JSON 不得出现 Key
- 不扩匿名面

Audit and lineage:

- 新 DDL 只进 Flyway `db/migration/master/`
- 不改历史 `backend/sql/`
- 可用现有 `@Log`；审计不记明文 Key

AI/rule-engine rules:

- V4：每租户客户端一种后端；代码可同时存在多种实现
- 不换官方 EmbeddingStore
- 不把集群当知识库表单字段
- AI 仍禁止 SQL MES 业务库（A7）

Database rules:

- 一张 master 表：仅每租户至多一行专绑定；无 NULL 默认行；ignore；专库不建此表
- 密钥列只存 cipher，不存明文
- 不改 `sys_tenant` 结构

## 2. Plan

### Implementation Approach

1. Flyway master 建 `ai_platform_vector_store`（无默认行、无真实 host）+ ignore。
2. `ktg-ai` 解析：当前 `tenantId` → 专行否则 yml/env；`VectorStoreFactory` / HTTP 适配按租户懒缓存；平台保存后 evict 该 `tenantId`。
3. `ktg-admin` 薄 Controller：`GET`/`PUT /platform/tenant/{id}/vector-store`。编排在 `ktg-ai` service。**不**增加 `/platform/ai-vector`。
4. yml 保留 `${VECTOR_STORE_TYPE:weaviate}` `${WEAVIATE_*}` `${DASHVECTOR_*}` 作为 **SHARED 产品面**；手册写明 DEDICATED 不靠 env。仓库无真值。
5. Vue 向导与编辑页向量段留给 **94**。

### Affected Modules

- `ktg-ai`：解析、cipher、按租户 evict、Factory
- `ktg-admin`：`/platform/tenant/{id}/vector-store` 薄 Controller
- `ktg-framework` 或既有 ignore 名单：本表不进行级租户拦截 include
- Flyway master
- `application.yml` 占位保留（SHARED）
- 不改 `frontend/`、不改 92 知识库页、不改 `sys_tenant` 列、不改向导 Vue（94）

### Public Contracts

- **新增**（实现写死 path）：`GET`/`PUT /platform/tenant/{id}/vector-store`（专绑定）。仅平台
- **不新增** `/platform/ai-vector`
- **冻结：** `/ai/knowledge` CRUD 与 92 表单不加集群字段；parse / chat/send / agent/send 不变
- 绑定 GET `data` 建议：`{ vectorIsolation, type, weaviateHost, dashvectorEndpoint, weaviateApiKeySet, dashvectorApiKeySet }`
- PUT body：档位 + 地址字段 + 可选 `weaviateApiKey` / `dashvectorApiKey`（只写）

### Persistence Changes

- master：`ai_platform_vector_store`：`tenant_id` 非空=专绑定；`store_type`、`weaviate_host`、`dashvector_endpoint`、两列 cipher。无真实值种子。无默认 NULL 行。
- 不改 `ai_knowledge`；不改工厂 overlay `sys_config`；不改 `sys_tenant`

### Transaction Boundaries

- PUT 绑定：校验档位/host → 插入或删除该 `tenant_id` 行 → evict 该 `tenantId`。短事务。
- GET：只读，不解密到响应

### Risks

- 误用 `selectConfigByKey` 导致工厂 overlay 劫持集群（禁止）
- 改 type 后仍命中旧 Weaviate bean 内缓存 host（必须按租户 evict / 每次解析）
- 把 Key 放进 GET、参数设置或工厂租户 `getInfo`
- DEDICATED 缺 host 却静默打 yml 共享集群（禁止）
- 误做 `/platform/ai-vector` 或 master 默认行，与本修订冲突
