# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 平台工作台运营汇总 — `GET /platform/home/summary` + 异常厂名单 + Vue3 平台首页
- Module: `startech-mes-basic/backend`（`ktg-admin` 薄 Controller + `ktg-system` 查询；登录失败计数若需忽略行级租户则专用 Mapper 方法）与 `startech-mes-front`（`PlatformHome.vue`、`api/platform/`、租户列表读 query）。**禁止**改 Vue2、`/mes/**`、工厂工作台契约、yml / `@Value`。
- Priority: P0（平台回家生产级工作台；80 已交付快捷入口）
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/07.mes-home-gaps.md`（H-D7、H-D9 修订、H-D16、H-D17、H-I5、H-I7、H-F8、H-X7）
  - 设计：`docs/03.design/08.mes-home-plan.md`（§2、§4.1、§5、§9 平台段）
  - 上一单元：`docs/04.specs/81.mes-home-vue3-charts.md`（工厂图；本单元不改图）
  - 租户页：`docs/04.specs/46.tenant-frontend-p9.md`（`/platform/tenant`、`views/platform/tenant/`）

### Business Goal

平台运营登录 `/index` 看到可行动的舰队与运维数字，以及最多 20 条异常厂，而不是仅菜单入口。不把跨厂 MES 挂上平台页。

### Scope

In scope:

- 新 `GET /platform/home/summary`：`@PreAuthorize` 与租户管理相同（`isPlatformOperator`）；`code/msg/data` 信封；`data` 含 `fleet`、`ops`、`exceptions`（字段见设计 §4.1）
- 到期窗口常量 **30** 天：Java 一处常量，summary 与 `GET /platform/tenant/list` 的 `expireStatus=expiring` 共用；不写 yml、不进 `sys_config`（第一期）
- `sys_tenant` list 增加可选 `provisionStatus`（`FAILED` \| `NOT_READY`）、`expireStatus`（`expired` \| `expiring`）；不改 list URL / method / `rows/total`
- `loginFailToday`：当日 00:00:00（JVM 默认时区）起 `status=1` 计数，平台专用可跨租户；**不改** `GET /monitor/logininfor/list`
- 在线人数：复用现有 token 扫描 + `TenantSessionAccess.visible` 后计数
- 任务：现有 `selectJobList` 语义 + `status` 0/1 计数（平台会话租户谓词不变）
- ops 字段：无对应 `monitor:online:list` / `monitor:job:list` / `monitor:logininfor:list` 时填 `null`，不查
- 异常名单 ≤20；reasons 与排序见设计 §4.1；排除平台行
- Vue3：`PlatformHome.vue` 请求 summary（`silentError`）；模块顺序：舰队卡 → 异常名单 → 运维卡 → 80 已有快捷入口；无 echarts、无 `/mes/**`、不读 `mes.index.layout`
- `src/api/platform/` 封装 summary（可与现有 `tenant.js` 同目录）
- `views/platform/tenant/index.vue`：启动时写入 `route.query` 的 `status`、`provisionStatus`、`expireStatus`、`tenantCode` 再查列表
- 监控列表页：若尚未读 `route.query.status`，**只**给 job / logininfor 补一次（与 80 工厂列表同一原则）；online 无筛
- 单测：summary 排除平台行；30 天边界；无 monitor 权限 ops 为 null；非平台 403；list 新筛不破坏旧条件

Out of scope:

- 许可到期、跨厂 MES / OEE、平台页图表、新 runAs API、改 Vue2
- 会话 O(1) 计数器（不改 Redis 会话模型）
- 把 30 天做成参数设置
- 改 `GET /monitor/logininfor/list` 为全平台
- 工厂 `FactoryHome` / 79–81 已交付行为

### Acceptance Criteria

- 平台运营：`GET /platform/home/summary` 200，`fleet.enabled + fleet.disabled` 不含 `tenant_id=0` / `is_platform=Y`
- `expire_time` 在 `[now, now+30d)` 计入 `expiringSoon` 且可进名单 `EXPIRING`；`< now` 为 `expired` / `EXPIRED`；空到期不计
- DATABASE `FAILED`/`NOT_READY` 计入对应 fleet 字段并可进名单；ROW 空 `provision_status` 不计入 NOT_READY
- 无 `monitor:online:list` 时 `ops.onlineSessions` 为 JSON `null`，页面无在线卡；有权限则数字 ≥0
- 工厂账号或非平台运营 403；runAs 会话不请求本接口（前端仍走 FactoryHome）
- 平台页网络面板无 `/mes/**`；不请求 `mes.index.layout`
- 点「即将到期」打开 `/platform/tenant?expireStatus=expiring`，列表只含即将到期厂（与 summary 同一窗口）
- `exceptions.length` ≤ 20
- `npm run build:prod` 实跑；后端相关 `mvn test` 覆盖本单元新测；不改 `frontend/`

### Rules and Constraints

Tenant isolation:

- summary 仅平台运营；舰队 SQL 显式排除平台行
- `loginFailToday` 的跨租户计数仅此专用方法；list 接口保持拦截器本租户
- 任务计数不关闭 job 租户谓词

Security and masking:

- 与 `/platform/tenant` 同一 `PlatformAccess`
- 异常名单与租户 list 一样不回 JDBC 明文 / cipher
- 日志不打印 token、cipher、内部路径
- `silentError` 不得静默 401

Audit and lineage:

- 无新表；无 Flyway（纯查询 + 可选 list WHERE）
- 不写 yml

AI/rule-engine rules:

- 不改 AI 入口

Database rules:

- `sys_tenant` / `sys_logininfor` / `sys_job` 查询走主库既有绑定；新 SQL 不手写与拦截器重复的工厂 `tenant_id` 谓词（平台忽略表除外）
- 到期比较用数据库 `expire_time` 与服务端传入的 `now` / `until` 参数，避免各引擎写死时区函数不一致

## 2. Plan

### Implementation Approach

1. 常量 `EXPIRE_WARN_DAYS = 30`（`ktg-system` 或 `ktg-common` 一处）。
2. `SysTenantMapper`：count 舰队各切片；select 异常候选；list WHERE 增加 `provisionStatus`、`expireStatus`（`expiring` 用 `now`+`until`）。
3. 登录失败 count 专用方法（`@TenantIgnore` 仅该方法，若现 Mapper 整接口不能忽略则新接口绑定主库）。
4. `SysTenantController` 或同前缀薄 Controller 增加 `GET /platform/home/summary`；编排在 `ktg-system` service，不把 Redis 扫描写进 Mapper。
5. Vue：`getPlatformHomeSummary`；`PlatformHome` 按 §9 排模块；租户 index 读 query。

### Affected Modules

- `backend/ktg-admin/.../SysTenantController.java`（或 `PlatformHomeController` 仍挂 `/platform`）
- `backend/ktg-system` tenant mapper/xml + service；logininfor count；job count 复用 service
- `startech-mes-front/src/views/dashboard/PlatformHome.vue`
- `startech-mes-front/src/api/platform/`（summary）
- `startech-mes-front/src/views/platform/tenant/index.vue`
- job / logininfor 列表 vue（仅 hydrate `status` query，若尚未读）
- 测试：`ktg-system` 或 `ktg-admin` 单测
- 禁止：`frontend/`；`ktg-mes`；`application*.yml`

### Public Contracts

- `GET /platform/home/summary`  
  - 认证：已登录 JWT；授权：`isPlatformOperator`  
  - 成功：`code=200`，`data.fleet` 全为整数；`data.ops` 各字段整数或 `null`；`data.exceptions` 数组  
- `GET /platform/tenant/list` 增加可选 query：`provisionStatus`、`expireStatus`；其余不变

### Persistence Changes

- 无 DDL。Mapper XML 增量条件与 count SQL。

### Transaction Boundaries

- 只读。summary 内多次查询无分布式事务。

### Risks

- 在线人数每次扫 Redis，与现网「在线用户」页相同；厂多时首页变慢，本单元不另做计数器
- `loginFailToday` 与点进去的 logininfor 列表（本租户）数字可能不一致；UI 不得写成「下列即全平台失败」
- 租户 list 的 `expireStatus` 与 summary 必须共用常量，否则点击会空窗

### Verification Strategy

- 单测：假时钟或传入 `now` 测 30 天边界；平台行不计入 enabled；ops null
- 反射或 Spring 测 summary 方法有平台门禁
- `mvn test`（至少本模块）；`npm run build:prod`
- 有环境时浏览器冒烟记第 4 节；无浏览器不得称 UI 已验
