### Business Goal

星报表应用目录收归本仓后，能在数据源登记入口 `/apps/kuaireport/data-sources` 登记数据源，并按一张报表的 `report_config` 查出一页结果。`UniReport` 的 config 模式能调到 `executeReport`，拿到 `data` / `total` / `summary`。此时还没有报表中心、设计器、大屏和分发。

### Scope

In scope:

- 去掉 `.gitignore` 里这两行，并加一行与星 AI 同类的例外注释，不改 `kuaiiot` 及其它专业应用的忽略行：
  - `riveredge-backend/src/apps/kuaireport/`
  - `riveredge-frontend/src/apps/kuaireport/`

- 数据源三种，写入已有表 `apps_kuaireport_data_sources.type`（默认 `'static'`）与 `config`（JSONB）：`static`、`dataset`（引用 `core_datasets`）、`http`。HTTP 只允许本租户已登记行上的地址，不另起白名单表。
- 一张报表只绑一个数据源。绑定唯一键是 `report_config.extra.data_source_uuid`（本租户 `apps_kuaireport_data_sources.uuid`），写在已有 `apps_kuaireport_reports.report_config`，不新增外键列，不用顶层整数 `data_source_id`。
- 执行：前端已有钩子是 `riveredge-frontend/src/components/uni-report/UniReport.tsx` 的 `KUAIREPORT_SERVICE`（`import.meta.glob('../../apps/kuaireport/services/kuaireport.ts')`）和函数 `executeReport(reportId, filters)`。返回类型已约定 `data?`、`total?`、`success?`、`summary?`。文件不存在时抛出 `kuaireport is not composed into this workspace`。本切片要补 `src/apps/kuaireport/services/kuaireport.ts`，导出同名函数，不改这个返回形态。
- `dataset` 类型只引用 `query_type` 为 `sql` 或 `api` 的数据集（模型 `core/models/dataset.py` 的 `Dataset.query_type`；执行入口 `core/api/datasets/datasets.py` 的 `POST /{dataset_uuid}/execute`）。调用该入口时请求体使用已有 `ExecuteQueryRequest` 的 `parameters`、`limit`、`offset`。报表配置不存放任意 SQL，不把 `query_config` 抄进 `report_config`。
- `static` 类型从该数据源 `config` 取行，仍返回 `data` / `total` / `summary`。
- 筛选、分页、合计按 `report_config` 作用在这一次执行上。`UniReport` config 模式把 `buildExecuteFilters`（`components/uni-report/configAdapter.ts`）的返回值交给 `executeReport`。放进 `executeReport` 的分页键是 `limit` 与 `offset`（由页码换算），不是 `current` / `pageSize`。区间筛选（`operator` 为 `between`）写成 `字段_start` / `字段_end`。

### Acceptance Criteria

1. 上述两个 `kuaireport` 忽略行不再排除本仓文件；`PRO_APPS` 不再包含 `kuaireport`；`kuaiiot` 的忽略行与名单项仍在。
2. 槽位目录与前后端 `manifest.json` 在本仓，且不来自私仓组装拷贝。目录在本切片之前不存在。
3. 能写入 `apps_kuaireport_data_sources`：`type` 仅为 `static`、`dataset`、`http`。`http` 的执行地址必须等于本租户一条 `type=http` 登记行的地址；其它地址拒绝。
4. `src/apps/kuaireport/services/kuaireport.ts` 存在并导出 `executeReport`。`UniReport` config 模式不再因 glob 为空抛出 `kuaireport is not composed into this workspace`。
5. 对一张已用 `report_config.extra.data_source_uuid` 绑定单一数据源的报表调用 `executeReport(reportId, filters)`，返回含 `data`（数组）、`total`（数字）、`summary`（字段到数字）。绑定不用顶层整数 `data_source_id`。`report_config` 与数据源 `config` 中不出现 SQL 正文。
6. 引用数据集时只调用已有数据集执行器，请求体为 `parameters`、`limit`、`offset`。`ExecuteQueryResponse` 现有字段是 `success` / `data` / `total` / `columns` / `elapsed_time` / `error`，另有 `affected`（仅 `sql_write`），**没有** `summary`。合计仍由报表层按 `report_config` 产生，不改数据集响应模型。本条不验收 `sql_write`。
7. 无租户上下文不读 `apps_kuaireport_*`。不读数采表。

### Rules and Constraints

Tenant isolation:

- 表上已有 `tenant_id`。登记与执行都带当前租户。跨租户的报表 id、数据源 id、数据集 uuid 不执行。

Security and masking:

- HTTP 登记行的地址不是密钥。日志不写口令、数据集连接密文、内部路径。
- 不把任意 URL 当作可执行地址。

Audit and lineage:

- 执行失败沿用数据集行上已有的 `last_error` 语义即可，不在本切片新造审计表。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 只用迁移 92 已创建的 `apps_kuaireport_data_sources` 与 `apps_kuaireport_reports`。不改 92 的文件名与已有列。
- `apps_kuaireport_dashboards.code` 在迁移 92 是表级 `UNIQUE`（不是 `(tenant_id, code)`）。本切片不改这个约束，也不靠大屏表完成验收。

## 2. Plan

### Implementation Approach

1. 收归槽位：只动 `kuaireport` 的忽略与 `PRO_APPS`，目录按 `apps/kuaiai` 的 manifest 骨架新建。
2. 数据源 CRUD 落在 `apps_kuaireport_data_sources`。`dataset` 的 `config` 只存数据集 uuid（及必要的显示名），不存 `query_config`。
3. 报表执行读 `report_config.extra.data_source_uuid`（本租户 `apps_kuaireport_data_sources.uuid`），不用顶层整数 `data_source_id`，按类型取数，套上字段、筛选、分页、合计，组装 `UniReport` 已约定的返回。
4. 前端补 `kuaireport.ts` 的 `executeReport`，让现有 glob 能加载。不改 `UniReport.tsx`。

### Affected Modules

- `kuaigeyun-mes/.gitignore`（只删两条 `kuaireport` 路径）
- `kuaigeyun-mes/fast-deploy/tools/workspace/generate_workspace.py`（`PRO_APPS` 去掉 `kuaireport`）
- 新建 `riveredge-backend/src/apps/kuaireport/`（本切片之前不存在）
- 新建 `riveredge-frontend/src/apps/kuaireport/services/kuaireport.ts`（本切片之前不存在；路径由 `UniReport.tsx` 的 glob 写死）
- 只读依赖：`core/models/dataset.py`、`core/api/datasets/datasets.py` 的 `execute_dataset_query`、`UniReport.tsx` 的 `executeReport`

### Public Contracts

- 已存在、本切片实现而不改签名：`executeReport(reportId, filters) -> { data?, total?, success?, summary? }`。
- 已存在、本切片调用而不改响应模型：`POST /datasets/{dataset_uuid}/execute`。请求体为 `parameters`、`limit`、`offset`。`ExecuteQueryResponse` 无 `summary`，有 `affected`（仅 `sql_write`；本切片不绑定该类型）。
- 应用内执行接口是本切片要补的槽位行为，不写成仓内已经存在的 URL。

### Persistence Changes

- 无新表、无新迁移。写入 `apps_kuaireport_data_sources`（`type`、`config`、`tenant_id`）和报表行的 `report_config`。

### Transaction Boundaries

- 一次执行只读数据源与报表配置，不在同一次执行里写版本、分享或订阅。

### Risks

- glob 路径写错则 `UniReport` 仍报未组装。验收必须看到 `services/kuaireport.ts` 被该 glob 命中。
- 数据集执行结果没有 `summary`，若直接透传，合计行为空。合计必须在报表层按 `report_config` 计算。

### Verification Strategy

- 见 §3。§4 在命令实跑后填写。本文件写下时未跑测试。
