# 工位终端边界收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变现有登录和业务接口契约的前提下，使纯工位账号只能使用专用工位界面，并以服务端可信的操作员会话约束工位写操作。

**Architecture:** 登录账号继续使用现有 JWT、RBAC 和租户上下文；新增的操作员会话只证明“谁正在该工位操作”，不参与提权。前端以纯工位角色判定落点和布局，Electron 仅做路径约束；后端以显式工位权限和数据库会话共同保护写操作，PC 用户仍走原权限路径。

**Tech Stack:** Python 3.11、FastAPI、Pydantic、Tortoise ORM、aerich、PostgreSQL；React 18、TypeScript、Vite、Ant Design；Electron 44、Node `node:test`。

**Spec:** `docs/04.specs/180.station-terminal-scope-hardening.md`

## Global Constraints

- 实现与提交只落 `kuaigeyun-mes/`；本文档仍由外层仓库管理。
- 保持现有 API URL、HTTP method、JWT 认证头、响应外层结构不变；只允许新增操作员会话接口和 `X-Station-Operator-Session` 业务头。
- 不引入第二套 ORM、认证或前端框架，不升级 React、Vite、Ant Design 或 Electron。
- `STATION_TERMINAL` 只能由管理员通过现有 `/core/roles/load-preset` 主动、幂等加载，迁移不得创建角色。
- 工位角色必须是纯角色：`station` 不得与 `internal` 或 `external` 同时绑定给同一用户。
- 当前操作员只改变业务记录归属，不改变 JWT 用户、角色或权限。
- 操作员确认只允许人脸或员工码；第一阶段无任何降级通道。
- 会话原始凭据只保存在页面内存；数据库仅保存 SHA-256 哈希，刷新、重启、崩溃或断电后不恢复。
- 操作员会话无固定时长和空闲超时，只在显式换人、退出或新确认替换旧会话时关闭。
- 所有操作员会话读写必须按当前租户、终端账号和工位过滤；失败响应不得泄露候选人或其他操作员信息。
- 新迁移放 `riveredge-backend/migrations/models/20261008120000_station_operator_sessions.py`；该时间戳大于计划编写时目录最大值 `20261007130000`，执行前若最大值已变化，先改为更大的 14 位时间戳且同步本文引用。
- 不修改 `fast-deploy`、Electron 打包产物或 `startech-mes-basic/`。

## Review Focus

- 用户同时拥有一个 `station` 和一个非 `station` 角色时，所有角色绑定入口都必须拒绝，不能只拦角色管理页。
- 纯工位账号直接输入 PC URL、使用浏览器后退或从 Electron 同源跳转时，必须 replace 回工位入口且不能短暂渲染 PC 壳。
- 候选人、员工码解析用户、人脸识别用户任一不一致时，确认必须失败且不得返回实际匹配人身份。
- 原始凭据、错误凭据、跨租户凭据、跨终端账号凭据和跨工位凭据均不得通过写门禁。
- PC 用户不携带工位会话头时，原有菜单、权限和写接口行为必须保持不变。
