### Capability

- Name: 委外收货套用来料检验

  - 判定：`docs/04.specs/140.kuai-inspection-gate-status-contract.md`

### Business Goal

委外收货与采购来料、客供料用同一套来料判定。没配策略必检；只有物料上显式免检，或环节/模块关闭，才在创建时完成并过账。必检的收货先落草稿，确认前必须已有合格来料检验，或已处理的让步单。

### Scope

In scope:

- 来料检验单增加可空的委外收货关联（标识与编码快照），与 `purchase_receipt_id` / `customer_material_registration_id` 并列。`source_type` 增加委外收货取值，与现网过账 `source_type` `outsource_material_receipt` 同一词。
- 按收货物料调用已有 `inbound_inspection_required`（环节 `iqc`）。
- 必检时 `create_material_receipt` 只落 `draft`；`complete_material_receipt` 在改成 `completed` 并过账之前做断言。
- 停用 `_normalize_legacy_draft_receipts` 把 draft 改成 completed。
- 建单沿用 `IncomingInspection`，增加从委外收货创建来料检验的入口，对标 `create_inspection_from_customer_material_registration`。

Out of scope:

- 不新造检验类型，不新检验单表，不新让步表，不给 `DefectRecord` 加委外外键，不新造 8D。
- 不把采购退料纳入。
- 不改 `assert_iqc_for_purchase_receipt_lines`、`assert_iqc_for_customer_material_registration_lines` 已经按 spec 140 收口的放行口。
- 不另做一套免检开关。
- 不重放历史「创建时已入库但状态仍是 draft」的库存。
- 不改采购来料与客供料的 URL、method、认证头、响应外层结构。

### Acceptance Criteria

1. source `default_none` 的委外收货物料：创建后状态为 `draft`，不增加委外工单已收/合格数量，不排库存与应付。`complete_material_receipt` 在没有合格来料检验、也没有已处理让步单时拒绝，单据保持 `draft`，库存不动，状态不被写成 `completed`。
2. 合格判定用已有 `iqc_inspection_passed_for_inbound`，检验单挂在该委外收货单上。通过后确认才把状态写成 `completed`、过账，并回写委外工单已收/合格数量。
3. 让步放行只认 `DefectRecord`：`disposition == "accept"`、`status == "processed"`，且 `incoming_inspection_id` 指向本收货单的来料检验。`status == "draft"` 的让步单不放行。
4. source `material` 且 eff `none`：创建即 `completed` 并按现网过账，不要求检验单。
5. source `stage_disabled` / `module_disabled`：同样放行，创建即完成并过账。
6. 列表（686 行）与详情（735 行）不再把 draft 扫成 completed。
7. 采购来料与客供料的既有放行口行为不变。采购退料不新增检验门禁。

### Rules and Constraints

Tenant isolation:

- 新关联与查询带现有组织隔离。委外收货单与来料检验单的 `tenant_id` 必须一致。

Security and masking:

- 拒绝文案不包含凭据或内部路径。

Audit and lineage:

- 不新审计表。检验单用来料检验单，让步用已有不良单。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 来料检验单增加可空委外收货标识与编码快照。需要一条 Tortoise app `models` 的 aerich 迁移。文件放 `migrations/models/`。文件名第一段为 14 位时间戳，且大于该目录已有迁移文件名里出现过的最大时间戳。不要接开源仓序号（如 793）。本 spec 不指定文件名。
- 不新检验单表，不新让步表。

## 2. Plan

### Implementation Approach

- 判定只调用 `inbound_inspection_required`（`inspection_policy_service.py` 1226–1236 行）。必检与免检分叉放在创建与确认，不放在提交后的异步过账任务。
- 免检与环节/模块关闭保持今天的创建即完成：写 `completed`、增加委外工单数量、提交后 `_schedule_stock_for_outsource_receipt`。
- 必检把过账与数量回写挪到确认成功之后。

### Affected Modules

- `src/apps/kuaizhizao/models/incoming_inspection.py`
- `src/apps/kuaizhizao/services/outsource_material_receipt_service.py`
- `src/apps/kuaizhizao/services/quality_service.py`（来料检验建单）
- `src/apps/kuaizhizao/services/inspection_policy_service.py`（只复用判定与合格函数，不改采购/客供断言）
- 来料检验与委外收货的 schema / 既有 API 编排（加可空字段与委外来源，不改既有 URL）
- `riveredge-frontend`：沿用现有来料检验建单与委外收货确认，能把检验单挂到 draft 收货上。不新页面类型。
- 对应单测

### Public Contracts

- 不改既有委外收货与来料检验 URL、method、认证头、响应外层结构。
- 来料检验响应对象增加可空委外收货标识与编码。`source_type` 允许 `outsource_material_receipt`，与模型注释里已有的 `purchase_receipt` / `customer_material_inbound` / `purchase_order` 并列。
- 委外收货创建在必检时返回的状态为 `draft`。免检时仍为 `completed`。

### Persistence Changes

- `IncomingInspection` 增加可空 `outsource_material_receipt_id` 与 `outsource_material_receipt_code`，与 30–39 行的采购入库、客供料字段并列。
- 一条 `models` 迁移，文件名规则见 Database rules。

### Transaction Boundaries

- 必检创建：只提交 draft 收货单。不增加委外工单已收/合格数量，不排库存，不排应付。
- 确认：断言失败则不把状态写成 `completed`，库存不动，draft 保留。断言通过后，状态、过账、委外工单数量回写同一成败。
- 免检创建：与现网同一事务写 `completed` 并回写数量，提交后再异步过账。

### Risks

- 列表把 draft 扫成完成，确认门禁被绕过。停用 635–649 行的状态改写。
- 物料显式免检被收成必检。source `material` 且 eff `none` 仍创建即完成。
- 把让步外键加到 `DefectRecord`。只反查 `incoming_inspection_id`。

### Verification Strategy

- 在 `kuaigeyun-mes/riveredge-backend` 用 `uv run pytest` 覆盖必检拒绝、免检放行、环节关闭放行、列表不改 draft。前端改了确认或建单交互时，在浏览器走一遍 draft 确认与免检创建。未跑通不得声称通过。
