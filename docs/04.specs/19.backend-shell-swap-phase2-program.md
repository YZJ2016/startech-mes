# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 后端换壳阶段 2 总控（2a Boot 3.x → 2b Boot 4.1；不改模块名/包名）
- Module: `startech-mes-basic/backend` 聚合（六平台模块 + `ktg-mes` 适配）
- Priority: P0
- Related requirement/design documents:
  - 阶段 1 总控与门禁：`docs/04.specs/11.backend-shell-swap-program.md`、`18.shell-swap-phase1-verify.md`
  - 五项接线与纯度：`09` / `10` 第 7 节（阶段 1 **已经做完**；阶段 2 只在新栈上 **重做检查**，不当成未抽出）
  - 本批开发单元：`20`–`26`

### Business Goal

在阶段 1 已把平台内容对齐 `origin/springboot2`（Java 8 / Boot 2.5.15 / javax，模块名仍 `ktg-*`、包名仍 `com.ktg`）的前提下，**分两跳**升到若依当前 `master` 线，避免一次从 Boot 2.5 跳到 Boot 4.1：

- **2a**：对齐 `origin/springboot3`（JDK 17 + Spring Boot **3.5.16** + jakarta + SpringDoc）
- **2b**：再对齐当前 `origin/master`（仍 JDK 17，Spring Boot **4.1.0**）

`ktg-mes` 必须单独适配，不能假装 721 个业务文件自动能编过。模块改名为 `ruoyi-*`、包名改 `com.ruoyi` 默认 **不做**（见 `25`）。前端 Vue3 另立项，不进 2a/2b 必做。本文件只写阶段 2 的前提、对照 commit、工作树、git 边界、顺序与完成定义；不写业务代码。

### Scope

In scope:

- 前提：阶段 1 完成（`18` 第 4 节有 JDK 8 全量 `compiler:compile` SUCCESS，五项已勾）。未完成则停止，先回到 `12`–`18`
- 2a：父 POM 工具链（`20`）+ 六平台模块内容对齐 springboot3（`21`）+ `ktg-mes` jakarta/第三方适配（`22`）+ 五项在 Security 6 `SecurityFilterChain` 上重挂（`23`）
- 2b：六平台模块再对齐 `master` Boot 4.1（`24`）；mes 若再破编译，只修编译闭合，不借机改业务
- 对照源锁定为下方实测 commit，**禁止**用错分支当 2a/2b 真源
- 改动只发生在 nested `startech-mes-basic`；外层 `RuoYi-Vue` / worktree / `RuoYi-Vue3-front` 只读
- 模块目录名、`<modules>`、`artifactId` 仍为 `ktg-*`；Java 包仍为 `com.ktg`（`25` 除外且默认跳过）

Out of scope:

- 把阶段 1 的抽出（`MesPermitAllProvider` 迁出、前缀首次 `ktg-mes:`→`ruoyi:`、notice `/list` 首次隔离、uploadMinio 首次迁 mes、手机号登录首次并入）再当「还没做」
- 一次从 Boot 2.5 直接换 `master`（跳过 2a）
- 2a 与 2b 混在同一单元、同一 PR
- `25` 模块/包名改名（除非产品书面要求）
- 前端 Vue 2 → Vue 3；不碰 `RuoYi-Vue3-front`；不改 `startech-mes-basic/frontend/`（AGENTS.md 冻结；**另立项**）
- 改工单/库存状态机、改历史 SQL 原地文件
- 在无命令输出时写「编译通过 / 测试通过」

### Acceptance Criteria

- `20`–`26` 各有独立 spec，顺序与本文件波次表一致
- 2a 结束：对照 worktree HEAD = springboot3 锁定 hash；`java.version=17`；`spring-boot.version=3.5.16`；平台 + mes 在 **JDK 17** 下聚合编译通过；五项在 `23`/`26` 勾选
- 2b 结束：对照 HEAD = master 锁定 hash；`spring-boot.version=4.1.0`；再次 JDK 17 聚合编译通过；五项再勾一次
- 模块名仍 `ktg-*`、包名仍 `com.ktg`（若未执行 `25`）
- `ktg-mes` 仍在聚合中；admin 仍依赖 `ktg-mes`
- 文档、补丁、日志不出现真实密码、Token、生产地址、数据库连接串

### Rules and Constraints

Tenant isolation:

- 本批不引入租户字段，不改变现有数据隔离方式

Security and masking:

- 不在 spec、补丁、日志中复述 Token、Minio/OSS 密钥、数据库口令或内网地址
- yml **只对键、不对密钥**：对照 springboot3 / master 的键名，值留在 nested 现有文件中
- 不得扩大匿名访问面；`MesPermitAllProviderImpl` 路径集合以阶段 1 收口后为准（`08` + 抽出后实现），不要猜 PathPattern 差异就改表
- 不引入第二套认证；继续 JWT `Authorization`

Audit and lineage:

- 历史 SQL 不原地改写；缺表另开增量脚本，不在本总控当必做
- 换壳是栈升级 + 接线，不是借机改 MES 业务语义

AI/rule-engine rules:

- 本批不涉及规则引擎或 AI

Database rules:

- MES 业务表本批不改结构
- 禁止把 mes 公告已读字段接回平台 `SysNotice`

#### 机械替换（2a/2b 每个平台模块相同）

1. 用对照树 `ruoyi-<mod>/` 覆盖 nested `backend/ktg-<mod>/` 的 **src**（及该模块 pom 中与上游对应的依赖声明）

3. 该模块 `pom.xml`：`artifactId` `ruoyi-*` → `ktg-*`；parent 保持 `com.ktg:ktg` + nested 现有 parent 版本（当前 `3.8.2`，不必改成若依产品号 3.9.2）；`${ruoyi.version}` → `${ktg.version}`

5. 覆盖后立刻把阶段 1 已有接线装回（清单见 `21`/`23`），然后用 **JDK 17** 编译

根 `backend/pom.xml`：保留 `<module>ktg-mes</module>` 与 `com.ktg` / `ktg`。2a 按 `20` 纳入 springboot3 属性（Java 17 / Boot 3.5.16 / jakarta）。2b 再按 `24` 纳入 Boot 4.1.0。禁止在 2a 引入 Boot 4 坐标。

#### 五项检查单（阶段 2 **重做检查**，与 `10` 第 7 节同一套契约）

前缀在阶段 1 结束后 **已应是** `ruoyi:`。阶段 2 要确认覆盖 yml/Java 后仍成立，而不是再做一次 `ktg-mes:`→`ruoyi:` 的产品决策。

3. mes 仍提供 `GET /system/notice/list`；换入的若依 `SysNoticeController` **无** `/list`
4. mes 仍提供 `POST /common/uploadMinio`；换入的 `CommonController` **无**该映射
5. `UserDetailsServiceImpl` 仍含 `selectUserByMobile` + 阶段 1 同一套手机号正则；无第二套 JWT

`ktg-mes` 路径冻结（换壳不得改 URL）：

- `GET /system/notice/list`
- `POST /common/uploadMinio`

- 2a 必改：`ktg-mes` 的 jakarta import、Swagger 注解、以及为编译闭合所必需的 pom（UReport/Minio/WebSocket 等，见 `22`）

### Risks

- 误用 `master` 当 2a 对照，一次跳到 Boot 4.1
- 只换六平台、不改编 mes，聚合永远失败却宣称 2a 完成
- 覆盖 common/framework 丢掉 `MesPermitAllProvider` 或 FilterChain 注入
- 覆盖 admin 再次引入若依 `/list` 或漏接 uploadMinio
- 覆盖 `UserDetailsServiceImpl` 丢掉手机号登录
- 用若依 yml **整文件覆盖** nested（密钥/库地址/8080 端口）
- UReport 2.2.9 / Minio / `javax.websocket` 在 jakarta 下的兼容性未知——**先编再记，不要猜 fork**
- Security 6 默认 PathPattern 与旧 ant 通配略有差异——**有环境再探测，先不要改路径表**
- 把 Vue3 或 `25` 改名塞进 2a
- 本机默认 JDK 8/21 却当成 JDK 17 成功
