本文件是可执行开发单元，直接承载实现方案、任务拆分与验证记录；需求边界来自 `docs/02.requirements/20.station-terminal-gaps.md`，设计理由来自 `docs/03.design/20.station-terminal-plan.md`。实现只落 `kuaigeyun-mes/`；本文位于外层仓库 `docs/04.specs/`。

## 1. Spec

- Module: `kuaigeyun-mes/riveredge-frontend`、`riveredge-backend`、`kuaigeyun-client/riveredge-app-station`

### Business Goal

把当前「Electron 全屏打开 PC Web」收口成真正的工位终端：纯工位账号只能进入专用界面，Electron 不能在同源站点内跳入 PC 模块；操作员必须经刷脸或员工码确认，且服务端确认会话通过后，工位账号才能执行产生业务记录的动作。

### Scope

In scope:

- 正式预设角色 `STATION_TERMINAL`：`role_type=station`、`functional_domain=production`、工位首页、显式最小权限集合；管理员主动、幂等加载。
- 用户角色纯度校验：`station` 不得与 `internal`、`external` 混挂。
- 纯工位账号的登录落点与路由守卫；Electron 拒绝非纯工位账号。
- 工位路径使用独立 `StationLayout`，移除 PC 侧栏、应用切换、UniTabs、系统配置与个人偏好入口。
- Electron 认证路径、锁屏、工位入口及其子路径白名单。
- 数据库操作员会话、随机凭据哈希、刷脸/员工码确认、关闭与状态接口。
- 纯工位账号的工位写操作增加服务端操作员会话门禁；现有 PC 调用保持不变。
- 默认工位角色不授 reporting assign，不展示独立代报入口。

Out of scope:

- 第二套前端构建、ORM、认证体系或登录 Token。
- 修改现有业务 URL、HTTP method、登录认证头或响应外层结构。
- 主管一次性码、终端密码、人工原因等身份降级。
- 当前操作员继承个人角色权限或刷脸提权。
- 计划、主数据、审批、财务和系统管理的工位页面。
- Electron 打包脚本、`.exe` 产物和 `fast-deploy` 改造。

### Acceptance Criteria

1. `STATION_TERMINAL` 可由管理员通过现有预设加载入口按租户幂等创建；迁移不静默创建角色。
2. 用户不能保存混合 `station` 与非 `station` 角色的绑定。
3. 纯工位账号从 Electron 或浏览器登录均进入工位入口，访问非工位业务路径会被 replace 回入口。
4. Electron 中非纯工位账号被拒绝，当前会话被清理并回到登录页。
5. 工位入口不出现 PC 侧栏、应用切换、UniTabs、系统配置、个人偏好或任意地址跳转。
6. 点选人员仅生成候选人；只有刷脸或员工码与候选人一致，服务端才创建操作员会话。
7. 凭据只存在页面内存，数据库只存哈希；刷新、Electron 重启、异常退出或断电恢复后必须重新确认。
8. 未确认操作员时可查看当前任务资料，但不能开工、报工、安灯、交接或执行其他写操作。
9. 操作员会话与租户、终端账号、工位、操作员不一致时，服务端拒绝写入且不泄露其他人员信息。
10. 默认工位角色没有 reporting assign；工位首页不展示独立代报入口。
11. PC 账号现有登录、菜单、路由和业务接口行为不回归。

### Rules and Constraints

Tenant isolation:

- 操作员会话所有查询与更新必须带当前租户条件；凭据不能跨租户、跨终端账号或跨工位复用。

Security and masking:

- `X-Client-Channel`、`window.stationShell`、URL、`workstationId` 均不是授权证明。
- 人脸特征、员工码明文、登录 Token、操作员会话原始凭据不得写入数据库、日志、toast 或错误响应。
- 数据库只存操作员会话凭据哈希；比较使用恒定时间策略。
- 当前操作员只提供业务归属，不改变登录用户和权限集合。

Audit and lineage:

- 会话记录终端账号、操作员、工位、确认方式、签发/最后活动/关闭时间、状态和关闭原因。
- 现有业务记录继续使用既有操作员字段；会话只作为可信来源与审计关联，不替换业务字段。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 新表放在现有 Tortoise `models` app；迁移文件放 `riveredge-backend/migrations/models/`，文件名首段使用大于目录现有最大时间戳的 14 位时间戳。
- 不另建迁移目录，不使用开源序号续编，不修改已执行迁移文件名。

## 2. Plan

### Implementation Approach

1. 为预设角色增加显式权限集合和纯角色类型校验；前后端共同阻止混合角色保存。
2. 在主路由按工位路径选择 `StationLayout`，并在认证完成后按角色纯度执行登录落点与路由守卫。
3. Electron 将 `will-navigate` 从同源判断收紧为必要认证/锁屏/工位路径白名单，并接收前端的非纯工位账号拒绝结果。
4. 新增操作员会话模型、迁移、服务与确认/关闭/状态接口。确认成功时关闭同一租户和终端账号的遗留活动会话。
5. 刷脸或员工码解析结果必须与候选人一致；不一致只返回通用失败。
6. 前端把随机会话凭据保存在运行时内存，并通过统一请求封装为工位写请求附加业务头。
7. 对纯工位账号的工位写入口统一增加会话依赖；读取路径与 PC 调用不改变。
8. 移除默认工位角色的代报入口和 assign 权限，补齐回归测试。

实施顺序遵循测试先行：每个任务先补失败测试，再做最小实现、运行专项测试并独立提交；全部任务完成后再执行全量回归。

### Public Contracts

- 保持 `/apps/kuaizhizao/production-execution/station` 及现有子路径不变。
- 保持现有业务 API URL、HTTP method、登录认证头与响应外层结构不变。
- 新增操作员确认、关闭、状态接口和独立工位业务凭据头；该凭据不替代登录 Token。
- `STATION_TERMINAL` 为稳定预设编码；预设加载继续使用现有 `/core/roles/load-preset`。

### Persistence Changes

- 新增工位操作员会话表。至少包含租户、终端用户、工位、操作员、确认方式、凭据哈希、状态、签发/最后活动/关闭时间、关闭原因和审计字段。
- 不存人脸特征、员工码明文或原始会话凭据。
- 迁移计划文件为 `riveredge-backend/migrations/models/20261008120000_station_operator_sessions.py`；计划编写时目录最大时间戳为 `20261007130000`。执行前若最大值变化，须改成更大的 14 位时间戳并同步本文。

### Transaction Boundaries

- 新确认操作员时，在同一事务中关闭当前终端账号的遗留活动会话并创建新会话。
- 关闭会话为幂等操作。
- 业务写操作验证会话后仍进入原有业务事务；会话校验不另行提交业务数据。

### Risks

- 仅在前端隐藏 PC 菜单会留下 URL 与接口绕过，必须同时落路由守卫、Electron 白名单和服务端 RBAC。
- 操作员凭据若写入持久存储，会违背刷新/重启后重新确认的决策。
- 预设权限若用宽泛前缀匹配，未来新增生产权限会使工位角色自动扩权。
- 会话无固定超时；界面必须持续醒目显示当前操作员。遗留活动行在下次成功确认时关闭。
- 第一阶段不允许身份降级，确认服务或网络不可用时生产写操作会被阻断，这是已接受的产品边界。

### Verification Strategy

- 后端：角色预设、混合角色拒绝、租户隔离、凭据哈希、候选人一致性、会话替换/关闭、工位与操作员不匹配、写操作门禁、PC 回归测试。
- 前端：登录落点、路由 replace、StationLayout、候选/已确认状态、凭据仅内存、刷新清空、无代报入口测试。
- Electron：允许/拒绝路径表、跨同源 PC 路由阻断、非纯工位账号拒绝流程测试。
- 实跑 `cd kuaigeyun-mes/riveredge-backend && uv run pytest` 与 `cd kuaigeyun-mes/riveredge-frontend && npm run build`；未实际成功不得写为通过。
- Windows Electron 真机手工验证全屏、登录、刷新、重启、断网和扫码/刷脸主路径。

### Implementation Decisions

- 员工码使用租户内唯一的 `KuaioaEmployeeProfile.employee_code` 解析，档案必须为 active、未删除、已关联同租户启用用户；不以 `User.username` 回退。现有系统用户二维码把 username 写入 `employee_code` 只是现状兼容数据，不能作为可信工号规则。
- 预设角色新增显式权限集合，至少包含基线权限、工位终端 read/execute、工单 read 及报工/物料所需 read；禁止使用权限前缀自动扩权，禁止 `reporting:assign`。
- 工位写权限使用 `kuaizhizao:production-execution-terminal:execute`。既有 PC 用户继续使用原权限；工位账号不通过授予宽泛 `work-order:create` 绕过最小权限原则。
- 业务请求头统一为 `X-Station-Operator-Session`。仅调用方显式 opt-in 的请求附加该头：工位写请求、操作员会话自管理端点中显式携带凭据的 current/close（confirm 为签发入口本身不带头），以及显式标记的操作员作用域读取（目前仅 `GET /station/face-templates/me`）；既有业务读取不附加。
- Electron 只允许当前服务 origin 下的登录、锁屏、工位入口及真实子路径；拒绝同源 PC 路由、伪前缀、新窗口和跨源跳转。
