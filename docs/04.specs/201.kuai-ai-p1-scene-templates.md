# KU-AI P1 场景预置模板

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施（2026-10-23）；T1、T2 选定均为 a。

## 1. Spec

### Capability

- Name: 用 P1 新 Tool 组装场景模板：新增 3 个出厂模板，更新既有模板定义；设置页模板开关改为后端驱动。
- Module: `riveredge-backend/src/apps/kuaiai/services/agent_scene_service.py`、`services/settings_service.py`、`core/utils/integration_settings.py`；`riveredge-frontend/src/apps/kuaiai/{pages/settings,pages/agent-library,assets/scenes}`。
- Priority: P1（S01、S02、S06、S07、S08、S11、S12、S21 的入口）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D12；设计 26 §5.3；设计 24 §5.2–5.3（预置规则）；前置 spec 190、195–200。

### Business Goal

各角色在智能体库直接找到对应场景（班组长、订单交期、作业指导等），管理员授权启用后即可使用 P1 场景，不必手工组装 Tool。

### Scope

In scope:

新增模板（新 key，经既有 `seed_kuaiai_agent_scenes_on_lifecycle` 自动为所有已安装租户补齐，停用、空授权）；模板落地即在能力矩阵出现同名场景卡（spec 191 默认绑定同 key 预置实例，Y1/Y2=a），无需人工配置绑定：

| key | 名称 | Tool 组合 | 覆盖场景 |
| --- | --- | --- | --- |
| `shift-lead` | 班组长助手 | `query_work_orders`、`analyze_kitting`、`query_material_shortages`、`query_production_daily`、`query_pulse_signals` | S02 S07 S08 |
| `order-delivery` | 订单交期助手 | `query_sales_orders`、`query_work_orders`、`analyze_delivery_risk`、`analyze_kitting` | S01 |
| `work-instruction` | 作业指导助手 | `search_knowledge`、`query_process_routes`、`query_work_orders` | S11 |

既有模板定义更新（T1=a：只改模板定义，已存在租户的预置档案不改）：

| key | 追加 Tool |
| --- | --- |
| `inventory-insight` | `query_inventory_alerts`、`query_replenishment_suggestions`、`query_slow_moving_inventory` |
| `purchase-followup` | `query_purchase_arrival_warnings` |
| `quality-analysis` | `query_quality_exceptions`、`analyze_first_pass_yield`、`analyze_defect_pareto` |

- 预置档案不含写 Tool（`submit_production_feedback` 由管理员在 HITL 上线后按需勾选，S09）。
- 设置页模板开关改为后端驱动：GET 返回 `agent_templates: [{key, name}]`（按 `SCENE_TEMPLATES` 顺序），前端删除 `AGENT_TEMPLATE_KEYS`、`AGENT_NAME_FALLBACK` 硬编码（`pages/settings/index.tsx` 现写死 6 个 key，而后端 `validate_agent_switches_payload` 要求 key 集合与模板完全一致，新增模板后不改前端将导致保存 422）。
- 新模板的业务路由加入 `SCENE_ROUTE_PERMISSIONS` 白名单（路径与权限码 T1 从 kuaizhizao manifest 取），插画加入 `assets/scenes`。

Out of scope:

- 设备、ECN 等 P2 场景模板。
- 自动启用档案或写授权名单（沿用 spec 181：不写 grant）。

### 决策（2026-10-23 用户选定）

- **T1 = a**：只改模板定义。评估前提：当前无生产数据与真实用户，选 a 几乎无迁移成本；同时确立长期规则——“模板定义是产品默认组合，已建档案归租户所有，后台不改写”，P2 模板调整沿用此规则，不写追加 Tool 的数据迁移。开发/测试租户需新组合时在 `/agents` 手动勾选或重装应用。平台更新日志写明“已有租户可在 Agent 档案页自行追加新工具”。
- **T2 = a**：新绘 3 张 SVG（风格同现有 `assets/scenes`）；设计资源未到位时先用 `_default.svg` 上线并记 Known gap。

原选项存档：

| 编号 | 场景 | 选项 | 推荐与理由 |
| --- | --- | --- | --- |
| T1 | 既有 6 个模板追加 P1 Tool 的方式。`seed` 只补缺失模板，已存在租户的预置档案不会被更新（spec 181 规定尊重租户定制） | a. 只改模板定义：新安装租户得到新组合，已存在租户档案不变，管理员可在 `/agents` 自行勾选；b. 不改既有模板，P1 Tool 全部放进新模板；c. 改模板定义并数据迁移给“未被修改过”的预置档案追加 Tool | **a**：模板是产品真源，应反映最佳组合；不覆盖租户已有档案符合 spec 181。b 会造成与既有卡片重复的近似场景；c 无法可靠判定“未修改”（档案无该标记），可能覆盖租户定制 |
| T2 | 3 个新模板插画 | a. 新绘制 3 张 SVG，风格同现有；b. 首期使用 `_default.svg` | **a**：卡片插画是智能体库识别度的主要来源；若设计资源不到位，先 b 上线并记 Known gap |

### Acceptance Criteria

1. 已安装租户在应用启用/同步后出现 3 个新场景实例与对应停用档案；既有实例与档案不变。
2. 新租户安装得到 9 个模板，既有 6 个模板档案按更新后定义建档；已存在租户的既有 6 份预置档案 `enabled_tools` 不变（T1=a）。
3. 预置档案 `enabled_tools` 只含只读 Tool，且全部在闭集内。
4. 设置页模板开关列表由后端返回驱动，9 个开关可保存；后端校验 key 集合不变（与 `SCENE_TEMPLATES` 一致）。
5. 新模板路由在白名单内，无目标权限时 `scene_available=false`。
6. 新模板 `system_prompt` 只引用其 Tool 名，并要求“查不到就如实说明”。
7. 新模板 key 出现在 hub 场景卡中且默认绑定解析到同 key 预置实例（依赖 spec 191）。

### Rules and Constraints

Tenant isolation:

- 预置沿用 spec 181 的租户事务与系统审计身份。

Security and masking:

- 不写 grant、不启用档案；使用权仍由管理员授权。

Audit and lineage:

- 预置行 `created_by=0`、`created_by_name="系统"`。

AI/rule-engine rules:

- 提示词只规定职责与事实引用边界，不含租户业务信息。

Database rules:

- 无表结构变更、无数据迁移（T1=a）。
