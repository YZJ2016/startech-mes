## 1. Spec

### Capability

- Name: 工厂首页后端 — `getIndexNum.prepareNum` + 首页打到的 MES list 鉴权 + 布局参数种子
- Module: `startech-mes-basic/backend` 的 `ktg-mes`（工单/质检/仓储 Controller + Mapper XML）、增量 SQL（`sys_config`）。测试放 `ktg-mes`。**不改** Vue2、**不改** Vue3（前端是 76/77）。
- Priority: P0（首页轨第一刀；76 依赖本单元信封与 403 行为）
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/07.mes-home-gaps.md`（H-D2、H-D6、H-D9、H-D15、H-I1、H-I2、H-I4、H-I5、H-X1–H-X3）
  - 设计：`docs/03.design/08.mes-home-plan.md`（§3 参数、§4 数据与权限）
  - 租户前提：`docs/03.design/04.mes-shared-db-tenant-plan.md`（D1 overlay、I8 `sys_config` 在主库）
  - 下一单元：`docs/04.specs/80.mes-home-vue3-workbench.md` → `81.mes-home-vue3-charts.md`

### Business Goal

工厂工作台能从一个已有工单汇总接口读出「待确认」条数，且无对应 `list` 权限的调用方拿不到工单三态或待办 `total`。工厂布局开关作为全局 `sys_config` 种子存在，本厂 overlay 仍走现有参数设置，不写 yml。

### Scope

In scope:

- `GET /mes/pro/workorder/getIndexNum` 的 `data` 增加 `prepareNum`（`pro_workorder.status = 'PREPARE'`）；路径/method/`code/msg/data` 不变
- 该方法补 `@PreAuthorize("@ss.hasPermi('mes:pro:workorder:list')")`（现状无注解）
- **只**恢复下列 **list** 方法上被注释的 `@PreAuthorize`（H-I1），其它 CRUD/export/pad **不动**：
  - `QcIqcController.list` → `mes:qc:iqc:list`
  - `QcIpqcController.list` → `mes:qc:ipqc:list`
  - `QcOqcController.list` → `mes:qc:oqc:list`
  - `WmItemRecptController.list` → `mes:wm:itemrecpt:list`（**不含** `listForPad`）
  - `WmIssueHeaderController.list` → `mes:wm:issueheader:list`（真实路径是 `/mes/wm/issueheader/list`，不是设计初稿里的 `/mes/wm/issue`）
- `ProWorkorderMapper.getPrepareNum()` + XML `count`；SQL **不**手写 `tenant_id`（拦截器）
- 增量 SQL：全局一行 `mes.index.layout` = `single`，`tenant_id` NULL，`config_type=Y`
- 扩展已有 `ProWorkorderControllerGetIndexNumTest`；用反射断言上述 6 个方法带 `@PreAuthorize`

Out of scope:

- 新首页汇总 Controller / BFF；改 list URL 或 `rows/total`
- 恢复工单 `/list` 或其它 MES `@PreAuthorize`（含 `getIndexNum` 以外的 `ProWorkorderController`）
- 改 Vue3 / Vue2；改 `/login` / `getRouters`；改 `application*.yml` / `@Value` / `@ConfigurationProperties`
- 开通租户时复制 `sys_config`；把该键打进专库 catalog（I8）
- 部门/本人范围裁 MES；OEE 等新 KPI；时序接口
- 改 `getConfigKey` 路径或鉴权（已登录即可，保持）

### Acceptance Criteria

- 有 `mes:pro:workorder:list` 时 `getIndexNum` 的 `data` 含 `allNum`、`ingNum`、`fiNum`、`prepareNum`（均为整数）；仍 **不**调用 `selectProWorkorderList`
- `prepareNum` 只计 `status='PREPARE'`，与 `MesConstants.ORDER_STATUS_PREPARE` 一致；与 `getIngNum`（`CONFIRMED`）互不改写
- 无该权限字（且非 `*:*:*`）调用 `getIndexNum` → 403；源码方法上有 `@PreAuthorize`
- 上列 5 个 list 无权限 → 403；有权限时信封仍 `rows` + `total`
- 全局种子幂等：`config_key='mes.index.layout' AND tenant_id IS NULL` 已存在则不再插第二行；值为 `single`；无口令/主机
- 不改 yml；`selectConfigByKey("mes.index.layout")` 仍走现有 overlay 再全局
- `mvn -pl ktg-mes -am test`（或至少本单元测试类）在实现后真实跑通；本节未跑不得写成功
- 文档无凭据

### Rules and Constraints

Tenant isolation:

- `getAllNum` / `getIngNum` / `getFiNum` / `getPrepareNum` 与现网一样靠租户拦截器，XML 不加 `tenant_id`
- 无 `TenantContext` 不得访问租户表；SQL 永不跳过 `tenant_id`
- `sys_config` 全局行 `tenant_id` 为 NULL，不回填 1；不进专库

Security and masking:

- 不引入第二套认证/ORM
- 只给首页打到的 list / `getIndexNum` 恢复或补注解
- 日志不打印 token / cipher / 内部路径
- 遗留 Vue2 若仍打 `getIndexNum` 且无 `workorder:list` 将 403：接受（管理端只上 Vue3）

Audit and lineage:

- 增量 SQL 接 `backend/sql/` 最大 `NN`（当前 `20260831_36_*` → `20260831_37_mes_index_layout.sql`；若合入时 37 已被占用则顺延）
- 不原地改 `ry_*.sql` / `20260821_10_*`

AI/rule-engine rules:

- 不改 `/ai/**`

Database rules:

- 不改 `pro_workorder` 表结构
- `sys_config` 只 INSERT 一行全局键；唯一性按现网 overlay（同键允许非空 `tenant_id` overlay，本脚本不插 overlay）

## 2. Plan

### Implementation Approach

1. 先红：扩展 `ProWorkorderControllerGetIndexNumTest`，断言 `prepareNum` 且仍不走工单 list；反射测 6 个方法的 `@PreAuthorize`。
2. Mapper 接口 + XML `getPrepareNum`：`select count(0) from pro_workorder where status = 'PREPARE'`。
3. `getIndexNum` 写入 `prepareNum`，并加 `@PreAuthorize`。
4. 五处 list 取消注释对应 `@PreAuthorize` 一行，不碰相邻方法。
5. 幂等全局 `sys_config` 种子。

### Affected Modules

- `ktg-mes`：`ProWorkorderController.java`、`ProWorkorderMapper.java`、`mapper/pro/ProWorkorderMapper.xml`
- `ktg-mes`：`QcIqcController`、`QcIpqcController`、`QcOqcController`、`WmItemRecptController`、`WmIssueHeaderController`（仅 list）
- 测试：`ProWorkorderControllerGetIndexNumTest`；新增反射测试类（建议 `HomeIndexPreAuthorizeTest`）
- SQL：`startech-mes-basic/backend/sql/20260831_37_mes_index_layout.sql`
- 禁止：`frontend/`；`startech-mes-front/`；`ktg-generator`；yml

### Public Contracts

保持：

- `GET /mes/pro/workorder/getIndexNum`（登录 + `mes:pro:workorder:list`）
- `GET /mes/qc/iqc/list`、`/mes/qc/ipqc/list`、`/mes/qc/oqc/list`
- `GET /mes/wm/itemrecpt/list`、`GET /mes/wm/issueheader/list`
- `GET /system/config/configKey/{configKey}`

行为变更：

- `getIndexNum` 的 `data` **增加** `prepareNum`（旧三键保留）
- 上列接口无权限由「能查」变为 403
- 全局可读 `mes.index.layout`（未 overlay 时为 `single`）

### Persistence Changes

`20260831_37_mes_index_layout.sql`：

```sql
INSERT INTO sys_config (config_name, config_key, config_value, config_type, create_by, create_time, remark, tenant_id)
SELECT '工厂首页布局', 'mes.index.layout', 'single', 'Y', 'admin', sysdate(),
       'single=平铺；role=按权限分区。本厂 overlay 同键覆盖。', NULL
FROM DUAL
WHERE NOT EXISTS (
  SELECT 1 FROM sys_config WHERE config_key = 'mes.index.layout' AND tenant_id IS NULL
);
```

列名若与现网 `sys_config` 不一致，以表结构为准，但必须：`tenant_id` NULL、`config_type='Y'`、无主机/口令。回滚注释只删本键全局行，不删 overlay。

`getPrepareNum` 只加 Mapper XML，无 DDL。

### Transaction Boundaries

- `getIndexNum` 四次只读 count，无写事务
- 种子 SQL 单条 INSERT；不进开通租户事务

### Risks

- 恢复 list 鉴权后，以前靠「注释掉 PreAuthorize」工作的账号会 403：这是 H-D6 的目标，不是回归失败
- 误恢复工单 `/list`：该 list 会顺带查工装，且 H-I1 禁止；待确认只走 `prepareNum`
- 把领料打成 `/mes/wm/issue`：现网是 `issueheader`
- `getFiNum` SQL 复杂，本单元不得改写其 WHERE
- 种子硬编码 `config_id` 与 ry 种子冲突
