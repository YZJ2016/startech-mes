### Business Goal

入站可以带上产品物模型里定义过的事件，严重事件留下告警。操作员能对设备下发指令并等到成功、失败或超时。设备可以分组。入站、事件、指令和写回结果留在消息追踪里。

### Scope

In scope:

- 产品上的事件与指令定义用迁移 `525_20260807180000_kuaiiot_wave6_events_commands_groups.py` 已加的 `apps_kuaiiot_products.events`、`functions`（JSONB，默认 `[]`）。153 只写了 `tags`。本切片补这两段的编辑。内置预设沿用路线图已点名的典型事件（如 fault、mold_change），写入 `events`，不另建事件表。
- 入站可选 `events` 数组是本切片要补的解释。150 不处理该数组。`event_key` 必须出现在该设备所属产品的 `events` 里，否则忽略。`warning` 或 `critical` 写入已有 `apps_kuaiiot_alerts`。迁移 525 已把 `alerts.rule_id` 改成可空；事件告警用 `rule_id` 为空来区分，不另建表，也不给 `alerts` 加列。`rule_type` 只在 `apps_kuaiiot_alert_rules`（迁移 524），不在 `alerts` 上。插入时 521 里仍为 NOT NULL 的列这样填：`device_id` 为入站命中的设备；`tag_key` 用事件的 `event_key`；`severity` 与 `message` 来自该事件定义或入站事件数据；`triggered_at` 用该条入站时间（缺 `timestamp` 时与 150 一样用服务端当前时间）。不改 525 的文件名。
- 指令用已有表 `apps_kuaiiot_device_commands`。状态沿用路线图已写的闭环：`pending` → `sent` → `success` 或 `failed` 或 `timeout`。列已有：`function_key`、`params`、`dispatch_channel`、`status`（默认 `pending`）、`result`、`error_message`、`sent_at`、`completed_at`、`expires_at`。`function_key` 必须在产品 `functions` 里。
- 下发通道本切片只做边缘心跳，不对 ThingsBoard 或 JetLinks 做 RPC。152 的配置响应在本切片补上 Agent 已经读取的 `command_result_path`。152 的心跳响应在本切片补上 `pending_commands`。Agent `maybe_heartbeat` 已按 `command_uuid`、`edge_action`、`params` 执行，且只接受 `edge_action.type=modbus_write`。云侧按这个已有形状下发。回执走 Agent 已调用的 `submit_command_result`（`command_uuid`、`success`、`result`、`error_message`），把指令标成 `success` 或 `failed`。超时由 `expires_at` 判定为 `timeout`。`taskiq_app.py` 已调度 `kuaiiot_command_timeout_tick`，引用 `run_kuaiiot_command_timeout_check`。`command_timeout_workflow` 目前不存在，本切片补这个函数，不新注册同名或平行任务。
- 设备分组用已有表 `apps_kuaiiot_device_groups`（`parent_id`、`sort_order`，`(tenant_id, code)` 唯一）和 `apps_kuaiiot_devices.group_id`。分组筛选只过滤 IoT 设备行，不改星制造设备台账。
- 消息追踪用已有表 `apps_kuaiiot_message_logs`。入站、事件、指令、监控写回各写一行。列：`direction`、`msg_type`、`payload`、`result`、`error_message`。`payload` 不放入鉴权凭据。

### Acceptance Criteria

1. 产品能保存 `events` 与 `functions`。入站 `events` 里未在产品中定义的 `event_key` 不产生告警。`warning` 或 `critical` 且已定义的事件新增一条 `rule_id` 为空的 `alerts`。
2. 指令从 `pending` 到 `sent`。Agent 回执成功为 `success`，失败为 `failed`。过了 `expires_at` 仍为 `sent` 的改为 `timeout`。`function_key` 不在产品 `functions` 里时不能创建。
3. 心跳响应含 `pending_commands`，元素带 `command_uuid` 与 `edge_action`。配置响应含 `command_result_path`。本切片没有 ThingsBoard / JetLinks 的调用代码。
4. 分组树能建、能把设备的 `group_id` 指到本租户分组。其它租户的分组 id 被拒绝。
5. 一次入站、一次事件、一次指令状态变化、一次监控写回，各自在 `message_logs` 留下一行，且 `payload` 不含鉴权凭据。
6. 无租户上下文不读分组、指令和消息。不改 `apps_kuaizhizao_equipment`。

### Rules and Constraints

Tenant isolation:

- 分组、指令、消息、产品事件都带 `tenant_id`。回执只更新凭据命中的那台设备上的指令。

Security and masking:

- 消息 `payload` 与日志不写鉴权凭据、不写 Influx 凭据。
- 不内置 MQTT Broker，不在配置里保存 Broker 口令。

Audit and lineage:

- 指令状态以 `device_commands.status` 与 `completed_at` 为准。消息行是追踪，不代替指令状态。

AI/rule-engine rules:

- 事件只按产品 `events` 里已有的严重级别联动告警。不另做规则引擎。

Database rules:

- 只用迁移 525 的列和三张表：`device_groups`、`device_commands`、`message_logs`。事件告警仍写已有 `alerts`，不给该表加 `rule_type`。
- 不改 525 的文件名。不往 `tag_history` 写采样。

### 依赖顺序

- 依赖 150 的入站、152 的心跳与配置响应、153 的产品行。
- 不依赖 155。
- 不改 145–149。

## 2. Plan

### Implementation Approach

1. 产品编辑补上 `events` 与 `functions`。入站在 150 的快照写回之外解释 `events`。
2. 指令状态机写入 `device_commands`。心跳多返回 `pending_commands`，回执更新状态。不改 Agent。
3. 分组维护 `device_groups` 与 `group_id`。上述动作各写一条 `message_logs`。

### Affected Modules

- `riveredge-backend/src/apps/kuaiiot/` 云侧（本切片之前没有指令、分组、消息服务）
- 只读、不改：`edge-agent/agent.py` 的 `execute_command`、`submit_command_result`、心跳里对 `pending_commands` 的循环
- 前端槽位内补产品事件/指令编辑、分组、指令下发与消息列表
- `tests/apps/kuaiiot/test_wave6_events_commands_groups.py` 引用的服务不在槽位中，不是实现

### Public Contracts

- 本切片要补：指令创建、回执 POST（路径放进 152 配置响应的 `command_result_path`）、分组 CRUD。仓内没有这些云侧路由。
- 已存在、本切片遵守而不改代码：Agent 只执行 `modbus_write`。

### Persistence Changes

- 无新表。写入 `products.events`、`products.functions`、`device_commands`、`device_groups`、`devices.group_id`、`message_logs`，以及事件产生的 `alerts`。

### Transaction Boundaries

- 创建指令与写一条消息追踪在同一事务。回执只更新属于该设备的那条指令。超时扫描不改已是 `success` 或 `failed` 的行。

### Risks

- 在本切片调用 ThingsBoard / JetLinks RPC，就把 KIO-D6 插进了六步。
- 心跳若不带 `command_uuid`，现有 Agent 会跳过该条指令。

### Verification Strategy

- 见 §3。§4 在命令实跑后填写。本文件写下时未跑测试。
