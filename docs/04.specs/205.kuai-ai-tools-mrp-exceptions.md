# KU-AI 场景 Tool：MRP 例外解读

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：待实施。

## 1. Spec

### Capability

- Name: 新增只读 Tool `query_mrp_exceptions`。
- Module: `riveredge-backend/src/apps/kuaiai/services`（tools 适配层）、manifest `ai_tools`。
- Priority: P2（S03 MRP 结果与例外解读）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D5、SC-D7；设计 26 §4、§5.2（P2）；前置 spec 189、190。

### Business Goal

计划员问“最近一次 MRP 有哪些错误级例外、先处理哪些”，助手基于计划员收件箱的真实例外给出分组与处理顺序建议。

### Scope

In scope:

| Tool | 参数 | 底层 service（已读） | 权限码 |
| --- | --- | --- | --- |
| `query_mrp_exceptions` | `computation_id?`、`code?`、`severity?(error\|warning\|info)`、`limit≤20` | `DemandComputationService.get_mrp_exception_inbox(tenant_id, computation_id, code, severity, skip, limit, max_computations)` | `kuaizhizao:plan-management-demand-computation:read`（与 `GET /mrp-exception-inbox` 路由一致） |

- 数据范围：现路由与 service 均不接收 `current_user`，Tool 与路由同口径，不额外收紧也不放宽；在 §4 记录该事实。
- 输出：例外码、严重级、涉及物料/需求/计算编号、建议动作（若 service 返回），错误优先。

Out of scope:

- 重算、确认计划单、下推采购/工单（写操作）。
- `compare_computations` 计算差异对比（视 S03 使用反馈再定）。

### Acceptance Criteria

1. 同参数下 Tool 条目与收件箱接口一致；`severity` 非闭集值返回固定错误文案。
2. 有界摘要（总数 + 前 N 条，错误级在前）；空结果、异常与既有 Tool 口径一致。
3. 登记于 manifest（`label`、`kind=read`、权限码）。

### Rules and Constraints

Tenant isolation:

- 传 `ctx.tenant_id`。

Security and masking:

- 不输出单价、金额。

Audit and lineage:

- 沿用 Tool 级审计。

AI/rule-engine rules:

- 例外判定、严重级来自 MRP 计算结果（SC-D5）。

Database rules:

- 无表结构变更。

### 场景模板（Y3=a）

本单元交付时同步登记场景模板 `mrp-exceptions`（MRP 例外助手）：预置档案 `enabled_tools` 为本单元 Tool 集合，停用 + 空授权（Y4=a）；模板 key 即能力矩阵场景卡，默认绑定同 key 预置实例（spec 191，Y1/Y2=a）。system_prompt 只引用本单元 Tool，插画按 spec 201 T2 约定。
