## 1. Spec

### Capability

- Name: 多租户身份绑定（身份表 `tenant_id` + LoginUser/JWT + 强制 `tenantCode`）
- Module: `startech-mes-basic/backend` 的 `ktg-common`（`LoginUser`、`LoginBody`、`Constants`）、`ktg-framework`（`TokenService`、`JwtAuthenticationTokenFilter`、`SysLoginService`、`UserDetailsServiceImpl`）、`ktg-system`（User/Dept/Role/Post 及关系/日志/通知 Mapper XML）、`ktg-admin`（`SysLoginController` 透传必填 `tenantCode`）；F7 还须改 `ktg-mes` 移动端 `LoginController` / `MobileLoginService` / `LoginParams` / `TokenController`（`GET /loginOuth`）
- Priority: P1
- Related requirement/design documents:

  - 缺口：`docs/02.requirements/02.mes-multi-tenant-gaps.md`
  - 总控：`docs/04.specs/35.mes-multi-tenant-program.md`
  - 上一单元：`docs/04.specs/36.tenant-foundation-p0.md`
  - 下一单元：`docs/04.specs/38.tenant-sidechannels-p2.md`

### Business Goal

登录从第一天起绑定租户：交互 `POST /login` 必须带 `tenantCode`，按 `(tenantId, username)` 查用户，JWT 与 Redis 中的 `LoginUser` 携带 `tenantId`。此后请求只信服务端会话，忽略客户端租户头。身份与通知相关表加上 `tenant_id` 并回填工厂 1。移动端与 `GET /loginOuth` 和管理端同一套 F5（缺 Host 且缺码则失败，不默认租户 1）。管理端只走 Vue3；**不改 Vue2**——本单元之后 Vue2 交互登录会失败，视为已接受（F1）。

### Scope

In scope:

- `LoginBody.tenantCode` **必填**（D2）；`SysLoginController` 把该字段传入 `SysLoginService.login`
- `SysLoginService`：先按码（及 F5 Host）解析主库 `sys_tenant` → 停用/过期拒绝 → 调用 P0 `TenantLoginGuard`（`DATABASE` 拒登录，D7）→ `TenantContext.set` → 再查用户
- `UserDetailsServiceImpl.loadUserByUsername` / `selectUserByUserName` / `selectUserByMobile` 带 `tenant_id`；同名用户跨租户不互命中
- `LoginUser.tenantId`；`Constants.JWT_TENANT_ID = "tenant_id"`；`TokenService.createToken` 增加 claim；Redis 仍为 `login_tokens:{uuid}`，值内含 `tenantId`（R6：不改 key 前缀、不加二级 SET）
- `JwtAuthenticationTokenFilter`：解析后写 `TenantContext` + MDC；`tenantId` 空或租户停用 → 401；`finally` 清理；忽略客户端租户头
- 失败文案统一「用户名或密码错误」（D9），含租户不存在/停用/过期/缺码/用户名密码错误，不单独返回「租户不存在」
- `GET /loginOuth`（`ktg-mes` `TokenController`）与 `MobileLogin`（`/mobile/login/loginByPassword`）：同一套 F5/F7；OAuth 的 `code` 参数 **不是** `tenantCode`，另增可选 `tenantCode`；Host 未命中且缺码 → 失败，**不**默认租户 1
- 匿名 Host 解析 API（permitAll）：只用 `request.getServerName()` 匹配 `sys_tenant.server_name`，至多返回一个 `tenantCode`；未命中空 data；**禁止**租户数组、禁止按用户名反查、禁止回隔离级别/JDBC
- 停用租户：立即 SCAN 全部 `login_tokens`，按值中 `LoginUser.tenantId` 删除（D6/R6）；下一请求 401。本单元提供停用 API 或在平台更新 status=停用时调用同一作废逻辑
- DataScope：租户谓词在拦截器层始终存在；`SecurityUtils.isAdmin(userId==1)` 只跳过部门过滤，**不**删除租户谓词（D3）
- `GET /getInfo`：工厂会话可选增加 `tenantId` / `tenantName`；**不**回 `isolationLevel`、许可清单、JDBC（F2）。隔离级别只出现在平台租户管理接口（P0 已有）
- 拦截器 include 扩大到本单元已加列的身份/日志/通知表（见 Persistence）
- 增量 SQL：身份表 + 关系表 + 日志 + 通知相关 `ADD tenant_id` + 回填 1 + 唯一键；`sys_config` 可空 `tenant_id` overlay（D1）。对 P0 已加的 `sys_user`/`sys_role.tenant_id` **幂等跳过 ADD**
- `checkUserNameUnique`（及手机号唯一若存在）改为 `(tenant_id, 业务键)`
- 平台 API 额外校验：调用方 `LoginUser.tenantId==0`；现网 `admin`（`user_id=1`）不能当平台、不能 runAs（runAs 本身留 P9，本单元只挡住误用）
- SQL 文件：`startech-mes-basic/backend/sql/YYYYMMDD_NN_topic.sql`，本单元建议 `20260821_10_sys_identity_tenant_id.sql`

Out of scope:

- **不改** `startech-mes-basic/frontend/`（F1）。不为 Vue2 做兼容或切序。发布说明须写明：P1 后 Vue2 交互登录缺 `tenantCode` 将失败，**已接受**
- Vue3 登录页 F5 UI（编码框显隐、绑 Host 隐藏输入）属 P9 `46.tenant-frontend-p9.md`；本单元只提供后端契约，**不改** `startech-mes-front/` 除非为实现所必需的零行——默认零行
- P2：`TenantCacheKeys`、`pwd_err_cnt` 键含租户、`repeat_submit`/`rate_limit`、zip 键、上传 `tenant/{id}/`、下载 403、异步 TaskDecorator、WebSocket 会话 key（I9）、`/monitor/online` 过滤（R4）
- P-D / I8：专库路由、忽略名单 Mapper 绑主库（41）
- I5 懒加载连接池；I1 UReport；I3 线程池拷贝（P2）
- 启用第二个 **启用中** 的工厂。同名用户夹具必须落在 **停用** 的第二租户行上，不得启用第二工厂（P4 前门禁）
- 跨租户报表（D5）；菜单克隆；揭明文 JDBC；runAs 完整产品（F9）
- MQ / Feign / OpenAPI / BPM；Sa-Token；MyBatis-Plus；Jugg；每租户 Redis
- 改 `ktg-generator` 业务；原地改写 `ry_*.sql` / `mes-*.sql` / `quartz.sql`
- `sys_job` / `sys_auto_code_*` / `sys_attachment` / `sys_message` 加列（后续波次 / P8）
- 自助注册重新打开（F8：v1 关闭；全局注册开关保持关）

### Acceptance Criteria

对齐设计第 9 节 P1 退出标准：

- 交互 `POST /login` **必须**带 `tenantCode`；缺码失败，不绑定默认租户 1（D2）
- 用 `default`（租户 1）登录成功（`ROW`，主池）；JWT claim 与 Redis `LoginUser.tenantId==1`
- 用 `platform` 登录进入平台租户 0；`LoginUser.tenantId==0`
- 失败文案对外始终为「用户名或密码错误」（D9），不单独返回「租户不存在」或「密码错误」
- `GET /loginOuth` / `MobileLogin` 与管理端同一套 F5（F7）：Host 未命中且缺码 → 失败，**不**默认租户 1
- 本阶段 **不改** `frontend/`。P1 之后 Vue2 交互登录失败为已接受后果（F1）
- Mapper `selectUserByUserName` 带 `tenant_id`；同名用户在不同租户不互相命中（第二租户为 **停用** 夹具，不启用第二工厂）
- Filter 在租户停用时 401；停用时立即作废该租户全部 token（D6：SCAN `login_tokens`，按值中 `tenantId`）
- 已登记 `DATABASE` 租户登录失败，直到 P-D（D7）；失败关闭，不写共享库
- DataScope：条件在 `tenant_id` 之后仍存在；`isAdmin` 不删除租户谓词（D3）
- 匿名 Host 解析：至多一个 `tenantCode`；无租户列表
- `getInfo` 工厂会话可含 `tenantId`/`tenantName`，**无** `isolationLevel`
- 身份 SQL 永不跳过 `tenant_id`（含 `user_id=1`）
- 文档无真实 JDBC URL、口令、OAuth secret、生产主机

### Rules and Constraints

Tenant isolation:

- 登录解析 `sys_tenant`（主库、`@TenantIgnore`）后再设 `TenantContext`；查用户已在租户上下文中
- 登录后权威只来自 JWT/`LoginUser.tenantId`；Body/Header/Query 中的租户一律忽略
- Host 命中 `server_name` 则写死该厂（F6），提交 Body 仍带该码；不可改登别厂。平台账号必须走平台域名或未绑定入口
- `DATABASE` 在 P-D 前 **拒绝登录**，禁止静默打主库
- 拦截器 include 加入本单元已加列表；谓词占位符绑定；`isAdmin()` / `user_id=1` **不得**去掉 `tenant_id`
- DataScope 只在租户结果集内再裁部门/本人；过滤顺序：租户拦截器 → DataScope
- 第二启用工厂门禁未到：夹具租户必须 `status` 停用
- 平台租户 0 强制 ROW；工厂 `default` 为租户 1
- SQL 永不跳过 `tenant_id`

Security and masking:

- 继续 Spring Security + JWT + Redis `LoginUser`；不引入第二套认证
- D9：缺码、租户不存在、停用、过期、DATABASE 未路由、用户不存在、密码错误 → 同一句「用户名或密码错误」。服务端日志可记内部原因，不得把租户是否存在回给客户端
- 停用立即作废会话（D6/R6）：`SCAN` `login_tokens:*`（即 `CacheConstants.LOGIN_TOKEN_KEY`），反序列化值，匹配 `tenantId` 后 `DEL`。禁止 `KEYS *` 作为唯一实现（若环境无 SCAN 权限须在实现时写明降级风险，仍不得改 key 形态）
- 匿名解析接口禁止返回租户列表、JDBC、隔离级别、用户列表
- `GET /loginOuth` 改租户映射时 **不在文档或接口中复述** OAuth client-secret / token-url 真实值
- `getInfo` 不回 `isolationLevel` / JDBC / 许可清单
- 日志 MDC `tenantId`；禁止打印 token、口令、JDBC 密码
- 上传前缀与下载 403 属 P2（I2），本单元只在缺口中指向，不实现

Audit and lineage:

- 登录失败日志：能解析到租户则 `sys_logininfor.tenant_id` 用该值，否则 `0`（完整异步包装属 I3/P2；本单元至少保证列存在且登录成功路径写入当前租户）
- 停用作废须可审计「谁停用了哪租户」（操作者、时间、租户 id），**不**把 token 明文写入审计
- 历史 SQL 只追加；P0 已加列则本脚本跳过 ADD，只补 UNIQUE 与其余表
- 现网/种子用户回填 `tenant_id=1`，但 **不得**把 `user_name=platform` 行更新为 1

AI/rule-engine rules:

- 本单元不涉及规则引擎或 AI

Database rules:

- 脚本：`startech-mes-basic/backend/sql/20260821_10_sys_identity_tenant_id.sql`（若 `09` 顺延则本文件 `NN+1`）
- 列：`tenant_id bigint not null DEFAULT 1`，然后回填 NULL；平台用户保持 0
- 唯一键改为 `(tenant_id, 业务键)`。加 UNIQUE 前跑 `GROUP BY tenant_id, 业务键 HAVING COUNT(*)>1`；0 则直接加；非 0 才改键/软删，禁止未清时加索引，不自动合并（S4 窄）。空库预期计数为 0
- `sys_user`：`uk_tenant_user (tenant_id, user_name)`；`checkUserNameUnique` 同步
- `sys_role`：建议 `uk_tenant_role_key (tenant_id, role_key)`
- `sys_post`：`(tenant_id, post_code)`
- `sys_dept`：按现网唯一语义补 `(tenant_id, ...)`；`ancestors` 不得跨租户
- 关系表 `sys_user_role` / `sys_user_post` / `sys_role_menu` / `sys_role_dept` **显式加** `tenant_id`
- `sys_oper_log` / `sys_logininfor` 加列
- `sys_notice`、`sys_notice_detail`、`sys_notice_read` 加列；已读唯一改为含 `tenant_id`（S5）。v1 不做平台群发
- `sys_config`：可空 `tenant_id`；`NULL`=全局；非空=覆盖。读取：租户行优先否则全局。缓存键分层属 P2，本单元先修正 DB 读路径（无上下文只读全局）
- `DATABASE` 专库将来同一套 DDL；本单元不建专库
- 禁止改 `quartz.sql` 的 `QRTZ_*` 列；禁止一次 ALTER 全部 MES 表

## 2. Plan

### Implementation Approach

1. **SQL：** 幂等为 `sys_user`/`sys_role` 补 UNIQUE（列已在 P0）；其余身份/关系/日志/通知/`sys_config` 加列、回填 1（跳过 `tenant_id=0` 的平台行）、加 UNIQUE。夹具：插入停用租户（例如 `tenant_code` 仅测试用、`status` 停用、`ROW`、无 JDBC、无 `server_name`）及同名用户，供隔离测试，**status 保持停用**。
2. **登录主路径：** `LoginBody.tenantCode`；`SysLoginController.login` 改为 `loginService.login(username, password, code, uuid, tenantCode)`。缺码 → D9，不查用户。解析租户：若匿名解析已命中 Host，仍要求 Body 码与命中码一致（防改登，F6）；未命中则必须有码。Guard（P0）拒绝 DATABASE/停用/过期。然后 `TenantContext.set`，再 `authenticationManager.authenticate`。`finally` 清理上下文（后续请求由 JWT Filter 再设）。
3. **查用户：** `SysUserMapper.selectUserByUserName` 改为 `@Param("userName")` + `@Param("tenantId")`（或从 `TenantContext.getRequired()` 取，XML 必须出现 `u.tenant_id = #{tenantId}`）。`selectUserByMobile` 同样。`UserDetailsServiceImpl` 在创建 `LoginUser` 时写入 `tenantId`。
4. **JWT/Redis：** `createToken` 增加 `tenant_id` claim；`refreshToken` 写入的 `LoginUser` 必须带 `tenantId`。Filter：无 `tenantId` 视为无效会话 → 401；加载租户状态，停用则 401；set 上下文 + MDC；忽略请求头中的租户。
5. **D6：** 平台停用租户成功后调用 `TokenService.invalidateByTenantId(Long tenantId)`：SCAN `login_tokens:` 前缀，匹配值删除。单测可用假 Redis 或嵌入式，至少保证匹配逻辑有单测。
6. **F5 匿名接口：** 例如 `GET /login/resolveTenant`（名称锁定为本路径，避免与 OAuth `code` 混淆）。`SecurityConfig` 对 `/login`、`/captchaImage` 已 permitAll，需把该 GET 加入 permitAll（`SecurityConfig` 或 `MesPermitAllProviderImpl`，不要用笼统 `/login/**` 放开注销）。只读 `getServerName()`，命中启用租户返回 `{ tenantCode }`，否则 `data=null`。禁止 query 指定编码做枚举。
7. **F7：** `LoginParams.tenantCode`；`loginByPassword` 从 request 读取；`TokenController.loginOuth` 增加可选 `@RequestParam(required=false) String tenantCode`，与 Host 解析共用同一 `TenantResolver`。缺 Host 且缺码 → D9，**不得**调用旧 `loginOuth(username)` 无租户查询。
8. **DataScope：** 不改 Aspect 用 `isAdmin` 跳过部门过滤的现行为；拦截器仍给 `sys_user` 加 `tenant_id`。单测或 XML 对照：最终 SQL 形状为 `tenant_id = ?` 在 DataScope 片段之前或并列，且 admin 用户 SQL **仍含** `tenant_id`。
9. **getInfo：** `SysLoginController.getInfo` 增加可选字段；从 `LoginUser` + `sys_tenant.tenant_name` 读取；工厂与平台都可以回 id/name，但 **都不回** isolationLevel。
10. **Vue2：** 零 diff。在本 spec 与发布说明中写明登录将失败。
11. **测试：** 登录成功/缺码/错误码/停用夹具同名不命中/DATABASE 夹具拒登/停用 SCAN/Host 解析只回一个。命令见 Verification Strategy。

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- `POST /login`：Body 在现有 `username`/`password`/`code`/`uuid` 上增加 **必填** `tenantCode`。成功仍 `ajax.put(Constants.TOKEN, token)`，信封 `code/msg/data` 不变
- 缺 `tenantCode`、码不存在、停用、DATABASE、用户名或密码错误 → HTTP 业务失败（沿用现有 AjaxResult/异常转译），`msg` = `用户名或密码错误`
- `GET /login/resolveTenant`（permitAll）：无查询枚举参数；data 为对象 `{ "tenantCode": "..." }` 或空；永不返回数组
- `GET /getInfo`：可含 `tenantId`、`tenantName`；不得含 `isolationLevel`
- `GET /loginOuth?code={oauthCode}&tenantCode={optional}`：OAuth `code` 语义不变；租户码按 F5。缺 Host 且缺 `tenantCode` → D9 失败，不发 token

- 登录后任意 API：忽略 `X-Tenant-Id` 等客户端租户声明
- Redis key 仍 `login_tokens:{uuid}`；JWT 增加 `tenant_id` claim，解析仍以 Redis `LoginUser` 为准
- 平台 `PUT` 停用租户：调用后该 `tenantId` 的 token 全部消失；已签发 JWT 下一请求 401
- 不把 JDBC 口令、OAuth secret 加入新字段

### Transaction Boundaries

- 登录：无业务写事务（验证码 Redis、查库、发 token）。失败不写 JWT。登录日志异步插入须带已解析 `tenant_id`（无则 0），且写主库
- 停用租户：更新 `sys_tenant` 与 SCAN 删 token **顺序**：先更新 status（新登录被拒）再 SCAN；允许短暂「status 已停但仍持有旧 token」窗口，必须以 SCAN 完成前 Filter 读到的停用状态 401 为兜底（Filter 每请求读租户状态或短缓存，停用时必须失效缓存）
- 用户/角色 CRUD 保持现有 Service 事务；拦截器填充 INSERT `tenant_id`，不扩大事务
- `sys_config` overlay 写入：仅当前租户行，禁止无上下文写覆盖行

### Risks

- Vue2 登录不可用（已接受，须在发布说明写明，避免被当成回归缺陷）
- `selectUserByUserName` 漏 `tenant_id` → 跨租户同名串号（本单元最高优先级）
- 缺码时默认租户 1（D4 已作废，测试必须覆盖）
- `loginOuth` 的 OAuth `code` 与 `tenantCode` 混淆
- `isAdmin` 被用来跳过拦截器或 include

- include 扩大后，未设上下文的启动/定时任务访问身份表失败——本单元不修 I3，但启动路径（Bootstrap 更新平台口令）必须 `@TenantIgnore` 或先 `TenantContext.set(0)`
- `sys_config` 读路径改了但 P2 缓存键未改，可能读到脏全局缓存——本单元注释技术债，P2 收口 R1；不得为此引入 fail-open
