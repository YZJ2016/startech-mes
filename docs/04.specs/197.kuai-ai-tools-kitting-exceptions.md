# KU-AI 场景 Tool：工单齐套分析与生产异常

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施；K1 已于 2026-10-23 选定（b）。

## 1. Spec

### Capability

- Name: 新增只读 Tool `analyze_kitting`、`query_material_shortages`、`query_delivery_delays`、`query_quality_exceptions`。
- Module: `riveredge-backend/src/apps/kuaiai/services`（tools 适配层）、manifest `ai_tools`、`apps/kuaizhizao/services/work_order_service.py`（K1=b）。
- Priority: P1（S01 交期答复、S02 缺料齐套、S07 开班简报、S12 质量异常）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D5、SC-D7、SC-D12；设计 26 §4、§5；前置 spec 189、190。

### Business Goal

计划员/班组长能问“这张工单缺什么料、齐套率多少”“当前有哪些缺料、延期、质量异常待处理”，回答来自工单齐套分析与异常单的真实数据。

### Scope

In scope:

| Tool | 参数 | 底层 service（已读签名） | 权限码 |
| --- | --- | --- | --- |
| `analyze_kitting` | `work_order_id`（必填） | `WorkOrderService.get_work_order_kitting_analysis(tenant_id, work_order_id)`（见 K1） | `kuaizhizao:work-order:read` |
| `query_material_shortages` | `work_order_id?`、`statuses?`、`alert_level?`、`material_code?`、`limit≤20` | `ExceptionService.list_material_shortage_exceptions(tenant_id, …)` | `kuaizhizao:production-execution-material-shortage-exceptions:read` |
| `query_delivery_delays` | `work_order_id?`、`statuses?`、`alert_level?`、`limit≤20` | `ExceptionService.list_delivery_delay_exceptions(tenant_id, …)` | `kuaizhizao:production-execution-delivery-delay-exceptions:read` |
| `query_quality_exceptions` | `exception_type?`、`work_order_id?`、`statuses?`、`severity?`、`limit≤20` | `ExceptionService.list_quality_exceptions(tenant_id, …)` | `kuaizhizao:production-execution-quality-exceptions:read` |

- `analyze_kitting` by-ID 前用既有 `_work_order_in_scope` 复核工单数据范围。
- 三个异常 service 不接收 `current_user`：适配层补数据范围，资源键 T1 从 kuaizhizao manifest 确定。

Out of scope:

- 处理/关闭异常、发起叫料（写操作，经 HITL 另立）。
- 异常上报（S10，P2）。

### 决策（2026-10-23 用户选定）

- **K1 = b**：`WorkOrderService` 抽出纯计算函数（暂名 `compute_work_order_kitting_analysis`）；原 `get_work_order_kitting_analysis` 改为“纯计算 + `persist_kitting_analysis_result`”，签名与返回不变；`analyze_kitting` 只调纯计算，不写 `work_orders` 任何字段。

原选项存档：

| 编号 | 场景 | 选项 | 推荐与理由 |
| --- | --- | --- | --- |
| K1 | `get_work_order_kitting_analysis` 在返回前调用 `persist_kitting_analysis_result` 写 `work_orders.readiness_rate` 等缓存字段（`work_order_service.py` 约 8325–8334 行）；只读 Tool 直接调用会产生写副作用 | a. Tool 只读已持久化的 `readiness_rate` 与缺料异常，不重算；b. 把齐套分析拆为纯计算函数 + 持久化步骤，既有调用方保持“计算后持久化”，Tool 只调纯计算；c. 直接调用现方法，接受缓存写入 | **b**：AI 读到的是实时齐套事实且不写库；拆分只把现方法尾部的持久化挪到调用方，口径（弹窗、列表、AI）仍是同一计算函数。a 的缓存可能过期，c 违反“只读 Tool 不写库” |

### Acceptance Criteria

1. `analyze_kitting` 返回齐套率与缺料明细（物料、需求量、可用量、缺口），按缺口降序取前 20；范围外工单按“不存在”回复。
2. K1=b：既有齐套弹窗/列表行为不变（既有测试通过），Tool 调用前后 `work_orders.readiness_rate` 与 `readiness_rate_updated_at` 不变。
3. 三个异常 Tool 结果经数据范围收敛；状态/级别枚举在 T1 从模型读取后固化。
4. 有界摘要、空结果、异常、limit 与既有 Tool 口径一致。
5. 四个 Tool 登记于 manifest（`label`、`kind=read`、权限码）。

### Rules and Constraints

Tenant isolation:

- 所有调用传 `ctx.tenant_id`。

Security and masking:

- 一 Tool 一权限码（SC-D7）；不输出处理人联系方式等扩展字段。

Audit and lineage:

- 沿用 Tool 级审计。

AI/rule-engine rules:

- 齐套率、缺口、异常级别取 service 结果，LLM 不计算。

Database rules:

- 无表结构变更。
