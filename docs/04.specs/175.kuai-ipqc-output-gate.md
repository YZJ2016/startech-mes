## 1. Spec

### Capability

- Name: 过程检验卡住报产出
- Module: `kuaigeyun-mes/riveredge-backend`：工序可转数量、报工完成、报工自动建过程检验、工单头产出与末道自动入库
- Priority: P0（KR-PG6）
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/22.kuai-production-grade-closeout-gaps.md`（**KR-PG6**）
  - 设计：`docs/03.design/22.kuai-production-grade-closeout-plan.md` 第 6 节

### Business Goal

关键工序未检验不得把数量算成报产出，也不得把简易模式或状态报工标成工序完成。让步必须有已处理的让步接收不良单。方案模式未检完不算工序完成，这条保持。简易模式不能再只凭报工合格数算工序完成。

### Scope

In scope:

- 关键工序 = 过程检验 eff 为 `simple` 或 `plan`。判定走 `resolve_ipqc_for_work_order_operation`。
- 简易模式完成数量改认过程检验放行数。状态报工在关键工序上走同一套完成数量。
- eff 为 `simple` 时，报工自动建单也建 `ProcessInspection`。
- 末道是关键工序时，工单头产出与末道自动入库只认放行合格数加已处理让步数量。

Out of scope:

- 不改方案模式可转下道数量。`mode == "plan"` 仍只走 `resolve_ordered_plan_transfer_qualified`。让步不加进可转下道。
- 不把 eff 为 `none` 的工序改成必检。无策略、环节关闭、模块关闭仍可用报工合格数完成和记产出。
- 不新造关键工序标志，不新造简易检验单，不新造 8D，不新造让步单据类型。
- 不改 `assert_fqc_for_finished_goods_receipt`。
- 不新表。不改 URL、method、认证头、响应外层结构。
- 不拒绝保存报工草稿或已审核报工行本身。

### Acceptance Criteria

1. eff 为 `plan` 或 `simple`（含 `work_order_override` 等把 eff 抬到这两档）的工序是关键工序。eff 为 `none` 且 source 为 `default_none`、`stage_disabled` 或 `module_disabled` 不是关键工序。
2. `resolve_operation_transfer_qualified` 在 `mode == "plan"` 时仍调用 `resolve_ordered_plan_transfer_qualified`（135–140 行）。未检完时 `_effective_completion_quantity` → `_maybe_mark_operation_completed` 仍不得把工序标 `completed`。该数量不含让步。
3. `mode == "simple"` 时，`resolve_operation_transfer_qualified` 不得返回 `woo.qualified_quantity`。完成数量等于本工序 `ProcessInspection` 上 `ipqc_inspection_passed_for_transfer` 为真的合格数量合计。该数量小于工单计划数量时，工序不得标 `completed`。
4. 状态报工（`reporting_service.py` 1640–1644 行）在关键工序上不得因报工数量大于 0 直接标 `completed`，改走同一套完成数量。非关键工序的状态报工保持现网。
5. `quality_automation_service.py` `maybe_auto_create_ipqc_fqc_from_reporting` 在 eff 为 `simple` 时也调用 `ProcessInspectionService.create_inspection_from_work_order`。建单失败只记录失败，不把工序算完成；报工记录可以留下。eff 为 `plan` 的现网建单保持。不新造单据类型。
6. `mode == "none"` 仍返回报工合格数。环节关闭和模块关闭仍可凭报工合格数完成，并按报工合格数记末道产出、允许末道自动入库。
7. 末道不是关键工序：工单头 `completed_quantity` / `qualified_quantity` 与末道自动入库仍用报工合格数。
8. 末道是关键工序：工单头产出与末道自动入库只认过程检验放行合格数，加上这些过程检验单上 `DefectRecord` 满足 `disposition == "accept"`、`status == "processed"`、`process_inspection_id` 指向该检验单的 `defect_quantity` 合计。没有这张已处理不良单时，不合格数量不得进入报产出，也不得触发自动入库。`status == "draft"` 的让步不算。合计为 0：不把工单头产出更新成报工合格数，不自动入库。报工记录仍可保存。后补放行后再计产出。
9. 方案模式末道的报产出可以含让步，可转下道数量不含让步。两者允许不一致。
10. 物料或工序显式免检（eff `none` 且不是「无策略被改判成必检」）不被本单元改成必检。`default_none` 不改判成必检。

### Rules and Constraints

Tenant isolation:

- 检验单与不良单查询带现有组织条件。

Security and masking:

- 不在日志中新增凭据或内部路径。自动建单失败保持现网 warning，完成判定另看有没有放行单。

Audit and lineage:

- 让步用已有 `DefectRecord`，检验用已有 `ProcessInspection`。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 不新表，不写迁移。

## 2. Plan

### Implementation Approach

- 完成数量的分叉放在 `resolve_operation_transfer_qualified`：`plan` 保持，`simple` 改认放行数，`none` 保持报工合格数。工序完成继续经 `_effective_completion_quantity`。
- 报产出与可转下道分开。末道关键工序的工单头合格数和自动入库用「放行合格数 + 已处理让步」，不把让步写进可转下道。
- 当前有两处写工单头产出。报工保存路径 1688–1692 行把 `completed_quantity` / `qualified_quantity` 都写成末道报工累计。`_sync_work_order_header_quantities_from_last_operation`（3070–3114 行）的 `qualified_quantity` 已走 `resolve_operation_transfer_qualified`，`completed_quantity` 仍取末道报工完成数。两处在末道为关键工序时都改为放行数加已处理让步；末道非关键工序保持报工合格数。

### Affected Modules

- `src/apps/kuaizhizao/services/operation_transfer_service.py`
- `src/apps/kuaizhizao/services/reporting_service.py`
- `src/apps/kuaizhizao/services/quality_automation_service.py`
- 对应单测

### Public Contracts

- 不改报工、过程检验、自动入库的 URL、method、认证头、响应外层结构。
- 不新增关键工序字段。

### Persistence Changes

- 无。

### Transaction Boundaries

- 未检验且无已处理让步：不把该数量记为工单头产出，不自动入库，不把简易模式或状态报工标成工序完成。
- 报工记录本身仍可保存。自动建单失败不回滚报工记录。
- 末道自动入库在报工事务提交之后调用（821–831 行注释）。关键工序合计为 0 时不建入库单，不回滚已保存的报工。

### Risks

- 方案模式可转下道被让步或简易规则改写。`plan` 分支保持只走 `resolve_ordered_plan_transfer_qualified`。
- 环节或模块关闭被收成必检。eff `none` 仍凭报工合格数完成和记产出。
- 只改 1688–1692 行、漏掉 3070–3114 行，工单头会被后一次同步写回报工合格数。两处一起改。

### Verification Strategy

- 在 `kuaigeyun-mes/riveredge-backend` 用 `uv run pytest` 覆盖：简易模式未检验不完成、状态报工未检验不完成、方案模式未检完不完成且可转下道不含让步、eff `none` 仍凭报工合格数、末道未检验不记产出且不自动入库、已处理让步计入产出但不计入可转下道。未跑通不得声称通过。
