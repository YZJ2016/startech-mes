## 1. Spec

### Capability

- Name: P4 MES 主数据 `md` 行级隔离（第二个 `ROW` 工厂门禁）
- Module: `startech-mes-basic/backend/ktg-mes`（`com.ktg.mes.md` + `src/main/resources/mapper/md`）；拦截器 include 名单在 `ktg-framework` 的 `TenantLineInterceptor`（P0 已建，本单元只扩表名）；增量 SQL 在 `startech-mes-basic/backend/sql/`
- Priority: P0（总控门禁：本单元完成前禁止启用第二个 `ROW` 工厂）
- Related requirement/design documents:
  - 设计：`docs/03.design/04.mes-shared-db-tenant-plan.md`（§4 表分类、§4.4 P4 表、S1/S4、P4 退出标准）
  - 缺口清单：`docs/02.requirements/02.mes-multi-tenant-gaps.md`（S1 md 波次、S4 / S4 窄）
  - 总控：`docs/04.specs/35.mes-multi-tenant-program.md`
  - 上一单元：`docs/04.specs/39.tenant-catalog-p3.md`
  - 下一单元：`docs/04.specs/41.tenant-dedicated-ds-pd.md`

### Business Goal

在共享主库上把 MES 主数据（物料/分类/BOM/客商/单位/车间工位/SOP，以及 S1 归入本波的缺 CREATE 表）全部加上 `tenant_id` 并由拦截器失败关闭过滤，使租户 1 的物料列表看不到租户 2 夹具行，且跨租户允许相同 `item_code`。本单元完成后**允许启用第二个 `ROW` 工厂**。不在本单元实现专库数据源；启用任何 `DATABASE` 工厂仍须等 41。

### Scope

In scope:

- 设计 §4.4 P4 表加 `tenant_id`、回填 `1`、按 S4 补复合唯一键：`md_item`、`md_item_type`、`md_product_bom`、`md_vendor`、`md_client`、`md_unit_measure`、`md_workshop`、`md_workstation`、`md_workstation_machine`、`md_workstation_worker`、`md_workstation_tool`、`md_product_sop`
- S1 本波全部租户表（禁止当全局）：`drawing_manage`、`md_item_capacity`、`md_meeting_minutes`、`md_product_packing`、`md_turnplate`、`sys_camera_configuration`
- 附属表 `md_turnplate_records`（`MdTurnplateRecordsMapper` 已写该表；与 `md_turnplate` 同波加列，避免转盘记录漏隔离）
- 拦截器 include 名单加入上列**全部**本波表（退出标准「全部 md 表」= 本清单，不是 `mapper/md` 目录下的 P5/P7 表）
- S4 窄口：每张有业务键的表在 `ADD UNIQUE` 前跑 `GROUP BY tenant_id, 业务键 HAVING COUNT(*) > 1`；0 则加索引；非 0 则保留最小 id、其余改 `{原键}__dup_{id}` 或软删；禁止未清时加 UNIQUE；不自动合并工单/库存（本波无工单/库存，禁止顺手去改 `pro_*`/`wm_*`）
- S1 DDL：实现时对上列缺 CREATE 表做现网 `SHOW CREATE TABLE`，按真实列写增量；禁止执行仓库空文件 `20260820_05_mes_missing_tables.sql` 来「建表」
- 领域或 Mapper 级夹具测试：两行不同 `tenant_id` 均在**主库**、模拟 `ROW`；`GET /mes/md/mditem/list`（或等价 `MdItemMapper.selectMdItemList`）在租户 1 上下文看不到租户 2；同 `item_code` 跨租户可并存
- `checkItemCodeUnique` 等业务唯一校验在拦截器生效后按租户判定（现网 XML 为 `where item_code = #{itemCode} limit 1`，不要另写一套只按业务键的全局唯一）

Out of scope:

- 本单元不实现专库 DS / 懒加载池 / I8 绑主库（41）
- 不启用、不登录第二个 `DATABASE` 工厂；不把租户 2 业务行当作可登录工厂（租户 2 仅 SQL 夹具，可为未启用）
- `sys_notice_detail`：随 S5，**不是** P4
- 虽在 `mapper/md` 但属后续波次：`cal_plan_workstation`、`cal_team_workstation`（P7）；`wm_tool_position`（P5）；`pro_task_turnplate`（P5）；`tm_tool_log`（P7）
- 不克隆 `sys_menu`、不复制物料到其他租户、不引入 Jugg eager 池 / Sa-Token / 失败开放 / MyBatis-Plus `@DS`
- 不改 Vue2 `startech-mes-basic/frontend/`；不改 Vue3（P9）
- 不原地改写 `backend/doc/**/mes-md.sql`、`ry_*.sql`、`20260820_05_mes_missing_tables.sql`
- 不在文档或脚本中写入真实 JDBC URL、口令、生产主机、摄像头设备口令

### Acceptance Criteria

- 拦截器 include 含本波全部表名（设计 P4 12 张 + S1 本波 6 张 + `md_turnplate_records`）；单测或名单断言可核对，漏表视为失败
- 夹具：主库插入 `tenant_id=1` 与 `tenant_id=2` 的物料（建议同一 `item_code`）；租户 1 上下文 `selectMdItemList` / `GET /mes/md/mditem/list` **不含**租户 2 行；租户 2 无需启用、无需能登录
- `item_code` 在同一 `tenant_id` 内唯一；跨租户允许相同编码（S4）；`DATABASE` 将来沿用同一套 `(tenant_id, item_code)`，本单元不改为「仅业务键」
- 上列有明确业务编码的表均完成 S4 窄口检测后再加 UNIQUE（见 Persistence Changes 对照表）
- S1 本波表：增量脚本基于现网 `SHOW CREATE TABLE`，仓库里看不到「猜列 CREATE」；未跑 05 空文件
- `ktg-mes` 当前无 `src/test`：本单元必须新建领域或 Mapper 夹具测试；执行 `mvn -pl ktg-mes -am test`（有测则跑；若模块仍无旧测，至少编译 + 本单元新测试通过）
- **GATE：本单元完成后，允许启用第二个 `ROW` 工厂。** 启用 `DATABASE` 工厂仍须 41 完成（建库+迁表+ping+连接预算）
- 本单元结束后，已登记但未就绪的 `DATABASE` 租户仍拒绝登录、永不写入共享主库（D7，行为由 36/37 保持，本单元不得打开回落）
- 文档与脚本无真实凭据

### Rules and Constraints

Tenant isolation:

- 默认 `ROW`；本波 SQL 全部打**共享主库**
- 两档将来共用同一拦截器：无上下文访问 include 表抛错；INSERT 填充/校验 `tenant_id`；SELECT/UPDATE/DELETE 加 `tenant_id = ?`（占位符）
- 本波加列后必须进 include；未加列的 MES 表仍不强制谓词
- JOIN 到尚未加列的表（例如工位 Mapper 现网 JOIN `cal_plan_workstation`）时，拦截器**只**给已 include 表加谓词，不得把未加列表当租户表改写
- `workshop_id` / `workstation_id` 不是租户键，与 `tenant_id` 并存
- `user_id=1` 不得跳过本波租户谓词（D3）
- SQL 永不跳过 `tenant_id`；不按客户端租户头覆盖 JWT 上下文

Security and masking:

- 不引入第二套认证
- `sys_camera_configuration` 若含设备口令列：增量脚本与 `SHOW CREATE` 记录中打码，禁止把现网口令贴进仓库或本 spec 第 4 节
- 日志、测试输出不得打印 token、JDBC 口令、内部绝对路径
- 失败关闭：不得加开关关掉本波拦截

Audit and lineage:

- 增量只追加 `startech-mes-basic/backend/sql/YYYYMMDD_NN_*.sql`，接目录现有最大 `NN`（现网已有 `20260820_08_*`；36–39 实现时还会占用号段，以实现当日目录为准）
- 现网回填 `tenant_id=1`；加列 `bigint not null` 且 `DEFAULT 1`
- 历史 `mes-md.sql` 不改
- 租户 2 夹具行不作为第二工厂开通；开通第二 `ROW` 工厂是本单元**完成之后**的运维动作，不是本单元 SQL 的副作用

AI/rule-engine rules:

- 本单元不涉及规则引擎或 AI

Database rules:

- 唯一键 `(tenant_id, 业务键)`；专库将来同一套 DDL，不改为仅业务键（S4）
- 空库不做脏数据治理，但仍必须跑 `GROUP BY ... HAVING COUNT(*) > 1`；计数 0 → `ADD UNIQUE`；非 0 → 改键或软删最小 id 策略，**禁止**在重复未清时 `ADD UNIQUE`（S4 窄）
- 禁止一次 ALTER 全部 MES 表；本单元只动本波表
- 禁止把仓库空的 `05` 文件当 DDL 执行
- 不在本单元 `CREATE DATABASE`、不写专库 JDBC

## 2. Plan

### Implementation Approach

1. 依赖 36 的 `TenantLineInterceptor` include 名单与 37 的登录/`LoginUser.tenantId`。建议 39 已能按许可裁剪路由，但本单元隔离验收不依赖菜单。
2. 对设计 P4 表：对照 `backend/doc/设计文档/数据库设计/mes-md.sql` 的列名写**增量** ALTER（不改该历史文件）。
3. 对 S1 本波 6 张表：在目标库执行 `SHOW CREATE TABLE`，把真实列类型记入实现笔记（打码敏感列）后写 ALTER；不要猜实体、不要跑 `20260820_05_mes_missing_tables.sql`。
4. 每张有业务键的表：先 `GROUP BY tenant_id, 业务键 HAVING COUNT(*) > 1`；0 则 `ADD UNIQUE`；非 0 则最小 id 保留、其余 `{原键}__dup_{id}` 或软删，再加 UNIQUE。
5. 把本波表名加入拦截器 include；`ktg-mes` 现有 `check*Unique` XML 不强制手写 `tenant_id`（拦截器加谓词）。用夹具证明跨租户同码与列表隔离。
6. **不**改 `DruidConfig` / `DynamicDataSource` 语义。租户 2 只插行，不启用登录。
7. 完成后在缺口清单实现证据处回写 S1 md 波次（产品决策已是 `[x]`，本单元补的是 DDL/include 证据，待第 4 节实现后填写；写 spec 时不得伪称已跑通）。

### Persistence Changes

增量脚本建议名（实现时按目录最大号 +1，禁止与 36–39 撞号）：`startech-mes-basic/backend/sql/YYYYMMDD_NN_md_tenant.sql`。可拆成「设计表」+「S1 表」两文件，但仍须同一波次一起完成 include。

列约定：`tenant_id bigint not null default 1`，随后 `UPDATE ... SET tenant_id = 1 WHERE tenant_id IS NULL`（若分两步从可空变非空）。

S4 窄口伪代码（每张要加 UNIQUE 的表，空库也要跑检测）：

```sql
-- 1) 检测（必须执行；空库期望 0 行）
SELECT tenant_id, item_code, COUNT(*) AS c
  FROM md_item
 GROUP BY tenant_id, item_code
HAVING COUNT(*) > 1;

-- 2a) 计数全 0：直接加
-- ALTER TABLE md_item ADD UNIQUE KEY uk_md_item_tenant_code (tenant_id, item_code);

-- 2b) 非 0：保留 MIN(item_id)，其余改码或软删后再 ADD UNIQUE
-- 禁止在 HAVING 仍有行时 ADD UNIQUE
-- 禁止自动合并工单/库存（本波不得去 UPDATE pro_workorder / wm_*）
```

回填：现网种子物料全部 `tenant_id=1`。夹具租户 2 行只存在于测试脚本或测试 schema，不作为生产开通。

### Transaction Boundaries

- DDL 与脏数据改键不包在业务事务里；按表顺序执行，失败则停在该表，禁止「部分表已 UNIQUE、部分表未加列」却扩大 include
- 业务写入仍走现有 service 事务；拦截器在 SQL 层，不扩大事务
- 夹具插入与断言在测试事务或可回滚测试库中进行，不写生产库

### Risks

- include 漏表 → 跨租户读写（最高）
- 把 `mapper/md` 里 P5/P7 表提前 include，但列尚未加 → SQL 报错或误过滤
- 未跑 HAVING 就 ADD UNIQUE，空库虽多半成功，导入旧数据时会炸
- `MdWorkstationMapper` JOIN 未加列表：拦截器误改写导致工位列表失败
- 把 `checkItemCodeUnique` 改成全局唯一，破坏 S4
- 本单元若误开专库路由或允许 DATABASE 登录，数据会写入共享库却自称专库（D7）
- `sys_camera_configuration` 脚本泄漏设备口令

### Verification Strategy

- 静态：include 名单与本 spec 表清单逐项勾对；增量脚本只含本波表
- 动态：新建测试，主库两 `tenant_id` 夹具 + 同 `item_code`；租户 1 列表不可见租户 2；同租户重复编码失败
- 命令：在 `startech-mes-basic/backend` 执行 `mvn -pl ktg-mes -am test`；无历史测试时至少 `mvn -pl ktg-mes -am test` 跑新类，或 `mvn -pl ktg-mes -am compile` **加上**新测试类的成功输出
- S1：实现记录中注明已对哪些表执行 `SHOW CREATE TABLE`（可贴无口令的列名清单），并确认未执行 05 空文件
- 未实际跑通不得在第 4 节写「测试通过」
- 本单元不测专库、不测 I5/I8
