## 1. Spec

### Capability

- Name: P1 租户模型配置与密钥加密
- Module: `ktg-ai` domain/service/mapper；`ktg-admin` 薄 Controller
- Priority: P1
- Related requirement/design documents:
  - 设计：`docs/03.design/06.mes-ai-platform-plan.md` §4–§5
  - 缺口：`docs/02.requirements/03.mes-ai-platform-gaps.md`（A2–A4、A13、A20、A24、I-A1、I-A5）
  - 总控：`docs/04.specs/48.mes-ai-platform-program.md`
  - 加密先例：`TenantJdbcCipher` / S6（独立密钥，不复用）
  - 上一单元：`docs/04.specs/49.ai-foundation-p0.md`
  - 下一单元：`docs/04.specs/51.ai-chat-p2.md`
  - ChatModel 工厂（配置源锁定为库表）：`docs/04.specs/61.ai-chatmodel-factory.md`

### Business Goal

工厂管理员为本租户配置 OpenAI 兼容模型：展示名、模型名、`baseUrl`、api_key（加密落库）、embedding 维度。列表打码。运行时能解密后发一次非流式探活（可选）。

### Scope

In scope:

- 表 `ai_model` + include + 专库 catalog
- CRUD：`/ai/model`（精确 method 实现时定，须 REST 风格且不撞现网）
- `AiModelCipher`：AES-256-GCM，`AI_MODEL_CIPHER_KEY`
- 启动门禁：已有密文模型行且缺密钥 → 拒启动
- 列表/详情不回 `apiKey`/cipher；更新密钥只写不回填
- 用户可选列表（给对话下拉）：`GET /ai/model/options` → `{id, modelName, providerCode, category}`，无密钥/主机（A20，以 57 冻结形状为准）

Out of scope:

- SSE 对话、会话表、知识库、向量、Vue 页（52）
- 智谱/百炼原生 SDK
- 揭明文（若做须审计；本单元可不做）

### Acceptance Criteria

- INSERT/SELECT `ai_model` 无上下文失败关闭（单测或拦截器夹具）
- 两次加密同一明文密文不同；篡改密文解密失败
- 列表 JSON 无 password/apiKey/cipher
- 跨租户 id 读写 404/403，不串数据
- 缺 `AI_MODEL_CIPHER_KEY` + 夹具密文行 → 启动失败（测试 profile）

### Rules and Constraints

Tenant isolation:

- `tenant_id` 必填；唯一键至少 `(tenant_id, 展示名或业务码)`
- 登录后只信 JWT

Security and masking:

- 主密钥只环境变量
- 日志断言无明文 key
- 许可闸沿用 49

Audit and lineage:

- 增量 SQL 新文件；`@Log` 记模型变更，不记密钥

AI/rule-engine rules:

- 只存 OpenAI 兼容字段；不存第二种协议枚举也可，用 `baseUrl` 区分
- 模型目录与 apiKey **不**改写进 yml（A24）

Database rules:

- include + 专库 catalog 同步
- 不把 key 明文列对外

## 2. Plan

### Implementation Approach

- 对齐 `SysTenant` 打码列表模式
- Cipher 独立类，单测从 `TenantJdbcCipherTest` 抄结构不抄密钥名

### Affected Modules

- `ktg-ai`、`ktg-admin`、`ktg-framework` include yml、专库 catalog、`backend/sql/`

### Public Contracts

- `/ai/model` CRUD + `/ai/model/options`（名称随风格）
- 信封 `code/msg/data` / 分页 `rows`/`total`

### Persistence Changes

- `CREATE ai_model`（`tenant_id`、展示名、model_name、base_url、api_key_cipher、dimension、status、审计列）

### Transaction Boundaries

- 保存：校验许可 + 加密 + upsert 同一事务

### Risks

- 复用 `TENANT_JDBC_CIPHER_KEY`（禁止）
- options 接口漏出 baseUrl 上的 userinfo 口令
- 表未进 include

### Verification Strategy

- `mvn -pl ktg-ai,ktg-admin -am test`（或至少 compile + 本模块单测）
- Cipher / 打码 / 租户隔离单测
