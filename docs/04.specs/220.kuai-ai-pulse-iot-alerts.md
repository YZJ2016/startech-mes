# KU-AI Pulse：接入 kuaiiot 设备告警

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已完成；§1 决策已于 2026-10-23 选定。

## 1. Spec

### Capability

- Name: Pulse 设备领域升级为多来源：MES 故障单 + kuaiiot 设备告警（传感器越限、离线等）。
- Module: `apps/kuaiai/services/pulse/`（detector、registry 部分语义）、kuaiiot `alert_service`/`trend_service` 调用封装；前端 Pulse 部分失败提示（如需）。
- Priority: P3 跟进项（spec 203 E1=a 遗留缺口；也是 S17 完整形态的前置）。
- Related requirement/design documents: 需求 25；设计 26 §4；前置 spec 203。

### Business Goal

注塑机温度超限已产生 5 条 IoT 告警但没人报修时，Pulse 能立刻提示“设备 X 有 N 条未处理告警”，而不是等故障单出现。

### Scope

In scope:

- 设备 detector 增加 kuaiiot 数据源：未处理告警按设备聚合（告警数、最新告警级别、最新告警时间），与 MES 故障单并列展示为不同信号类型。
- 应用可用性：kuaiiot 未安装时该来源整体跳过，不影响 MES 故障单部分。
- 权限语义：见 X8（关键决策）。
- 同设备同时有故障单与告警时：两条信号并列展示，内容各自准确，不做合并去重（两者是不同事实：有人报修 vs 传感器告警）。

Out of scope:

- IoT 告警的确认/处理动作（写）。
- 告警趋势图（`trend_service`）接入 AI Tool——如需另立。
- spec 203 已交付的 MES 故障单逻辑改动最小化。

### 决策（2026-10-23 已选定）

选定：**X8=a** —— 领域内来源级权限：无权限来源显示“无 XX 权限”占位小节，与 spec 218 分域小节同语义。

| 编号 | 场景 | 选项 | 推荐与理由 |
| --- | --- | --- | --- |
| X8 | 用户有设备故障权限但没有 `kuaiiot:alert:read`（或反之）时：现有 Pulse 框架是“一领域一权限，无权限整领域隐藏”，没有“领域内部分数据源不可用”的语义 | a. 引入“来源级权限”：领域内各数据源独立判权，无权限的来源显示“无 IoT 告警权限”占位小节（参考 spec 218 的分域小节语义）；b. 权限取并集：有任一权限才显示该来源，两者都无则整领域隐藏；c. 权限取交集：只有两个权限都有才显示设备领域 | **a**：信息不静默丢失，用户知道“存在但我看不到”；b 会让无 IoT 权限用户永远看不到告警却不知道原因；c 会把原本有故障权限的用户也挡掉。需要给 registry/前端补“来源级无权限”语义，改动可控 |

### Acceptance Criteria

1. kuaiiot 未安装：设备领域仅显示 MES 故障单信号，无报错。
2. kuaiiot 已安装且有权限：设备信号包含故障单与告警两类，各自计数与最新时间准确。
3. X8=a：单权限用户看到有权来源 + 无权来源的占位小节；无权来源不泄露数据。
4. 与 spec 203 的信号格式兼容，前端正常渲染。

### Rules and Constraints

Tenant isolation:

- 传 `ctx.tenant_id`；跨应用调用只传 tenant_id 与已判权参数。

Security and masking:

- 告警原文（传感器读数等）按 kuaiiot 权限控制，不外泄。

Audit and lineage:

- Pulse 查询沿用现有审计。

AI/rule-engine rules:

- 信号生成沿用 detector 确定性规则；告警级别沿用 kuaiiot 数据。

Database rules:

- 无表结构变更。

## 4. Verification Record

T1 事实表（代码核对结果）：

- `AlertService.list_alerts(tenant_id, page=1, page_size=20, status=None, device_id=None) -> (items, total)`，按 `-triggered_at` 排序（`apps/kuaiiot/services/alert_service.py:18-32`）；kuaiiot 无设备聚合专用方法，detector 内分页拉取后按 `device_id` 聚合（数/最新级别/最新时间）；`trend_service` 未接入（本单元 Out of scope）。
- `IotAlert.status` 闭集 `open|acknowledged`（模型注释 iot.py:410；代码另写 `recovered`/`closed` 终态）；「未处理」口径 = `status='open'`（与 kuaiiot dashboard `listAlerts({status:'open'})` 同口径）。`severity` 闭集 `info|warning|critical`（iot.py:407）。
- 应用可用性判法：沿用 spec 212 `_plm_enabled` 模式——`ApplicationService.get_application_by_code(tenant_id, 'kuaiiot')` 的 `is_installed`+`is_active`；判定异常按未安装处理（失败关闭）。
- `kuaiiot:alert:read` 存在于 kuaiiot manifest permissions；告警路由 `/apps/kuaiiot/alerts`（manifest menu_config）；kuaiiot manifest 无 `reference_resources` → IoT 告警无 data_scope_key，仅租户隔离，跨应用调用只传 `tenant_id`。

Result:

- kuaiiot 未安装：设备领域仅 MES 故障单信号，IoT 来源整体跳过（不出现在 sources）。
- 已安装且有权限：故障单 + IoT 告警两类信号并列；同设备两源各一条，不合并。
- X8=a：单权限用户见有权来源信号 + 无权来源占位（`no_permission`，signals 恒空、不查数）；两源均无权限仍整领域 `permission_denied`（spec 203 语义不变）。
- IoT 来源独立短超时（3s）：超时/异常 → `unavailable`，不影响 MES 部分。
- 响应契约：`PulseGroupOut.sources[]` 新增 `{key,label,status,count}`；旧前端忽略新字段仍可用。

审计后修复与保留口径记录：

- IoT 告警分页拉取加上限 `IOT_ALERT_MAX_PAGES = 10`（`equipment.py:81`、`:327`），防止告警量大的设备拖垮 detector。
- `PulseSourceOut.count` 口径改为 severity 过滤/去重后该来源实际贡献条数（`registry.py:210-224`），来源计数与分组可见条数口径一致；占位来源 signals 恒空 → count=0。
- 前端 `pages/pulse/index.tsx` 存量 4 处 `Alert message=` 已按 antd6 改 `title=`。
- `resource_uuid=equipment_uuid` 保留并加注释（`equipment.py:416-418`）：IoT 信号主体是 MES 设备而非单条告警，与其他 detector 的 resource 语义对齐，属有意口径差异。
