### Business Goal

Maven 与安全边界就位：`ktg-ai` 可被 `ktg-admin` 启动扫描；`mes_module` 有 `ai`；未许可工厂打 `/ai/**` 得到 403；平台可将 `ai` 许可给工厂。尚无模型与对话。

### Scope

In scope:

- 聚合 `pom.xml` 增加 `ktg-ai`；`ktg-admin` 依赖
- 包 `com.ktg.ai`；一个健康或空 Controller 挂 `/ai/health`（须登录，不 permitAll）
- 许可码：`mes_module` 字典增量 `ai`；`MenuModuleMapper` 识别 path 前缀 `ai`
- `/ai/**` 许可闸（Service 或拦截器）；未许可 403；平台账号策略按设计（默认平台管理许可，不强制平台自己聊天）
- 可选：占位菜单目录 `ai`（无子页也可，52 再补叶子）

Out of scope:

- 模型表、会话、知识库、向量、Vue 对话页
- permitAll 任何 `/ai/**`
- 本单元不引入 LangChain4j 运行时依赖或向量 SDK（父 POM 双 BOM 另见 `docs/04.specs/60.ai-langchain4j-bom.md`，不在本单元加 `ktg-ai` 依赖）
- 改 Vue2；改租户拦截器语义

### Acceptance Criteria

- `mvn -pl ktg-admin -am compiler:compile -DskipTests` 能编过（写明是否跳过 antrun）
- 未许可租户调用 `/ai/health` → 403；已许可 → 200（可用单测或 MockMvc，不连生产）
- 给工厂保存 `module_code=ai` 通过字典校验；`platform` 仍不能许可给工厂（F3 不回退）
- 无 `/ai/**` 出现在 `MesPermitAllProvider` 实现里
- 文档无敏感值

### Rules and Constraints

Tenant isolation:

- 本单元可不建 `ai_*` 表；许可表仍是忽略表（既有）
- 许可闸读当前 `LoginUser.tenantId`，不信客户端租户头

Security and masking:

- `/ai/health` 必须认证
- 不扩大匿名面

Audit and lineage:

- 字典增量 SQL 新文件，不改历史脚本

AI/rule-engine rules:

- 无模型调用

Database rules:

- 只追加 `mes_module` 字典行；建议 `YYYYMMDD_NN_ai_module_dict.sql`

## 2. Plan

### Implementation Approach

- 按现有 `ktg-*` 模块骨架建空 jar：`ktg-common` 依赖即可
- 许可校验放 `ktg-ai` service，供后续 Controller 复用
- 菜单映射只加前缀规则，不克隆菜单行

### Affected Modules

- `backend/pom.xml`、`backend/ktg-ai/**`、`backend/ktg-admin/pom.xml`
- `ktg-system`：`mes_module`、`MenuModuleMapper`
- `backend/sql/` 增量

### Public Contracts

- `GET /ai/health`：登录 + 许可；信封 `code/msg/data`
- 许可写入仍走既有 `/platform/tenant/{id}/licenses`

### Persistence Changes

- `mes_module` 字典 data 增加 `ai`
- 无新业务表

### Transaction Boundaries

- 无新写事务（许可写入沿用既有平台 API）

### Risks

- 扫描不到 `com.ktg.ai`（admin 未依赖或未扫包）
- 许可闸写在 framework 字面量路径（禁止；保持领域模块）
- 把 `/ai/**` 放进 permitAll

### Verification Strategy

- 编译 `ktg-admin -am`
- 许可闸单测：无许可 403 / 有许可通过
- 不跑 Vue 构建
