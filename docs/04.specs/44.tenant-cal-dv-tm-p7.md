## 1. Spec

### Capability

- Name: P7 日历 `cal` + 设备 `dv` + 工装 `tm` 行级租户隔离
- Module: `startech-mes-basic/backend/ktg-mes` 包 `com.ktg.mes.cal`、`com.ktg.mes.dv`、`com.ktg.mes.tm` 及对应 `mapper/cal`、`mapper/dv`、`mapper/tm`（S1 部分 XML 现位于 `mapper/md`，按**表名**进本波 include）
- Priority: P7（设计 §4.4；总控 44）
- Related requirement/design documents:
  - 设计：`docs/03.design/04.mes-shared-db-tenant-plan.md`（§4.4 P7、S4、I6）
  - 缺口清单：`docs/02.requirements/02.mes-multi-tenant-gaps.md`
  - 总控：`docs/04.specs/35.mes-multi-tenant-program.md`
  - 上一单元：`docs/04.specs/43.tenant-qc-p6.md`
  - 下一单元：`docs/04.specs/45.tenant-rest-p8.md`

### Business Goal

把班组排班、设备点检维修、工装台账纳入同一套失败关闭的 `tenant_id` 隔离。设计表全部加列并进入拦截器 include；点检、维修、班组与设备主数据不得跨租户泄漏。本波一并处理 S1 P7 表。`workshop_id` 仍是车间维度，与 `tenant_id` 同时存在。`DATABASE` 租户由应用打同一套增量（I6）；未迁成功则该租户本波不可用，禁止回落主库。

### Scope

In scope:

- 设计表加 `tenant_id` 并进 include：
  - `mes-cal.sql`：`cal_team`、`cal_team_member`、`cal_plan`、`cal_shift`、`cal_plan_team`、`cal_holiday`、`cal_teamshift`
  - `mes-dv.sql`：`dv_machinery_type`、`dv_machinery`、`dv_subject`、`dv_check_plan`、`dv_check_machinery`、`dv_check_subject`、`dv_repair`、`dv_repair_line`
  - `mes-tm.sql`：`tm_tool_type`、`tm_tool`
- S1 P7（产品已分类为租户表）：`cal_plan_workstation`、`tm_purchase`、`tm_purchase_line`、`tm_tool_log`、`tm_tool_purchase`、`tm_tool_purchase_line`
- 设计外但现网已有 CREATE、且被 Mapper JOIN 的 `cal_team_workstation`（`backend/sql/1106teamWorkstation.sql`）：本波**一并**加列进 include，避免点检/排班 JOIN 漏过滤；不把该表推给 P8
- 增量只追加 `startech-mes-basic/backend/sql/YYYYMMDD_NN_*.sql`；禁止原地改 `mes-cal.sql` / `mes-dv.sql` / `mes-tm.sql`
- S1 缺 CREATE：现网 `SHOW CREATE TABLE` 后再写增量；**禁止**执行空的 `20260820_05_mes_missing_tables.sql`
- S4 / S4 窄：班组编码、排班计划编码、设备编码/类型、点检计划、维修单号、工装编码/类型、采购单号 → `(tenant_id, 业务键)`；空库也先 HAVING 再 UNIQUE；专库同一套 DDL
- I6：应用把本波增量打到每个已启用 `DATABASE` 租户；失败则该租户本波阻断，无主库回落
- SQL 永不跳过 `tenant_id`；不克隆菜单；不引入 MyBatis-Plus；无跨租户报表

Out of scope:

- 本任务不实现 Java/SQL（只写 spec）
- 改写 `mes-cal.sql` / `mes-dv.sql` / `mes-tm.sql` 或其它历史初始化 SQL
- `pro_trans_consume`（P5 已排除）；P8 的 `report` / `task` / `msg` / `autocode` / `sys_job` / UReport（I1 落 45）
- 用 `workshop_id` 当租户键或删除该列
- 菜单克隆、跨租户报表、专库回落主库、第二套认证/Plus
- 跑空 05 文件；未迁成功的 `DATABASE` 租户写入共享主库

### Rules and Constraints

Tenant isolation:

- 本波三包设计表 + S1 P7 + `cal_team_workstation` 均为租户表
- `workshop_id` / `warehouse_id` / `location_id` / `area_id` 不是租户键（工装可能关联仓位，仍须 `tenant_id`）
- 点检计划与设备、班组与工作站的关联表必须各自带 `tenant_id` 谓词，禁止只按 `plan_id` / `machinery_id` / `team_id` 跨租户展开
- 无跨租户设备/排班报表（D5）

Security and masking:

- 漏 include 会导致他厂设备台账、维修历史、工装库存位置被读走
- `TmToolLogMapper.xml` 现 JOIN `tm_tool`、`wm_tool_position`、`wm_storage_location`、`wm_storage_area`：后三张须已在 P5 include；本波必须把 `tm_tool_log` / `tm_tool` 纳入，JOIN 全表加租户谓词
- `CalPlanWorkstationMapper.xml` / `TmToolLogMapper.xml` 现位于 `mapper/md/`，按表名进本波，不得因目录误判为 P4 已覆盖
- 日志与脚本无真实 JDBC/口令/生产主机
- 不引入 Plus；I8 名单本单元不改

Audit and lineage:

- 增量追加-only；回填租户 1
- S1 DDL 证据：**非现网证据：mes-*.sql + Mapper XML**（USER DECISION A）；第 4 节只记表名与键，不贴生产 dump

AI/rule-engine rules:

- 本单元不涉及规则引擎或 AI

Database rules:

- 建议一批或按包拆批，均追加-only：`YYYYMMDD_NN_tenant_cal_dv_tm.sql`（NN 接最大号）；若拆批须 cal → dv → tm 且全部在本单元退出前打完
- `tenant_id bigint not null default 1`
- S4 窄：空库也先 `GROUP BY ... HAVING COUNT(*) > 1` 再 UNIQUE
- 行表（`dv_repair_line`、`tm_purchase_line`、`tm_tool_purchase_line`、`dv_check_*` 关系表）只加列，不加主单号 UNIQUE
- SQL 永不跳过 `tenant_id`
- 禁止改写 `mes-cal.sql` / `mes-dv.sql` / `mes-tm.sql`；禁止跑空 05

### Persistence Changes

Tables, indexes, migrations, mapper XML, and lifecycle rules:
