- Priority: P0（KR-X2；依赖 S1 委托与会话管线）
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/16.kuai-ai-rebuild-gaps.md`（KR-D5/D6/D7/D8/D9/D10/D14、KR-F3/F4/F6、KR-I* 含 I6、KR-X2）

  - 上一单元：`134.kuai-ai-chat-skeleton.md`；后续 `136`–`139`

### Business Goal

把 LangChain 运行时适配进 `core/ai/runtime/`：目录优先的 `model_factory`、`create_agent` 装配、Tool 五值闭集 + `wrap_tool_call` RBAC/审计；档案与授权闸生效；退役 `CompletionService`/`AgentRunner` 后 im/OCR/视觉一律走工厂（非 DeepSeek SDK）。

### Scope

In scope:

- 新建 `core/ai/runtime/`：`model_factory`、`agent_factory`、`tool_bridge`、`sse_adapter`、`memory`（交付另含支撑模块 `context`、`vision`，共 7 文件）
- 退役 `completion_service.py`、`agent_runner.py`；调用点改 `model_factory`
- 表与 API：`llm_providers` / `llm_models`、`agent_profiles` / `agent_grants`（路径见契约表）
- 档案字段：`system_prompt`、`default_model_id`、`knowledge_ids`（库 id）、`enabled_tools`、`mcp_server_ids`、`status`、`grant_mode`（KR-D8/D9）
- `agent_assembler` + `grant_service`：每请求 `create_agent`；ROLE|USER 互斥；管理 list 返回本租户全部档案；停用允许空名单；启用空名单 400；options 仅可用启用档案；写 Tool 默认不勾；种子非强制，若种子则 `enabled_tools` 只有 `search_knowledge`
- Tool 闭集五值注册 + `wrap_tool_call`；保存未知名 400；无权限回 `ToolMessage(status="error")`
- `chat_service` 扩展路径 B：选中档案则装配；**未传 `agent_id` 且本次走 agent 路径** → 解析租户默认档案并做同一使用权校验；**未选档案的纯对话不自动挂默认档案**（KR-D8）
- 有 `agent_id`（含解析到的默认档案）时**忽略请求级模型覆盖**，只用档案 `default_model_id`（KR-F3）
- 路径 B **必须落** `role=tool` 与 `assistant.tool_calls`；回放经 `memory.to_lc_messages` 重建 `ToolMessage`（KR-D6/D7）
- 带 tools 走 `astream_events` 真流式；端点不支持 tool_calls 流式时非流式补全再适配同线格式（删假流式）
- **S2 收口：** 纯对话路径 A 也走 `model_factory`（目录行优先，无目录行才 IntegrationConfig 兜底）；收回 S1 对 `AiRuntimeConfig` 的暂用（KR-D5）
- 抽屉发送的页上下文摘要：后端 `chat_service` / `page_context` 规则（KR-F4/F6）——只信服务端 screen 白名单与按 resource 查到的单号；客户端 `screenLabel`/`recordLabel` 不进 prompt；有读权限才拼短摘要；全宽不拼。S1 可不做摘要；本单元钉死归属
- im_service 与 OCR/视觉出站改 `model_factory`（目录优先 → IntegrationConfig OpenAI 兼容兜底）
- 异步（taskiq、`astream` 后台）：必须拷贝租户与用户上下文，空上下文失败关闭（KR-I6）
- 若 S1 未引入钉死依赖，本单元引入实际用到的契约 D 包（`langchain` / `langchain-openai` / `langgraph`）；`langgraph-checkpoint-postgres`（本期不启用）、`langchain-mcp-adapters`（S4）、`langchain-text-splitters`（S3）版本号仍以契约 D 为准，随对应单元引入——**与代码对齐**

Out of scope:

- 知识库表/解析/retrieval/`search_knowledge` 实现体（S3；本单元可预留 Tool 名与空实现或 stub 仅当测试需要，正式检索属 S3）
- MCP 表与 `MultiServerMCPClient`（S4）
- 前端五页与 F1（S5；前端只传抽屉 context、全宽不传）；`structured_draft`（S6）
- 确认闸、工作流、HyDE、OCR 扫描件、FAQ/`training_samples`、审计查询页、换维/外部向量
- 改 `chat_handler` 契约签名；改 `/ai/**` 或 `code/msg/data`

### Acceptance Criteria

1. `model_factory`：目录行优先；无行则 IntegrationConfig OpenAI 兼容兜底；无厂商 SDK 分支；Key 不回 options/详情；路径 A 与路径 B 均经工厂（收回 S1 `AiRuntimeConfig` 暂用）。
2. 档案 CRUD + grants 符合 KR-D8/D9（字段清单、list 全租户、停用可空/启用空 400、写 Tool 默认不勾、种子非强制）；无授权 send → 403，不静默降级。
3. 未传 `agent_id` 且走 agent 路径 → 解析默认档案并做同一使用权校验；纯对话不自动挂默认；有档案时忽略请求级模型覆盖。
4. 路径 B 落 `role=tool` + `assistant.tool_calls`；回放可重建 `ToolMessage`。
5. Tool 仅五值；写 Tool 调既有 service + 权限码；禁止 SQL 工具。
6. 带 tools 真流式；无 `wrap_sse_from_completion`；兼容分支为非流式补全再适配。
7. 抽屉摘要仅服务端白名单 screen + 有读权限短摘要；label 不进 prompt；全宽不拼。
8. im/OCR/视觉不再直调 `CompletionService`；不绑 DeepSeek SDK。
9. 异步任务拷贝租户/用户上下文；空上下文失败关闭（KR-I6）。
10. checkpointer 默认 `None`；确认闸不实现。

### Rules and Constraints

Tenant isolation:

- 档案/目录/授权全 `tenant_id`；跨租户 404/403；空上下文不得装配/跑 Tool。
- taskiq / `astream` 后台必须拷贝租户与用户上下文（KR-I6）。

Security and masking:

- Key 复用 IntegrationConfig 加密打码；禁全局 client、禁 yml 明文。
- 页上下文：客户端 `screenLabel`/`recordLabel` 不进 prompt。

Audit and lineage:

- `wrap_tool_call` 写 `core_ai_audit_logs`（user/tenant/toolName/businessKey/latency/token）；不落 Key/MCP token。

AI/rule-engine rules:

- `recursion_limit` 替代 `MAX_TOOL_ROUNDS`；每请求 `create_agent`；`knowledge_ids`=库 id（库表属 S3，本单元存 JSONB，调用时复核待 S3）。
- 有档案时只用 `default_model_id`，忽略请求级模型覆盖。

Database rules:

- 新建 providers/models/profiles/grants；密文列不回前端。

### 依赖上一单元

依赖 **S1（134）**：`apps/kuaiai` 骨架、`chat_service` 单名委托、会话/消息表与纯对话管线。本单元在其上挂档案装配与 runtime。

移交项（S1 review 已修，S2 须遵守的形态约定）：`apps_kuaiai_chat_messages.tool_calls` 列**存 OpenAI 线格式** `[{id, type, function:{name, arguments}}]`；回放进 `AIMessage(tool_calls=)` 前须经 `apps.kuaiai.services.chat_service._normalize_tool_calls` 转 LangChain 形态 `{name, args, id}`（S1 已落地并有单测）。S2 路径 B 落 `assistant.tool_calls` 时按 OpenAI 线格式写库；若把回放逻辑抽到 `runtime/memory.py` 的 `to_lc_messages`，必须连同该转换一并搬走，不得直接喂列原值（LangChain 1.x 会 pydantic 校验失败）。

## 2. Plan

### Implementation Approach

1. 落地 `runtime/` 五文件；切 im/OCR；删/退役 runner 与 completion。
2. 模型目录表 + REST；工厂缓存 `(tenant_id, model_id)` + 写路径 evict；路径 A 改走工厂。

4. Tool 桥接 + middleware；`chat_service` 路径 B（落 tool 行）+ `page_context` 摘要；SSE 抽到 `sse_adapter`；异步拷贝上下文。

- `apps/kuaiai`：catalog、agent、assembler、grant、chat_service 扩展、`page_context`

### Public Contracts

- 见 §1 契约；本单元落地 agents/grants/options 与 llm-providers/llm-models。

### Persistence Changes

- `apps_kuaiai_llm_providers` / `apps_kuaiai_llm_models`
- `apps_kuaiai_agent_profiles` / `apps_kuaiai_agent_grants`

### Transaction Boundaries

- 切换 `grant_mode` 同事务清空对侧名单；档案保存与授权更新原子。

### Verification Strategy

- 见 §4；跨租户档案/模型单测；无权限 Tool 回 error ToolMessage。
