- Priority: P11（62 受控写 + 68/72 档案白名单之后；Demo A 第一段可对话脚本）
- Related requirement/design documents:
  - 受控写 / 禁止 SQL：`docs/03.design/06.mes-ai-platform-plan.md` §5.3（**A7 / A26**）；代码 `docs/04.specs/62.ai-controlled-write-tools.md`
  - Agent 档案白名单：`docs/03.design/07.mes-ai-runtime-hardening-plan.md` §5.3（**A31**）；代码 `docs/04.specs/68.ai-agent-profile.md`
  - Vue3 档案勾选：`docs/04.specs/72.ai-agent-profile-ui.md`（**A35**；本单元只追加两个只读 Tool 名）
  - 缺口：`docs/02.requirements/03.mes-ai-platform-gaps.md`（A7、A26）；`docs/02.requirements/05.mes-ai-runtime-hardening-gaps.md`（A31、A35、**R9**）
  - 对话信封（不得漂移）：`docs/04.specs/58.ai-phase1-session-chat.md`、`docs/04.specs/61.ai-langchain4j-runtime.md`
  - 链：`62` / `68` / `72` → **`83`（本文件）**

### Business Goal

工厂用户（租户 `default` / `tenant_id=1`）在已选 Agent 档案上用业务口语走通 Demo A：查待确认工单 → 用既有 `updateWorkorderStatus` 下达 → 列工序任务 → 用既有 `submitProductionFeedback` 报工。本单元只补**两条只读 Tool**，写路径不新开。

Goal：模型能按白名单查本租户工单与工序；无 SQL / JDBC；默认档案仍不含写 Tool。

### Scope

In scope:

- `enabledTools` 枚举新增且冻结为：`queryWorkorder`、`listWorkorderTasks`（只读；`isWriteTool()==false`）
- **queryWorkorder**：可选 `workorderCode`、`productName`（产品名/关键字）、`status`（`PREPARE|CONFIRMED|FINISHED`）。调 `IProWorkorderService.selectProWorkorderList`。返回短文本：workorderId、编号、产品名、数量、状态。最多 20 条。空结果返回「未找到」。无 `tenantId` 参数。
- **listWorkorderTasks**：`workorderId` 和/或 `workorderCode`。先在本租户解析工单，再调 `IProTaskService.selectProTaskList`。返回 taskId、taskCode、工作站 id/code/name、工序名、状态、数量。工作站名缺省时可用 `IMdWorkstationService`。工单不存在 404。无任务「未找到」。
- 权限失败关闭：`queryWorkorder` → `mes:pro:workorder:list`；`listWorkorderTasks` → `mes:pro:protask:list`。空 `TenantContext` / 无 JWT / 无权限不得调 MES service。
- `AiAgentProfileAssembler.selectTools` 仅在档案列出时挂载；`AiAgentEnabledTools.defaultReadOnly()` 仍仅 `searchKnowledge`
- `MesAiAssistant` `@SystemMessage` 告知何时调用新 Tool
- Vue3 `startech-mes-front/src/views/ai/agent/index.vue` 增加两个中文复选框
- 单测：Mock MES service；模式对齐 `ProductionFeedbackWriteToolTest` / `WorkorderStatusWriteToolTest`

Out of scope:

- `confirm()` 大事务、`execute` 报工、IQC / 仓储 / SOP Tools
- MCP、Supervisor、SQL / JDBC Tool、任意 Mapper
- 改 `POST /ai/chat/send`、`POST /ai/agent/send`、`/ai/agent/profile` 信封（只扩展 `enabledTools` 枚举值）
- Vue2；提交 lockfile；升级 Vue / Vite / Element Plus
- 新表 / Flyway；向 Default 租户 SQL 种子 Demo 档案（管理员在 UI 创建「车间生产助手」）
- 配置 live 模型 Key、灌知识库
- 工作流步骤白名单扩容（64）；本 Demo 走 Agent 对话

Non-goals:

- 不把新只读 Tool 写进默认 profile seed
- 不自动勾选写 Tool
- 不为 Tool 新造 MES 查询 SQL

### Acceptance Criteria

- 档案勾选后，模型 tool list 含 `queryWorkorder` / `listWorkorderTasks`；未勾选不得出现
- 默认 / `defaultsOff` 档案仍无写 Tool，亦无本单元两条只读 Tool（除非管理员另建档案勾选）
- 无 JWT / 无 `TenantContext`：不调 MES list；跨租户工单 id/code → 404 或不回他租数据
- 缺 list 权限字：403，不查
- 空列表文案含「未找到」；结果条数 ≤ 20
- Vue3 档案表单可勾选两个新 Tool 的中文标签；新建默认仍不勾写 Tool
- 第 4 节未跑通不得写通过；文档无真实地址/凭据

### Rules and Constraints

Tenant isolation:

- 只信 JWT / `TenantContext`；禁止 Tool 参数 `tenantId`
- 工单/任务经现有 service + 拦截器再查本租户；跨租户不得泄漏字段

Security and masking:

- `/ai/**` 必须登录；不进 `MesPermitAllProvider`
- 日志只记 tenantId / userId / tool / 业务键；禁止 apiKey、cipher、JDBC
- 写 Tool 权限字与 62 不变

Audit and lineage:

- 沿用 71 的 Tool 审计挂载；本单元不改审计表

AI/rule-engine rules:

- 禁止 SQL Tool；只包装 `IProWorkorderService` / `IProTaskService` / `IMdWorkstationService`
- Demo A 下达工单用既有 `updateWorkorderStatus`（只改状态）；Default 数据 `MO202608180005` 已有 NORMAL 任务，不包 `confirm()`

Database rules:

- 无新表、无新 Flyway。不改历史 `backend/sql/` 正文

## 2. Plan

### Implementation Approach

1. `AiAgentTool` 增加两个只读枚举；`fromCode` / `isWriteTool` 覆盖单测。

4. 更新 `MesAiAssistant` 系统提示；Vue3 `toolOptions` 两条中文。
5. 单测 Mock list service；跑 `mvn -pl ktg-ai -am test`。
