- 把 `/ai/**` 写入 `MesPermitAllProvider`
- 实现或改写 `docs/04.specs/49`–`56`

### Frozen HTTP contract (Phase 1 — do not drift)

Assume classic MES `code/msg/data` / `rows`+`total`. All authenticated.

- `GET/POST /ai/provider` list/create; `GET/PUT /ai/provider/{id}`; `DELETE /ai/provider/{ids}`
- `GET/POST /ai/model` list/create; `GET/PUT /ai/model/{id}`; `DELETE /ai/model/{ids}`
- `GET /ai/model/options` → `{id, modelName, providerCode, category}[]` no keys
- `GET/POST /ai/session` list/create; `GET/PUT/DELETE /ai/session/{id}`
- `GET /ai/session/{id}/messages`
- `POST /ai/chat/send` body `{sessionId?, modelId, content}` response `text/event-stream` data lines JSON `{content, done}`

Permissions (propose, keep consistent): `ai:provider:list|query|add|edit|remove`, `ai:model:*`, `ai:chat:list|send`.

本单元只实现上列 **provider / model / options**。session / chat 由 58 实现，路径不得改名。列表是 `GET /ai/provider` 与 `GET /ai/model`（**不要**再加 `/list` 后缀）。`ai:model:*` = `list|query|add|edit|remove`。

### Acceptance Criteria

- `cd startech-mes-basic/backend && java -version` 为 17；`mvn -pl ktg-admin -am compiler:compile -DskipTests` 能编过（写明是否跳过 antrun）
- 无 JWT 调 `GET /ai/provider` → 401；有 JWT 无 `ai:provider:list` → 403
- `GET /ai/model` 与 `GET /ai/model/options` JSON **无** `apiKey` / cipher / 明文 Key；详情 `apiKey` 仅打码或空
- 夹具：两租户各插一厂商/模型；租户 1 列表不含租户 2；跨租户 `GET/PUT/DELETE` 按 id → 404 或 403，不串数据
- include 名单含 `ai_provider`、`ai_model`；无 `TenantContext` 访问失败关闭
- `MesPermitAllProvider` 实现中无 `/ai/**`
- 文档与脚本无真实主机、口令、Token

### Rules and Constraints

Tenant isolation:

- 默认 ROW；`tenant_id` 只从 `LoginUser` 填充，不信客户端租户头
- `DATABASE` 租户：表进 `TenantDedicatedSchema`，未就绪失败关闭，禁止回落主库写共享库
- 唯一键至少 `(tenant_id, provider_code)`、`(tenant_id, provider_code, model_name)`

Security and masking:

- 列表/options 去掉密钥字段；详情可回 `****` + 末 4 位一类打码
- 更新时空 `apiKey` = 不改原密文；非空 = 重新加密
- 日志断言无明文 Key
- `/ai/**` 必须认证

Audit and lineage:

- 增量新文件，不改历史 `ry_*.sql` / `mes-*.sql` / `20260820_*`–`20260822_*`
- `@Log` 记厂商/模型变更，审计内容不含 Key

AI/rule-engine rules:

- 只存 OpenAI 兼容：`apiHost` + 模型名 + Key
- `category`：Phase 1 业务只用 `chat`；允许写入 `vector`/`rerank` 但不被 58 调用
- 不调上游对话（探活可选，非本单元门禁）

Database rules:

- 列与审计字段对齐现有 MES（`create_by` / `create_time` / `update_by` / `update_time` / `remark`）
- `describe` 为 JSON 字段名；库列用 `model_describe`（避免 MySQL 保留字）
- 配置占位只允许环境变量，禁止把现网 yml 真值抄进文档

## 2. Plan

### Implementation Approach

- 按 `ktg-mes` 风格建 `ktg-ai`：依赖 `ktg-common` + `ktg-framework`（或与 mes 相同的安全/Web 传递依赖），MyBatis XML，不要 MyBatis-Plus
- Controller 放 `com.ktg.ai.controller`，继承 `BaseController`；Service 做校验、加密、租户
- Cipher 独立类（可对照 `TenantJdbcCipher` 结构，**密钥名不得复用**）
- 与 58 并行：本单元独占模块 POM、provider/model 包；不要创建 session/chat 包以免冲突

### Affected Modules

- 本单元可改：`backend/pom.xml`、`backend/ktg-ai/**`、`backend/ktg-admin/pom.xml`、`backend/ktg-admin/src/main/resources/application.yml`（只追加表名，不改其它已有值、不复述现网凭据）、`backend/ktg-common/.../TenantDedicatedSchema.java`（只追加）、`backend/sql/20260823_21_*.sql`（若当日 `NN` 已被占用则顺延，禁止改历史号）
- 本单元不可改：`startech-mes-front/**`、`frontend/**`、`ktg-generator`、UReport、`MesPermitAllProvider` 放行列表

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- 信封：列表 `TableDataInfo`（`rows`/`total`）；详情/写 `AjaxResult`（`code/msg/data`）
- 权限：`@PreAuthorize("@ss.hasPermi('ai:provider:list')")` 等，与 Frozen 块一致
- `GET /ai/model/options`：`@PreAuthorize` 允许 `ai:model:list` **或** `ai:chat:list`（对话页无模型管理权也能拉下拉）
- 厂商字段（对照 ruoyi-admin，适配）：`providerName`、`providerCode`、`providerIcon`、`apiHost`、`status`；可选 `providerDesc`、`remark`、`sortOrder`
- 模型字段：`category`、`modelName`、`providerCode`、`describe`、`modelShow`、`dimension`、`apiHost`、`apiKey`（只写 / 详情打码）
- `providerIcon` 存 URL 或 MinIO 对象键；若页面上传，走既有 `POST /common/uploadMinio`，本模块不接文件流
- session / chat 路径由 58 提供，本单元不要占这些 mapping

### Persistence Changes

Tables, indexes, migrations, mapper XML, and lifecycle rules:

- 建议文件（实现日按 `backend/sql/` 最大 `NN+1` 顺延）：
  - `20260823_21_ai_provider_model.sql`：建表 → **加入** `TenantDedicatedSchema.incrementalSqlFiles()`
  - `20260823_21_ai_provider_model_menu.sql`：`sys_menu` / `sys_role_menu`（超管绑定沿用仓库既有 admin 角色写法）→ **不要**加入专库 catalog
- `ai_provider`：`provider_id` PK、`tenant_id NOT NULL`、`provider_name`、`provider_code`、`provider_icon`、`api_host`、`status`、`provider_desc`、审计列；`UNIQUE (tenant_id, provider_code)`
- `ai_model`：`model_id` PK、`tenant_id NOT NULL`、`category`、`model_name`、`provider_code`、`model_describe`、`model_show`、`dimension`、`api_host`、`api_key_cipher`、`status`、审计列；`UNIQUE (tenant_id, provider_code, model_name)`
- Mapper XML 放 `ktg-ai/src/main/resources/mapper/ai/`
- include-tables **只追加** `ai_provider`、`ai_model`（58 追加另外两张，禁止重排整表名单）
- `TenantDedicatedSchema` 追加 `AI_TABLES`（本单元两张；58 往同一 list 再追加 session/message，禁止删既有 list）

### Transaction Boundaries

- 保存厂商/模型：校验 +（可选）加密 + insert/update 同一事务
- 删除：本租户 id 批量；不级联删 58 的会话（58 未落地时无行）

### Risks

- 与 58 同时改 `application.yml` / `TenantDedicatedSchema` 产生冲突 → 只追加本单元表名/文件名
- 把 `/ai/provider` 做成 `/ai/provider/list` 导致 59 对不齐 Frozen 契约
- options 或列表漏出 Key / `apiHost` 上的 userinfo 口令
- 模块未被 `com.ktg` 扫描到（admin 未依赖）
- 把 `/ai/**` 放进 permitAll

- 有单测则 `mvn -pl ktg-ai,ktg-admin -am test`（Cipher 往返/篡改、打码、跨租户）
- 静态：`rg` 确认 `MesPermitAllProvider` 无 `/ai`；options VO 无 apiKey
- 不跑 Vue `build:prod`（59 的职责）
- 未真实跑通不得写「测试通过」
