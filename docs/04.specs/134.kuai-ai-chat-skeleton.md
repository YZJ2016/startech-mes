## 1. Spec

### Capability

- Name: S1 — `apps/kuaiai` 骨架 + 会话/消息 + `chat_service` 单名委托 + 纯对话 SSE
- Module: **业务**落 `kuaigeyun-mes` 的 `apps/kuaiai`（后端 `riveredge-backend`、前端本单元不建页）+ KR-G0 白名单内 `core/ai/chat_handler.py` 探测点小改。**禁止**改 `startech-mes-basic/`、外层 `AGENTS.md`；不放开白名单与 F1 挂钩以外的快格仓目录。
- Priority: P0（本轨首刀；KR-X1）
- Related requirement/design documents:
  - 缺口：`docs/02.requirements/16.kuai-ai-rebuild-gaps.md`（KR-D2/D3/D4/D5/D6/D7、KR-I1–I5、KR-X1）
  - 设计：`docs/03.design/16.kuai-ai-rebuild-plan.md`（§3–§6 路径 A、§8、§13、§15 S1）
  - 同轨后续：`135`（runtime/档案）、`136`（知识）、`137`（MCP）、`138`（前端）、`139`（结构化草稿）

### Business Goal

在快格仓独占 `apps/kuaiai` 槽位：应用骨架、会话/消息自表、网关 `find_spec` 单名委托到 `chat_service`，已登录用户可走纯对话 SSE（`ChatOpenAI`，OpenAI chunk 线格式），消息表回放为唯一历史基线。

### Scope

In scope:

- 后端 `apps/kuaiai` 骨架：`manifest.json`、路由注册、权限码种子（本轨全套管理位一并进 manifest，实现可按单元启用）
- 表 `apps_kuaiai_chat_sessions` / `apps_kuaiai_chat_messages`（含 tool 列，供后续全宽历史）
- `chat_service.create_chat_completion`：验会话归属 → 写 user → 消息表回放 → `ChatOpenAI` 纯对话流式 → 写 assistant + token；不 `bind_tools` / 不传 tools（等价 `tools=[]`），不装配档案（与代码对齐）
- `chat_handler.py`：契约签名不动；`find_spec` 改为单名 `apps.kuaiai.services.chat_service`，废止 `deepseek_service`
- 产品 REST：会话/消息 CRUD（见下方契约表）
- 依赖：可与 S2 同批引入钉死版本（§钉死契约 · 版本）；本单元至少能跑 `ChatOpenAI` 纯对话（S1 实钉 `langchain`/`langchain-openai`；`langgraph` 随 langchain 传入；其余契约 D 包随后续单元）
- 无档案纯对话：模型解析可暂走 `AiRuntimeConfig` / IntegrationConfig 兜底（出站仍是 `ChatOpenAI` + 可配置 `base_url`/`api_key`，**不是** DeepSeek SDK；辅助函数/默认值名可含 `deepseek_*`）；**S2 收口时路径 A 也必须改走 `model_factory`**（目录行优先，无目录行才 IntegrationConfig 兜底）（KR-D5；与代码对齐）

Out of scope:

- `core/ai/runtime/`、`agent_assembler`、档案/授权、Tool 闭集、im/OCR 改道、路径 B 落 tool 行、页上下文摘要（S2）
- 知识库 / RAG / `search_knowledge`（S3）
- MCP（S4）；前端五页与 F1（S5）；`structured_draft`（S6）
- 确认闸、工作流、换维、外部向量、HyDE、OCR 扫描件、FAQ/`training_samples`、审计查询页
- 改网关为 `/ai/**` 或 `code/msg/data`；放开 KR-G0 白名单以外的 `core/ai` 文件

### Acceptance Criteria

1. `find_spec` 仅探测 `apps.kuaiai.services.chat_service`；旧名不再命中。
2. 登录 + `kuaiai:act:execute` 可对自有会话纯对话 SSE；线格式兼容现网前端（`choices[].delta.content` + `[DONE]`）。
3. 会话/消息 REST 权限码与路径同契约表；跨租户/跨用户 session → 404/403 且不调上游。
4. 消息表回放为发送历史唯一来源；**S1 纯对话可不落 tool 行**（无 tools），但表结构含 tool 列；**S2 路径 B 必须落** `role=tool` 与 `assistant.tool_calls`（见 `135`）。
5. 未选档案的纯对话不自动挂默认档案；不引入第二套 RAG/Agent。
6. 文档与日志无真实地址、密钥、口令。
7. S1 允许暂用 `AiRuntimeConfig` 出站（`ChatOpenAI`，OpenAI 兼容；实现注释已标 S2 收回）；须在文档/实现注释标明 **S2 收回**为 `model_factory`（目录行优先）。

### Rules and Constraints

Tenant isolation:

- 全表 `tenant_id`；查询强制本租户；空上下文失败关闭（KR-I1–I3）。
- body / context 禁 `tenantId`；只信 `get_current_tenant`。

Security and masking:

- AI 端点须登录 + 权限码；不进匿名白名单（KR-I4）。
- 日志 / SSE 不落 apiKey、cipher、JWT、内部路径（KR-I5）。

Audit and lineage:

- 复用 `AiAuditMiddleware`（`/api/v1/core/ai`）；产品写操作本期不进工具审计。

AI/rule-engine rules:

- 本单元纯对话、无 tools；checkpointer 默认不接。

Database rules:

- 新建 chat 两表；软删沿用 `BaseModel`；唯一键 `(tenant_id, 业务键)`。
