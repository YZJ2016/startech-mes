### Business Goal

报表中心能列出草稿与已发布、系统报表与自定义报表，并按业务分类分组。KRP-D6 的 10 张系统报表随应用种入，打开后能筛选、分页、合计、打印，并能由后端生成全量 Excel。本段结束时还不能自己拖列。

### Scope

In scope:

- 列表使用已有列，不新增列：
  - `category`：迁移 92 已有，迁移 93 注释为 `system` / `custom`（系统报表 / 用户自定义）。默认 `'custom'`。
  - `classify`：迁移 512 增加，注释为业务分类（销售/采购/生产等），默认 `'未分类'`。与 `category` 分开。
  - `is_system`：迁移 92，默认 `false`。
  - `status`：迁移 92，默认 `'DRAFT'`。发布后与 `'DRAFT'` 区分，仍用这一列，不新增状态表。迁移没有发布态检查约束，需求只要求草稿/发布可区分。
- 预览与打印走已有 `UniReport`（`mode='config'` 时用 `reportConfig` + `reportId`，内部调用 `executeReport`）。打印走已有 `useUniReportPrint`。
- 全量 Excel 仍由本切片在后端生成。`useUniReportExport`（`uni-report/useUniReportExport.ts`）的当前页与勾选行是浏览器 CSV；`type==='all'` 且配了 `exportConfig` 时走星制造 `exportDomainReport`，不是星报表后端 Excel。这两条都不算本切片的全量导出。
- 本切片只种入下面 10 张系统报表，不新建 `category=custom` 行，也不提供设计器。列表要能筛出 `custom`；这类行的新建与 `report_config` 写入归 147。
- 代码种入且不靠设计器的 10 张（KRP-D6）。`category='system'`，`is_system=true`，`report_config` 只引用数据源 / 数据集，不存放 SQL 正文。`code` 用下表，满足已有唯一约束 `(tenant_id, code)`。需求给了中文名、没给 `code`，这里只为验收绑定已有列：

| code | name |
| --- | --- |
| `inv_ledger` | 库存台账 |
| `wo_tracking` | 工单跟踪 |
| `qc_pass_rate` | 检验合格率 |
| `perf_stats` | 效能统计 |
| `node_timeliness` | 节点时效 |
| `process_efficiency` | 处理效率 |
| `sales_trace` | 销售全链路追踪 |
| `purchase_trace` | 采购全链路追踪 |
| `material_trace` | 物料全生命周期追踪 |
| `biz_overview` | 业务综合看板 |

- `classify` 使用迁移 512 的列。销售全链路追踪为「销售」，采购全链路追踪为「采购」。其余写入业务分类中文，不得把「分析报表」「跨业务报表」种成第 11、12 张报表。
- 不恢复已下线的「效能中心」侧栏分组。星制造固定看板页留在 `kuaizhizao`，不迁入。
- 种入的 10 张默认不开启分享。
- 种入查询落在 MES 这一个库的数据集上（`query_type` 为 `sql` 或 `api`）。不在本文件写死每一列的业务公式；验收是这 10 张能打开并返回 `data` / `total` / `summary`。

Out of scope:

- 设计器拖列、保存版本、新建 `category=custom` 并写入 `report_config`（147）
- 大屏与受控分享（148）
- 角色授权、订阅、版本回看（149）
- 数采与数采专用接口
- 把 `useUniReportExport` 当作全量导出
- 增补 KRP-D6 以外的系统报表

### Acceptance Criteria

1. 报表中心能按 `status` 区分草稿（`'DRAFT'`）与已发布，按 `category` 区分 `system` / `custom`，按 `classify` 分组。
2. 上表 10 个 `code` 各种入一行，`name` 与表一致，`category='system'`，`is_system=true`。没有名为「分析报表」或「跨业务报表」的报表行。侧栏没有「效能中心」分组。
3. 打开其中一张，预览走 `UniReport` config 模式并调用 `executeReport`，得到 `data` / `total` / `summary`。打印走 `useUniReportPrint`。
4. 全量导出是后端生成的 Excel。当前页与勾选行的浏览器 CSV，以及 `type==='all'` 且配了 `exportConfig` 时的星制造 `exportDomainReport`，都不是这条全量 Excel。
5. 这 10 张的 `report_config` 不含 SQL 正文。列表能按 `category` 筛出 `custom`。本切片不新建 `custom` 行，也不提供设计器。
6. `kuaizhizao` 原有报表页仍在原应用。无租户上下文不读报表表。

### Rules and Constraints

Tenant isolation:

- 列表与种入都带 `tenant_id`。种入行属于当前租户，不写成全局无租户数据。

Security and masking:

- 导出文件不包含连接密文或内部路径。

Audit and lineage:

- 不新造审计表。`created_by` / `updated_by` 使用表上已有列。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 不新增列，不改迁移 92 / 93 / 512 的文件名。
- `category` 只使用注释已说明的 `system` / `custom`。

### 依赖顺序

- 依赖 145 的 `executeReport` 与数据源登记。
- 不依赖 147–149。

## 2. Plan

### Implementation Approach

1. 报表中心读 `apps_kuaireport_reports`，筛 `status`、`category`、`classify`。
2. 应用启动或安装路径种入上表 10 行；已存在同一 `(tenant_id, code)` 则不重复插入。
3. 预览页把 `reportId` 与 `report_config` 交给已有 `UniReport`。
4. 全量导出在后端按同一套筛选调用执行结果并写 Excel。不把 `useUniReportExport` 的浏览器 CSV，或它在 `type==='all'` 且配了 `exportConfig` 时调用的星制造 `exportDomainReport`，当作本切片的全量 Excel。

### Affected Modules

- `riveredge-backend/src/apps/kuaireport`（145 新建之后的报表列表、种入、导出）
- `riveredge-frontend/src/apps/kuaireport`（报表中心页；预览复用 `components/uni-report/UniReport.tsx`）
- 只读：`useUniReportPrint.ts`、`useUniReportExport.ts`（后者不作为全量导出）

### Public Contracts

- 预览契约仍是 145 的 `executeReport`。
- 不改 `UniReport` 的 config 模式。

### Persistence Changes

- 无新表。插入或更新 `apps_kuaireport_reports` 的已有列：`code`、`name`、`category`、`classify`、`is_system`、`status`、`report_config`、`tenant_id`。

### Transaction Boundaries

- 同一租户的 10 张种入在一个事务里完成；中途失败不留下半套 `code`。

### Risks

- 把「分析报表」「跨业务报表」当成报表名种入，会超出 KRP-D6。
- 用前端导出顶替后端全量 Excel，验收不通过。

### Verification Strategy

- 见 §3。§4 实跑后填写。本文件写下时未跑命令。
