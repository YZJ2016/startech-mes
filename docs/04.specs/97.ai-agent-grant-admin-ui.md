### Business Goal

管理员在现网档案对话框选择「按角色」或「按人员」，维护对应名单。`USER` 用部门树选人，提交仍是 `userIds`。启用保存时名单不能空。无 `add/edit` 的人仍然不能改。list 继续展示全部档案。

### Scope

In scope:

- 授权 UI 只做在现有 `/ai/agent`（`views/ai/agent/index.vue` 新增/修改对话框）；不新开菜单、不新开独立授权页；管理 list 仍全量
- 表单：`grantMode` 单选 `ROLE` | `USER`（中文标签：按角色 / 按人员）
- `ROLE`：本租户角色**多选**；支持按名称筛选；不强制部门树；复用 Vue3 `src/api/system/role.js` 的 `listRole`（现网 `GET /system/role/list`），不新造权限字
- `USER`：选人 UI，不是按部门授权。左侧/上侧部门树，右侧（或同区）该部门下人员**多选**；仍可按用户名/昵称筛选。提交体仍是 `userIds` 数组（96 契约不变）。复用现网用户管理：部门树 `GET /system/user/deptTree`（`src/api/system/user.js` 的 `deptTreeSelect`）；人员列表 `GET /system/user/list`（同文件 `listUser`，query 带 `deptId`，并可带 `userName` / `nickName`）。不新造 path、不新造组织权限字
- 切换模式清空另一侧并提示；提交体只带当前侧 id 数组，另一侧 `[]`（契约仍 96 `roleIds` / `userIds`）
- 启用状态 + 当前侧空 → 前端拦截；以后端 400 为准
- `v-hasPermi` 仍 `ai:agent:profile:*`；axios `request.js`
- 列表页可选一列「授权方式」（角色/人员），不展示完整 id 名单也允许（详情/对话框必须可编辑名单）

Out of scope:

- 改 `/ai/agent/profile` Java（属 96）
- 对话页 / F1（**98**）
- 独立授权菜单/页；按部门作为授权模式 / 岗位授权（AG-G1 本期不做；选人用部门树 ≠ 按部门授权）；有效期（AG-G2）
- 改 Vue2；提交 lockfile；升级 Vue / Vite / Element Plus

Non-goals:

- 不在本页发起 SSE
- 不把 options 当成本页 list 数据源

### Acceptance Criteria

- 授权编辑在现有档案新增/修改对话框内完成；无新菜单、无独立授权路由/页
- `ROLE`：角色多选 + 按名称筛选；不强制部门树
- `USER`：部门树 + 该部门人员多选；仍可按用户名/昵称筛选；保存体 `userIds`，不传部门 id、不传 `grantMode=DEPT`
- 有 `profile:edit` 能改授权；无配置权按钮仍隐藏（72 已有）
- 保存体含 `grantMode` 与一侧 id 数组，不传 `tenantId`
- 切换模式不会把角色 id 当 userId 提交
- `npm run build:prod` exit 0 后才写第 4 节通过
- `frontend/` git diff 为空

### Rules and Constraints

Tenant isolation:

- 不传客户端租户头；角色/用户下拉走现网本租户接口

Security and masking:

- toast 不打印凭据、内部路径

Audit and lineage:

- 不改历史菜单 SQL；本页无新菜单

AI/rule-engine rules:

- 无

Database rules:

- 无（前端）
