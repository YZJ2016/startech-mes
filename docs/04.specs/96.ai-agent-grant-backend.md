### Business Goal

服务端成为使用权唯一真相：启用档案必须有 ROLE 或 USER 名单；options 只返回当前用户能用的启用档案；`agent/send` 无授权 403。存量启用档案迁成「本租户全部正常角色」。

### Scope

In scope:

- Flyway **tenant**：`ai_agent.grant_mode`（`ROLE`/`USER`）；表 `ai_agent_grant`（`tenant_id`、`agent_id`、`target_type`、`target_id`）；存量启用档案插入该租户全部正常 `sys_role`
- include + 专库 catalog 同步 `ai_agent_grant`
- profile 读/写 VO 增量 `grantMode`、`roleIds`、`userIds`；保存覆盖授权行；启用+空名单 400；mode 与行 type 必须一致
- `selectOptions()` 按 AG-D4/D5 过滤；权限字仍 68（`profile:list|query` 或 `ai:chat:list`）
- `AiAgentProfileAssembler.assemble` / send 路径：无使用权 403；未传 `agentId` 校验默认档案
- 单测：角色命中/未命中、人员命中/未命中、跨租户 404、空名单启用 400、send 403 不调模型工厂、list 不过滤、`isAdmin` 不跳过、迁移脚本语义（可用 mapper 夹具）

Out of scope:

- Vue3（**97/98**）
- 部门/岗位、有效期
- 改 send URL / SSE 信封
- 改 Vue2；真实地址、凭据

Non-goals:

- 不新造 `ai:agent:use:*` 权限字
- 不在本单元改 Tool 鉴权逻辑

### Acceptance Criteria

- 启用档案无授权行 → 保存 400；options 不含；send 403
- 用户角色命中 ROLE 档案 → options 含；send 可组装
- 仅 USER 名单外用户 → options 不含该档案；send 403
- 管理 list 含当前用户不能使用的档案
- 跨租户 id 不泄漏他厂名称
- `/ai/**` 仍不进 permitAll
- 第 4 节未编码前不得写「测试通过」

### Rules and Constraints

Tenant isolation:

- 只信 JWT；禁止 body `tenantId`
- 角色/用户 id 必须本租户；SQL 带 `tenant_id`

Security and masking:

- 403 文案不回内部路径、不回他厂字段
- 写 Tool 闸不因本单元放宽

Audit and lineage:

- 只 Flyway tenant + catalog；不改 `backend/sql/` 历史文件

AI/rule-engine rules:

- 无授权不得挂载该档案 Tool/MCP/systemPrompt

Database rules:

- `grant_mode` 与 grant 行 type 一致；唯一键防重复挂

## 2. Plan

### Implementation Approach

1. Flyway 加列、建表、存量 ROLE 绑定全部正常角色；include；catalog。
2. Mapper + 保存时删后插授权行；校验 mode XOR 与空名单。
3. `canUse(agent)` 读 `LoginUser`；options / assemble / send 共用。
4. 单测覆盖 Scope 列表。

### Affected Modules

- `ktg-ai`：domain、mapper、profile service、assembler、agent send、测试
- `ktg-system`：Flyway tenant、include、专库 catalog

### Public Contracts

- profile JSON 增量：`grantMode`、`roleIds`、`userIds`
- options：形状不变，结果集变少
- `POST /ai/agent/send`：无授权 HTTP 403（`ServiceException` + 现网信封）

### Persistence Changes

- `ai_agent.grant_mode` NOT NULL 默认 `ROLE`
- `ai_agent_grant` + unique `(tenant_id, agent_id, target_type, target_id)`
- 迁移：启用档案 × 本租户正常角色

### Transaction Boundaries

- insert/update 档案与覆盖 grant 同一事务
- send 校验在 `prepare` / 调模型之前

### Risks

- 迁移「全部角色」使上线瞬间行为接近现网，必须靠管理员后续收紧（产品接受）
- options 与 send 规则分叉

### Verification Strategy

- `cd startech-mes-basic/backend && mvn -pl ktg-ai -am test`（第 4 节实跑）
- 无浏览器（97/98）
