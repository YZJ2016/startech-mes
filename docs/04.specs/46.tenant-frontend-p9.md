## 1. Spec

### Capability

- Name: P9 Vue3 管理端多租户最小改动（登录 F5+F6、getInfo、自助注册关闭、runAs、分步建租户）
- Module: 仅 `startech-mes-basic/startech-mes-front/`（Vue 3 + Element Plus + Vite）。**禁止**改 `startech-mes-basic/frontend/`（Vue2 冻结）
- Priority: P1
- Related requirement/design documents:

  - 缺口清单：`docs/02.requirements/02.mes-multi-tenant-gaps.md`

### Business Goal

让唯一上线管理端（Vue3）按域名优先、编码兜底完成强制 `tenantCode` 登录；工厂会话只展示租户名；平台运营在本工程内分步建租户、看打码 JDBC、代管工厂。Vue2 不改；P1 之后 Vue2 登录失败视为已接受。

### Scope

In scope:

- 登录页 F5+F6：优先按当前 Host 调匿名接口；命中则隐藏编码框且不可「使用其他编码」；未命中才显示编码输入。匿名接口至多返回一个 `tenantCode`，永不返回列表
- `POST /login` Body 仍必填 `tenantCode`（D2）。改 `src/api/login.js`、`src/views/login.vue`、`src/store/modules/user.js`
- `GET /loginOuth` / `src/views/loginOuth.vue`：与管理端同一套 F5（F7）；缺 Host 且缺码 → 失败，不默认租户 1
- 工厂 `getInfo`：可选 `tenantId` / `tenantName`；**不**展示、不存储 `isolationLevel`（F2）。隔离级别只出现在平台租户管理接口与页面
- 关闭自助注册（F8）：登录页去掉「立即注册」；`/register` 路由不作为可用入口（隐藏或重定向登录）；不新增租户下拉的找回页。若已有找回/重置，走同一 F5，禁止租户列表
- 平台 runAs（F9）：仅 Vue3 PC；页眉标明「正在代管工厂 X」；显式退出；工厂管理员 UI 不出现代管痕迹。平板不是代管面（本单元不建平板工程）
- 分步新建租户（F4）：① 基本信息（编码、名称、隔离级别、可选 `server_name`）；② 仅 `DATABASE` 填 JDBC URL / 用户 / 口令；③ 后续步骤建 schema/表。列表：编码、可选域名、隔离级别、部分打码 JDBC、用户名、打码口令；揭明文须显式操作（后端已审计）
- 租户管理菜单只挂本应用的平台运营；精确路由本单元锁定为 **`/platform/tenant`**（子页可 `/platform/tenant/create` 等，均在 `/platform/**` 下）
- `src/utils/request.js` **不得**增加 `X-Tenant-Id` 或其它客户端租户头
- `tenantCode` / `server_name` 表单只许平台改（F10）；工厂设置页不得出现这两项
- 文档写明 Vue2 登录失败为已接受（F1+D2）

Out of scope:

- 任何对 `startech-mes-basic/frontend/` 的改动（F1）
- 新建平板/手机工程；平板注册 `/platform/**`（入仓后的白名单属后续，本单元只把边界写进路由约定）
- 启用后端未提供的 Vue3 3.9 锁屏契约变更（现有 `/lock` UI 可保留，不把租户逻辑绑到 `/unlockscreen` 新字段）
- 跨租户报表页（D5 / 47）
- 改 Java/SQL（消费 36/37/41 已提供的平台 API；揭明文 / schema / runAs HTTP 由 spec 41 落地，本单元只接线、不另造 URL）
- 引入第二套认证；登录后信任客户端租户头
- 提交 `package-lock.json` / `yarn.lock`

### Acceptance Criteria

对齐设计 P9 退出标准，须全部满足：

- 绑了 `server_name` 的 Host 打开登录页：不展示编码框、无「使用其他编码」，提交 Body 仍含该 `tenantCode`
- 未绑定 Host：展示编码输入框；匿名接口不返回租户列表
- Vue3 交互登录必须带 `tenantCode`；缺码失败；失败文案统一（D9，前端不把后端「用户名或密码错误」改写成「租户不存在」）
- `GET /loginOuth` 缺 Host 且缺码失败（F7）
- 工厂 `getInfo` 无 `isolationLevel`；平台租户管理接口可返回隔离级别与许可
- 平台租户管理菜单不出现在工厂许可内（平台模块永不许可给工厂；前端即使拿到多余路由也不得在工厂会话展示 `/platform/**`）
- 响应结构仍为 `code/msg/data`；工厂页眉可展示租户名称，不展示 JDBC
- 本阶段不碰 `frontend/`，不新建平板工程
- **已接受（F1+D2）：** P1 之后 Vue2 `frontend/` 现行登录不发 `tenantCode`，交互 `POST /login` 失败。不为 Vue2 做兼容、不排切序窗口。管理端只走本目录 Vue3
- `request.js` 源码中不存在 `X-Tenant-Id`
- `npm run build:prod`（在 `startech-mes-front/` 内）实际跑过；未跑通不得写构建成功

### Rules and Constraints

Tenant isolation:

- 登录后租户只在 JWT 中；前端不再传租户头
- Host 命中则写死该厂（F6），禁止提供切换编码入口
- 匿名解析只用当前 Host，禁止用查询参数枚举任意编码、禁止返回租户数组或他厂名称
- 工厂会话不展示隔离级别、许可清单、JDBC
- runAs 仅平台运营账号 UI 可见；DS/上下文由后端切换，前端只调平台 API 并展示页眉

Security and masking:

- 列表默认打码 JDBC / 打码口令；明文只走带审计的揭开接口；页面不得把 cipher 当密码回填
- `ROW` 租户表单不出现 JDBC 列；提交不得带 JDBC 字段
- 揭明文按钮仅平台；工厂账号不渲染该按钮
- 登录失败不提示「租户不存在」（D9）
- 不在前端日志、toast、示例中写入真实 JDBC URL、口令、生产主机
- 平台模块路由 `/platform/tenant` 不得作为工厂可分配菜单的组件 path 文档去鼓励赋权（后端永不许可）

Audit and lineage:

- 揭明文、runAs 进入/退出的审计在后端；前端只触发显式操作，不把明文写入浏览器持久化
- Cookie「记住密码」不得存 `tenantCode` 以外的 JDBC/口令；Host 命中时记住的是该厂码，不得用来改登别厂

AI/rule-engine rules:

- 本单元不涉及规则引擎或 AI

Database rules:

- 本单元不改表、不写 SQL
- 不把真实库地址写进 `.env` 示例；新增环境项只用占位符或变量名

## 2. Plan

### Implementation Approach

1. **匿名 Host 解析：** 沿用 37 已锁定 **`GET /login/resolveTenant`**（permitAll，无查询参数，只读 `request.getServerName()`）。Vue3 登录页加载时调用；`data` 为单码或空，永不按数组渲染下拉。
2. **登录 F5+F6：** `loginForm` 增加 `tenantCode`。Host 命中：隐藏输入框、锁定该码、无「使用其他编码」。未命中：必填编码框。`login()` API 把码放入 Body。缺码不发请求或接受后端失败，不默认 `default`。
3. **loginOuth：** 同一套解析；省略码且 Host 未命中则失败提示与 D9 一致，不跳进租户 1。
4. **F8：** `login.vue` 去掉注册链接；`router` 中 `/register` 对匿名用户重定向 `/login`（或 hidden 且不从登录可达）。全局注册开关保持关闭的消费方，不在 UI 打开。
5. **getInfo F2：** store 增加可选 `tenantId`/`tenantName`；**丢弃**响应里若误带的 `isolationLevel`。Navbar 工厂显示租户名；不显示 JDBC/隔离级别。
6. **request.js：** 只保留 Bearer；明确禁止加租户头。回归时 rg 确认。
7. **平台页 `/platform/tenant`：** 动态路由组件放在 `src/views/platform/tenant/`（名称随现有风格）。列表打码列；分步向导对接后端创建/JDBC/建 schema 接口；揭明文按钮走单独 API。菜单 path 与后端 `sys_menu` 种子（若 36/39 已插）对齐为 `/platform/tenant`；本单元若需文档约定菜单 component 为 `platform/tenant/index`。
8. **runAs F9：** 平台列表「进入工厂」；Navbar 在代管态显示「正在代管工厂 X」+ 退出。工厂角色不渲染该入口。调用后端 runAs/退出接口（路径若 36 已定则沿用，否则与 `/platform/tenant` 同前缀，如 `POST /platform/tenant/runAs/{id}` 与退出接口——**以后端 36/37 契约为准，本单元不发明第二套 URL**）。
9. **F3/F10：** 工厂设置/资料页不提供改编码/域名。前端路由守卫：非平台会话访问 `/platform/**` 回 401 页（纵深，权威仍在后端许可）。
10. **Vue2 说明：** 本 spec 与发布说明级注释（仅本文件）写明不改 `frontend/`；不为其加 `tenantCode`。

### Public Contracts

- 保持：`POST /login`、`GET /getInfo`、`GET /getRouters`、`Authorization: Bearer`、`code/msg/data`；登录成功仍用 `token` 字段
- 变更（前端消费）：`LoginBody.tenantCode` 必填；`getInfo.data` 工厂侧可读 `tenantId`/`tenantName`，忽略 `isolationLevel`
- 匿名：`GET /login/resolveTenant`（37 已锁定）→ 至多一个 `tenantCode`
- 平台：租户 CRUD / JDBC 揭明文 / 分步建 schema / runAs——仅平台；Vue 路由 `/platform/tenant`
- runAs：`POST /platform/tenant/runAs/{id}`、`POST /platform/tenant/runAs/exit`（spec 41 已落地；本单元 Vue3 按此契约接线）
- 揭明文：`POST /platform/tenant/{id}/jdbc/reveal`（spec 41 已落地；Body `{ field }`）
- 建 schema：`POST /platform/tenant/{id}/schema`（spec 41 已落地）
- 不加 `X-Tenant-Id`

### Persistence Changes

- 无。菜单 path `/platform/tenant` 若需种子数据，由 36/39 的 SQL 负责；本单元只约定字符串，不直接改库

### Transaction Boundaries

- 无浏览器本地「事务」。分步建租户每步独立调后端；建 schema 失败按 I6 展示未就绪与重试，不在前端删除登记

### Risks

- 登录页下拉枚举租户造成编码泄露
- Host 命中后仍保留编码框，导致 F6 被绕过
- `request.js` 被误加租户头，登录后客户端可改头撞后端（后端应忽略，但仍禁止）
- 工厂 `getInfo` 把 `isolationLevel` 渲染到页眉
- Vue2 被顺手打补丁，破坏 F1
- 平台页误挂进可赋给工厂的组件路径
- 明文 JDBC 进 vuex、localStorage 或列表默认列

### Verification Strategy

- 手工/组件级：三种登录页状态（Host 命中 / 未命中 / 平台未绑定入口）
- 缺 `tenantCode` 的请求失败；文案不含「租户不存在」
- 工厂账号 `getRouters` 后侧栏无「租户管理」；直开 `/platform/tenant` 被拒
- 列表响应无 password 明文；揭明文走单独动作
- rg `startech-mes-front/src` 无 `X-Tenant-Id`；`git diff` 无 `frontend/`
- `cd startech-mes-front && npm run build:prod`
- 不跑 Vue2 `frontend/` 的 lint/build（本单元未改该树）
