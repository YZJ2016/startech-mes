# KU-AI 能力矩阵绑定场景实例

从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已实施（浏览器端到端点击验收待补）。

## 1. Spec

### Capability

- Name: 能力矩阵按场景模板逐场景出卡（Y1=a），每卡默认绑定同 key 预置实例（Y2=a），点击后走档案装配并真实使用 Tool；原 `data_query` 泛卡移除（Y5=a）。
- Module: `riveredge-backend/src/apps/kuaiai/services/{operations_service,settings_service,agent_scene_service}.py`、`core/utils/integration_settings.py`；`riveredge-frontend/src/apps/kuaiai/pages/{hub,settings}`。
- Priority: P0。
- Related requirement/design documents: 需求 25 SC-D6、SC-D14、SC-D15、§4.7；设计 26 §2（能力矩阵三行事实）、§8；设计 24 §4、§10、§11.1–11.2；spec 181、185。

### Business Goal

用户在能力矩阵直接看到“订单交期”“缺料齐套”等场景卡（每场景模板一卡），卡显示就绪时点进去的对话确实挂上业务 Tool；未就绪时明确告诉用户缺什么（模板停用、实例停用、档案未启用、无使用权、模型未配置、档案没有业务 Tool、已解绑）。零配置打通：模板落地即自动绑到同 key 预置实例，管理员只需“开模型 + 启用档案 + 授权”。

### Scope

In scope:

- hub `capabilities[]` 由 `SCENE_TEMPLATES` 驱动：除 `ask` 卡（纯对话路径 A，SC-D15）外，每个场景模板渲染一张场景卡；原 `data_query` 泛卡移除（Y5=a）。
- `capability_key` 与场景模板 key 同一命名空间。**默认绑定解析**：某 key 在 `capability_bindings` 中无条目 → 解析到同 key 的预置场景实例（存在且未删除时）；显式 `null` → 解绑；显式实例 key → 覆盖绑定。
- 站点设置 `integrations.kuaiai` 新增键 `capability_bindings`：`{capability_key: instance_key | null}`，**只存覆盖**；`guide`、`recommend` 落地时再扩，本单元不预留空键。
- `/settings` 页新增“能力绑定”区块，按模板列出，每项默认显示“随预置实例”，选项来自智能体库实例列表；保存复用 spec 185 的版本锁 + 深合并 + 单次 save。
- hub 响应每个场景卡新增 `scene_key`、`agent_profile_id`（脱敏规则同 `_build_item`）；状态按解析后的绑定实例计算。
- hub 前端 `openKuAsk` 对场景卡写入 `agentKey` + `agentId`，`capabilityMode` 照带。

Out of scope:

- 新建场景模板（spec 201 及后续各 Tool spec 内登记，Y3=a）。
- `guide`、`recommend` 能力本身。
- 改 `/core/ai/chat/completions` 或 `guard_scene_agent_key` 的校验链。

### Acceptance Criteria

1. 场景卡 = `SCENE_TEMPLATES` 逐模板一项；`data_query` 不再出现在 `capabilities[]`；`ask` 卡行为不变。
2. 绑定解析：无条目→同 key 预置实例；`null`→解绑（`not_ready`，reason“已解绑场景”）；实例 key→覆盖。预置实例已软删且无覆盖 → `not_ready`（“预置场景已删除”，改绑可恢复）。
3. 已绑定时状态按以下顺序判定：模板总开关关 / 实例停用 / 未绑定档案 / 档案不存在 / 档案未启用 → `not_ready`；chat 未就绪 / 当前用户无使用权 → `partial`；档案 `enabled_tools` 不含任何 `kind=read` 且非 `search_knowledge` 的 Tool → `not_ready`（“绑定档案未勾选业务查询工具”；含 `kind=write` Tool 的档案不受此条限制）；否则 `ready`。
4. 移除 `_has_registered_scene_readonly_tool` 作为就绪依据。
5. 点击就绪卡：请求 context 含 `agent_id` 与 `extra.agent_key`，后端进入 `guard_scene_agent_key` → `assemble`，Tool 帧出现在流里。
6. 覆盖保存校验 instance_key 属本租户且未删除，否则 422。
7. hub 既有字段语义不变，场景卡新增 `scene_key`、`agent_profile_id`。

### Rules and Constraints

Tenant isolation:

- 绑定值只存本租户站点设置；保存与读取均按 tenant_id 校验实例归属。

Security and masking:

- 保存需 spec 185 既有设置写权限（`kuaiai:settings:update`）；`agent_profile_id` 仅在当前用户有使用权或 `kuaiai:agent:read` 时下发。
- 客户端传入的 `agentKey/agentId` 仍由服务端守卫全量复核。

Audit and lineage:

- 设置保存审计沿用 spec 185：记录变更字段名 `capability_bindings` 与新旧值（instance_key，非敏感）。

AI/rule-engine rules:

- 能力卡不改变档案提示词或 Tool；只决定点击走哪个档案。

Database rules:

- 无表结构变更、无迁移；`capability_bindings` 写入现有站点设置 JSON。

## 2. Plan

### Implementation Approach

- `integration_settings.py` 增加 `CAPABILITY_BINDINGS_SETTING_KEY`、`read_capability_bindings`、`validate_capability_bindings_payload`（key 限 `SCENE_TEMPLATES` key 集，值为字符串或 null），与 `agent_switches` 同风格；另加 `resolve_capability_binding(tenant_id, key)`：设置中有条目用条目值（含 null=解绑），无条目回退同 key 预置实例。
- `settings_service` GET 返回绑定、可选实例列表与各模板的解析结果（复用 `list_agent_library` 的实例行，不另查）；PUT 在既有事务内校验实例归属后深合并。
- `operations_service._build_capabilities` 改为按 `SCENE_TEMPLATES` 逐模板生成场景卡：读解析后的绑定实例，复用 `agent_scene_service._build_item` 的状态结果，再追加“业务 Tool”判定（读 spec 189 目录的 `kind`）。

### Affected Modules

- Modify: `core/utils/integration_settings.py`、`apps/kuaiai/services/settings_service.py`、`services/operations_service.py`、`schemas/operations.py`。
- Modify: 前端 `pages/hub/index.tsx`、`pages/settings/*`、`types/operations.ts`、`services/operations.ts`、`locales/zh-CN.ts`。
- Test: `tests/apps/kuaiai/test_spec191_hub_binding.py`；回归 spec 181/185 测试。

### Public Contracts

- `GET/PUT /api/v1/apps/kuaiai/operations/settings` 新增字段 `capability_bindings`（PUT 可选；缺省视为不修改）。
- `GET /api/v1/apps/kuaiai/operations/hub` 的 capability 项新增 `scene_key?`、`agent_profile_id?`；`capabilities[]` 由固定三卡改为 `ask` + 逐模板场景卡。

### Persistence Changes

- 站点设置 JSON 新键；无迁移。

### Transaction Boundaries

- PUT 沿用 spec 185：事务内锁站点行、比对版本、一次写入。

### Risks

- 前端设置页 PUT 若整包回传旧结构会丢新键：PUT 缺省 `capability_bindings` 表示不修改，测试覆盖。
- 依赖 spec 189 的 `kind` 字段；189 未完成时本单元不开工。

### Verification Strategy

- 状态矩阵单测（每个分支一例）+ 默认绑定/解绑/覆盖三态 + 越租户/已删实例保存 422 + PUT 缺键不改。
- 前端 build；浏览器点任一场景卡确认流中出现 `kuaiai_tool` 帧。
