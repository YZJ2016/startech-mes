### Business Goal

`POST /ai/knowledge/attach/{id}/parse` 对 PDF / Office / txt / md 抽出可读正文，按 Ingestor 四段切块写入 fragment 与现网向量库。不再把整文件当 UTF-8 字符串视为成功。

### Scope

In scope:

- `ktg-ai` 增加无 version：`langchain4j-document-parser-apache-pdfbox`、`langchain4j-document-parser-apache-poi`、`langchain4j-document-parser-apache-tika`；BOM 含 markdown 解析器则加，否则 md 走 Text
- 从 MinIO 流解析；按扩展名路由；冲突时 Tika 探测；空文本失败
- `DocumentTransformer` / `DocumentSplitters.recursive`（overlap>0）+ 知识库 `chunk_separator` / `chunk_size` / `chunk_overlap`（空则 `sys_config`） / `TextSegmentTransformer`
- 写 `ai_knowledge_fragment`（可选 Flyway `source_ref`）；向量元数据仍含 `tenant_id`、kid、docId、fid；写入的集群按当前 `TenantContext` 解析（93：DEDICATED 否则默认/env）
- Flyway **tenant**：`ai_knowledge` 增 `chunk_size` / `chunk_overlap`（int NULL，空=回落）。实体/Mapper/XML 同步；JSON camel `chunkSize` / `chunkOverlap`
- Flyway **master**：`sys_config` 全局种子 `ai.rag.chunk-size=500`、`ai.rag.chunk-overlap=200`、`ai.rag.chunk-separator=\n\n`、`ai.rag.top-k=5`、`ai.rag.min-score=0`（`tenant_id` NULL，对齐 `mes.index.layout`；无既有 `ai.*` 键）。91 的展开/再排序键可另脚本，前缀同 `ai.rag.`
- `AiKnowledgeChunker` / `parseAttach` ingest：切块参数 **知识库列 → `ISysConfigService.selectConfigByKey` → 与种子相同的硬编码**。拆除 `AiProperties` rag `@Value` 与 yml `ruoyi.ai.rag.*` / `AI_RAG_*`（向量集群 `@Value` **本单元不拆**；产品面改平台默认/专绑定 + 默认 env 回落见 **93 / PR-D20**）
- embedding 走 A24；支持则 `DOCUMENT` input type
- 单测：夹具 PDF 或 DOCX 抽出非乱码关键词；纯文本仍通过；空/损坏文件 `parse_status=2`；跨租户 objectKey 仍 403；**禁止**断言 Easy RAG

Out of scope:

- RetrievalAugmentor（91）
- 知识库管理页 Vue（92：embedding 下拉、chunkSize/overlap 表单、片段浏览、浏览器点选）
- 向量集群平台页与每厂绑定（**93**；禁止把 host/type 写进本单元或知识库表单）
- 把 RAG 默认写回 yml / 新 `@Value`；双源（yml + sys_config）
- OCR、加密 PDF 破解
- 换 `VectorStoreService` 实现、连 live 集群、改向量集群产品面（**93**）
- `langchain4j-easy-rag`、`InMemoryEmbeddingStore`

### Acceptance Criteria

- 允许类型主路径不是 `new String(bytes, UTF-8)`
- overlap>0 且 < chunk_size（现网夹取：overlap≥size → `size-1`）；分隔符仍优先于纯窗口
- 空列不读 yml：单测断言走 `sys_config`（或硬编码与种子相同的 500/200/`\n\n`）
- 无 embedding 模型 → 失败关闭，不标解析成功
- 第 4 节未跑通不得写「测试通过」
- 文档无真实主机/凭据

### Rules and Constraints

Tenant isolation:

- 读对象键前缀仍 `tenant/{id}/`
- fragment INSERT 填当前租户
- 向量写入走当前 `TenantContext` 解析的 store（有 DEDICATED 绑定用该厂客户端，否则平台默认）；禁止空上下文

Security and masking:

- parse_msg 短句；日志不打印存储凭据与绝对路径

Audit and lineage:

- `ai_knowledge` 新列只进 `db/migration/tenant/`；`sys_config` 种子只进 `db/migration/master/`（I8 全局表，不进专库）
- 不改已发布 `backend/sql/20260823_24*` / `20260825_29*`；不把密钥写入种子

AI/rule-engine rules:

- 切块用 LC4j DocumentSplitter，不把 `AiKnowledgeChunker` 当 PDF 主路径（纯文本可作 splitter 底层）；splitter 的 size/overlap/separator 解析规则与本单元 ingest 相同（列 → sys_config）

Database rules:

- include 已含三表则不扩匿名表

## 2. Plan

### Implementation Approach

1. POM 加 parser 坐标，无 version。
2. 解析器注册表：扩展名 → Parser；失败再 Tika 探测一次。
3. `parseAttach` 改为 InputStream → Document → ingest 四段 → 原 `storeVectors`。
4. 不改知识库 Vue 表单（92）。本单元负责列、Mapper、ingest 读路径与拆除 yml rag 键。

### Affected Modules

- `ktg-ai/pom.xml`、knowledge service / Mapper、`AiProperties` rag 字段拆除、Flyway tenant + master、`application.yml` 删除 `ruoyi.ai.rag.*`

### Public Contracts

- **冻结：** `POST /ai/knowledge/attach/{id}/parse`（URL / method / 认证不变）
- 知识库 POST/PUT 增量可选 `chunkSize` / `chunkOverlap`（camel）；不新 path。`embeddingModelId` 后端语义不变（空则第一条 vector）；下拉属 92

### Persistence Changes

- tenant：`ai_knowledge.chunk_size` / `chunk_overlap` int NULL；可选 `ai_knowledge_fragment.source_ref varchar(128)`
- master：`sys_config` 五键全局种子（见 Scope）。`config_type='Y'`、无主机/口令。不插默认厂 overlay

### Transaction Boundaries

- 先删旧 fragment 再插入；向量失败标 2 可重试（现网）

### Risks

- POI/PDFBox 版本与 Boot 4
- 大 xlsx 内存；可按现网 20MB 上限拒绝

### Verification Strategy

- `mvn -pl ktg-ai -am test`（Java 17）
- 不连 live MinIO/向量也可：mock ObjectStore + Fake VectorStore + classpath 夹具
