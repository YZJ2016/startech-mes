# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 站内信、WebSocket、附件、公告已读迁入 `ktg-mes`
- Module: `ktg-framework` / `ktg-system` / `ktg-admin` → `ktg-mes`
- Priority: P1
- Related requirement/design documents:
  - `docs/04.specs/00.backend-extract-program.md`
  - `backend/doc/设计文档/数据库设计/mes_sys.sql`（`sys_attachment`、`sys_message`）
  - 调查：新若依有 `SysNoticeRead`，与 MES 的 `SysNoticeDetail` 平行，不能直接当同一实现替换

### Business Goal

车间消息推送、单据附件、公告已读状态在换壳替换 system/framework 后仍然可用。平台模块不再承载这套 MES 协作能力。

### Scope

In scope:

- WebSocket：`WebSocketConfig`、`WebSocketServer`、`WebSocketUsers`、`SemaphoreUtils`
- 消息：`MessageProvider`、`SysMessage` 领域/Mapper/Service/XML、`SysMessageController`（`/system/message`）、`SysMessageMobController`（`/mobile/system/message`）
- 附件：`SysAttachment` 全套与 `SysAttachmentController`（`/system/attachment`）
- 公告已读：`SysNoticeDetail` 全套与 `SysNoticeDetailController`（`/system/notice/detail`）
- **回退**对共享 `SysNoticeMapper.xml` 的 left join 改动：join 逻辑随 Detail 迁走后，平台 `SysNoticeMapper.xml` 应回到可被若依替换的形态；已读查询改走 mes 侧查询
- 补 `sys_notice_detail` 增量建表脚本（仓库内无 CREATE）
- HTTP 路径保持不变

Out of scope:

- 与若依 3.9.2 `SysNoticeRead` 做数据迁移合并（可列为后续换壳单元）
- 移动登录（`06`）
- 改 WebSocket 协议格式

### Acceptance Criteria

- 上述类与 XML 仅存在于 `ktg-mes`
- `/system/message`、`/mobile/system/message`、`/system/attachment`、`/system/notice/detail` 路径与方法不变
- `MessageProvider.sendMessage` 仍写 `sys_message` 并推送给在线用户（现有 `WebSocketUsers.sendMesssageToUserByName` 行为）
- 新增可审查的 `sys_notice_detail` 增量 SQL；不改 `mes_sys.sql` 原文
- 平台 `SysNoticeMapper.xml` 不再依赖 `sys_notice_detail`
- compile 通过

### Rules and Constraints

Tenant isolation:

- 消息按现有 `recipient_id` 投递，不新增租户过滤

Security and masking:

- 消息内容可能含业务信息，日志只记 id，不把 `message_content` 打到 info
- `/websocket/**` 鉴权调整留给 `08`；本单元不扩大匿名面

Audit and lineage:

- 附件行继续关联 `source_doc_id` / `source_doc_type`
- `mes_sys.sql` 中 `drop table if exists sys_messsage` 拼写错误不在原文修复；若需纠正，写在增量脚本注释中说明

AI/rule-engine rules:

- 不涉及

Database rules:

- 使用已有 `sys_attachment`、`sys_message`
- `sys_notice_detail`：从现网 `SHOW CREATE TABLE` 或实体/Mapper 字段生成增量脚本，字段至少覆盖 Mapper 中的 `id, notice_id, user_id, create_by, create_time, update_by, update_time, remark`
- 禁止把已读数据迁到若依 `SysNoticeRead` 除非另开单元并做对照

## 2. Plan

### Implementation Approach

1. 在 `ktg-mes` 建 `msg` / `notify` / `file` 子包（具体包名实施时统一，避免拆过碎）
2. 先补 `sys_notice_detail` 脚本并在有库的环境核对
3. 迁 WebSocket + MessageProvider + 消息全套
4. 迁附件全套
5. 迁 NoticeDetail；改写公告列表查询，去掉对平台 `SysNoticeMapper.xml` 的侵入
6. 删除 platform 旧文件

### Affected Modules

- `ktg-mes`：接收实现与 Controller
- `ktg-framework`：删除 websocket 包与 `MessageProvider`
- `ktg-system`：删除 Message/Attachment/NoticeDetail 的 domain/mapper/service/xml；还原 `SysNoticeMapper.xml`
- `ktg-admin`：删除对应 Controller

### Public Contracts

- `GET/POST /system/message` 及现有 export/id 路径
- `GET /mobile/system/message/getMyMessage`
- `/system/attachment` 现有 list/export/id/post
- `/system/notice/detail` 现有 message/list/export/id/post
- WebSocket 端点路径保持现有 `WebSocketConfig` 注册值（实施时从源码抄入 PR，不在此臆造）

### Persistence Changes

- 新文件：`backend/sql/` 下增量脚本 `sys_notice_detail`（文件名带日期或序号，可回滚）
- `sys_message` / `sys_attachment` 无结构变更
- Mapper namespace 随包名更新

### Transaction Boundaries

- `MessageProvider.sendMessage` 现为 `@Transactional`：保持「写库 + 推送」在同一方法；推送失败策略不在本单元放大（不新增补偿框架）

### Risks

- 还原 `SysNoticeMapper.xml` 后管理端公告列表丢失已读标记，必须在 mes 查询补上
- 无 `sys_notice_detail` 脚本导致新环境无法建表
- WebSocket 与 Spring Security 的握手顺序在迁包后扫描不到

### Verification Strategy

- 类名检索仅 `ktg-mes`
- 对比迁前后 `SysNoticeMapper.xml`
- Maven compile
- 有环境时：发一条站内信、传一个附件、点一条公告已读（不强制无环境）
