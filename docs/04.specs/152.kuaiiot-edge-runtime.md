### Business Goal

已入库的 Modbus TCP Agent 能向云侧拉取边缘配置、上报心跳，并在断网后把缓冲批量续传进 150 的同一条入站。OPC UA 与 S7 只在保存配置时做字段校验，没有对应的可执行采集程序。

### Scope

In scope:

- 边缘配置用已有表 `apps_kuaiiot_edge_configs`（迁移 `521_20260807140000_kuaiiot_wave2_tables.py` 建表，`protocol` 默认 `modbus_tcp`，`config` 为 JSONB）。运行时列在迁移 `522_20260807160000_kuaiiot_wave4_edge_runtime.py`：`config_version`、`last_agent_heartbeat_at`、`agent_version`、`agent_status`（默认 `unknown`）、`buffer_pending_count`。云侧下发、心跳和续传是本切片要补的服务，这些列还没有写入代码。
- 配置下发对齐 Agent 已经在调用的路径：`GET /api/v1/apps/kuaiiot/edge-runtime/{device_token}/config/{edge_config_code}`（`edge-agent/agent.py` 的 `pull_runtime_config`）。响应至少含 `config_version`、`protocol`、`config`、`ingest_path`、`batch_ingest_path`、`heartbeat_path`。鉴权凭据只放在路径上做服务端校验，响应体不回显凭据。`command_result_path` 与 `pending_commands` 留给 154，本切片的心跳响应不带指令。
- 心跳对齐 Agent 已经在 POST 的字段：`edge_config_code`、`config_version`、`agent_version`、`buffer_pending_count`、`status`。云侧更新 522 的心跳列。`config_version` 与云侧不一致时响应 `config_changed=true`。Agent 已有这个判断，本切片不改 `agent.py`。
- 离线判定沿用 `EDGE-AGENT-RUNTIME.md`：超过 5 分钟无入站则把 `apps_kuaiiot_devices.is_online` 写成假；Agent 3 分钟无心跳则 `agent_status=offline`。`taskiq_app.py` 已 import `apps.kuaiiot.workflows.functions.device_lifecycle_workflow.run_kuaiiot_offline_check` 与 `apps.kuaiiot.workflows.functions.edge_agent_lifecycle_workflow.run_kuaiiot_edge_agent_offline_check`。函数必须落在这两个已有 import 上，不新注册 cron。离线告警行（`rule_type=offline`）不在本切片写，留给 153。
- 批量续传对齐 Agent 的 `ingest_batch`：`POST` 到配置里给出的 `batch_ingest_path`。路线图与运行时说明写的是 `POST /api/v1/apps/kuaiiot/ingest/{device_token}/batch`，单批最多 100 条。每条必须调用 150 与 151 已收口的同一条入站：幂等（`ingest_dedup`）、快照、5 秒写回、护栏、阈值告警。禁止另写一条只插入监控、绕过 151 的路径。超过 100 条拒绝整批。Agent 本地缓冲表 `pending_ingest` 已在 `agent.py`，本切片不改那段缓冲。
- OPC UA / S7 只做配置校验。`protocol` 允许运行时说明已列的 `modbus_tcp`、`modbus_rtu`、`opc_ua`、`s7`。校验字段：Modbus 为 `host`、`port`、`unit_id`、`registers[]`（`tag_key`、`address`、`data_type`，`data_type` 仅为 `int16`、`uint16`、`int32`、`uint32`、`float32`、`bool`）；OPC UA 为 `endpoint`、`nodes[]`；S7 为 `host`、`rack`、`slot`、`db_blocks[]`。运行时说明还写了 `publish.mode` 为 `http_ingest` 或 `mqtt`。本切片可保存该字段，但只执行 `http_ingest` 这条入站；不订阅 MQTT，不内置 Broker。校验通过只表示配置可保存，不表示有采集程序。
- 可执行采集仍只是仓内 Agent 的 Modbus TCP。`agent.py` 在 `protocol != modbus_tcp` 时已经直接报错。本切片不给它补 OPC UA 或 S7 驱动，也不把 `modbus_rtu` 做成可运行采集。

Out of scope:

- 不在本切片重做 150 的槽位收归与单条入站，也不重做 151 的护栏、模板、阈值、预填。批量续传只调用这两段已收口的同一条入站
- 产品物模型、Influx 趋势、离线告警记录（153）
- 心跳响应里的 `pending_commands`、`command_result_path`、指令回执（154）。Agent 已能读这些字段，但云侧在本切片不返回指令
- 报表馈送与 OEE（155）
- MQTT 订阅、ThingsBoard、JetLinks；内置 MQTT Broker
- 已调度但不在六步交付里的 `kuaiiot_mqtt_reload_tick`、`kuaiiot_telemetry_pull_tick`（ThingsBoard/JetLinks）、`kuaiiot_connection_health_tick`：cron 已在 `taskiq_app.py`，本六步不实现、不新造第二套、不重复注册
- 改 `edge-agent/agent.py`、`config.yaml` 或模拟从站
- 改迁移 521、522 的文件名
- 改 `startech-mes-basic`

### Acceptance Criteria

1. 凭据与 `edge_config_code` 命中本租户一条启用配置时，上述 GET 返回 `config_version`、`protocol`、`config` 和三条路径。凭据错误不返回配置。
2. 心跳写入 `last_agent_heartbeat_at`、`agent_version`、`agent_status`、`buffer_pending_count`。版本不一致时 `config_changed` 为真。响应里没有 `pending_commands`。
3. 超过 5 分钟无入站则把设备 `is_online` 写成假。超过 3 分钟无心跳的配置 `agent_status` 为 `offline`。这两种结果都不自动插入 `alerts`。
4. 一批 1 到 100 条调用 150 与 151 已收口的同一条入站（幂等、快照、5 秒写回、护栏、阈值告警）。第 101 条使整批被拒绝。重复 `idempotency_key` 不倍增快照。只插入监控、绕过 151 的路径不算通过。
5. `opc_ua`、`s7` 配置缺运行时说明里的必填字段时不能保存。保存成功后，仓内 Agent 仍只在 `protocol=modbus_tcp` 时轮询；本切片没有新增 OPC UA / S7 采集代码。
6. `publish.mode` 为 `http_ingest` 或 `mqtt` 都可以保存。`mqtt` 时本切片不建立订阅、不连接 Broker，只执行 `http_ingest`。无租户上下文不读 `edge_configs`。

### Rules and Constraints

Tenant isolation:

- 配置与心跳都落在凭据命中的设备租户上。不能用一台设备的凭据拉取另一租户的 `edge_config_code`。

Security and masking:

- 路径中的鉴权凭据不写入日志。配置 JSON 不存放 Broker 口令。

Audit and lineage:

- 心跳只更新 522 已有列。不新造边缘运行时表。

AI/rule-engine rules:

- 不涉及。

Database rules:

- 只用 521 的 `edge_configs` 与 522 的列。不改这两份迁移的文件名。
- 批量续传不绕过 `apps_kuaiiot_ingest_dedup`，也不绕过 151 的护栏与阈值告警。

### 依赖顺序

- 依赖 150 的单条入站、幂等、快照和 5 秒写回，以及 151 已收口的写回前护栏与阈值告警。批量续传必须走这一条入站。
- 不依赖 153–155。
- 不改 145–149。

## 2. Plan

### Implementation Approach

1. 云侧实现 Agent 已经调用的配置 GET、心跳 POST、批量 POST。不改 Agent 源码。
2. 保存配置时按协议校验 JSON。只有 `modbus_tcp` 被现有 Agent 执行。
3. 离线与心跳超时只实现上述两个已有 import 上的函数，不另注册 cron。不在这里写 `alerts`。

### Affected Modules

- 新建于 `riveredge-backend/src/apps/kuaiiot/` 的云侧边缘服务（本切片之前不存在；`tests/apps/kuaiiot/test_wave4_edge_runtime.py` 引用的 `EdgeConfigService` 不是实现）
- 只读、不改：`riveredge-backend/src/apps/kuaiiot/edge-agent/agent.py`
- 前端槽位内补边缘配置编辑，校验失败时展示缺哪个字段

### Public Contracts

- 本切片要补、且 Agent 已按此调用：配置 GET、心跳 POST、批量入站 POST。仓内没有云侧路由。
- 批量每条调用 150 与 151 已收口的同一条入站（幂等、快照、5 秒写回、护栏、阈值告警）。

### Persistence Changes

- 无新表。更新 `edge_configs` 的 522 列，以及 150 已规定的快照、幂等和监控行。
- 不更新 `tag_history`。

### Transaction Boundaries

- 一批中每条沿用 150 的幂等。整批超过 100 条时一条都不写入。心跳更新与入站写回分开。

### Risks

- 本切片若在心跳里返回 `pending_commands`，就把 154 的指令提前做了。
- 只校验 OPC UA / S7 字段却去改 Agent，会把「配置校验」做成可执行采集。

### Verification Strategy

- 见 §3。§4 在命令实跑后填写。本文件写下时未跑测试。
