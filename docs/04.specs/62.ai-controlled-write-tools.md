### Business Goal

在已落地的 Agent（`POST /ai/agent/send`）上挂**列死**的第一批受控写 Tools：模型只能调用现有 MES service 做报工登记与工单状态更新，并带当前 JWT / `TenantContext` / 原权限字。工厂用户仍走既有 Agent 口，不新开聊天信封。禁止模型直连业务库或执行任意 SQL。

Goal：第一批写操作可被 Agent 调用；无权限 / 跨租户 / 空上下文失败关闭且不落库。

### Scope

In scope:

- 第一批 Tool **列死为下列两项**，本单元不得再加第三条（含「执行报工」Controller 大事务、删工单、任意 Mapper）：
  1. **登记报工** `submitProductionFeedback`：只调现网 `com.ktg.mes.pro.service.IProFeedbackService.insertProFeedback`。参数白名单：`workorderId`、工作站或任务 id（对照现网 `ProFeedback` 必填最小集）、`quantityFeedback`。禁止把整个实体当自由 JSON。
  2. **更新工单状态** `updateWorkorderStatus`：只调现网 `com.ktg.mes.pro.service.IProWorkorderService.updateProWorkorder`，且**只改既有状态字段**为该业务已允许的取值。禁止删工单、禁止改数量/BOM/工艺。
- Tools 为进程级 `@Tool` 单例（对齐 A25）；**调用时**读 `TenantContext` / `LoginUser`，禁止构造期写死租户。工单 / 报工主键必须再查本租户，跨租户 404/403 且不调 service。
- 写前显式校验原权限字（即使现网 Controller 上 `@PreAuthorize` 被注释）：报工 `mes:pro:feedback:add`；工单状态 `mes:pro:workorder:edit`。无权限与 HTTP 层 403 同等，不得因「是 Tool」绕过。
- 每个 Tool 只用该业务既有短事务，**不**包住整个 Agent / SSE 循环。并行 Tool 线程拷贝 `TenantContext`（I-A4）。
- 若 `ktg-ai` 尚无 `ktg-mes` 依赖：允许 `ktg-ai/pom.xml` 增加 `com.ktg:ktg-mes`（**不写 version**，走父聚合）。禁止 `ktg-mes` 反向依赖 `ktg-ai`。禁止在 `ktg-ai` 新建 MES Mapper / XML / JDBC。
- 挂到现网 `MesAiAssistant`（或同等 AiService）与只读 `TenantKnowledgeSearchTool` 并列。仍走 `POST /ai/agent/send`。
- 单测：Mock MES service；空上下文 / 跨租户 / 无权限 **不得**调用 insert/update；禁止打真实公网模型、禁止连 live 库做写。

Out of scope:

- MCP、`langchain4j-mcp`、工作流 HTTP、Vue3 / Vue2（见 63 / 64 / 65）
- JDBC、`execute_sql_query`、`query_all_tables`、任意 Mapper、把 `DataSource` 交给模型
- 把 `ProFeedbackController.execute`（现网执行报工大事务在 Controller）原样搬进 Tool；本单元不做「执行报工」第三条
- 改 `POST /ai/chat/send` 或 `POST /ai/agent/send` 的 path、method、body、SSE `{content, done}` 信封
- 把 `/ai/**` 写入 `MesPermitAllProvider` / `MesPermitAllProviderImpl`（现网匿名列表无 `/ai`，保持）
- Milvus / Qdrant 适配、官方 EmbeddingStore、live 向量 / live 模型环境
- 短剧、Coding Harness、匿名 `/workflow/run`、内置 SQL MCP（A22）
- 独立 Agent 管理端页（设计 §7：无独立 Agent 页）
- Sa-Token、MyBatis-Plus、第二套 `SecurityFilterChain`、真实主机 / 凭据 / Token

Non-goals:

- 不开放「任意写 / 任意表」配置项
- 不引入 MCP 坐标或 A2A / agentic 全家桶
- 不把 63–65 的范围提前做完
- 不为 Tool 新造一套 MES 业务规则

### Acceptance Criteria

- 进程内仅上述两个受控写 `@Tool` + 61 已有只读知识 Tool；无 SQL Tool、无 MCP 依赖
- 无 JWT / 无 `TenantContext`：不调 MES service、不写业务行
- 他租户 `workorderId` / 报工关联 id：404/403，不调 service
- 缺 `mes:pro:feedback:add` 或 `mes:pro:workorder:edit`：拒绝写
- `POST /ai/chat/send` 与 `POST /ai/agent/send` 信封与 61/58 冻结一致；`MesPermitAllProviderImpl` 仍无 `/ai`
- 审计能追到用户、租户、Tool 名、业务主键；日志 / SSE / 异常不打印 apiKey、cipher、JDBC
- 第 4 节未编码前不得写「测试通过」；文档无真实地址/凭据

### Rules and Constraints

Tenant isolation:

- 只信 JWT / `TenantContext`；禁止请求体或 Tool 参数传 `tenantId`
- 工单、报工、知识库 id 必须再查本租户，跨租户不调上游、不跑 Tool
- `DATABASE` 专库：写的是当前租户数据源上的 MES 表，禁止跨源

Security and masking:

- `/ai/**` 必须登录；Agent 口不进 `MesPermitAllProvider`
- 写操作不得绕过原权限字
- 日志、SSE、异常不打印 apiKey、MCP token、cipher、JDBC 连接串

Audit and lineage:

- 受控写须能追到用户、租户、Tool 名、业务主键；审计不记密钥
- 无本单元新表亦可；若加审计表必须 `tenant_id` + include + 专库 catalog + 新增量 SQL（不改历史脚本）

AI/rule-engine rules:

- A7：禁止直连库与任意 SQL。所谓「SQL 工具」= 白名单 service 调用，不是 JDBC
- 不引入 `langchain4j-mcp`（A27 留给 63）
- 不削弱纯对话 `POST /ai/chat/send`（无 Tool）

Database rules:

- 不把向量 blob 或密钥写入 MES 业务行
- 根键仍 `ruoyi:`；yml 不新增租户模型清单或全局 `chat-model.api-key`

## 2. Plan

### Implementation Approach

1. 确认 `ktg-ai` → `ktg-mes` 单向依赖（若尚未有）；禁止循环依赖。
2. 新增两个 `@Component` `@Tool` 类（名随风格），内部只调 `IProFeedbackService` / `IProWorkorderService`。
3. 每个 Tool：空上下文抛既有租户异常；`select*ById` 校验租户后再写；`SecurityUtils.hasPermi`（或项目同等）校验权限字。
4. 注册进现网 AiService / `MesAiAssistant` tools 列表；只读知识 Tool 保留。
5. 单测 Mock service；不跑 live MES 写、不跑 live 模型。

### Affected Modules

- `startech-mes-basic/backend/ktg-ai`（Tool 类、AiService 装配、测试）
- `startech-mes-basic/backend/ktg-ai/pom.xml`（仅当需要 `ktg-mes`）
- 不改：`AiChatController` / `AiAgentController` 映射与请求 DTO、`MesPermitAllProviderImpl`、`startech-mes-front/`、`frontend/`、父 BOM、向量适配器

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- **冻结不变：** `POST /ai/chat/send` body `{sessionId?, modelId, content}`（既有可选 `knowledgeId`）；SSE `data:` JSON `{content, done}`
- **冻结不变：** `POST /ai/agent/send` body `{sessionId?, modelId, content}`；SSE `{content, done}`（可选 `reasoning`）；权限 `ai:chat:send`；须 JWT
- **本单元不新增 HTTP。** 受控写仅经 Agent Tool 调用
- 禁止 `/system/message`、禁止无前缀 `/chat/send`、禁止匿名 `/workflow/run`

### Persistence Changes

Tables, indexes, migrations, mapper XML, and lifecycle rules:

- 默认无新表、无增量 SQL。写路径走现网 `pro_feedback` / `pro_workorder`（名以现网为准）及既有 Mapper
- 不改历史 `ry_*.sql` / `mes-*.sql`

### Transaction Boundaries

- 单次 Tool = 该 service 方法的既有短事务
- 禁止用一个事务包住整个 Agent 循环或多步 Tool
- 与 58/61 相同：user 消息先提交；assistant 另事务；流失败不回滚 user 行

### Risks

- 把方案 B 理解成「模型可以跑 SQL」或开放任意 Mapper
- Tool 捕获构造期 `tenantId`，或 SSE 线程丢上下文后写串租
- 因「是 AI」跳过 `mes:pro:*` 权限字
- 把 MCP / 工作流 / Vue / 执行报工大事务一并塞进本单元
- `ktg-mes` ↔ `ktg-ai` 循环依赖
- 改 `send` 信封导致 Vue3 对话页回归

- JDK 17：`cd startech-mes-basic/backend && mvn -pl ktg-ai -am test`（实现后填写第 4 节）
- 静态：`ktg-ai/pom.xml` 无 `langchain4j-mcp`；`MesPermitAllProviderImpl` 无 `/ai`
- 单测：Mock 两租户；无权限不写；空上下文不写
- 本单元不跑 Vue `build:prod`、不连 live 模型 / 向量 / 现场 JWT
