# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 阶段 2a 用 springboot3 内容替换六个平台模块（仍 `ktg-*` / `com.ktg`）
- Module: `ktg-common` → `ktg-framework` → `ktg-system` → `ktg-quartz` → `ktg-generator` → `ktg-admin`
- Priority: P0
- Related requirement/design documents:
  - `docs/04.specs/19.backend-shell-swap-phase2-program.md`
  - `docs/04.specs/20.phase2-toolchain-jdk17-jakarta.md`（须先完成父 POM）
  - 阶段 1 同模块接线：`14`–`17`（**装回**已有接线，不是重新抽出）
  - 五项勾选单元：`23`（本块覆盖时就要装回，`23` 再全表勾）

### Business Goal

把若依 `origin/springboot3` 的 `ruoyi-*` **内容**换入对应 `ktg-*`，得到 Java 17 / Boot 3.5.16 / jakarta 的平台层，同时模块名、包名、MES 721 文件路径不变。每覆盖一块，把阶段 1 已经存在的接线立刻拷回，避免窗口期内丢掉 PermitAll / 手机号 / notice / Minio。

### Scope

In scope:

- 对照根：`RuoYi-Vue-springboot3/`，HEAD 必须是 `9e3fb55f46d9998c6cecefd04fcf55c5d17158af`
- 一次一块覆盖 `src/` + 该模块 pom 依赖（机械规则见 `19`）
- 顺序固定为下表（与阶段 1 的 quartz 优先不同：Boot 3 必须先有 jakarta 的 common）
- 覆盖后 **装回** 阶段 1 已有、会被冲掉的文件/片段（见模块表「须留下」）
- `ktg-admin`：保留 `ktg-mes` 依赖、现有 antrun、`@EnableAsync` / `@EnableScheduling`、`static/` 不整目录清空；yml 只对键；端口保持 `8085`
- 每块用 JDK 17 编译 **本模块 `-am`（尽量不含把 mes 当失败主因）** 后再下一块；admin 依赖 mes，本单元允许 admin 全量 `-am` 因 mes 仍 javax 而失败，失败交给 `22`

Out of scope:

- 改 `ktg-mes` 的 721 个业务 Java（`22`）
- 在本单元「发明」新的匿名路径或新 JWT
- Boot 4.1 / `24` 的 Jackson `tools.jackson`、`spring-boot-starter-webmvc`、`DataSourceAutoConfiguration` 新包名
- 模块/包名改 ruoyi（`25`）
- 前端 Vue3、改 `frontend/`
- 把阶段 1 未完成项（若 `18` 未收口）在这里补做抽出

### Acceptance Criteria

- 六模块源码来自上述 springboot3 commit 的对应 `ruoyi-*`，包名为 `com.ktg.*`，`artifactId` 仍 `ktg-*`
- `rg "com\\.ruoyi" backend/ktg-{common,framework,system,quartz,generator,admin}` 为 0（admin 的 yml 值里若误拷对照注释也不要出现 `com.ruoyi` 作为 logging 包名）
- `rg "javax\\.servlet" backend/ktg-{common,framework,system,quartz,generator,admin}/src` 为 0
- 阶段 1 接线在覆盖后仍在（细节见模块表）；`23` 再勾五项
- common→generator 各块 JDK 17 `compiler:compile` SUCCESS 后再下一块
- admin 若因 mes 失败：第 4 节写明失败模块是 `ktg-mes`，不得勾「2a 完成」
- 未整文件覆盖带密钥的 yml

### Rules and Constraints

Tenant isolation:

- 不借换壳改数据权限

Security and masking:

- yml 只对键、不对密钥；禁止用对照 `application.yml` 覆盖 nested 密钥
- framework 禁止把 MES 路径写回 `SecurityConfig` 字面量

Audit and lineage:

- `selectUserByMobile` SQL 从 **覆盖前 nested** 拷回，不要发明新查询
- 不要把 mes 已读接回 `SysNotice`

AI/rule-engine rules:

- 不涉及

Database rules:

- 不执行对照 `sql/`；不改 MES 表

## 2. Plan

### Implementation Approach

每块共同步骤：

1. nested toplevel = `startech-mes-basic`；对照 HEAD 锁定；`git status` 清洁或已知
2. 覆盖对照 `ruoyi-<mod>/src` → `ktg-<mod>/src`
3. 按对照模块 pom 更新依赖，GAV 留在 ktg 坐标系
4. 全模块 `com.ruoyi` → `com.ktg`
5. 执行该块「须留下」（从覆盖前工作区或 git 拷回，不要手写一套新实现）
6. JDK 17 编译后再下一块

若编译失败是引用了尚未换入的下一模块类型：**停止**，不要把后续模块文件偷拷进本块。

#### 模块顺序（一次一块）

| 顺序 | 模块 | 对照目录 | 本块必须留下/装回 | 本块不要做 |
| ---- | ---- | -------- | ----------------- | ---------- |
| 1 | `ktg-common` | `ruoyi-common` | **`MesPermitAllProvider.java`**（接口正文与阶段 1 一致）。`RuoYiConfig` 前缀保持 `ruoyi`（对照已是 ruoyi，不要改回 `ktg-mes`）。mes 若仍 fastjson1：只保证 pom 能解析，不改 721 文件 | 不改 SecurityConfig；不改 mes Java |
| 2 | `ktg-framework` | `ruoyi-framework` | 对照 `SecurityConfig` 已是 Security 6 `requestMatchers`。装回 `@Autowired(required = false) MesPermitAllProvider`，在 `authorizeHttpRequests` 里对列表 `requestMatchers(url).permitAll()`。`UserDetailsServiceImpl` 以对照为底，并入阶段 1 的 `REGEX_MOBILE` / `selectUserByMobile` 分支。无第二套 JWT 过滤器 | 不把 `/mes/`、`ureport`、`autocode`、`loginOuth`、`/mobile/` 写成字面量；不改 `MesPermitAllProviderImpl` 路径表 |
| 3 | `ktg-system` | `ruoyi-system` | 拷回 `selectUserByMobile` 全链（Service/Mapper/XML）。公告：保留 mes 列表所需的 `userId` 过滤/`userName` 展示能力（阶段 1 `15` 已定义）。允许对照 `SysNoticeRead*` 进入；**禁止**与 mes 已读合并 | 不删 mes `SysNoticeListController`；不改已读表结构 |
| 4 | `ktg-quartz` | `ruoyi-quartz` | 无五项。整模块覆盖 + 包名 | 不改 `sys_job` 表 |
| 5 | `ktg-generator` | `ruoyi-generator` | vm 模板里 `com.ruoyi` 一并替换为 `com.ktg` | 不改 Vue2、不接 Vue3、不真跑生成覆盖业务 |
| 6 | `ktg-admin` | `ruoyi-admin` | 依赖 `ktg-mes`；保留 antrun；启动类在对照 `@SpringBootApplication(exclude={DataSourceAutoConfiguration})` 之上加 `@EnableAsync` `@EnableScheduling`。**2a 的 exclude 包名跟 springboot3**：`org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration`（**不是** Boot 4 的 `jdbc.autoconfigure`）。删除换入的 `GET /system/notice/list`；不在 `CommonController` 增加 `uploadMinio`。yml 根键保持 `ruoyi:`，只补缺键、保留现值，端口 `8085`。`SwaggerConfig` 跟对照改为 SpringDoc/OpenAPI 3 | 不覆盖 `static/`；不抄密钥；不在本块修完 mes jakarta（`22`） |

`ApplicationConfig` 的 `@MapperScan("com.ruoyi.**.mapper")` 机械替换后应为 `com.ktg.**.mapper`（覆盖 mes mapper）。不要改成只扫 `com.ktg.system`。

对照 springboot3 文档 UI：`springdoc-openapi-starter-webmvc-ui` 2.9.0；`SecurityConfig` 放行 `/swagger-ui.html`、`/v3/api-docs/**`、`/swagger-ui/**`、`/druid/**`。`ResourcesConfig` 里若仍写 `springfox-swagger-ui` 资源路径，**以对照文件为准复制**，不要自行「修」成未验证路径。

### Affected Modules

- 改：六个 `ktg-*` 平台模块 + 根 POM 若 `20` 有漏项可补（仍禁止 Boot 4）
- 不改：`ktg-mes` 业务 src（pom 仅当平台依赖传递断裂且属于 fastjson1 这类阶段 1 已允许的例外）

### Public Contracts

- URL / method / `code/msg/data` / `Authorization` 不变
- 匿名集合仍由 mes provider 提供

### Persistence Changes

- 无新表。不把上游 sql 打进现网

### Transaction Boundaries

- 各模块原有服务事务；本单元不扩大

### Risks

- 用 `master` 树覆盖，把 Boot 4 文件带进 2a（尤其 `RuoYiApplication` 的 DataSource 包、`jackson-databind` groupId）
- 先换 admin 再换 common，jakarta 类型找不到
- 覆盖后忘记装回 Provider / 手机号 / 删 `/list`
- vm 模板残留 `com.ruoyi`
- 把 mes 编译失败当成平台换入失败而回滚错误模块

### Verification Strategy

每块命令模板（PowerShell）：

```text
# JAVA_HOME=JDK 17
mvn -pl ktg-<mod> -am compiler:compile "-DskipTests" "-Dmaven.antrun.skip=true"
```

admin 额外允许再跑 `mvn -pl ktg-admin -am compiler:compile ...`；若失败在 `ktg-mes`，进入 `22`，不要改对照 hash。
