### Business Goal

任意已登录业务页按 F1（或点顶栏「助手 (F1)」）打开右侧/右下抽屉，带着当前页/当前单标签，用**现有**会话与 completions 说话。无 `ai:chat:list` 不拦截 F1。

### Scope

In scope:

- `startech-mes-front/src/layout/components/Navbar.vue`：有 `ai:chat:list` 且 `device !== 'mobile'` 时显示助手入口，`el-tooltip` 为 **「助手 (F1)」**
- 已登录壳（Navbar 或 `src/layout/index.vue`）`keydown`：仅 `F1`（输入框内也拦）；有 `ai:chat:list` 才 `preventDefault` 并 **toggle** 抽屉。登录页 / `/lock` 不监听
- Pinia `src/store/modules/aiContext.js`（名可微调）：`set` / `clear`；形状见设计 09 `MesAiContext`
- 工单列表 `src/views/mes/pro/workorder/index.vue`：`onMounted` 写入 `screen` + `screenLabel`；打开同页查看对话框时补 `resourceKey=mes.pro.workorder`、`recordId`、`recordLabel`；**关闭查看后清单据三字段**；`onUnmounted` `clear`
- 右侧 `el-drawer` `rtl`（约 400–480）：标题旁展示当前标签；**第一次打开再挂载**聊天面板；须有「打开对话页」链到 `/ai/chat`
- 抽屉面板：复用 `src/api/ai/chat.js` `sendChatStream`、`src/api/ai/agent.js` `sendAgentStream`、`src/api/ai/session.js`；未选档案 → `POST /ai/chat/send`，选中档案 → `POST /ai/agent/send`；body 附带当前 `context`（可空）。**不改**全宽 `views/ai/chat/index.vue` 发送体
- `AiChatSendRequest` 增加可选 `context`；`AiChatServiceImpl` / `AiAgentServiceImpl`（或二者已抽的公共 prepare）在有标签时追加 system 句：「用户正在 {screenLabel}，单据 {recordLabel}」
- 无 `context` 或标签皆空：与现网完全一致

Out of scope:

- 按 `resourceKey+recordId` 拉 MES 摘要（**85 / S-D9**）
- 工作台 `dispatchEvent`、改 `FactoryHome` 点击（**85 / S-D10**）
- 给 HeaderSearch 绑 `/`（**85 / S-D11**；本单元只保证 F1 不抢 `/`）
- 写库 Agent、`confirmToken`、SQL / JDBC、新 `/ai/**` path
- 改 Vue2；扫全站业务页写 context；把全宽 `/ai/chat` 删掉或改路由
- 改 `MesPermitAllProvider`；引入第二套认证；提交 lockfile；升级 Vue / Vite / Element Plus

### Acceptance Criteria

- 有 `ai:chat:list`：任意已登录壳内页按 F1（含输入框内），浏览器帮助页不出现，抽屉打开；再按关闭（toggle）；Esc / 抽屉关闭钮亦可关
- 无 `ai:chat:list`：F1 **不** `preventDefault`；顶栏无助手图标
- 宽度 &lt;992（`device === 'mobile'`）：顶栏无助手图标；有权限时实体键盘 F1 仍 toggle
- Tooltip 文案精确为 `助手 (F1)`
- 首次打开网络面板才出现抽屉内聊天组件的会话/模型请求；未打开过抽屉不预挂载
- 工单列表挂载后抽屉标题含「生产工单」（或同等 `screenLabel`）；打开查看后含该单 `workorderCode`；**关闭查看后标题不再含 workorderCode**；离开工单页 store 清空
- 抽屉内有「打开对话页」链到 `/ai/chat`
- 抽屉发送：`POST /ai/chat/send` 或 `/ai/agent/send` 的 JSON **可**含 `context`，且仍含现网 `modelId` / `content` / 可选 `sessionId` / `knowledgeId` / `agentId`
- 全宽 `/ai/chat` **不传** `context`；不传的旧调用行为与现网一致；单测覆盖「无 context 不改 system」
- `event.key === '/'` 不会打开本抽屉
- `MesPermitAllProvider` 仍无 `/ai/**`；文档与代码无密钥
- `cd startech-mes-basic/startech-mes-front && npm run build:prod` 成功（有前端改动时实跑）
- `cd startech-mes-basic/backend && mvn -pl ktg-ai -am test`（或至少 `compiler:compile`）实跑后写入第 4 节

### Rules and Constraints

Tenant isolation:

- `context` 禁止 `tenantId`；跨租户只靠既有 session/model 校验
- 本单元不读 MES 业务表

Security and masking:

- 拦截 F1 用 **`ai:chat:list`**（与 `FactoryHome.showAi` 同一字）；发送用 **`ai:chat:send`**
- 现网没有 `ai:chat` 这一档，禁止按该字符串鉴权
- `/ai/**` 必须登录；不进 `MesPermitAllProvider`
- 日志 / SSE / toast 不打印 apiKey、cipher、JWT、内部路径
- SSE 仍 `Authorization: Bearer ` + `getToken()`

Audit and lineage:

- 不改历史 SQL / 已冻菜单 id
- 本单元无新表

AI/rule-engine rules:

- 只追加一句标签 system，不替换档案 `systemPrompt`，不挂新 Tool
- 不走 SQL MCP；不直连业务库
- A36 分支保持：未选档案不静默改成 `agent/send`

Database rules:

- 无 DDL / Flyway
- 不把 F1 开关写入 yml；本期也不新造 `sys_config` 键

## 2. Plan

### Implementation Approach

- 前端：Pinia `aiContext` → 布局挂 F1 与 Drawer → Navbar 图标 → 工单页 set/clear → 抽屉瘦面板复用现有 API，发送时 `JSON.stringify({ ...existing, context })`
- 后端：`AiChatSendRequest` 增加嵌套对象或 Map `context`（建议静态内部类 / 独立 `AiChatContext`，字段与设计表一致，忽略未知键）。prepare 阶段若标签非空则往发给模型的 messages/system 追加一句。chat 与 agent **共用**，避免只改一口
- 兼容：Jackson 缺字段为 null；现网前端不传则零行为变化
- **不改** `/ai/chat` 全宽页布局与发送体（S-D14）

### Affected Modules

- 可改：`startech-mes-front/src/layout/**`、`src/store/modules/aiContext.js`（新）、`src/views/mes/pro/workorder/index.vue`、新建抽屉组件（如 `src/components/AiAssistantDrawer/index.vue`）、`src/api/ai/*` 仅当发送封装需要透传 `context`（现网已 `JSON.stringify(data)`，页面组 payload 即可）
- 可改：`backend/ktg-ai` 的 `AiChatSendRequest` 与 chat/agent send prepare；单测
- 不可改：`frontend/`、`MesPermitAllProvider`、`ktg-generator`、UReport、对话 URL

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- **冻结不变：** `POST /ai/chat/send`、`POST /ai/agent/send` 的 URL / method / 认证头 / SSE `{content, done}`；`/ai/session/**`
- **可选增量：** body.`context` = `{ screen?, screenLabel?, resourceKey?, recordId?, recordLabel? }`
- **权限字（现网）：** `ai:chat:list`、`ai:chat:send`
- 本单元**不**发布 `mes-ai-assistant-open`（留给 85）

### Persistence Changes

Tables, indexes, migrations, mapper XML, and lifecycle rules:

- 无

### Transaction Boundaries

- 发送仍：先落 user 消息，再流式，再落 assistant。拼 system 句不另开事务、不写业务库

### Risks

- 误用权限字 `ai:chat` 导致全员拦不住或全员被拦
- F1 监听挂到 `document` 且不判权限，抢走浏览器帮助
- 把 `/` 也绑到抽屉
- 抽屉预挂载导致每个页面都打 session list
- 改了 SSE path 或必填 `context` 弄坏旧客户端
- 工单页卸载未 clear，串到下一页标题

### Verification Strategy

- 前端：`npm run build:prod`；有浏览器则：有权限 F1 开抽屉、无权限 F1 不拦、工单进出标题变化、Network 看 body 可选 `context`
- 后端：`ktg-ai` 单测 — 无 context 与现网 prepare 一致；有标签则发给 mock 模型的 system 含约定句；`tenantId` 若被传入须忽略
- 未实跑不得在第 4 节写通过
