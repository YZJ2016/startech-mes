### Business Goal

对 **任意已过账（`FINISHED`）** 的生产领料 / 销售出库整单（含旧页手工建单，**不依赖** `outboundpull` / 130），仓管在权限允许时可 **撤回**：出库过账是库存 −1，撤回是加回库存；写新 `wm_transaction` **反向 flag**，单据回到 `PREPARE`，并写审计日志。禁止物理删除历史流水；失败全滚。Hub 抽屉出按钮，实际调用各单据 withdraw。

**现网事实（2026-09-19，`startech-mes-basic`）：**

| 项 | 现网 | 131 假设 |
| --- | --- | --- |
| 撤回 API | **无** 出库 `…/withdraw` | **新建** 分单据 `PUT …/withdraw` |
| 状态机 | `PREPARE` → 执行 → `FINISHED`；**无** `CONFIRMED`（OH-D6） | 仅 **FINISHED** 可撤；**无 unconfirm 步** |
| 库存流水 | `processIssue` / `processProductSalse` 写 `wm_transaction`；StorageCore 已有 **入库** `reverse*`（127），**无** `reverseIssue` / `reverseProductSalse` | 新增出库冲销：同类型流水、反向 flag；禁止盲改、禁止删历史行 |
| 领料副作用 | 执行后原材料低于下限可能 `addPurchase`（OH-D7） | **不级联删**已生成采购单；只回滚本单库存；执行路径不改 |
| 销售副作用 | 有 `soCode` 时 `updBySend` 增加 `shipmentNum`、减少 `remainingNum` | 撤回 **等量反向** 回冲发货量/剩余量 |

### Scope

In scope:

- **仅** 已过账 `ISSUE`、`PRODUCT_SALSE` **整单**撤回
- 校验可撤 → 新流水反向 flag 冲销库存 → 销售出库回冲订单量 → 状态回 `PREPARE` → `@Log`
- Hub 抽屉按钮转发：
  - `PUT /mes/wm/issueheader/{id}/withdraw`
  - `PUT /mes/wm/productsalse/{id}/withdraw`
- 权限：独立 `withdraw`（`mes:wm:issueheader:withdraw` / `mes:wm:productsalse:withdraw`）+ 可选 `sys_config` `mes.wm.outbound.withdraw.enabled` 默认 **on**（缺失/非法当 on）
- 单测：租户隔离；过账后再撤库存回到前值；销售行发货量回冲；重复撤回拒绝；开关 off 拒绝

Out of scope:

- 出入库混用万能 withdraw（禁止复用 127 `InboundWithdrawSupport` / 统一 facade 乱调入库+出库）
- 委外发料 Hub 拉单与撤回（Hub **禁撤**；128 preview 不是 Hub 拉单）
- 送货单进 UNION / 扣库存 / 当拉单目标 / 撤回（113）
- 其他出库 / 借料 / 采购退货的撤回（第二刀见 **133**，不进本 AC）
- 生产退料 / 销售退货进出库 Hub
- 改现有 list / 执行 PUT、加 confirm、改自动建采购 **执行**逻辑（OH-D7 路径不改）
- 撤回级联删自动采购、级联撤下游
- 无 `CONFIRMED` unconfirm 步（出库一步过账 OH-D6）
- CAT-W01 / W04 / W05 / W06 / W07；价目、快财务、UReport、Vue2、前端假分页
- 对照仓 React / Python / kuaizhizao 权限字、`MaterialStockMovement`、委外创建即过账
- 改 `frontend/`；扩 PermitAll

### Acceptance Criteria

1. 点名 **131**。Git 根 `startech-mes-basic/`。功能不依赖 130 / `outboundpull`；工序建议先改 130 以减 Hub 页冲突。
2. 仅 `FINISHED` 的 `ISSUE` / `PRODUCT_SALSE` 可撤；草稿/已撤/他类型拒绝。手工建单过账后也必须可撤。
3. 出库过账是库存 −1，撤回是加回库存（不是 127「入库减库存 / 负库存拒单」）。撤回后同租户同仓同批次库存与过账前一致；失败全滚；**不**物理删历史 `wm_transaction`。拒撤仅限：并发双撤、非 `FINISHED`、开关 off、仓/批次档不在、销售回冲找不到订单行。下游已耗用（生产已领用该批等）默认加回仍允许，不另开会、编码不得发明拒撤。
4. 销售出库撤回：`ProSalesOrderItem` 发货量/剩余量与过账写入 **等量反向**。
5. 领料撤回 **不**删除 `addPurchase` 已生成采购单。
6. Hub 无委外发料/送货单/112/129 撤回按钮；入库 Hub 无出库撤回入口。
7. **无** `PUT …/unconfirm`。
8. **编码门禁（本单元）：** 点名 **131** + 单测（租户隔离 + 撤回加回库存）+ `npm run build:prod` **实跑后**才写入 §4「代码已落」。**不要求**先关 OH-X1 / OH-X2。对照清单 **待确认（冲突）= 0**。部署手验仍开、后置。
9. Vue3 出库 Hub 抽屉：`FINISHED` 的 `ISSUE` / `PRODUCT_SALSE` 必须有「撤回」；`issueheader` / `productsalse` API 只加 `PUT …/withdraw`（附录 B）。权限独立 `withdraw`（`mes:wm:issueheader:withdraw` / `mes:wm:productsalse:withdraw`）；无对应 `withdraw` 时按钮隐藏。

11. 撤回对象是任意已过账领料/销售出库（含旧页手工建单）；**不依赖** `outboundpull` / 130 代码落地。

- 无 `TenantContext` 不得访问租户表；SQL 永不跳过 `tenant_id`

- 新 `PUT …/withdraw` 须 `@PreAuthorize` 对应 `withdraw`；不进 PermitAll
- 日志不打印密钥/内部路径

Audit and lineage:

- `@Log` 撤回；冲销流水可追溯原单
- 可选 master Flyway：`mes.wm.outbound.withdraw.enabled`=`on`（键名禁止进 yml；禁止明文密钥进参数表）
- 不改历史 `backend/sql/`

AI/rule-engine rules:

- 不涉及 AI；撤回不得直连任意 SQL

Database rules:

- **默认无新业务表**；依赖既有 `wm_transaction`
- 配置走 `ISysConfigService.selectConfigByKey`，不新增 `@Value` / yml 键
- 出库冲销方法挂 `IStorageCoreService`（如 `reverseIssue` / `reverseProductSalse`），**编排服务**不得与 127 入库 withdraw 共用一个类对外乱调

## 2. Plan

### Implementation Approach

1. T0：点名 131；读 `processIssue` / `processProductSalse` 与 127 `reverse*` 形态，出库侧对称实现（不复用入库编排类）。工序建议先改 130 以减 Hub 页冲突；功能不因 130 未落而停止。
2. StorageCore 出库冲销 + 领料/销售出库 `PUT …/withdraw` + 可选 master `sys_config`。
3. 销售出库 withdraw 内等量回冲 `ProSalesOrderItem`；领料不碰采购单删除。
4. Hub 抽屉按钮（仅 ISSUE / PRODUCT_SALSE 且 `FINISHED`）；委外等无按钮。
5. 单测库存还原 + 租户；负向：重复撤、开关 off、Hub 禁撤发料。

### Affected Modules

- `ktg-mes` wm + storage；可选 `ktg-system` master Flyway `sys_config`；Vue3 出库 Hub 抽屉 + 现有 issue/productsalse API 文件 **仅加** withdraw 方法
- 禁止：改 127 入库 withdraw 行为；改 OH-D7 `addPurchase` 执行逻辑；改 Vue2；改入库 Hub

### Public Contracts

- **加法** 两条 withdraw URL；旧 execute PUT 语义不变
- Hub list 可不破坏契约（前端按 `FINISHED` + 类型显示按钮；服务端拒绝兜底）

### Persistence Changes

- **默认无新表**；新冲销行写入既有 `wm_transaction`
- 可选 master：`mes.wm.outbound.withdraw.enabled`=`on`（Flyway 号按当时目录最大号顺延）

### Transaction Boundaries

- withdraw：读单 → 校验开关/状态/租户 → 冲销库存 →（销售）回冲订单量 → 更新 `PREPARE`；任一步失败回滚。禁止先改状态再丢流水。

### Risks

| 风险 | 缓解 |
| --- | --- |
| 与 127 共用万能服务 | 独立 support / 独立 reverse 出库方法；扫描禁止依赖 `InboundWithdrawSupport` |
| 物理删历史流水 | AC 禁止；只插反向 flag |
| 抄 127 负库存拒单 | **出库撤回是加回库存**，不是 127「下游已消耗无法再减」。失败表见 T0：并发双撤、非 `FINISHED`、开关 off、仓/批次档不在、销售回冲找不到订单行。下游已耗用 **仍允许加回**（本刀不拒撤） |
| 误删自动采购 | T0：不级联删；只回滚本单库存 |
| 销售发货量不平 | 与过账 `shipmentNum`/`remainingNum` 等量反向；无 `soCode` 则跳过订单回写 |
| 做成 unconfirm 两步 | 出库无 CONFIRMED；不新增路径 |
| 委外 Hub 可撤 | 128 禁撤；本单元无按钮无 API |
| Hub 页与 130 同改 | 工序建议先 130 减冲突；功能不依赖 130 |

### Verification Strategy

- 单测：过账→撤→库存还原；销售发货量还原；重复撤；跨租户；开关 off。
- 编译/前端：指定测试类 `mvn -pl ktg-mes -am test` + `npm run build:prod`。
- 手验后置：Hub 抽屉撤回成功与失败 toast。
