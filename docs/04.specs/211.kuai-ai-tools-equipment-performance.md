从 `docs/01.temlplates/01.development_unit_template.md` 复制，保留五章。状态：已完成。

## 1. Spec

### Capability

- Name: 新增只读 Tool `query_equipment_oee`、`analyze_equipment_losses`。
- Module: `riveredge-backend/src/apps/kuaiai/services`（tools 适配层）、manifest `ai_tools`。
- Priority: P2（S18 OEE 损失分析）。
- Related requirement/design documents: 需求 25 SC-D1、SC-D5、SC-D7；设计 26 §4、§5.2；前置 spec 189、190、210。

### Business Goal

设备/生产主管问“上周 3 号注塑机 OEE 多少、主要损失在哪”“车间 OEE 趋势是升还是降”，助手基于 OEE 服务给出指标与损失分解，并引用故障/保养记录（spec 210 的 Tool 可在同一会话中由模型自行联用）。

### Scope

In scope:

| Tool | 参数 | 底层 service | 权限码 |
| --- | --- | --- | --- |
| `query_equipment_oee` | `equipment_id?`、`workshop_id?`、`date_start`、`date_end`、`limit≤20` | `equipment_oee_service` 的 OEE 列表方法（T1 核对签名与返回字段） | `kuaizhizao:equipment-oee:read`（T1 从 manifest 核实确切编码） |
| `analyze_equipment_losses` | `equipment_id`（必填）、`date_start`、`date_end` | OEE service 的趋势/明细方法 + 内部确定性聚合 | 同上 |

- `analyze_equipment_losses` 的输出：时间开动率/性能开动率/良品率三个分量、按停机原因/故障类型聚合的损失工时 TopN、样本天数。分解计算在适配层用确定性代码完成（SC-D5），LLM 只负责解释文案。
- 数据范围：service 不接收 `current_user` 时，适配层补行级范围；资源键 T1 定。

Out of scope:

- OEE 数据采集与手工补录（写操作）。
- 实时 IoT 数据（spec 219）。

### Acceptance Criteria

1. `query_equipment_oee` 输出设备、期间 OEE 与三分量，与 OEE 页面列表同源一致。
2. `analyze_equipment_losses` 输出固定结构（三分量 + 损失 TopN + 样本量）；无损失记录时输出真实“期间内无损失记录”。
3. 三分量数值与 service 返回一致，不得由 LLM 估算；聚合的 TopN 可复算核对。
4. 两个 Tool 登记于 manifest（`label`、`kind=read`）。

### Rules and Constraints

Tenant isolation:

- 传 `ctx.tenant_id`。

Security and masking:

- 不输出操作人员个人信息。

Audit and lineage:

- 沿用 Tool 级审计；`route` 业务键记录设备与期间。

AI/rule-engine rules:

- OEE 三分量与损失归类来自 OEE service/确定性聚合；LLM 不得生成指标值（SC-D5）。

Database rules:

- 无表结构变更。

### 场景模板（Y3=a）

本单元更新场景模板 `equipment-ops`（设备运维助手，spec 210 登记）定义：启用工具追加本单元 Tool 集合（T1=a 规则：只改模板定义，既有租户档案不变）；system_prompt 补充引用，不另出新卡。

## 2. Plan

### Implementation Approach

- 损失聚合放在 tools 适配层内部函数：拉取期间明细 → 按停机/故障类别分组求和 → TopN（N=5）→ 注明其余合并为“其他”。

### Affected Modules

- Modify/Create: tools 适配模块、`constants.py`、`manifest.json`（两份）。
- Test: `tests/apps/kuaiai/test_spec211_equipment_oee_tools.py`。

### Public Contracts

- Tool 闭集新增两名。

### Persistence Changes

- 无。

### Transaction Boundaries

- 只读。

### Risks

- 期间内明细量大：分页拉取并对明细条数设内部上限，超出时在输出注明“统计截至前 N 条明细”。

### Verification Strategy

- 单测：三分量透传、聚合可复算、空期间、范围收敛。
