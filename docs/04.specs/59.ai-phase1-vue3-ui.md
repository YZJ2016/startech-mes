### Frozen HTTP contract (Phase 1 — do not drift)

Assume classic MES `code/msg/data` / `rows`+`total`. All authenticated.

- `GET/POST /ai/provider` list/create; `GET/PUT /ai/provider/{id}`; `DELETE /ai/provider/{ids}`
- `GET/POST /ai/model` list/create; `GET/PUT /ai/model/{id}`; `DELETE /ai/model/{ids}`
- `GET /ai/model/options` → `{id, modelName, providerCode, category}[]` no keys
- `GET/POST /ai/session` list/create; `GET/PUT/DELETE /ai/session/{id}`
- `GET /ai/session/{id}/messages`
- `POST /ai/chat/send` body `{sessionId?, modelId, content}` response `text/event-stream` data lines JSON `{content, done}`

Permissions (propose, keep consistent): `ai:provider:list|query|add|edit|remove`, `ai:model:*`, `ai:chat:list|send`.

前端必须打上述路径（**不要**写成 `/ai/provider/list` 或 `/system/message`）。列表查询用 `params: { pageNum, pageSize, ... }`。按钮 `v-hasPermi` 与上列权限字一致。

### Acceptance Criteria

- 在 `startech-mes-basic/startech-mes-front` 执行 `npm run build:prod` 成功（依赖已装前提；失败则报告原文，不顺手升依赖）
- 源码无 `hook-fetch`、`vue-element-plus-x`、UnoCSS、`ant-design-vue`、硬编码生产地址、明文 Key

- 本单元不改、不新增 lockfile

### Rules and Constraints

Tenant isolation:

- 不传租户头；依赖已有 JWT
- 不在前端存 `tenant_id` 覆盖登录上下文

Security and masking:

- 前端不持久化 apiKey；不写 localStorage
- SSE 请求头 `Authorization: Bearer ` + `getToken()`（`src/utils/auth.js` 的 `Admin-Token`）
- 不把 `${AI_DEFAULT_API_KEY:}` 或任何 Key 放进 `.env.*` 真值

Audit and lineage:

- 无新业务表；菜单由 57/58 的 SQL 挂 `path` 前缀 `ai`（如 `ai/provider`、`ai/model`、`ai/chat`），本单元 component 路径与之对齐

AI/rule-engine rules:

- 只消费 Frozen 契约；模型下拉只用 `options` 的 `id/modelName/providerCode/category`
- 发送时只选 `category === 'chat'`（或 options 已由后端过滤）

Database rules:

- 无

## 2. Plan

### Implementation Approach

- API 文件风格对齐 `src/api/system/notice.js`：`import request from '@/utils/request'`
- 配置页对照 `src/views/mes/md/workshop/index.vue`：查询条 + 工具栏 + 表 + 分页 + 对话框
- 对话页对照 `ruoyi-web` 布局重做 Element Plus，不拷 TS/UnoCSS
- SSE：`fetch('/ai/chat/send', { method:'POST', headers:{ Authorization, Accept:'text/event-stream', 'Content-Type':'application/json' }, body })`，按 `data:` 行解析 `{content, done}` 追加气泡；401 时走与 `request.js` 相同的跳登录习惯（可复用现有提示，不复制一套 axios）

### Affected Modules

- 本单元可改：`startech-mes-front/src/api/ai/**`、`startech-mes-front/src/views/ai/**`
- 若现有动态路由只靠后端菜单，**不要**为了本页去改 `src/router` 的常量业务表，除非仓库已有「目录路由」惯例且必须挂 component
- 本单元不可改：`backend/**`、`frontend/**`、`package.json` 依赖、lockfile、`.env.*` 生产地址

### Public Contracts

APIs, facades, DTOs, events, or database contracts:

- 只消费 Frozen 块；上传图标走既有 MinIO 封装（与其它页相同），不新增 OSS API
- 厂商表单：`providerName` / `providerCode` / `providerIcon` / `apiHost` / `status`
- 模型表单：`category` / `modelName` / `providerCode` / `describe` / `modelShow` / `dimension` / `apiHost` / `apiKey`（只写）
- `GET /ai/model/{id}` 若带回打码 `apiKey`：输入框 placeholder 显示打码，`v-model` 保持空直到用户改

### Persistence Changes

Tables, indexes, migrations, mapper XML, and lifecycle rules:

- 无业务表。后端菜单由 57/58 写入 `sys_menu`。

### Transaction Boundaries

- 无

### Risks

- 为 SSE 新建 axios 丢掉 401 / 重复提交拦截
- 把 ruoyi-admin / ruoyi-web 整页贴进仓库（Ant Design Vue / Vben）
- 列表 URL 误用 `/list` 与 57/58 Frozen 契约漂移
- 在 `frontend/` 或后端补「快捷菜单」造成双端/双仓冲突
- 提交 lockfile 或升级 Element Plus

### Verification Strategy

- `cd startech-mes-basic/startech-mes-front && node -v && npm run build:prod`
- 静态：`rg` 无禁用依赖名、无游客分支、API 路径与 Frozen 块一致
- 浏览器点选属联调（需 57+58 与登录环境）；本单元落盘不声称 UI 已在浏览器验过，实现完成后按仓库规则再验
- 未真实跑通不得写「构建成功」
