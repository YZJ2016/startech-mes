# Development Unit Template

Use this template before each implementation unit.

## 1. Spec

### Capability

- Name: 将 MES 匿名放行从平台 `SecurityConfig` 迁出或收紧
- Module: `ktg-framework` → `ktg-mes` 配置 / 方法注解
- Priority: P0
- Related requirement/design documents:
  - `docs/04.specs/00.backend-extract-program.md`
  - `docs/04.specs/05.extract-message-attachment-notice.md`
  - `docs/04.specs/06.extract-or-drop-mobile-login.md`
  - `docs/04.specs/07.extract-ureport-bootstrap.md`
  - 调查：`SecurityConfig` 继承 `WebSecurityConfigurerAdapter`，含一批 MES 专用 `antMatchers`

### Business Goal

`ktg-framework` 的安全配置回到接近若依的登录/静态/Swagger/Druid 集合，便于整模块替换。MES 仍需要匿名的路径改为 `ktg-mes` 可随代码走的配置（或显式收紧为需登录）。不引入第二套认证。

### Scope

In scope:

- 处理下列**现行**放行（注释掉的大屏接口不恢复匿名）：
  - `/mobile/login/**`、`/mobile/**`
  - `/ureport/**`
  - `/websocket/**`
  - `/system/autocode/get/**`
  - `/uploadFiles/**`、`/files/**`、`/template/**`、`/upload/**`
  - `/mes/tm/tool/importData`
  - `/mes/sys/camera/list`
  - `/loginOuth`
- 依赖 `02` `04` `05` `06` `07` 已把对应资源迁走或已 DROP
- 在当前 Spring Security 5 API 上实现（仍可用 `antMatchers`）；不要提前改成 Boot 4 的 `SecurityFilterChain`（属换壳）
- 优先给必须匿名的接口加现有工程能用的方式（若无 `@Anonymous` 则用 mes 侧 `WebSecurityConfigurerAdapter` 的额外 `HttpSecurity` 配置，或集中常量列表被主 `SecurityConfig` 读取）。**禁止**复制一套 JWT 过滤器

Out of scope:

- 升级到 Spring Security 6/7
- 恢复已注释的大屏 `permitAll`
- 改 Token 密钥或过期时间

### Acceptance Criteria

- `ktg-framework` `SecurityConfig` 不再出现 `/mes/`、`/ureport`、`/websocket`、`/system/autocode`、`/loginOuth`、`/mobile/` 等 MES 字符串（上传静态路径若平台头像仍需要 `/profile/**` 可留平台侧）
- 每个原放行路径有记录：匿名保留 / 改为 authenticated / 随 `06` DROP 删除
- `/mes/tm/tool/importData` 默认改为**需登录**（调查视为过宽）；若现场必须匿名，在第 4 节写明理由，不得静默保持
- `/login`、`/register`、`/captchaImage` 行为不变
- compile 通过；有环境时未登录访问应收紧的接口返回 401，保留匿名的接口仍可达

### Rules and Constraints

Tenant isolation:

- 不借放行清单做数据权限绕过

Security and masking:

- 只允许迁移或收紧，不允许新增 MES 匿名接口
- 导入、摄像头列表默认收紧
- 不在日志打印 Token

Audit and lineage:

- 本单元 PR 必须附「路径 × 决策」表，作为后续换壳改 `SecurityFilterChain` 的输入

AI/rule-engine rules:

- 不涉及

Database rules:

- 无

## 2. Plan

### Implementation Approach

1. 等 `05`–`07` 与 `02` `04` 完成后，对现行 matcher 逐条分类
2. 在 `ktg-mes` 增加安全扩展（额外 `WebSecurityConfigurerAdapter` 的 `order` 或 `HttpSecurity` 定制需验证与主配置共存；若不能共存，则主配置改为注入 `List<String> mesAnonymousPaths`，列表由 mes 模块 Bean 提供，框架不写死 MES 路径）
3. 推荐：framework `SecurityConfig` 读取 `MesPermitAllProvider`（接口在 common 或 mes，由 mes 实现）。换壳时只改 provider 注册方式
4. 按 `06` 决策删除或保留 mobile 相关项
5. 删除注释掉的大屏 matcher 死代码（可选，属清理，不改变运行行为）

### Affected Modules

- `ktg-framework`：`SecurityConfig` 去 MES 硬编码
- `ktg-mes`：提供匿名路径列表或自身安全配置
- 间接：`02` 编码 GET、`07` ureport、`05` websocket、`06` mobile

### Public Contracts

- 认证头仍为 `Authorization` JWT
- 标准登录路径不变
- 被收紧的接口从匿名变为需登录，属于**有意的契约收紧**，必须在 PR 与本文件第 4 节列出，供前端后续评估使用

### Persistence Changes

- 无

### Transaction Boundaries

- 无

### Risks

- 双 `WebSecurityConfigurerAdapter` 顺序导致全部放行或全部拦截
- `06` 未决策时本单元无法删 `/mobile/**`
- 收紧导入接口导致旧脚本失败

### Verification Strategy

- `rg "antMatchers\\(\"/mes|ureport|websocket|autocode|loginOuth|mobile" backend/ktg-framework`
- 对照本单元路径决策表逐条手工或脚本探测（不写内网主机）
- Maven compile
