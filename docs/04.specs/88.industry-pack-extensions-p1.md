### Capability

- Name: 行业包 P1 — 扩展声明登记 / replace 槽位互斥

- Related requirement/design documents:

  - 总控：`docs/04.specs/86.mes-industry-pack-program.md`

### Business Goal

两个行业模块若都声明要替代**同一宿主菜单 path**，平台保存许可时失败关闭（整单不写），避免将来电子包与另一行业包同时改同一张通用单据页。本单元**不**把任何现网 MES 页换成行业组件，也**不**写入 `sys_config` profile。

### Scope

In scope:

- Java 显式 `IndustryExtensionRegistry`（名可微调）：按 `module_code` 列出 `IndustryExtensionDecl`（字段对齐设计 §6，不必抄 Python dataclass 名）
- P0 模块 `ip.demo`：仅 `standalone`，无 replace
- `saveLicenses`：对**即将落库**的有效 `ip.*` 收集 replace 声明，`(hostPath)` 冲突则 `ServiceException`（HTTP 400），不调用 delete/insert 或整事务回滚
- **无 replace 声明、或本次写入不含任何 `ip.*`：** 互斥校验不跑或 no-op，**不得**挡住 md / pro / ai 等无关模块的 `saveLicenses`（IP-D20）
- 单测：无冲突通过；两夹具声明同一 `hostPath` 失败；`ip.demo` 单独许可仍成功；无 `ip.*` 时保存其它模块与今日一致
- 文档注释：将来 `profile` 走 `sys_config` 键 `mes.ip.*`（IP-D10），本单元**不**插入这些行

Out of scope:

- `useDocumentReplacement`、改 `permission.js` `loadView`、按租户改 `sys_menu.component`
- 给 `views/mes/md/bom`、`views/mes/pro/process`、工单页接 profile 或换页（**IP-G3**）
- 扫描 `manifest.json`、ServiceLoader、新 HTTP「列出 document replacements」
- 真实行业模块、领域表、套餐 / PRO Key
- 重做 87 的菜单/字典/桩页（只消费 `ip.*`）
- 改 Vue2；扩 `MesPermitAllProvider`

### Acceptance Criteria

- 许可仅 `ip.demo`（及非行业码）：与 87 行为一致，无 400
- **无 `ip.*`、登记表无 replace：** 保存其它模块许可与今日一致，不因互斥逻辑 400（IP-D20）
- 测试夹具：模块 A、B 均 `replace` 同一 `hostPath`（例如 `mes/md/bom`）→ `saveLicenses` 抛错，库中许可集不变
- 生产登记表在 88 落盘时**没有**指向现网 BOM/工艺/工单的 replace（避免未拍板就占槽）
- 无新 Vue 依赖、无 lockfile、无密钥
- `mvn -pl ktg-system -am test` 实跑后写入第 4 节

### Rules and Constraints

Tenant isolation:

- 互斥按**该租户**即将写入的许可集计算，不看他厂
- 只信 `TenantContext` / 平台接口的路径 `id`（现网许可 API 已是平台操作目标租户）
- 无客户端租户头

Security and masking:

- 仍仅平台可写许可
- 错误信息可含 `hostPath` 与冲突 `extension id`，不得含 JDBC/JWT

Audit and lineage:

- 无新表亦可；不要为 P1 建 `core_applications`
- 不改 9200 菜单 id

AI/rule-engine rules:

- 无

Database rules:

- 无 DDL（除非单测不需要）
- 不写 `sys_config` 行业键

## 2. Plan

### Implementation Approach

- 注册类放 `ktg-system`（许可保存已在此），避免 `ktg-admin` 堆逻辑
- 夹具声明用测试可见性或 `package` 内测试模块码，**不要**把假 `ip.conflict.a` 写进生产 `mes_module`，除非另有产品要求
- 冲突键：至少 `hostPath` 规范化（去查询串、去尾 `/`）。可选 `hostModule` 仅作文档；互斥真源是 path，对齐快格云 `menu_path`
- **不要**在 Vue 宿主入口加 hook「去拉替换组件」

### Affected Modules

- 可改：`ktg-system` 新注册类、`SysTenantLicenseServiceImpl.saveLicenses`、单测
- 不可改：`startech-mes-front` 业务页 component（本单元无前端任务除非 87 残留隐藏 `ip` 已做）
- 不可改：`frontend/`、`MesPermitAllProvider`、Flyway 菜单（无新页）

### Public Contracts

- HTTP：仍只是 87 的 licenses PUT；冲突时 `code` 非成功，**无**新 URL
- 声明：编译期登记，不是 REST 扫描结果

### Persistence Changes

- 无

### Transaction Boundaries

- 校验在 `saveLicenses` 写库之前；失败不删旧许可

### Risks

- 把现网 BOM path 写进生产登记，未做换页却占死槽
- 互斥只看内存、不看即将保存的列表（漏检）或看了已停用模块（误检）——应以**本次 body 规范化后的码**为准（现网 save 是全量覆盖）
- 引入前端动态 import 绕过 `loadView`
- 默选 IP-G3 去改工艺页
- 无 replace / 无 `ip.*` 时仍跑互斥，挡住无关模块的 `saveLicenses`

### Verification Strategy

- 单测覆盖冲突/不冲突/`ip.demo`/无 `ip.*` 时无关模块可保存
- 无浏览器换页验收（本单元无换页）
- 未实跑不得写通过
