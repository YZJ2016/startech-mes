## 1. Spec

### Capability

- Name: 用 springboot2 内容替换 `ktg-framework`（SecurityConfig + 手机号登录）
- Module: `ktg-framework`
- Priority: P0
- Related requirement/design documents:
  - `docs/04.specs/11.backend-shell-swap-program.md`
  - `docs/04.specs/08.migrate-security-permit-all.md`
  - `docs/04.specs/06.extract-or-drop-mobile-login.md`
  - `docs/04.specs/10.backend-extract-review.md` 第 7 节

### Business Goal

框架层换成若依 3.9.2 springboot2 的 `ruoyi-framework`，仍为 `ktg-framework` / `com.ktg.framework`。换入后 **MES 匿名路径仍由 `MesPermitAllProvider` 提供**，**手机号登录判断并入 `UserDetailsServiceImpl`**。不引入第二套 JWT。

### Scope

In scope:

- 对照：`RuoYi-Vue-springboot2/ruoyi-framework/`（commit `913524b1525a0e374774afbb54c452d8f68a5a8f`）
- 覆盖 nested `backend/ktg-framework/`；机械替换包名与 pom GAV
- **SecurityConfig**：对照源在 Boot 2.5.15 / Security 5.7 上已是 `@EnableMethodSecurity` + `SecurityFilterChain`（**不是** Boot 4 / jakarta Security 6）。阶段 1 允许换入该形态
  - 保留对照的 `PermitAllUrlProperties` + `@Anonymous` 扫描
  - **另外** `@Autowired(required = false) MesPermitAllProvider`，在 filter chain 里对 `getPermitAllAntMatchers()` 做 `permitAll()`（逻辑对齐抽出后 `resolveMesPermitAll()`）
  - 禁止把 `/mes/`、`ureport`、`autocode`、`loginOuth`、`/mobile/` 再写成框架字面量
  - 禁止复制第二套 JWT 过滤器；继续用换入的 `JwtAuthenticationTokenFilter`
- **UserDetailsServiceImpl**：以对照源为底（含 `SysPasswordService.validate`、`MessageUtils`），并入抽出后 nested 的手机号分支：
  - 保留 nested 的 `REGEX_MOBILE` 与 `isMobileNumber`
  - `loadUserByUsername`：若是手机号则 `userService.selectUserByMobile(username)`；若未取到用户再 `selectUserByUserName`
  - 不恢复 `PhoneUtils` 类型
- 标准 `/login` `/register` `/captchaImage` 放行与对照一致

Out of scope:

- Boot 3/4、Java 17、jakarta、`SecurityFilterChain` 再升级到 Security 6/7 API
- 改 `MesPermitAllProviderImpl` 路径表（属 mes；本块只接线）
- 改模块名/包名为 ruoyi
- 前缀 yml、notice `/list`、uploadMinio（`17`）
- 扩大匿名面或恢复 `/mobile/**` 整段放行

### Acceptance Criteria

- `SecurityConfig` 注入 `MesPermitAllProvider`（`required = false`）；无实现时不追加 matcher
- `rg "/mes/|ureport|autocode|loginOuth|/mobile/" backend/ktg-framework/src/main/java/com/ktg/framework/config/SecurityConfig.java` 无 MES 路径字面量
- `UserDetailsServiceImpl` 含 `selectUserByMobile` 与手机号正则；无 `PhoneUtils`
- 无第二套 `TokenService` / 平行 AuthenticationManager 实现（对照源里 `ProviderManager`+`DaoAuthenticationProvider` 是 Security 5 写法，允许）
- `rg "com\\.ruoyi" backend/ktg-framework` 为 0
- JDK 8 编译 `ktg-framework,ktg-mes,ktg-admin -am` 通过后再 `17`

### Rules and Constraints

Tenant isolation:

- 不借 Security 改数据权限

Security and masking:

- 只迁移/保持 `08` 的放行入口，不新增长期匿名 MES 接口
- 不在日志打印 Token

Audit and lineage:

- 手机号正则与抽出后 nested `UserDetailsServiceImpl` 一致，不「改进」号段

AI/rule-engine rules:

- 不涉及

Database rules:

- 无

## 2. Plan

### Implementation Approach

1. `15` 通过（尤其 `selectUserByMobile` 已在）后再开始
2. 拷出 nested `SecurityConfig` 的 Provider 注入/`resolveMesPermitAll`，以及 `UserDetailsServiceImpl` 的手机号段
3. 整树覆盖 framework；机械替换
4. 在换入的 `SecurityConfig`（`SecurityFilterChain` bean）中并入 Provider 循环 `antMatchers(paths).permitAll()`，位置在标准 login/static/swagger/druid 放行之后、`anyRequest().authenticated()` 之前
5. 在换入的 `UserDetailsServiceImpl` 并入手机号分支；保留对照的删除/停用校验与 `passwordService.validate`
6. 确认仍依赖 `com.ktg.common.security.MesPermitAllProvider`，不要把接口搬进 framework

nested 现网关键（实施时以当时源码为准）：

- `ktg-framework/.../config/SecurityConfig.java`
- `ktg-framework/.../web/service/UserDetailsServiceImpl.java`

对照关键：

- `ruoyi-framework/.../config/SecurityConfig.java`（`PermitAllUrlProperties` + `SecurityFilterChain`）
- `ruoyi-framework/.../web/service/UserDetailsServiceImpl.java`（无手机号）

### Affected Modules

- `ktg-framework`
- 运行时依赖 mes 的 Provider 实现与 `FieldMetaObjectHandler`（MyBatis 插件仍靠扫描，不在本块改 mes）

### Public Contracts

- `Authorization` JWT 不变
- `/login` `/register` `/captchaImage` 行为不变
- mes 匿名集合仍由 Provider 给出（`08` 决策表）

### Persistence Changes

- 无

### Transaction Boundaries

- 无

### Risks

- 只拷对照 SecurityConfig、忘记 Provider → `/ureport/**` `/websocket/**` `/mobile/login/**` 等 401
- 只拷对照 UserDetailsServiceImpl → 手机号当用户名查失败
- 把 Adapter 时代 API 与 FilterChain 混用编不过
- 误升级到 Boot 4 的 jakarta Security

### Verification Strategy

- `rg "MesPermitAllProvider" backend/ktg-framework`
- `rg "selectUserByMobile|REGEX_MOBILE" backend/ktg-framework`
- `rg "PhoneUtils" backend` 仍为 0
- JDK 8 compile
- 运行时 401 探测留给 `18`（不写内网主机）
