## 1. Spec

### Capability

- Name: AI 权限/门控/审计状态与调用统计可视化。
- Module: `riveredge-backend/src/apps/kuaiai`、`riveredge-frontend/src/apps/kuaiai/pages/{trust,insights}`。
- Priority: P1。
- Related requirement/design documents: 需求 24 KO-06/KO-07；设计 24 §8/§9、§11.5、§12.1。

### Business Goal

让租户管理员准确知道 AI 读取、写执行和审计链当前做到什么程度，并通过 7/30 天趋势与最近调用定位使用量、延迟和失败；不能把尚未实现的 HITL 描述成已完成。

### Scope

In scope:

- `GET /operations/trust` 聚合当前用户权限、RBAC、HITL 和审计可用状态。
- trust 三卡、权限 chip、审计表与真实状态文案。
- insights 四指标、7/30 天、按日趋势、能力分布、最近动态。
- 复用 `/core/ai/stats/overview`、`/core/ai/audit/logs`，只修复其被本页暴露的真实缺陷。

Out of scope:

- 实现 LangGraph interrupt/checkpointer、propose/execute、人审队列。
- 新建统计表、复制审计数据、对现有审计日志提供编辑/删除。
- 声称截图验证等于 WCAG 合规。

### Acceptance Criteria

1. Trust 三卡状态只为 ready/partial/not_ready；HITL 在实现前固定 not_ready，页面使用未完成时态。
2. 权限列表只反映当前用户，不允许 query user_id 枚举他人权限。
3. 审计表显示时间、能力、路由、耗时、状态；普通展示不显示完整 error_message。
4. Insights 7/30 天切换会同步刷新全部区域；by_day 缺失日期补 0，null capability 显示“未分类”。
5. 空数据依据 empty_reason 呈现，与 5xx/网络错误严格区分。
6. 图表有数值摘要/可访问替代；颜色不是唯一状态信息。
7. 不改变 core stats/audit URL、参数、权限、响应结构；进入 trust/insights 必须同时具备 `kuaiai:entry:read` 与各自 display，不能出现“菜单可见但 core stats/audit 403”。

### Rules and Constraints

Tenant isolation:

- trust、stats、audit 全部使用当前 tenant_id；审计 user_id 只作响应展示且不得用作越权筛选。

Security and masking:

- 遵循 181 权限矩阵：trust/insights 页面和读取 API 均需 `kuaiai:entry:read` + 各自 display；core stats/audit 仍需原有 `kuaiai:entry:read`，不得为展示页放宽；缺任一码显示 403 且不发 core 请求。
- 错误详情先服务端脱敏；无专门高权限时页面不展开 error_message。权限码可展示，角色关系和凭据不可展示。

Audit and lineage:

- 统计来源为 `core_ai_audit_logs`；页面不自算总量。数据缺失须用 empty_reason/partial 标记。

AI/rule-engine rules:

- 不调用 LLM。Pulse 建议数只有存在真实 SuggestionService 时才显示数值；服务不可用不能显示假 0。

Database rules:

- 预期无迁移。必要索引优化需以查询计划证据另行写明，不能为图表复制表。

## 2. Plan

### Implementation Approach

- trust service 检查既有权限依赖、审计表/服务可用性与明确的 HITL feature state，输出证据数组。
- insights 直接并行调用两个 core API；前端建立日期补齐和 capability label 纯函数并测试。
- 图表复用仓内已安装组件；不存在合适依赖时采用 Ant Design/现有图表能力，不升级全局依赖。

### Affected Modules

- Create: trust schemas/service/route；前端 `pages/trust`、`pages/insights`。
- Modify: operations router、manifest/index/locale、operations service/type。
- Conditional modify: `core/ai/stats_service.py` 仅修复 Pulse unavailable 与日期数据语义，不改契约。
- Test: `tests/apps/kuaiai/test_spec184_trust_insights.py`、现有 core stats 回归。

### Public Contracts

- `GET /api/v1/apps/kuaiai/operations/trust` 精确响应见设计 §11.5。
- `GET /api/v1/core/ai/stats/overview?days=7|30` 与 `/audit/logs?page=&page_size=&capability=` 原样复用。
- 审计 item 字段台账见设计 §12.1。

### Persistence Changes

- 无。

### Transaction Boundaries

- 全部只读，无跨服务事务。

### Risks

- 以代码是否存在推断“ready”可能过度乐观；证据必须检查实际挂载与当前租户可用性。
- error_message 可能包含上游隐私；默认不下发或脱敏。
- 图表日期受时区影响；按 Asia/Shanghai 日期补齐。

### Verification Strategy

- 后端测试 current user 权限、无 user_id 参数、HITL not_ready、审计不可用 partial、脱敏。
- 前端纯函数测试日期补齐、null capability、空/错区分；角色组合测试仅 display、仅 entry、两者都有及 core 请求数；浏览器测试 Segmented、图例、表格分页和键盘。
- 跑现有 core AI 统计/审计回归。

Result:

- `GET /api/v1/apps/kuaiai/operations/trust` 实装：三卡（rbac/hitl/audit）状态只 ready|partial|not_ready，evidence 只放可复核事实、异常只记 error_type；permissions 为当前用户持有状态（10 个权限码闭集，无 user_id 参数）；hitl 由 checkpointer 装配 + propose/execute 端点双重检查，未接线固定 not_implemented。
- `core/ai/stats_service.py` 条件修复：`pulse_suggestion_count` 在 SuggestionService 不可用时返回 None（契约字段名不变，类型 int → Optional[int]）；by_day 分桶改用 `to_site_date`（Asia/Shanghai），与前端补齐时区一致。
- trust 页：双码门控（entry:read + trust:display，缺一即 403 且不发请求）、三等宽卡、权限 chip（码 + 拥有/未拥有文字）、审计表（时间180/能力120/路由自适应/耗时100/状态90，2xx 绿 4xx 橙 5xx 红数值码，20/页服务端分页，error_message 不渲染）、页脚写权限说明。
- insights 页：双码门控、Segmented 7/30 + 刷新（days 进两 queryKey，切换同步刷新全部区域）、四指标卡（pulse null → 「—」）、每日趋势（by_day 补 0、纵轴从 0、<2 有效点附说明、role=img + 数值摘要）、能力分布饼图（null capability → 未分类）、最近动态表 20/页、empty_reason 空态与错误严格区分。
- 六语言修正 `actHint`/`hitlDesc` 完成时态假声明为未完成时态，新增 col.status/auditForbidden/auditTotal/permGranted/permMissing/trendSummary/trendSparse 键。

Known gaps:

- [ ] HITL 明确不在本单元；状态必须保持 not_ready，直至独立单元真实交付。
- [ ] error_message 列未做权限分支展开：当前无专门管理级权限码可判定「可展开」身份，页面一律不渲染；待后续 spec 定义管理级码后可在脱敏摘要前提下放开（opsData.maskErrorSummary 已备好并测试）。
- [ ] 浏览器交互验证（Segmented 切换、分页、四视口）未实跑，留待 186 集成验收。
- [ ] 角色组合（仅 display / 仅 entry / 两者都有）core 请求数为 0 的验证由前端 `enabled: allowed` 门控保证，未做自动化计数断言。
