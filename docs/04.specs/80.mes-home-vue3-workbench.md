### Business Goal

登录后 `/index` 按身份进入平台回家或工厂工作台。工厂按本厂 `mes.index.layout` 平铺或按权限分区；无权限不渲染、不请求。去掉整页大字欢迎主体。

### Scope

In scope:

- `views/index.vue`：`userStore.isPlatformTenant && !userStore.isRunAs` → `PlatformHome`，否则 `FactoryHome`
- `views/dashboard/PlatformHome.vue`：图标快捷入口（有对应 `hasPermi` 才出），**零** `/mes/**` 请求、不上图。运营汇总与异常名单由 **82** 叠加，本单元不请求 `/platform/home/summary`
- `views/dashboard/FactoryHome.vue`：读布局；按权限挂块；`single` 平铺 / `role` 分区；空区不渲染
- `views/dashboard/PanelGroup.vue`：四张图标卡（全部 / 进行中 / 已完成 / 待确认），数据由父组件传入，本组件 **不再** 自己请求（避免 77 重复打 `getIndexNum`）
- `src/utils/request.js`：仅当请求配置带 `silentError: true` 时，非 401 不弹 `ElNotification`/`ElMessage`；401 仍走现有重新登录。默认行为不变
- 首页相关 API 调用带 `silentError`；失败只藏该块
- 点击 `router.push` 现有列表并带 `query.status`；列表页若尚未读 `route.query.status`，**只**给下列页补一次读取（不改其它查询逻辑）：
  - `views/mes/pro/workorder/index.vue`
  - `views/mes/qc/iqc/iqc.vue`
  - `views/mes/qc/ipqc/index.vue`
  - `views/mes/qc/oqc/index.vue`
  - `views/mes/wm/itemrecpt/index.vue`
  - `views/mes/wm/issue/index.vue`（页面目录是 `issue`，HTTP 仍是 `/mes/wm/issueheader/list`）
- 公告 / 消息用现有 `src/api/system/notice.js`、`message.js`，列表展示，有则请求
- 设备：`mes:dv:repair:list` → `/mes/dv/repair`；`mes:dv:checkplan:list` → `/mes/dv/checkplan`；不请求计数
- AI：`ai:chat:list` → 现有对话路由（与 59 一致，如 `/ai/chat`）；不嵌会话

Out of scope:

- echarts / 柱状图 / 饼图 / 折线（77）
- 改 Vue2；新首页路由；升级 Vue/Vite/Element Plus；提交 lockfile；`vue-echarts`
- 新 KPI API；部门数据范围；拖拽布局；改参数设置列表实现（工厂 overlay 仍用现页新增同键）
- 教育 / 合同 / 售后 / 摄像头；平台群发公告

### 点击约定

- 工单「全部」→ `/mes/pro/workorder`（不带 status）
- 工单「进行中」→ 同页 `query.status=CONFIRMED`（与现 `getIngNum` 一致）
- 工单「已完成」→ 同页不带 status（`getFiNum` 不是单纯 `FINISHED`，不能用假 status 过滤）
- 工单「待确认」与全部待办 → `query.status=PREPARE`
- 跳转 path 与现网 `sys_menu` 的 Vue3 路由一致（工单 `mes/pro/workorder` 等）

### Acceptance Criteria

- 平台回家：无工单卡、网络面板无 `/mes/**`、不请求 `mes.index.layout`（运营数字见 82）
- 工厂 / runAs：同一 `FactoryHome`；布局来自目标会话的 `getConfigKey`（H-I6 已由 JWT 上下文保证）
- 无 `workorder:list` 不渲染工单卡、不打 `getIndexNum`
- 仅仓储权限：无质检数字、不请求 qc list
- `layout` 非法或接口失败 → `single`，不挡整页
- 某块 403/网络失败：只藏该块；带 `silentError` 时不连环 toast；其它页面（无该标记）toast 不变
- 数字 0 仍显示并可点进列表
- 去掉「欢迎使用本系统 / 星技谷管理系统」作为主体
- `npm run build:prod` 在 `startech-mes-front` 成功（实现后实跑）；不提交 lockfile；不改 `frontend/`

### Rules and Constraints

Tenant isolation:

- 不传客户端租户头；身份只用 Pinia `user`（`tenantId`、`isPlatformTenant`、`isRunAs`）

Audit and lineage:

AI/rule-engine rules:

- 只入口；不改 `/ai/**` 调用契约

Database rules:

- 无

## 2. Plan

### Implementation Approach

1. `request.js` 增加 `silentError`：业务码非 200 且非 401、以及 HTTP 错误拦截里，若 `config.silentError` 则 `reject` 但不弹通知。
2. `dashboard.js` 的 `getIndexNum` 及工厂页发出的 list/config 传入 `silentError: true`（可在 `request({ ..., silentError: true })`）。
3. 拆 `index.vue`；`FactoryHome` 集中请求并传 props 给 `PanelGroup`。
4. 列表页启动时若 `route.query.status` 有值则写入 `queryParams.status` 再 `getList`。

### Risks

- `silentError` 误设到全局默认 → 全站不弹错。必须默认 `undefined`/false

- 列表页补 `route.query` 时覆盖用户已选筛选：仅在 **首次** 进入且 query 有 status 时写入
