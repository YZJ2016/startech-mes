## 1. Spec

### Capability

- Name: 写类 Tool 调用前中断等待人工确认，确认/拒绝后续跑同一次运行。
- Module: `riveredge-backend/src/apps/kuaiai/services/{agent_assembler,chat_service}.py`、`core/ai/runtime/{agent_factory,sse_adapter}.py`、`core/api/ai/router.py`、`apps/kuaiai/services/operations_service.py`（信任中心）。
- Priority: P0。
- Related requirement/design documents: 需求 25 SC-D3、SC-D8、§4.4；需求 16 KR-D15、KR-G3（2026-10-23 改判）；设计 26 §9；前置 spec 189（`kind`）、192（saver）。

### Business Goal

AI 不能在用户不知情时改业务数据：报工、改工单状态及今后所有写类 Tool，必须由当前用户看到将执行的动作并确认后才落库；拒绝则不执行且模型被告知。

### Scope

In scope:

- 装配：档案 Tool 中 manifest `kind=write` 的，生成 `HumanInTheLoopMiddleware(interrupt_on={name: {"allowed_decisions": [...]}})`；与现有 `build_mcp_aware_tool_guard` 并存（RBAC 与审计仍由 guard 在执行时完成）。
- `build_agent` 传入 spec 192 的 saver；`configurable` 带 `tenant_id`、`thread_id`。
- 流式：中断时发顶层扩展帧 `kuaiai_interrupt`（与现有 `kuaiai_tool` 同风格，不进回答正文）后正常收尾。
- 续跑：新增 `POST /api/v1/core/ai/chat/resume`，经网关委托到 kuaiai `chat_service`，`Command(resume={"decisions": [...]})` 续跑同一 thread，流式返回。
- 消息落库：中断前产生的 assistant（含 tool_calls）照写；续跑后的 tool 行与最终 assistant 行照写（KR-G3 方案 C）。
- 存量写 Tool `submit_production_feedback`、`update_workorder_status` 标 `kind=write`，自动受闸。
- 审计：确认、拒绝、过期各写一条 `core_ai_audit_logs`（`capability="tool_confirm"`，route `ai/tool/{name}/{approve|reject|expire}`，不落参数值）。
- 信任中心 `_hitl_feature_state` 改为真实装配判定：写类 Tool 存在中断配置 ∧ 装配使用 saver ∧ resume 路由已注册。
- 运行结束（无挂起中断）即 `adelete_thread`；挂起超期由过期策略清理。

Out of scope:

- 前端确认卡（spec 194）。
- 新增写 Tool（报异常、草稿类在后续 spec）。
- 工作流编排（KR-D16 仍不做）。

### 决策（2026-10-23 用户选定）

- **H1 = a**：写类 Tool 只在有会话时执行；抽屉选用含写 Tool 的档案时先经既有 `POST /api/v1/apps/kuaiai/sessions` 建会话并携带 `session_id`。无会话请求中出现写 Tool 调用时，后端拒绝装配该写 Tool 的中断（返回明确错误“写操作需要会话”），不以一次性 thread 执行。
- **H2 = a**：挂起期间同会话收到新消息，先补写拒绝 ToolMessage（“用户未确认，已取消”）并记审计 `reject`，再处理新消息。
- **H3 = a**：有效期读 `TenantConfig` 键 `kuaiai.hitl.pending_ttl_minutes`，缺省 30，合法 1..1440；未配置取 30（约定缺省值，同 Pulse 阈值语义）；值非法回落 30 并记脱敏配置告警；配置读取异常时失败关闭——本次写操作不进入挂起，回复“确认闸配置读取失败，请稍后重试”，不猜测有效期。
- **H4 = a**：只允许 approve / reject；resume 请求出现其他决策类型返回 422。

### Acceptance Criteria

1. 档案含写 Tool 时，模型发起该调用：流里出现 `kuaiai_interrupt` 帧（含 `thread_token`、`actions[{tool, label, args_summary}]`），Tool 未执行、业务表无变化。
2. `resume` approve：Tool 执行（RBAC/数据范围/业务校验照常），结果与最终回答流式返回并落库。
3. `resume` reject：Tool 不执行，模型收到拒绝说明并给出回复；落库 tool 行内容为拒绝说明。
4. 非本人、非本租户、已完成或已过期的 `thread_token` 调 resume：404，不泄露存在性。
5. 只读 Tool 不中断，行为与现状一致。
6. 服务重启后对挂起中的 thread resume 仍可完成（依赖 spec 192）。
7. 信任中心 HITL 卡在本单元合入后为 `ready`，证据数组列出三项真实检查；任一缺失为 `not_ready`/`partial`。
8. H1–H4 决策对应用例通过：无会话请求的写调用被拒；挂起时新消息先写拒绝再回答；有效期按 TenantConfig 生效、非法值回落 30、读取异常失败关闭；resume 非 approve/reject 返回 422。

### Rules and Constraints

Tenant isolation:

- `thread_id` 由服务端生成，形如 `{tenant}:{user}:{session}:{nonce}`（nonce 为每次挂起运行新生成的 uuid4 随机段，同会话两次挂起 token 必不同）；客户端只持有不透明 `thread_token`；resume 时按 tenant_id + user_id + session 复核归属。

Security and masking:

- resume 需 `kuaiai:act:execute`（与 chat/completions 相同）。`args_summary` 只含标量参数且截断，不含密钥或内部路径。
- 确认不绕过 Tool 自身的 RBAC 与数据范围：guard 仍在执行时检查。

Audit and lineage:

- 审计如 Scope 所列；审计语义为「决策记录」——resume 在会话行锁事务内完成
  claimed 标记 CAS + 决策审计同事务提交，并发 resume 只有一个成功（另一个
  404），不重复执行写 Tool、不重复审计；消息表为展示与审计真源，
  checkpoint 仅执行现场。
- 失败关闭：checkpoint 读失败一律拒绝——`_close_pending_thread` 读失败拒绝
  本次发送（不落 user 行），resume 读失败拒绝续跑，不静默放行残留挂起；
  已被认领且仍在宽限窗口（300s）内的挂起，同会话新消息拒发而非写「已取消」
  谎报。

AI/rule-engine rules:

- 中断只针对 `kind=write`；`recursion_limit` 沿用 `DEFAULT_RECURSION_LIMIT`。

Database rules:

- 本单元不新增表（表在 spec 192）；H3=a：只读 `infra_tenant_configs`，不补种。

## 2. Plan

### Implementation Approach

- `agent_assembler.assemble` 读 spec 189 目录取 `kind`，组装 HITL middleware 与 saver；无写 Tool 时不挂 HITL、不挂 saver（保持现状路径）。
- `sse_adapter.agent_to_openai_sse` 识别 `__interrupt__` 结果，转扩展帧；`chat_service` 在中断时落已产生消息、记录挂起元数据（thread_id、session、user、过期时间，存 checkpoint metadata，不新增表）。
- 网关新增 resume 路由，委托方式与 `/chat/completions` 相同（importlib 单名探测 kuaiai 模块级函数）。
- 过期：resume 与同会话新消息时惰性检查；另提供 `purge` 由既有 Taskiq 定时机制每 10 分钟调用（`kuaiai_hitl_purge_tick`，复用 `core/tasks` 现有调度注册方式）。

### Affected Modules

- Modify: `core/ai/runtime/agent_factory.py`（文档注释）、`core/ai/runtime/sse_adapter.py`、`core/api/ai/router.py`、`core/ai/chat_handler.py`（委托）、`apps/kuaiai/services/agent_assembler.py`、`services/chat_service.py`、`services/operations_service.py`、`manifest.json`（两份，写 Tool `kind=write`）。
- Test: `tests/apps/kuaiai/test_spec193_hitl_gate.py`；回归 spec 184 信任中心测试。

### Public Contracts

- 新增 `POST /api/v1/core/ai/chat/resume`：body `{thread_token, decisions:[{type:"approve"|"reject", message?}]}`，`stream` 同 chat/completions；响应为同格式 SSE。
- SSE 新扩展帧 `kuaiai_interrupt`：`{thread_token, expires_at, actions:[{tool,label,args_summary}]}`。
- 既有 `/chat/completions` 请求与响应外层不变。

### Persistence Changes

- 无新表；使用 spec 192 两表。

### Transaction Boundaries

- 写 Tool 内部事务不变；resume 的「claimed 认领 + 决策审计」在同一会话行锁事务内提交（`_lock_session_row` 复用），`_close_pending_thread` 收口整体并入同一把锁，使收口与在途 resume 互斥；审计写失败只记日志（沿用 `_audit_tool_call` 取舍）。

### Risks

- `create_agent` + HITL middleware 与现有 `_AgentRunTracer` 的消息收集在中断/续跑两段运行下需拼接正确：以测试固定两段落库顺序。
- 非流式（`sse_adapter` 非流式兼容分支）同样要支持中断：测试覆盖。

### Verification Strategy

- 单测/集成：中断、approve、reject、越权 resume、过期、重启后续跑（真实 saver）、只读 Tool 不受影响、H2 新消息处理。
- 手工：`/chat` 选含报工 Tool 的档案走通一次确认报工（前端 spec 194 完成后补浏览器记录）。
