## 用户故事

工厂管理员在知识库页上传工艺 PDF、作业指导书 Word、点检 Excel 或 Markdown 后，点解析能抽出可读正文（不是乱码），切块带文件名与页/表来源。已登录员工在对话里挂该库、或经 Agent `searchKnowledge` 追问「上面那份 SOP 第三步是什么」时，系统先把指代压成独立问句，再按本厂知识库检索、融合排序后注入模型。不要 Easy RAG 演示件，也不要把「整文件当 UTF-8 字符串再固定窗口切」当生产方案。

## 现网事实（以代码为准，禁止臆造）

核对仓库：`startech-mes-basic/`（2026-09-08 工作区，**未提交**）。编码前曾是 UTF-8 整文件 + Naive RAG + 无 `chunk_size` 列 + 向导固定三步，已被 90–94 覆盖。

## PR-D — 产品决策

- [x] **PR-D1** 目标形态。**已拍板：LangChain4j Advanced RAG，不是 Naive RAG，不是 Easy RAG。** 检索入口为 `DefaultRetrievalAugmentor`（QueryTransformer → QueryRouter → ContentRetriever(s) → ContentAggregator → ContentInjector）。禁止把 `AiServices.contentRetriever(EmbeddingStoreContentRetriever)` 当作唯一生产路径。禁止引入 `langchain4j-easy-rag`、进程内 `InMemoryEmbeddingStore`、ONNX 默认 bge 当本厂 embedding。
- [x] **PR-D2** 覆盖 A32 的范围。**已拍板：** 保留 overlap、分隔符、topK、minScore、chat 与 `searchKnowledge` **同一检索 facade**。A32「不做 rerank」**不**阻止本轨 `ContentAggregator`（RRF + Scoring 再排序）。仍禁止：BM25 / Azure / Elasticsearch hybrid；**单次检索**融合多种 `VECTOR_STORE_TYPE`；知识库直连 MES SQL（A7）。同进程多租户各用各的 type 见 V4 修订，不是本条禁止项。
- [x] **PR-D3** 文档解析。**已拍板：按类型走 LangChain4j `DocumentParser`，禁止整文件 UTF-8 兜底当成功。** 路由：`pdf` → `ApachePdfBoxDocumentParser`；`doc/docx/ppt/pptx/xls/xlsx` → `ApachePoiDocumentParser`；`md` → `MarkdownDocumentParser`（或与 txt 相同若 markdown 模块未纳入 BOM 则 `TextDocumentParser`）；`txt` → `TextDocumentParser`。扩展名与 Content-Type 不一致时以魔数/Tika 探测再路由；探测失败或抽出文本为空 → 解析失败（附件 `parse_status=2`），不得写入乱码片段。`ApacheTikaDocumentParser` **只作探测/未知但允许类型的回退**，不得替代 PDFBox/POI 主路径。
- [x] **PR-D4** 字节来源。**已拍板：** 仍从现网 MinIO `AiObjectStore` 读流。禁止 `FileSystemDocumentLoader` 扫服务器磁盘；禁止把 MinIO 对象下载到未隔离临时目录后当「本机语料库」。
- [x] **PR-D5** 索引管线。**已拍板：** 对齐 `EmbeddingStoreIngestor` 四段：**DocumentTransformer**（写入 `tenant_id` / `knowledgeId` / `attachId` / `file_name`，去空控制符）→ **DocumentSplitter**（`DocumentSplitters.recursive` + overlap>0；知识库 `chunk_separator` 作为优先切分）→ **TextSegmentTransformer**（段首附加文件名，有页/表则附加 `source_ref`）→ embedding（A24，`EmbeddingInputType.DOCUMENT` 仅当该模型 `supportedParameters` 支持，否则不传）→ **现网 `VectorStoreService`**。禁止换官方 `langchain4j-weaviate` 为本期主存储。
- [x] **PR-D6** Query 变换。**已拍板：必须 `CompressingQueryTransformer`**（用当前对话/Agent 的 A24 `ChatModel`，把多轮指代压成独立问句）。**默认开启** `ExpandingQueryTransformer`（压缩后再展开，条数小，默认 3，可 `sys_config` 关）。禁止 HyDE 进本期（PR-G2）。变换失败：回退原始用户问句，不 500、不跨租户检索。
- [x] **PR-D7** Query 路由。**已拍板：`DefaultQueryRouter` 扇出到本请求允许的每个 knowledgeId 的 ContentRetriever。** 禁止 `LanguageModelQueryRouter`（贵且可能漏库）。chat 只带一个 `knowledgeId` 则单 Retriever；Agent 用档案 `knowledgeIds`。
- [x] **PR-D8** ContentRetriever。**已拍板：** 自写 Retriever，内部调现网向量 `search(tenantId, kid, vector, topK)` + fragment 回表。Filter 只信 `TenantContext` + 已校验 kid，禁止客户端传 `tenantId`。query embedding 走 A24；支持则 `EmbeddingInputType.QUERY`。
- [x] **PR-D9** 聚合与再排序。**已拍板：** 先 `DefaultContentAggregator` 两段 RRF；再 `ReRankingContentAggregator`。Scoring 用本厂 A24 **chat 模型实现 `ScoringModel`**（结构化打分），**不**引入 Cohere / 新 SaaS。Scoring 失败或超时 → 保留 RRF 顺序（失败打开，不空检索）。候选上限为实现 spec 写死的小倍数（如 2×topK）。
- [x] **PR-D10** 邻块扩窗。**已拍板：** 向量命中后按同一 `attach_id`、`chunk_index` ±1 从 `ai_knowledge_fragment` 回表拼接（parent / window），再交给 Injector。禁止把整份附件塞进提示词。
- [x] **PR-D11** 注入。**已拍板：** `DefaultContentInjector`（或等价）注入片段；`metadataKeysToInclude` 至少 `file_name`、`source_ref`。提示词与 SSE **不含** 对象键全路径、MinIO 内网、apiKey。无命中仍纯对话（55 行为保留）。
- [x] **PR-D12** 接线。**已拍板：** `POST /ai/chat/send` 的 `knowledgeId`、`searchKnowledge`、以及挂知识的 Agent 对话，都走同一 `RetrievalAugmentor` facade。禁止再保留一条「只 embed 原句、不压缩、不聚合」的平行生产路径。单测可保留 Fake 向量。
- [x] **PR-D13** HTTP 契约。**已拍板：不改** `POST /ai/knowledge/attach/{id}/parse`、`POST /ai/chat/send`、`POST /ai/agent/send` 的 URL / method / 认证 / SSE `{content, done}`。解析失败 `msg` 对用户可读（如「无法从 PDF 提取文本」），不回堆栈与内部路径。
- [x] **PR-D14** 明确不做。**已拍板：本期不做** Easy RAG；`SqlDatabaseContentRetriever`；Web Search；Neo4j / GraphTransformer；OCR 扫描件（PR-G1）；官方 Azure/ES hybrid；把 fragment 原文改成进向量库而不回 MySQL。
- [x] **PR-D15** 依赖。**已拍板：** `ktg-ai` 增加无 version 坐标：`langchain4j-document-parser-apache-pdfbox`、`langchain4j-document-parser-apache-poi`、`langchain4j-document-parser-apache-tika`；markdown 解析器若在 1.19.x BOM 中则加 `langchain4j-document-parser-markdown`，否则 md 走 Text。父 POM 仍只 60 的双 BOM，禁止手写 version，禁止 `langchain4j-easy-rag`。
- [x] **PR-D16** 并行检索线程。**已拍板：** `DefaultRetrievalAugmentor` 自定义 `Executor` 必须拷贝 `TenantContext`（对齐 I-A4 / I-A7）。空上下文不得检索。
- [x] **PR-D17** 可运营旋钮。**已拍板（修订）：** 运行时可调 RAG 项**不写 yml、不新增 rag `@Value`。** ① 租户/全局默认走系统管理「参数设置」`sys_config`（`ISysConfigService.selectConfigByKey`，键前缀 `ai.rag.`）：展开开关、展开条数、是否再排序，以及切块/检索回落默认（`chunk-size` / `chunk-overlap` / `chunk-separator` / `top-k` / `min-score`）。② 知识库级覆盖走 `ai_knowledge` 列（现列 top_k / min_score / chunk_separator，加列见 PR-D19）。空列 → `sys_config`（本厂 overlay 优先，否则全局行）。禁止 yml 与 `sys_config` 双源。现网 `ruoyi.ai.rag.*` / `AI_RAG_*` **作为产品配置拆除**（实现 90/91 去掉对应 `@Value`）。yml / 环境变量留给启动基础设施。**共享向量集群地址/类型走 yml**（PR-D20），不是本条 `ai.rag.*`。密钥仍不进 yml 明文，也不进 `sys_config`。种子：Flyway **master** 全局行（`tenant_id` NULL），对齐 `mes.index.layout`；现网无既有 `ai.*` 键。缺键时 Java 硬编码与种子相同的 500 / 200 / `\n\n` / 5 / 0，仅防空库单测，不是第二套产品配置。
- [x] **PR-D18** embedding 模型。**已拍板：** 知识库可绑本租户 `category=vector` 的 `embeddingModelId`；空则仍取本租户第一条启用 vector 模型。未配置 embedding → 解析失败关闭（现网已如此），不得静默跳过向量当成功。
- [x] **PR-D19** 切块 size/overlap 上知识库页。**已拍板：** 管理员在现网知识库新增/修改对话框输入切块参数，不靠运维改 yml。`ai_knowledge` 增列 `chunk_size`、`chunk_overlap`（SQL snake；Java/JSON `chunkSize` / `chunkOverlap`）；与已有 `topK` / `minScore` / `chunkSeparator` 同一表单。空 = 不覆盖，回落 PR-D17 的 `sys_config`。校验：overlap **> 0** 且 overlap **<** chunk_size（对齐 `AiKnowledgeChunker` / `AiProperties.getRagChunkOverlap`：overlap≤0 非法；overlap≥size 则夹到 `size-1`）。不改 parse / chat/send / agent/send URL。列与 ingest 读路径：90；表单：92；检索 topK/minScore 读路径：91。**不把向量集群地址放进该对话框**（PR-D20 / 93）。
- [x] **PR-D20** 向量集群：共享走 yml，专库走开通向导。**已拍板（2026-09-08 再修订）：**「向量集群地址」= 现网 `ruoyi.ai.vector-store.*` 的 **type**（`weaviate` \| `dashvector`；未知失败关闭）、**Weaviate host**、**DashVector endpoint**。不是 MinIO、不是 chat 模型 host、不是知识库切块/RAG 旋钮。**不是** `/ai/knowledge`，**不是**工厂「参数设置」overlay。现网工厂可对 `sys_config` 同键插 overlay 且 overlay 赢 → 禁止把集群 URL 放进该表。
