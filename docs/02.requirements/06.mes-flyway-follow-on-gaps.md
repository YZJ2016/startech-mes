## A — 产品决策

- [x] **A1** 用 Flyway 管理切线之后的结构演进。**已拍板：** 历史 `backend/sql/` **不进**版本链（含 `ry_*`、xinhe dump、带 `DELIMITER` 的增量、以及切线前已落地的 21–35）。切线 = **Flyway 实现开工时** `sql/` 最后一号；本文落盘日仓库最后一号是 `20260827_35`，基线写作 `20260827.35`。开工时若又追加了手工号，先把那些号打进已有库，再把基线前移，然后才打开 Flyway。切线打开后，新发布 DDL 只走 Flyway，不再往 `sql/` 追加作为上线脚本。
- [x] **A2** 主库何时对齐。**已拍板：** 应用启动自动 migrate（覆盖主库上的全部 `ROW` / 平台）。失败则**拒绝启动**。结构未对齐不得对外服务。
- [x] **A3** 共享库租户。**已拍板：** `ROW` 与平台没有独立 schema。主库 migrate **一次**即覆盖全部非独立库租户。不要按租户循环打主库。专库不建全局表（菜单、租户登记、字典、Quartz 物理表等，对齐 I8）。
- [x] **A4** 新建独立库。**已拍板：** 平台点「创建 schema/表」当场：库不存在则创建 → Flyway 跑租户脚本全链建表 → 复制角色/角色菜单模板（不克隆菜单行、不复制物料）→ ping → `READY`。失败：登记保留、可重试、不删行、不把该厂数据写入共享主库；**应用进程不停**。开通同时进行最多 **2** 家（第 3 家拒绝，登记仍在）。
- [x] **A5** 已就绪独立库。**已拍板：** 启动时对该专库跑尚未应用的增量。一次性连接，**不建**专库连接池（专池仍等第一次业务访问）。启动时多家 READY 专库 **不限制并行**。
- [x] **A6** 已就绪专库启动迁失败。**已拍板（修订）：** 任一 `READY` 专库启动 migrate 失败 → **整个进程不启动**（平台与全部共享厂一并停）。失败不靠改 `provision_status` 来跳过坏库。修库后重启再迁。
- [x] **A7** 登录是否跑 DDL。**已拍板：** 不跑。独立库用户登录只看 `provision_status=READY`；未就绪拒登。文案仍「用户名或密码错误」（D9），不回落主库。**不**再比 Flyway 版本（能启动则认为当时所有 READY 专库已追上）。
- [x] **A8** 自动钉基线。**已拍板：** 禁止 `baselineOnMigrate`。空专库无记账表 → 从切线快照跑到最新（建表）。现网 / 已对齐实验室 / 已有 READY 专库：运维在启动前显式 `baseline` 到切线号。未钉就启动 → 主库按 A2 拒绝启动。
- [x] **A9** 已发布脚本。**已拍板：** 冻结。发现错误只加新版本，禁止改已发布文件字节（含只改注释：仍会变校验和）。
- [x] **A10** 空实验室平台库。**已拍板：** Flyway **不**从零建平台库。仍按 runbook 初始化 + 手工把 `sql/` 打到切线号 + 显式 baseline，再启动应用。禁止把 `ry_*` / dump 放进版本链。
- [x] **A11** 迁表器套数。**已拍板：** 落地前专库仍走现有文件清单。落地后只留 Flyway 一套；禁止与旧清单并行。

## I — 隔离 / 约束（不重开租户 I5 / I7 / I8）

- [x] **I1** 连接池。**已拍板：** 启动只建主池。专库 migrate 用一次性连接，不建专池。专库不可用禁止回落主库（I5）。
- [x] **I2** 开通并行。**已拍板：** 「创建 schema/表」同时最多 2 家（维持现网 I6）。与 A5 启动不限并行不是同一时刻，允许不同上限。
- [x] **I3** 全局表。**已拍板：** 租户脚本不得创建/修改 I8 名单表。菜单、字典、租户登记、Quartz 物理表只在主库。
- [x] **I4** 栈。**已拍板：** 不引入第二套 ORM / 认证。Flyway 只通过 JDBC 跑 DDL。依赖与配置留设计 05 / 实现 spec；未拆 spec 前仓库不加 `flyway-core`。
