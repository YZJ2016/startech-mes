## A — 产品决策

- [x] **A1** 用 Flyway 管理切线之后的结构演进。**已拍板：** 历史 `backend/sql/` **不进**版本链。Tenant 基线由 76 钉死为 **`20260825.31`**（catalog 尽头 `20260825_31_ai_tool_audit.sql`）。`20260826_32` / `33` 改 `sys_menu`（I8）；`20260826_34` / `20260827_35` 为平台种子，不抬 tenant 基线。切线打开后，新发布 DDL 只走 Flyway，不再往 `sql/` 追加作为上线脚本。
- [x] **A2** 主库何时对齐。**已拍板：** 应用启动自动 migrate（覆盖主库上的全部 `ROW` / 平台）。失败则**拒绝启动**。结构未对齐不得对外服务。
- [x] **A3** 共享库租户。**已拍板：** `ROW` 与平台没有独立 schema。主库 migrate **一次**即覆盖全部非独立库租户。不要按租户循环打主库。专库不建全局表（菜单、租户登记、字典、Quartz 物理表等，对齐 I8）。
- [x] **A4** 新建独立库。**已拍板：** 平台点「创建 schema/表」当场：库不存在则创建 → Flyway 跑租户脚本全链建表 → 复制角色/角色菜单模板（不克隆菜单行、不复制物料）→ ping → `READY`。失败：登记保留、可重试、不删行、不把该厂数据写入共享主库；**应用进程不停**。开通同时进行最多 **2** 家（第 3 家拒绝，登记仍在）。
- [x] **A5** 已就绪独立库。**已拍板：** 启动时对该专库跑尚未应用的增量。一次性连接，**不建**专库连接池（专池仍等第一次业务访问）。并行 **N≤2**（FLY5）。
- [x] **A6** 已就绪专库启动迁失败。**已拍板（75 FLY6）：** 该 `READY` 专库 migrate 失败 → 该行 `provision_status=FAILED`，**主库进程继续**（平台与 ROW 厂可服务）。修库后经既有「创建 schema/表」重试。08-28「整进程不启动」作废。
- [x] **A7** 登录是否跑 DDL。**已拍板（75 FLY7）：** 不跑。独立库用户登录须 `provision_status=READY`，且专库 tenant 版本追上主库已应用的 tenant 版本；落后或主库 tenant 版本不可读则拒登。文案仍「用户名或密码错误」（D9），不回落主库。
- [x] **A8** 自动钉基线。**已拍板：** 禁止 `baselineOnMigrate`。空专库无记账表 → 从切线快照跑到最新（建表）。现网 / 已对齐实验室 / 已有 READY 专库：运维在启动前显式 `baseline` 到 `20260825.31`。未钉就启动 → 主库按 A2 拒绝启动。
- [x] **A9** 已发布脚本。**已拍板：** 冻结。发现错误只加新版本，禁止改已发布文件字节（含只改注释：仍会变校验和）。
- [x] **A10** 空实验室平台库。**已拍板：** Flyway **不**从零建平台库。仍按 runbook 初始化 + 手工把 `sql/` 打到切线号 + 显式 baseline，再启动应用。禁止把 `ry_*` / dump 放进版本链。
- [x] **A11** 迁表器套数。**已拍板：** 落地前专库仍走现有文件清单。落地后只留 Flyway 一套；禁止与旧清单并行。
