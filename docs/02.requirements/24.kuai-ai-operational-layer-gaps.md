## 1. 用户目标

在不破坏本地已经完成的会话、Agent 档案、知识库、MCP 与应用连接器治理能力的前提下，补齐示例系统面向业务用户的运营入口。业务人员从“能力矩阵—智能体库—异常感知”发现和使用 AI，管理员从“知识语料—信任中心—调用分析—模型设置”观察和治理 AI；底层仍复用本地的 FastAPI、Tortoise、LangChain、应用连接器、RBAC、审计和租户隔离。智能体库采用已选方案 B 的“场景模板→租户 Agent 档案”映射：模板是展示/入口，档案是唯一执行底座，不再造 Agent 引擎。

## 2. 调研证据边界

- 页面事实来自 2026-10-10 在 1280×720、DPR 2 的示例环境实页观察；尺寸为浏览器可见区域测量值，允许实现阶段在同一断点内有 1–2 px 的浏览器取整误差。
- 已实际观察七个页面的稳定加载状态、主要按钮、表格、卡片、筛选与部分跳转；“打开 KU-Ask”已确认会打开右侧抽屉并自动发送卡片示例问题，“查看场景”已确认可跳入对应业务页。
- 示例系统的服务端源码不可见。本文不把未抓到的示例私有 API 路径、字段或算法写成事实；新增 API 以本地现有契约和页面需要反推设计。

## 5. 功能需求

### KO-01 通用页面壳

- [ ] 七个新增页面使用当前应用壳、面包屑/标签栏和 Ant Design，不引入第二套 UI 框架。
- [ ] 桌面基准内容区保持 951 px 可用宽度；侧栏展开时内页左边缘约为 viewport x=272，右边缘约为 x=1223。
- [ ] 标准页头高 96–112 px：标题 24 px/600，副标题 14 px，右侧动作高 32 px。
- [ ] 页面刷新只重载当前页数据；进行中的请求应取消或以最新请求结果为准，避免旧响应覆盖新筛选。
- [ ] 每页都有加载骨架、空状态、403、404/资源失效、5xx/网络失败与重试操作。
- [ ] 1280 px 以上按示例密度；960–1279 px 卡片减少列数；小于 768 px 单列，不允许横向溢出主页面。

### KO-02 能力矩阵

- [ ] 页头显示“能力矩阵”、说明文字和当前选用的 chat 模型；未配置时显示“未配置”，不得展示默认模型假值。
- [ ] 展示八个能力标签：智能问答、智能问数、智能实施、异常感知、智能录单、智能推荐、知识检索、可信执行。
- [ ] 展示近 7 日 AI 调用、Pulse 异常建议、语料条目、平均响应四张指标卡。
- [ ] 展示一个品牌视觉卡与八张能力卡；每张卡包含名称、就绪状态、说明和入口按钮。
- [ ] “打开 KU-Ask”打开既有助手抽屉；普通能力按钮跳到本地已注册路由。目标路由缺失或无权限时禁用按钮并给出原因，不跳 404。

### KO-03 智能体库

- [ ] 首期内置库存洞察助手、计划员顾问、采购跟单助手、排程解读助手、质量异常分析、供应商协同 Agent 六个后端场景模板；模板定义稳定 key、卡片名称/说明/插画、样例问题、能力标签和白名单业务路由；前端不得把六卡作为不可扩展的数据真源。
- [ ] KU-AI 安装时为该租户幂等创建六份与模板逐一绑定的真实 Agent 档案及场景实例；既有已安装租户在应用升级/同步时补齐缺项。六档案初始为 `status=停用`、`grant_mode=ROLE`（沿用现有档案页默认）、`default_model_id=null`、空授权名单，不自动授予管理员、角色或员工，也不自动启用；管理员随后在现有“Agent 档案”页自行选择 ROLE/USER、配置名单并启用。不得将六卡仅实现为无档案虚拟卡，不得覆盖租户已经定制、改绑、停用或手工授权的档案；重复安装/同步不重复建档、授权或清空配置。
- [ ] 预置档案各有稳定场景语义、可审查的专用提示词和最小只读 Tool 集合；新增真实 MES 只读 Tool 补足库存、生产交付风险、采购跟单、排程、质量异常、供应商协同，复用既有领域 service 和业务读权限/数据范围，不预置写 Tool、自动业务改单、MCP 凭据。业务功能必须由真实工具支撑，无合适数据/权限时说明缺项，不让 LLM 编造事实。
- [ ] 安装时不新建空知识库，不自动把租户所有知识库绑定到六档案；知识检索由管理员在原“知识库”准备语料，再在“Agent 档案”显式勾选准许使用的库，并启用检索 Tool；chat 连接未选用/无密钥、无相应业务权限或知识库无数据时分别给出待配置/无权限/无内容状态，不把“档案已预置”伪装成 AI 全部就绪。
- [ ] 新增按租户隔离的场景实例与预置/自建 Agent 档案映射；实例可覆盖模板的展示字段、绑定同租户已有档案、单项启停。档案停用/删除/无使用权时卡片仍可见但不能发问，不回退到无档案对话；手动解绑/删除后不得由安装同步暗中重绑。
- [ ] 有 Agent 配置权限的管理员可在预置场景之外按需从本租户已有档案复制一份停用的新档案并生成场景副本；复制不继承授权名单，须由管理员按既有授权流程授予使用权后启用；也可将已有档案重新绑定到场景。复制/改绑/编辑不得改变原档案或现有 `/agents` 契约。
- [ ] 每卡显示真实插图、名称、启用/未启用状态、场景说明、能力标签、样例问题、“打开 KU-Ask”和“查看场景”。不得用 emoji、CSS 图形或空白占位替代插图；新实例从后端返回，UI 不限制只能六张卡。
- [ ] 六个预置模板的 Settings 总开关与场景实例单项开关同时开启，且档案和 chat 可用，才允许自动首问；总开关缺失时默认 true 仅表示卡片可发现。任一开关关闭时卡片仍可见、发送禁用；“查看场景”若业务页可访问仍可用。
- [ ] 打开助手后自动发送该卡片 `sample_prompt`，同时传稳定场景 key 和已绑定 `agent_id`；携带场景 key 的请求由服务端复核当前租户模板/实例绑定、双开关、档案使用权和运行时配置，不能只靠前端按钮禁用；无场景 key 的原 `/chat` 保持既有行为。
- [ ] 查看场景使用服务端白名单业务路由映射，跳转前不创建 AI 会话；从模板复制的实例仅能指向合法目标路由。

### KO-04 异常感知

- [ ] 顶部显示异常总数、高优先级、紧急、警告与错误、涉及场景五项汇总。
- [ ] detector 不得把内部扫描批次上限当成业务总数；超过 200 条时汇总、领域总数和后续页仍须准确。允许分批有界读取，但不得新增截断式公开契约或留下失控后台任务。
- [ ] 异常按生产、库存、销售、质量、设备领域分组；没有条目的领域默认不渲染分组。
- [ ] 卡片显示严重度、领域、优先级、标题、事实摘要、建议和业务跳转。
- [ ] 检测规则必须由领域服务或只读查询确定，LLM 只能解释已有事实，不得生成数据库事实、不得执行任意 SQL。
- [ ] 首期至少交付示例已出现的生产工单延期与销售订单交期风险；销售风险阈值沿现有 TenantConfig 租户配置，键 `kuaiai.pulse.sales_delivery_risk`，缺省 `warning_days=3`（详见 spec 182）；其它领域在没有可核实规则前显示“尚未接入检测器”，不得返回伪造 0 正常。
- [ ] 单次加载超过 400 ms 显示骨架；超过 15 s 显示“仍在计算”及取消/重试；单一 detector 失败不拖垮其它领域，响应须携带局部错误。

### KO-05 知识语料

- [ ] 以跨知识库扁平表格呈现语料，现有知识库治理页保持不变。
- [ ] 顶部支持标题模糊搜索、高级筛选、重置、已索引/待索引/索引失败快捷筛选和“更多”折叠筛选。
- [ ] `/corpus` 支持加载出厂 FAQ、添加 FAQ、状态查看、跨库搜索、导出训练 JSONL、批量删除、批量索引/重试；文件上传与文本添加只在 `/knowledge`，语料页提供“前往知识库添加文档”。

- [ ] 表格列固定为选择框、标题、所属知识库、类型、分块数、创建时间、索引状态、操作。
- [ ] FAQ 必须选择当前租户启用知识库并填写问题、答案、启用状态；复用既有文档表的 `source_type=faq`、`faq_question`/`faq_answer`、`knowledge_id`、状态/切块/向量索引/删除生命周期；不另建 FAQ 表，首期不增加分类/标签或迁移。当前代码中的遗留列尚未产品化，交付前须补齐契约与索引正文适配。
- [ ] 删除、批量删除需二次确认；跨租户或已删除 ID 按资源不存在处理，批量结果逐项返回成功/失败，不做越权存在性泄露。
- [ ] JSONL 导出按当前筛选条件生成，文件只含允许训练的文本字段，不含 tenant_id、内部存储 UUID、凭据、错误堆栈。

### KO-06 信任中心

- [ ] 展示 RBAC 读权限、HITL 写门控、全链路审计三卡。
- [ ] 每张卡的状态由后端返回，值为 `ready|partial|not_ready`；本地 HITL 未实现前必须显示“未就绪/规划中”，不能照抄示例“已完成”。
- [ ] 展示与当前用户有关的 KU-AI 权限码及拥有状态，不向普通用户枚举全租户角色关系。
- [ ] 审计表复用现有 `/api/v1/core/ai/audit/logs`，显示时间、能力、路由、耗时、状态；错误信息默认隐藏，只有有权用户可查看脱敏摘要。
- [ ] 页面底部明确：任何写操作仍受原业务单据权限与服务规则约束。只有实际接入 propose/execute 后才能出现相应完成文案。

### KO-07 调用分析

- [ ] 提供近 7 天/近 30 天分段选择，切换后同时刷新指标、趋势、分布和最近动态。
- [ ] 展示总调用次数、平均延迟、Pulse 建议数、知识语料文档数。
- [ ] 折线图按日补齐缺失日期为 0；能力分布对 `null` capability 统一显示“未分类”。
- [ ] 最近动态支持分页，并显示时间、能力、路由、耗时、状态。
- [ ] 复用现有 stats/audit 契约，不为图表另造重复统计表。

### KO-08 模型设置

- [ ] 页面由“对话模型”“OCR 视觉识别”“智能体开关”“KU-AI 能力配置”四个区块组成。
- [ ] 对话模型下拉只列 `model_role=chat` 且启用的应用连接；保存后调用既有角色选用机制。
- [ ] OCR 不保存第二份明文密钥。视觉连接来自 `model_role=vision` 的应用连接；页面只显示已配置状态，留空密钥不覆盖。
- [ ] 六个预置模板总开关逐项保存，不以一个总开关替代；缺省默认 true 仅表示可发现；181 安装后六份真实预置档案已绑定，但实际可运行状态还取决于管理员是否已在现有 Agent 档案页配置 ROLE/USER 使用权并启用档案、租户场景实例单项开关、当前用户档案使用权和 chat 连接。预置缺失是安装/升级未完成，不是常规待手工建档。角色选用与能力配置保存到现有 `SiteSetting.settings.integrations.kuaiai`，一次事务原子提交，不复制到连接 config；租户场景实例与档案映射单独持久化。
- [ ] 能力项至少包含业务单据工具、知识语料 RAG、向量检索、RAG 条数、RAG 引擎、企业系统说明；RAG 条数范围 1–20，默认 5；当前唯一引擎显示“原生”，不允许重新启用已废弃的 llamaindex 产品选项。
- [ ] “重置”恢复最近一次服务端成功加载值，不立即写库；“保存”原子提交可编辑配置；“刷新”放弃未保存修改并重新加载。

### KO-09 审计修复与验收回收

- [ ] 智能体库的 chat 就绪只认当前应用连接运行时，不得以历史模型目录行兜底为可用。
- [ ] Hub“智能问数”仅在 chat 可用、Tool 总开关开启且至少一个已注册只读 Tool 可用时显示 ready；知识检索入口固定为 `/apps/kuaiai/corpus`。
- [ ] Settings 保存须在同一事务内锁定并重新校验所选 chat/vision IntegrationConfig，再锁定 SiteSetting 完成 version 比对与白名单深合并，避免校验与提交之间连接状态漂移。
- [ ] 当天超过计划完成时刻的工单显示“今日已逾时”，内部日期差为 0；跨业务日后才显示实际逾期天数，不把 0 天强制写成 1 天。

## 7. 权限与隔离

- [ ] 新增展示权限：`kuaiai:hub:display`、`kuaiai:library:display`、`kuaiai:pulse:display`、`kuaiai:corpus:display`、`kuaiai:trust:display`、`kuaiai:insights:display`、`kuaiai:settings:display`；所有新页面/读取 API 同时要求既有根入口 `kuaiai:entry:read`，尤其 trust/insights 调用 core stats/audit 仍按原有 entry 权限检查。
- [ ] 写权限细分为 `kuaiai:corpus:{create|update|delete|export}`、`kuaiai:settings:update`；场景复制、定制、绑定档案仅允许具备 `kuaiai:library:manage` 的管理员，绑定/克隆档案还需现有 `kuaiai:agent:read`，克隆另需 `kuaiai:agent:create`（已有档案的独立修改仍要求 `kuaiai:agent:update`），不得复用展示权限写入。两端 manifest 注册、预设角色与存量角色授权策略见 spec 181，升级验收见 186。
- [ ] 业务跳转仍由目标业务页面权限控制；拥有智能体库权限不等于拥有库存、生产、采购、销售或质量页面权限。
- [ ] 普通用户不得通过 URL 参数或请求 body 切换租户；平台超管仍沿用既有 `X-Tenant-ID` 规则。
- [ ] 日志、SSE、toast、审计与导出不得暴露 API Key、cipher、JWT、MCP token、内部路径或完整异常栈。
