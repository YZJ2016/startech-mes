## 用户故事

质量与仓储人员在未给物料配检验策略时，成品入库与来料入库仍被默认拦住，必须显式免检才能跳过；检验单中文质量态与批次英文质量态对得上。库存过账时序列号与批次同事务同锁，重试不双过账。库存成功则业财/成本副作用也成功，失败则整单同一成败；成品入库有存货/生产成本事件；金蝶推失败看得见。业务查询默认带本组织条件；超管跨组织显式可审计。单据关系只从一个入口写；工单拆分写关系失败则整单回滚。

## KR-CL — 闭环断点决策（已拍板）

- [x] **KR-CL1** 检验门禁与状态契约。**已拍板（D1–D4）：** 物料没有检验策略时，成品入库与来料入库都默认必检。免检只能走物料级显式策略。质量态：检验单中文「合格/不合格/待判定」；批次账 `qualified`/`pending_qc`/`quarantine`/`unqualified`；成品入库过账写批次 `qualified`，查检验单对「合格」。半成品一键入库同时接受工单英文 `in_progress`/`completed` 与中文「进行中」「已完成」。**范围只到检验与入库确认相关状态。不做 SPC/Cpk、不做 8D。** 实现单元：`docs/04.specs/140.kuai-inspection-gate-status-contract.md`。

  - **D1。** `require_fqc_before_finished_goods_receipt` 与 `require_incoming_inspection_for_receipt` 下线或只读展示，不参与 skip。禁止只改代码默认值：库里已存的来料开关 False 对存量租户不会因默认值变化而生效。开关不再被读取来放行，**不做** aerich 数据迁移把存量 False 翻成 True。无策略时无论这两个开关存何值都必检。
  - **D2。** 客供料登记与采购来料同一规则：无策略默认必检，免检仅物料级显式。`require_incoming_inspection_for_customer_material`（门禁键 `require_iqc_before_customer_material_confirm`）同样不再当放行口。本期覆盖的 assert：`assert_fqc_for_finished_goods_receipt`、`assert_iqc_for_purchase_receipt_lines`、`assert_iqc_for_customer_material_registration_lines`。采购退料没有检验 assert（`PurchaseReturnService.confirm_return` 只扣库存），本期不纳入必检。委外收货 `src/apps/kuaizhizao/services/outsource_material_receipt_service.py` 没有检验 assert，本期未覆盖、不新造检验类型。
  - **D3。** `assert_fqc_for_finished_goods_receipt` 在入参 `work_order_id` 为空时（1225–1226 行 `if not work_order_id: return`）不得直接 return 绕开 FQC。无策略仍默认必检。该函数同时被成品入库 `FinishedGoodsReceiptService.confirm_receipt`（`warehouse_service.py` 5136 行）与半成品入库 `SemiFinishedGoodsReceiptService.confirm_receipt`（374 行）调用；短路去掉后两条确认都受同一规则约束。
  - **D4。** `resolve_inspection_policy` 返回 `(eff, plan_id, source)`，代码里第三项名叫 `reason`。eff 全集：`none`、`simple`、`plan`。source 全集：`default_none`、`material`、`material_legacy`、`material_group`、`stage_disabled`、`module_disabled`、`work_order_override`、`work_order_operation`、`operation`、`operation_legacy`。无策略 source 只有 `default_none`（物料不存在、`inspection_stages` 为空、或 iqc/fqc/oqc 三环节 mode 都是 `none`）→ 必检，不得跳过。物料级显式免检的 source 字符串是 `material`，且 eff 为 `none`：`resolve_material_stage_policy_from_rows` 在 `inspection_stages` 非空且至少一环节 mode 不是 `none`（`has_custom`）时返回 `material`；当前环节 mode 为 `none` 时 eff 仍是 `none`、source 仍是 `material` → 放行。`material_legacy`、`material_group` 只在 mode 不是 `none` 时返回，表示要检。`stage_disabled`、`module_disabled` 表示组织环节或模块关闭，保持「该环节不启用」，不改判成 `default_none` 必检，也不当作免检配置。IPQC 的 `work_order_override`、`work_order_operation`、`operation`、`operation_legacy` 不作为物料免检口。现网 868–875 行在 eff 为 `none` 时丢弃内层 `material` 并返回 `default_none`；收口后这两个 source 必须能区分。修法是按 source 判定，不是删掉所有 `continue`。

- [x] **KR-CL2** 库存过账与序列号一致性。**已拍板（D6）：** 序列号与批次同一事务、同一把行锁（失败全滚）。幂等键在 `_increase_stock_no_atomic` 与 `_decrease_stock_no_atomic` 签名级强制：不传键即拒绝，禁止 `idempotent_stock_change` 在键空时直跑。公共包装 `increase_stock`/`decrease_stock` 在调用方未传键时按 `source_type` + `source_doc_id` + 动作合成确定性键（A 案），无法合成同样拒绝；其 20 个调用方不逐点补键、不计入 27 处清单，已显式传键的沿用显式键。验收是全部 27 处调用点都传键，包含半成品入库与客供料登记，不只 `warehouse_service.py` 15369 行的其他入库。保留负库存默认关、批号管理出库必带批号。**不拆** `warehouse_service`。调用点清单见 spec 141。实现单元：`docs/04.specs/141.kuai-inventory-serial-idempotency.md`。

- [x] **KR-CL3** 业财与库存同一成败。**已拍板（D5）：** 禁止吞掉会计事件后假装成功；成本失败不得留下已过账库存（与库存同一成败）。成品入库必须产生存货/生产成本事件（不能只记数量）。常数 30 喂的是统计/预估展示（`reporting_service.py` `_get_reporting_estimated_wage_rate` 490 行 → `get_reporting_statistics` 的 `estimated_wages`；API 副本 `api/productions/reporting.py` 122 行 → 概览统计），不是过账金额。缺 `estimated_wage_rate` 时该字段返回 null 并带「未配置」标记，接口其余数据照常返回；禁止整端点报错；禁止回退 30。若同一数值被拿去当记账金额，缺配置则该笔记账失败（与库存同一成败），不得静默用 30。金蝶推送失败必须变成可见「未推送」（放在本缺口，不另开）。保留：借贷不平拒绝记账；结账默认预检；不新增 `skip_checks=True` 偷跑。**依赖 KR-CL1 与 KR-CL2。** 实现单元：`docs/04.specs/142.kuai-finance-inventory-same-fate.md`。

- [x] **KR-CL4** 租户查询强制隔离。**已拍板（D7、D9）：** 一个机制强制组织条件，覆盖租户模型的读，以及 queryset 写：`.filter(...).update()` / `.delete()`。机制不能只收读。空组织上下文失败关闭。超级管理员跨组织必须显式且可审计；默认仍本组织。`DataScopeService` 是组织内行权限，不与组织间隔离混层。本期要收口的是经 API handler 可达、作用于租户模型的读和写（含 `filter().update()` / `delete()`）。约 12509 处 `tenant_id=` 含写入赋值与注释，不是泄漏条数，本期不要求改完这些字面，也不上 RLS。`TenantQuerySet.filter` 高扇入是方法名碰撞，不是采用证据。**可与 KR-CL1 并行设计，但 KR-CL1–CL3 的新查询合并前必须满足本缺口。** `02.mes-multi-tenant-gaps.md` 针对 Startech，不是本修法契约源。实现单元：`docs/04.specs/143.kuai-tenant-query-forced-isolation.md`。

- [x] **KR-CL5** 追溯单一关系。**已拍板（D8）：** 主写入入口定为 `document_relation_new_service`（`create_relation`、`batch_create_relations`、`delete_relation`；引用面约 46 个文件）。旧 `document_relation_service`（约 11 个引用文件、仅引旧 4 个，现为追溯读）改为薄委托，或停止被新代码调用。选择不留到实现 PR。工单拆分时关系写失败必须整单回滚。`split_type==operation` 继续拒绝，不实现工序拆分。**不拆**仓储/工单上帝服务。本缺口不挡住 KR-CL1–CL4（除拆分关联写路径自身须遵守租户约定）。实现单元：`docs/04.specs/144.kuai-document-relation-single-entry.md`。
