## 用户故事

设备数据经现场 Modbus TCP Agent 进入云侧。云侧认出设备、收下报文、留下最新值，并按节流写回星制造设备状态。随后补上告警与预填、边缘配置与续传、物模型与趋势、事件与指令。最后把设备运营馈送登记为星报表的一条 HTTP 数据源，同时种入一张已绑定该源的设备运营大屏，设计器仍可改布局。

## 前置与先后

- [x] **KIO-D1** 前置。星报表 KRP-P1–P5 收口之后才开本域编码。此前报表不出现数采专用接口。
- [x] **KIO-D2** 六步都纳入本文件，顺序锁定。前一步的能力未具备时，不把后面的平台连接器或报表衔接提前当入口。

| 编号 | 步 | 能力边界 |
| --- | --- | --- |
| **KIO-W1** | 入站闭环 | 设备 token、HTTP 入站、幂等、最新值快照、至少 5 秒节流写回设备状态 |
| **KIO-W2** | 护栏与预填 | 状态护栏、点位模板、阈值告警、报工/点检预填 |
| **KIO-W3** | 边缘运行时 | 边缘配置下发、心跳、断网批量续传。OPC UA / S7 先做配置校验。Agent 仍只跑 Modbus TCP |
| **KIO-W4** | 物模型与趋势 | 产品物模型、批量建设备、离线告警、趋势。趋势只认租户自建 InfluxDB；未配置时趋势不启用，不用 `tag_history` 顶上，W1 的快照和写回仍然可用，见 **KIO-D8** |
| **KIO-W5** | 事件与指令 | 事件、指令闭环、设备分组、消息追踪 |
| **KIO-W6** | 报表衔接 | `equipment-ops-feed` 作为星报表的 HTTP 数据源。登记时种入已绑定 `ops_metrics` 等路径的大屏，设计器仍可改布局。数据源类型仍是 HTTP。OEE 随本步计算，见 **KIO-D7** |

OEE 只在同时有传感器状态分段和已审核报工良品率时计算。放在 KIO-W6，见 **KIO-D7**。

MQTT Broker 不内置。需要时外接。MQTT 订阅、ThingsBoard、JetLinks 是六步之后的后续完善，见 **KIO-D6**，不插入 W1–W6。

## KIO-D — 已拍板

- [x] **KIO-D3** 落点。云侧新建 `apps/kuaiiot`，骨架对齐 `apps/kuaiai`。表用现成 `apps_kuaiiot_*`，不另起一套，不改已经进过库的迁移文件名。忽略规则与 `PRO_APPS` 去掉本应用，不对这个目录做私仓组装。现场 Agent 继续用仓内 Modbus TCP 程序，不在本文件重写 Agent。
- [x] **KIO-D4** 与报表的衔接只有 W6 一处。接上之后，设备运营大屏是一块普通大屏，不是报表里的数采专用接口。
- [x] **KIO-D5** 与主工程隔离。不合并进 `startech-mes-basic`。CAT-A09 仍为对照轨道的默认后置。
- [x] **KIO-D6** 平台入站后续完善（2026-09-28）。MQTT 订阅、ThingsBoard 拉遥测、JetLinks 拉遥测都要做，但不在 KIO-W1–W6 内。六步收口后再开，不插入任一步，也不改 W6 的报表衔接。三条路的终点与 HTTP 入站相同：点位进入同一条入站、快照与写回。MQTT 只做订阅客户端，Broker 仍由现场自备，星数采不内置。本决定不把这三项写成可放弃项。实现单元见 spec 156（`docs/04.specs/156.kuaiiot-platform-inbound.md`）。
- [x] **KIO-D7** OEE 放在 KIO-W6（2026-09-28）。随 `equipment-ops-feed` 一起算，结果放进 `ops_metrics`（如 `oee_live`）。不在 W1–W5 单列，也不在 W5 与 W6 之间加一步。仅当同时有传感器状态分段和已审核报工良品率时才计算。缺一则该指标空着，不填默认值。馈送里的其它字段照常给出。状态分段来自 W1 已写回的设备状态，不为 OEE 提前造指标。
- [x] **KIO-D8** 趋势只认租户自建 InfluxDB（2026-09-28）。趋势在 KIO-W4。未配置 InfluxDB 时，趋势不启用；W1 的最新值快照和设备状态写回仍然可用。`apps_kuaiiot_tag_history` 不作为无 Influx 时的趋势数据源，不用于趋势折线，也不做降采样替身。该表已在迁移 519，本决定不删表、不改已经进过库的迁移文件名。未另拍板前，产品不往这张表追加采样来充当历史趋势。

### 新增已拍板边界

- **KIO-D9（方案 A）**：core 管连接地址、认证凭据、连接启停与公共连接测试；kuaiiot 管数采映射、采集设备与 MES 设备绑定及采集运行。两者建立租户内关联，不维护两份独立凭据。现有 URL、method、认证头和响应外层结构保持。

### 本轮已选策略（2026-10-07）

用户已授权推荐方案：单调快照，同时间首值保留，旧样本只进历史，未知状态保持未知，坏质量不写业务值；Agent 先持久化采样身份、有限补传、缓存满停采；独立心跳、逐点隔离、最后成功配置离线启动、候选验证后替换；指令结果持久化重试回执，不重复执行。历史和触发/恢复通知采用事务待投递记录及 Taskiq 重试。确认/处置保留审计。

OEE 两端统一三因子，维护理想节拍和明确计划窗口，断采或缺因子返回空值及原因。Web 提供结构化点位、现场原始/转换值试读和分段诊断；当前发布入口只提供 Agent 实际可执行的 Modbus TCP 保持寄存器及 HTTP 上报。平台基线为 ThingsBoard 4.4、JetLinks Community 2.10.0。留存沿用业务配置参数 kuaiiot_retention_days；未维护时报告需要配置，不擅自清理，清理只针对过期消息日志和已完成投递。
