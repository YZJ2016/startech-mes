## P1-D — 产品决策

- [x] **P1-D1** 目标形态。**已拍板：MES 内嵌助手。** 不是再做一个 AI 平台。不做独立对话端、不做游客聊天。
- [x] **P1-D2** Maven / 包 / HTTP。**已拍板：** 新建 `ktg-ai`，包 `com.ktg.ai`，HTTP 前缀 `/ai/**`。`ktg-admin` 依赖该模块。Controller 薄层，业务在 `ktg-ai` service。
- [x] **P1-D3** 认证。**已拍板：仅现有 Spring Security JWT。** 对话必须登录。禁止 `/ai/chat/**` 进入 `MesPermitAllProvider`。禁止 Sa-Token、第二套 `SecurityFilterChain`、第二套 Token 服务。
- [x] **P1-D4** 租户。**已拍板：** 表 `tenant_id bigint NOT NULL`，加入 `tenant.line.include-tables`。上下文只信 JWT `LoginUser`。默认 **ROW**；`DATABASE` 租户仍写 `tenant_id`，表进专库 catalog，禁止回落主库。
- [x] **P1-D5** 上传。**已拍板：默认仍 `POST /common/uploadMinio`。** 不引入 OSS。Phase 1 **无**知识库上传。
- [x] **P1-D6** 前端。**已拍板：只改 `startech-mes-front/`。** 不改遗留 `frontend/`。不引入 `vue-element-plus-x`、UnoCSS、hook-fetch、Ant Design Vue、Vben、TypeScript 工程形态，不提交 lockfile。
- [x] **P1-D7** 模型供应商。**已拍板：对话走 OpenAI 兼容协议**（DeepSeek / 自定义 `apiHost`）。Phase 1（57–59）运行时曾为 JDK `HttpClient` + Jackson 解析 SSE。**现行出站**已由单元 61 改为 LangChain4j Chat/Embedding API（`(tenantId, modelId)` 工厂）。父 POM 双 BOM（`docs/04.specs/60.ai-langchain4j-bom.md`）：`dev.langchain4j:langchain4j-bom:1.19.0`（内部管理 Boot 4 starters `1.19.0-beta29`）与 `dev.langchain4j:langchain4j-community-bom:1.19.0-beta29`。禁止改用过期的 `langchain4j-spring-bom`。仍禁止 Sa-Token、第二套 `SecurityFilterChain`、MyBatis-Plus。平台当期 Agent 见缺口 03 的 A25，**不**在 57–59 实现。白名单 MCP 见 A27 / 设计 06 §5.3，**不**在 57–59 / 61 实现。运行时改写证据：`docs/04.specs/61.ai-langchain4j-runtime.md` 第 4 节。
- [x] **P1-D8** 密钥。**已拍板：** 落库加密（AES-256-GCM，主密钥 `${AI_MODEL_CIPHER_KEY:}`，不复用 `TENANT_JDBC_CIPHER_KEY`）**或**行内空 Key 时运行时回退 `${AI_DEFAULT_API_KEY:}`。列表与 `options` **永不**回明文 `apiKey`；详情可回打码。禁止回 cipher。出站必须用当前租户该 `ai_model` 行的 Key（**P1-D15**）。
- [x] **P1-D9** UI 对照。**已拍板：只读参考** `ruoyi-web` 对话交互、`ruoyi-admin` `views/chat/{provider,model}` 字段清单。不拷其技术栈。
- [x] **P1-D10** 明确不做。**已拍板：不进 Phase 1（57–59）：** RAG、Agent、MCP、workflow、短剧、coding harness、ruoyi-ai 租户套餐、登录租户下拉。禁止匿名 `/workflow/run`。禁止会话 API 使用 `/system/message`。平台当期 Agent 另见 A25 / 设计 06 §5.2；受控写/MCP/已登录工作流另见 A26–A28 / 设计 06 §5.3。不要在本三页里做。
- [x] **P1-D11** 许可闸。**已拍板（修订）：`@PreAuthorize` + 菜单权限与工厂 `mes_module.ai` 许可闸同时生效。** 工厂（非平台 `tenantId==0`）调用 `/ai/**` 须当前租户有效 `module_code=ai`；过期视为未许可 → 403。平台租户策略按 I-A2 / 49。**禁止**按「无许可也能调 `/ai`」实现。历史：57–59 落盘时本条曾写「Phase 1 不建工厂套餐，许可闸留给 48–56」；该分期已被 `docs/04.specs/49.ai-foundation-p0.md` 覆盖，与缺口 03 **A9 / I-A2** 对齐。57–59 的 HTTP 信封与权限字不因此重开。
- [x] **P1-D12** 表。**已拍板：** `ai_provider`、`ai_model`（单元 A）；`ai_session`、`ai_message`（单元 B）。模型分类 `chat` 先用；`vector` / `rerank` 列保留但对话拒绝。
- [x] **P1-D13** HTTP 契约。**已拍板：下列路径冻结**（见各 spec  verbatim 块）。分页信封 `code/msg/data` 与 `rows`+`total`。全部需登录。
- [x] **P1-D14** 权限字。**已拍板：** `ai:provider:list|query|add|edit|remove`，`ai:model:list|query|add|edit|remove`（`ai:model:*`），`ai:chat:list|send`。
- [x] **P1-D15** ChatModel 生命周期。**已拍板：厂商/模型/apiKey 仍只在 DB**（`ai_provider` / `ai_model`），**不**进 yml。出站客户端按 `(tenantId, modelId)` 懒建缓存；每个租户用自己的 apiKey 请求。**不**要求租户间密钥互不可见。禁止全局 `ChatModel`、禁止启动按租户各造一个实例。证据：`docs/03.design/06.mes-ai-platform-plan.md` §5.1。实现：`docs/04.specs/61.ai-langchain4j-runtime.md`（已落地）。
