## 用户故事

仓库过账时，读不到批号/序列号管理开关就拒绝，不能当成没开管理放行。工单没有 BOM 时，下达前的缺料检查拒绝下达，不能当成不缺料。委外收货与采购来料、客供料同一套来料规则：没配检验策略就必检，只有物料上显式免检才放行。采购预付批量补齐某一单失败时，这一单在采购订单上留成未补齐。需求、仓储、销售、财务、半成品、采购、发票合并的单据关系删除、更新和内部创建，都走 `document_relation_new_service` 的 `create_relation` / `delete_relation`，失败按设计写死的语义处理。序列号能查出在哪张出入库单上；明细行上的序列号仍只是录入。关键工序未检验不得把数量算成产出；让步必须有已处理的不良单。方案模式未检完不算工序完成，这条保持。简易模式不能再只凭报工合格数算工序完成。

## KR-PG — 决策（已拍板，代码未改）

- [ ] **KR-PG1** 检查失败必须拒绝。
  - 要什么：仓库管理标志读失败时，入库的批号与序列号强制校验改为拒绝过账，不能 warning 后继续。工单没有 BOM 时，下达前的缺料检查拒绝下达，不能返回「不缺料」。
  - 坏结果：读失败或没有 BOM 仍过账、仍下达。
  - 不做：不改变「开关明确为关」时的跳过；不改变有 BOM 时的下达缺料拒绝；不把出库读标志失败再包一层（出库已经会冒泡）；不把无 BOM 的拒绝扩到开工、报工、看板查询。

- [ ] **KR-PG2** 委外收货套用来料检验。
  - 要什么：与采购来料、客供料相同。判定只用 `inbound_inspection_required`：没配策略（source `default_none`）必检；source `material` 且 eff `none` 才放行；`stage_disabled` / `module_disabled` 放行。检验单据仍是来料检验单，不新造检验类型。
  - 坏结果：未检的委外收货变成已完成并入库。
  - 不做：不把采购退料纳入；不改采购来料与客供料已经按 spec 140 收口的放行口；不另做一套免检开关。

- [ ] **KR-PG3** 采购预付补齐失败留在单据上。
  - 要什么：批量补齐某一单失败时，该采购订单标成未补齐，然后才能处理下一单。已有预付关联的单标成已补齐并跳过生成。
  - 坏结果：失败只打日志，单据上看起来和「还没跑过」一样。
  - 不做：不因此中断已经成功的其他订单；不改单笔 `ensure_prepayment_payment_for_purchase_order` 已有的抛错；不把销售预收批量补齐写进本条（现网没有对称的销售批量函数）。

- [ ] **KR-PG4** 内部单据关系的删除和更新收口。
  - 要什么：上表现网事实里的内部删除、更新、创建，迁到 `document_relation_new_service`。创建走 `create_relation`，删除走 `delete_relation`。每一处失败语义以设计为准：整单回滚、显式幂等成功，或拒绝。
  - 坏结果：关系没写成、没删掉，业务单据却已经成功。
  - 不做：金蝶、飞书、OA 推送上的 `DocumentRelation.create` 不迁。不使用 `batch_create_relations` 的逐条跳过语义来假装收口。不拆仓储/工单服务。

- [ ] **KR-PG5** 序列号单据归属。
  - 要什么：增加出入库留痕台账，能按序列号查出这件货经过哪些单据、当前落在哪张单上。明细行 `serial_numbers` 仍是录入口。撤回追加反向留痕，不删历史行。
  - 坏结果：只能看到在库/已出库，看不到单据。
  - 不做：不造第二套序列号主数据（`MaterialSerial` 仍是序列号身份与当前状态）。不做多级投料族谱。不改 spec 141 已经落地的行字段和库存幂等键语义。

- [ ] **KR-PG6** 过程检验卡住报产出。
  - 要什么：关键工序未检验不得把数量算成报产出；让步必须有已处理的让步接收不良单。方案模式「未检完不算工序完成」保留。简易模式不能再只凭报工合格数算工序完成。关键工序沿用过程检验策略的 `plan` / `simple` / `none` 与 source，不另起关键工序标志。
  - 坏结果：简易模式或状态报工在未检验时把工序打成完成，末道未检验仍记产出或自动入库。
  - 不做：不改方案模式已经用过程检验放行数量计算的可转下道数量。不新造 8D。不把 eff 为 `none` 的工序（无策略、环节关闭、模块关闭）改成必检。
