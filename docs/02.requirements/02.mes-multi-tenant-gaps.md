## D — 决策待确认

- [x] **D1** `sys_config` 分层：全局内置键（验证码、注册开关）与租户覆盖值如何共存。**已拍板：** 全局键 + **可空 `tenant_id` overlay**（有租户行则覆盖，否则用全局）。`DATABASE` 租户读全局键须走主库。缓存键策略见已关闭的 R1（实现在 P2）。
- [x] **D2** 登录租户码时机。**已拍板：从第一天起始终必填。** 交互 `POST /login` 必须发送 `tenantCode`，不提供「单启用工厂可省略」。管理端只走 Vue3（F1），无 Vue2 兼容切序。移动端同一套 F5（F7），不是 Vue2 替代路径。
- [x] **D3** 平台运营账号。**已拍板：拆分。** 现网 `admin`（`user_id=1`）只操作租户 1；平台租户（`tenant_id=0`，`is_platform` 落库，强制 `ROW`）另建账号：`user_name=platform`，`tenant_id=0`，**不是** `user_id=1`。角色 `platform_admin` 永不许可给工厂。口令**不写进 SQL**；首次启动从环境变量 `PLATFORM_ADMIN_PASSWORD` 做 BCrypt 写入；生产缺该变量则拒绝启动。**SQL 永不跳过 `tenant_id`，包括 admin。**
- [x] **D4** `GET /loginOuth` 的租户绑定。**已被 F7 取代。** 原「省略 `tenantCode` → 租户 1」作废。移动端与管理端同一套 F5：Host 命中则写死该厂；未命中必须带码；缺 Host 且缺码则失败。禁止把 OAuth 凭据或 JDBC 密码暴露到租户管理 API。
- [x] **D5** 跨租户报表是否进入 v1。**已拍板：不进 v1。** 普通 MES 报表与 UReport 均仅当前租户；平台也不做跨租户报表（不只是「特权 SQL 仪表盘」不做）。即便将来做，SQL JOIN 只能覆盖共享库上的 `ROW` 租户，不能跨 `DATABASE` 专库。P10 不立项。UReport 注入方式见已关闭的 I1。
- [x] **D6** 租户停用后在线会话。**已拍板：立即作废该租户全部 Redis token**；下一请求 401。同时拒绝新登录。`DATABASE` 租户同时 **卸载专池**（不删库）。作废方式见 R6：SCAN `login_tokens`，按值中 `LoginUser.tenantId` 删除；不改 key 前缀、不加二级 SET。
- [x] **D7** v1 范围：枚举落库 vs 真正路由。**已拍板：** P0 持久化 `isolation_level` + 加密 JDBC；**P-D 在 P4 之后**实现懒加载 DS 路由（进 v1）。第二个 `ROW` 工厂不依赖 P-D；启用任何 `DATABASE` 工厂必须先有 P-D。P-D 未落地时 `DATABASE` 租户 **失败关闭（拒登录）**，禁止静默打主库、永不写入共享库。
- [x] **D8** 创建后变更隔离级别。**已拍板：v1 直接禁用改档。** 不预留迁数工单入口。更新 API **拒绝**改 `isolation_level` 与 JDBC 目标。ROW↔DATABASE 迁数不进 v1。
- [x] **D9** 登录失败文案。**已拍板：统一**「用户名或密码错误」。不单独返回「租户不存在」或「密码错误」。租户码当秘密的一部分，禁止用文案扫工厂编码。
- [x] **D10** 种子编码与域名。**已拍板：** 平台 `tenantCode=platform`（tenant_id=0）；首个工厂 `default`（tenant_id=1）。**都不绑** `server_name`。当前无真实生产用户，不绑生产域名；上线后由平台页再配 Host（F10）。

## S — schema / 表分类

- [x] **S1** 缺 CREATE 的 Mapper 表分类。**已拍板：** 有工厂业务行 → 租户表；纯平台目录/调度元数据 → 全局；无 Mapper 无引用 → 废弃候选（不进拦截器 include）。禁止靠表名前缀 `sys_` 当全局。调查 4.2 节 23 张全部为**租户表**，按波次进 include：P4 `drawing_manage`、`md_item_capacity`、`md_meeting_minutes`、`md_product_packing`、`md_turnplate`、`sys_camera_configuration`；P5 `pro_assessment`、`pro_evaluation`、`pro_maintenance_records`、`pro_sales_invoice`、`pro_sales_order`、`pro_sales_order_item`、`pro_task_auto`、`pro_task_turnplate`、`pro_workorder_tool`、`wm_after_salse`、`wm_tool_position`；P7 `cal_plan_workstation`、`tm_purchase`、`tm_purchase_line`、`tm_tool_log`、`tm_tool_purchase`、`tm_tool_purchase_line`。`sys_notice_detail` 随 S5 通知加列，不进 P4。`sys_camera_configuration` 虽带 `sys_`，只被 MES 摄像头 Mapper 使用，按租户隔离。`sys_user_online` 不是表（走缓存）。`pro_trans_consume` 有 CREATE、无 Mapper XML → **废弃候选**。DDL 须现网 `SHOW CREATE TABLE` 补脚本，禁止跑仓库空的 `05` 文件。某波次开始前该波次表必须已分类且加列。`DATABASE` 专库启用前须具备与主库当前波次对齐的同等列。
- [x] **S2** 谁管理定时任务。**已拍板：一期仅平台**可建/改/删 `sys_job`。工厂管理员看不见定时任务菜单、不能自助调度。`sys_job` / `sys_job_log` 仍加 `tenant_id`；平台自己的任务写平台租户；若平台为某厂配置任务则该行 `tenant_id` 为该厂，执行时切该厂上下文（I3）。`QRTZ_*` 仍全局（主库），JobKey 含租户以免冲突。`DATABASE` 的 job 行在专库。
- [x] **S3** 自动编码是否按租户流水。**已拍板：是。** `sys_auto_code_rule/part/result` 唯一键改为 `(tenant_id, rule_code)` 及对应流水键，两厂互不抢号。专库保持同一套 `(tenant_id, 业务键)` DDL。同厂重复规则码：空库检测通过即加 UNIQUE（S4 窄口已关）。
- [x] **S4** 两厂是否允许相同物料/业务编码（如 `md_item.item_code`）。**已拍板：允许。** 唯一性为 `(tenant_id, 业务键)`，不是全局唯一。`DATABASE` 专库保持同一套复合唯一键，不改为「仅业务键」唯一，以免两套 Mapper XML。
- [x] **S4 实现细节（窄）** **已拍板：空库不做脏数据治理。** 当前无既存工厂业务数据。加 `(tenant_id, 业务键)` UNIQUE 前仍跑 `GROUP BY tenant_id, 业务键 HAVING COUNT(*) > 1`；计数为 0 则直接加索引。不为 0 才保留最小 id、其余改 `{原键}__dup_{id}` 或软删，**禁止**重复未清时 `ADD UNIQUE`，**不自动合并**工单/库存。覆盖键由各波次 spec 列出（至少 `item_code`、客商编码、仓/车间编码、工单号、`sys_auto_code.rule_code`、同租户 `user_name`）。以后从旧库导入时沿用同一门禁。
- [x] **S5** 公告/铃铛是否按租户。**已拍板：按租户隔离。** v1 **不做**平台群发所有工厂。`sys_notice` / `sys_notice_detail` / `sys_notice_read` 与 MES 铃铛路径一并加 `tenant_id`，不得用若依 3.9 公告已读 HTTP 覆盖。平台群发属后续需求。
- [x] **S6** JDBC 口令与加密密钥。**已拍板：** 专库 **JDBC 口令**（不是工厂登录密码）**只许平台覆盖重填**（只写不回填，与 F4 一致）。算法 **AES-256-GCM**（JDK `AES/GCM/NoPadding`）；密钥只来自环境变量 `TENANT_JDBC_CIPHER_KEY`（32 字节，hex 或 base64），IV/nonce 每次随机并与密文同存。**加密密钥轮换不进一期。** 缺密钥时：有 `DATABASE` 租户则拒绝启动，保存 JDBC 则失败。`isolation_level=ROW` 且 URL/用户/口令任一非空 → **HTTP 400**，不落库、不静默丢弃。列表打码、揭明文须审计。禁止把 cipher 回传。工厂不能改 JDBC。URL/库名仍按 D8 不可当改档。

## I — 集成旁路

- [x] **I1** UReport 如何注入租户。**已拍板：** Servlet Filter 在 `/ureportM/**` 与设计器 `/ureport/**` 请求链入口从 JWT 设 `TenantContext`（及 P-D 后的 DS 路由）；报表数据源走与业务相同的租户路由，不得单独绑死主库。空上下文不得跑未加 `tenant_id` 的报表 SQL。`DATABASE` 专库报表 **失败关闭、禁止回落主库**（专库不可用则报错，不查共享库）。实现落 P8 spec。产品范围仍见 D5（仅本租户，v1 无跨租户报表）。
- [x] **I2** 对象存储隔离。**已拍板：单 bucket + 对象键前缀 `tenant/{id}/`。** 禁止在租户 API 中下发存储凭据。隔离级别不改变对象键规则。空上下文拒绝上传。
- [x] **I3** 线程池 / 异步 / Quartz 上下文。**已拍板：不用 `InheritableThreadLocal`。** `threadPoolTaskExecutor` 用 `TaskDecorator`：提交时拷贝 `TenantContext` + `SecurityContext` + MDC `tenantId`，`finally` 全部 clear。`AsyncManager`/`AsyncFactory` 的 `TimerTask` 同样捕获；登录日志能解析到租户则写 `sys_logininfor.tenant_id`，否则写 `0`。`AbstractQuartzJob.before` 用 `SysJob.tenantId` 设上下文（P-D 后再切专池），`after` clear；任务无 `tenantId` 则失败关闭，不跑租户 SQL。`CallerRunsPolicy` 也走同一套 set/clear。P2 单测：两租户交错异步不串；空上下文写租户 Redis 键抛错。P-D 再测专库 Job 打到正确 DS。
- [x] **I4** 缓存键策略。**已拍板（R1 + D1）：** `RedisCache` **不**自动加前缀；租户键由 `TenantCacheKeys` 组装；空 `tenantId` 写租户键 → 抛异常。全局键（验证码、字典；菜单缓存同属全局）保持全局、手写 `CacheConstants`。`sys_config` overlay 见 D1。实现改动在 P2 各调用点，不改 `RedisCache` get/set。字典/菜单**内容**仍共享，不按租户拆缓存。
- [x] **I5** 懒加载连接池。**已拍板：** 启动**只建主池**，禁止启动时把所有租户池一次性建齐（那是参考框架 `jugg-master` 的做法，不是本项目名）。专池拷主池参数，但 `initialSize=0`、`minIdle=0`，`maxActive` 单独配置，默认 **8**。开通：迁表 + ping 成功后，**第一次业务访问**才建专池。停用：`close` 并从路由表摘掉，不删库。门禁：`主池 maxActive + N×专池 maxActive + 余量(建议 20) ≤ MySQL max_connections × 0.7`；再开一个 `DATABASE` 会超上限则拒绝开通。专库不可用 **禁止回落主库**。验收：停用后连接数回落。
- [x] **I6** 专库 schema 演进。**已拍板：由应用**把与主库同一套增量 SQL 打到每个 `DATABASE` 租户。与 I7 同一条路径。
- [x] **I6 建表失败。** **已拍板：** 登记**保留**，标 **未就绪**，不可登录；可改 JDBC 口令/权限后重试「创建 schema/表」，不用重填基本信息。禁止删除登记；禁止把该厂数据写入共享主库。并行 N、`CREATE DATABASE` 权限验收、与发布流水线衔接在 P-D spec 写死（不再作为产品开放项）。
- [x] **I7** 新厂开通与专库谁建。**已拍板（修订）：** 空租户 + 复制角色/角色菜单授权模板（不克隆 `sys_menu` 行），**不复制物料等主数据**。`DATABASE`：应用建 schema + 同一套租户表增量，迁后再 ping 才可登录。失败处理见 I6（保留未就绪、可重试，不删登记、不写共享主库）。全局表不进专库（I8）。JDBC 账号须能 CREATE DATABASE 与 DDL。自动建库**不是** D8 改档迁数。
- [x] **I8** `DATABASE` 请求访问全局表。**已拍板：忽略名单 Mapper 整接口绑定主库 DataSource。** 不按 SQL 表名运行时回切（JOIN/子查询易漏）。不引入 MyBatis-Plus `@DS`；在现有 `DynamicDataSource` / `DataSourceAspect` 之上扩展：这些 Mapper 固定主池，即使当前请求已绑专池。名单：`sys_tenant`、`sys_tenant_license`、`sys_menu`、`sys_dict_*`、`QRTZ_*`、`gen_*`、`sys_config`（全局键与 overlay 都在主库，用可空 `tenant_id` 区分，不拷进专库；对齐 D1）。禁止把菜单/字典/许可复制进专库。专库宕机时：全局 Mapper 仍读主库；业务 Mapper **失败关闭、禁止回落主库**。实现落 P-D spec。单测：专库无 `sys_menu` 时 `getRouters` 仍成功。
- [x] **I9** WebSocket 站内信推送。**已拍板：v1 必须隔离，不跳过。** 现网 `WebSocketUsers` 以 **username** 为会话 key，`MessageProvider` 按 `recipientName` 推送；多租户后同名会串租。P2（依赖 P1 的 `LoginUser.tenantId`）：key 改为 `{tenantId}:{userId}`；推送按当前租户 + `recipientId`；无 tenantId 拒绝建连；禁止跨租户广播与客户端按裸用户名投递。端点路径不改。MQ / Feign / Jugg 开放域验签 / BPM 现网未使用，仍为 v1 非目标。`sys_message.tenant_id` 随 S5 波次加列，不替代本条会话隔离。

## F — 前端

- [x] **F1** 管理端是否改 Vue2。**已拍板：管理端只走 Vue3**（`startech-mes-front/`）。Vue2（`frontend/`）不再作为上线管理端，不兼容、无切序。多租户 UI 全部只做 Vue3。
- [x] **F2** Vue3 `getInfo` 租户展示字段。**已拍板：** 工厂会话增加可选 `tenantId` / `tenantName`；**不**回传 `isolationLevel`、许可清单、JDBC。隔离级别只出现在平台租户管理接口。模块显隐只靠 `getRouters`。保持 `code/msg/data` 信封。登录后不再传租户头。
- [x] **F3** 平台运营 vs 工厂/平板菜单。**已拍板：端职责拆开，不按端克隆菜单。** 平台租户管理（CRUD、JDBC、许可、runAs）**只**在 Vue3 PC 管理端（`startech-mes-front/`），永不进平板，不混入车间平板路由。平板与 PC **都走 F5**（域名优先，否则手填 `tenantCode`）——与 F7 一致，不重开。一台平板终端**通常只属于一个租户**；平板菜单由**该工厂租户**分配（工厂管理员给平板用户赋角色/菜单），不是平台下发一套全厂共用平板菜单。`sys_menu` 仍是一份全局表；平台用 `sys_tenant_license` 许可模块；工厂在许可范围内给用户（含平板用户）赋角色→菜单。平台模块（租户管理）**永不许可给工厂**，工厂即使想赋也赋不到。平板工程尚未入仓；入仓后客户端仍须白名单车间路由，`getRouters` 可能多回管理页，平板不得注册 `/platform/**`。平台运营只用 Vue3 PC；平板不是 runAs 或租户管理面。精确 Vue3 路径（如 `/platform/tenant`）spec 时再定；**PC 平台运营 vs 工厂/平板菜单由租户分配**这一拆分已关。
- [x] **F5** 登录如何得到 `tenantCode`。**已拍板：域名优先，编码输入兜底（互补）。** 匿名接口只按当前 Host 匹配 `sys_tenant.server_name`，命中返回这一个 `tenantCode`；未命中显示编码文本框。禁止未登录拉全量租户下拉或按用户名反查所属租户。`POST /login` Body 仍必填该码。`server_name` 非空全局唯一。管理端与移动端同一规则（F7）。
- [x] **F6** 域名命中后能否改登别厂。**已拍板：不能。** 命中则写死该厂，不提供「使用其他编码」。平台运营必须用平台自己的域名或未绑定入口。工厂域名进不去平台账号。
- [x] **F7** 平板/手机登录。**已拍板：与管理端同一套 F5。** `MobileLogin` 与 `GET /loginOuth` 均适用。Host 命中写死该厂（F6）；否则必填 `tenantCode`。**取代 D4。** 省略码且 Host 未命中 → 失败，不默认租户 1。
- [x] **F8** 自助注册 / 找回密码 / 改密。**已拍板：v1 关闭自助注册。** 找回/重置走同一 F5（域名或手填编码），禁止租户下拉。验证码登录前全局、不按租户。改密在已登录会话内，租户来自 JWT。
