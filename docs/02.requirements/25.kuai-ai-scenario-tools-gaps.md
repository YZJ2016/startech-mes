# KU-AI 制造场景与 Tool 目录缺口清单

- 日期：2026-10-23
- 目标仓库：`kuaigeyun-mes/riveredge-backend`、`kuaigeyun-mes/riveredge-frontend`
- 详细设计：`docs/03.design/26.kuai-ai-scenario-tools-plan.md`
- 上游基线：`docs/02.requirements/16.kuai-ai-rebuild-gaps.md`、`docs/02.requirements/24.kuai-ai-operational-layer-gaps.md`
- 状态记号：`[x]` 已由用户决策或现有代码确定；`[ ]` 尚未实现或待决。本文是需求与差距，不代表代码已完成。

## 1. 用户目标

KU-AI 底座（会话、Agent 档案、知识库/RAG、MCP、运营层、11 个 Tool）已基本完成。结合 MES/MOM 工厂实际场景与智能制造行业标准，把现有业务功能封装为 Agent 可调用的 Tool 或知识库；Tool 粒度既不零散、也不过度封装，尽可能跨场景复用。

## 2. 已确定的决策

- [x] **SC-D1 Tool 粒度**：业务对象中心 + 闭集枚举视图（方案 B）。一个 Tool 对应一个业务对象或一项可复用分析能力；场景差异由 Agent 档案表达，不按场景新增 Tool。（用户 2026-10-23 选定）
- [x] **SC-D2 存量 Tool**：按新目录合并/改名，并以 aerich 数据迁移改写 `enabled_tools`；不保留别名映射。（用户 2026-10-23 选定）
- [x] **SC-D3 写路径**：先实现 HITL 确认闸，再开放新增写 Tool（方案 C）。本条**推翻 KR-D15“本期不做”**；机制沿用 KR-G3（LangGraph interrupt + checkpointer，`Command(resume)` 续跑同一 run，消息表仍写、checkpoint 只存执行现场）。存量写 Tool 同步纳入确认闸。（用户 2026-10-23 选定）
- [x] **SC-D4** 禁止通用 SQL / 自然语言查库 Tool（延续需求 24 §9）。
- [x] **SC-D5** LLM 不参与风险、严重度、计数、合格判定；只转述领域 service 事实（延续设计 24 §6.2）。
- [x] **SC-D6 能力矩阵打通**：能力卡由后端绑定智能体库场景实例；点击时携带实例 `agentKey` + 绑定 `agentId`，复用既有 `guard_scene_agent_key`、档案使用权与模板/实例开关；卡片状态按绑定档案的实际可用性计算（方案 A）。不走按名称解析的「默认助手」路径，也不把能力卡降为纯导航。（用户 2026-10-23 选定）
- [x] **SC-D7–SC-D15**：原待决 O1–O9 已于 2026-10-23 逐项选定，结论见 §5。

## 4. 需求清单

### 4.1 场景目录

- [ ] 以设计 26 §4 的 26 个场景为目录真源；每个场景实现前须在 spec 中逐项核实候选 service 的签名、数据范围与权限码，未核实不得写成契约。
- [ ] 首批（P1）场景：S01 S02 S06 S07 S08 S09 S11 S12 S21（SC-D12）；S09 写操作在 HITL 落地后接入。

### 4.2 Tool 目录与粒度

- [ ] 按设计 26 §5.2 定稿 Tool 名、视图枚举与权限码；按 SC-D7 对照实际权限码拆分后，P1 为 23 个、全目录约 35–40 个（设计 26 §5.2）。
- [ ] 每个只读 Tool：闭集参数、`limit ≤ 20`、有界摘要文本、真实空结果、失败关闭固定文案；service 不收 current_user 时补 DataScope，并有越界测试。
- [ ] 每个 Tool 只挂一个业务权限码，同一 Tool 的全部视图共用该权限；视图需要不同权限码时拆为独立 Tool（SC-D7），handler 内不做按视图的二次权限判断。
- [ ] `query_pulse_signals` 复用 `run_pulse`，不另写判定。

### 4.3 存量合并迁移

- [ ] `query_workorder` + `list_workorder_tasks` → `query_work_orders`；`query_purchase_followup` + `query_supplier_orders` → `query_purchase_orders`；`query_inventory_balance`、`query_delivery_risk`、`query_published_schedule`、`query_quality_anomalies` 同批改为新目录名（SC-D13），一次迁移完成。
- [ ] aerich 数据迁移改写 `apps_kuaiai_agent_profiles.enabled_tools`（去重保序）；迁移命名遵守 AGENTS.md 14 位时间戳规则。
- [ ] 同步 `constants.py`、manifest `ai_tools`、handler、`agent_scene_service.py` 预置模板、前端常量与标签、既有测试。
- [ ] 合并后视图输出不得少于旧 Tool 已有字段（预置档案行为不劣化）。
- [ ] 新增只读接口按 manifest `ai_tools` 返回 Tool 名、显示标签、是否写类、权限码；前端档案页从该接口取可选 Tool，删除前端硬编码闭集 `KUAI_AI_TOOL_NAMES` 与 `TOOL_LABELS`（SC-D9）。接口为新增契约，不改既有接口。

### 4.4 HITL 确认闸

- [ ] 写 Tool 在 manifest 声明需确认；装配时转为 `HumanInTheLoopMiddleware`，与现有 RBAC/审计 guard 并存。
- [ ] `build_agent` 接入 checkpointer；thread 绑定租户 + 会话；checkpointer 基于 Tortoise 自实现 `BaseCheckpointSaver`，表结构走 aerich 迁移，不引入 psycopg 或 `langgraph-checkpoint-postgres`（SC-D8）。
- [ ] 自实现 saver 须有接口契约测试（put / get_tuple / list / put_writes），并列为 langgraph 升级时的必跑回归项。
- [ ] 中断时 SSE 下发待确认动作；新增确认/修改/拒绝端点经 `Command(resume)` 续跑；不改 `/core/ai/chat/completions` 既有 URL、method、响应外层。
- [ ] 确认、修改、拒绝均入 `core_ai_audit_logs`；消息表照写。
- [ ] `submit_production_feedback`、`update_workorder_status` 纳入确认闸。
- [ ] 信任中心 HITL 卡改为真实装配判定，落地前仍显示 not_ready。

### 4.5 Pulse 与页上下文

- [ ] inventory、quality、equipment detector 接入既有领域判定 service，沿用局部失败、超时与去重契约。
- [ ] 页上下文扩展复用 L1 格式化函数，仍只信服务端白名单。

### 4.6 知识语料

- [ ] 提供制造语料分类指引（设计 26 §6），不新增知识表。
- [ ] SOP 发布（`publish`）与作废（`obsolete`）后投递 Taskiq 异步任务，按 SOP 版本幂等入库或下架到配置的目标知识库；任务失败不回滚 SOP 发布，失败可见并可重试（SC-D11）。
- [ ] 待 S11 spec 核实：SOP 载体内容能否被现有解析器处理；目标知识库配置位置；KU-AI 未安装时任务的处理方式。

### 4.7 能力矩阵与档案打通

- [ ] 需要对话执行的能力卡（至少 `data_query`；`guide`、`recommend` 落地时同规则）由后端返回绑定的场景实例 key 与可下发的 `agent_profile_id`；前端打开助手时写入 `agentKey` + `agentId`，不再只传 `capabilityMode`。
- [ ] 后端发送路径复用 `guard_scene_agent_key`（同租户实例、模板总开关、实例 enabled、`agent_id` 与绑定一致、档案启用/使用权、chat 就绪），不新增第二套守卫。
- [ ] 能力卡状态按「当前用户点击后实际会走的路径」计算：未绑定、档案停用、无使用权、chat 未就绪、档案未勾选任何业务 Tool 均不得为 `ready`，`disabled_reason` 写明具体原因；不再以全局注册表存在 Tool 判就绪。
- [ ] 绑定关系写入站点设置 `integrations.kuaiai` 槽（键名由 spec 定，如 `capability_bindings`），在 `/settings` 配置；复用 settings 既有版本锁、深合并保存与闭集校验，不改场景实例表结构（SC-D14）。
- [ ] `ask` 卡保持纯对话路径 A，不绑定档案（SC-D15）。
- [ ] 不改 `GET /operations/hub` 既有字段语义，只新增字段；不改 `/core/ai/chat/completions` 契约。

### 5.1 原选项与理由（存档）

| 编号 | 场景 | 选项 | 推荐与理由 |
| --- | --- | --- | --- |
| O1 | 一个 Tool 的视图跨不同业务权限码（例：设备与模具、各检验类型权限不同）；`tool_bridge` 每 Tool 只能挂一个 permission | a. 权限边界即 Tool 边界，跨权限就拆 Tool；b. Tool 挂入口权限，handler 内按视图二次校验 | **a**：守卫仍集中在 `tool_bridge` 一处，审计 403 口径不变；b 把权限判断分散进各 handler，长期易漏 |
| O2 | checkpointer 持久化 | a. 新增 `langgraph-checkpoint-postgres`（psycopg，自建表不经 aerich）；b. `InMemorySaver`（单进程，重启丢待确认）；c. 基于 Tortoise 自实现 `BaseCheckpointSaver`，表走 aerich | **c**：守住“表结构只走 aerich、不引第二套数据库访问栈”红线，多实例部署可用；代价是自维护 saver 接口 |
| O3 | 前后端 Tool 闭集来源 | a. 前端常量与后端常量手工同步；b. 前端从后端接口取可选 Tool 列表（含标签） | **b**：单一真源，后续增删 Tool 不再出现 5 vs 11 的漂移 |
| O4 | 管理层问数（S25）是否使用 kuaireport 系统报表数据集 | a. 暂不开放；b. 先给数据集补用户级数据范围再开放；c. 仅租户管理员可用 | **a**：数据集当前只有租户过滤，S25 先用 L1/L2 Tool 组合汇总，数据范围补齐另立缺口 |
| O5 | 已发布 SOP 是否自动同步进知识库 | a. 管理员手动上传；b. `publish`/`obsolete` 内同步调用入库/下架；c. 发布/作废投递 Taskiq 异步任务按版本幂等入库/下架 | **c**：满足文件控制（作废版本须下架）；不拖延发布事务，embed 失败或 KU-AI 未装不阻断 SOP 发布；Taskiq 为现栈 |
| O6 | 首批场景范围 | a. 采纳设计 26 P1 九个；b. 用户另定 | **a**：均以现有成熟只读 service 为主，复用 L1/L2 核心 Tool，能最快验证粒度模型 |
| O7 | 非重复存量 Tool（`query_inventory_balance`、`query_delivery_risk`、`query_published_schedule`、`query_quality_anomalies`）是否同批改为新目录名 | a. 同批改名，一次迁移；b. 只合并重复，其余保留原名 | **a**：只迁移一次 `enabled_tools`，目录命名一致；分两批会产生两次数据迁移 |
| O8 | 能力卡→场景实例的绑定存放与配置入口 | a. 写入站点设置 kuaiai 槽（如 `capability_bindings`），在 `/settings` 配置；b. 场景实例表增加「承接能力」字段，在 `/agent-library` 配置；c. 后端常量固定映射到预置模板 key，不可配置 | **a**：与 `agent_switches` 同处、复用 settings 既有版本锁与深合并保存，不动实例表结构；c 无法覆盖租户复制的场景 |
| O9 | `ask`（智能问答）卡是否也绑定档案 | a. 保持纯对话路径 A；b. 同样绑定场景实例 | **a**：纯问答本无业务 Tool 需求，路径 A 已可用；绑定会让未配置档案的租户失去基础问答 |
