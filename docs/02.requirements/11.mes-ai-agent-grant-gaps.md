## 用户故事

工厂管理员在 Agent 档案页增删改档案（提示词、Tool、MCP、知识库）时，必须有配置权限。一线员工不能改档案。

通用档案按 **角色** 分配（例如「车间班组长」都能用「报工助手」）。只给少数人的档案按 **人员** 分配（例如只给几位领导「经营看板助手」）。**一份档案只能选一种分配方式**，不能角色和人混挂。

员工打开 `/ai/chat` 或 F1 抽屉时，下拉只出现自己被授权的启用档案。没有授权的档案看不见，也不能靠改 `agentId` 打 send。选中档案之后，报工/改工单/MCP 仍走既有 Tool / MCP 权限，授权不能绕过 MES 字。

## 现网事实（以代码为准，禁止臆造）

核对仓库：`startech-mes-basic/`（2026-09-09）。

| 项 | 现网 |
| --- | --- |
| 配置 CRUD | `GET/POST/PUT/DELETE /ai/agent/profile`；权限 `ai:agent:profile:list\|query\|add\|edit\|remove`；页 `views/ai/agent/index.vue` |
| 下拉 | `GET /ai/agent/profile/options`：本租户全部 `status=0`；权限 `profile:list\|query` **或** `ai:chat:list`；不分页。对话页 / F1 用 `listAgentProfileOptions()` |
| 发送 | `POST /ai/agent/send` 只 `@PreAuthorize ai:chat:send`；`assemble(agentId)` 只校验本租户启用档案，**不**查角色/人员授权 |
| 未选档案 | 前端走 `POST /ai/chat/send`（无 Tool） |
| 未传 `agentId` 的 send | 后端 `requireDefault()` 默认助手 |
| Tool / MCP | 档案决定挂载子集；写 Tool 再查 `mes:pro:*`；MCP 再过 `AiMcpGuard` |
| 配置权 ≠ 使用权 | 无 `profile:*` 的对话用户，只要有 `ai:chat:list` 就能在下拉看到全部启用档案 |

## AG-D — 产品决策

- [x] **AG-D1** 配置权。**已拍板：增 / 删 / 改档案（含授权名单）只允许有对应配置权限的人。** 沿用现网 `ai:agent:profile:add` / `edit` / `remove`（列表/详情仍 `list` / `query`）。不新造 `ai:agent:profile:grant` 字。无配置权不能打开档案管理页改字段或改授权。**授权 UI 做在现有 Agent 档案维护页**（`/ai/agent`，`views/ai/agent/index.vue` 新增/修改对话框），不新开菜单、不新开独立授权页。
- [x] **AG-D2** 配置与使用分离。**已拍板：有配置权不等于自动有使用权。** 管理员要在对话里试用某档案，必须按 AG-D3 把自己的角色或自己这个人写进该档案授权。
- [x] **AG-D3** 使用授权二选一。**已拍板：每份档案 `grantMode` 只能是 `ROLE` 或 `USER`，互斥。** `ROLE` 挂本租户 `sys_role.role_id`；`USER` 挂本租户 `sys_user.user_id`。同一档案禁止两种 target 同时非空。切换模式时另一侧名单清空（同一保存事务）。
- [x] **AG-D4** 角色模式。**已拍板：** 当前用户的**任一**本租户角色命中该档案角色名单即可用（并集）。角色必须本租户、状态正常；跨租户 roleId 保存失败关闭。停用角色不产生授权。
- [x] **AG-D5** 人员模式。**已拍板：** 仅名单内的本租户用户可用。不看角色。跨租户 userId 保存失败关闭。授权行仍只存 `userId`。部门树仅 USER 模式选人 UI（AG-F2），不是 `grantMode=DEPT`。
- [x] **AG-D6** 空名单。**已拍板：失败关闭。** `status=正常` 的档案，对应模式的名单不得为空（启用前必须至少挂一个角色或一个用户）。停用档案允许空名单。空名单启用保存 → 400。
- [x] **AG-D7** 可见性前置。**已拍板：** `GET /ai/agent/profile/options` **只返回当前用户有使用权的启用档案**。对话页与 F1 下拉都只消费这份列表，不再在前端做第二套过滤当安全边界。无使用权的档案不出现在下拉。
- [x] **AG-D8** 发送闸。**已拍板：** `POST /ai/agent/send` 在组装 Assistant 前校验对 `agentId`（未传则对默认档案）的使用权。无授权 → **403**，不得挂载该档案 Tool/MCP/提示词，不得静默改走 `chat/send` 或另一份档案。URL / method / SSE 信封不变。
- [x] **AG-D9** 未选档案。**已拍板：不重开 A36。** 下拉未选（空）仍 `POST /ai/chat/send`。前端不得把「看不见任何档案」自动改成 `agent/send`。
- [x] **AG-D10** 默认档案。**已拍板：** 未传 `agentId` 的 `agent/send` 仍解析租户默认档案，但必须通过同一使用权校验；不通过 403。默认档案与其它档案同一套 `grantMode`，无特权。
- [x] **AG-D11** 调用面仍双重闸。**已拍板：** 使用权只决定「能否选用该档案」。写 Tool / 工单查询 / MCP 仍走 62/83/`AiMcpGuard` / MES `@PreAuthorize`。授权名单不能代替 MES 权限字。
- [x] **AG-D12** 不新造「每档案一个权限字」。**已拍板：** 不生成 `ai:agent:use:{id}` 之类 Spring Security 权限。授权是档案上的数据名单，读当前 `LoginUser` 的 userId / 角色 id。
- [x] **AG-D13** HTTP 增量。**已拍板：不改** `/ai/agent/profile`、`/options`、`/ai/agent/send` 的 URL / method / 认证头 / `code/msg/data` / SSE `{content, done}`。profile 写/读 **追加** `grantMode` + `roleIds` / `userIds`（只填与模式匹配的一侧，另一侧空数组）。options 元素形状仍 `{ id, agentId, name, defaultModelId, status }`，不下发授权名单、提示词、Tool、MCP。
- [x] **AG-D14** 存量迁移。**已拍板：** 已有启用档案 → `grantMode=ROLE`，绑定**该租户全部状态正常的角色**（近似现网「有对话入口的人都能看到」；无对话权限的角色即使被绑也打不开 options）。已有停用档案 → `grantMode=ROLE`、名单可空，启用前必须按 AG-D6 补名单。新建档案启用前必须选模式并至少一名单。
- [x] **AG-D15** 管理 list/详情。**已拍板：** 档案管理页 list 仍返回本租户全部档案（含停用、含当前用户不能使用的），否则管理员无法给「自己用不了」的档案做授权。options 与 list 继续分工。
- [x] **AG-D16** 会话恢复。**已拍板：** 打开旧会话时，若会话上的 `agentId` 当前用户已无使用权或档案已停用，选择器清空，不得带入 send。不删历史消息。
- [x] **AG-D17** 删角色/删用户。**已拍板：** 悬挂 id 不产生授权（查询时忽略）。不在本轨做「删角色级联清 grant」的独立产品页；保存档案时以提交名单为准整表覆盖该档案授权行。
- [x] **AG-D18** 明确不做。**已拍板：本期不做** 按部门/岗位作为授权模式（AG-G1；**选人用部门树 ≠ 按部门授权**）；授权有效期；按档案再拆 Spring 权限字；工作流节点选档案；Vue2；把 send 改成匿名或进 `MesPermitAllProvider`。

## AG-I — 隔离 / 权限

- [x] **AG-I1** 只信 JWT / `LoginUser` / `TenantContext`。body 禁止 `tenantId`。`isAdmin()` 不得关租户拦截器，也不得跳过使用权校验。
- [x] **AG-I2** `ai_agent` / 授权表 SQL 必须带 `tenant_id`。跨租户 `agentId` / roleId / userId → 404 或 400，不泄漏他厂名称。
- [x] **AG-I3** `/ai/**` 必须登录；不进 `MesPermitAllProvider`。不新开匿名 options。
- [x] **AG-I4** 日志 / SSE / toast 不打印密钥、MCP token、内部路径。403 文案可说「无权使用该助手」，不回他厂档案字段。
- [x] **AG-I5** 新表进租户 include 与专库 catalog；DDL 只走 Flyway `db/migration/tenant/`（切线后规则）。不改历史 `backend/sql/`。

## AG-F — 前端

- [x] **AG-F1** 只改 Vue3 `startech-mes-front/`。不改 `frontend/`。不引入 element-plus-x / UnoCSS / hook-fetch；不提交 lockfile。
- [x] **AG-F2** 档案页。**已拍板：授权做在现有维护页 `/ai/agent`（`views/ai/agent/index.vue` 新增/修改对话框），不新开菜单、不新开独立授权页。** 管理 list 仍全量（AG-D15）。模式单选「按角色 / 按人员」。`ROLE`：角色多选 + 按名称筛选；不强制部门树；复用 Vue3 `src/api/system/role.js` 的 `listRole`（现网 `GET /system/role/list`）。`USER`：选人 UI，不是按部门授权；左侧/上侧部门树，右侧（或同区）该部门下人员多选，仍可按用户名/昵称筛选；提交体仍是 `userIds` 数组（96 契约不变）。复用现网用户管理口：部门树 `GET /system/user/deptTree`（`src/api/system/user.js` 的 `deptTreeSelect`）；人员列表 `GET /system/user/list`（同文件 `listUser`，query 带 `deptId`，并可带 `userName` / `nickName`）。不新造 path、不新造组织权限字。切换模式清空另一侧并提示。启用保存时前端也拦空名单（以后端 400 为准）。
- [x] **AG-F3** 对话页 / F1：继续 `listAgentProfileOptions()`；有 `ai:chat:list` 或 `profile:list|query` 才渲染选择器（不重开 73 显示条件）。列表内容以后端过滤为准。无可用档案：选择器可空，发送走 `chat/send`。
- [x] **AG-F4** axios 仍 `src/utils/request.js`；SSE 仍现网 `fetch` + Bearer。不传客户端租户头。
