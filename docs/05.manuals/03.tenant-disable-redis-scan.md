# 停用 / 改档租户时的 Redis SCAN

适用：平台停用租户、或改档导致必须作废该厂已发会话。对象是共享 Redis 上的登录 token。不改 key 形态、不加二级 SET（R6）。

本手册不含口令、Token 明文、生产主机。

## 行为

停用租户（以及需要立刻踢掉该厂会话的改档）会调用 `TokenService.invalidateByTenantId`：

1. `SCAN` 全部 `login_tokens:*`（常量 `login_tokens:` + uuid）
2. 反序列化值，按其中的 `LoginUser.tenantId` 匹配
3. 只 `DEL` 命中的 key

权威租户在 **value** 里，不在 key 上。禁止为此改成 `login_tokens:{tenantId}:…` 或加「每租户 session SET」。

改档本身仍受 D8 约束（v1 禁用改隔离级别）；这里只说明：**只要走了按租户作废会话的路径，SCAN 成本相同。**

## 运维含义

- 会话量上来之后，停用一家工厂会扫 **全部** 在线 token，不只扫该厂。安全语义正确，成本随全局会话数线性上升。
- 这是已接受的代价，直到会话量迫使重新设计。重新设计前不要加 yml 开关、不要改 Redis key。
- 停用顺序仍是：先把 `sys_tenant.status` 标停用（新登录被拒），再 SCAN。SCAN 完成前，Filter 读到停用状态仍应 401。
- `DATABASE` 租户同时卸载专池；**不**删库。不要把专库卸载和 token SCAN 理解成同一件事。

## 观察（不要贴凭据）

看耗时与 SCAN 游标是否打满 Redis，不要 dump token 值、不要把 cipher 或 JDBC 写进工单。会话量逼近让停用操作不可接受时，再单独立项改 key 形态；本手册不预先给第二套索引。
