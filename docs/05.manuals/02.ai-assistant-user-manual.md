# MES AI 助手用户手册（全角色）

- 适用产品：星极谷 MES 管理端 Vue 3（`startech-mes-front`）内嵌 AI
- 读者：平台运营、运维、工厂管理员、工厂对话用户
- 不含：实现步骤、接口契约正文、真实主机 / 口令 / API Key
- 依据：`docs/02.requirements/03.mes-ai-platform-gaps.md`、`04.mes-ai-phase1-gaps.md`、`05.mes-ai-runtime-hardening-gaps.md`、`10.mes-ai-production-rag-gaps.md`；`docs/03.design/06.mes-ai-platform-plan.md`、`07.mes-ai-runtime-hardening-plan.md`、`11.mes-ai-production-rag-plan.md`；`docs/04.specs/48`–`73`、`89`–`93`

遗留 Vue 2 管理端不提供 AI。未登录不可对话，也没有独立聊天网站。

## 1. 这套 AI 能做什么

工厂在管理端里配置本厂的对话模型与知识库，已登录员工在同一套系统里流式对话。平台给工厂开通 `ai` 许可后，侧栏才会出现「AI 助手」相关菜单。

| 能力 | 谁用 | 当前状态 |
| --- | --- | --- |
| 给工厂开通 / 关闭 AI 许可 | 平台运营 | 已上线 |
| 加密主密钥、平台默认 Key | 运维 | 已上线（环境变量；禁止写 yml） |
| 向量集群地址 / 类型（Weaviate host、DashVector endpoint、`VECTOR_STORE_TYPE`） | 运维 + 平台运营 | **SHARED：** 部署 yml/env（§4.4）。**DEDICATED：** 开通/编辑租户时绑定（spec 93/94 已编码；向导点选与 live 未做）。不是知识库页，不是工厂「参数设置」，没有 `/platform/ai-vector` |
| 厂商、模型、密钥 | 工厂管理员 | 已上线 |
| 会话列表 + 流式对话 | 工厂用户 | 已上线 |
| 知识库、附件、对话挂知识库 | 工厂管理员 / 对话用户 | 已上线 |
| 白名单 MCP、已登录工作流 | 工厂管理员 | 已上线 |
| Agent 代为检索知识、受控报工 / 改工单状态 | 工厂用户（须权限） | 后端已上线；档案配置页与对话页选档案 **未交付**（见 §9） |
| Agent 档案 CRUD、对话页选档案、Tool 审计查询页 | 工厂管理员 / 审计 | **未交付**（见 §9） |

明确不做：游客聊天、独立对话端、模型直连 MES 业务库、任意 SQL、匿名工作流、短剧 / Coding Harness。

## 2. 角色与准入

三道闸同时生效，缺一不可：

1. **已登录**（现有账号 + JWT；登录须填租户编码，无默认租户）
2. **本厂有效 `ai` 许可**（过期视为未开通；侧栏无 AI 菜单，接口 403）
3. **角色权限字**（有菜单不等于有按钮；对话用户通常只需对话权限）

数据按租户隔离。A 厂看不到 B 厂的模型、会话、知识库、MCP。会话还按用户隔离：只能看到自己的对话。

| 角色 | 典型账号来源 | 主要菜单 | 不做什么 |
| --- | --- | --- | --- |
| 平台运营 | 平台租户（`tenant_id=0`）回家 | 平台 → 租户管理 → 许可、专库 JDBC；独立向量在开通向导绑定（93/94 已编码，点选未做）。共享向量走 yml | 不给工厂配模型 Key；不把平台模块许可给工厂；不把集群地址交给工厂改 |
| 运维 | 部署 / 启动进程的人 | 无业务菜单 | 不把密钥写进仓库 yml 真值；**共享**集群地址/类型走 yml/env（§4.4）。专集群必须由平台在开通/编辑租户时录入，不要靠「工厂 env」 |
| 工厂管理员 | 工厂租户、角色勾了 AI 配置权限 | 厂商 / 模型 / 知识库 / MCP / 工作流 | 不配向量集群地址（不在知识库对话框、也不在本厂参数设置改集群）；不改他厂数据 |
| 工厂对话用户 | 同一工厂、角色勾了对话权限 | 对话 | 不改模型密钥；不登记任意 MCP |

同一人可以同时是管理员和对话用户，由角色勾选决定。

建议角色模板（工厂在「系统管理 → 角色」勾选）：

| 模板 | 建议权限字 |
| --- | --- |
| AI 配置管理员 | `ai:provider:*`、`ai:model:*`、`ai:knowledge:*`、`ai:mcp:*`、`ai:workflow:*`（含 `ai:workflow:run`） |
| 仅对话 | `ai:chat:list`、`ai:chat:send`（模型下拉另需 `ai:model:list` 或已有 `ai:chat:list` 即可拉 options） |
| 要用 Agent 报工 / 改工单 | 对话权限 **加上** `mes:pro:feedback:add`、`mes:pro:workorder:edit`。没有这两项时，模型即使想写 MES 也会被拒绝 |

`ai:model:*` 展开为 `list` / `query` / `add` / `edit` / `remove`。其它 `ai:xxx:*` 同理。

## 3. 平台运营

### 3.1 开通工厂 AI

1. 用平台账号登录 Vue 3 管理端（不要用工厂账号进 `/platform`）。
2. 打开 **平台管理 → 租户**。
3. 选中目标工厂，维护模块许可，勾选字典码 **`ai`**（名称以界面「MES 模块许可」为准）。
4. 可设过期时间。过期后该厂 AI 菜单消失，已有对话数据仍留在该厂库中，但不能再调 `/ai/**`。
5. 保存后，请该厂用户 **重新登录**（或重新拉路由），侧栏才会出现 AI 目录。

不要给工厂许可 `platform`。`ai` 可以许可给工厂。默认不必给平台自己开 AI；平台只给工厂开通即可。

### 3.2 关闭或到期

取消 `ai` 或等到过期：该厂 `getRouters` 不再出现 AI 菜单，接口 403。不要用删菜单行代替关许可。

### 3.3 进入工厂（runAs）

平台运营进入某厂代运维时，看到的是 **该厂许可 ∩ 该厂菜单目录**，不是平台回家自己的角色菜单。进厂后按工厂管理员 / 对话用户章节操作。不要在工厂会话里改平台许可。

### 3.4 向量集群（平台基础设施，不是知识库页）

「向量集群地址」指 **向量数据库**：类型（`weaviate` 或 `dashvector`）、Weaviate host、DashVector endpoint。不是 MinIO，不是对话模型 host，也不是知识库切块长度。

对齐本系统给工厂配 **MySQL** 的方式：共享库（`ROW`）用平台库；专库（`DATABASE`）由平台在 **租户管理** 填 JDBC，工厂不能自己改连接串。向量同样两档，工厂知识库对话框和「参数设置」**没有**这些字段：

- **共享（SHARED）：** 该厂没有专绑定，用进程 **yml / 环境变量** 里的共享集群（与主库数据源同类）。改共享地址要改部署配置并重启，没有单独的「默认向量页」。
- **专集群（DEDICATED）：** 该厂能且必须用自建向量库时，平台在 **新建租户** 基本信息打开「独立向量数据库」，后续步骤绑定 type / host（或 endpoint）和只写 API Key。运行时只连这家的库，不连共享集群。绑定必须由平台录入，不能靠工厂环境变量。不能出厂的工厂通常绑自建 Weaviate；能走云的可以用 DashVector。

开通租户时，基本信息页用两个独立开关（独立 DB、独立向量）。**只展示已打开开关对应的后续步骤**；两关则填完基本信息即结束。

不要在系统管理「参数设置」里给本厂 overlay 一个集群地址——工厂不能自己改指向。

- Weaviate / DashVector 的 **共享** API Key：只走环境变量占位，不要贴进仓库 yml 真值，也不要明文进参数表。
- **专绑定** API Key：只写不回显（加密保存）。工厂用户看不见 Key。
- 同一套 MES 进程里，A 厂可以走 Weaviate、B 厂走 DashVector。
- 专绑定走平台租户页 `GET`/`PUT /platform/tenant/{id}/vector-store`，**没有**「默认向量页」`/platform/ai-vector`，也没有 master 默认空行再回落 env。Maven 单测已覆盖解析与 HTTP（见 `docs/04.specs/93` / `94` 第 4 节）。**已登录平台向导点选与 live 集群未做。**

## 4. 运维（进程与环境）

两把进程级主密钥、**共享**向量集群由运维写 yml/env。业务人员在界面填的是 **本厂模型 API Key** 或 **专库 JDBC 口令**；真正加密用的主密钥只来自环境变量，不读 yml。已绑专集群的工厂不走这些共享向量环境变量。

| 变量名 | 加密什么 | 和另一把的关系 |
| --- | --- | --- |
| `AI_MODEL_CIPHER_KEY` | 模型 API Key、MCP 凭证 | **禁止**与 JDBC 那把相同 |
| `TENANT_JDBC_CIPHER_KEY` | 专库租户的 JDBC 口令（不是工厂登录密码） | **禁止**与模型那把相同 |

格式相同：必须是 **32 字节** 密钥材料，写成 64 位十六进制，或解码后正好 32 字节的 Base64。任意普通密码（如 `123456`）无效。**不要写进 `application.yml`。** 开发测试全员共用值见 §4.3（已写入本手册）；生产必须另生成，禁止用 §4.3 那一对。配到 **跑 `RuoYiApplication` 的进程**（IDEA Run Configuration → Environment variables，或启动脚本）。改完必须 **重启**。一旦加密过库里的密文，不要更换。

也可设同名 JVM 系统属性（`-DAI_MODEL_CIPHER_KEY=...`）。

### 4.1 `AI_MODEL_CIPHER_KEY`（存模型 / MCP 时需要）

保存带 API Key 的模型、或带凭证的 MCP 时，若进程没有这把主密钥，界面会提示类似 **`AI model cipher key is missing`**，保存失败。

行内模型 Key 留空时，运行时可以回退 **`AI_DEFAULT_API_KEY`**（仍不要写入 yml 真值）。工厂要各用各的上游 Key 时，应在模型表单填写并加密保存。

纯共享库、只做对话、模型 Key 留空且运维配了默认 Key 时，可以暂时不设本变量；**一填模型 Key 就必须设**。

### 4.2 `TENANT_JDBC_CIPHER_KEY`（专库 JDBC 时需要）

这把钥匙 **不是** 给 AI 模型用的。平台给工厂配 **专库（`DATABASE`）** 的 JDBC 口令时，口令会加密落库；登录专库工厂、切换数据源时再解密。共享库（`ROW`）工厂不要填 JDBC；填了会拒绝保存。

| 场景 | 要不要设 |
| --- | --- |
| 库里已有专库租户 | **必须**。缺了 **启动失败** |
| 平台给工厂保存 / 修改专库 JDBC 口令 | **必须**。否则保存失败 |
| 专库工厂登录、切数据源 | **必须**。否则解不开口令、连不上专库 |
| 全是共享库 `ROW`、也不配 JDBC | 可暂不设；**不影响**保存 AI 模型（模型用的是上一把） |

开发机如果只测共享库 + AI，可以只配 `AI_MODEL_CIPHER_KEY`。一旦要测专库开通 / 专库登录，两把都要配，且必须是 **两串不同的 32 字节材料**。

### 4.3 开发 / 测试全员共用（贴进 IDEA）

下列两把钥匙 **只用于开发与测试**，全员同一套，才能解同一份库里已加密的模型 Key / 专库 JDBC。**禁止用于生产。禁止写入 `application.yml`。** 生产环境自行生成新的一对，不要用下面的值。

| 变量 | 值（64 位 hex，32 字节） |
| --- | --- |
| `AI_MODEL_CIPHER_KEY` | `e241ab9382783771e0f2c4d7379fe8309134f0365a2f93ff6ef0f33aaaa0b2bf` |
| `TENANT_JDBC_CIPHER_KEY` | `3691f78f6c711faeb6e7e6e8c01bd755f246a39c3f1810f593bf7975190cb8d1` |

IDEA：`Run` → `Edit Configurations` → 选中 `RuoYiApplication` → `Environment variables`，整行粘贴后重启后端：

```text
AI_MODEL_CIPHER_KEY=e241ab9382783771e0f2c4d7379fe8309134f0365a2f93ff6ef0f33aaaa0b2bf;TENANT_JDBC_CIPHER_KEY=3691f78f6c711faeb6e7e6e8c01bd755f246a39c3f1810f593bf7975190cb8d1
```

两串必须保持不同。连同一份已加密数据时全员都用这一对，不要各自再生成，否则解不开同事写入的密文。

生产或独立环境需要另做一对时，用下面脚本生成（不要覆盖上面的开发共用值）：

```powershell
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
function New-CipherHex {
  $b = New-Object byte[] 32
  $rng.GetBytes($b)
  -join ($b | ForEach-Object { $_.ToString('x2') })
}
$ai = New-CipherHex
$jdbc = New-CipherHex
if ($ai -eq $jdbc) { throw 'two keys must differ' }
Write-Output "AI_MODEL_CIPHER_KEY=$ai"
Write-Output "TENANT_JDBC_CIPHER_KEY=$jdbc"
```

### 4.4 向量集群（共享走 yml；专绑定走开通向导）

未知类型会失败关闭，不会悄悄改用内存库。**SHARED 产品面就是下列 yml / 环境变量**（与主库数据源同类）。**不要**用这些变量给某一厂偷偷改指向——专集群必须由平台在开通/编辑租户时录入。仓库 `application.yml` 只保留占位，禁止提交真值 Key。

| 变量名 | 用途 |
| --- | --- |
| `VECTOR_STORE_TYPE` | `weaviate`（本地常见默认）/ `dashvector`（现网已实现）。未知值失败关闭。`milvus` / `qdrant` 代码未齐，不要当已上线选项 |
| `WEAVIATE_HOST`、`WEAVIATE_API_KEY` | type=weaviate；Key 只走本变量（SHARED），不要写进仓库 yml 真值 |
| `DASHVECTOR_ENDPOINT`、`DASHVECTOR_API_KEY` | type=dashvector；Key 同上 |
| （Milvus / Qdrant） | 仍未作为本期字段 |

切块长度、重叠、分隔符、检索条数、相似度阈值**不要**再设 `AI_RAG_*` 环境变量（将从产品配置拆除）。工厂在知识库页填写；空则用系统管理「参数设置」键 `ai.rag.chunk-size` / `ai.rag.chunk-overlap` / `ai.rag.chunk-separator` / `ai.rag.top-k` / `ai.rag.min-score`（本厂 overlay 优先）。**不要**把向量集群地址写进知识库对话框，也**不要**用本厂参数设置 overlay 去指另一套集群。

### 4.5 运维注意

- 日志、SSE、toast 不得出现 Key、cipher、MCP token、内部绝对路径。
- 知识附件走现有 MinIO 上传，对象键必须是当前租户前缀，运维不要改成匿名下载 `tenant/`。
- 专库工厂：AI 表必须已进该厂 catalog；未迁成功则该厂 AI 失败关闭，不会写回主库。

## 5. 工厂管理员

前提：本厂已有 `ai` 许可，账号具备对应权限。菜单名称以侧栏为准，路径均为 `ai/...`。

推荐开通顺序：

```text
厂商 → 模型（填 Key，先确认运维已配主密钥）→ 对话试通
      → 知识库上传并解析 → 对话时挂知识库
      →（可选）MCP 白名单、工作流
```

### 5.1 厂商管理（`/ai/provider`）

登记本厂要用的 OpenAI 兼容上游（DeepSeek、阿里云兼容模式、自建网关等都可以，用 **接口根地址 + 模型名** 区分，不单独接百炼/智谱原生协议）。

| 字段 | 说明 |
| --- | --- |
| 厂商名称 | 列表展示 |
| 厂商编码 | 本厂内唯一，模型挂靠用 |
| 接口地址 `apiHost` | OpenAI 兼容根，例如兼容网关的 host；不要把口令写进 URL |
| 图标 | 可选；上传走现有 MinIO |
| 状态 | 停用后不要再给新模型使用 |

密钥配在 **模型** 上，不配在厂商上。

### 5.2 模型管理（`/ai/model`）

| 字段 | 说明 |
| --- | --- |
| 厂商编码 | 下拉已建厂商 |
| 模型名 | 上游要求的 id（如对话模型名）；同一厂商下本厂唯一 |
| 展示名 / 描述 | 给员工看 |
| 分类 `category` | 对话请用 **`chat`**。`vector` / `rerank` 可保存，对话页不会调用 |
| 接口地址 | 可覆盖厂商 host；都空则对话失败 |
| API Key | **只写不回填**。详情最多看到打码。留空保存表示不改原密钥（编辑时）或运行时走平台默认 Key（新建且运维配了默认 Key） |
| 维度 | embedding 用；创建向量集合时写死，改维度需运维配合重建 |
| 状态 | 停用后 options 下拉不应再选 |

保存带 Key 的模型前，确认 §4.1。提示 `AI model cipher key is missing` 时找运维，不要反复点保存。

列表和选项 **不会** 返回明文 Key 或 cipher。不要把打码内容再当新 Key 提交。

### 5.3 知识库（`/ai/knowledge`）

1. 新建知识库（名称、备注）。可选填：**检索条数**、**相似度阈值**、**切块大小**、**切块重叠**、**切块分隔符**；空则用系统默认（参数设置 `ai.rag.*`，不是运维 yml）。重叠必须大于 0 且小于切块大小。**不要**在本页填 Weaviate / DashVector 地址（那是平台页 §3.4）。
2. 上传附件：走 **`POST /common/uploadMinio`**，不要改用其它 OSS 口。当前解析按 **UTF-8 纯文本** 切块，优先 `.txt` / `.md`；PDF / Office 可能失败或切出乱码（生产级按类型解析见缺口 `10` / 单元 90，编码前仍如此）。
3. 系统登记附件行。对象必须落在本厂租户前缀下，否则拒绝。
4. 等待解析：切块写入片段表，并向当前向量库写入向量（运维已选一种，且本厂须有启用的 embedding / `vector` 模型）。状态以页面为准。
5. 删除：若仍有附件，按实现可能先拒绝删除，需先清附件。

对话检索只命中 **本厂** 该知识库，与 Agent 知识检索共用同一套参数。不要指望用知识库「查 MES 工单表」——那不是知识库的职责。向量集群未配或解析未成功时，选了知识库仍会像纯对话。

### 5.4 MCP 白名单（`/ai/mcp`）

为本厂登记允许 Agent 连接的 MCP 服务。不是应用市场，不能粘贴任意地址即连。

- 凭证只写不回填，列表无明文 token。
- 加密主密钥与模型相同（`AI_MODEL_CIPHER_KEY`）。
- 仅已启用且属于本厂的条目可被 Agent 使用。
- 禁止当作「任意 SQL 执行器」。

当前对话页 **未** 提供「选 Agent 档案再开 MCP」的完整产品路径（§9）。配好白名单后，需等工作流或后续档案功能才能按设计挂到对话上。工作流步骤只能引用已登记且启用的条目。

### 5.5 工作流（`/ai/workflow`）

为本厂定义多步编排，在本页以登录态运行。

- 步骤只能调用已注册白名单：知识检索、受控报工、改工单状态、已启用 MCP。不能在步骤里写任意 SQL 或未登记 HTTP。
- 运行走流式进度（内容 / 结束，可选步骤号）。不是 ruoyi 那套工作流帧。
- 定义权与运行权分开配置；**写 MES 的步骤仍检查** 报工 / 工单权限，不会因为「走了工作流」而绕过。
- 必须登录。不存在匿名运行地址。

工作流内嵌「再调一次大模型对话」的步骤见 §9（未交付）。

### 5.6 给员工开通对话

1. 角色勾选 `ai:chat:list`、`ai:chat:send`。
2. 确保至少有一条启用的 `chat` 模型。
3. 需要知识库时，建库并解析完成。
4. 需要模型代为报工时，另授 MES 报工 / 工单权限，并等待 Agent 档案上线（§9）。

## 6. 工厂对话用户

入口：**AI 助手 → 对话**（全宽页）。必须先登录。没有「未登录先聊」。

### 6.1 日常对话

1. 左侧会话列表：新建、选择、删除自己的会话。看不到同事的会话。
2. 上方选择 **本厂 chat 模型**。没有模型时找管理员。
3. 输入问题发送。回答以气泡流式出现。
4. 可选：选择本厂知识库。系统先检索片段再生成。无命中时仍可纯对话（或按页面提示）。
5. 不要选择非 `chat` 分类的模型。

纯对话 **不会** 改工单、不会报工。那是 Agent / 工作流路径，且还要你本人有 MES 权限。

### 6.2 安全与隐私

- 不要把 API Key、密码贴进对话框。
- 回答里的厂内资料仍属本厂上下文，不要复制到厂外。
- 断线或 401 时重新登录，不要用游客方式继续。

### 6.3 权限不够时

| 现象 | 处理 |
| --- | --- |
| 侧栏没有 AI | 许可未开、过期，或角色未赋 AI 菜单；找平台或工厂管理员 |
| 能进对话但不能发 | 缺 `ai:chat:send` |
| 模型下拉为空 | 无启用 chat 模型，或无 options 权限 |
| 选了知识库仍像没读文档 | 未解析完成、向量集群未配，或问的内容和文档不相关 |
| 希望 AI 报工却没动作 | 纯对话不会写 MES；且本人要有报工权限；档案选择尚未交付 |

## 7. 受控写（报工 / 工单）说明

设计允许模型 **只** 通过白名单调用现有 MES 功能，不能直接操作数据库。

当前第一批：

| 能力 | 权限字 | 限制 |
| --- | --- | --- |
| 登记报工 | `mes:pro:feedback:add` | 最小字段：工单、工作站或任务、报工数量；不是「执行报工」大事务 |
| 更新工单状态 | `mes:pro:workorder:edit` | 只改业务允许的状态，不改数量 / BOM / 工艺，不删工单 |

这些能力挂在 Agent 发送口上。**当前对话页默认仍是纯对话。** 在档案配置页与「对话选档案」交付前，不要对一线员工承诺「在聊天框里改工单一定成功」。管理员可在工作流里编排已注册的写步骤（仍检查上述权限）。

## 8. 常见问题

**保存模型报 `AI model cipher key is missing`**  
进程缺少 `AI_MODEL_CIPHER_KEY`。开发测试把 §4.3 那一行贴进 IDEA 后重启。填了 API Key 才会加密；完全不填 Key 可以保存，对话则依赖运维配置的默认 Key。

**启动失败 / 保存专库 JDBC 失败，提示缺 `TENANT_JDBC_CIPHER_KEY`**  
进程缺少 JDBC 主密钥。开发测试同样用 §4.3 那一行。仅共享库、不配 JDBC 时可以不设；已有专库租户或要保存 JDBC 时必须设，且不能与 `AI_MODEL_CIPHER_KEY` 相同。

**提示密钥无效 / 必须是 32 字节**  
主密钥格式不对。必须是 64 位 hex 或 32 字节 Base64，不能当普通密码写。两把钥匙各自生成，不要复用。

**未许可 403 / 没有菜单**  
平台未勾 `ai`、许可过期、或角色没赋菜单。工厂管理员不能自己给本厂加许可。

**跨厂用了别人的模型 id**  
系统按本厂校验，失败且不会请求上游。不要在地址栏或脚本里传租户号。

**编辑模型时 Key 是 `****xxxx`**  
那是打码。不改密钥就留空提交。

**Vue 2 登录或旧前端**  
不支持 AI；登录还可能因缺少租户编码失败。请用 Vue 3 管理端。

**对话很慢或失败**  
检查模型 host、Key、上游额度；看页面错误文案（不应出现密钥）。知识库路径还依赖向量集群是否可达。

## 11. 推荐验收清单（按角色）

**平台：** 给测试工厂勾 `ai` → 该厂重新登录出现 AI 菜单 → 去掉许可后菜单消失。

**运维 / 开发：** IDEA 已贴 §4.3 两把钥匙并重启 → 工厂可保存带 Key 的模型；有专库时 JDBC 也能加解密；向量 type 与集群可达 → 知识库能解析。生产不用 §4.3 那一对。

**工厂管理员：** 建厂商与 chat 模型 → 自己发一条对话成功；上传文档并挂知识库提问能引用文档；MCP / 工作流页能打开且凭证不回显。

**对话用户：** 仅对话权限时能聊、不能进模型配置（或按钮灰掉）；不能看到他厂或他人会话。
