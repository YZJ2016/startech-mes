# Flyway 基线操作手册

适用：I10 切线落地之后（`docs/04.specs/76`–`78`）。对象是**已经有表**的主库 / 已 `READY` 的专库，以及空实验室主库怎么接到这条链上。

不写 Java、不改契约。本手册不含口令、真实 JDBC、生产主机。

## 先分清两件不同的事

| 名字 | 做什么 | 跑 SQL 吗 | 用在哪 |
| --- | --- | --- | --- |
| 运维命令 `flyway baseline` | 往默认表 `flyway_schema_history` **插一行**，版本 **`20260825.31`** | **不跑。** 零 DDL | 已有业务表的主库、已有 `READY` 专库。必须在**启动应用之前** |
| 快照文件 `V20260825.31__tenant_schema_snapshot.sql` | Flyway 普通 versioned 迁移（classpath `db/migration/tenant/`） | **会。** `CREATE TABLE` 全套租户表 | **空的新 DATABASE** 开通时由 migrate 执行。禁止对这类库先 baseline |

切线后开通 schema **只跑一套 DDL**：Flyway `tenant/` migrate。禁止把 `backend/sql/` 历史文件和 Flyway 叠在「创建 schema/表」按钮上。

`spring.flyway.baseline-on-migrate` **必须保持 `false`**。已有表、无 history 的库若直接启动，Flyway 会尝试再 `CREATE` 已存在的表 → 进程起不来（fail-closed，符合 FLY8）。不要为了「能启动」打开该开关。

基线号以 76 钉死为准：**`20260825.31`**（catalog 最后一项 `20260825_31_ai_tool_audit.sql`）。不要用设计文撰写时的 `20260827.35`。

## 前置

对**即将 baseline 的那一个 catalog**：

- 切线前租户增量已手工打到 catalog 最后一项：`backend/sql/20260825_31_ai_tool_audit.sql`
- 其后 `20260826_32`～`20260827_35` 只动 I8 / 平台种子，**不抬** tenant 基线号；主库若要对齐现网菜单与平台数据，仍按 `sql/` 手工跑，不要改写成 `db/migration`
- Flyway **12.x** + `flyway-mysql`（与 Spring Boot 4.1 一致）。CLI 或 Maven 插件连 MySQL 都必须带 `flyway-mysql`，不要只用 `flyway-core`
- JDBC 与应用 **同一条**（同一 host/port/catalog、同一账号权限）。只用环境变量，不要写进仓库：

```bash
# 在 shell 里 export，不要 echo 口令，不要写入 flyway.conf 后提交
export JDBC_URL='jdbc:mysql://${DB_HOST}:${DB_PORT}/${DB_NAME}'
export DB_USER='${DB_USER}'
export DB_PASSWORD='${DB_PASSWORD}'
```

应用侧（已落地，勿改）：

- `spring.flyway.enabled=true`
- `spring.flyway.baseline-on-migrate=false`
- `spring.flyway.validate-on-migrate=true`
- `spring.flyway.locations=classpath:db/migration/master,classpath:db/migration/tenant`
- 禁止 `outOfOrder=true`
- 入口：`ktg-admin` / `com.ktg.RuoYiApplication`
- history 表名：**默认** `flyway_schema_history`（不要另起第二套表名）

工作目录约定：下列命令均在业务仓 `startech-mes-basic/backend` 下执行。

## 1. 已有主库（共享 ROW + 平台）

### 1.1 确认还没钉过

```sql
-- 应能看到业务表
SHOW TABLES LIKE 'sys_user';

-- 此时不应有 history（没有表、或空表都不算已 baseline）
SHOW TABLES LIKE 'flyway_schema_history';
```

`sys_user` 不存在 → 这不是「已有主库」，改走第 3 节空实验室。  
已有 `flyway_schema_history` 且已有 `20260825.31` 的 `BASELINE` 行 → 不要再 baseline。

### 1.2 钉到 `20260825.31`（不执行快照）

**Flyway CLI**（locations 与应用主库一致：master + tenant；baseline **不执行**这些文件，只对齐应用稍后 migrate 用的目录）：

```bash
flyway \
  -url="${JDBC_URL}" \
  -user="${DB_USER}" \
  -password="${DB_PASSWORD}" \
  -baselineVersion="20260825.31" \
  -baselineDescription="tenant schema snapshot" \
  -locations="filesystem:ktg-system/src/main/resources/db/migration/master,filesystem:ktg-system/src/main/resources/db/migration/tenant" \
  baseline
```

**或 Maven 插件**（版本用与 classpath 上 `flyway-core` 同系列的 12.x，勿写进口令到 pom）：

```bash
mvn -pl ktg-system org.flywaydb:flyway-maven-plugin:${FLYWAY_VERSION}:baseline \
  -Dflyway.url="${JDBC_URL}" \
  -Dflyway.user="${DB_USER}" \
  -Dflyway.password="${DB_PASSWORD}" \
  -Dflyway.baselineVersion=20260825.31 \
  -Dflyway.baselineDescription="tenant schema snapshot" \
  -Dflyway.baselineOnMigrate=false \
  -Dflyway.validateOnMigrate=true \
  -Dflyway.locations=filesystem:src/main/resources/db/migration/master,filesystem:src/main/resources/db/migration/tenant
```

### 1.3 验收：只多了一行 BASELINE

```sql
SELECT installed_rank, version, description, type, script, checksum, success
FROM flyway_schema_history
ORDER BY installed_rank;
```

期望：

- **恰好一行**（切线日 `master/` 无更高号文件时）
- `version` = `20260825.31`
- `type` = `BASELINE`（不是 `SQL`）
- `script` 不是 `V20260825.31__tenant_schema_snapshot.sql`
- `success` = 1

`type=SQL` 且 script 指向快照文件 → 快照被执行了。已有库上这是事故：停应用，不要再 migrate；按第 5 节处理，不要改已发布快照字节。

### 1.4 再启动 `ktg-admin`

```bash
# Java 17；口令只走环境变量 / 既有本地配置，不要贴到日志或工单
mvn -pl ktg-admin -am spring-boot:run
```

期望：主库 migrate **跳过**快照，不重放 `CREATE TABLE sys_user`。启动后 history 里不应出现第二行「再执行一遍」`V20260825.31__tenant_schema_snapshot.sql`。

## 2. 已有 READY 专库

每家 **独立 catalog** 各做一次，版本仍是 **`20260825.31`**。不需要专库连接池；一次性 CLI / Maven 即可。locations **只要 tenant**（与开通/补齐相同，不要扫 `master/`）。

把 `${JDBC_URL}` 换成该专库自己的 URL（仍用占位符，不要把解密后的串写入仓库或日志）。

```bash
flyway \
  -url="${DEDICATED_JDBC_URL}" \
  -user="${DEDICATED_DB_USER}" \
  -password="${DEDICATED_DB_PASSWORD}" \
  -baselineVersion="20260825.31" \
  -baselineDescription="tenant schema snapshot" \
  -locations="filesystem:ktg-system/src/main/resources/db/migration/tenant" \
  baseline
```

验收 SQL 与第 1.3 节相同，在**该专库**上查。

未 baseline 的 READY 专库：启动后 `TenantFlywayCatchupRunner` 会尝试 migrate → 快照 `CREATE` 撞表 → **拒绝启动**（75 FLY6 / 78）。修好方式：对该 catalog 做 baseline（若 history 仍空）或按失败原因修库后再启，不要打开 `baseline-on-migrate`。

## 3. 空实验室主库

Flyway **不能**从零建平台库（无 master 快照，`ry_*.sql` / xinhe dump 禁止进 `db/migration`）。

顺序：

1. 按 `backend/sql/20260820_00_runbook.sql` 做空实验室初始化（新若依 + quartz + MES 结构；xinhe dump 或等价）
2. 手工跑完切线前 `sql/` 增量（租户 catalog 到 `20260825_31_ai_tool_audit.sql`；32–35 按需手工，不改写成 Flyway）
3. 按第 1 节 **baseline `20260825.31`**
4. 再启动 `ktg-admin`

禁止：把 `ry_*.sql`、xinhe dump、带 `DROP` 的实施包拷进 `ktg-system/src/main/resources/db/migration/`。

---

## 4. 全新空 DATABASE 租户

**不要 baseline。** 空库没有业务表，需要 **执行** 快照才能建表。

平台步骤（77）：`POST /platform/tenant/{id}/schema`

```text
预算 + 并行槽 N≤2
→ CREATE DATABASE IF NOT EXISTS          （JDBC，不是 Flyway 文件）
→ Flyway.migrate(locations = tenant/)    （无 history → 先跑快照 CREATE，再跑更高号）
→ 复制角色 / 角色菜单模板
→ ping → READY
```

不扫描 `master/`，不读 `backend/sql/`。`baseline-on-migrate=false` 才能保证快照被执行。

## 5. 失败与恢复

### 已有主库忘了 baseline

现象：进程起不来（主库 migrate 在已有 `sys_user` 上执行快照 `CREATE`）。

处理：

1. **停掉** `ktg-admin`（不要反复重启）
2. 确认 `flyway_schema_history` 仍不存在，或没有成功的快照 `SQL` 行
3. 按第 1 节 baseline `20260825.31`
4. 再启动

**不要**把 `spring.flyway.baseline-on-migrate` 改成 `true`。

若已经部分写入 history、或快照执行到一半（MySQL DDL 隐式提交）：不要改已发布快照文件；停机后按实际表状态人工判断，用**新版本号文件**补缺口（A9 / FLY 冻结）。不要 `repair` 改 checksum 来「通过」被改过的快照。

### checksum / validate 失败

已发布的 `V20260825.31__tenant_schema_snapshot.sql` **冻结**。注释、空白、列顺序改了都会变 checksum → `validate-on-migrate=true` 拒启动。

处理：恢复仓库里的已发布字节；纠错只加 **新的** `VyyyyMMdd.nn__{master|tenant}_*.sql`（`nn` 跨 master+tenant 全局唯一）。

### 查看 history（不要顺带打出连接信息）

```sql
SELECT installed_rank, version, description, type, script, checksum, installed_on, success
FROM flyway_schema_history
ORDER BY installed_rank;
```

不要 `SELECT *` 从业务表里把口令列贴进工单；不要把 JDBC URL 写进这次查询的备注。

---

## 6. 安全

- 命令、工单、应用日志、异常栈都不要出现口令、Token、cipher、真实 JDBC
- 专库 URL 只在内存解密；lookup 仍是 `TENANT_{id}`
- **不要**把填了真实 `flyway.url` / 口令的 `flyway.conf` 提交进任何 git
- 不扩大匿名 HTTP 面；开通仍走既有 `POST /platform/tenant/{id}/schema`
