## 1. 目标与非目标

星制造需要一套移动工作台，同一份 Vue 业务模块出 H5、微信小程序和手机安装包。现有后端已经提供工作台入口和设备角标。本仓没有对应的移动页面。PC 前端 `riveredge-frontend` 是 React，不能把那套页面编译进这个客户端。

### 1.1 目标

- 在 `kuaigeyun-mes/kuaigeyun-client/riveredge-app-mobile` 建 uni-app x 工程，与工位壳 `riveredge-app-station` 同级，由 `kuaigeyun-mes` 跟踪
- 同一套业务模块编译到 H5、微信小程序、Android、iOS
- 工作台数据来自 `GET /api/v1/apps/kuaizhizao/mobile/workbench`，查询参数 `scope`。五个 scope 为 `workshop`、`warehouse`、`quality`、`equipment`、`mold`。客户端每次请求都带 `scope`，不依赖未传时的默认值 `equipment`。响应是分区列表，分区字段为 `key`、`title`、`entries`。入口字段沿用现有响应：`key`、`label`、`route`、`icon`，以及可选的 `icon_group`、`solo_row`。`title` 为空时不展示分区名，也不用「工作台」填空。入口中文名与 route 见需求 **MOB-Q2** 至 **MOB-Q6**。本节目录注释与该清单保持同一套 key、中文名和 route
- 设备角标来自 `GET /api/v1/apps/kuaizhizao/mobile/bootstrap`，现有字段是 `pending_fault_count`、`overdue_maintenance_reminder_count`。角标只读这两个数，不在客户端另做设备规则
- 请求头：`Authorization: Bearer`、`X-Tenant-ID`、`X-Client-Channel`。渠道码只发 `mobile_h5`、`miniprogram`、`android`、`ios`

### 1.2 留在本文之外

- 好力 GO 的页面。`apps/` 只留以后的扩展位，现在不设计其页面
- 工位机。工位壳已在 `kuaigeyun-client/riveredge-app-station`，加载服务器上的工位页
- 复制 PC 菜单
- 在客户端重写报工或库存规则。写入继续走现有后端
- 把 React 的 `riveredge-frontend` 编译进 uni-app
- 顶栏小程序码。它只是图片，不建业务包
- 具体推送 SDK。后端推送已有，客户端只在 `platforms` 留 `push.register` 适配位
- 渠道页面、微信小程序与安装包的发行。H5 挂到现有 Caddy `/mobile` 的做法见第 8 节

- 蒸汽模式页对小程序和 Web：「目前 uni-app x 蒸汽模式编译到小程序和web时，会以VDOM模式运行，后续会升级为蒸汽模式，无需担心使用蒸汽模式后无法编译到web和小程序。」
- 简介页：「并将于2027年初停止uni-app的App平台的维护。」以及「如果开发App，那么推荐改用 uni-app x。」同页另写蒸汽模式最低 Android 6、iOS 15。
- 小程序页：「截止到HBuilderX 4.41发版时微信的主流基础库版本是3.7.1。 uni-app x主要是在这个版本库上适配。」「请开发者检查并确保基础库版本大于3.7.1。」

运行和发行仍在 HBuilderX。Android、iOS 可云打包出 apk、ipa，也可走 HBuilderX CLI 做持续集成。本文不展开 CLI 子命令。

`@dcloudio/uni-ui`、`uview-plus`、`@wot-ui/ui` 属于 uni-app Vue3 生态。本方案的框架是 uni-app x，这三套不进入候选，也不当作已选 UI。

## 6. 功能切割

后端 `mobile_workbench` 决定某个 scope 下显示哪些入口。接口按后端 manifest 条目上的 `permission` 或 `permissions_any` 过滤后再返回；客户端只渲染响应，不另抄一套权限码。分区 `title` 为空时不展示分区名。每个 feature 包导出一份功能声明：入口 `key`、对应 manifest `route`、支持的端（`h5` / `mp-weixin` / `app`）。壳的 `registry` 只汇总已安装的包。

后端返回了入口、本地没有对应包：该入口显示显式空态，不崩溃。不支持的端不注册，该端工作台上不出现这一格。删一个功能等于删一个目录，并从 `registry` 去掉该包的导入。页面清单由注册表拼出，不维护一份堆满入口实现的手写路由表。

首批声明按三端都注册。现有 manifest 没有按端拆入口。扫码、摄像头、登录跳转的差异放在适配器里，不因此把入口从某一端拿掉。以后某个入口确实做不到某一端，只改该入口的功能声明。

| 端 | 编译目标 | `X-Client-Channel` |
| --- | --- | --- |
| H5 | web | `mobile_h5` |
| 微信小程序 | `mp-weixin` | `miniprogram` |
| Android 安装包 | app | `android` |
| iOS 安装包 | app | `ios` |

这四个码已经在后端渠道表里。客户端直接发正式码。

## 7. 长期原则

这些原则约束以后加功能和切功能，本文不把它们拆成任务。

- 新业务域等于新的 feature 包，加上后端工作台里的一个 scope。壳、`platforms` 和 `shared/api` 不改。
- 好力 GO 若以后进同一个安装包，放在 `apps/` 下的另一个应用包，不塞进星制造的五个 scope。这里只留目录。
- 执行、库存、质量、设备、模具的写入仍走现有后端。移动端不复制工位页面，也不另写一套报工或库存规则。
- 小程序和 Web 目前按官方说明以 VDOM 模式运行，后续由框架升级到蒸汽模式。业务页面不为这条升级分叉第二套目录。
- 删功能保持「删目录 + registry 去掉导入」。入口是否出现，先看后端 workbench，再看本地有没有包、该端有没有注册。

## 8. H5 部署

H5 挂现有 Caddy `/mobile`。不新增站点，不替换 PC 的 `FRONTEND_ROOT`，不动工位机 `/static/client-packages`。

`fast-deploy` 不再把 `riveredge-app/mobile` 当作 Expo 工程，也不执行 `npm run build:web`。uni-app x 不支持用 npm/cli 创建工程，发行依赖本机 HBuilderX（其 cli 可以打包，但本轮不把 HBuilderX 装进服务器，也不在 CI 里从零编译）。

输入是工程 `kuaigeyun-mes/kuaigeyun-client/riveredge-app-mobile` 下的 `unpackage/dist/build/web`。这是 HBuilderX 发行 Web 的默认目录：官方写明「在当下项目下的 `unpackage/dist/build/web` 目录找到出的资源，部署服务器」（[H5 开发注意](https://uniapp.dcloud.net.cn/matter.html)）。uni-app x 的项目结构与老版基本一致，`unpackage` 存放发行编译结果（[uni-app x 项目](https://doc.dcloud.net.cn/uni-app-x/project.html)）。

`build.mobile.web.sh` 与 `install-h5` 在该目录已有 `index.html` 时，把它复制到现有部署目录 `riveredge-app/mobile/web-dist`（变量 `MOBILE_WEB_DIR`）。Caddy 模板里的 `handle_path /mobile/*` 不变。没有这份产物时，仍写入「移动端 H5 尚未安装」占位页，并说明要先用 HBuilderX 发行 Web。工程目录可以尚未创建；本轮不新建 uni-app 页面，也不做云打包。

`kuaigeyun-mes/README.md` 里移动端仍写成 Expo。那是产品介绍，不是这条部署路径。部署脚本和部署指南已按上面的复制关系改过。
