## 1. 问题与目标

现网知识库管理端已能建库、上传、点解析、对话挂库。索引侧把任意字节当成 UTF-8；检索侧是教程定义的 Naive RAG：把**当前一句** embed 后 topK 拼进 system prompt。多轮「他指哪份 SOP」会检索失败；PDF/Office 会切出乱码。A32 把 overlap/阈值产品化了，但没有 DocumentParser，也没有 RetrievalAugmentor。

### 1.1 目标（90–93）

- 管理员上传的允许类型能抽出可读正文，失败可解释
- 切块带来源元数据，向量写入仍走现网一种向量库
- 对话与 Agent 知识检索走 Advanced RAG：压缩问句、（默认可关）展开、按允许的知识库扇出、RRF、可选再排序、邻块扩窗后注入
- HTTP 与 SSE 信封不变；无命中仍可纯聊
- 知识库管理页能选 embedding、填写切块 size/overlap（及已有 topK / minScore / 分隔符）、只读浏览切块，并留下浏览器点选记录（或据实未点选）
- **平台**能在 `/platform/**` 页配置向量库 type / Weaviate host / DashVector endpoint（Key 只写）；yml 仅空配置时的启动回落

### 1.2 非目标

- 重开 A1–A28、改 `/ai/**` 认证、合并 ruoyi-ai
- Easy RAG、内存向量库、本机 ONNX embedding 替代工厂模型
- BM25 hybrid、Azure AI Search、Elasticsearch、Neo4j、SQL ContentRetriever、公网搜索
- OCR、HyDE（PR-G1/G2）
- 换掉 Weaviate/DashVector HTTP 适配为官方 EmbeddingStore
- 改 Vue2
- 每工厂独立向量 Cluster（A14 仍成立）；集群字段进知识库对话框
- 把集群 URL 放进工厂可 overlay 的 `sys_config`

### 1.3 与 Naive / Easy 的边界

| 教程档位 | MES 态度 |
| --- | --- |
| Easy RAG | 禁止。质量按教程只适合 POC；会引入错误解析器与错误 embedding |
| Naive RAG | 现网即此。本期 **拆除为唯一路径** |
| Advanced RAG | 本期目标。组件用官方默认实现 + 自写 Retriever/Scoring，以迁就现网向量 SPI 与 A24 |

## 2. 形态

```text
索引（90）
  MinIO 字节 ──► DocumentParser（按类型）
           ──► DocumentTransformer（tenant/kid/attach/file_name）
           ──► DocumentSplitter.recursive + overlap + 可选分隔符
           ──► TextSegmentTransformer（file_name / source_ref 前缀）
           ──► A24 EmbeddingModel（DOCUMENT input type 若支持）
           ──► VectorStoreService + ai_knowledge_fragment

检索（91）
  UserMessage ──► DefaultRetrievalAugmentor
       │ QueryTransformer: Compressing →（可选）Expanding
       │ QueryRouter: 每个允许的 kid 一个 ContentRetriever
       │ Retriever: A24 QUERY embed + 向量 search(tenant,kid) + fragment 回表
       │ Aggregator: RRF → ScoringModel（A24 chat）失败则 RRF
       │ 扩窗: chunk_index ±1
       │ Injector: 片段 + file_name + source_ref
       ▼
  仍走现网 SSE {content, done}
```

chat 带 `knowledgeId` 与 Agent `searchKnowledge` / 档案 `knowledgeIds` 只是 Retriever 集合不同，Augmentor 只有一份。

## 4. 解析与元数据

- 输入：附件 `object_key` + `file_name`。扩展名小写路由；与 MIME 冲突则 Tika 探测后再路由一次。
- 输出：`Document.text()` 非空才切块。空文本、加密 PDF、损坏 OLE → 失败。
- `Metadata` 必含：`tenant_id`、`knowledgeId`、`attachId`、`file_name`；能取到则 `source_ref`（PDF 页、Excel sheet）。
- 切块参数解析顺序（PR-D17 / D19）：本库 `chunk_size` / `chunk_overlap` / `chunk_separator` 非空则用；否则 `selectConfigByKey`（`ai.rag.chunk-size` / `ai.rag.chunk-overlap` / `ai.rag.chunk-separator`）。禁止再读 `AiProperties` rag `@Value`。overlap 夹取与现网 `AiKnowledgeChunker` 相同。
- 向量侧现网已有 `tenant_id` / `kid` / `docId` / `fid`；ingest 不得丢掉这些过滤字段（I-A3）。

## 5. Advanced RAG 组件落点

### 5.1 QueryTransformer

对话记忆已在 A30/`ai_message`。压缩器必须看到「当前问句 + 最近若干轮」，否则「那份文件呢」无法检索。ChatModel 来自本次请求的 `modelId`（Agent 则档案默认模型），经 A24，禁止新 Bean。

### 5.2 ContentRetriever

不把现网向量库假装成完整 `EmbeddingStore`（metadata Filter 能力因适配而异）。Retriever 显式传 `tenantId`+`kid`。minScore 对 Weaviate 继续按现网「distance → 1-distance」再比（69 已处理）。

### 5.3 Aggregator 与 Scoring

多 query × 多 kid 需要 RRF，否则只取第一路会丢掉展开问句。再排序用 chat 打 0–1 分，避免新供应商。超时/解析失败不得清空命中。

### 5.4 并行

多 Retriever 时 Augmentor 会用 Executor。装饰器必须复制 `TenantContext`，与 SSE 工作线程同一红线。

### 5.5 Agent

`searchKnowledge` 仍暴露给模型；内部改为 facade（压缩可用 Tool 参数里的 query + 会话记忆）。档案未列出的 kid 仍 404。不要给 AiService 再挂第二套 `contentRetriever` 导致重复注入。

## 6. 前端（管理页，单元 92）

现网 `/ai/knowledge` 已有名称、topK、minScore、分隔符、附件上传与解析按钮。缺口留在同一单元 92，不塞进 90 解析器，也不另开 Vue spec：

1. **embedding 下拉：** `GET /ai/model/options` 过滤 `category=vector`；可空；空则后端第一条启用 vector。无 Key。
2. **切块/检索旋钮：** 同一对话框保留 topK / minScore / chunkSeparator；**增** chunkSize、chunkOverlap。placeholder 说明空 = 系统默认（`sys_config`，不是 yml）。两字段都填时：overlap > 0 且 overlap < chunkSize。
3. **片段浏览：** 附件区打开只读列表，`GET /ai/knowledge/{id}/fragments`。前端补 API 封装。禁止新 path、禁止改 fragment。
4. **浏览器点选：** 建库 → 可选模型 →（可选）填切块参数 → 上传 txt/md → 解析 → 看见切块。无登录环境则 92 第 4 节写未点选。

解析失败展示 `parse_msg`。不改对话发送 body。**本对话框不出现**向量 type / Weaviate host / DashVector endpoint / 向量 API Key。
