## 1. 问题与目标

开源仓 `core/ai` 只是「网关 + 薄转发」：出站代理、权限、审计、Tool 注册表齐全，但**产品层在不可见的私仓 `apps.kuaiai`**——无会话持久化、无知识服务实现、无档案。要在开源侧（或经 KR-G0 确认的落点）按 `ktg-ai` 的领域模型把产品层补齐，同时把自写 6 轮循环换成 LangChain 官方运行时，拿到真流式工具轮、middleware 生态与 `with_structured_output`。

### 1.1 目标

- `apps/kuaiai` 承载产品语义：表、路由、服务、页面
- `core/ai` 保留通道骨架，仅新增 `runtime/` LangChain 适配，退役 `agent_runner.py` / `completion_service.py`
- 发送链路：会话持久化 + 历史回放 + 档案装配 + 工具 RBAC/审计 + 真流式 SSE
- 知识库：按类型解析 + pgvector 检索 + 可配切块

### 1.2 非目标（本期）

- 不改 `core/ai` 对外契约（KR-D4）；不迁私仓代码；不引第二 RAG 栈、AutoGen、外部向量库
- 确认闸（KR-D15）、已登录工作流（KR-D16）、模型多行目录（KR-G2）、OCR / HyDE / rerank
- 改 `riveredge-frontend` 非 AI 区域；改遗留 `frontend/`（startech 侧）

## 6. LangChain 运行时（`core/ai/runtime/`）

### 6.1 `model_factory.py`（≈ A24）

```python
_MODEL_CACHE: dict[tuple[int, str], ChatOpenAI] = {}

async def build_chat_model(tenant_id: int, model_id: int | None) -> ChatOpenAI:
    key = (tenant_id, str(model_id or "default"))
    if key not in _MODEL_CACHE:
        # 目录行优先：llm_models JOIN llm_providers（tenant_id 过滤 + status）
        # 无行 → AiRuntimeConfig.load(tenant_id) 单活连接兜底
        src = await resolve_model_source(tenant_id, model_id)
        _MODEL_CACHE[key] = ChatOpenAI(
            api_key=src.api_key, base_url=src.base_url,
            model=src.model_name, streaming=True,
            http_async_client=get_http_client())     # 复用平台连接池
    return _MODEL_CACHE[key]
```

缓存键 `(tenant_id, model_id)`（对齐 ktg-ai `(tenantId, modelId)` 语义）；`llm_providers`/`llm_models`/`IntegrationConfig`/site_settings 写路径 evict 对应键；禁全局 client；Key 只来自服务端解析（目录行或 `AiRuntimeConfig`），不回明文。provider 预设（deepseek/openai/qwen/zhipu/moonshot/siliconflow）仅作建表模板，`provider_type` + `base_url` 决定实际端点——不绑定固定厂商。

### 6.2 `agent_factory.py`

`build_agent(model, tools, system_prompt, middleware, checkpointer=None)` → `create_agent(...)`；`recursion_limit` 由调用方经 `config` 传入（默认上限 8，替代 `MAX_TOOL_ROUNDS`）。

### 6.3 `tool_bridge.py`（≈ A31 子集 + RBAC/审计）

- `registry_to_lc_tools(names, executor)`：`ToolRegistry` 定义 → `@tool` 包装（args_schema 由 definition 生成），体内仍调 RBAC'd `executor.execute(name, args)`；
- `wrap_tool_call` middleware：查 `RegisteredTool.permission` vs 当前 `AuthContext`（经 `runtime.context` DI 透传）→ 无权限回 `ToolMessage(status="error")`；计时 + 写 `core_ai_audit_logs`（KR-D17）。

### 6.4 `sse_adapter.py`

`agent_to_openai_sse(agent, messages, config)`：`astream_events(version="v2")` → 仅取 `on_chat_model_stream` → 翻成 `choices[].delta.content` chunk → `[DONE]`；`on_tool_start/end` 可扩展为 status 事件（线格式白名单外可丢）。前端零改。

### 6.5 `memory.py`

`to_lc_messages(rows)`（§8 回放规则）+ 窗口截断封装；checkpointer 留口（默认 `None`，KR-G3）。

### 6.6 执行流程

**路径 A 纯对话流式**（无档案 / `enabled_tools` 空）：

```text
POST /api/v1/core/ai/chat/completions → RBAC → AiAuth
→ create_chat_completion → find_spec → apps.kuaiai DeepSeekService
→ chat_service.send:
    验 session 归属(tenant+user) → 写 user 行
    → history = SELECT ... tenant_id+session_id ORDER BY seq → to_lc_messages → trim
    → agent = build_agent(model, tools=[], prompt) 
    → agent_to_openai_sse(astream_events) → wrap_ai_sse_stream → StreamingResponse
    → 末尾写 assistant 行 + token 回填
```

**路径 B 带工具**（选中档案）：同 A，区别在 `agent_assembler` 产出 tools/prompt/model，`tool_bridge` middleware 生效；`astream_events` 全程真流式；工具轮次按 §8 落行。

**路径 C 结构化**：`chat_model.with_structured_output(TargetSchema)` → `ainvoke` → 校验过的 pydantic 对象；图片走多模态 content block。

**路径 D MCP**：`mcp_client_service` 按档案 `mcp_server_ids` 取白名单连接 → `MultiServerMCPClient` → `load_mcp_tools(session, tool_interceptors=[RBAC])` → 并入 tools。

**路径 E RAG**：`retrieval.search(tenant_id, kid, vector, top_k, min_score)` pgvector SQL；`search_knowledge` 以 `@tool` 注入（kid 白名单闭包烤死）；或 `before_model` middleware 注入片段（file_name/source_ref 等价 metadata）。

## 7. Agent 档案装配（KR-D8/D9）

三步流对齐 ktg-ai：页面维护档案 → chat 页 `context.agent_id` 选择 → 发送时装配。

```text
agent_assembler.assemble(tenant_id, auth, agent_id):
  1. 查档案（tenant 过滤，跨租户 404；status=正常）
  2. grant_service.check(agent, auth)：ROLE 命中任一角色 / USER 在名单 → 不过 403
  3. model = build_chat_model(tenant_id, 档案.default_model_id)  # 目录行→provider+model_name；缓存键 (tenant, model_id)
  4. tools = registry_to_lc_tools(档案.enabled_tools)
           + knowledge_search_tool(档案.knowledge_ids)
           + mcp_tools(档案.mcp_server_ids)
  5. build_agent(model, tools, 档案.system_prompt, middleware, checkpointer=None)
```

每请求新建 agent（图构造毫秒级）；可选 `(tenant_id, agent_id, profile_updated_at)` 缓存编译产物，保存时 evict（同 A24 纪律）。授权/装配置于 send 入口，无授权档案不构造 agent、不静默降级（KR-D9）。

## 8. 会话持久化与历史回放（KR-D6/D7）

**写路径**：user 行先落 → 运行 → assistant 行（含最终文本）与工具行（`role=tool` / assistant.`tool_calls`）落库 → token 回填。SSE 边流边累积，结束后一次落库。

**回放规则**：

```python
role=="user"      → HumanMessage(content)
role=="assistant" → AIMessage(content or "", tool_calls=row.tool_calls or [])
role=="tool"      → ToolMessage(content, tool_call_id=..., name=...)
```

只存文本不存工具行的降级方案可用但多轮工具问答退化——默认存工具行（三列成本）。

**窗口**：`trim_messages` 留尾部 N 条/token 预算；超长会话用 `langchain.agents.middleware.SummarizationMiddleware` 压摘要（可选，进 KR-G6 一并定）。

**checkpointer 留口**（方案 C 预留）：`thread_id="{tenant}:{user}:{session}"`（只服务端生成，禁客户端传）；需要 interrupt/resume（确认闸）或崩溃恢复时再开，届时消息表仍写（双写纪律：消息表=展示/审计真相，checkpoint=执行现场）。

## 9. 知识库与 RAG（KR-D12）

| 环节 | 选择 |
| --- | --- |
| 解析路由 | `pdf`→`pypdf`；`docx/pptx`→python-docx/pptx（如未引则加轻量解析包）；`xls/xlsx`→`openpyxl`（已在依赖）；`md/txt`→文本；魔数/类型探测失败 → `status=failed` 不落乱码 |
| 切块 | `langchain-text-splitters` `RecursiveCharacterTextSplitter`；`chunk_size`/`chunk_overlap`/`separator` 可配（库级列 + 租户默认） |
| embedding | `OpenAIEmbeddings(api_key, base_url, model)`，维度随模型（现表 `vector(768)`，换维度须迁列/分表，见 KR-G7） |
| 检索 | 直写 SQL：`embedding_vector <=> %s`，`WHERE tenant_id=? AND document_id IN (...)`，`min_score`/`top_k` 过滤；HNSW 已建 |
| 注入 | 片段带 `file_name`/`source_ref` 等价 metadata；无命中走纯对话 |

不建 `VectorStoreService` 式工厂；外部向量库诉求记 KR-G7。

## 10. MCP 白名单（KR-D11）

`mcp_servers` 表存加密连接（复用 `IntegrationConfig` 加密/打码惯例）；`MultiServerMCPClient` 按 `mcp_server_ids` 子集建连；`load_mcp_tools(tool_interceptors=[...])` 内做权限+审计+超时；远程 server 必须登录租户白名单行，禁 SQL MCP、禁匿名。

## 11. 确认闸预案（KR-D15 本期不做）

| 方案 | 机制 | 取舍 |
| --- | --- | --- |
| interrupt+checkpointer | `HumanInTheLoopMiddleware`/`InterruptOnConfig` 中断 → checkpoint 存现场 → `Command(resume)` 续跑同一 run | 语义最正；须开 checkpointer（方案 C）+ LangGraph 自有表 |
| `action_pending_tokens` | 轮次正常结束回「待确认」→ 确认后直调业务 service → 可选新起一轮告知模型结果 | 表已建、与 checkpointer 无关；不是「恢复 run」 |

届时按 KR-G3 拍板，本期两侧都只留接口位。

## 16. 风险
