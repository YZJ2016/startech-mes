## 1. 问题与目标

开源仓 `core/ai` 只是「网关 + 薄转发」：出站代理、权限、审计、Tool 注册表齐全，但**产品层在不可见的私仓 `apps.kuaiai`**——无会话持久化、无知识服务实现、无档案。要在 `kuaigeyun-mes` 的 `apps/kuaiai` 按 `ktg-ai` 的领域模型把产品层补齐，同时把自写 6 轮循环换成 LangChain 官方运行时，拿到真流式工具轮、middleware 生态与 `with_structured_output`。

### 1.1 目标

- `apps/kuaiai` 承载产品语义：表、路由、服务、页面
- `core/ai` 保留通道骨架，仅新增 `runtime/` LangChain 适配，退役 `agent_runner.py` / `completion_service.py`（含 im/OCR/视觉改走 `model_factory`）
- 发送链路：会话持久化 + 历史回放 + 档案装配 + 工具 RBAC/审计 + 真流式 SSE
- 知识库：库级配置 + 按类型解析 + pgvector 检索 facade（压缩/展开/RRF/打分/±1 扩窗）

### 1.2 非目标（本期）

- 不改 `core/ai` 对外契约签名（KR-D4）；不迁私仓代码；不引第二 RAG 栈、AutoGen、外部向量库
- **非 OpenAI 兼容的原生协议**（厂商私有 SDK、不能走 `/chat/completions`）不在本期（KR-D5 边界）；阿里云仅兼容模式地址在本期
- 确认闸（KR-D15）、已登录工作流（KR-D16）、HyDE、OCR 扫描件、BM25/hybrid、FAQ/`training_samples` 产品化、审计查询页、密钥轮换
- 改 `riveredge-frontend` 非 AI 区域（**例外：** 已登录布局只加 F1 挂钩，见 KR-G0）；改遗留 `frontend/`（startech 侧）

## 6. LangChain 运行时（`core/ai/runtime/`）

### 6.1 `model_factory.py`（≈ A24；KR-D5）

```python
_MODEL_CACHE: dict[tuple[int, str], ChatOpenAI] = {}
_EMBED_CACHE: dict[tuple[int, str], OpenAIEmbeddings] = {}

async def resolve_model_source(tenant_id: int, model_id: int | None):
    # 目录行优先：llm_models JOIN llm_providers（tenant_id 过滤 + status）
    # 无行 → AiRuntimeConfig / IntegrationConfig 单活连接兜底
    # 返回仅：base_url + api_key + model_name（及 model_type）
    ...

async def build_chat_model(tenant_id: int, model_id: int | None) -> ChatOpenAI:
    key = (tenant_id, str(model_id or "default"))
    if key not in _MODEL_CACHE:
        src = await resolve_model_source(tenant_id, model_id)
        _MODEL_CACHE[key] = ChatOpenAI(
            api_key=src.api_key, base_url=src.base_url,
            model=src.model_name, streaming=True,
            http_async_client=get_http_client())     # 复用平台连接池
    return _MODEL_CACHE[key]

async def build_embeddings(tenant_id: int, model_id: int | None) -> OpenAIEmbeddings:
    key = (tenant_id, str(model_id or "default-embed"))
    if key not in _EMBED_CACHE:
        src = await resolve_model_source(tenant_id, model_id)
        _EMBED_CACHE[key] = OpenAIEmbeddings(
            api_key=src.api_key, base_url=src.base_url,
            model=src.model_name,
            # 维度仍受 KR-G7：写入 vector(768) 失败关闭
        )
    return _EMBED_CACHE[key]
```

缓存键 `(tenant_id, model_id)`（对齐 ktg-ai `(tenantId, modelId)` 语义）；`llm_providers`/`llm_models`/`IntegrationConfig`/site_settings 写路径 evict 对应键；禁全局 client；Key 只来自服务端解析（目录行或 `AiRuntimeConfig`），不回明文。

**出站规则（钉死）：**
- 一律 `ChatOpenAI` / `OpenAIEmbeddings`；**只用**该行（或兜底连接）的 `base_url` + api_key + `model_name`。DeepSeek、阿里云百炼（DashScope OpenAI 兼容地址）、其它 OpenAI 兼容端点均无代码厂商分支。
- 内置 deepseek/openai/qwen/zhipu/moonshot/siliconflow **仅**前端/种子可选填写模板（点一下带出常见 `base_url`，文档不写死真实地址）；保存后是普通目录行。**禁止**照搬现网 `LLM_PROVIDER_SPECS` 闭集：`provider_type` 枚举校验失败就拒绝自定义厂商。
- **消费方一律经本工厂（目录行优先）：** 对话、档案默认模型、知识库 embedding（`build_embeddings`）、结构化草稿、im、OCR/视觉。**禁止**「OCR/IM 继续只走旧单活 DeepSeek/`IntegrationConfig`、不受目录影响」。无目录行时兜底连接亦是 OpenAI 兼容 `base_url`+key，**不是** DeepSeek SDK / 厂商私有客户端；视觉不再绑 `deepseek_vision_client`。
- **不在本期：** 非 OpenAI 兼容原生协议（私有 SDK、不能走 `/chat/completions`）。阿里云兼容模式在本期，原生 SDK 不在本期。embedding **768 维失败关闭**（KR-G7）不变。
- 禁止直调已退役的 `CompletionService`。

### 6.2 `agent_factory.py`

`build_agent(model, tools, system_prompt, middleware, checkpointer=None)` → `create_agent(...)`；`recursion_limit` 由调用方经 `config` 传入（默认上限 8，替代 `MAX_TOOL_ROUNDS`）。

### 6.3 `tool_bridge.py`（≈ A31 子集 + RBAC/审计）

- Tool 闭集五值：`search_knowledge` / `query_workorder` / `list_workorder_tasks` / `submit_production_feedback` / `update_workorder_status`；保存未知名 400；默认不勾写 Tool。
- `registry_to_lc_tools(names, executor)`：`ToolRegistry` 定义 → `@tool` 包装（args_schema 由 definition 生成），体内仍调 RBAC'd `executor.execute(name, args)`（既有 service + 当前用户/租户，禁止 SQL）；
- `wrap_tool_call` middleware：查 `RegisteredTool.permission` vs 当前 `AuthContext`（经 `runtime.context` DI 透传）→ 无权限回 `ToolMessage(status="error")`；计时 + 写 `core_ai_audit_logs`（user/tenant/toolName/businessKey/latency/token，KR-D17）。

### 6.4 `sse_adapter.py`

主路径：`agent_to_openai_sse(agent, messages, config)`：`astream_events(version="v2")` → `on_chat_model_stream` 翻成 `choices[].delta.content` chunk → `[DONE]`。`on_tool_start/end` 另发顶层 `kuaiai_tool`（`phase` start/end、`name`、可选 `args_summary`/`result_summary`），`choices[].delta` 为空对象，不写入 `delta.content`。抽屉识别该帧并实时显示；不认识该帧的客户端只读正文即可忽略。落库工具轨迹仍是全宽历史的展示来源。

兼容分支（KR-D14）：端点不支持 `tool_calls` 流式时，该轮退回**非流式补全**，再适配成同一 OpenAI chunk 线格式。这是兼容分支，**不是**旧的整段假流式兜底，**不**恢复 `wrap_sse_from_completion`。正文线格式不变；抽屉额外消费 `kuaiai_tool`。

### 6.5 `memory.py`

`to_lc_messages(rows)`（§8 回放规则）+ 窗口截断封装；checkpointer 本期默认 `None`。将来确认闸再接（KR-G3：interrupt + 续跑同一 run）。

### 6.6 执行流程

**路径 A 纯对话流式**（无档案 / 未走 agent 路径）：

```text
POST /api/v1/core/ai/chat/completions → RBAC → AiAuth
→ create_chat_completion → find_spec → apps.kuaiai chat_service
→ chat_service.send:
    验 session 归属(tenant+user) → 写 user 行
    → history = SELECT ... tenant_id+session_id ORDER BY seq → to_lc_messages → trim
    → model = build_chat_model(...)  # ChatOpenAI（目录行或 AiRuntimeConfig）
    → 可选：请求带 knowledge_id → retrieval facade 注入片段
    → agent = build_agent(model, tools=[], prompt)
    → agent_to_openai_sse(astream_events) → wrap_ai_sse_stream → StreamingResponse
    → 末尾写 assistant 行 + token 回填
```

未选档案的纯对话**不**自动改挂默认档案。全宽 chat 无档案时可传目录 chat 模型 id；选了档案则只用档案 `default_model_id`，忽略请求级模型覆盖。

**路径 B 带工具**（选中档案 / 未传 agent_id 但走 agent 路径并解析到默认档案）：同 A，区别在 `agent_assembler` 产出 tools/prompt/model，`tool_bridge` middleware 生效；`astream_events` 全程真流式（不支持则走 §6.4 兼容分支）；工具轮次按 §8 落行。选中档案**不接受**请求级 `knowledge_id`，只用档案 `knowledge_ids` 经 `search_knowledge` Tool。

**路径 C 结构化：** `build_chat_model`（目录行优先，同 KR-D5）→ `with_structured_output(TargetSchema)` → `ainvoke` → 校验过的 pydantic 对象；图片走多模态 content block（vision 目录行经同一工厂，不绑 `deepseek_vision_client`）。

**路径 D MCP：** `mcp_client_service` 按档案 `mcp_server_ids` 取白名单连接 → `MultiServerMCPClient` → `load_mcp_tools(session, tool_interceptors=[RBAC])` → 并入 tools。

**路径 E RAG（唯一 facade，禁止 Tool / before_model 二选一）：**

```text
retrieval.retrieve(tenant_id, knowledge_ids, query, chat_model):
  1. 问句压缩（当前对话模型；失败回退原句，不 500、不跨租户）
  2. 有限展开（默认开，条数小，可配置关；在检索前生成少量问句变体）
  3. 每个变体 × 各库分别向量检索（WHERE tenant_id AND knowledge_id IN 已校验库；复用 embedding_vector）
  4. 多库命中 RRF 聚合
  5. 当前 chat 模型打分再排序（失败/超时保留 RRF 顺序）
  6. 命中按同一 document、chunk_index ±1 回表扩窗（禁止整篇进提示词）
  7. 返回带 file_name/source_ref 等价 metadata 的片段；无命中则空
```

- 纯对话：可选一个请求级 `knowledge_id` → facade 注入。
- 档案路径：`search_knowledge` Tool（kid 闭包烤死，调用时复核归属）→ 同一 facade。
- 仍不做：HyDE、OCR 扫描件、BM25/hybrid、单次检索多向量库融合、外部向量库。

**路径 F 抽屉页上下文：** 服务端用白名单 `screen` 拼页名；单据侧只信按 `resource_key`/`record_id` 查到的单号；客户端 `screenLabel`/`recordLabel` 不进 prompt；有读权限则调既有 service 拼短摘要（状态/数量类），禁止整单 JSON/SQL；未知或无权限省略摘要，不 500。全宽 `/apps/kuaiai/chat` 不传这套页上下文。

## 7. Agent 档案装配（KR-D8/D9）

三步流对齐 ktg-ai：页面维护档案 → chat 页 `context.agent_id` 选择 → 发送时装配。

```text
agent_assembler.assemble(tenant_id, auth, agent_id):
  1. 查档案（tenant 过滤，跨租户 404；status=正常）
  2. grant_service.check(agent, auth)：ROLE 命中任一角色 / USER 在名单 → 不过 403
     （配置权≠使用权；悬挂 role/user id 不产生授权）
  3. model = build_chat_model(tenant_id, 档案.default_model_id)  # 目录行→provider+model_name；缓存键 (tenant, model_id)
  4. tools = registry_to_lc_tools(档案.enabled_tools ∩ 五值闭集)
           + knowledge_search_tool(档案.knowledge_ids)   # 库 id，非文档 id
           + mcp_tools(档案.mcp_server_ids)
  5. build_agent(model, tools, 档案.system_prompt, middleware, checkpointer=None)
```

每请求新建 agent（图构造毫秒级）；可选 `(tenant_id, agent_id, profile_updated_at)` 缓存编译产物，保存时 evict（同 A24 纪律）。授权/装配置于 send 入口，无授权档案不构造 agent、不静默降级（KR-D9）。

授权边角：启用档案空名单 400，停用允许空名单；切换 `ROLE|USER` 同一事务清空另一侧；管理 list = 本租户全部档案，options = 当前用户可用的启用档案。

默认档案：仅当未传 `agent_id` 且发送走 agent 路径时解析并做同一使用权校验；纯对话不自动改挂。新系统可不强制种子；若种子，`enabled_tools` 只有 `search_knowledge`。

## 8. 会话持久化与历史回放（KR-D6/D7）

**写路径**：user 行先落 → 运行 → assistant 行（含最终文本与 `tool_calls`）与工具行（`role=tool`）落库 → token 回填。SSE 边流边累积，结束后一次落库。**必须继续存 tool 行**，供全宽 chat 重开渲染工具轨迹。

**回放规则**：

```python
role=="user"      → HumanMessage(content)
role=="assistant" → AIMessage(content or "", tool_calls=row.tool_calls or [])
role=="tool"      → ToolMessage(content, tool_call_id=..., name=...)
```

只存文本不存工具行的降级方案不可取——默认存工具行。

**窗口**：`trim_messages` 留尾部 N 条/token 预算；超长会话可用 `SummarizationMiddleware` 压摘要（可选，不挡主路径）。

**checkpointer（KR-G3 已选，本期不接）**：将来确认闸用 interrupt，`thread_id="{tenant}:{user}:{session}"`（只服务端生成，禁客户端传），`Command(resume)` 续跑同一 run。消息表仍写（展示/审计真相），checkpoint 只存执行现场（方案 C 双写）。`action_pending_tokens` 不作选定机制。

**前端展示**：全宽 chat 历史渲染 `role=tool` 与 `assistant.tool_calls`（名称、参数摘要、结果文本）。抽屉实时消费 SSE 顶层 `kuaiai_tool`（开始显示「正在调用」及参数摘要，结束改为「已调用」及结果摘要），不把该帧拼进回答正文。SSE 正文线格式仍是 OpenAI chunk。

## 9. 知识库与 RAG（KR-D12）

| 环节 | 选择 |
| --- | --- |
| 库表 | 新建 `apps_kuaiai_knowledge_bases`；documents 增 `knowledge_id` FK；档案 `knowledge_ids` = 库 id |
| 原文 | `file_uuid` → 快格既有文件/对象存储读流；禁扫服务器磁盘、禁未隔离临时目录当语料库 |
| 解析路由 | `pdf`→`pypdf`；`doc`/`docx`/`ppt`/`pptx`→对应轻量解析包（缺包列入依赖）；`xls`/`xlsx`→`openpyxl`；`md`/`txt`→文本；魔数失败或抽出文本为空 → `status=failed` + `error_message`，不落乱码 chunk |
| 切块 | `langchain-text-splitters` `RecursiveCharacterTextSplitter`；库级列可空，空则回落租户可运营配置（site_settings/参数机制，不新写 yml）；`overlap > 0` 且 `< chunk_size` |
| embedding | 绑目录 `model_type=embed` 行，经 `build_embeddings`（`OpenAIEmbeddings` + 该行 base_url/key/model_name）；空则本租户第一条启用 embed；无可用 embedding → 解析失败不得标成功；**本期只接受 768 维**，维度 ≠ 768 → 该库解析失败关闭，不截断、不静默写入；换维迁列与向量物理出库 **KR-G7 不进本期** |
| 生命周期 | 删文档同事务删 chunks（含向量）；支持重解析；片段浏览只读；FAQ/`training_samples` 不接产品 |
| 检索 | 唯一 facade：压缩 → 有限展开（检索前）→ 分库检索 → RRF → 打分再排序（失败保留 RRF）→ `chunk_index ±1` 扩窗；`WHERE tenant_id AND knowledge_id IN (...)`；本期 pgvector 同库 |
| 注入入口 | 纯对话可带一个 `knowledge_id` 注入；档案路径仅 `search_knowledge` Tool；两者同一 facade |
| metadata | 片段带 `file_name`/`source_ref` 等价字段；无命中走纯对话 |

不建 `VectorStoreService` 式工厂；可配置维度与外部向量抽象都不进本期（KR-G7）。`rag_backend=llamaindex` 废弃（KR-G6 已收口），`llama-index-core` 仅留 optional extra 槽位。

## 10. MCP 白名单（KR-D11）

`mcp_servers` 表存加密连接（复用 `IntegrationConfig` 加密/打码惯例，不新建 cipher、不复用数据库口令密钥；轮换不进本期）；`MultiServerMCPClient` 按 `mcp_server_ids` 子集建连；`load_mcp_tools(tool_interceptors=[...])` 内做权限+审计+超时；远程 server 必须登录租户白名单行，禁 SQL MCP、禁匿名。options/详情/日志/SSE 不回明文。

## 11. 确认闸（KR-D15 本期不做；机制已选）

将来做确认闸时**只走已选路径**（KR-G3）：`HumanInTheLoopMiddleware` / `InterruptOnConfig` 中断 → checkpoint 存现场 → `Command(resume)` 续跑同一 run；同时打开 checkpointer（LangGraph 自有表）。消息表继续写（展示/审计真相），checkpoint 只存执行现场（方案 C 双写）。`action_pending_tokens` **不是**选定机制（表可留着，本期不接，不作并列可选）。本期默认 `checkpointer=None`，不实现确认闸。

## 12. 前端（KR-F）

复用件保持 OpenAI 正文契约（抽屉/`AiContext`/顶栏按钮/`deepseekChat`/ai-draft）。抽屉额外识别 `kuaiai_tool` 扩展帧并实时显示工具调用。新页 `src/apps/kuaiai/pages/{chat,agents,knowledge,models,mcp}`：

- **chat：** 会话列表 + 档案下拉（options）+ Bubble/Sender；无档案可选目录 chat 模型（options 不下发密钥）；有档案用 `default_model_id` 且不再另传模型覆盖；历史渲染 tool 行与 `assistant.tool_calls`；不传页上下文摘要。
- **agents：** 表格/对话框 + Tool（五值闭集，默认不勾写）/MCP/知识库勾选 + 模式单选（角色多选 / 部门树选人）+ 模型目录下拉。
- **knowledge：** 库/文档/切块浏览 + embedding 模型下拉（只 embed）+ 切块参数 + 解析失败文案 + 重解析。
- **models：** 厂商与模型两表可增删改多行。厂商：名称、`base_url`、API Key（加密落库、回显打码、详情/options 不回明文或 cipher）——**不是**下拉死名单。模型：挂厂商、`model_name` 自由填、`model_type` 至少 chat/embed/vision。内置 deepseek/openai/qwen/zhipu/moonshot/siliconflow 仅为可选填写模板（点一下带出常见 `base_url`）；保存后仍是普通目录行，可改 URL/Key/模型名。
- **mcp：** 白名单表格（连接打码）。

全局热键 **F1**（KR-G5）：挂已登录布局全局 keydown、toggle、无入口权限不拦截、焦点在输入框内仍拦截 F1、窄屏可隐藏按钮但有权限时 F1 仍可用、抽屉提供打开全宽对话页的链接。实施时若与快格既有快捷键冲突，再改键并回写 KR-G5。工作台若已有「打开助手并预填、不自动发送」则保持。抽屉在调用发生时展示 `kuaiai_tool` 实时反馈；全宽页重开历史仍渲染落库工具轨迹。
