## 1. 问题与目标

开源仓有数据集、`UniReport` 执行钩子和八张 `apps_kuaireport_*` 表，没有可运行的星报表应用目录。私仓源码不在本仓。自研把产品放进 `apps/kuaireport`，按五段补齐执行、账表、设计器、大屏和分发。

### 1.1 目标

- 报表配置能执行，预览沿用 `UniReport` 已约定的 `data` / `total` / `summary`
- KRP-D6 列出的系统报表能打开、能导出
- 账表设计器只改 `report_config`，大屏使用已有布局与组件字段
- 分享、授权、订阅、版本回看落在迁移 563 已有表上

### 1.2 非目标

- 数采、设备运营馈送、数采专用接口
- 搬迁星制造写死看板页
- 跨库关联、在报表配置中存放任意 SQL
- 合并进 `startech-mes-basic` 或 UReport
- 新造一套报表表，或改已经进过库的迁移文件名

## 2. 落点与依赖

```text
apps/kuaireport（后端 + 前端 manifest）
  数据源与执行     读平台数据集；HTTP 只读已登记地址
  报表 / 大屏配置  apps_kuaireport_reports / dashboards / data_sources
  预览             UniReport config 模式
  版本与分发       迁移 563 的 versions / share_* / subscriptions
```

依赖保持在开源仓已有能力上，核心平台尽量不改：

- 查询执行器：平台数据集（SQL / API）。报表侧只引用数据集，不把 SQL 正文抄进 `report_config`。
- 预览与打印：`UniReport`。不另做一套表格。
- 全量导出：后端生成 Excel，不靠浏览器拼全表。
- 免登录分享入口：已约定路径 `/apps/kuaireport/dashboards/shared` 与 `/apps/kuaireport/reports/shared`（**KRP-D9**）。不扩大到这两条以外的匿名面。

槽位收归：`.gitignore` 中本应用的排除，以及 `fast-deploy/tools/workspace/generate_workspace.py` 的 `PRO_APPS` 中的对应项，要去掉，写法对齐星 AI 已收归的注释。目的是提交能入库，且专业包组装不再删掉这个目录。不对 `kuaireport` 执行私仓 `compose`。

## 3. 五段方案与取舍

### 3.1 执行引擎（KRP-P1）

先有数据源和执行，后面的设计器才有可保存、可预览的对象。

数据源三种：`static`、引用现有数据集、HTTP。HTTP 地址必须先登记在已有 `apps_kuaireport_data_sources`，执行时只允许这些登记行。不另起白名单表。

`executeReport(reportId, filters)` 按该报表 `report_config` 的字段、筛选、分页、合计返回 `data` / `total` / `summary`。一张报表只绑一个数据源。

跨业务账（销售、采购、物料追溯）写成系统报表，查询落在 MES 这一个库。取舍：不做跨库关联，避免报表配置变成任意 SQL 入口。

### 3.2 账表（KRP-P2）

报表中心提供列表、草稿/发布、业务分类、系统报表与自定义报表。预览和打印交给 `UniReport`。

系统报表配置写入 `report_config`，由代码种入，不依赖设计器。名单以缺口 18 的 **KRP-D6** 为准，含效能统计。这些行出现在报表中心的系统报表中，不为此恢复已下线的「效能中心」侧栏。「分析报表」「跨业务报表」不另种一张表。星制造原有固定页保持不动，避免两套入口互相覆盖。

本段结束时能查、能导出，列还不能拖。这是故意的：设计器放在执行和种入之后。

### 3.3 表格设计器（KRP-P3）

设计器只编辑账表的 `report_config`：选数据源、列、筛选、格式、合计。保存写入已有 `apps_kuaireport_report_versions`。本段不编辑大屏字段。版本回看与恢复放到分发段，避免设计器同时承担发布治理。

### 3.4 大屏（KRP-P4）

用已有字段：`layout_config`、`widgets_config`、`theme_config`、`tv_config`。每个组件一个数据源、一个刷新间隔。一块大屏可以混用多个组件源，每个组件仍然单源。

组件分两截，都在本段内：先指标、表格、图表；再边框、标题、轮播、时钟、图片、视频、网页嵌入。第二截不提前做成独立产品。

预览与免登录分享使用已约定的 `/apps/kuaireport/dashboards/shared`。链接过期、访问口令、IP 白名单、访问日志与该入口同段做完（KRP-D7）。过期、口令哈希、IP 白名单用大屏表上已有列；访问日志用 `apps_kuaireport_share_access_logs`。P4 结束时，打开的分享链接已经受这四项约束。访问口令只走应用内已有的存储与打码方式，文档不写口令、不新造一套密钥配置。

空 IP 白名单（**KRP-D8**）：`share_allow_ip_cidrs` 为空时不做 IP 匹配，过期与访问口令仍然有效。非空且 IP 不在名单内才拒绝。白名单是可选加严，不是打开分享的必填项。大屏与账表同一套规则。

账表免登录路径同期交付（**KRP-D9**）：`/apps/kuaireport/reports/shared` 与大屏同一套四项管控，通过后才返回账表数据。页面为 `riveredge-frontend/src/apps/kuaireport/pages/ReportSharedView.tsx`。KRP-D6 的 10 张系统报表默认不开启分享，须人显式打开后才签发免登录链接；种入仍在 P2，本段不改这些行的默认不分享。登录后的按角色授权仍在 P5。

### 3.5 分发（KRP-P5）

沿用迁移 563 的表，不新增分发表。分享链接的四项管控（含账表免登录，**KRP-D9**）已在 KRP-P4。本段不做这四项，只做下面三件，顺序固定：

1. 按角色授权（`apps_kuaireport_share_grants`）
2. 定时订阅：附件是现有 `MessageService.send_message` 的可选参数。不传附件时请求体和原有列不变；传了则工作簿随同一次站内信落在 `core_message_logs` 的 `attachment_name` / `attachment_content`。收件人用现有用户消息下载接口取字节，列表和详情只给文件名（`apps_kuaireport_report_subscriptions`）
3. 版本回看与恢复（`apps_kuaireport_report_versions` / `apps_kuaireport_dashboard_versions`）

## 4. 数据归属

| 数据 | 归属 |
| --- | --- |
| 报表定义、`report_config`、草稿/发布、分类 | `apps_kuaireport_reports` |
| 大屏布局与组件 | `apps_kuaireport_dashboards` |
| 数据源登记（含 HTTP 地址） | `apps_kuaireport_data_sources` |
| 账表版本 / 大屏版本 | `apps_kuaireport_report_versions` / `apps_kuaireport_dashboard_versions` |
| 分享授权、访问日志、订阅 | 迁移 563 对应三张表 |
| 数据集 SQL / API 定义 | 平台数据集，报表只引用 |
| 星制造固定看板 | 原应用页面，不写入星报表表 |

租户沿用快格现有行级 `tenant_id`。无租户上下文不读这些表。分享入口是本应用唯一约定的免登录面，其它报表接口保持登录。日志不记录访问口令或内部路径。

## 5. 与数采的分界

报表五段收口标准：能建数据源，能设计并发布一张账表，能设计并分享一块受控大屏（KRP-D7），并能按 KRP-D9 分享一张受控账表，KRP-D6 的系统报表能打开。收口前报表不调用数采。数采把 `equipment-ops-feed` 登记成普通 HTTP 数据源时，同时种入一张已绑定该源的设备运营大屏，设计器仍可改布局，见设计 19。星报表不出现数采专用接口。
