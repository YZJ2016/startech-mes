## 1. 问题与目标

当前 MES 是**单租户**：所有业务表无 `tenant_id`；`LoginUser` 只有 `userId`/`deptId`；JWT claims 无租户；MyBatis 唯一拦截器是审计字段填充；`@DataScope` 只在 `ktg-system` 做部门/本人过滤；动态数据源是 MASTER/SLAVE，不是按租户切库。`workshop_id` / `warehouse_id` 是车间与仓库维度，不能当租户键。

v1 要让同一套后端安全地承载多个工厂租户，并保持现有 `code/msg/data`（及登录 `token` 字段）契约。**默认**仍是同一库、同一主连接池、列级 `tenant_id`；**每个租户在创建时**可指定隔离级别，高隔离客户走独立 JDBC（懒加载连接池），而不是事后靠开关切库。

### 1.1 目标（v1）

- **创建租户时配置隔离级别**（见 2.1）：默认 `ROW`（共享库行级）；可选 `DATABASE`（独立库）。
- 共享库路径：`tenant_id` 加在 include 表上，**失败关闭**（无租户上下文不得访问租户表）。
- 独立库路径：该租户懒加载专用 DataSource；上下文与行上**仍然写 `tenant_id`**（纵深防御，一条拦截器/一套 Mapper）。独立库缺失或不健康 → **失败关闭**，禁止回落到主库。
- 登录先绑定租户记录，再按该记录**路由 DataSource**；登录后租户只来自服务端 `LoginUser`/JWT，**忽略客户端后续传来的租户**。
- 自定义 MyBatis 拦截器做全局 `tenant_id` 谓词与 INSERT 填充（不引入 MyBatis-Plus、不引入第二套认证/ORM）。**无论哪一档隔离，include 表都走同一拦截器。**
- 先租户硬隔离，再叠加现有 `@DataScope`。
- 菜单/字典共享；模块许可用独立许可表，**禁止把菜单复制进每个租户**。
- 平台租户管理租户与许可。列表默认只回打码 JDBC / 用户名 / 打码口令；**明文仅经带审计的揭开接口**（F4）。独立库凭据落库须加密，密钥只来自环境变量。
- 缓存、文件、异步、Quartz 任务携带租户；空上下文不得使用空缓存前缀。
- 现网数据一次性回填为 `tenant_id=1`，单租户行为对现有用户保持连续。平台/运营租户固定走共享主库。

### 1.2 非目标（v1 明确不做）

- 把隔离级别做成创建后的**开关**：`ROW` ↔ `DATABASE` 是迁数项目（见 2.1.4），**v1 禁用改档**（D8），不预留迁数工单入口。
- 第三档「MySQL schema 隔离」：在 MySQL 上 SCHEMA 与 DATABASE 同义，与 `DATABASE` 无独立语义（见 2.1.2）。
- 启动时为所有租户 eager 建池（Jugg 路线）；独立库池必须懒加载。
- 专库失败时回落主库；登录后信任客户端租户头；把菜单复制进每个租户库；列表/详情**默认**回传 JDBC 明文口令，或揭明文不写审计。
- 引入 Sa-Token、第二套 JWT、JPA、MyBatis-Plus `@DS`。
- 把 Vue 3 写进 `frontend/`。管理端只走 Vue3（F1）；`frontend/` 不改、不作为上线管理端。
- 重写历史初始化 SQL、对现网跑 `DROP TABLE`。
- 跨租户报表（含普通 MES 报表、UReport、平台特权仪表盘）：v1 全部不做（D5）。查询仅当前租户。跨**独立库**的 SQL JOIN 永远做不到。
- 改造 `ktg-generator` 业务行为（`gen_*` 仅列入拦截忽略表）。
- 改造 **MQ / Feign / Jugg 式开放域验签 / BPM**：现网 MES **未使用**这些通道，v1 不引入、不按 Jugg 旁路改造。
- **不把 WebSocket 当跳过项。** 现网站内信推送是活通道（`/websocket/message/{token}`），v1 **必须**按租户隔离（I9，随 P2）。

## 2. 决策记录

### 2.1 按租户可配置隔离级别

产品决定：数据隔离级别通过配置按租户设置；**新增租户时指定**，而不是全局只有一档。

#### 2.1.1 两档（`sys_tenant.isolation_level`）

落库枚举只设两档，默认 `ROW`：

| 存储值 | 产品别名 | 数据落点 | 连接池 | 何时用 |
| --- | --- | --- | --- | --- |
| `ROW` | SHARED / 行级共享 | 主库；include 表带 `tenant_id` | 与平台及其他 `ROW` 租户共用**现有主 Druid 池**（MASTER/SLAVE 语义不变） | **默认**；现网租户 1、平台租户 0 |
| `DATABASE` | DEDICATED / 独立库 | 该租户自己的 JDBC 目标库；行上仍有 `tenant_id` | **每租户一个池**，懒创建；启动不加载全部租户 | 监管/高隔离客户；加价例外 |

平台租户（`tenant_id=0`，`is_platform=Y`）**强制 `ROW`**，始终走共享主库，不允许配独立 JDBC。

#### 2.1.2 为什么不设第三档 SCHEMA

MySQL 中 `SCHEMA` 与 `DATABASE` 是同义词。所谓「同实例另一个 schema」就是另一条 JDBC URL（换库名，主机可相同），已被 `DATABASE` 覆盖：连接、迁移、备份、`max_connections` 预算与独立库相同。第三档不会带来可区分的隔离或运维语义，故不设。

若将来要「同实例多库」与「跨主机专库」在运维上分开报价，用 JDBC URL 本身区分即可，不必新枚举。

#### 2.1.3 创建租户时的配置字段

平台「新增租户」= **新建一家工厂租户**（F4），不是新建用户。API 与表单在编码/名称/状态/过期之外增加：

| 字段 | 约束 |
| --- | --- |
| `isolationLevel` | 必填语义，缺省 `ROW` |
| `jdbcUrl` / `jdbcUsername` / `jdbcPassword` | **仅当 `DATABASE` 时必填**；`ROW` 时忽略且不得落库明文 |
| 口令存储 | 写入时加密为 `jdbc_password_cipher`（或等价列）；密钥来自环境变量，禁止写进仓库或返回体 |
| 查询/列表 BO | 平台列表展示：编码、可选域名、隔离级别、**部分打码的 JDBC URL**、用户名、**打码口令**。禁止把 cipher 当密码回传。`ROW` 连接列为空 |
| 揭明文 | 查看完整 JDBC URL 或明文口令须**显式操作** + **审计**（操作者、时间、租户、字段）。审计**不得**写入明文。仅平台 `is_platform` 可调；工厂 403 |

校验：

- `ROW` + 传来 JDBC → 拒绝或丢弃（实现 spec 写死一种；推荐拒绝，避免误存）。
- `DATABASE` + 缺 URL/用户/口令 → 拒绝创建。
- P-D 之后：**先保存基本信息与 JDBC，后续步骤**才建 schema + 租户表增量，然后 ping。失败则登记**保留为未就绪**，不可登录，可改口令/权限后重试「创建 schema/表」；**禁止**删除登记，**禁止**把该厂数据写入共享主库。
- 页面分步（F4，2026-09-08 修订）：① 租户基本信息（编码、名称、可选 `server_name`）+ 开关「独立 DB」「独立向量数据库」；② 仅独立 DB 填写 JDBC（URL / 用户 / 口令）；③ 仅独立向量（须已登记）填写专向量连接；④ 仅独立 DB 执行创建 schema 与表。步骤条不展示未开开关的步。共享库且共享向量：填完①点完成即结束。列表见上：打码展示，揭明文须审计。共享向量地址不进本向导（yml）。

#### 2.1.4 创建后改隔离级别不是开关

变更 `isolation_level` **不是**表单上的 toggle，而是独立、高风险的迁数项目。**D8 已拍板：v1 直接禁用改档，不预留迁数工单入口。**

| 方向 | 含义 | 风险 |
| --- | --- | --- |
| `ROW` → `DATABASE` | 从共享库 **copy-out** 该 `tenant_id` 的全部 include 表 → 目标库；切枚举与 JDBC；切断共享库写入；再决定是否删除共享库残留 | 漏表、双写窗口、自增/唯一键、文件前缀仍按 tenantId 但库已换 |
| `DATABASE` → `ROW` | 从专库 **copy-in** 到共享库（`tenant_id` 仍为该租户）；切枚举；卸载专池；再下线专库 | 与共享库编码冲突、连接泄漏、回切窗口 |

v1：更新租户 API **拒绝**改 `isolation_level` 与 JDBC 目标 URL/库（D8）。不提供「迁数工单」。**JDBC 口令**只许平台覆盖重填（S6）；加密密钥轮换不进一期。需要变更隔离级别时单独立项，带备份与回滚。

#### 2.1.5 一条代码路径 vs 独立库额外项

**始终同一条路径（两档都要）：**

1. 登录解析 `sys_tenant`，绑定 `LoginUser.tenantId`（及隔离级别，供路由使用）。
2. 请求内 `TenantContext` + JWT/`LoginUser`；登录后忽略客户端租户头。
3. `TenantLineInterceptor` 对 include 表：无上下文抛错；SELECT/UPDATE/DELETE 加 `tenant_id = ?`；INSERT 填充/校验。**独立库里即便只有一个租户，也过滤 `tenant_id`。**
4. 唯一索引 DDL 保持 `(tenant_id, 业务键)`，专库不改成「仅业务键」，以免两套 Mapper XML。
5. 菜单不克隆；许可表裁剪路由；失败关闭；不引入 Plus / Sa-Token。

**仅 `DATABASE` 额外：**

- 加密 JDBC 的写入与解密（只在服务端路由时）。
- 按租户懒建/销毁 Druid 池；停用时卸载池。
- 路由：登录成功后业务 SQL 默认打专池；缺失/不健康则失败关闭。
- **全局/忽略表（`sys_tenant`、许可、菜单、字典、`QRTZ_*`、`gen_*`、`sys_config`）始终走主库**：I8 已拍板，**忽略名单 Mapper 整接口绑定主池**，不按表名回切、不克隆菜单。
- 对该租户库应用与主库相同的增量 SQL（I6/I7：由应用执行）。**不**把全局表拷进专库。
- JDBC 账号必须能 `CREATE DATABASE`（MySQL 上即 schema）及对该库 DDL；文档不写真实口令。
- `max_connections` 随专池线性增加，必须有运维上限意识。
- 报表不能跨专库做 SQL JOIN。

#### 2.1.6 连接池策略

| 租户 | 池 |
| --- | --- |
| 平台 + 所有 `ROW` | 现有主 DataSource（单池，MASTER/SLAVE 仍由 `@DataSource` 切换，与租户无关） |
| 每个 `DATABASE` | 独立 Druid 池；**启动不扫描全部租户建池**；开通时应用建库+迁表后可 ping；池仍懒加载，不因此 eager 常驻所有池 |
| 停用 / 删除租户 | 拒绝登录 + 作废该租户 token；若存在专池则 **close + 从路由表移除**，避免连接泄漏。**不删库** |
| 专池不健康 | 该租户请求失败关闭，不借用主池 |

运维警告：MySQL `max_connections`、应用侧每个池的 `maxActive` × 专库租户数，必须按容量规划；专库不是「免费更安全」，是连接与迁移成本换隔离。

#### 2.1.7 Schema 迁移

- `ROW`：增量脚本只打**共享主库**一次。
- `DATABASE`：**应用**把与主库同一套增量打到该租户库（I6/I7）。新建时：保存加密 JDBC → 若缺失则 `CREATE DATABASE` → 跑身份表 + MES 租户表 DDL（空表）→ 插入角色/角色菜单授权模板 → ping 健康检查 → 才可登录。全局表（`sys_tenant` / 许可 / 菜单 / 字典 / `QRTZ_*`）**不**进专库。
- 主库后来的增量也必须由应用打到每个已启用的 `DATABASE` 租户；某专库未迁成功 → **该租户**失败关闭（不可登录或拒绝业务 SQL），**禁止**为对齐去把该租户写进共享主库，也不要为对齐去改拦截器。
- 这不是 D8：自动建库/迁表只服务**新 DATABASE 租户**及之后的增量，不是 ROW↔DATABASE 改档迁数。

### 2.2 为什么默认仍是共享库 + `tenant_id`

| 选项 | 与现状匹配 | 主要成本 | 结论 |
| --- | --- | --- | --- |
| A. 共享库 + `tenant_id` + 主池 + 失败关闭（`ROW`） | 现有一个 Druid 池、MASTER/SLAVE、一套 Mapper | 全表加列与唯一键改造；拦截器必须失败关闭 | **默认档** |
| B. 租户级独立 JDBC + 懒加载池（`DATABASE`） | 要在现有 MASTER/SLAVE 之上加「按租户选 DS」，连接数随专库租户涨 | 建库/迁脚本/下线/泄漏；MES 尚无编排 | **创建时可选**；路由在 P-D 落地；不是默认 |
| C. 继续单租户 + 用 `workshop_id` 冒充租户 | 维度语义错误，无法隔离用户/角色/库存 | 假隔离 | 否决 |
| D. 再加 MySQL SCHEMA 档 | 与 B 无法区分 | 枚举噪音 | 否决 |

MES mill 级多工厂、同一版本、同一套主数据模型、需要偶尔由平台看许可与健康度：`ROW` 更贴合运维与报表。物理专库留给「监管/高隔离客户」，在**创建租户时**显式选择。

### 2.3 从 Jugg 明确拒绝复制的部分

Jugg 仅作参考实现，**不是 Maven 依赖**。

| Jugg 做法 | MES 处理 |
| --- | --- |
| 每租户 eager 连接池 | `ROW` 共用主池；`DATABASE` **懒加载**一池，启动不加载全部租户 |
| 拦截器失败开放 | 失败关闭：无上下文访问租户表直接异常；专库缺失不回落主库 |
| 菜单复制进每个租户库 | 共享 `sys_menu` + 许可表裁剪路由 |
| 租户管理 API 下发 JDBC | 列表默认**打码** URL + 用户名 + 打码口令；明文只走带审计的揭开接口。专库凭据加密落库，路由时仅服务端解密 |
| Sa-Token / MyBatis-Plus `@DS` | 沿用 Spring Security + JWT + 现有 MyBatis；自建租户 DS 路由，不引入 Plus |
| 硬编码 `enableTenant`、`isPlatform` 不落库 | 租户状态与 `is_platform`、**`isolation_level` 必须落在 `sys_tenant`** |
| 停用租户 = 丢掉数据源（且往往连带不可用） | 停用 = 拒绝登录 + 作废 token；`ROW` 无专池可丢；`DATABASE` **卸载专池防泄漏**，库保留 |

可借鉴的顺序（不是抄代码）：会话/JWT 优先于域名/请求头；上下文传到任务/缓存/文件；平台租户 + 带过期的模块许可；专库连通性 ping。

## 3. 逻辑架构

```
请求
  → JwtAuthenticationTokenFilter
       解析 JWT uuid → Redis LoginUser（含 tenantId）
       若 LoginUser.tenantId 空或租户停用 → 401，不放行
       忽略 Header/Query/Body 中的 tenantCode（登录接口除外）
       读 sys_tenant（进程内缓存可有）：isolation_level
       TenantContext.set(tenantId)
       MDC.put("tenantId", ...)
       路由 DataSource：
         平台或 ROW → 共享主池
         DATABASE → 业务/身份表走懒加载专池；无池/不健康 → 失败关闭（禁止回落主池）
         全局忽略表（菜单/字典/许可/sys_tenant 等）→ 仍走主池（I8）
       SecurityContext 设置 Authentication
  → Controller（契约仍 AjaxResult：code/msg/data）
  → Service
       若方法标 @DataScope：Aspect 把部门/本人条件写入 BaseEntity.params.dataScope
  → Mapper
       TenantLineInterceptor（失败关闭，两档都执行）
         忽略表：不加 tenant 谓词
         租户表：无上下文 → 抛异常（不执行 SQL）
         INSERT：填充/校验 tenant_id == 上下文
         SELECT/UPDATE/DELETE：AND tenant_id = ?
       FieldMetaObjectHandler：审计字段
  → 已路由的 DataSource
  → finally：TenantContext.clear + MDC.remove（含异步装饰器与 Quartz after）
             不在 finally 里关闭专池（池按租户生命周期管理）
```

登录路径（在发 JWT 之前）：交互 `POST /login` 与移动端 `MobileLogin` / `GET /loginOuth` **同一套 F5**（F7）：Host 命中 `server_name` 则写死该厂（F6，不可改登别厂）；未命中则 **必须**有 `tenantCode`（D2）。加载 `sys_tenant` → 停用/过期拒绝 → **按 `isolation_level` 确认 DS 可路由**（`DATABASE` 且 P-D 未就绪或 ping 失败则拒绝登录）→ 再按 `(tenantId, username)` 查用户。失败文案统一为「用户名或密码错误」（D9），不暴露租户是否存在。缺 Host 且缺码 → 失败，**不**默认租户 1（D4 已作废）。

**过滤顺序（硬性）：** 租户谓词在 SQL 层永远存在（拦截器）→ `@DataScope` 只在租户结果集内再裁部门/本人。平台运营账号进入租户表时，必须显式 `@TenantIgnore` 或切换到目标租户上下文，禁止靠 `isAdmin()` 漏过租户条件。平台 `runAs(targetId)` 时 DS 必须跟目标租户走：目标是 `DATABASE` 则进该专池，不能在主库上假装该 `tenant_id`。

### 3.1 建议新增的类型（均沿用现有分层，不新开认证模块）

| 类型 | 建议位置 | 职责 |
| --- | --- | --- |
| `TenantContext` | `ktg-common` `com.ktg.common.tenant` | ThreadLocal；`getRequired()` 空则异常 |
| `Tenant` 实体 / `sys_tenant` | `ktg-system` | 注册表：编码、名称、状态、过期、`is_platform`、**`isolation_level`、加密 JDBC 列** |
| `SysTenantLicense` / `sys_tenant_license` | `ktg-system` | 模块许可 + 过期时间 |
| `TenantLineInterceptor` | `ktg-framework` | MyBatis 拦截器（两档共用） |
| `TenantDataSourceRouter` | `ktg-framework` | P-D：按租户选主池/专池；懒建、停用驱逐；失败关闭 |
| `@TenantIgnore` | `ktg-common` | Mapper 方法或表级忽略（仅平台 API / 全局表） |
| `TenantTaskDecorator` | `ktg-framework` | 包装 `threadPoolTaskExecutor`，拷贝 TenantContext + MDC + SecurityContext |
| JWT claim 常量 | `Constants`（已有 `LOGIN_USER_KEY` / `JWT_USERNAME`） | 新增 `JWT_TENANT_ID = "tenant_id"`，值为 Long |

平台表 vs 租户表由拦截器的**忽略名单 + 表名规则**决定，见第 4 节。不在实体上用 MyBatis-Plus 租户注解。`sys_tenant` 自身在忽略名单，查隔离级别与 JDBC 元数据时走主库。

### 3.2 平台租户 vs 工厂租户

| | 平台租户 | 工厂租户 `ROW` | 工厂租户 `DATABASE` |
| --- | --- | --- | --- |
| 建议 `tenant_id` | `0` | `1` 起；现网回填为 `1` | 同样 `1` 起的 id 空间（注册表在主库） |
| `sys_tenant.is_platform` | `Y`（落库） | `N` | `N` |
| `isolation_level` | 强制 `ROW` | `ROW`（默认） | `DATABASE` |
| 用户 | 运营账号（新建，D3：与现网 admin 拆分）。本租户可自管部门/岗位/角色/用户（D11）；种子部门/岗位见 S7 | 现网用户（含 `user_id=1` 的 admin，只操作本租户） | 该工厂用户（身份表在**该专库**，仍带 `tenant_id`） |
| 可调用 | 租户 CRUD、许可、停用；本租户系统管理（用户/角色/部门/岗位，数据仅 `tenant_id=0`）。v1 无跨租户报表（D5） | MES 业务 API | 同左，SQL 落在专库 |

| 不可 | 用平台身份默认 `SELECT` 全库业务表；把平台租户配成独立库；靠代码发全菜单绕过角色表 | 改其他租户数据、读 JDBC 口令 | 回落到主库；列表 API 吐出口令 |

`DATABASE` 租户的 `sys_user` 等身份数据在专库中。登录查用户必须已路由到该 DS，否则会在主库找不到用户或误命中。`sys_tenant` / 许可仍在主库（全局表）。

## 5. 认证与登录绑定

保持：**一套** Spring Security + JWT；`POST /login`、`GET /getInfo`、`GET /getRouters`、`Authorization: Bearer`；响应 `code/msg/data`，登录成功仍 `ajax.put(Constants.TOKEN, token)`。

### 5.1 v1 绑定规则（失败关闭）

1. 增量脚本插入平台租户 `tenant_id=0`（`tenantCode=platform`，`is_platform=Y`，`isolation_level=ROW`）与首个工厂 `tenant_id=1`（`tenantCode=default`，`ROW`）。两者 `server_name` 均为空（D10）。
2. 所有已分类租户表 `UPDATE ... SET tenant_id=1 WHERE tenant_id IS NULL`（加列时 `DEFAULT 1` 更稳）。当前无真实生产用户，回填只承接现有种子数据，不绑生产域名。
3. `LoginBody` 增加**必填** `tenantCode`。交互 `POST /login` **从第一天起始终要求该字段**（D2）。前端如何填这个字段见 **F5 / F6**。不把租户放在可伪造且登录后仍生效的 Header 作为权威来源。
4. `SysLoginService.login`：
   - 解析租户：必须有 `tenantCode` → 查主库 `sys_tenant`；**缺码 → 失败**，不绑定默认租户 1，也不按「仅一个启用工厂」省略。
   - 租户 `status` 停用或许可/租户过期 → **直接拒绝**，不发 token。对外文案与「用户不存在 / 密码错误」**同一句**「用户名或密码错误」（D9）。
   - **路由 DS**：`ROW`/平台 → 主池；`DATABASE` → 专池（懒建）。专池不可用或 P-D 未落地 → **拒绝登录**，不回落主库。
   - `UserDetailsServiceImpl.loadUserByUsername` 改为按 `(tenantId, username|mobile)` 查 `selectUserByUserName`（已在目标 DS 上；Mapper 必须带租户）。
5. `createLoginUser` 写入 `LoginUser.tenantId`。
6. `TokenService.createToken`：claims 增加 `tenant_id`；Redis **保持** `login_tokens:{uuid}` 存完整 `LoginUser`（值内含 `tenantId`；R6：**不**把租户加进 key 前缀，**不**加二级 SET 索引）。
7. 此后任何 API：**以 LoginUser.tenantId 为准**。请求体/头里的 tenant 一律忽略。平台「进入某工厂」见 **5.4（F9）**。现网 `admin`（`user_id=1`）不得做跨租户运维。
8. `GET /loginOuth` 与 `MobileLogin`：**与管理端同一套 F5**（F7，**取代 D4**）。Host 命中则写死该厂（F6）；未命中必须带 `tenantCode`。省略码且 Host 未命中 → 失败，**不**默认租户 1。

### 5.1.1 如何得到 `tenantCode`（F5 + F6，已拍板）

两种方式**互补**，不是二选一；**优先域名，解析不到再用输入框**。禁止登录前下拉展示全部租户。管理端登录页、`MobileLogin`、`GET /loginOuth` **同一规则**（F7）。

1. **优先：按当前 Host 解析（匿名、只回一个或空）**  
   客户端打开登录页时，用当前主机名调用匿名接口（路径在 P1/P9 spec 定，须加入现有 permitAll）。服务端**只**用 `request.getServerName()`（或 Host）匹配 `sys_tenant.server_name`：命中启用租户 → 返回这一个 `tenantCode`（不要带隔离级别、JDBC、用户列表）；未命中 → 空。  
   **禁止：** 查询参数指定任意编码做枚举、返回租户数组、返回其它工厂的名称。  
   命中后：编码输入框**隐藏且不可展开**（F6：不提供「使用其他编码」）。提交时仍把该码放进 Body。登录后权威仍是 JWT，不继续信 Host。  
   平台运营必须用平台自己的域名或**未绑定**入口（编码框）。从工厂域名进不去平台账号。

2. **兜底：编码输入框**  
   仅当未绑域名或 Host 未命中时显示「工厂编码」文本框。不知道编码则无法登录。没有「租户列表」接口。

`server_name` 非空则全局唯一。只许平台改编码和绑定域名（F10）；工厂管理员不能改，避免抢别人的登录入口。平台创建租户表单（F4）增加可选绑定主机名。

验证码 Redis `captcha_codes:` 发生在登录前，保持全局、不按租户。`pwd_err_cnt:` 必须改为含租户，否则两租户同名用户会互锁。

### 5.2 失败关闭清单（登录与会话）

| 条件 | 行为 |
| --- | --- |
| 租户不存在 / 停用 / 过期 / 用户名或密码错误 | 对外**同一句**「用户名或密码错误」（D9）；停用时 **立即作废该租户全部 Redis token**（D6：R6 SCAN `login_tokens` 按值中 `tenantId`） |
| 交互 `POST /login` 或缺 Host 命中时缺 `tenantCode` | 登录失败，不绑定默认租户（D2）；移动端同样（F7） |
| `DATABASE` 专池缺失、解密失败、ping 失败、P-D 未启用 | 登录失败 / 业务请求失败；**不**改用主库 |
| JWT 有 uuid 但 Redis `LoginUser` 无 `tenantId` | 视为无效会话 |
| 业务 SQL 时 `TenantContext` 空 | 拦截器抛错，不执行 |
| 客户端登录后改 Header 自称另一租户 | 忽略 |
| `enableTenant=false` 一类开关 | **不允许**做成「关掉拦截器」；最多「拒绝所有登录」 |

### 5.3 自助注册、找回密码、改密（F8，已拍板）

- **v1 关闭自助注册**（全局注册开关关掉）。不开「新用户默认进租户 1」。
- 找回/重置密码：与登录同一套 F5（域名命中写死该厂，否则手填 `tenantCode`），禁止租户下拉。
- 已登录改密：租户只来自 JWT，不再要编码。
- 验证码仍为登录前全局，不按租户配置。

### 5.4 平台进入某工厂（F9，已拍板）

仅平台租户上的独立运营账号（D3）可调用专门接口，在服务端 `TenantContext.runAs(targetId)`，**DS 随目标租户**（目标是 `DATABASE` 则进该专池）。

- 运营端**可以列出全部租户**（与登录页禁止列表相反）。
- 进入后页眉标明「正在代管工厂 X」；提供显式退出代管，回到平台租户上下文。
- 写审计（谁、何时、进入/退出哪个工厂）。工厂管理员**不能**发现被代管（不在工厂侧日志/页眉展示）。
- 现网 `admin`（`user_id=1`）不能 runAs。
- runAs **只**在 Vue3 PC 平台运营端；平板不是代管面（F3）。

### 5.5 新厂开通（I7 + I6，已拍板）

产品理由：开通更方便；强制系统维护好 SQL 增量脚本，专库不能靠运维手搓一套落后的 DDL。

- 创建空租户后，**复制一份角色 + 角色菜单授权模板**到该 `tenant_id`（指向全局 `sys_menu` 的 `menu_id`）。**不**按租户克隆 `sys_menu` 行，**不**复制物料等主数据。表由脚本建成空表，再插入模板角色。
- `DATABASE` 开通顺序（P-D 落地后，F4 分步）：① 保存租户基本信息；② 填写 JDBC URL / **用户 / 口令**并加密落库；③ **后续步骤**建 schema（若缺失则 `CREATE DATABASE`）→ 跑同一套租户表增量 → ping → 才允许登录。建库或迁表失败：**登记保留，状态未就绪，不可登录**；改完口令或权限后可再点「创建 schema/表」，不用重填基本信息。**禁止**因失败删除登记，**禁止**把该厂数据写入共享主库。
- **不**把全局表拷进专库：`sys_tenant`、`sys_tenant_license`、`sys_menu`、`sys_dict_*`、`QRTZ_*`、`gen_*`、`sys_config` 仍在主库（I8：忽略名单 Mapper 绑定主池）。「创建租户表」≠ 克隆菜单。
- JDBC 账号必须能 `CREATE DATABASE` 与对该库 DDL。这是开通前提，文档与接口不写真实口令。
- 主库 schema 演进后，应用须把**同一套增量**打到每个已启用 `DATABASE` 租户（I6）。**开通/现网清单路径：** 某库失败只阻断该租户。**Flyway 落地后启动迁 READY：** 改为整进程停，见缺口 06 A6 / 设计 05。
- 这不是 D8：自动建库/迁表只针对**新 DATABASE 租户**及之后增量，不是 ROW↔DATABASE 改档。
- `tenantCode` / `server_name` 只由平台填写（F10）。
- 开通 checklist（P-D spec）：谁点「创建 schema/表」、未就绪如何展示与重试、角色模板谁签。并行 N 与 JDBC `CREATE DATABASE` 权限验收在该 spec 写死。

## 6. 与 `@DataScope` 的组合

现用法（仅 ktg-system）：

```text
SysUserServiceImpl / SysRoleServiceImpl / SysDeptServiceImpl
  @DataScope(deptAlias=..., userAlias=...)
DataScopeAspect：非 admin 把 AND (dept/user 条件) 放入 BaseEntity.params.dataScope
Mapper XML：${params.dataScope}
```

落地后 SQL 逻辑形状（主库或专库相同）：

```sql
SELECT ... FROM sys_user u
 WHERE u.tenant_id = ?          -- 拦截器，不可被 admin 跳过
   AND ( ... 部门/本人 ... )    -- DataScope，admin(租户内) 可跳过
```

规则：

1. `SecurityUtils.isAdmin(userId==1)` 继续只影响 DataScope，**不影响**租户拦截器，也不影响 DS 路由。
2. 多租户后「租户内超管」用角色权限表达，不要继续把「全库超管」绑死在 `user_id=1`（D3 已拍板：现网 admin 只操作租户 1；SQL 永不跳过 `tenant_id`）。
3. MES 域今天几乎无 `@DataScope`；不要为了租户去给 md/pro 补部门权限。那是另一条需求。
4. 拦截器拼接必须使用占位符绑定 `tenantId`，禁止把 ID 拼进字符串（与 DataScope 现有字符串拼接不同；租户路径要更严）。

## 7. 缓存、文件、异步、Quartz

### 7.1 缓存（`CacheConstants` + `RedisCache`）

**R1 组装规则：** `RedisCache` **不**自动加租户前缀；get/set 签名不变。租户键由 `TenantCacheKeys`（名称随现有风格）组装。全局键（验证码、字典）仍用手写 `CacheConstants`。P2 改各调用点，不改 `RedisCache` 本体。

| Key | v1 策略 |
| --- | --- |
| `login_tokens:{uuid}` | **保持**此形态（R6）。值内含 `tenantId`，**不**把租户加进 key 前缀，**不**加二级 SET 索引。D6 停用：SCAN 全部 `login_tokens`，删除值中 `LoginUser.tenantId` 匹配的会话 |
| `captcha_codes:` | 登录前，全局（手写 `CacheConstants`） |
| `sys_dict:` | 全局共享，不按租户（手写 `CacheConstants`） |
| `sys_config:` | 随 D1：全局 `sys_config:{key}`；租户覆盖 `sys_config:{tenantId}:{key}` |
| `repeat_submit:` / `rate_limit:` | **必须**在有登录上下文时纳入 `tenantId`（R2）。登录前限流仍仅 IP |
| `pwd_err_cnt:` | **必须** `pwd_err_cnt:{tenantId}:{username}` |
| `upload_task_status:{tenantId}` | **必须**按租户（R3，`ZipFileUtil.UPLOAD_TASK_STATUS_KEY`）。空上下文禁止。同厂仍只允许一个并发 zip 任务（不是按用户） |

硬规则：需要租户前缀的缓存，`tenantId == null` → **抛异常**，禁止写成 `sys_config::key`、`pwd_err_cnt::admin` 或 `upload_task_status:` 空段。缓存按 tenantId，不按隔离级别分前缀（专库租户与共享租户 id 不重叠）。

会话旁路（同属 Redis，P2 一并做）：

- `/monitor/online`：工厂用户只看当前租户会话（过滤 `LoginUser.tenantId`）；平台账号可列全部租户（R4，对齐 F9）。工厂看不见其他工厂。
- `forceLogout`：仅当目标会话 `tenantId` == 当前租户（或 runAs 目标厂）才允许。`refreshPermissionByRoleId` 只刷新**当前租户**中持有该角色的用户。平台 runAs 到工厂 X 视为工厂 X（R5）。禁止留下未校验租户的全局 `forceLogout`。

### 7.2 文件

现有：`FileUploadUtils`（本地盘）、`MesFileUploadUtils.uploadMinio`、`MesMinioUploadController` `POST /common/uploadMinio`、`UploadFilePathConfig` 的 `/profile/**`。

v1 已拍板（I2）：**单 bucket / 单 upload 根目录** + 对象键前缀 `tenant/{tenantId}/...`。空上下文拒绝上传。下载鉴权仍走现有登录；URL 不成为跨租户读文件的口子（按对象键校验租户）。凭据只留在服务端配置/环境变量。隔离级别不改变对象键规则。

### 7.3 异步

- `ThreadPoolConfig.threadPoolTaskExecutor`：设置 `TaskDecorator`，提交时拷贝 `TenantContext`、MDC、`SecurityContext`（P-D 后含 DS 绑定所需的 tenantId），任务结束 `clear`。
- `AsyncManager` / `AsyncFactory`（登录日志等）：同样包装；登录失败日志：能解析到租户则写该 `tenant_id`，否则写 `0`（I3）。登录失败写主库日志，不要误路由到未建专池。
- 禁止业务代码 `new Thread()` 跑租户 SQL。

### 7.4 Quartz

- `AbstractQuartzJob.execute`：从 `SysJob` 读 `tenantId`，`before` 设置上下文（P-D 后按租户路由 DS），`after` 清理（现已有 startTime 的 ThreadLocal，可并列）。
- 无 `tenantId` 的历史任务：只允许调用 `@TenantIgnore` 的平台维护逻辑，否则失败关闭。
- `QRTZ_*` 忽略租户列；`job_name`/`job_group` 应用层加租户后缀或独立 JobKey，避免两租户同名任务互相覆盖（S2/I3）。
- 调度目录 `sys_job` / `sys_job_log` 与 `QRTZ_*` 同在主库；行上 `tenant_id` 标明目标厂，执行再切专池。不为 DATABASE 另存 job 行，避免调度器 `selectJobAll` 看不见。P-D 须保证 Job 能解析 tenantId 并切到专池（I3 已关：`AbstractQuartzJob` 用 `SysJob.tenantId`）。

### 7.5 WebSocket（站内信推送，I9）

现网：`WebSocketServer` `@ServerEndpoint("/websocket/message/{token}")`；`onOpen` 用 JWT 取 `LoginUser` 后 `WebSocketUsers.put(username, session)`；`MessageProvider.sendMessage` 按 **`recipientName`（用户名）** 推送。`/websocket/**` 在 `MesPermitAllProviderImpl` 匿名可达，鉴权靠路径上的 token。

风险：多租户后 `(tenant_id, user_name)` 才唯一，跨厂同名会把消息推到别人的会话。`sendMessageToUsersByText` 会广播全部连接。客户端 `onMessage` 也可按用户名转发。

**v1 必须改（P2，依赖 P1 的 `LoginUser.tenantId`）：**

- 会话 Map 的 key 改为 `{tenantId}:{userId}`，禁止再用裸 `username`。
- `MessageProvider` / 服务端推送按 **当前租户 + recipientId**（或同租户下的 username）查找会话；`recipientId` 对应的用户必须属于当前 `tenantId`。
- `LoginUser.tenantId == null` 拒绝建连（失败关闭）。
- 禁止全局广播；若保留群发，必须只发给同一 `tenantId`。
- 客户端 `onMessage` 不得向其他租户的用户名投递；无租户上下文则忽略或断开。
- 端点路径保持 `/websocket/message/{token}`，不改握手 URL；不把 Vue3 写进 `frontend/`。
- `sys_message` 表加 `tenant_id` 随消息/公告波次（S5），与本条会话隔离同时有效：即使表尚未改列，P2 也必须先改会话 key，避免推送串租。

### 8.1 菜单、许可与端边界（F3）

`sys_menu` 仍是**一份全局表**：不按租户克隆，也不按端（PC / 平板）克隆。

1. **平台许可模块**给工厂租户（`sys_tenant_license`）。工厂只能看见已许可的模块。
2. **工厂租户**在许可范围内给用户赋角色 → 菜单，**包括平板用户**。平板看到的是本租户的分配，不是平台级「全厂共用平板菜单」。
3. **平台模块（租户管理）永不许可给工厂。** 工厂即使想赋也赋不到；因此平板即使用同一套 `getRouters` 也拿不到该模块。

5. 平台运营只用 Vue3 PC；平板不是 runAs 或租户管理面。
6. 平板与 PC 登录均走 F5（F7）。精确 Vue3 路由字符串 spec 时再定；**PC 平台运营 vs 工厂/平板菜单由租户分配**这一拆分已关。
7. **D11：** 平台**回家**会话与工厂同一管线：先按角色取 `sys_role_menu`，租户 0 不套工厂许可（许可码对 0 返回「不裁」）。**禁止**因 `isPlatformOperator` 调用 `selectMenuTreeAll` 或写入 `*:*:*`。进入工厂（F9）仍加载共享目录再按**目标厂**许可裁剪，不把 `platform_admin` 的角色菜单带到厂内。
8. **S7：** 租户 0 预置与租户 1 同结构的部门树与岗位；`dept_id` 全局主键，必须新行 + 重写 `ancestors`。

`getRouters` 服务端：工厂按许可过滤模块；平台回家按角色菜单；工厂用户不单独看许可页或隔离级别（F2）。

**D2×F1：** 管理端只走 Vue3，不是「P1 后 Vue2 会挂」的发布冲突。移动端走 F7，不是 Vue2 替代登录。

## 9. 可执行阶段与退出标准

每阶段独立增量 SQL + 可编译模块 + 可重复的测试。**禁止「一次 ALTER 全部 MES 表」。** 未轮到的 MES 表：拦截器白名单暂时忽略（或尚未加列的表名不强制谓词），但必须在该阶段结束时把「已接管表」写进忽略名单的反集，并在下一波扩大。过渡期策略：

- P0–P3：拦截器只对**已加列**的表生效（显式 include 名单随波次增长）。
- 未加列的表：尚未多租户，仍是单租户数据（全部将回填为 1）。风险窗口：P4 之前不会有第二套工厂数据写入。

**第二工厂门禁（两档分开）：**

| 要开通的第二工厂 | 硬门禁 |
| --- | --- |
| 第二个 **`ROW`** 启用工厂 | **P4 完成**且身份隔离测试通过。不依赖 P-D |
| 第二个（或第一个）**`DATABASE`** 启用工厂 | P4 完成 **且 P-D 完成**；应用建库+迁表成功、ping 健康、连接预算评估（I5/I7） |

P0 即可把 `DATABASE` **登记**进 `sys_tenant`（创建时能选级别），但在 P-D + 应用建库/迁表成功前不得使其登录成功（D7：失败关闭，永不写共享库）。

### P0 — 地基：上下文 + 失败关闭拦截器 + 隔离级别落库

**模块：** `ktg-common`、`ktg-framework`（`MyBatisConfig` 注册 plugin）、测试放 `ktg-framework` 或 `ktg-admin`。

**SQL：** `sys_tenant`、`sys_tenant_license` CREATE；种子租户 0（`tenantCode=platform`，`ROW`）与 1（`tenantCode=default`，`ROW`），`server_name` 均为空（D10），均无 JDBC。`sys_tenant` 含 `isolation_level` 默认 `ROW`、可空 JDBC URL/用户/**密文口令**列。无明文口令列对外。平台用户 `user_name=platform`、`tenant_id=0`（**不是** `user_id=1`）；角色 `platform_admin` 永不许可给工厂。口令不进 SQL；首次启动从 `PLATFORM_ADMIN_PASSWORD` BCrypt 写入，生产缺变量拒绝启动（D3）。

**代码：** `TenantContext`、`TenantLineInterceptor`（include 名单先空或仅演示表）、MDC key `tenantId`、`@TenantIgnore`。租户写入 API 接受 `isolationLevel`；`DATABASE` 时 **AES-256-GCM** 加密存储口令（密钥 `TENANT_JDBC_CIPHER_KEY`，S6）。`isolation_level=ROW` 且 JDBC 任一字段非空 → **HTTP 400**，不落库、不静默丢弃。列表 BO 只回打码 JDBC/口令（F4）；本阶段可暂不实现揭明文接口。本阶段**不**实现按租户切 DS（仍全部打主库）；对已登记的 `DATABASE` 租户：**拒绝登录**（失败关闭），避免数据写进主库却自称专库。

**退出：**

- 单测：无上下文访问 include 表 → 异常；忽略表 → SQL 不加 `tenant_id`；INSERT 填充。
- `MyBatisConfig` 同时保留 `FieldMetaObjectHandler` 与租户拦截器。
- 创建 `ROW` 租户成功；创建 `DATABASE` 缺 JDBC 失败；`ROW` 且带 JDBC 字段 → HTTP 400。
- 列表响应无 password 字段。
- 种子租户 0 = `platform`、1 = `default`，均为 `ROW`，均无 `server_name`、无 JDBC（D10）。平台用户 `user_name=platform`、`tenant_id=0`。
- 缺 `TENANT_JDBC_CIPHER_KEY` 且已有 DATABASE 租户 → 拒绝启动；缺 `PLATFORM_ADMIN_PASSWORD`（生产）→ 拒绝启动。
- `mvn -pl ktg-framework,ktg-common -am test`（或聚合编译 + 新测试类）实际跑过。

### P1 — 身份表 + LoginUser/JWT

**模块：** `ktg-common`（`LoginUser`、`LoginBody`、`Constants`）、`ktg-framework`（`TokenService`、`JwtAuthenticationTokenFilter`、`SysLoginService`、`UserDetailsServiceImpl`）、`ktg-system`（User/Dept/Role Mapper XML）、`ktg-admin`（`SysLoginController` 透传**必填** `tenantCode`）。

**SQL：** `sys_user/dept/role/post` 及关系表、日志、通知相关表 `ADD tenant_id` + 回填 `1` + 唯一键。

**退出：**

- 交互 `POST /login` **必须**带 `tenantCode`；缺码失败，不绑定默认租户（D2）。
- 用 `default`（租户 1）登录成功（`ROW`，主池）；JWT/Redis 中 `LoginUser.tenantId==1`。用 `platform` 登录进平台租户 0。
- 失败文案统一「用户名或密码错误」（D9），不单独返回「租户不存在」。
- `GET /loginOuth` / `MobileLogin` 与管理端同一套 F5（F7）：Host 未命中且缺码 → 失败，**不**默认租户 1。
- 本阶段**不改** `frontend/`（F1：管理端只走 Vue3）。
- Mapper `selectUserByUserName` 带 `tenant_id`；同名用户在不同租户不互相命中（可用第二租户**停用**行做夹具，不启用第二工厂）。
- filter 在租户停用时 401；停用时立即作废该租户全部 token（D6）。
- `DATABASE` 登记租户在 P-D 前登录失败（D7）。
- DataScope 单测或对照 XML：条件在 `tenant_id` 之后仍存在；`isAdmin` 不删除租户谓词（D3）。

### P2 — 缓存 / 文件 / 异步 / MDC / WebSocket

**模块：** `RedisCache` 使用处、`CacheConstants`、`TenantCacheKeys`、`ZipFileUtil`、在线用户 `/monitor/online` 与 `forceLogout`、`ThreadPoolConfig`、`AsyncManager`、`FileUploadUtils` / `MesFileUploadUtils`、`AbstractQuartzJob`（可先只加上下文钩子，job 表列放到 P8）、`ktg-mes` `WebSocketServer` / `WebSocketUsers` / `MessageProvider`。

**退出：**

- 空 tenantId 写租户缓存键 → 异常单测（`TenantCacheKeys` 组装；`RedisCache` get/set 不加自动前缀）。
- `pwd_err_cnt` 键含租户；`repeat_submit` / `rate_limit` 有登录上下文时含租户（登录前限流仍仅 IP）。
- zip 状态键为 `upload_task_status:{tenantId}`；空上下文禁止写；同厂一个并发 zip。
- `/monitor/online` 按 `LoginUser.tenantId` 过滤；工厂不可见他厂；平台可列全部（R4/F9）。`forceLogout` / `refreshPermissionByRoleId` 按 R5 校验当前租户（含 runAs）。
- D6：SCAN `login_tokens`，按值中 `LoginUser.tenantId` 删除；不改 key 为含 `tenantId` 前缀，不加二级 SET（R6）。
- 异步线程内 `TenantContext.get()` 等于提交方；结束后 ThreadLocal 为空（防池化串租户）。
- 上传路径或对象键含 `tenant/{id}/`；无上下文上传失败。
- WebSocket：会话 key 为 `{tenantId}:{userId}`；两租户同名用户互收不到对方推送；无 `tenantId` 的 token 无法建连；不存在按裸用户名的 `USERS.get(username)` 推送路径（I9）。

### P3 — 共享菜单 / 字典 + 许可

**模块：** `SysMenuService`（`getRouters` 链路）、许可 Service；**不**改 `sys_menu` 行复制。

**SQL：** 许可表若 P0 已建，本阶段补模块编码字典（全局 dict）与校验。

**退出：**

- 租户 1 关闭某模块许可后，`GET /getRouters` 不再出现该模块（夹具数据，不克隆菜单）。
- 字典接口无 `tenant_id` 谓词（忽略表）。
- 无「按租户 INSERT sys_menu」的代码路径。
- 平台回家菜单短路（全量目录 + `*:*:*`）**不是**本阶段产品目标；若实现曾如此，由 P11 / D11 收回。

### P4 — MES 主数据 `md`

**模块：** `ktg-mes` `com.ktg.mes.md` + `mapper/md`。

**SQL：** `mes-md.sql` 中表 `ADD tenant_id`、回填 1、补 `(tenant_id, 业务编码)`；S1 中归入 md 的缺脚本表一并处理。

**退出：**

- 拦截器 include 加入全部 md 表。
- 用两个 `tenant_id` 的夹具行（均在**主库**、模拟 `ROW`）：租户 1 登录 `GET` 物料列表看不到租户 2 行（租户 2 可为未启用工厂，仅 SQL 夹具）。
- `item_code` 唯一按租户；跨租户允许相同编码（**S4 已拍板**，不是倾向）。
- 领域测试或 Mapper 级测试；`mvn -pl ktg-mes -am test`（有测则跑，无测则编译 + 上述夹具测试新建）。
- **至此允许启用第二个 `ROW` 工厂。** 启用 `DATABASE` 工厂仍要等 P-D + 应用建库/迁表成功。

### P-D — 独立库路由（与 P5+ 可并行，但是 `DATABASE` 启用门禁）

**排期（D7 已拍板）：** P4 之后再开（先在共享库证明拦截器与 md 隔离）。本阶段**进 v1**。创建后的 `DATABASE` 租户在本阶段完成前保持「不可登录」——**仍然禁止回落主库**。

**模块：** `ktg-framework`（路由器、懒建池、停用驱逐）、`ktg-system`（创建时建库 + 租户表增量 + ping）、登录链路接路由。不引入 MyBatis-Plus `@DS`。

**行为：**

- 启动只初始化现有主池。
- 开通 `DATABASE` 租户：解密 JDBC、若缺失则建 schema、跑同一套租户表增量、ping；失败则该租户不可登录，不写共享主库。
- 首次业务使用时懒建 Druid 池；失败关闭。
- 停用/删除：卸载该池。
- 拦截器不变，专库 SQL 仍带 `tenant_id`。
- **I8：** 忽略名单 Mapper 整接口绑定主池（菜单/字典/许可/`sys_tenant`/`QRTZ_*`/`gen_*`/`sys_config`）。不按表名回切，不引入 Plus `@DS`。
- 平台 `runAs` 进入 `DATABASE` 租户时切到该专池。
- 主库后续增量由应用打到每个 `DATABASE` 租户（I6）。

**退出：**

- 夹具：走应用建库+迁表入口（空表 + 角色模板，不复制物料）；该租户登录只读写专库，主库同 `tenant_id` 夹具行不可见；专库无 `sys_menu`。
- 建库/迁表失败 → 登记保留为未就绪、不可登录、可重试；专库宕掉或错口令 → 登录/请求失败，主库无该租户写入。
- `getRouters` / 字典在专库无 `sys_menu` 时仍走主库成功（I8）。
- 列表/详情默认无明文 password（打码）；揭明文接口须审计且仅平台（F4）。
- 停用后池被关闭（可用测试间谍或连接计数证明不再泄漏）。
- 不在启动日志里打印 JDBC 口令。

### P5 — 生产 `pro` + 仓储 `wm`

**顺序：** 先 `pro` 再 `wm`（库存事务依赖物料与工单），可同一开发单元两批 SQL，但退出标准分开勾。`DATABASE` 租户由**应用**把同一增量打到专库（I6/I7）；未迁成功则该租户本波不可用，不回落主库。

**退出：**

- include 名单扩大到 pro、wm 设计表 + 本波 S1 表。
- 工单/库存查询互不可见；仓库维度仍用 `warehouse_id`，且受 `tenant_id` 约束。
- 唯一单号按租户。

### P6 — 质量 `qc`

**退出：** 检验单、模板、缺陷记录隔离；QC 引用的 `item_id` 不得通过「只按 id 不按租户」读到他租物料（依赖 P4 拦截器已覆盖 `md_item`）。

### P7 — 日历 `cal` + 设备 `dv` + 工装 `tm`

**退出：** 对应设计表全部加列并进 include；点检/维修/班组与设备主数据互不串租户。

### P8 — 其余 MES + 自动编码 + Quartz 元数据

**范围：** `report`、`task`、`msg`、`autocode`、`turnplate`/`area` 等剩余表；`sys_job`/`sys_job_log`（S2）；UReport 上下文（I1 已拍板：Filter 从 JWT 注入；专库报表失败关闭不回落主库。D5：仅本租户，v1 无跨租户报表）。

**退出：**

- include 名单覆盖 ktg-mes 全部租户表；无「漏网 Mapper 表」。
- 自动编码流水按租户递增（S3 已拍板）。
- 定时任务仅平台可管理（S2）；公告/铃铛按租户、v1 无平台群发（S5）。
- Quartz 任务执行带租户并走正确 DS；无租户任务不能碰业务表。
- MES `report` 与 UReport 查询仅当前租户（D5）；Filter 已设 JWT 上下文；空上下文不得跑报表 SQL；`DATABASE` 专库报表不得回落主库（I1）。

### P9 — 前端最小改动（Vue3 only）

**范围：** 仅 `startech-mes-front/`（Vue3）：登录页 F5+F6；工厂 `getInfo` 回 `tenantId` / `tenantName`，**不**回 `isolationLevel`（F2）。关闭自助注册（F8）。runAs（F9）。新建租户分步（F4，2026-09-08 修订：基本信息两开关，步骤条只含已开开关对应的步；P9 当时固定三步条，**94 已裁步骤**，浏览器未点选）。平台租户**列表**展示编码、可选域名、隔离级别、部分打码 JDBC、用户名、打码口令；查看明文须审计。**F3：** 租户管理只挂本工程的平台运营菜单，不进平板、不混车间路由；精确 path 字符串 spec 时再定。本阶段**不建**平板工程（尚未入仓），但边界已关：后续导入不得从 `getRouters` 继承平台路由。**不改** `frontend/`（F1）。`request.js` 不加租户头。

**退出：**

- 绑了 `server_name` 的 Host 打开登录页：不展示编码框、无「使用其他编码」，提交 Body 仍含该 `tenantCode`。
- 未绑定 Host：展示编码输入框；匿名接口不返回租户列表。
- Vue3 交互登录必须带 `tenantCode`；缺码失败；失败文案统一（D9）。
- `GET /loginOuth` 缺 Host 且缺码失败（F7）。
- 工厂 `getInfo` 无 `isolationLevel`；平台租户管理接口可返回隔离级别与许可。
- 平台租户管理菜单不出现在工厂许可内（平台模块永不许可给工厂）。
- 平台回家侧栏以角色菜单为准（D11，实现见 P11 / spec 74）；本阶段不要求代码已收回全菜单短路。
- 响应结构仍为 `code/msg/data`；工厂页眉可展示租户名称，不展示 JDBC。
- 本阶段不碰 `frontend/`，不新建平板工程。

### P11 — 平台回家角色菜单 + 租户 0 身份种子（D11 / S7）

**范围：** 收回平台回家会话对 `selectMenuTreeAll` / `*:*:*` 的短路，改回 `sys_role_menu`；为租户 0 预置与 `default` 同结构的部门树与岗位，并把 `platform` 用户挂到对应研发部门。增量赋权 `platform_admin`：`system`、`monitor`（含 job，S2）、`platform`；保留已赋 AI 菜单；不赋 MES 业务模块。runAs 与 `/platform/**` 身份门禁不变。不改 Vue2、不改工厂许可语义。

**退出：**

- 平台回家 `getRouters` 只含角色已赋模块；夹具角色仅绑 `platform` 时树无 `system` / `mes/md`。
- 平台回家权限字无 `*:*:*`；`@PreAuthorize` 按角色 `perms` 生效。
- runAs 到租户 1 仍走共享目录 ∩ 该厂许可，不出现仅角色未赋、但厂已许可的模块缺失（与 39/41 夹具一致）。
- 租户 0 存在完整部门树且 `ancestors` 不含租户 1 的 `dept_id`；`platform.dept_id` 指向本树研发节点。
- `mvn` 受影响模块测试实际跑过。实现单元：`docs/04.specs/74.platform-home-role-identity.md`。

### P10 — 特权跨租户报表（**不进 v1**，D5 已拍板）

v1：**普通 MES 报表、UReport、平台运营端均只查本租户。** 平台不做跨租户报表（不只是「将来的特权 SQL 仪表盘」不做）。

**范围限制（若将来立项）：** 仅平台租户 + 明确权限标识；只读 + 全程审计；普通角色 403。默认查询始终仅当前租户。

**SQL 事实：** 只能对**共享主库上的 `ROW` 租户**做 JOIN/UNION。`DATABASE` 租户不在同一 MySQL 连接里，**不能**用一条 SQL 跨专库 JOIN。

v1 **不立项**本阶段（D5）。

## 10. 安全说明

| 项 | 要求 |
| --- | --- |
| 认证 | 不引入第二套认证；继续 Spring Security + JWT + Redis `LoginUser` |
| 失败关闭 | 无上下文 / 停用租户 / 伪造客户端租户 / 专库不可用：拒绝，不降级为全表扫描或主库回落 |
| 凭据 | 列表默认打码 JDBC/口令；明文只经平台揭开接口且须审计（审计不记明文）。Redis/Minio/OAuth secret 仍不得下发。加密密钥用环境变量 |
| 超管 | `userId==1` 不得关闭租户拦截器，也不得把任意请求打到未授权租户的专池 |
| 日志 | MDC `tenantId`；日志、异常、审计正文不得打印 token、口令、JDBC URL 中的密码、内部绝对路径 |
| SQL | 增量、可回滚；禁止把现网 dump 贴进仓库 |
| 专库 | 凭据加密落库；路由时仅服务端解密；默认前端 BO 为打码 password；揭明文单独审计；停用卸载池 |
| SSO | `TokenController` 已有 OAuth 配置项；改租户映射时不在文档或接口中复述 secret |

风险：拦截器漏表 > 专库失败开放回落主库 > DataScope 误用 > 缓存空前缀 > 异步/池化串上下文 > 连接泄漏与 `max_connections` 打满 > 文件 URL 未校验租户。P0–P2 与 P-D 专门打这些洞，再开第二工厂。
