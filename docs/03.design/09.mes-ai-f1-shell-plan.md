## 1. 问题与目标

现网已有独立全宽对话页 `/ai/chat` 与 `POST /ai/chat/send`（及选档案时的 `POST /ai/agent/send`）。用户必须离开工单/检验/领料页才能问「这一单怎么了」。快格云的做法是顶栏助手 + **任意页 F1**，把当前屏/当前单带进同一套会话。

MES 要对齐的是**入口与上下文**，不是再做一套模型/会话/认证。

### 1.1 目标

- 有 `ai:chat:list` 的用户在任意已登录页按 F1（或点顶栏）打开同一抽屉
- 当前页写入的 `MesAiContext` 出现在抽屉标题，并作为可选 `context` 进入既有 completions
- P1 再按白名单资源拉只读短摘要，工作台卡打开同一抽屉并预填问题
- `/` 与 F1 分工，互不抢

### 1.2 非目标

- 写库 Agent、`confirmToken`、第二套 JWT / Sa-Token
- AI 直连 MES 业务库或任意 SQL
- 改 Vue2；取消或改名 `/ai/chat`
- 改现有对话 URL / method / 认证头 / SSE 信封
- 首页嵌完整会话（H-D11 仍成立）
- P0 拉业务摘要、P0 改工作台点击
- 新造缺料/OEE 等 KPI（H-D5）
- 把可运营开关写进 yml（若以后要关 F1，走 `sys_config`，本期不做该键）

## 2. 四层形态

```text
① 热键 / 顶栏
   layout Navbar：keydown F1（有 ai:chat:list 才 preventDefault）
   图标 Tooltip = 「助手 (F1)」
        │
        ▼
② Drawer（右 / 右下）
   首次打开才 mount 聊天面板
   标题：助手 · {screenLabel} · {recordLabel}
        │
        ▼
③ aiContext（Pinia）
   业务页 onMounted / keep-alive onActivated set
   keep-alive onDeactivated 与 onUnmounted 均 clear
   MesAiContext { screen, screenLabel, resourceKey?, recordId?, recordLabel? }
        │
        ▼
④ 既有 completions（可选增量）
   POST /ai/chat/send  或  POST /ai/agent/send
   body 增加 context? ；其余字段与现网相同
   system 追加：服务端白名单屏名 + 查库单据号（忽略客户端 label）
   「用户正在 {trustedScreenLabel}，单据 {trustedRecordLabel}」
   P1 另追加只读摘要短句（仍走本口，不新开 path）
```

与独立会话页的关系：**同一套** `ai_session` / `ai_message` / A24 ChatModel / A36 档案分支。抽屉是瘦入口；全宽 `/ai/chat` 仍是运营与长会话的主界面。不要为抽屉再开 `POST /ai/drawer/send`。

## 3. `MesAiContext`

前端 store 与 POST `context` 共用同一形状（JSON camelCase）。全部可选；后端忽略未知键。

| 字段            | 类型              | P0          | P1   | 说明                             |
| ------------- | --------------- | ----------- | ---- | ------------------------------ |
| `screen`      | string          | 建议          | 同左   | 稳定键，如 `mes.pro.workorder.list`。**prompt 屏名只认此键的服务端白名单** |
| `screenLabel` | string          | 进抽屉标题       | 同左   | 给人看的页名，如 `生产工单`。**不进 system** |
| `resourceKey` | string          | 可写、P0 不拉数   | 摘要路由 | 如 `mes.pro.workorder`          |
| `recordId`    | number / string | 可写、P0 不拉数   | 摘要主键 | 工单用现网 `workorderId`            |
| `recordLabel` | string          | 进抽屉标题       | 同左   | 如 `WO-20260902`。**不进 system**（prompt 单据号由服务端查库） |

禁止字段：`tenantId`、`apiKey`、整单 `payload` / 行 JSON。

P0 第一批写入页（够验收即可）：

- 工单列表 `views/mes/pro/workorder/index.vue`：`onMounted` / keep-alive `onActivated` 写列表态 `screen` + `screenLabel`（查看对话框仍打开时才补单据三字段）；同页「查看」打开时补 `resourceKey=mes.pro.workorder`、`recordId=workorderId`、`recordLabel=workorderCode`；**关闭对话框后清掉单据三字段**，回到列表态；keep-alive `onDeactivated` 与 `onUnmounted` 均 `clear`
- 工厂工作台 `/index` 的 FactoryHome：可写 `screenLabel=工厂工作台`，无单据；同样用 activate/deactivate，避免 tags-view keep-alive 把工单/工作台标签留在下一页

其它业务页按同一约定加，不在本期扫全站。

## 4. P0 与 P1 边界

| 能力                               | P0（84）                      | P1（85）   |
| -------------------------------- | --------------------------- | -------- |
| F1 + 顶栏 + Drawer + 懒挂载 + tooltip | 做                           | —        |
| Pinia `aiContext` + 工单页写入        | 做                           | 可复用，不改形状 |
| POST 可选 `context` + 标签 system 句  | 做（忽略客户端 label；屏名白名单）   | 沿用；单据号查库 |
| `/` 不抢（F1 不监听 `/`）               | 写死                          | —        |
| HeaderSearch 全局 `/`（非输入框）        | 不做                          | 做        |
| `resourceKey+recordId` 只读摘要      | 不做                          | 做        |
| 工作台 `dispatchEvent` + 预填         | 仍 `router.push('/ai/chat')` | 改为开抽屉    |
| 写库 / confirmToken / SQL          | 不做                          | 不做       |

P0 上线后，无 `context` 的旧前端与独立会话页行为与今天一致。**84/85 不改**全宽 `/ai/chat` 发送体（S-D14）。

## 5. 现网契约（增量，不改冻结面）

现网 `AiChatSendRequest`：`sessionId`、`modelId`、`content`、`knowledgeId`、`agentId`。

增量：

```text
context?: MesAiContext
```

| 口 | 权限 | 变化 |
| --- | --- | --- |
| `POST /ai/chat/send` | `ai:chat:send` | 只加可选 `context` |
| `POST /ai/agent/send` | `ai:chat:send` | 同上（共享 DTO） |
| `/ai/session/**` | `ai:chat:list` | 不改 |

未选档案仍走 `chat/send`，选中档案仍走 `agent/send`（A36）。抽屉内同样遵守。

system 拼句（P0）：**忽略**客户端 `screenLabel` / `recordLabel`。屏名仅当 `screen` 命中白名单（`mes.pro.workorder.list` / `mes.pro.workorder` →「生产工单」；`mes.home.factory` →「工厂工作台」）。单据号仅当服务端按 `resourceKey`+`recordId` 查到工单号。两侧都有：`用户正在 生产工单，单据 WO-20260902`。只页不单：`用户正在 生产工单`。只单不页：`单据 WO-20260902`。都没有则不拼。该句追加到既有 system（档案 `systemPrompt` 或纯对话默认）之后，不替换档案提示。

P1 摘要另起短段，接在该句后面，限长（实现建议 ≤ 500 字），字段白名单：**状态、数量**。缺料句本期不写（S-G1）。

不新开 `GET /ai/context/summary`。摘要只在发送路径内部拉取，避免扩大 `/ai/**` 面。

## 6. 热键、顶栏、抽屉

监听挂在已登录壳（`layout/index.vue` 或 Navbar），不在每个业务页复制。

- `F1` + `ai:chat:list` → `preventDefault`，**toggle** 抽屉（再按关闭）；输入框内同样拦截
- 无 `ai:chat:list` → 不注册有效拦截（或监听后立即 return）
- 登录页、锁屏无壳则无监听
- 顶栏图标：与现网工具图标同一规则，`device !== 'mobile'`（宽度 **&lt; 992**）才显示（S-D13）。窄屏仍可在有权限时用实体键盘 F1
- 顶栏：`el-tooltip` content=`助手 (F1)`；无权限不渲染

抽屉：

- `el-drawer`，`direction=rtl`，宽度约 400–480（实现可微调）。**不用**右下角自研浮层
- 标题：`助手` + 当前标签
- `v-if`：`openedOnce` 为真才挂载聊天面板
- 面板瘦身：输入 + 气泡 + 可选模型/档案下拉；不复制全宽页左侧长会话列表；须有「打开对话页」去 `/ai/chat`
- 无 `sessionId` 时沿用现网 `POST /ai/session` 再建 send（与 `views/ai/chat/index.vue` `ensureSession` 同款）

## 7. P1 只读摘要与 RBAC

```text
JWT → TenantContext
  → 解析 context.resourceKey + recordId
  → 白名单路由到 MES service（禁止 Mapper/SQL）
  → 复核该单 list/query 权限字
  → 拼短句；失败/无权限/未知 key → 不加摘要，不阻断对话
```

第一批白名单：

| resourceKey | 服务（现网名，以实现时类为准） | 权限（以实现时注解为准） |
| --- | --- | --- |
| `mes.pro.workorder` | `IProWorkorderService` 按 `workorderId` 读 | `mes:pro:workorder:list` 或 `query` |

缺料：85 **省略**。现网无以缺料/齐套命名的可复用 service；禁止临场新造（S-G1 / H-D5）。后续另开单元再补句。

并行 SSE 线程仍走既有 `TenantTaskDecorator`（I-A4 / I-A7）。空上下文不得调 MES。

## 8. 工作台与 `/`

P1 工厂 AI 卡：

```text
window.dispatchEvent(new CustomEvent('mes-ai-assistant-open', {
  detail: { preset: '帮我看看当前工作台的待办和工单' }
}))
```

壳监听后：打开抽屉、把 `preset` 写入输入框、不自动 `send`。**不回退** `router.push('/ai/chat')`。`showAi` 仍是 `ai:chat:list`。平台回家无此卡（现网已无）。

`/`：

- 可编辑控件（input / textarea / contenteditable / 对话框输入）内：必须是字符 `/`
- 其它焦点：P1 可打开 HeaderSearch（现网仅点击）
- F1 处理器不得处理 `/`

## 9. 安全

- `/ai/**` 登录 + 许可 `mes_module.ai` + `@PreAuthorize`；不进 `MesPermitAllProvider`
- 摘要不是「模型自己查库」，是服务层只读包装，与 83 只读 Tools 同一红线（A7）
- 本两期不挂写 Tool、不引入执行确认令牌
- 日志不打密钥；`context` 不当错误详情回前端
- 客户端 `screenLabel` / `recordLabel` 不进 system（S-D4）；屏名只信 `screen` 白名单，单据号只信服务端查库
