## 1. 问题与目标

MES 已在 `feature/mes-multi-tenant` 落地共享库失败关闭租户（可选专库）。`ruoyi-ai` 是另一套 AI 平台（Boot 3.5 + Sa-Token + MyBatis-Plus + LangChain4j），前端用户端在 `ruoyi-web`（独立对话 SPA），管理端 Vben 不在本机。两边认证、ORM、租户字段、上传、接口前缀均不兼容，**不能整仓合并**。

要在现行 MES 栈上自建多租户 AI 平台：平台许可工厂开通 AI；工厂配置本租户模型与知识库；已登录管理端用户在内嵌页对话。AI 数据从第一天带 `tenant_id`。

### 1.1 目标（本期 49–56）

- 新建 `ktg-ai`，HTTP 一律 `/ai/**`
- 许可模块 `ai` 裁剪路由并闸住 API
- OpenAI 兼容对话 + 按租户加密模型密钥
- 已登录 SSE 会话（内嵌 Vue3）
- 知识库 + 三种开源向量策略 + 随后 DashVector
- 向量与文件按租户隔离

### 1.2 非目标（本期）

- 整仓搬 ruoyi-ai / ruoyi-web / 缺失的 ruoyi-admin
- Sa-Token、MyBatis-Plus、第二套认证、默认 OSS 上传
- 独立用户对话端、游客聊天、登录页租户下拉
- Agent、MCP、SQL 工具、AI 工作流、短剧、Coding Harness
- 计费钱包（消息可记 token 用量，不做扣费）
- 改遗留 Vue2 `frontend/`
- 把 Vue 3 AI 页写成 Vben / element-plus-x / TypeScript 工程

## 2. 形态

```text
平台运营 (startech-mes-front / platform)
  给工厂 sys_tenant_license.module_code=ai

工厂管理员 (startech-mes-front)
  /ai/model     配本租户 OpenAI 兼容模型（key 加密）
  /ai/knowledge 知识库与附件（MinIO）

工厂用户 (同一管理端，已登录)
  /ai/chat      全宽 SSE 对话，可选挂本租户知识库

后端 ktg-ai
  现有 JWT → TenantContext → 许可校验 → /ai/**
  include-tables 含全部 ai_* 表
  向量策略工厂（配置只激活一种）
```

`ruoyi-web` 只当交互蓝本。`ruoyi-ai` 只当能力清单，不当可合并模块。

## 3. 模块与契约

| 层 | 选择 |
| --- | --- |
| Maven | 新建 `ktg-ai`，`ktg-admin` 依赖；启动类仍 `com.ktg.RuoYiApplication` |
| 包 | `com.ktg.ai`；Controller 薄，逻辑在 service |
| HTTP | `/ai/model`、`/ai/session`、`/ai/chat/send`、`/ai/knowledge`、`/ai/fragment`（精确 path 在对应 spec 定） |
| 响应 | 保持 `code/msg/data` / `rows` / `total`；SSE 为文本事件流，不是把 token 放进 JSON 信封里冒充结束 |
| 认证 | `@PreAuthorize` + 现有 `SecurityUtils`；另加许可校验（未许可 403） |
| 上传 | 知识附件：先 `uploadMinio`，再把对象键写入知识附件表 |
| 配置 | `ruoyi:` 下增加 `ai:` 段，值全部 `${ENV:}` 占位 |

保持不变：`POST /login`、`GET /getInfo`、`GET /getRouters`、`POST /unlockscreen`、`POST /common/uploadMinio`、`MesPermitAllProvider` 机制、手机号登录。

## 4. 数据

建议表（名称可在实现 spec 微调，列语义锁定）：

| 表 | 用途 | 隔离 |
| --- | --- | --- |
| `ai_model` | 本租户模型：展示名、模型名、baseUrl、加密 api_key、维度、状态 | `tenant_id` |
| `ai_session` | 会话 | `tenant_id` + `user_id` |
| `ai_message` | 消息；可选 `prompt_tokens` / `completion_tokens`（仅审计） | `tenant_id` |
| `ai_knowledge` | 知识库 | `tenant_id` |
| `ai_knowledge_attach` | 附件（MinIO 对象键，无存储凭据） | `tenant_id` |
| `ai_knowledge_fragment` | 切块原文 | `tenant_id` |

- `tenant_id bigint NOT NULL`，唯一键 `(tenant_id, 业务键)`
- 全部进入 include 名单与 `DATABASE` 专库增量 catalog（A21）
- 不把向量 blob 存 MySQL
- 模型 `api_key` 列只存密文；列表/详情默认打码

增量脚本：`startech-mes-basic/backend/sql/YYYYMMDD_NN_ai_*.sql`（I10 Flyway 代码未落地前仍走现有 `sql/` 增量，不改历史 `ry_*.sql` / `mes-*.sql`）。专库须列入与 I6 相同的 catalog。

## 5. 密钥与供应商

- 对话与 embedding：OpenAI 兼容 HTTP（`/v1/chat/completions` 流式、`/v1/embeddings`）
- 一期只实现这一条适配器；厂商差异用不同 `baseUrl` + 模型名表达
- 加密：JDK `AES/GCM/NoPadding`，IV 随机与密文同存（对齐 `TenantJdbcCipher`，**独立类 + 独立环境变量**）
- 运行时解密只在 service 调上游时发生，不写日志、不进响应

## 6. 向量层

```text
VectorStoreService
  createSchema / storeEmbeddings / search / removeByDoc
        │
        ├ weaviate   （第一批，本地默认）
        ├ milvus     （第一批）
        ├ qdrant     （第一批）
        └ dashvector （单元 56）
```

- 配置 `VECTOR_STORE_TYPE`，未知值失败关闭
- 一进程只建一种客户端
- 元数据至少：`tenant_id`、`kid`、`docId`、`fid`
- 检索必须带当前 `TenantContext.tenantId`，禁止跨库「只按 kid」
- 不复制 ruoyi-ai 三种策略源码（其 Mapper 是 MyBatis-Plus，且按 kid 拼名而不校验租户）
- DashVector：官方 Java SDK 或 HTTP；平台 Cluster；Partition `tenant_{id}` 或 Field 过滤，两条至少一条强制，推荐都做
- LangChain4j：若引入，只限 OpenAI 兼容客户端 + 必要时某种 EmbeddingStore；禁止借机引入其 Agent/MCP 全家桶。也允许先用 JDK HTTP 客户端，不引 LangChain4j

## 7. 前端

| 页 | 谁用 | 说明 |
| --- | --- | --- |
| `/ai/chat` | 已许可工厂用户 | 全宽；会话列表 + 模型下拉 + SSE 气泡 |
| `/ai/model` | 工厂管理员（权限字） | 表格/表单；密钥只写不回填 |
| `/ai/knowledge` | 工厂管理员 | 库 / 附件 / 解析状态 |

菜单进全局 `sys_menu`，`path` 前缀 `ai`，由 `MenuModuleMapper` 映射 `module_code=ai`。种子：不给平台误许可成「工厂模块」以外的平台专属；`ai` 可许可给工厂。平台自己是否使用 AI 由产品在实现时定：默认平台可不许可自己，只给工厂。

不引入 `vue-element-plus-x` / UnoCSS / `hook-fetch`。SSE 用 `fetch` 流，走与 `request.js` 相同的 Bearer 头。

## 8. 安全

- `/ai/**` 认证 + 许可 + 租户拦截器三重闸
- 不扩大 `MesPermitAllProvider`
- 不把模型 Key、向量库 token 放进前端 env
- 提示词与检索结果按当前租户裁剪；禁止把 A 厂片段送给 B 厂模型上下文
- Agent/SQL 工具本期不存在，故无「模型直接查 MES 库」路径
