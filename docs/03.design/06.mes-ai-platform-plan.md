## 1. 问题与目标

MES 已在 `feature/mes-multi-tenant` 落地共享库失败关闭租户（可选专库）。`ruoyi-ai` 是另一套 AI 平台（Boot 3.5 + Sa-Token + MyBatis-Plus + LangChain4j），前端用户端在 `ruoyi-web`（独立对话 SPA），管理端 Vben 不在本机。两边认证、ORM、租户字段、上传、接口前缀均不兼容，**不能整仓合并**。

要在现行 MES 栈上自建多租户 AI 平台：平台许可工厂开通 AI；工厂配置本租户模型与知识库；已登录管理端用户在内嵌页对话。AI 数据从第一天带 `tenant_id`。

### 1.1 目标（本期 49–56）

- 新建 `ktg-ai`，HTTP 一律 `/ai/**`
- 许可模块 `ai` 裁剪路由并闸住 API
- OpenAI 兼容对话 + 按租户加密模型密钥
- 已登录 SSE 会话（内嵌 Vue3）
- 知识库 + 三种开源向量策略 + 随后 DashVector
- 向量与文件按租户隔离

### 1.2 非目标（本期）

- 整仓搬 ruoyi-ai / ruoyi-web / 缺失的 ruoyi-admin
- Sa-Token、MyBatis-Plus、第二套认证、默认 OSS 上传
- 独立用户对话端、游客聊天、登录页租户下拉
- 短剧、Coding Harness、匿名 `/workflow/run`、内置 SQL MCP、任意 SQL（**Agent 见 A25；受控写/白名单 MCP/已登录工作流见 A26–A28 / §5.3，不进 49–56 与 61**）
- 计费钱包（消息可记 token 用量，不做扣费）
- 改遗留 Vue2 `frontend/`
- 把 Vue 3 AI 页写成 Vben / element-plus-x / TypeScript 工程

## 2. 形态

```text
平台运营 (startech-mes-front / platform)
  给工厂 sys_tenant_license.module_code=ai

工厂管理员 (startech-mes-front)
  /ai/model     配本租户 OpenAI 兼容模型（key 加密）
  /ai/knowledge 知识库与附件（MinIO）

工厂用户 (同一管理端，已登录)
  /ai/chat      全宽 SSE 对话，可选挂本租户知识库

后端 ktg-ai
  现有 JWT → TenantContext → 许可校验 → /ai/**
  include-tables 含全部 ai_* 表
  向量策略工厂（配置只激活一种）
```

`ruoyi-web` 只当交互蓝本。`ruoyi-ai` 只当能力清单，不当可合并模块。

## 5. 密钥与供应商

- 对话与 embedding：OpenAI 兼容 HTTP（`/v1/chat/completions` 流式、`/v1/embeddings`）
- 一期只实现这一条适配器；厂商差异用不同 `baseUrl` + 模型名表达
- 加密：JDK `AES/GCM/NoPadding`，IV 随机与密文同存（对齐 `TenantJdbcCipher`，**独立类 + 独立环境变量**）
- 运行时解密只在 service 调上游时发生，不写日志、不进响应
- **不**把每租户模型清单或 apiKey 写进 yml / LangChain4j `chat-model.api-key`。yml 只保留平台占位（cipher、向量集群、平台租户 0 默认 Key）

### 5.1 ChatModel 实例（A24）

每个租户有自己的 apiKey；**该租户的对话/embedding 请求必须带上自己那一行的 Key**。产品不把「租户之间密钥互不可见」当作本条验收，也不列为要实现的功能（列表打码与 VO 不下发明文仍按 A3/A20，那是 API 契约，不是本条的隔离定义）。

隔离靠请求时选实例，不靠启动时造好全局 Bean：

```text
JWT → TenantContext.tenantId
    → 校验 modelId 属于本租户（否则 404/403，不调上游）
    → 缓存 get-or-create (tenantId, modelId)
    → 出站只用该实例上的 apiKey / baseUrl / modelName
```

约束：

- 配置源 = 库表。yml **不**写按 `tenantId` 展开的模型目录，**不**写 `langchain4j.open-ai.chat-model.api-key` 这类全局模型凭证。yml 仅平台占位（cipher、默认 Key、向量集群）
- 缓存键是 `(tenantId, modelId)`，不是「一租户一个 ChatModel」（多模型会串 Key）。Chat 与 embedding 出站都走同一套键
- **懒建**：第一次用到再读库、解密、builder；不要启动时扫全表，不要 `ApplicationRunner` 全量预热。`DATABASE` 专库懒建读的是当前租户数据源上的 `ai_model`，启动扫主库本来就不完备
- 该行改 Key / host / 模型名 / 删除后必须 evict 对应键（TTL 或写路径显式 evict）
- 动态 `builder`，禁止 `@Autowired` 唯一 `ChatModel`，禁止 starter 全局 `api-key` Bean
- 只信 JWT / `TenantContext`；禁止请求体传 `tenantId` 或明文 `apiKey` 来换钥匙。`modelId` / `sessionId` / `knowledgeId` 必须属于当前租户，否则 404/403，且不调上游、不创建缓存项
- 出站 Key 必须来自该行（解密或既有 `tenantId == 0` 平台默认 Key 回退）。工厂缺 Key 不得 silently 用别人的 Key
- A3 加密与 A20 VO 不下发明文不变。日志仍不打印 apiKey / cipher（I-A5）

风险（实现时不得踩）：把「懒缓存」做成启动全量 Map；按 `tenantId` 只缓存一个模型；改 Key 不 evict；误开 yml 全局 `api-key` 导致所有租户共用一把钥匙。

验收：夹具两租户两模型时，mock 上游 `Authorization` 各用各的 Key；跨租户 `modelId` 不调上游。

决策正文即本节，不另占 spec 号。**代码**见 `docs/04.specs/61.ai-langchain4j-runtime.md`。

### 5.2 Agent / AiService（A25）

当期包含 Agent。与 ChatModel **同一套凭证**，不要另搞一份 yml 模型。本决策不要求密钥互不可见（那是 A24 的请求路由隔离）。

| 层 | 怎么建 |
| --- | --- |
| 接口、Agent 拓扑、`@Tool` 类 | **一份**（进程级定义 / Spring 单例）。不为每个租户 new 一份 Tool 实例（除非 Tool 自身持有无法共享的连接） |
| `ChatModel` | 仍走 A24：`(tenantId, modelId)` 懒缓存 |
| AiService 代理 | 按同一键缓存，或唯一代理内部路由到 A24 |
| Agent | 一份定义；执行时 `chatModel(Function<AgenticScope, ChatModel>)`（或等价）向 A24 get。禁止只传 modelName |
| `ChatMemory` | `ChatMemoryProvider`；id 含 `tenantId + userId + sessionId`。禁止全进程一份 `ChatMemory` |
| Tools | 单例；**调用时**读 `TenantContext` / `LoginUser`，禁止构造期写死租户 |
| RAG / Retriever | 检索时带当前 `tenant_id`，禁止构造期写死他租 kid |

禁止：启动扫描全租户注册 Agent；全局 `@AiService` + 唯一 `ChatModel` Bean。红线仍是 A7（不准直连 MES 库、不准任意 SQL）。`/ai/**` 必须登录；Agent 口不进 `MesPermitAllProvider`。Tool 禁止接受客户端 `tenantId`；知识库/工单等 id 必须再查本租户。并行 Tool / SSE 工作线程拷贝 `TenantContext`（I-A4）。不得削弱现网 `POST /ai/chat/send` 的 `{content, done}` 纯对话行为。`langchain4j-agentic` 若引入，只为执行时解析 ChatModel；MCP 留给 §5.3。

61 第一批 Tool 只读知识检索。受控写 / MCP / 工作流见 §5.3。

风险（实现时不得踩）：`@AiService` 自动装配全局 `ChatModel`；Agent 按租户启动全量注册；Tool 捕获构造期 `tenantId`；把工作流/MCP/受控写塞进运行时单元。

决策正文即本节，不另占 spec 号。**代码**见 `docs/04.specs/61.ai-langchain4j-runtime.md`。

### 5.3 受控写 Tools、MCP、工作流（A26–A28）

在 A25 Agent 之上纳入当期平台轨道，**不扩大 61**。写操作必须走现有 MES service + 当前 JWT 权限，不能让模型直连业务库或执行任意 SQL。A7 红线是「禁止直连库 / 禁止任意 SQL」，不是「禁止任何看起来像 SQL 的 Tool」：所谓 SQL 工具 = 白名单 service 调用，不是 JDBC / `execute_sql_query`。

| 编号 | 做什么 | 不做什么 |
| --- | --- | --- |
| A26 | 白名单 Tool 调现有 MES service 受控写（报工、工单状态等）；权限字与登录用户不变 | JDBC、`execute_sql_query`、任意 Mapper、绕过 `@PreAuthorize` |
| A27 | 白名单 MCP 当 Tool 后端；配置加密落本租户 | 任意远程 MCP、SQL MCP 跑任意语句、permitAll |
| A28 | 已登录 `/ai/**` 多步编排 | 匿名 `/workflow/run`、ruoyi `[NODE_CHUNK_*]`、拷 ruoyi-web runner |

约束：

- 只信 JWT / `TenantContext`；禁止请求体传 `tenantId`。工单、报工、知识库、MCP server id 必须再查本租户，跨租户 404/403 且不调上游、不跑 Tool
- `/ai/**` 必须登录；Agent / MCP / 工作流口不进 `MesPermitAllProvider`。写操作不得因为「是 Tool」就绕过原 `@PreAuthorize`
- 并行 Tool、MCP 调用、工作流节点拷贝 `TenantContext`（I-A4）；空上下文失败关闭
- A26：第一批白名单在代码单元列死，不开放「任意 Mapper」。每个受控写 Tool 用该业务既有短事务，**不**包住整个 Agent / 工作流循环
- A27：主密钥仍 `${AI_MODEL_CIPHER_KEY:}`，不复用 JDBC 密钥。列表/options 不回明文或 cipher（对齐 A20）。`langchain4j-mcp` 可以，禁止借机上 A2A / agentic 全家桶与匿名端点
- A28：精确 path 留给代码单元，须 `/ai` 前缀；禁止无前缀 `/workflow/run`、禁止 `/system/message`。SSE 自定（A17 仍有效）
- 不改 `POST /ai/chat/send` 信封，不改 61 已冻的 `POST /ai/agent/send`。后续若需 `ai_mcp_*` / `ai_workflow_*`，必须 `tenant_id` + include + 专库 catalog，新增量 SQL
- 日志、SSE、异常不打印 apiKey、MCP token、cipher、JDBC。受控写须能追到用户、租户、Tool 名、业务主键；审计不记密钥
- MES 自有 MCP/工作流页另开 Vue 单元，仍 Element Plus；不拷 ruoyi-web MCP 卡片 / runner（F-A3），不引入 x/UnoCSS
- 短剧 / Coding Harness / 匿名 `/run` / 内置 SQL MCP **仍不做**（A22）

风险（实现时不得踩）：把 B 理解成「模型可以跑 SQL」；把 MCP/工作流塞进 61；匿名 `/workflow/run` 或 MCP 口进 `permitAll`；拷 ruoyi-web 工作流 UI。

- 检索必须带当前 `TenantContext.tenantId`，禁止跨库「只按 kid」
- 不复制 ruoyi-ai 三种策略源码（其 Mapper 是 MyBatis-Plus，且按 kid 拼名而不校验租户）
- DashVector：官方 Java SDK 或 HTTP；平台 Cluster；Partition `tenant_{id}` 或 Field 过滤，两条至少一条强制，推荐都做
- LangChain4j：**依赖管理已落地**（单元 60）：父 POM 导入 `langchain4j-bom:1.19.0` 与 `langchain4j-community-bom:1.19.0-beta29`（核心 vs community，GA 不重叠；Boot 4 starters 由 BOM 内部管理 `1.19.0-beta29`）。禁止改用过期的 `langchain4j-spring-bom`。community 含 DashScope、**不含** DashVector（DashVector 仍自定义 HTTP）。**chat/embedding 出站已由单元 61 改写为 LangChain4j**（`(tenantId, modelId)` 工厂 + Agent；证据见 `docs/04.specs/61.ai-langchain4j-runtime.md` 第 4 节）。**向量适配仍为 JDK HTTP**（Weaviate/DashVector 自定义客户端；官方 EmbeddingStore 不在 61）。禁止 yml 全局模型。白名单 MCP 见 A27 / §5.3，禁止借 61 上 MCP 全家桶
