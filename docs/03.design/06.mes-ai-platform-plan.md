## 1. 问题与目标

MES 已在 `feature/mes-multi-tenant` 落地共享库失败关闭租户（可选专库）。`ruoyi-ai` 是另一套 AI 平台（Boot 3.5 + Sa-Token + MyBatis-Plus + LangChain4j），前端用户端在 `ruoyi-web`（独立对话 SPA），管理端 Vben 不在本机。两边认证、ORM、租户字段、上传、接口前缀均不兼容，**不能整仓合并**。

要在现行 MES 栈上自建多租户 AI 平台：平台许可工厂开通 AI；工厂配置本租户模型与知识库；已登录管理端用户在内嵌页对话。AI 数据从第一天带 `tenant_id`。

### 1.1 目标（本期 49–56）

- 新建 `ktg-ai`，HTTP 一律 `/ai/**`
- 许可模块 `ai` 裁剪路由并闸住 API
- OpenAI 兼容对话 + 按租户加密模型密钥
- 已登录 SSE 会话（内嵌 Vue3）
- 知识库 + 三种开源向量策略 + 随后 DashVector
- 向量与文件按租户隔离

### 1.2 非目标（本期）

- 整仓搬 ruoyi-ai / ruoyi-web / 缺失的 ruoyi-admin
- Sa-Token、MyBatis-Plus、第二套认证、默认 OSS 上传
- 独立用户对话端、游客聊天、登录页租户下拉
- 短剧、Coding Harness、匿名 `/workflow/run`、内置 SQL MCP、任意 SQL（**Agent 见 A25；受控写/白名单 MCP/已登录工作流见 A26–A28 / §5.3，不进 49–56 与 63**）
- 计费钱包（消息可记 token 用量，不做扣费）
- 改遗留 Vue2 `frontend/`
- 把 Vue 3 AI 页写成 Vben / element-plus-x / TypeScript 工程

## 2. 形态

```text
平台运营 (startech-mes-front / platform)
  给工厂 sys_tenant_license.module_code=ai

工厂管理员 (startech-mes-front)
  /ai/model     配本租户 OpenAI 兼容模型（key 加密）
  /ai/knowledge 知识库与附件（MinIO）

工厂用户 (同一管理端，已登录)
  /ai/chat      全宽 SSE 对话，可选挂本租户知识库

后端 ktg-ai
  现有 JWT → TenantContext → 许可校验 → /ai/**
  include-tables 含全部 ai_* 表
  向量策略工厂（配置只激活一种）
```

`ruoyi-web` 只当交互蓝本。`ruoyi-ai` 只当能力清单，不当可合并模块。

## 4. 数据

建议表（名称可在实现 spec 微调，列语义锁定）：

| 表 | 用途 | 隔离 |
| --- | --- | --- |
| `ai_model` | 本租户模型：展示名、模型名、baseUrl、加密 api_key、维度、状态 | `tenant_id` |
| `ai_session` | 会话 | `tenant_id` + `user_id` |

- `tenant_id bigint NOT NULL`，唯一键 `(tenant_id, 业务键)`
- 全部进入 include 名单与 `DATABASE` 专库增量 catalog（A21）
- 不把向量 blob 存 MySQL
- 模型 `api_key` 列只存密文；列表/详情默认打码

增量脚本：`startech-mes-basic/backend/sql/YYYYMMDD_NN_ai_*.sql`（I10 Flyway 代码未落地前仍走现有 `sql/` 增量，不改历史 `ry_*.sql` / `mes-*.sql`）。专库须列入与 I6 相同的 catalog。

## 5. 密钥与供应商

- 对话与 embedding：OpenAI 兼容 HTTP（`/v1/chat/completions` 流式、`/v1/embeddings`）
- 一期只实现这一条适配器；厂商差异用不同 `baseUrl` + 模型名表达
- 加密：JDK `AES/GCM/NoPadding`，IV 随机与密文同存（对齐 `TenantJdbcCipher`，**独立类 + 独立环境变量**）
- 运行时解密只在 service 调上游时发生，不写日志、不进响应
- **不**把每租户模型清单或 apiKey 写进 yml / LangChain4j `chat-model.api-key`。yml 只保留平台占位（cipher、向量集群、平台租户 0 默认 Key）

### 5.1 ChatModel 实例（A24）

每个租户有自己的 apiKey；**该租户的对话/embedding 请求必须带上自己那一行的 Key**。产品不把「租户之间密钥互不可见」当作本条验收（列表打码与 VO 不下发明文仍按 A3/A20，那是 API 契约，不是本条的隔离定义）。

隔离靠请求时选实例，不靠启动时造好全局 Bean：

```text
JWT → TenantContext.tenantId
    → 校验 modelId 属于本租户（否则 404/403，不调上游）
    → 缓存 get-or-create (tenantId, modelId)
    → 出站只用该实例上的 apiKey / baseUrl / modelName
```

约束：

- 缓存键是 `(tenantId, modelId)`，不是「一租户一个 ChatModel」（多模型会串 Key）
- **懒建**：第一次用到再读库、解密、builder；不要启动时扫全表。专库租户在启动数据源上本来扫不全
- 该行改 Key / host / 模型名 / 删除后必须 evict 对应键
- 后续改写 LangChain4j 时动态 `builder`，禁止 `@Autowired` 唯一 `ChatModel`，禁止 starter 全局 `api-key`
- 实现细节与禁项：`docs/04.specs/61.ai-chatmodel-factory.md`。代码改写：`docs/04.specs/63.ai-langchain4j-runtime.md`

### 5.2 Agent / AiService（A25）

当期包含 Agent。与 ChatModel **同一套凭证**，不要另搞一份 yml 模型。

| 层 | 怎么建 |
| --- | --- |
| 接口、Agent 拓扑、`@Tool` 类 | **一份**（进程级定义 / Spring 单例） |
| `ChatModel` | 仍走 A24：`(tenantId, modelId)` 懒缓存 |
| AiService 代理 | 按同一键缓存，或唯一代理内部路由到 A24 |
| Agent | 一份定义；执行时 `chatModel(Function<AgenticScope, ChatModel>)`（或等价）向 A24 get。禁止只传 modelName |
| `ChatMemory` | `ChatMemoryProvider`；id 含租户+用户+会话 |
| Tools | 单例；**调用时**读 `TenantContext`，禁止构造期写死租户 |

禁止：启动扫描全租户注册 Agent；全局 `@AiService` + 唯一 `ChatModel` Bean。红线仍是 A7（不准直连 MES 库、不准任意 SQL）。63 第一批 Tool 只读知识检索。受控写 / MCP / 工作流见 §5.3。细节：`docs/04.specs/62.ai-agent-tenant-factory.md`。代码改写：`docs/04.specs/63.ai-langchain4j-runtime.md`。

### 5.3 受控写 Tools、MCP、工作流（A26–A28）

在 A25 Agent 之上纳入，**不扩大 63**：

| 编号 | 做什么 | 不做什么 |
| --- | --- | --- |
| A26 | 白名单 Tool 调现有 MES service 受控写（报工、工单状态等）；权限字与登录用户不变 | JDBC、`execute_sql_query`、任意 Mapper、绕过 `@PreAuthorize` |
| A27 | 白名单 MCP 当 Tool 后端；配置加密落本租户 | 任意远程 MCP、SQL MCP 跑任意语句、permitAll |
| A28 | 已登录 `/ai/**` 多步编排 | 匿名 `/workflow/run`、ruoyi `[NODE_CHUNK_*]`、拷 ruoyi-web runner |

凭证仍走 A24。并行节点拷贝 `TenantContext`。决策：`docs/04.specs/64.ai-tools-mcp-workflow.md`。代码在 63 完成后再拆。

## 6. 向量层

```text
VectorStoreService
  createSchema / storeEmbeddings / search / removeByDoc
        │
        ├ weaviate   （第一批，本地默认）
        ├ milvus     （第一批）
        ├ qdrant     （第一批）
        └ dashvector （单元 56）
```

- 配置 `VECTOR_STORE_TYPE`，未知值失败关闭
- 一进程只建一种客户端
- 元数据至少：`tenant_id`、`kid`、`docId`、`fid`
- 检索必须带当前 `TenantContext.tenantId`，禁止跨库「只按 kid」
- 不复制 ruoyi-ai 三种策略源码（其 Mapper 是 MyBatis-Plus，且按 kid 拼名而不校验租户）
- DashVector：官方 Java SDK 或 HTTP；平台 Cluster；Partition `tenant_{id}` 或 Field 过滤，两条至少一条强制，推荐都做
- LangChain4j：**依赖管理已落地**（单元 60）：父 POM 导入 `langchain4j-bom:1.19.0` 与 `langchain4j-community-bom:1.19.0-beta29`（核心 vs community，GA 不重叠；Boot 4 starters 由 BOM 内部管理 `1.19.0-beta29`）。禁止改用过期的 `langchain4j-spring-bom`。community 含 DashScope、**不含** DashVector（DashVector 仍自定义 HTTP）。**chat/embedding 出站已由单元 63 改写为 LangChain4j**（`(tenantId, modelId)` 工厂 + Agent；证据见 `docs/04.specs/63.ai-langchain4j-runtime.md` 第 4 节）。**向量适配仍为 JDK HTTP**（Weaviate/DashVector 自定义客户端；官方 EmbeddingStore 不在 63）。禁止 yml 全局模型。白名单 MCP 见 A27 / 64，禁止借 63 上 MCP 全家桶

## 7. 前端

| 页 | 谁用 | 说明 |
| --- | --- | --- |
| `/ai/chat` | 已许可工厂用户 | 全宽；会话列表 + 模型下拉 + SSE 气泡 |
| `/ai/model` | 工厂管理员（权限字） | 表格/表单；密钥只写不回填 |
| `/ai/knowledge` | 工厂管理员 | 库 / 附件 / 解析状态 |

菜单进全局 `sys_menu`，`path` 前缀 `ai`，由 `MenuModuleMapper` 映射 `module_code=ai`。种子：不给平台误许可成「工厂模块」以外的平台专属；`ai` 可许可给工厂。平台自己是否使用 AI 由产品在实现时定：默认平台可不许可自己，只给工厂。

不引入 `vue-element-plus-x` / UnoCSS / `hook-fetch`。SSE 用 `fetch` 流，走与 `request.js` 相同的 Bearer 头。

## 8. 安全

- `/ai/**` 认证 + 许可 + 租户拦截器三重闸
- 不扩大 `MesPermitAllProvider`
- 不把模型 Key、向量库 token 放进前端 env
- 提示词与检索结果按当前租户裁剪；禁止把 A 厂片段送给 B 厂模型上下文
- Agent Tools **不准**直连 MES 业务库、不准任意 SQL。63 只允许只读知识检索；受控写必须走现有 service + 权限字（A26）。并行 Tool / MCP / 工作流节点必须带 `TenantContext`
