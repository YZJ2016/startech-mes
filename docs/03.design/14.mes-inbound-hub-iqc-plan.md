## 1. 问题与目标

现网物料入库与来料检验是两张互不卡位的 CRUD。确认/执行只检查有没有行；IQC 甚至可以在确认时按采购号**另建**一张入库单。成熟度评估已指出「质量不卡流程」。

快格云用入库 Hub 把多类型收进一张表，并在确认入库前询问「能否入库」。要对齐的是这条**运营闭环**，不是它的前端模板。

### 1.1 目标

- 工厂角色勾选 9300 后，Vue3 侧栏多一个入库 Hub：物料入库 + 成品入库同行分类型
- 点单号打开抽屉：表头、明细、状态、物料入库的检验闸预览
- 必检物料未 `ACCEPT` 时：默认挡住 **执行过账**；确认步默认与今日一样不查 IQC。两键都 `on` 则确认与执行都拒
- 旧入库/IQC 菜单与 URL 仍可用

### 1.2 非目标

- 出库 Hub / 领料聚合、退料进 **出库** Hub
- 其他入库 / 客供 / 半成品 Hub 余型 / 拉单 / 撤回（IH-G7→**120** 代码已落、部署手验仍开；IH-G10 半成品→**121** 文档已开、未编码；IH-G9/G11/G12 仍无文件或开放指针）
- 成品 FQC 闸、8D/SPC、Demand/MRP
- 入库金额（IH-G5）、Hub 打印（IH-G6）
- 换若依壳、kiosk、第二套组件库、改 Vue2
- 替换旧 list/执行 URL
- 改首页、F1、行业包

### 1.3 回归基线

未勾 9300 的用户：无 Hub 菜单；旧页仍在。默认执行闸 `on` 之后，**旧物料入库页的执行也会被拒**——真源在服务端。工厂 overlay 把 `mes.wm.inbound.iqc.gate.execute` 设为 `off` 即回到今日过账。默认确认闸 `off`，旧确认行为不变；要卡确认须把 `mes.wm.inbound.iqc.gate.confirm` 设为 `on`。

## 2. 页模式与运行时

```text
快格云                         Startech MES
─────────────────────────────────────────────────────────
多源前端聚合                    GET /mes/wm/inboundhub/list（服务端合并）
DetailDrawer + AntD            el-drawer + Element Plus
ensureForPurchaseReceipt       GET .../iqc-gate（预览）+ 对应 PUT 内校验
确认入库卡 IQC                  两键：默认只卡 execute；confirm 键可开
```

运行时：

```text
① 工厂角色勾 9300（不自动授）
        │
        ▼
② GET /mes/wm/inboundhub/list
   许可 ∩ 角色；SQL 带 tenant_id
   行：receiptType + recptId + 单号/状态/日期/仓库（可筛 warehouseId）
        │
        ▼
③ 抽屉：现有 GET 头 + 行；物料入库再 GET .../iqc-gate
   + 只读 GET /mes/qc/iqcline/list（有 iqcId 时）
   行可改合格量/不合格量/序列号（现有行 PUT 加法）
        │
        ▼
④ 物料入库：
   `PUT /confirm` — 仅当 `gate.confirm=on` 时按行校验 IQC
   `PUT /{recptId}` — 仅当 `gate.execute=on` 时在 `processItemRecpt` 前校验
   失败 AjaxResult.error；执行失败则库存事务不开始
```

### 2.1 Hub 行

| 字段 | 含义 |
| --- | --- |
| `receiptType` | `ITEM_RECPT` / `PRODUCT_RECPT` |
| `recptId` | 现网主键 |
| `recptCode` / `recptName` / `status` / `recptDate` | 展示 |
| `vendorName` 或工单号 | 有则带出；无则空 |

筛选：类型、状态、单号、日期、**仓库**（`warehouseId` 可空）。分页在服务端完成。无打印按钮。

### 2.2 抽屉

- 上：`el-descriptions` + 状态轴（字典 `mes_order_status`）；关联 IQC / 采购号 / 工单号可深链到现有页
- 中：现有行表字段 + **合格量 / 不合格量 / 序列号 / 批次**（可编辑加法字段；不改旧 CRUD 页）
- 下（仅物料入库）：闸预览表（物料、是否必检、检验单号、结果、确认能否过、执行能否过）；其下只读检验项目（现网 `iqcline`）
- 主按钮：与旧页同一套确认/执行 API；无权限隐藏；无打印

### 2.3 闸

合格规则（IH-D5/D6）共用。`mes.wm.inbound.iqc.gate.confirm` / `.execute` 各自 `on` 时，该步必须有合格 IQC。两键都 `on` 则两步都拦。全部行非必检则该步与今日一样放行。

预览返回两步能否过，对应 PUT 再算一遍。确认键 `off` 则确认跳过 IQC；执行键 `off` 则过账跳过 IQC。

## 3. HTTP 与数据

### 3.1 保持不变

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/mes/wm/itemrecpt/list` | 首页待来料入库仍用它（H-D9） |
| PUT | `/mes/wm/itemrecpt/confirm` | URL 不变；**confirm 键 on 时可能多一种业务 error** |
| PUT | `/mes/wm/itemrecpt/{recptId}` | URL 不变；**execute 键 on 时可能多一种业务 error** |
| GET/POST/PUT/DELETE | `/mes/qc/iqc` 及行接口 | 确认自动建入库单的副作用不改 |
| GET | `/mes/qc/iqcline/list` | 抽屉只读复用；不改 URL |
| GET/POST/PUT | 物料/成品入库行 | URL 不变；body **加法**合格量/不合格量/序列号 |
| GET | `/mes/wm/productrecpt/list` 等 | 成品执行不改语义 |

### 3.2 附加

**`GET /mes/wm/inboundhub/list`**

- 登录；`mes:wm:inboundhub:list`
- Query：与 RuoYi 分页一致（`pageNum`/`pageSize`）+ `receiptType`（可空）+ 状态/单号/日期 + **`warehouseId`（可空）**
- `data`：`{ rows, total }` 或现网 `TableDataInfo`（实现与 `BaseController.getDataTable` 对齐）
- 无上下文 4xx/业务失败关闭，不扫他厂

**`GET /mes/wm/itemrecpt/{recptId}/iqc-gate`**

- 登录；IH-I3
- `data`：`canConfirm`、`canExecute`、`confirmGateEnabled`、`executeGateEnabled`、`message`、`lines[]`（`itemId`、`itemCode`、`required`、`iqcId`、`iqcCode`、`checkResult`、`status`、`canInbound`）
- 跨租户 id → 与现网 getInfo 一样当作不存在/无权限，不泄漏他厂

### 3.3 持久化

- **tenant** Flyway：`qc_iqc.recpt_id BIGINT NULL`；索引建议 `(tenant_id, recpt_id)`。不加 NOT NULL，兼容历史。`wm_item_recpt_line` 与 `wm_product_recpt_line` 增加可空 `quantity_qualified`、`quantity_unqualified`、`serial_numbers`（TEXT）。**不加**金额列（IH-G5）。
- **master** Flyway：`sys_menu` 9300 段；`sys_config`：`mes.wm.inbound.iqc.gate.confirm`=`off`、`mes.wm.inbound.iqc.gate.execute`=`on`、`mes.wm.inbound.iqc.autoDraft`=`off`。不种子旧单键。不改历史 `backend/sql/`。
- 不新建入库头表。不把 Hub 行物化成第三张单据表。

`POST /mes/qc/iqc`：在现有 `recptCode` 回头逻辑上，解析到的 `recptId` 写入 `recpt_id`。请求体可增加 `recptId`（可选，加法）。不删 `recptCode` 处理。

### 3.4 事务

确认闸在把状态写成 `CONFIRMED` **之前**。`autoDraft=on` 时先为缺草稿的必检行 insert `PREPARE` IQC（同一事务），再算确认闸（草稿仍不合格，确认闸 `on` 时仍拒）。执行闸在 `processItemRecpt` **之前**。GET `iqc-gate` 不建单。配置读取走 `ISysConfigService.selectConfigByKey`（含租户 overlay）。

## 4. 错误处理

- 闸拒绝：`AjaxResult.error`，文案说明哪一物料未检/不合格；不堆栈、不内部路径
- 配置键缺失或非法：确认当 `off`、执行当 `on`、autoDraft 当 `off`
- 预览失败：抽屉藏闸块，执行按钮仍以服务端为准；禁止前端因预览 500 而乐观放行
- Hub list 某一类型查询失败：整单失败（4xx/5xx），不半页他厂数据

## 5. 保持不变的周围系统

- 若依壳、标签页、F1 抽屉、工厂 `/index` 卡片与 `getIndexNum`
- 行业包 9200 段
- Vue2、pad、`MesPermitAllProvider`
- 出库/领料/退料页
- 入库金额列、Hub 打印：105 不含；分别由 110 / 111 在 Hub 抽屉交付（旧 CRUD 仍不加）

## 6. 风险

- 头表单一 `iqc_id` 无法覆盖多物料：以 `recpt_id`+`item_id` 为准（IH-D7）
- 默认 execute=`on` 挡现网未做 IQC 的过账：overlay 把 execute 设 `off` 回退。确认与 autoDraft 默认 `off`，开 Hub 不改变今日确认、也不自动建 IQC。
- IQC 确认仍可能自动建另一张入库单：本轨不改；Hub 只处理已存在的入库单
