## 1. 问题与目标

61–65 已落地 LangChain4j 出站、Agent、受控写、MCP、工作流与 Vue 管理页。现网三条入口（chat / agent / workflow run）在 session 校验、SSE 帧格式、异常翻译与异步 `TenantContext` 上存在重复与轻微漂移风险；Agent 记忆尚未系统化落 `ai_message`；Tools 默认全开不符合「先只读、按需开写/MCP」的运营预期；RAG 切块与检索参数缺少产品级约束；工作流无法内嵌 LLM 对话步；Tool 调用缺少统一审计面。

### 1.1 目标（66–73）

- 统一运行时管线，冻结三条 HTTP 与 SSE 信封
- Agent 记忆可读可写 `ai_message`，memoryId 含租户
- 租户级 Agent profile（`knowledgeIds` + `enabledTools` + `mcpServerIds`），写/MCP 默认关、按需开
- RAG overlap + 分隔符 + 阈值 + topK，单一路径 `AiRetrievalService`
- 工作流新增 `chat` 白名单步
- Tool 调用可审计、可计量，不打密钥
- Vue3 可维护 Agent 档案；对话页可选档案走 Agent 发送（仍非独立 Agent 聊天 SPA）

### 1.2 非目标

- 重开 A1–A28、改 `/ai/**` 认证、合并 ruoyi-ai
- Supervisor 多 Agent、langgraph、ruoyi `[NODE_CHUNK_*]`
- hybrid BM25、多向量库融合、第二套 trace（**rerank 作为 Advanced RAG 的 Scoring 另立设计 11，不在 66–73 做**）
- **独立 Agent 聊天 SPA** / 新开 Agent 对话菜单（profile 为配置 CRUD；对话仍 `/ai/chat`）
- 本设计内写 Java / SQL / Vue 正文（实现落对应 spec）

## 2. 形态

```text
POST /ai/chat/send ─────┐
POST /ai/agent/send ────┼──► AiSharedRuntime（session-prepare / SSE / error / TenantContext）
POST /ai/workflow/run ──┘
         │
         ├─ ChatMemoryStore ──► ai_message（memoryId = tenant:user:session）
         ├─ ai_agent profile ──► knowledgeIds + enabledTools + mcpServerIds 子集（默认写/MCP OFF）
         ├─ AiRetrievalService ◄── chat RAG + searchKnowledge Tool
         ├─ workflow step chat ──► A24 ChatModel 工厂
         └─ Tool 审计 ──► ai_tool_audit（或等价表名）

Vue3（加固轨前端）：
  /ai/agent  ──► CRUD /ai/agent/profile（A35）
  /ai/chat   ──► 未选档案 → /ai/chat/send；选中档案 → /ai/agent/send?agentId（A36）
```

## 5. 决策正文

### 5.1 共享运行时管线（A29 / I-A7）

从 `AiChatServiceImpl`、`AiAgentServiceImpl`（及工作流 run 中等价路径）抽出：

- **session-prepare：** 校验 `modelId` / `sessionId` / `agentId` 属本租户；创建或续会话；先落 user 消息（chat/agent）
- **SSE：** 统一 `data:` JSON 写入；基础字段 `content`、`done`；workflow 可附加 `step` / `error`（A17/A28 仍有效）
- **error：** 上游失败、租户缺失、许可过期映射为对前端安全文案；日志保留 stack，不回密钥
- **TenantContext：** 异步线程统一装饰；空上下文抛既有租户异常

禁止：为抽公共层改三条 path；引入 `[NODE_CHUNK_*]`；削弱纯 chat 无 Tool 行为。

代码单元：`docs/04.specs/66.ai-shared-runtime-pipeline.md`。

### 5.2 Agent 记忆 Store（A30）

- LangChain4j `ChatMemoryStore` 实现读写 `ai_message`
- `memoryId` = `{tenantId}:{userId}:{sessionId}`（Long 转字符串）
- 加载：按 session 读历史；写入：assistant / tool 消息在流结束或 Tool 返回后落库
- 跨租户 sessionId → 404/403，不读写消息

禁止：客户端指定 memoryId；全进程 `InMemoryChatMemory` 作为生产默认。

代码单元：`docs/04.specs/67.ai-agent-memory-store.md`。

### 5.3 租户 Agent profile（A31）

- 形态：学 ruoyi `agent_info`（**不要** Supervisor）；仍是一份 `MesAiAssistant` 接口，A24 工厂按档案组装
- 表 `ai_agent`：每租户至少一条默认 profile（实现可 seed）
- 字段语义（API camelCase / 列 snake_case 对齐）：
  - `name`、`systemPrompt`、`defaultModelId`
  - `knowledgeIds`（JSON 数组，本租户 `ai_knowledge.id`；空=档案不绑库；Tool 调用仍复核 tenant）
  - `enabledTools`（JSON 数组，现行五值与 **83** 一致，非本文件独自「冻结且互斥」：`searchKnowledge` | `submitProductionFeedback` | `updateWorkorderStatus` | `queryWorkorder` | `listWorkorderTasks`；默认档案只读 `searchKnowledge`）
  - `mcpServerIds`（JSON 数组，本租户 MCP 白名单 server id 子集；空=不挂 MCP）
- **默认：** 无 profile 时写 Tool 与 MCP **均 OFF**；seed 默认 profile 的 `enabledTools` 为空或仅 `searchKnowledge`，`mcpServerIds` 为空；未传 `agentId` 时用默认 profile 装配
- **按需挂载：** 仅 `enabledTools` 列出的 Tool 名进入 LangChain4j tool list；**未列出写 Tool 不得出现**
- **MCP 子集：** 仅 `mcpServerIds` 中且通过 `AiMcpGuard` / 租户启用白名单（63）的 server 挂载；**禁止**档案开启 MCP 即挂本租户全部 server
- `POST /ai/agent/send` 可选 `agentId`；未传用默认 profile 的 modelId + systemPrompt + knowledgeIds + tools 子集 + mcpServerIds 子集
- CRUD：`/ai/agent/profile`（列表/详情/增删改）；权限字独立（如 `ai:agent:profile:*`）；保存时 `knowledgeIds` / `mcpServerIds` / `defaultModelId` 须属本租户
- **管理端 UI 不在本条 Java 单元**：Vue3 档案页见 **A35 / 单元 72**；对话可选档案见 **A36 / 单元 73**。菜单 9107 曾因无页隐藏（`20260826_32_ai_agent_menu_hide.sql`），72 交付时恢复可见

禁止：Supervisor / 子 Agent 编排；SQL Tool；请求体 `tenantId`。

代码单元：`docs/04.specs/68.ai-agent-profile.md`。

### 5.4 RAG 检索管线（A32）

- **切块：** 解析附件时 **overlap**（具体字符数/比例留给 spec，须 > 0）+ **分隔符**（per-`ai_knowledge` 可配或租户/全局默认；如段落/换行/自定义字符串；具体留给 spec）
- **检索：** `AiRetrievalService.search(tenantId, knowledgeId, query, topK, minScore)` 形态（名可微调）
- **topK / 阈值：** 可 per-knowledge 或租户默认；**现行**产品源为 knowledge 列 / `sys_config` `ai.rag.*`（缺口 10 / PR-D17），禁止 yml 与 sys_config 双源，禁止 `ruoyi.ai.rag.*` / `AI_RAG_*` / `@Value` 作为产品配置
- **共用：** `POST /ai/chat/send` 的 `knowledgeId` 与 Agent `searchKnowledge` 同一 service
- 向量层仍带 `tenant_id`（I-A3 不变）

禁止（**69 基线**）：hybrid BM25、cross-encoder rerank、多 store 融合。

生产级文档解析与 Advanced RAG（Query 压缩/展开、RRF、chat Scoring、邻块扩窗）**不在本单元**，见 `docs/03.design/11.mes-ai-production-rag-plan.md` 与 `docs/04.specs/89`–`91`。

代码单元：`docs/04.specs/69.ai-rag-pipeline.md`。

### 5.5 工作流 chat 步骤（A33）

- 步骤 JSON 扩展：`toolName=chat`，必填 `modelId`，可选 `prompt` / 引用上游 `input`
- 运行时经 A24 取 `ChatModel`，单步生成；结果写入 run 上下文供后续步使用
- SSE：每步可推送 `step` 名 + `content` 片段；结束 `done=true`
- 仍禁止 langgraph、禁止 `[NODE_CHUNK_*]`

代码单元：`docs/04.specs/70.ai-workflow-chat-step.md`。

### 5.6 Tool 调用审计（A34 / I-A8）

- 钩子包在 Tool 执行前后（含 MCP connector、工作流 executor）
- 记录：`tenant_id`、`user_id`、`tool_name`、`business_key`（可选）、`latency_ms`、`prompt_tokens`、`completion_tokens`、`status`、时间戳
- 日志 / SSE / 响应不打印密钥；审计行不存 Authorization / cipher
- 不引入 `ruoyi-common-trace`
- **本期无查询口**（无 list HTTP、无管理端页）；延后见缺口 `05` **R11**

代码单元：`docs/04.specs/71.ai-tool-audit.md`。

### 5.7 Agent 档案 Vue3 管理页（A35）

- 页：`/ai/agent` → 组件 `ai/agent/index`；API 模块 `src/api/ai/agent.js` → `/ai/agent/profile`
- 形态：Element Plus 表格 + 对话框，对齐 `ai/mcp`、`ai/knowledge`；**仅配置**，不做聊天气泡
- 表单：`name`、`systemPrompt`（多行）、`defaultModelId`（本租户模型 options）、`knowledgeIds`（多选本租户知识库）、`enabledTools`（五值多选/开关，与 **83** 一致：`searchKnowledge` | `submitProductionFeedback` | `updateWorkorderStatus` | `queryWorkorder` | `listWorkorderTasks`；默认只读 `searchKnowledge`）、`mcpServerIds`（多选本租户 MCP server，无 token 展示）、`status`、`remark`
- 默认新建：写 Tool 与 MCP **不勾选**；可仅勾 `searchKnowledge`
- 菜单：`menu_id=9107` 恢复 `visible='0'`（显示）；按钮权限 9171–9174 已存在则复用；增量 SQL 不改写历史 seed 文件
- 权限：`v-hasPermi` 对齐 `ai:agent:profile:*`；不传客户端 `tenantId`

禁止：独立 Agent 聊天路由；拷 ruoyi-web / Vben Agent 页；引入 x/UnoCSS/hook-fetch；改 Vue2。

代码单元：`docs/04.specs/72.ai-agent-profile-ui.md`。

### 5.8 对话页可选档案（A36）

- 在既有 `/ai/chat` 增加可选 Agent 档案下拉（数据源：`GET /ai/agent/profile` 列表或等价 options，仅本租户正常状态）
- **未选：** 行为与 58/59 一致 → `POST /ai/chat/send`（可挂 `knowledgeId` 的纯对话路径不变）
- **已选：** → `POST /ai/agent/send`，body 带 `agentId`；模型/提示/Tools/MCP 以档案为准（档案 `defaultModelId` 优先于页内模型下拉的冲突规则：以档案为准，页内模型下拉在已选档案时可只读或隐藏——实现细节留给 73）
- SSE 信封仍 `{content, done}`；权限 `ai:chat:send`
- **不**新增 `/ai/agent/chat` 菜单或路由

禁止：把未选档案静默改成 agent/send（避免纯对话用户意外挂 Tool）；改 chat/send path。

代码单元：`docs/04.specs/73.ai-chat-agent-select.md`。
