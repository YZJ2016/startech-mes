## 1. 问题与目标

现状：登录后 `/index` 只有工单三态卡（`GET /mes/pro/workorder/getIndexNum`，无权限注解）和整页欢迎语。平台回家与工厂共用这一页；平台没有 MES 模块，工单卡无意义。同厂不同岗位若继续把所有数字铺在一页且接口不鉴权，会看见不该看见的汇总。

目标：登录后进入与身份匹配的工作台；工厂可按本厂喜好在「单页」与「按权限分区」之间切换；卡片只展示调用方已有权限的数据；不把首页做成假驾驶舱。

### 1.1 目标

- 平台回家：舰队与运维数字、异常厂名单、快捷入口；零 `/mes/**`
- 工厂：工单三态、待办跳转、公告/消息、可选 AI 入口；同类数字不全用同一种卡
- 本厂 `mes.index.layout` 切换平铺与分区，卡片集合与各块展示形态不变
- 无权限不渲染、不请求；首页相关接口拒绝无权限调用
- 失败关闭租户语义不变

### 1.2 非目标

- 部门/本人范围裁工单、库存、检验单
- OEE、一次合格率、缺料、安灯、SN 族谱
- 首页卡片 JSON 编排、用户级布局、拖拽
- 新首页路由、工厂 MES 驾驶舱 BFF、跨租户 MES 报表（D5）
- 重开全部 MES `@PreAuthorize`、改 Vue2、改 `/login` / `getRouters` 信封
- 教育 / 合同 / 售后 / 摄像头进首页
- 在首页嵌 AI 会话
- 为图表新增时序/KPI 接口；引入第二套图表库或升级 echarts
- 把 `allNum` / `ingNum` / `fiNum` 画成饼图（三者不是互斥占比）

## 2. 形态

```text
登录 → GET /getInfo（permissions、tenantId、runAs）
         │
         ├─ 平台回家（tenantId==0 且非 runAs）
         │     ├─ GET /platform/home/summary（isPlatformOperator；silentError）
         │     └─ PlatformHome：舰队卡 + 异常名单 + 运维卡（有 monitor 权限才出）+ 快捷入口
         │
         └─ 工厂 / runAs
               ├─ GET /system/config/configKey/mes.index.layout
               │     overlay → 全局 → 缺省 single
               └─ FactoryHome
                     ├─ 有 mes:pro:workorder:list → getIndexNum（含 prepareNum）
                     ├─ 有各 list 权限 → 对应 list?status=PREPARE&pageSize=1 → total
                     ├─ 公告 / 消息（现有）
                     └─ 有 ai:chat:list → AI 入口
                     single：平铺
                     role：生产 / 仓储 / 质检 / 设备 分区（空区不渲染）
```

## 3. 参数

| 项 | 约定 |
| --- | --- |
| 键 | `mes.index.layout` |
| 值 | `single` 或 `role`；其它或空 → `single` |
| 全局 | `tenant_id` 空，`config_type=Y`，增量 SQL 一条 |
| 本厂 | 同 key 的 overlay 行；`selectConfigByKey` 已先读 overlay |
| 开通租户 | **不**复制 `sys_config`（全局表，I8） |
| 工厂 UI | 参数列表只含 overlay，切布局 = 新增/修改本厂行；删 overlay 回全局 |
| 平台改全局 | 只影响无 overlay 的厂 |
| 读取 HTTP | 已有 `GET /system/config/configKey/{configKey}`，不改路径 |

`DATABASE` 租户读该键仍走主库（I8）。缓存走现有 overlay 键，不新造 Redis 前缀规则。实现不得把该开关写进 `application*.yml` 或 `@ConfigurationProperties`（H-D15）。

## 4. 数据与权限

工厂不新增 MES 汇总 Controller。信封保持 `code/msg/data` 与列表 `rows/total`。平台运营附加 `GET /platform/home/summary`（H-D17），不改既有 list URL。

| 块 | HTTP | 权限 | 说明 |
| --- | --- | --- | --- |
| 工单三态 + 待确认 | `GET /mes/pro/workorder/getIndexNum` | `mes:pro:workorder:list` | 现 `allNum`/`ingNum`/`fiNum`；增加 `prepareNum`。待确认不走工单 `/list`（该 list 会顺带查工装） |
| 待 IQC | `GET /mes/qc/iqc/list` | `mes:qc:iqc:list` | `status=PREPARE`，`pageNum=1`，`pageSize=1`，只用 `total` |
| 待 IPQC | `GET /mes/qc/ipqc/list` | `mes:qc:ipqc:list` | 同上 |
| 待 OQC | `GET /mes/qc/oqc/list` | `mes:qc:oqc:list` | 同上 |
| 待来料入库 | `GET /mes/wm/itemrecpt/list` | `mes:wm:itemrecpt:list` | 同上 |
| 待生产领料 | `GET /mes/wm/issueheader/list` | `mes:wm:issueheader:list` | 同上（现网是 issueheader，不是 `/mes/wm/issue`） |
| 公告 | `GET /system/notice/list` | 现有公告能力 | 本租户 |
| 消息 | `GET /system/message/list` | 现有消息能力 | 本租户 |
| 布局 | `GET /system/config/configKey/mes.index.layout` | 已登录即可（现接口无 list 权限） | 工厂工作台才读 |

上述 MES list 上被注释的 `@PreAuthorize` **只恢复本表这些方法**（H-I1）。`getIndexNum` 现状无注解，本设计要求补上。

点击：`router.push` 到现有页面并带同一 `status`（工单待确认 → 工单列表 `PREPARE`）。设备：有 `mes:dv:repair:list` / 点检相关 list 才显示入口，不请求计数。

`role` 归区：

- 生产：工单三态、待确认工单
- 仓储：待来料入库、待生产领料
- 质检：待 IQC / IPQC / OQC
- 设备：维修单、点检计划入口

某区零块则整区不出现。无任何 MES 块：文案「暂无业务待办」；公告/消息仍可显示。

平台工作台：`GET /platform/home/summary` + 现有 `/platform/tenant`、监控、系统快捷入口。不调 `/mes/**`。详见 §4.1。

## 4.1 平台运营汇总（H-D17）

仅 `isPlatformOperator`。`user_id=1` 与工厂会话 403。runAs 进厂不走本接口（走 FactoryHome）。

**到期：** 服务常量 30 天（与 list 筛共用，不写 yml）。已过期 = `expire_time < now`；即将到期 = `now ≤ expire_time < now+30d`。`expire_time` 空不计入。时区用 JVM 默认。

**舰队计数**排除 `is_platform=Y` 与 `tenant_id=0`。`provisionFailed` / `provisionNotReady` 仅 `isolation_level=DATABASE`。ROW 厂出现在启用/停用/到期计数中，不因空 `provision_status` 算 NOT_READY。

**`data`：**

| 段 | 字段 | 含义 |
| --- | --- | --- |
| `fleet` | `enabled` / `disabled` | `status=0` / `1` 的工厂数 |
| `fleet` | `provisionFailed` / `provisionNotReady` | DATABASE 的 `FAILED` / `NOT_READY` |
| `fleet` | `expired` / `expiringSoon` | 已过期 / 30 天内到期 |
| `ops` | `onlineSessions` | 可见 token 数；无 `monitor:online:list` 则为 `null` |
| `ops` | `jobsRunning` / `jobsPaused` | `sys_job.status` 0/1；无 `monitor:job:list` 则为 `null`；沿用平台会话下现有 job 租户谓词 |
| `ops` | `loginFailToday` | 当日 00:00:00 起 `sys_logininfor.status=1` 条数，平台专用可跨租户；无 `monitor:logininfor:list` 则为 `null` |
| `exceptions` | 最多 20 | 入选：DATABASE 的 FAILED/NOT_READY，或已过期/即将到期。字段：`tenantId`、`tenantCode`、`tenantName`、`status`、`expireTime`、`provisionStatus`、`reasons[]`（`FAILED` \| `NOT_READY` \| `EXPIRED` \| `EXPIRING`）。排序：FAILED → EXPIRED → NOT_READY → EXPIRING（到期日升序，空到期排后） |

在线人数与打开「在线用户」同一代价（扫 `login_tokens` 后再 `TenantSessionAccess.visible`），不另做会话计数器。

**租户 list 附加查询（不改 URL）：** `provisionStatus`（`FAILED` \| `NOT_READY`）；`expireStatus`（`expired` \| `expiring`）。`expiring` 使用同一 30 天常量。既有 `status`、`tenantCode`、`isolationLevel` 保留。

点击（H-F8）：

| 控件 | 去向 |
| --- | --- |
| 启用 / 停用 | `/platform/tenant?status=0\|1` |
| 开通失败 / 未就绪 | `/platform/tenant?provisionStatus=FAILED\|NOT_READY` |
| 已过期 / 即将到期 | `/platform/tenant?expireStatus=expired\|expiring` |
| 异常行 | `/platform/tenant?tenantCode=` 该厂编码，并带对应筛（有则带） |
| 在线 | `/monitor/online` |
| 运行中 / 暂停任务 | `/monitor/job?status=0\|1` |
| 当日登录失败 | `/monitor/logininfor?status=1`（列表仍本租户；与汇总跨租户计数可能不一致，文案不声称「全平台失败列表」） |

不做：许可到期、跨厂 MES、平台页 echarts、新进厂 API。

## 5. 前端结构

路由仍 `/index`。不改 Vue2。

| 文件 | 职责 |
| --- | --- |
| `views/index.vue` | 分流：`isPlatformTenant && !isRunAs` → 平台，否则工厂。去掉大字欢迎主体 |
| `views/dashboard/PlatformHome.vue` | 平台工作台：summary + 快捷入口 |
| `views/dashboard/FactoryHome.vue` | 读布局参数；按 `auth.hasPermi` 挂块；`single`/`role` 两种排法 |
| `views/dashboard/PanelGroup.vue` | 工单数量图标卡（全部 / 进行中 / 已完成 / 待确认），仅工厂且有工单 list 权限 |
| `views/dashboard/` 内本地 echarts 封装 | 工单对比柱、质检待办横条、仓储待办横条；不新建 npm 依赖 |

身份用现有 Pinia `user`：`tenantId === 0` 为平台回家；`isRunAs` 为进厂（H-I6）。权限用 `src/plugins/auth.js` 的 `hasPermi`，与侧栏同一 `getInfo.permissions`。

无权限：不渲染、不发请求（H-D6 主路径）。

## 5.1 展示映射（H-D16）

数据几乎都是**当前时点计数**，没有按日序列。形态按「这组数是什么关系」选，不按装饰选。`echarts` 已在 Vue3 `package.json`，首页只用它，不升级、不加 `vue-echarts`。

| 块 | 数据关系 | 展示 | 不采用 |
| --- | --- | --- | --- |
| 工单 `allNum` / `ingNum` / `fiNum` / `prepareNum` | 同一对象上的并列快照；**全部 ≠ 其余之和**，不能当占比 | **图标数字卡**（四张，可点进列表）+ **分组柱状图**（四类并排比大小） | 饼图/环形图；折线（无历史） |
| 待 IQC / IPQC / OQC | 同单位「待检单」条数，可横比，不共享总体 | **横向柱状图**（三类）；柱可点进对应列表 | 三张再铺一套大数字卡（与工单区重复形态）；饼图（三类不是一块饼） |
| 待来料入库 / 待生产领料 | 同单位「待处理仓单」，仅两类 | **横向柱状图**（两类） | 为凑图去拆更多仓单类型 |
| 设备维修 / 点检 | 无计数（H-D10） | **图标入口磁贴** | 空柱、假 0 趋势 |
| 公告 / 消息 | 有标题与时间的条目 | **列表**（现有接口，条数有限） | 图表 |
| AI | 入口（H-D11） | **图标入口** | 会话嵌入、用量图 |
| 平台回家 | 运营时点计数 + 异常厂 | **舰队/运维数字卡** + **异常名单** + **图标快捷入口** | 任何 `/mes/**` 图；饼图；许可覆盖率 |

点击：图与卡同一套 `router.push`（H-F4）。`role` 下图跟所属分区走，形态不变。

某待办无权限：该系列不进图，不发对应请求。质检只剩一类权限时，仍用横条（一根柱），不改回单独数字卡，避免同区形态来回跳。仓储同理。

## 6. 空态与错误

| 情况 | 行为 |
| --- | --- |
| 块加载 | 卡片骨架 |
| 数字 0 | 显示 0，可点进空列表 |
| 布局键失败/非法 | 当 `single`，不挡整页 |
| 某块 403 / 网络失败 | 只藏该块，其它块继续 |
| 401 | 现有重新登录，首页不另做 |
| 并发 403 toast | 首页这几发带静默标记；`request.js` **仅当该标记存在**时不弹非 401 通知；默认行为不变（H-I3） |

不把整页打成错误页。不自动重试。

## 7. 测试与验收（设计约束，非 task 清单）

实现单元须能证明：

- 无 `workorder:list` 时 `getIndexNum` 403，工厂页无工单卡
- 仅仓储权限时无质检数字、不请求 qc list
- A 厂 overlay=`role` 不影响 B 厂未覆盖时的 `single`
- 平台回家不出现工单卡、不请求 `/mes/**`；有平台运营身份时出现舰队/异常；有对应 monitor 权限才出现运维数字
- runAs 进厂看到该厂布局与该厂 `total`
- Vue3 `build:prod`；不改 `frontend/`
- 工厂页同时出现工单图标卡与工单柱、质检横条、仓储横条、公告列表（在对应权限下）；工单区无饼图；无按日折线

未要求本设计阶段跑命令。现场 JWT / 浏览器冒烟在对应 spec 第 4 节记录。

## 9. 视觉语言（管理端工作台外观）

产品块、权限与接口不变。本节省的是「看起来像生产 MES 工作台」，而不是 RuoYi 演示首页。

选择：**工业工作台（hybrid）**。页头标明谁 / 哪厂 / 哪天；业务按模块成卡；工单数字卡与分组柱同属「生产」；质检 / 仓储为独立模块（紧凑计数便于扫 0，横条比大小）；图表是对照，不是装饰。不采用密排控制室（与现有白底管理端侧栏冲突），也不采用大留白企业门户（待办少时更空）。

约定：

- 页头：工厂为「工厂工作台」，平台为「平台工作台」。文案只读现有 user store（`tenantName`、`nickName` / `name`、runAs 标记）；日期为浏览器本地日，无新接口
- 模块：`single` 与 `role` 都出模块标题（生产 / 质检 / 仓储 / 设备 / AI / 公告 / 消息）。H-D4 仍是同一套卡片；`role` 只改质检与仓储的排列顺序（仓储在前）
- 栅格：生产通栏；质检|仓储、设备|AI、公告|消息在 `md+` 两列，缺一块则另一块通栏
- 色：Element Plus 语义色（info / primary / success / warning）。禁止 RuoYi PanelGroup 青绿 / 粉红 hover 换底，禁止巨型装饰图标压过数字
- 图：2D 柱 / 横条，可读轴与柱顶或柱侧数字；无 3D、无饼、无折线
- 平台：页头下先舰队数字卡，再异常厂名单，再运维数字（有权限），快捷行仍按组织 / 配置 / 运行分组。不正中大图标磁贴，不上 echarts

非目标：新 KPI、新图表库、拖拽布局、用户级主题。
