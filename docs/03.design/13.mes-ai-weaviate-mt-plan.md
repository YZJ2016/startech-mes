## 1. 问题与目标

现网 Weaviate 用 `MesAiK{tenantId}_{knowledgeId}` 当 class，再在对象上写 `tenant_id`。这满足 I-A3 的「不要只靠 kid」，但和 Weaviate 官方建议相反：数据集一多不应「一份数据一个 collection」。原生 multi-tenancy 在 **同一个 collection** 里按 tenant 切 shard，查询必须带 tenant 名，才能撑住 SHARED 上多家厂、每厂多个知识库。

目标：

- SHARED：一台平台 Weaviate 上，按厂分 shard、按维度分 collection
- DEDICATED：仍各连各的集群，schema 规则与 SHARED 相同
- 公开 HTTP 与 93 绑定不变

### 1.1 非目标

- 取消 A14 或把原生 MT 标成第三档隔离
- 用 MT 替换 `tenant_id` 属性过滤
- DashVector / Pinecone / Milvus / Qdrant 本轨改造
- 自动搬运已有 `MesAiK*` 数据
- 产品页配置 class / tenant 名

## 2. 三层隔离（不得并成一层）

```text
A14 集群
  SHARED  → 平台 yml Weaviate
  DEDICATED → 该厂专行 host/Key（禁止回落 yml）

Weaviate 原生 MT（本轨，仅 type=weaviate）
  collection MesAiD{dimension}
    └ tenant t{tenantId}     ← 只信 TenantContext
         └ objects + tenant_id, kid, docId, fid

I-A3 属性过滤（保留）
  where tenant_id 且 kid
```

原生 MT 使「漏写 where」也不会扫到他厂 shard；属性过滤使「tenant 名写对但 kid 串库」仍被挡住。SHARED 的 API Key 仍能打到该集群全部 tenant（WM-I3）；密钥级隔离只走 DEDICATED。

## 3. 命名与维度

| 用途 | 字符串 | 谁计算 |
| --- | --- | --- |
| Weaviate class | `MesAiD` + 维度整数 | ingest / search 用 embedding 向量长度；`createSchema` 用入参 `dimension` |
| Weaviate tenant | `t` + 租户 id | `TenantContext.getRequired()` |
| 知识库 | 属性 `kid` | 已校验的本厂 knowledgeId |
| DashVector collection | 仍 `MesAiK{tid}_{kid}` | **禁止**改成 `MesAiD*` |

`removeByDoc` 无向量：调用方传入该库 embedding 模型维度，Weaviate 定位 `MesAiD{dim}`。缺维度失败关闭。

同一租户两个知识库若 embedding 维度不同，落在两个 class 上，但 tenant 名相同（Weaviate 的 tenant 是 **每个 collection 内** 的）。每个 class 都要确保该 tenant 存在。

## 4. 适配器行为

继续 JDK HTTP，不引入 `langchain4j-weaviate`。

- 建 schema：class `MesAiD{dim}`，`vectorizer: none`，`multiTenancyConfig.enabled=true`；属性集与现网相同。已存在则允许 409/422。
- 确保 tenant：对该 class `PUT/POST` tenants `t{tid}`（或等价；允许已存在）。检索不得在 tenant 不存在时落到默认空间。
- 写入 / GraphQL / 删除：必须带 tenant；`where` 仍 And `tenant_id` + `kid`（删除再加 `docId`）。
- 启动仍懒连；缺 host 到调用再失败。

精确 REST 路径与 GraphQL 字段名留给单元 100，不得改成「不带 tenant 的旧 class 网格」。

## 5. SPI

`VectorStoreService` 对 Weaviate：

- `createSchema(kid, dimension)`：class 用 `dimension`；`kid` 仍校验（无效 kid 失败关闭），但不再编进 class 名。
- `storeEmbeddings`：一批记录必须同一 `tenantId`、同一 `knowledgeId`、同一向量长度。
- `search`：class 用 `queryVector.length`；tenant 用上下文。
- `removeByDoc`：**增加** `dimension`；HTTP 层删除附件仍只传业务 id，由 knowledge 服务补维度。

DashVector 实现保持现网 collection/partition；新增参数忽略。

## 6. 与 DashVector 的对照

| | 本轨 Weaviate | 现网 DashVector（不动） |
| --- | --- | --- |
| 集群两档 | 相同 Factory | 相同 Factory |
| 物理切分 | collection 内 tenant shard | collection 每 kid + partition `t{tid}` |
| 逻辑过滤 | `tenant_id` + `kid` | 同左 |

不要求两个引擎的 collection 字符串对齐。

## 7. 存量

未连过 live 时，默认没有要迁的 `MesAiK*`。若有：不双写、不自动读旧 class；重解析写入 `MesAiD*`（WM-G2）。单元 100/101 不得实现「新旧 class 都搜」。
