# KU-AI 运营层详细设计（兼容优先）

- 日期：2026-10-10
- 需求：`docs/02.requirements/24.kuai-ai-operational-layer-gaps.md`
- 设计性质：示例系统页面逆向观察 + 本地契约映射；不包含实现任务清单
- 基准视口：1280×720，DPR 2；尺寸为 CSS px

## 1. 设计结论

采用双层产品结构：现有 `/chat`、`/agents`、`/knowledge`、`/mcp` 继续作为可配置治理底座；新增 `/hub`、`/agent-library`、`/pulse`、`/corpus`、`/trust`、`/insights`、`/settings` 作为业务运营层。新增后端全部进入 `/api/v1/apps/kuaiai/operations/*`，只在必要处编排既有 core 服务，不复制模型连接、审计、知识库或权限实现。智能体库按已选方案 B 建立“后端场景模板→租户场景实例→现有 Agent 档案”映射：卡片与业务路由属运营层，提示词、知识库、工具、MCP 和授权仍以现有 Agent 档案/执行管线为唯一真源。

| 标签栏 | y=56–96 | 复用现有壳 |
| 页面外层 | 展开态约 x=231–1263 | `padding: 16px 16px 24px`，不另造固定定位 |

| 状态 | 呈现 |
| --- | --- |

## 3. 菜单与路由

`manifest.json` 使用仓内已存在的无 path 分组节点形式。推荐顺序：

```text
星AI
├─ 智能运营
│  ├─ 能力矩阵        /apps/kuaiai/hub
│  ├─ 智能体库        /apps/kuaiai/agent-library
│  ├─ 异常感知        /apps/kuaiai/pulse
│  └─ AI 对话         /apps/kuaiai/chat
└─ 智能治理
   ├─ 知识语料        /apps/kuaiai/corpus
   ├─ Agent 档案      /apps/kuaiai/agents       （保留）
   ├─ 知识库          /apps/kuaiai/knowledge    （保留）
   ├─ MCP 白名单      /apps/kuaiai/mcp          （保留）
   ├─ 信任中心        /apps/kuaiai/trust
   ├─ 调用分析        /apps/kuaiai/insights
   └─ 模型设置        /apps/kuaiai/settings
```

路由组件继续在 `src/apps/kuaiai/index.tsx` 懒加载。运营页不得 import 管理页内部状态；共享类型和请求放 `services/operations.ts`，共享页面壳放 `components/OperationalPageHeader.tsx`。

星AI 根菜单沿用 `kuaiai:entry:read`；新页面同时要求该入口权限和各自 display 权限。后端新增读取 API 同样双检；trust/insights 的 core stats/audit 继续只检查既有 entry 权限，insights 页面要同时具备 `kuaiai:insights:display` 才可见。注册、预设授权与存量租户处理矩阵以 spec 181/186 为准，升级只注册权限不自动扩权自定义角色。

## 4. 能力矩阵 `/hub`

### 4.1 页面结构

1. 页头：标题“能力矩阵”；副标题“制造场景 AI 能力总览，当前模型 {model}”。右侧紫色描边“打开 KU-Ask”（约 142×32）与刷新（82×32）。
2. 能力标签行：距页头内容约 18 px，8 个蓝色标签，高约 26 px、水平 padding 12 px、间距 8 px，允许换行。
3. 指标行：四列，列间 16 px；基准宽约 226 px、高约 95 px。标题 14 px，数值 24–28 px/600，单位和变化说明放数值下方。
4. “能力矩阵”二级标题：距指标行 24 px。
5. 主区：左侧品牌视觉卡约 300 px；右侧四列能力卡、两行，每列间 16 px。容器窄于 1180 时改为三列；窄于 960 时视觉卡占整行；窄于 768 时单列。

### 4.2 能力卡

每卡至少 184×150 px，白底、1 px 弱边框、12 px 圆角、16 px padding。顶行左侧能力名 16 px/600，右侧状态 Tag 52×22；中部两行说明，底部按钮 111×32。卡片不得因说明长度不同造成同一行按钮错位，使用 flex column + margin-top auto。

| 能力 | 状态来源 | 入口 |
| --- | --- | --- |
| 智能问答 | chat 连接已配置 | 打开助手 |
| 智能问数 | 工具开关 + 至少一个只读 Tool | 打开助手，mode=query |
| 智能实施 | 对应引导配置存在 | 打开助手，mode=guide |
| 异常感知 | 至少一个 Pulse detector 可用 | `/pulse` |
| 智能录单 | vision 连接已配置 | 已注册的录单业务入口 |
| 智能推荐 | 推荐场景已注册 | 对应业务入口 |
| 知识检索 | RAG 开启 + 至少一个启用知识库 | `/corpus` |
| 可信执行 | 受控 Tool 可用；HITL 未完成时为“部分就绪” | `/trust` |

### 4.3 交互

- “打开 KU-Ask”调用现有 `AiContext` 抽屉，不新造聊天组件。
- 能力卡传 `context.extra.capability_mode`，只允许 `ask|query|guide`。
- 状态为 `not_ready` 时按钮禁用并用 Tooltip 说明缺少连接、权限或检测器。
- 指标点击：调用数/平均响应进入 `/insights`；Pulse 数进入 `/pulse`；语料数进入 `/corpus`。

## 5. 智能体库 `/agent-library`

### 5.1 布局

页头标题“智能体库”，副标题“预置制造场景智能体，一键对话或跳转业务页”，右侧刷新。正文采用两列卡片，基准每卡约 468×244 px，横向间距 16 px、纵向 16 px；小于 900 px 单列。

卡片内部左图右文：外 padding 16 px；插图区约 140×210 px、圆角 10 px、`object-fit: cover`；内容区 `flex:1`，左 margin 16 px。名称 18 px/600，状态 Tag 52×22；说明最多三行；能力标签为深灰小 Tag；样例问题以次要文字展示，最多两行；底部两个按钮各约 135×32。

### 5.2 六个出厂场景模板

| key | 名称 | 能力标签 | 样例问题 | 查看场景目标（实现前须按现存路由复核） |
| --- | --- | --- | --- | --- |
| `inventory-insight` | 库存洞察助手 | KU-Ask | 查询缺料相关的物料即时库存 | 即时库存查询 |
| `planner-advisor` | 计划员顾问 | KU-Ask、KU-Pulse | 分析近期工单延期风险并给出处理顺序 | 生产计划/工单 |
| `purchase-followup` | 采购跟单助手 | KU-Draft、KU-Act | 汇总近期采购交期风险 | 采购订单 |
| `schedule-explainer` | 排程解读助手 | KU-Suggest | 解释当前排程冲突与调整依据 | 排程中心 |
| `quality-analysis` | 质量异常分析 | KU-Pulse、KU-Know | 汇总近期质量异常并分析可能原因 | 质量异常/8D |
| `supplier-collaboration` | 供应商协同 Agent | KU-Act | 汇总待协同供应商事项 | 供应商协同 |

上述六项是首期后端内置模板，不是前端固定死的六条 Agent 档案。模板提供 `template_key`、卡片名称/说明、插画 key、样例问题、能力标签、业务路由白名单目标和受审查的初始 Agent 档案配置（场景提示词、最小只读工具名）；预置档案固定以 `status=停用`、`grant_mode=ROLE`、`default_model_id=null`、空授权名单、空 `knowledge_ids`、空 `mcp_server_ids` 创建，不含模型密钥、跨租户 Agent ID 或未经授权的知识库 ID。安装 KU-AI 时为当前租户实际创建六份 Agent 档案，不以仅渲染六个空壳卡片代替；以后扩充模板遵循同一租户预置规则，前端仍消费后端列表，不限制只能六卡。

租户场景实例表按 `(tenant_id, instance_key)` 非软删唯一，存 `template_key`、`origin(system_seed|copy)`、本租户 `agent_profile_id?`、覆盖字段 JSON（仅名称/说明/插画 key/样例问题/能力标签/经白名单校验的业务路由）、`enabled`、审计字段和 `deleted_at`；`instance_key=template_key` 为该租户的六个预置场景行，复制场景时创建新唯一 instance_key、保留源 `template_key`。安装服务在同租户事务中以稳定模板 key 幂等创建六档案与六行绑定；既有安装租户升级/同步只补缺失的系统预置项，不更新已有自定义档案、改绑、授权名单或手动停用状态；不把用户自己创建的同名档案当作系统档案，也不因为手动解绑/软删而悄然重建。场景目录返回后端合并后的六个预置项和租户复制项；每次写入和发送都复核租户/档案归属，删/停用的档案不回退到别的档案。

### 5.3 预置档案与首次可用性

安装生命周期：沿用既有 `ApplicationService.install_application`，它当前只把应用设为 installed 且 inactive 并同步菜单，本次须加 KU-AI 专属幂等预置服务 `seed_kuaiai_agent_scenes_on_lifecycle(tenant_id)`——沿用同函数内 `kuaireport` 调 `seed_system_reports_on_lifecycle` 的先例，在 `app_code == "kuaiai"` 时调用，并在 `enable_application` 与清单/菜单同步路径为已安装租户重复执行同一幂等函数，不对其它应用自动建档。安装/扫描路径没有用户上下文，预置档案与场景行的审计字段按本仓系统创建约定写 `created_by=0`、`created_by_name="系统"`，不得冒名任一管理员或员工。在同一个 Tortoise 事务内为六个模板创建 `status=停用`、`grant_mode=ROLE`、`default_model_id=null`、无授权名单的本租户档案和 `instance_key=template_key` 的场景映射行，任一档案/映射失败时六组创建全部回滚；实例记录系统预置来源以识别升级补齐与租户手工改动，不以档案名称推断种子归属。系统档案默认使用模板中文名；若与同租户现有档案重名，追加 `（预置）`，仍冲突则追加递增序号，绝不覆盖用户档案。预置身份由 `origin=system_seed` 的场景映射与 `agent_profile_id` 关联确认，不以名称判断。`install` 接口的应用标记目前由单独 DB 连接更新，不能声称与新表同一事务：`install`/`enable` 调用预置服务失败时必须向调用方返回失败，不得吞成“安装成功”；应用扫描路径若按现有整体异常策略捕获，智能体库必须经 `provisioning.complete=false` 暴露未就绪，并在应用启用、扫描/升级同步中安全重试，不报告六场景已准备好。既有已安装/启用租户按同一幂等流程补齐真正缺失项，尊重已经手动解绑、软删、改绑、授权或定制的种子。

预置流程不写任何 `apps_kuaiai_agent_grants` 行、不自动启用档案，也不需要给 grant 增加“系统来源”字段。六份档案的初始 `grant_mode=ROLE` 只是沿用现有档案页默认的可编辑配置；管理员在 `/apps/kuaiai/agents` 打开对应档案后可改为 ROLE 或 USER，配置角色/人员名单，再按现有“启用档案必须有非空名单”的规则启用。场景展示权限、档案配置权限、档案使用权、业务 Tool 权限互相独立；没有任何用户因安装动作自动获得六档案使用权，管理员身份本身也不绕过 Agent grant 或 Tool 的业务读权限。

首期预置档案只勾选最小**只读** Tool：

| 模板 | 初始只读 Tool（新增名为本次设计，非现网已有） | 已读到的本地领域服务/现有权限锚点 |
| --- | --- | --- |
| 库存洞察 | `query_inventory_balance` | `ReportService.get_inventory_report`；Tool 自身必须检查 `kuaizhizao:inventory:read` 并在适配层套用库存数据范围，因为该 service/现有报表入口不接收 `current_user` |
| 计划员顾问 | 既有 `query_workorder`、`list_workorder_tasks` + `query_delivery_risk` | `ProductionControlService.get_delivery_risk_orders`、现有工单 service；`kuaizhizao:work-order:read`；该 service 只按 tenant 查风险，Tool 适配层必须补当前用户工单数据范围 |
| 采购跟单 | `query_purchase_followup` | `PurchaseService.list_purchase_orders`（已接收 current_user 数据范围）；`kuaizhizao:purchase-order:read` |
| 排程解读 | `query_published_schedule` | `RollingScheduleService.get_plan_by_date`；`kuaizhizao:plan-management-rolling-scheduling:read`；service 不接收 current_user，Tool 必须复核权限/数据范围且只暴露已发布可读事实 |
| 质量异常分析 | `query_quality_anomalies` | `FinishedGoodsInspectionService.get_quality_anomalies`；`kuaizhizao:quality-analysis:read`；service 不接收 current_user，Tool 适配层必须补当前用户数据范围过滤 |
| 供应商协同 | `query_supplier_orders` | `PurchaseService.list_purchase_orders` 按 supplier_id 与当前用户范围过滤；`kuaizhizao:purchase-order:read`；现有 `SupplierCollaborationService.get_supplier_purchase_orders` 不带当前用户范围且无分页，不直接对 AI 暴露 |

Tool 参数只允许闭集白名单，且每个 Tool 返回有界摘要而非整表：`query_inventory_balance(keyword?, warehouse_id?, limit<=20)`、`query_delivery_risk(limit<=20)`、`query_purchase_followup(supplier_id?, buyer_id?, status?, delivery_date_from?, delivery_date_to?, limit<=20)`、`query_published_schedule(plan_date)`、`query_quality_anomalies(inspection_type?, start_date?, end_date?, material_id?, supplier_id?, limit<=20)`、`query_supplier_orders(supplier_id, status?, limit<=20)`。日期/状态枚举按底层 service 当前契约验证，输出字段只保留回答场景所需的编码、名称、数量、日期、状态和风险摘要，不返回客户/供应商敏感扩展字段、内部路径或 SQL。

Tool 名、参数白名单、业务读权限与可用状态必须同步 `ENABLED_TOOL_NAMES`、KU-AI manifest `ai_tools`、工具注册/执行 guard；默认不开 `submit_production_feedback`、`update_workorder_status` 或其它写 Tool，不自动给任一预置档案 MCP 凭据。每个 Tool 从已授权业务服务取有界摘要、复核当前租户、用户权限及数据范围；若现有 service 不接收用户，则在适配层补齐数据范围，不能直接拿全租户数据返回或接受任意 SQL。没有 MES 数据时返回真实空结果，LLM 不编造库存、采购、排程、质量或供应商事实。初始提示词只规定各自职责与事实引用边界，不含租户真实业务信息或密钥。

知识库按管理员显式选库：安装不新建空库，也不把现有所有库一键绑给六份档案；管理员在 `/knowledge` 准备语料并在 `/agents` 选定该档案准用的 `knowledge_ids`，需要检索时才勾既有 `search_knowledge`，缺 embed 连接/索引失败/无命中均不伪装“已有知识答案”。应用连接器仍是 chat/embed 等角色连接和密钥的唯一来源；chat 未配置时预置档案和卡片存在但运行状态 not_ready、提示去 `/settings`/应用连接器；缺某业务权限则该 Tool 不暴露对应业务数据。所谓“开箱即用”是无需手工建六档案、手工绑六卡或另造一套 Agent 引擎；实际业务问答仍以模型连接、授权和真实业务数据为前置。

### 5.4 场景复制与定制

复制时管理员指定本租户已有且自己有管理读权限的源 Agent 档案；在同一数据库事务内复用现有 `agent_service.create_profile` 的字段校验克隆其允许复制的提示词、知识库、工具、MCP 配置为**停用**新档案，创建复制场景实例并绑定新档案；源档案若选了默认模型目录 ID，还须用现有同租户 chat 模型校验后在事务内写入新档案（当前 create_profile 会忽略 default_model_id，不得假称已复制）；新档案名称用源名称截断加唯一后缀，冲突重试仅针对该名称；不复制使用授权名单、模型密钥或租户身份。之后由管理员在现有 `/agents` 设定授权并启用；也可不复制，直接为场景绑定本租户现有档案。原档案和 `/agents` REST 不变；空源档案不能假装已完成复制。场景的复制/定制/绑定仅有 `kuaiai:library:manage` 的管理员可操作，绑定/复制还须 `kuaiai:agent:read`，克隆另须 `kuaiai:agent:create`；使用权始终由既有 Agent grant 决定。

业务路由不能凭文案猜测。实现 spec 必须从当前业务 manifest 取实际存在且用户有 display 权限的路径；找不到时 `scene_available=false`，按钮禁用。实例自定义路由也只能选择服务端白名单且每次跳转仍检查目标权限。

### 5.5 助手行为

点击“打开 KU-Ask”后：

1. 打开已有右侧助手抽屉，宽度沿用当前实现；示例约 560 px，仅作为视觉参考。
2. 抽屉上下文显示“智能体库”和智能体名称。
3. 自动创建/复用会话并发送样例问题，不只是填入输入框。
4. 请求使用现有 `POST /api/v1/core/ai/chat/completions`；发送前要求模板总开关、实例 enabled 均为 true，绑定的本租户档案已启用且当前用户有使用权、chat 已就绪；未绑定/停用/删除则显示 not_ready 且禁发送。context 顶层传已复核的 `agent_id`，`extra.agent_key` 传实例稳定 key、`preset_prompt` 仅作场景首问标识，不代替服务端档案/权限检查。
5. 现有 chat_service 只按 `context.agent_id` 组装档案，不会自动消费 `extra.agent_key`。181 须在请求携带 `extra.agent_key` 时于现有 chat service 内增加场景校验：同租户实例/模板解析、总/单项开关、传入 `agent_id` 与实例绑定一致、档案启用/使用权及 chat 就绪；缺失或不一致拒绝后才可进入原有 assemble，不改既有 URL/请求字段/响应外层；不携带 `agent_key` 的普通 `/chat` 请求沿用原流程，不把模板开关当作全局禁用对话。客户端隐藏按钮不是服务端校验。
6. 有绑定但当前用户无档案使用权时 403 在抽屉内显示明确权限提示；不得自动降级到无档案纯对话。

## 6. 异常感知 `/pulse`

### 6.1 布局

页头后是五张汇总卡，一行五列，间距 16 px、高约 96 px。随后按领域分节；节标题“生产 19条”形态为 18 px/600 + 次数字。异常卡三列，基准约 303×173 px（示例在侧栏折叠时约 357 px），间距 16 px；小于 1100 两列，小于 768 单列。

异常卡：顶部三个 Tag（严重度、领域、优先级）；标题 16 px/600；事实摘要 2–3 行；建议 1–2 行；底部蓝色文本按钮“查看工单/查看销售订单”。卡片同一行等高，按钮贴底。

### 6.2 领域模型

```text
PulseDetectorRegistry
 ├─ ProductionDelayDetector
 ├─ SalesDeliveryRiskDetector
 ├─ InventoryShortageDetector      （后续接入）
 ├─ QualityAbnormalDetector        （后续接入）
 └─ EquipmentAbnormalDetector      （后续接入）
```

统一项：`id`、`domain`、`severity(info|warning|error|critical)`、`priority(low|medium|high)`、`title`、`fact`、`suggestion`、`resource_type`、`resource_id`、`resource_uuid`、`route`、`detected_at`。规则由领域 service 返回已授权的事实；路由层只聚合。相同 `domain+rule_code+resource_id` 去重。

首期规则：

- 生产延期：计划完成时间早于当前时间且业务状态不属于已完成/已关闭；逾期天数由日期差确定。
- 销售交期风险：约定交期在未来 0..3 天（含今日，缺省值）或逾期且履约未完成；阈值从现有 TenantConfig 按租户读取 `config_key="kuaiai.pulse.sales_delivery_risk"`、`config_value.warning_days`（合法整数 0..365）；缺键/非法值回落 3，读取失败为 detector 局部失败，不写 yml。
- 严重度映射必须写入对应实现 spec，并以实际状态枚举为准；本文不臆造未读到的状态值。

LLM 可在用户点击“解释”后基于 `fact` 生成说明，但不能参与是否异常、计数、严重度和业务 ID 的判定。

### 6.3 局部失败

各 detector 单独设置超时并收集 `errors[]`。汇总只计算成功 detector；响应 `complete=false` 时页面指标旁显示“部分数据”，不能把失败领域计入“0 条”。15 秒仍未完成时前端允许取消，后端不得留下无界后台查询。

## 11. 新增 API 设计

所有响应仍走项目现有成功信封/`apiRequest` 解包机制，以下表格描述解包后的 `data`。认证头和错误外层结构保持现状。

### 11.1 能力矩阵

`GET /api/v1/apps/kuaiai/operations/hub?days=7`

- query：`days: int=7, 1..90`
- 权限：`kuaiai:entry:read` + `kuaiai:hub:display`
- 响应：

```json
{
  "days": 7,
  "model": {"configured": true, "name": "deepseek-v4-flash", "connection_uuid": "..."},
  "metrics": {"total_calls": 208, "pulse_count": 39, "corpus_count": 15, "avg_latency_ms": 79},
  "capabilities": [{"key": "ask", "name": "智能问答", "status": "ready", "description": "...", "route": "/apps/kuaiai/chat", "disabled_reason": null}]
}
```

`status` 只允许 `ready|partial|not_ready`。`capabilities` 固定最多 8 项。

### 11.2 智能体库

`GET /api/v1/apps/kuaiai/operations/agent-library`

- 权限：`kuaiai:entry:read` + `kuaiai:library:display`
- 响应顶层含 `provisioning{complete,missing_template_keys,retryable}` 与 `items[]`。item 字段为 `key`（实例稳定 key）、`template_key,name,description,image_key,enabled`（实例开关）、`status,capability_tags,sample_prompt,agent_profile_id,scene_route,scene_available,disabled_reason`；列表含六个系统预置档案所绑定的模板卡及租户复制实例，按模板次序和实例创建时间稳定排序。模板总开关从 Settings 读取，最终状态按模板开关 ∧ 实例 enabled ∧ 档案/chat/使用权计算；若安装/升级预置尚未完成，`provisioning.complete=false`、缺失模板以明确 not_ready 占位卡提示“预置未完成/待重试”，不得把无实例虚拟卡伪装为开箱可用。
- `agent_profile_id` 可空表示未绑定，或当前用户既无该档案使用权也无 `kuaiai:agent:read` 时因脱敏未下发 ID；后者须返回不泄露档案细节的权限状态；有管理读权限但无使用权的管理员可见绑定 ID 供治理，仍不可发送；不返回 `system_prompt`、授权名单或模型密钥。客户端不得仅凭 `agent_key` 伪造任意绑定档案，后端发送仍按既有档案使用权校验。
- `PUT /api/v1/apps/kuaiai/operations/agent-library/instances/{instance_key}`：仅预置 key 或本租户已存在实例，body `agent_profile_id?:int|null,enabled?:bool,name?,description?,image_key?,sample_prompt?,capability_tags?,scene_route?`（extra forbid）；按实例 key 局部更新，六预置实例应在安装时已存在；缺失时返回待修复错误并走幂等预置同步，不以匿名虚拟实例覆盖。须 `entry:read` + `library:display` + `library:manage`，绑定另需 `agent:read`；返回更新后单项，不允许修改 `template_key` 或跨租户改绑。插画 key 与路由只允许已登记资源/白名单。
- `POST /api/v1/apps/kuaiai/operations/agent-library/instances`：body `template_key,source_agent_id,overrides?`（覆盖字段与 PUT 相同但不含 `agent_profile_id`，extra forbid）；须 `entry:read` + `library:display` + `library:manage` + `agent:read` + `agent:create`；克隆同租户现有档案为停用且无授权的新档案，原子创建绑定到它的复制实例，返回 201 单项。新实例 key 服务端生成；源档案不存在/跨租户返回 404；不自动启用、授权或绑定到六个基础卡。

对话继续使用现有 `POST /api/v1/core/ai/chat/completions`：

```json
{
  "messages": [{"role": "user", "content": "查询缺料相关的物料即时库存"}],
  "stream": true,
  "temperature": 0.7,
  "context": {
    "agent_id": "12",
    "extra": {"agent_key": "inventory-insight", "preset_prompt": "查询缺料相关的物料即时库存", "capability_mode": "query"}
  }
}
```

### 11.3 Pulse

`GET /api/v1/apps/kuaiai/operations/pulse`

- query：`domain?: production|inventory|sales|quality|equipment`（可重复或逗号分隔，由实现 spec 固定一种）、`severity?: info|warning|error|critical`、`page=1`、`page_size=60(1..100)`。

### 11.4 跨库语料

`GET /api/v1/apps/kuaiai/operations/corpus`

- query：`page=1`、`page_size=20(1..100)`、`keyword?`、`knowledge_id?`、`type?:faq|text|file`、`status?:pending|parsing|ready|failed`、`created_from?`、`created_to?`。
- 权限：`kuaiai:entry:read` + `kuaiai:corpus:display`。

写接口：

| method/path | 请求 | 响应/说明 |
| --- | --- | --- |
| `POST /operations/corpus/faqs` | `knowledge_id,question,answer,is_active=true` | 201 语料项；extra forbid；create 权限，必选启用知识库 |

### 11.5 信任概览

`GET /api/v1/apps/kuaiai/operations/trust`

- 权限：`kuaiai:entry:read` + `kuaiai:trust:display`；审计列表仍需 core 原有 entry 权限，不改 core 契约
- 响应：`cards[{key,title,status,description,evidence[]}]`、`permissions[{code,granted}]`、`hitl{implemented,mode}`。
- 不接收 user_id；只返回当前用户权限视图。
- 审计列表直接请求既有 `GET /api/v1/core/ai/audit/logs`。

### 11.6 设置

`GET /api/v1/apps/kuaiai/operations/settings`

- 权限：`kuaiai:entry:read` + `kuaiai:settings:display`
- 响应：`chat_connection_uuid`、`vision_connection_uuid`、`chat_options[]`、`vision_options[]`、`ocr{configured,base_url_masked,model}`、`agent_switches` 六键 map、`capabilities{tools_enabled,rag_enabled,rag_use_embedding,rag_backend,rag_top_k,stream_enabled,custom_system_prompt}`、`version`。
- option 只含 `uuid,name,provider,model,model_role,is_active,is_selected`，不含 key/cipher。

`PUT /api/v1/apps/kuaiai/operations/settings`

```json
{
  "version": "opaque-version",
  "chat_connection_uuid": "uuid",
  "vision_connection_uuid": "uuid-or-null",
  "agent_switches": {
    "inventory-insight": true,
    "planner-advisor": true,
    "purchase-followup": true,
    "schedule-explainer": true,
    "quality-analysis": true,
    "supplier-collaboration": true
  },
  "capabilities": {
    "tools_enabled": true,
    "rag_enabled": true,
    "rag_use_embedding": true,
    "rag_backend": "native",
    "rag_top_k": 5,
    "stream_enabled": true,
    "custom_system_prompt": ""
  }
}
```

- 权限：`kuaiai:entry:read` + `kuaiai:settings:display` + `kuaiai:settings:update`。
- `version` 用于防止覆盖他人更新，冲突返回 409。
- chat UUID 必须属于当前租户、启用且 `model_role=chat`；vision 同理；预置六档案存在不代表已选模型可调用，未配置时显示待配置而不返回假 ready。
- 未提供任何密钥字段；密钥仅由现有应用连接器管理，不在本设置 API 增加 `ocr_api_key`。`version` 以 SiteSetting 当前行身份/updated_at 派生，PUT 事务内锁行重算后对比，成功后角色 UUID 和能力项一次保存。

## 12. 既有 API 参数台账

### 12.1 Core AI

| API | 参数 | 返回关键字段 | 权限 |
| --- | --- | --- | --- |
| `GET /core/ai/status` | 无 | `configured,enabled,model` | `kuaiai:entry:read` |
| `POST /core/ai/chat/completions` | `messages[]` 必填；`model?`; `stream=false`; `temperature=0.7,0..2`; `context?` | JSON `choices,usage` 或 SSE | `kuaiai:act:execute` |
| `GET /core/ai/stats/overview` | `days=7,1..90` | 见第 9 节 | `kuaiai:entry:read` |
| `GET /core/ai/audit/logs` | `page>=1,page_size=20(1..100),capability?` | `items,total,page,page_size,empty_reason` | `kuaiai:entry:read` |

审计 item 精确字段：`uuid,route,capability,model,latency_ms,prompt_tokens,completion_tokens,status_code,error_message,created_at,user_id`。

### 12.2 Agent 档案（保留）

- `GET /apps/kuaiai/agents?page=1&page_size=50(<=200)` 返回数组，不是分页对象。
- create 必填 `name(1..100)`、`grant_mode(ROLE|USER)`；可选 `description,system_prompt,default_model_id,knowledge_ids,enabled_tools,mcp_server_ids,status`；extra forbid。
- `GET/PUT/DELETE /agents/{agent_id}`；`GET/PUT /agents/{agent_id}/grants`，PUT body `{target_ids:[int]}`。
- `GET /agents/options` 只返回当前用户可使用的启用档案。

### 12.3 知识库（保留）

- `GET /knowledge-bases?page=1&page_size=50(<=200)&keyword=` → `{items,total}`。
- create/update 字段：`name,description,embedding_model_id,chunk_size,chunk_overlap,expand_enabled,status`；现行运行时已经转向应用连接角色，文档不得把保留列写成当前模型真源。
- 文档 create：`title(1..300),source_type(<=20),file_uuid?(<=36),raw_content?(<=200000)`，文件与正文二选一由 service 校验。
- `GET /knowledge-bases/{id}/documents?page=1&page_size=20`；`GET/DELETE /documents/{id}`；`POST /documents/{id}/parse`；`GET /documents/{id}/chunks`。

### 12.4 应用连接器（模型设置复用）

- `GET /core/application-connections?page=1&page_size=20(<=100)&search=&type=&is_active=` → `items,total,page,page_size`。
- `GET /core/application-connections/llm-roles` → `{chat,embed,vision,rerank}` UUID 字符串。
- `POST /core/application-connections/{uuid}/select-role` → `{role,uuid}`；角色取连接 `config.model_role`，闭集为 chat/embed/vision/rerank。
- 连接 create 字段：`name(1..100),code(1..50),type(1..40),description?,config{},is_active=true`；update 不允许改 code/type。
- 返回 config 已脱敏；设置页不得依赖明文 key。

## 15. 可访问性与响应式验收

- 标题采用正确 heading 层级，不能只靠放大 `div`。
- Tag 的状态需有文本；图标按钮有 `aria-label` 和 Tooltip。
- 表格批量选择、下拉菜单、Segmented、Switch、Modal/Drawer 可键盘操作。
- 自动发送样例问题前，在按钮文案或辅助说明中明确“打开并发送”，避免用户误认为只预填。
- 图表同时提供数值摘要或可访问数据表；颜色不是唯一信息载体。
- 200% 缩放不遮挡保存按钮；小屏操作栏可换行，不能横向覆盖内容。
- 插图 `alt` 使用智能体名称；纯装饰背景使用空 alt。

## 16. 验收矩阵

| 页面 | 必验主路径 | 必验失败路径 |
| --- | --- | --- |
| hub | 指标加载、八卡跳转、打开助手 | 无 chat 连接、无目标页权限、部分统计失败 |
| agent-library | 安装/升级自动建六份停用且无授权的档案并绑定六卡、六场景只读 Tool 真实可用、管理员在 `/agents` 配置授权并启用后可定制/复制、自动首问和业务跳转 | 安装部分失败可重试、无档案使用权/无 chat、源数据为空/无业务权限/无知识库、跨租户源档案、总/单项开关关闭、无路由 |

## 17. 调研局限与实现前复核点

- 示例系统插图、接口实现和检测阈值未公开；只能复刻信息结构和交互，不复制未知版权资产或算法。
- 示例页面在一次 Pulse 首载中等待接近 20 秒，说明必须设计长加载和局部失败，但不能据此推断其服务端架构。

- 示例信任中心声称 HITL 已闭环，而本地代码与上游需求明确尚未实现；本地必须以代码事实显示未就绪。
- 业务跳转的最终路径和生产/销售状态枚举必须在对应实现 spec 中再次从当前代码核对，不能只依赖本调研时的示例路径。
