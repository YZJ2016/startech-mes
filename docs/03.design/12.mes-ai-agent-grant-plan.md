## 1. 问题与目标

现网把「谁能改档案」和「谁能用档案」混在对话入口上：配置页有 `profile:*`，但 `GET /ai/agent/profile/options` 对有 `ai:chat:list` 的人返回本厂全部启用档案，`POST /ai/agent/send` 只查 `ai:chat:send`。一线只要知道或猜到 `agentId`，就能打到「车间报工」这类挂了写 Tool / MCP 的档案（写操作仍被 MES 字拦住，但提示词、知识库、只读 Tool、MCP 会生效）。

目标：

- 配置面不变：没 `add/edit/remove` 就不能改档案
- 使用面按档案授权，并且 **看见 = 能发** 由服务端同一规则保证
- 通用档案走角色，少数人走人员，一份档案只能选一种

### 1.1 非目标

- 按部门/岗位作为授权模式、授权过期（AG-G1 / AG-G2）。选人用部门树属 AG-F2，不是 AG-G1。
- 每档案一个 Spring 权限字、独立 Agent 聊天路由
- 改 `chat/send` / `agent/send` URL 或 SSE 信封
- 用授权绕过 `mes:pro:*` / `AiMcpGuard`
- Vue2；匿名 `/ai/**`

## 2. 两层闸

```text
配置（已有）
  ai:agent:profile:add|edit|remove
  → CRUD + 改 grantMode / 名单
  → 管理 list 仍全量（AG-D15）

使用（本轨）
  LoginUser.userId + 本租户角色 id
  → 命中档案授权？
        │
        ├─ GET /ai/agent/profile/options  → 只返回命中且 status=0
        └─ POST /ai/agent/send            → 未命中 403
              │
              └─ 命中后再按档案挂 Tool/MCP
                    └─ 各 Tool / MCP 仍查 MES 权限（AG-D11）
```

对话未选档案：仍 `POST /ai/chat/send`，不进本图。

## 3. 数据形态

`ai_agent` 增列 `grant_mode`：`ROLE` | `USER`（存大写；JSON `grantMode`）。

授权行表 `ai_agent_grant`（名称以实现 spec 为准，语义冻结）：

| 列 | 含义 |
| --- | --- |
| `tenant_id` | 必填，进 include |
| `agent_id` | 本租户档案 |
| `target_type` | 与档案 `grant_mode` 相同：`ROLE` 或 `USER` |
| `target_id` | `role_id` 或 `user_id` |

唯一键 `(tenant_id, agent_id, target_type, target_id)`。禁止一行 ROLE 一行 USER 挂在同一 `agent_id` 上（保存时按 mode 删除另一侧）。

VO 增量（profile 详情/写）：

- `grantMode`
- `roleIds: number[]`（mode=ROLE 时有值，否则 `[]`）
- `userIds: number[]`（mode=USER 时有值，否则 `[]`）

options **不下发** 上述名单。

命中规则（当前租户）：

- `grantMode=ROLE`：存在 grant 行 `target_type=ROLE` 且 `target_id ∈ 用户角色id` 且角色本租户正常
- `grantMode=USER`：存在 grant 行 `target_type=USER` 且 `target_id = LoginUser.userId`

`isAdmin()` / 平台运营身份 **不**跳过本规则（AG-I1）。

## 4. HTTP

保持 68 前缀。行为变化写在缺口 AG-D13，不新开 path。

| 口 | 变化 |
| --- | --- |
| `GET/POST/PUT /ai/agent/profile` | 读写增加 grant 字段；保存校验 AG-D3/D6、本租户角色/用户 |
| `GET /ai/agent/profile/options` | 同一权限字；**结果按使用权过滤** |
| `POST /ai/agent/send` | 同一 `ai:chat:send`；增加使用权 403 |
| 管理 `GET` list | 不过滤使用权 |

## 5. 迁移

Flyway **tenant**（专库 catalog 同步 `ai_agent_grant`）：

1. 加 `grant_mode`，默认 `ROLE`
2. 建授权表
3. 对每个租户：每个 **启用** 档案插入该租户全部 `status=正常` 的 `sys_role.role_id` 为 ROLE 行
4. 停用档案不插行（空名单合法）

编码期空库单测可跳过第 3 步数据，但脚本必须可重复、失败关闭（无 `tenant_id` 不写）。

## 6. 前端形态

档案页（97）：授权 UI 做在现有维护页 `/ai/agent`（`views/ai/agent/index.vue` 新增/修改对话框），不新开菜单、不新开独立授权页。管理 list 仍全量。表单增加「谁能使用」——模式单选角色/人员。

`ROLE`：角色多选 + 按名称筛选；不强制部门树。复用 Vue3 `src/api/system/role.js` 的 `listRole`（现网 `GET /system/role/list`）。

`USER`：选人 UI，不是按部门授权。左侧/上侧部门树，右侧（或同区）该部门下人员多选；仍可按用户名/昵称筛选。提交体仍是 `userIds` 数组（96 契约不变）；不得把部门 id 写入授权行，档案不能 `grantMode=DEPT`。复用现网用户管理选人：部门树 `GET /system/user/deptTree`（`src/api/system/user.js` 的 `deptTreeSelect`）；人员列表 `GET /system/user/list`（同文件 `listUser`，query 带 `deptId`，并可带 `userName` / `nickName`）。不新造 path、不新造组织权限字。

切换模式清空另一侧。启用且名单空：不能提交。

对话 / F1（98）：继续 options。会话 `agentId` 不在当前 options → 清空（AG-D16）。send 403 走现网错误提示。无档案可选时保持纯对话。

## 7. 测试要点（设计层，非 task）

- 同租户：角色命中可见；换角色不可见；人员模式仅名单用户
- 跨租户 agentId / 伪造 roleId → 404/400，options 不含他厂
- 启用 + 空名单保存 400
- send 无授权 403，且不调上游模型
- 配置权用户 list 仍能看到自己不能使用的档案
- 未选档案仍 chat/send
- `isAdmin()` 不能跳过 grant
- Vue2 diff 空
