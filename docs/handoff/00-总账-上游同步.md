## 5. 未评估队列怎么看

打开本目录对应批次文件（如 `批次-批D.md`）→ 筛 **⬜未评** 行即该批队列（D 53 / E 38 / F 43 / G 59 为主）；要文件级细度再看 `上游同步-评估覆盖.md`「未登记」472 笔。每轮同步固定动作：

```bash
git fetch gitee develop --filter=blob:none
python riveredge-backend/scripts/sync_upstream_audit.py audit --from <水位> --to gitee/develop
# NEW=没见过 / REEVAL=评过但上游又改 / DELETED=上游删了 / SKIP=未变直接跳
# 落地后:record --to <tip> --verdict applied|superset|deferred|domain-out --note "..." <paths>
```

覆盖清单重新生成方法：跑 `audit` 前对「评估过但未 seed 的提交」可 `seed --to <tip> <sha>...`；全表重生成脚本见本会话 `/tmp/gen_coverage.py`（可按需固化进 `scripts/`）。
