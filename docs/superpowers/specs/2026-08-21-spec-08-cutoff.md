# Spec 08 — Remaining pages, MES extras, build, cutover

Date: 2026-08-21  
Parent: `2026-08-21-mes-vue3-front-upgrade.md`  
Depends on: spec 01 (shell) and specs 03–07 (domain pages). Selectors (spec 02) must already exist.

## Goal

Finish the Vue 3 admin surface: the remaining **~19** MES views (tm, edu, report, camera, contract, sale), custom dashboard, autocode, in-app messages, UReport **via env vars**, a production build of `startech-mes-front`, and an explicit **cutover decision** for Vue 2 `frontend/`. This spec does not silently replace Vue 2.

### Dashboard

Source: `frontend/src/views/index.vue`, `frontend/src/views/dashboard/**` (`PanelGroup.vue`, charts, mixins).  
API: `getIndexNum` → `GET /mes/pro/workorder/getIndexNum`.

Do **not** port backup views that embed hardcoded hosts. Any iframe/report URL must be an env placeholder.

### Autocode

Source: `frontend/src/api/system/autocode/part.js`, `rule.js`; `frontend/src/views/system/autocode/index.vue`, `part.vue`.  
Target: same paths under `startech-mes-front`. URLs stay `/system/autocode/**`. Needed by many already-ported domain pages.

### In-app messages

Source: `frontend/src/api/system/message.js` (`/system/message/**`); `frontend/src/views/system/message/index.vue`.  
This is MES-specific relative to stock notice. Keep it distinct from RuoYi 3.9 notice-read APIs the 3.8.2 backend may not fully share.

### UReport

- Keep `/ureportM` REST wrappers.
- Designer iframe and preview base URL: **env only** (e.g. `VITE_APP_UREPORT_URL`). Never copy Vue 2 `src/config/website.js` hosts into Vue 3.
- Vite proxy, if needed for `/ureport/designer`, also from env/local config.
- `reportSelect` (spec 02) must read the same env key.

### Production build and cutover

- Run `npm run build:prod` in `startech-mes-front` and record actual output (AGENTS.md: do not claim success without the command).
- Decide whether Vue 2 `frontend/` is replaced later (reverse proxy / antrun / nginx) or kept as fallback. **Default: keep Vue 2 until a named cutover change.** Spec 08 documents the recommendation; it does not delete `frontend/`.

## Decisions

1. Remaining 19 pages follow the same `<script setup>` rule as 03–07.
2. Keep misspelled API/view names (`salse.js`) for contract stability of imports.
3. Camera `hkvideo` stays a local component; no new vendor SDK unless Vue 2 already bundled it (then port the same asset, no new secrets).
4. Edu evaluate MinIO upload uses spec 01 `/common/uploadMinio`.
5. Autocode UI is in 08 even if `genCode` API was added earlier — pages must be complete here.
6. Cutover is a **decision record**, not an implicit delete. Vue 2 freeze remains until that record says otherwise and a follow-up task executes it.
7. Lock screen / password-expiry stay disabled (spec 01). Do not re-enable them at cutover.

## Conversion checklist

- Options API → `<script setup>`
- `visible.sync` → `v-model` / `v-model:visible`
- `slot-scope` → `#default`
- `el-icon` / `.native`
- dicts → `useDict`
- treeselect → `el-tree-select`
- Pagination/RightToolbar `v-model:*`
- dashboard charts: Vue 2 echarts 4 usage → Vue 3 shell echarts 5; same series/APIs, no new backend
- ureport preview: `website.reportUrl` → `import.meta.env.VITE_APP_UREPORT_URL` (or agreed single env name)
- `import.meta.env.VITE_APP_*`

## Non-goals

- Implementing backend UReport or MinIO changes.
- Re-enabling Vue 3 3.9 lock screen.
- Committing or deleting `frontend/` unless a later task explicitly says so.
- Inventing a pad/shop-floor client.
- Copying secrets or IPs from Vue 2 config into `.env*` samples. Samples stay placeholders (`VITE_APP_BASE_API=/dev-api`, `VITE_APP_UREPORT_URL=` empty or a non-host placeholder like `https://ureport.example.internal`).
